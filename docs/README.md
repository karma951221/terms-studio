# terms-studio 문서

## 문서 규칙

- **기능 하나 = 문서 하나.** 기획 · 화면 · 유저액션을 한 문서에 쓴다. 따로 두는 것은 `시나리오/`(E2E 정본, 파일명이 좌표라 바꾸지 않는다)와 `결정/` 뿐이다.
- **상태 배너**를 첫 줄 아래에 둔다 → `> 상태: 빈 뼈대 | 초안 | 합의 | 확정 | 폐기 · 최종수정: YYYY-MM-DD`
- **위키링크는 docs 기준 전체 경로**로 쓴다 — `[[기능/구분자/결정/ADR-0036-…]]` · `[[공통/화면/디자인원칙]]`. 파일명만 쓰지 않는다. 검사: `npm run docs:links` (0건 유지).
- 날짜는 **절대 날짜**로 쓴다 (`지난주` 금지).
- 변경 경위는 문서에 쌓지 않는다 — **커밋 메시지가 변경이력**이다. 문서에는 현재만 둔다.

## 결정

- **결정은 기능 문서가 기본이다.** 한 기능 안의 결정은 그 문서 §3 규칙(이유가 안 보이면 `— 왜:` 한 줄)과 §6.2 **결정 메모**(결정 · 왜 · 버린 안)에 둔다.
- **ADR 은 둘 다 만족할 때만 쓴다** — ① 여러 기능에 걸치거나 아키텍처 · 데이터 모델의 뼈대를 정한다, ② 버린 대안이 다시 제안될 만하고 규칙만 봐서는 이유가 안 보인다.
  자리는 주인 기능의 `기능/<f>/결정/`, 공통은 `공통/화면/결정/` · `공통/기술/결정/`, 인수 · 테스트 범위는 `QA/결정/`.
- 번호는 전 폴더에 걸쳐 하나로 매긴다(가장 큰 번호 + 1). 번호 · 파일명은 바꾸지 않는다 — 코드 주석이 `ADR-NNNN` 으로 가리킨다.
  흡수 · 번복된 번호는 다시 쓰지 않는다.
- **리포에는 현행만.** 새 결정이 옛 결정을 바꾸면 같은 커밋에서 ① 옛 ADR 을 `_archive/` 로 옮기거나 현행으로 고쳐 쓰고(원본은 아카이브), ② 기능 문서 §3 · §6 을 고치고, ③ 옛 번호를 가리키는 코드 주석을 고친다.
- 기능마다 결정 목록은 그 문서 §6 (6.1 ADR · 6.2 결정 메모 · 6.3 다른 기능의 결정).
