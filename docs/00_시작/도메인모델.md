# 도메인모델

> 상태: 초안 (1차 정서) · 최종수정: 2026-09-08
> 2026-08-29 대화로 정의했다. 모든 결정에 날짜를 남긴다. 미결은 §7.

## 0. 전제

- **실체는 뼈대만 갖는다** — id · 관계 · 순서 · **이름** (2026-08-30: 이름은 뼈대 속성으로 확정 —
  [[기능/담보/담보]]). 그 외 입력값은 전부 구분자 값으로 저장한다.
- **폼 = 구조체 = 구분자 하나.** 화면에 입력하는 모든 폼은 구조체 타입의 구분자 하나다.
- 값의 세계는 **직접**(모델링 화면에서 결정)과 **파생**(직접 값에서 계산) 2층으로 가른다.
- **파생 로직은 데이터다** — 코드에 심지 않는다 ([[00_시작/문제정의]] S4).

## 1. 실체 뼈대

```
[마스터]                      [상품]
담보                          상품 ── 보통약관 마스터 선택
 └─ 세부보장 1:N               ├─ 세목 선택지 ×N
     └─ 급부 1:N               ├─ 상품세목 = 명시 등록된 유효 조합
                               └─ 상품담보 ×N = 담보 탑재 (다중 탑재 가능)
```

### 담보 트리 (2026-08-29 확정)

- **담보 > 세부보장 > 급부 2단 구조 유지.**
  세부보장 = 담보 안에서 지급사유가 갈라지는 단위. 급부 = 보험금이 지급되는 최소 단위.
  단순한 담보(각 1개)도 같은 3층의 최소 사례로 표현한다.
- **구조(트리)는 마스터 소유이며 모든 상품에서 동일하다.** 상품담보는 구조를 빼거나 바꿀 수 없다.

### 세목 (2026-08-29)

- ~~종·형 2축 고정~~ → 같은 날 반례 확인 (기본납입형/가벼운납입형 — 세목이지만 종·형으로 구분 안 함).
  **일반 모델에서 축은 종·형에 고정되지 않으나, 번호 없는 축은 MVP 에서 다루지 않는다** (2026-08-29 확정).
  **MVP 는 세 경우만 고려한다**: ① 종·형 둘 다 사용 ② 둘 중 하나만 사용 ③ 둘 다 미사용(0종 0형).
- **세목유형은 상품모델링에서 추가한다** (2026-08-29 확정).
- **세목유형**: 납입면제유형 · 무저해지유형 · 계약전환형 · 영위업종적용형 · ~~납입형태~~(2026-09-06 제외).
  필드 정의는 2026-09-06 확정 → [[기능/상품/상품]] §세목. 종형명 = 선택지 이름(유형 필드 아님).
  - **고지유형은 세목유형이 아니다** (2026-08-29 확정). 기존 시스템에서는 종형으로 구분하지 않는
    세목 구분자의 일종이었으나, 이 프로젝트에서는 **상품 레벨 enum 구분자**로 둔다 —
    유효값: 일반심사 · 간편심사 · 건강고지. 「특정 고지유형에서는 기본납입형만」 같은 제약은
    상품 구분자 값 ↔ 세목 구성 간 제약이 된다.
  **유형마다 필드가 다르다 → 유형 하나 = 구조체 하나.** 세목 폼은 그 구조체가 그린다.
- **축은 유형의 그릇이 아니다.** 유형을 고르는 단위는 종형 번호 하나하나다.
  - **한 유형은 한 축에만 걸칠 수 있다** (2026-08-29 확정 — terms-lab 규칙 계승).
  - **여러 유형이 한 축에 걸칠 수 있다** (2026-08-29 확정) —
    예: 형 축에 무저해지유형의 1형(해약환급금지급형)·2형(해약환급금미지급형)과 계약전환형유형의 4형(계약전환형).
  - 한 축의 번호들은 배타적 선택지다 — 계약은 축마다 하나를 고른다. 유형이 엇갈리는 조합((2종, 4형))도
    의미는 같다: 축마다 하나씩 고른 것일 뿐.
  - 뼈대: `(축, 번호, 이름, 세목유형 참조, 유형 구조체 값)`.
- **문면 번호는 선택 속성이다** (해석 A). 번호 없는 선택지가 존재하고,
  같은 유형이라도 종형 축으로 분리할지는 상품마다 다르다.
- **세목 조합은 카테시안이 아니다.** 상품에는 명시 등록한 유효 조합만 들어간다.
  조합 제약이 유형을 가로지른다 (예: 특정 고지유형에서는 기본납입형만).
  문면 표기는 `제2종(보험료 납입면제형)` 처럼 번호 + 유형명 병기.
- **담보 적용범위는 세목 선택지에 따라 담보마다 상이할 수 있다** — 담보 ↔ 유효 조합 관계 필요.

### 상품담보 = 탑재 (2026-08-29 확정 · 2026-08-31 개정)

- **같은 담보를 한 상품에 여러 번 탑재할 수 있다.**
  일반상해사망 담보 하나 → 「갱신형 일반상해사망」·「일반상해사망」·「일반상해사망 추가」.
- ~~새 모델에서는 별도 장치 없이 값 차이가 곧 탑재분의 구별~~ → **2026-08-31 번복 —
  담보속성을 별도 카탈로그 실체로 복원** ([[README]] ADR-0015 · [[기능/상품/상품]]).
  - 담보속성 = 종류 + 유효값 목록, 둘 다 유저 편집 가능한 데이터.
  - **상품담보 = 담보 × 담보속성 값 조합** — 조합이 상품담보를 하나 결정(중복 탑재 거부),
    **특별약관 한 벌이 나오는 단위**다. 필요한 속성만 붙인다(sparse).
  - 식의 참조 대상이다 — `exist` · `=` · `≠` 만, RHS 는 유효값 리터럴만.
    미사용 속성의 =/≠ 평가는 오류 + 좌표 (조용한 false 없음).
  - **문면 없는 담보 허용** — 그 탑재분은 조립에서 문서를 내지 않는다.
    현행의 특별조건부류는 별지·PV 산출용 — 약관 전용인 MVP 에서는 만들지 않는다.
- **탑재는 값 스냅샷이다.** 탑재 순간 마스터 값이 상품담보로 복사되고,
  이후 마스터 값 변경은 이미 탑재된 상품담보에 영향을 주지 않는다 (이후 탑재분에만).
  수정은 **필드 단위**. 공유되는 것은 구조뿐.
- **상품담보명은 작명 규칙으로 생성한다** (기존 시스템 차용). default 이름은 담보속성
  조합에서 생성하고 속성별 담보명 규칙(prefix/suffix·적용 순서)도 유저 정의 —
  상품모델링에서 직접 변경 가능. ~~구분자 정의의 작명 메타~~ 는 2026-08-31 담보속성
  정의로 이동 (ADR-0015).

### 기본계약 (2026-08-29)

- **기본계약** = 상품담보 중 보통약관이 내용을 따라가는 담보.
  보험금의 지급사유·지급하지 않는 사유 등이 이 담보를 따르므로 상품마다 다르다.
- **MVP 는 기본계약이 정확히 1개인 상품만 다룬다.** 없거나 복수인 상품은 요건이 달라짐 — 범위 밖.

## 2. 값의 체계

> **2026-09-12 개정 — 값의 체계 3층, 1층은 코드 마스터** ([[기능/구분자/결정/ADR-0036-폼-구분자-문면-3층]] · [[기능/마스터/결정/ADR-0037-입력항목-코드마스터-유저정의폼-MVP이후]]).
> **입력 마스터**(레벨별 고정 필드, 코드) → **구분자**(마스터 필드에 건 식 하나, 결과 타입은 식에서) → **문면**(조건식 · 반복 · 슬롯은 구분자만).
> 유저 정의 폼 · 선택 필드 · 노출여부는 MVP 이후. 구분자 종류(일반 · 상수 · 파생)는 없다. 세부는 [[기능/구분자/구분자]].

### 타입 (2026-08-29 확정)

- 원시형 5: `string` · `number` · `boolean` · `date` + 사용자 정의 `enum`
  (enum 값 = 코드 불변 + 표시명 가변). terms-lab 4종에 date 추가.
- **`list<enum>`** (2026-08-29 추가) — 한 필드에서 enum 값 여러 개를 고르는 유즈케이스가 실재한다
  (예: 납입면제사유 다중선택).
- ~~**const 구분자**~~ → **2026-09-12 마스터 필드 + 기본값 (+ 투영 구분자)** (ADR-0037). (2026-08-29 추가) — 값이 정의(마스터)에 사는 구분자. 상품이 아니라 마스터가 값을 정하고,
  문면 템플릿이 참조한다 (예: 평균공시이율). 변경은 마스터 한 곳에서. **MVP 에서는 string 만.**
- **구조체 규칙 확정** (2026-08-29):
  - **중첩 금지** — 필드 타입으로 구조체를 둘 수 없다. 소그룹이 필요하면 폼을 쪼개 별도 구분자로 채번한다.
  - ~~**`list<T>` 허용**~~ — 표 입력(행 추가) 필드. → **2026-09-01 MVP 제외** —
    입력의 소비처(표 출력)가 동적표와 함께 MVP 밖. 동적표 기획 때 재도입 ([[00_시작/범위]]).
  - ~~정리 — 필드 타입 전체: `string` · `number` · `boolean` · `date` · `enum 참조` · `list<enum>` · `list<T>`.~~
    → **2026-09-12 MVP 입력 항목은 코드 마스터** (ADR-0037) — 타입은 코드 타입 그대로 (`string` · `number` · `boolean` · `date` · `enum` · `list<enum>`).
    유저 정의 폼의 「일단 목록」(`int` · `float` · `list<string>` …)은 MVP 이후로 넘어간 문제.
    유즈케이스 예: 감액기간별 지급률 표 (1차연도 50% · 2차연도 60% …).
    → **2026-09-13** 이 유즈케이스(최초지급금액표)는 `list<T>` 가 아니라 **급부 아래 목록 구조 `감액구간[] {시작, 끝, 감액률}`** 로 푼다 — 급부마다 구간 · 감액률이 다르다.
    급부 마스터 필드(ADR-0037)에 자리가 생긴다. ADR-0042(아카이브) · [[기능/담보/담보]].
- **입력 마스터 = 코드, 구분자 = 식** (2026-09-12, ADR-0036 · 0037). 입력 항목은 레벨별 고정 필드로 코드에 산다 — 항목 추가는 배포.
  값 자리 = 노드 × 마스터 필드, 모든 노드에 항상 있다 (노출여부 없음 · 마스터 코드가 정한 선택 필드는 값이 없으면 화면에 안 보이고 세지 않는다). 구분자는 마스터 필드만 참조하는 식 하나 — 항등 투영(`= 레벨.필드`)도 허용.
  문면은 구분자만 본다. ~~폼 = 구조체 = 구분자 하나 (ADR-0001)~~ 는 유저 정의 폼과 함께 MVP 이후.
- 조건식·파생식 참조는 **경로**: `보험금지급.면책여부`.
- **필드 사전(공용 개념 등록처)은 두지 않는다** (오버엔지니어링 판단).
  ⚠ 감수 — 같은 개념 필드의 구조체 간 중복을 시스템이 못 막는다.
  [[00_시작/문제정의]] S2 의 보증 범위는 구분자(폼) 단위, 필드 중복은 운영 리뷰로.

### 부착 (2026-08-29 확정)

- **부착 레벨 5개: 상품 · 세목 · 담보 · 세부보장 · 급부.**
  조합 실체(상품담보 등)에 새 구분자를 부착하지 않는다 — 정의가 사는 곳은 5레벨뿐.
  상품담보에는 정의가 아니라 스냅샷 값이 산다.

### 파생 (2026-08-29 확정)

- 사내 유효값·파생 로직의 실제 분포 = **열거**와 **모델링 구조 의존**이 대부분.
  대표형: `보험금지급.면책여부 = any(급부별 면책여부)` — 사내에서는 이 식을 구분자마다
  개발 요청으로 코드에 심었다(블랙박스). **새 모델에서 파생식은 데이터다.**
- 집계 연산 6개 (2026-08-29 확정): `any` · `all` · `sum` · `count(distinct)` · `exist` · `not exist`.
  소비처 = 약관 문면의 if 조건식.
- **집계 범위 = 부착한 실체의 하위 트리.** 별도 범위 문법 없음 —
  세부보장에 부착하면 자기 급부들, 담보에 부착하면 자기 아래 전체.
  (기존 시스템은 담보 단위 고정 순회 → 세부보장 단위 조건식 불가 → 담보별 예외처리 폭발.
  **세부보장 단위 순회·조건식 지원이 이 프로젝트의 핵심 개선.**)
- 형제·타 담보 참조 식은 알려진 사례 없음 — 필요해지면 그때 참조 문법을 연다.
- **구분자 식의 참조 규칙** (2026-09-12, ADR-0036 · 0037): 식은 마스터 필드만 참조(구분자 → 구분자 없음), 경로는 `레벨.필드`, 같은 레벨 필드는 그대로,
  **하위 레벨 필드는 집계 안에서만**, 미입력은 오류 + 좌표, **MVP 는 상위 → 하위 방향만**. 별칭 금지는 구분자 사이에만 — 투영 구분자는 허용.
- **다단 파생은 MVP 제외.**
- **별칭형 파생(`A = B`)은 금지다** (2026-09-01 확정). 파생식은 실제 계산이 있어야 한다 —
  같은 값에 이름만 얹는 것은 중복 채번의 경위 재생산 ([[기능/구분자/구분자]]).

## 3. 문면

- **문면은 마스터 소유다.** 상품별로 문장을 고치지 않는다 — 상품 간 차이는 값이 가른다.
- **특약 문서 N : 담보 1.** 담보 하나에 문면 1벌, 탑재분마다 문서가 파생된다
  (「갱신형 일반상해사망 특별약관」·「일반상해사망 특별약관」 = 같은 문면 + 값 차이).
- **보통약관도 마스터 문서다.** 마스터 여러 벌 · 상품이 선택. 상품별 변주는 기본계약 연동뿐
  — 예외 1호: 공용조항 **옵션 오버라이드** (2026-09-01, [[기능/공용조항/공용조항]] §3.2 옵션 — 유효 옵션 집합 안에서만).
- **분기의 책임은 마스터 문면에 있다** (2026-08-29 확정).
  - 상품모델링은 개별 담보(특약)의 약관 내용을 수정할 수 없다 — 담보속성-담보 조합으로
    상품담보를 생성·탑재할 뿐, 문면에 영향을 주지 못한다.
  - 따라서 **담보약관 작성화면이 모든 케이스의 상품담보 문면을 처리해야 한다** —
    탑재분 간 달라지는 부분은 이 화면에서 조건문으로 미리 써 둔다.
  - **조건문은 if / elif / else 모드를 지원한다** (2026-08-29 확정).
  - **조건식의 참조 범위**: 상품모델링에서 사용한 **상품 레벨 구분자** + 그 화면에서 정하는 **담보 레벨 구분자**.

- **문면은 이름을 직접 부르지 않는다** (2026-08-29 확인).
  - 본문에서 상품담보명·상품명을 참조하는 일이 없다 — 「이 특별약관에서는」·「이 계약의」로 표현한다.
  - 따라서 **이름 치환 슬롯은 불필요**하다. 상품담보명·상품명은 문서 제목 등 메타 자리에만 쓰인다.
  - 지급률 같은 숫자값은 담보 레벨에서 기본값을 정의하고 상품모델링에서 상품담보별로 달리 정할 수 있다
    (스냅샷 모델 그대로). ~~종별로 다르게 하는 경우는 없다~~ → **같은 날 정정 — 종별 문구 차이 유즈케이스가 존재한다**:
  - **유즈케이스 (기억할 것, 2026-08-29)** — 담보 문면이 상품의 세목 구성에 의존하는 문구.
    예: 「1종(보험료납입면제미적용형)은 ~~~합니다」. 담보약관 작성 시점에는 그 상품에
    납입면제미적용형이 존재하는지, 몇 종인지 알 수 없다. 기존 시스템은
    `if 세목.납입면제미적용형.개수 > 1 → 단, {{세목.납입면제미적용형.종형명}}은 ~~~` 식으로 처리했다.
    **새 시스템은 이 방식을 그대로 만들지 않는다 — 단, 이 유즈케이스를 감당할 메커니즘은 필요하다** (미결).
    함의: ① 조건식이 세목의 존재·개수를 물을 수 있어야 하고 ② 상품의 종형 표기명을 문면에 찍는
    값 치환이 어떤 형태로든 존재한다.

- **조연결** — 담보약관의 각 조가 대응하는 보통약관 조를 안다 (UI 로 선택).
  보통약관에 이미 있는 내용을 담보마다 다시 쓰지 않기 위한 준용·생략의 기반.
  - ~~조합 옵션은 보통약관 템플릿 마스터의 각 조에 정의한다. 적용 단위 = 조 전체.~~ →
    **2026-09-06 정정**: 보통약관 조 옵션은 조 안 **block 공용조항 참조 노드**의 「비교 제외」 하나뿐.
  - **생략하기** 확정: (조 명 제외) 완전 동일하면 상품담보 쪽 조를 생략.
  - 기존 3종(생략·덮어쓰기·준용/생략 예외처리)을 그대로 따르지 않는다.
    → **2026-09-06 준용 규칙 확정** [[기능/조립산출/조립산출]]: 항 단위 자동 판정(생략/준용/통째) ·
    기본계약 수 0/1/2+ 가 보통약관 구조를 정함 · 1개 모드는 조연결 = 대치 · 준용규정 조는 조립 생성
    (ADR-0020 · ADR-0021).
- **부분 사전평가와 뷰 토글** (2026-08-30 확정 — MVP 포함).
  조건식은 문맥이 채워지는 만큼만 평가된다 — 담보약관 편집 문맥에서는 담보 레벨 조건은 평가 가능,
  상품 레벨 조건은 미결(조립 때 결정). 편집 화면은 **평가 가능한 분기를 사전평가해서
  타지 않는 분기를 톤다운(회색)** 표시하고, **사전평가 뷰 ↔ 전체 뷰 토글**을 제공한다
  (현행 시스템의 회색처리 방식 차용). → [[공통/화면/화면목록]] 편집기 요구사항.

- **공용조항** (2026-08-30 추가) — 담보약관들에 공통으로 나타나는 문구를 공통 템플릿으로 정의해 가져다 쓴다.
  - 실물 근거: 알파Plus 특약 10건 전부에 「특별약관의 소멸」·「준용규정」 조가 있다.
    단, **내용이 완전 동일하지는 않다** (사망 담보의 소멸 조는 문구가 다름) — 변형 처리 방식이 기획 쟁점.
  - 상세 기획 → [[기능/공용조항/공용조항]] (2026-08-31 합의 — 미결 없음).
  - **공용조항의 참조는 늦은 바인딩이다** (2026-08-31 확정 → [[README]] ADR-0010).
    공용조항은 평가 문맥을 갖지 않고 사용처 문서의 문맥에서 해소된다. 참조 범위는 제한하지 않되
    요구 구분자를 식에서 자동 추출해 **붙이는 시점에 부착을 검사**한다.

- **보통약관 문맥의 담보 레벨 참조는 기본계약으로 해소한다** (2026-08-31 확정 → [[기능/조립산출/조립산출]] §3.2 평가 문맥).
  보통약관 문면 전체에 적용되는 규칙이다(공용조항 전용 아님). 해소 시점은 조립 —
  기본계약 지정이 상품모델링이므로 보통약관 편집 화면에서 담보 레벨 조건은 미결로 남는다.
  MVP 의 기본계약 1개 전제([[00_시작/범위]])에 의존한다.

- **동적 처리는 3종이 전부다: 치환(슬롯) · 조건 분기 · 반복.** (기존 시스템 동일)
  - ~~MVP 는 반복문 제외~~ → **2026-08-30 번복 — 반복문 MVP 포함.**
    세부보장이 여러 개인 담보의 문면이 반복 없이는 성립하지 않는다:
    ① 제1조(보장범위)에 부착된 세부보장명들을 순서대로 기입
    ② 지급금액표의 세부보장별 행 (실물: 수술비 특약 1종수술~7종수술 표).

    **순회 소스는 모델링 구조**(문맥 담보의 하위 목록). 파생 집계의 「부착점 하위 트리」와 같은 결.
  - **모든 상품에서 같은 값은 const 구분자다** (2026-08-29 확정 — 텍스트로 적자는 초안을 같은 날 정정).
    일반 구분자는 템플릿 작성 시점에 값을 알 수 없지만(상품이 정한다), 평균공시이율 2.5% 처럼
    **템플릿 작성 시점에 값이 알려진 것은 const 구분자로 정의**한다 — 값은 마스터에서 정하고,
    템플릿은 이 구분자를 참조만 한다. 2.65% 로 바뀌면 마스터에서만 변경한다.
    **MVP 의 const 는 string 만** — 표시 형식 변환은 두지 않는다.
  - **조건 분기는 인라인(문장 중간)까지 반드시 지원** — 「~합니다. 다만, 갱신형의 경우 ~」.
- **별표는 독립 마스터다** (장해분류표 등). 상품약관은 문서들이 참조한 별표를 모아

  ~~나열 순서는 본문 등장 순으로 자동 계산~~ → **2026-09-07 개정 — 번호 = 상품 별표 목록의 순서**
  (ADR-0030(아카이브 → [[기능/별표/결정/ADR-0063-별표-자동수집-자동번호]])). 실물 번호는 등장 순이 아니라 책자의 고정 순서였다.

## 4. 조립

- 책자 순서는 고정: 표지 → 목차 → … → 보통약관 → 특별약관들 → 별표들.
- **MVP 는 보통약관 + 특별약관만 생성한다.** 표지·목차 등 앞부분 문서는 범위 밖.
- **특약 배치는 그룹핑이다** (2026-08-31 확정 — [[기능/조립산출/조립산출]]). 유저가 상품모델링에서
  그룹(타이틀)을 만들고 하위에 상품담보를 배치. 같은 담보의 탑재분은 뭉친다.
  한 그룹 = 한 보통약관 템플릿 (다중 보통약관은 MVP 이후 — [[00_시작/범위]]).
- **조립은 구체 문맥의 실행이다** (2026-08-31 확정 — ADR-0016). 오류는 실행이 밟은 자리에서만
  탐지, 부분 조립 + 오류 마커 + 좌표 목록, 오류 있으면 「완성본 아님」. 매번 재계산.
- **별표 MVP 범위: 목록 추가·조회 + 약관 본문 참조까지.** 별표 실제 출력은 만들지 않는다.
- 관통의 종점은 화면의 조립 결과 미리보기다. `.docx` 등 최종 서식은 뒤로 ([[00_시작/범위]]).

## 5. 파괴적 변경 — 역할로 가드 (2026-08-29 모드 확정 → 2026-09-04 역할로 대체)

> ~~개발 / 프로덕션 모드~~ 는 **2026-09-04 폐지** ([[공통/화면/결정/ADR-0019-모드폐지-역할권한]]).
> 파괴적 변경의 허용 여부를 시점(모드)이 아니라 **판단 주체(역할)** 가 가른다.

- **파괴적 변경은 관리자 역할만 실행한다.** 기준: 이미 저장된 값이나 참조를 없애는가.
  대표 사례: 탑재된 상품이 있는 담보의 구조 변경, 정의·enum 값·필드 삭제, 타입 변경, 부착 해제.
- **화면 숨김이 아니라 서버가 거부한다** — 숨김 ≠ 잠금. 역할 검사는 도메인 계층에 있다.
- **규칙은 한 벌이다** — 영향 범위(소실될 값 행·깨질 참조 목록)를 보여주고 확인 후 허용.
  깨진 참조는 오류 상태로 남아 관계정보 뷰·조립 오류에 드러난다.
- 구조 변경 시 값 처리 (2026-08-30 확정): **추가 노드는 기존 상품담보에 빈 값으로 나타나고,
  삭제 노드의 상품담보 값 행은 함께 삭제된다.** (마스터 기본값의 사후 복사는 두지 않는다 —
  탑재 시점 스냅샷 외의 두 번째 복사 시점을 만들지 않기 위해.)
- 구조체 **필드 추가는 비파괴**(새 자리 미입력, 편집자 가능) · **타입 변경·필드 삭제는
  영향 표시 + 확인 후 허용, 관리자 전용** (2026-09-01 규칙 · 2026-09-04 역할 적용 — [[기능/구분자/구분자]]).
- 역할은 MVP 에서 관리자 · 편집자 2종. 1인 사용 동안 현재 사용자 = 관리자.

## 6. 불변 규칙 (모아 두기)

- 값의 출처는 항상 하나다 — 정의는 5레벨의 마스터에, 상품담보에는 그 정의의 스냅샷 값만 ([[00_시작/문제정의]] S3).
- 구분자 추가·파생식 정의에 코드 배포가 필요하면 실패다 (S1 · S4).
- 문면·구조는 마스터 소유, 값만 상품 쪽에서 달라진다.
- **null 은 없고 미입력은 상태다** (2026-08-30 확정). 값 자리는 명시 값 또는 미입력 둘뿐.
  기본값은 폼 프리필 전용 — 저장소로 자동 유입되지 않는다. 평가가 미입력을 만나면
  오류 + 좌표 보고 — 아무도 확인 안 한 값으로 약관이 조립되지 않는다. 상세: [[기능/구분자/구분자]].
- **참조는 그래프이고 무결성은 타협 불가다** (2026-08-31 확정). 구분자·공용조항·조·별표 참조
  전부 — 순환·고아 탐지가 가능해야 하고, 관계정보 뷰(역방향 조회)는 MVP 필수.
  참조 추가 시점 검증 + 조립 시점 오류·좌표 보고. 상세: [[기능/문면/문면]].
- **구분자는 문면이 묻는 개념으로 딴다** (2026-08-30 확정). 그 개념이 지금 어떤 세목·운영 형태로
  팔리는지는 구분자의 정의에 넣지 않는다 — 값이 채워지는 경로가 바뀌어도 구분자는 그대로다.
  (재발 방지 대상 사례: 체증·체감납여부 ↔ 보험료가벼운납입형 중복 채번.
  체증체감납여부 = 개념 = 상품 레벨 구분자 / 가벼운납입형 = 운영 형태 = 세목 선택지.)
