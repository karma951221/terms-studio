## 목표

`(무)알파Plus보장보험2604` 실물 약관을 이 시스템의 데이터로 모델링해 **조립 결과가 원문과 같은 약관**이 되게 한다.
같은 과정을 **E2E 테스트로 고정**해 이후 회귀·확장(특약 10건 전부)에 재사용한다.

재현 범위 (2026-09-07 결정):
- 조·항·호·목 텍스트 · 관(款) 제목 · **정적 표** · **【용어풀이】 박스** · 조 참조 슬롯 · 별표 참조 슬롯.
- **가지번호는 쓰지 않는다** — 실물 `제27조의1` 은 순번으로 다시 매겨진다(제28조 …). 참조 슬롯이 계산 번호를 따라가므로 본문 참조는 어긋나지 않는다. 대조는 조 **순서 + 조 명** 기준.
- 종별 문구(1종/2종 행·「1종으로 가입한 경우」)는 이번엔 **정적 텍스트** (P7).
- 준용규정 조는 각 담보 문면에 **실물 텍스트 그대로** 쓴다 (조립 자동 생성은 「준용규정」 조가 있으면 건너뛴다 — 상세 자동 생성은 MVP 이후).
- 반복·동적 표(수술비 1~7종 등)는 범위 밖. 별표 내용 출력도 범위 밖.

## 1. 문면 모델 확장 (문면 §3.2)

노드 3종 추가. 허용 자식 규칙(ADR-0012)의 확장이며 저장 구조는 그대로다.

| 노드 | 자리 | 필드 |
|---|---|---|
| `section` | 문서 직속 (조와 섞여도 됨) | `title`, `children: (article \| condBlock)[]` |
| `table` | 항·호 뒤 — `article.children` · `paragraph.items` (`item.subitems` 는 실물에 없어 제외) | `title?`, `columns: { width?: number }[]`(% 너비), `rows: { header?: boolean; cells: string[] }[]` |
| `box` | 위와 같음 | `title`, `lines: string[]` |

- 조 번호는 관을 넘어 문서 전역 연속. 표·박스는 번호를 갖지 않는다.
- 표 서식 = **제목줄(header) 여부 · 열 너비** 두 가지. DB 의 트리 jsonb 에 노드 필드로 저장된다. 그 외 서식은 두지 않는다.
- 항이 정확히 하나인 조는 항 마커(①)를 찍지 않는다 (실물: 단항 조 전부 번호 없음). 번호 계산은 그대로, 렌더에서 생략.
- 준용 판정(ADR-0020)의 비교 단위에 표·박스를 각각 한 단위로 포함한다(항 뒤에 붙은 표가 다르면 다른 조).
- 편집기: section·table·box 추가·편집·삭제 최소형 — 표는 제목·행/열 추가·삭제·셀 텍스트·제목줄 토글·열 너비 입력.
- 미리보기 렌더: 관 제목 · 표(제목줄 굵게/음영, 열 너비 적용) · 박스(테두리).

## 2. ~~별표 번호 = 상품 별표 목록 순서 (ADR-0030)~~ — 폐기, ADR-0063 자동 수집 · 자동 번호

- 상품에 **순서 있는 별표 목록**을 둔다 (`product_appendices`: product_id · appendix_code · order). 번호 = 목록 위치(1부터).
- 본문이 참조한 별표가 목록에 없으면 조립 오류 + 좌표. 목록에 있으나 참조되지 않은 별표는 그냥 번호를 차지한다.
- 「참조된 별표만 모아 등장 순」 규칙(문면_기획 · 조립_기획)은 폐기.
- 상품 페이지에 별표 목록 편집(추가·순서·삭제) 최소형.

## 3. 문면 데이터 생성 — 변환 스크립트

`scripts/terms/convert.ts` (개발 도구, 제품 기능 아님):
- 입력: `docs/_자료/*_원문.md` (파싱양식). 출력: 시드 JSON 의 문서 트리 (`src/db/seed/data/generals.json` · `documents.json`).
- 관·조·항(`@`/`=`)·호·목·표·용어풀이를 기계적으로 노드로. `= 본문` 은 항 1개.
- 본문의 `제N조(제목)` / `제N조의M(제목)` 평문 → 제목으로 대상 조를 찾아 **조 참조 슬롯**(같은 문서 self / 담보약관에서 「보통약관 제N조」 앞 접두가 있으면 general). 「제1항」 등 항 참조는 같은 조 안 항 id 로. 못 찾으면 텍스트로 남기고 보고서에 기록.
- `【별표N(이름)】` → 별표 참조 슬롯 (코드는 별표 목록 정의에서 번호로 찾음).
- 결정적이며 재실행 가능. 노드 id 는 `문서코드-경로` 규칙으로 안정.
- 슬롯(담보명·평균공시이율)·공용조항 참조·조연결·인라인 조건은 변환 후 **오버레이 패치**(스크립트 안 표 형태)로 얹는다 — 원문 파일은 건드리지 않는다.
- 변환 결과는 서브에이전트(하위 모델)가 원문과 대조 검수한다.

## 4. 검증

- **정규화 대조기** `scripts/terms/compare.ts`: 조립 결과 문서트리 → 파싱양식 텍스트로 역직렬화 → 원문 `.md`(머리·통계·주석 제거, 조 번호를 조 명 기준으로 정규화, 공백 정리)와 **조 단위 diff**.
- Vitest `src/db/seed/real.test.ts`: 실물 시드 적재 → `assembly.preview` → complete · 보통약관 48조 + 특약 4벌이 원문과 일치.
- Playwright `tests/e2e/alpha-plus.spec.ts`(하이브리드): 마스터 재료는 시드, 화면으로 상품 생성 → 세목 2 + 조합 2 → 별표 목록 → 기본계약 1 + 특약 담보 탑재(부가유형 기본/추가) → 담보명 값 확인 → 그룹 → 미리보기 → 원문 대조. 문면 편집기는 「제1조(목적)」 한 조를 화면으로 작성해 시드 결과와 같은지 확인.
- 기존 「알파Plus(축약)」 시드·스모크·load 테스트는 실물 시드로 대체. 도메인 조립 스냅샷 픽스처는 그대로 둔다.
