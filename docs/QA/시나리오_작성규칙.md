# 시나리오 작성 규칙

> 상태: 초안 · 최종수정: 2026-09-27
>
> 옛 색인(`05_QA/시나리오/README.md`)은 `_archive/2026-09-27_문서재편/05_QA/시나리오/` 에 있다. 파서 · 좌표 설계는 [[QA/E2E_관측복구_설계]] §3.3, 깨졌을 때는 [[QA/E2E_복구절차]].

사용자 흐름 하나가 파일 하나. 사람은 시나리오 문서를 쓰고, E2E 는 그 문서를 정본으로 삼는다.

## 둘 곳 · 파일명

| 시나리오 | 둘 곳 |
|---|---|
| 한 기능의 흐름 | `기능/<feature>/시나리오/` — 목록은 그 기능 문서 §7 |
| 기능을 가로지르는 공통 흐름(역할 · 권한) | `공통/화면/시나리오/` |
| 인수 · 실물 재현 절차 | `QA/시나리오/` |

- 파일명은 `<흐름>_시나리오.md` (인수 시나리오는 `<흐름>_인수시나리오.md`). **파일명을 바꾸지 않는다** — `_시나리오.md` 앞부분이 E2E 좌표의 슬러그다(`그룹핑별표#5`).
- 옮길 때도 파일명 · 본문을 그대로 둔다.
- `실물재현_E2E_시나리오.md` 는 절차 문서라 좌표 체계에서 뺀다.

## 형식 — 파서가 읽는 모양

`scripts/e2e/scenarios.ts` 가 아래 모양만 읽는다. 어긋나면 `npm run e2e:coverage` 에 형식 오류로 뜬다.

```markdown
## 시나리오 N — <제목>
**전제**: <상태>
**흐름**:
1. <단계>
2. <단계>
**기대 결과**: <무엇이 보이고 무엇이 저장되나>
**경계·오류**:
- <막히는 경우와 그때 보이는 것>
```

- 머리 줄은 `## 시나리오 N — 제목`. 번호 N 은 파일 안에서 한 번 붙이면 바꾸지 않는다(좌표가 된다).
- 라벨 넷(`전제` · `흐름` · `기대 결과` · `경계·오류`)은 굵게, 콜론 뒤에 이어 쓴다. `흐름` 은 번호 목록, `경계·오류` 는 불릿이나 한 문단.
- 테스트 쪽은 Playwright annotation `{ type: "시나리오", description: "<슬러그>#<N>" }` 으로 이 좌표를 가리킨다.

## 쓰는 법

- 흐름은 유저액션(기능 문서 §4)을 순서대로 엮은 것이다. 단계마다 대응하는 액션이 있어야 한다 — 없으면 액션 누락이다([[공통/화면/유저액션_작성원칙]] 완전성 검사 ②).
- 기대 결과는 화면에 보이는 것과 저장소에 남는 것을 함께 쓴다. 입력률 · 진행 숫자를 기대 결과로 쓰지 않는다([[공통/화면/디자인원칙]] §9.2).
- 경계 · 오류는 서버가 막는 조건과 그때의 안내(해당 항목 · 수정 위치)를 쓴다.
- 시나리오는 사람이 쓰고 에이전트는 고치지 않는다 — E2E 가 깨지면 코드나 테스트가 시나리오를 따라간다([[QA/E2E_복구절차]]).
