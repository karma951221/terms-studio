# E2E 복구절차

> 상태: 합의 · 최종수정: 2026-09-08
> 설계: [[QA/E2E_관측복구_설계]] · 대상 문서: [[QA/시나리오_작성규칙]] · 층 분담: [[QA/테스트전략]]

E2E 가 깨졌을 때 에이전트가 따르는 절차. **사람은 시나리오 문서를 쓰고, 에이전트가 실행·진단·복구한다.**

## 1. 정본은 시나리오 문서다

시나리오 문서 `docs/**/시나리오/*.md`(기능별 `기능/<f>/시나리오` · `공통/화면/시나리오` · `QA/시나리오`)가 「무엇이 맞는 동작인가」의 유일한 근거다.
그래서 실패는 셋 중 하나로 갈리고, 조치가 각각 다르다.

| 판정 | 뜻 | 조치 |
|---|---|---|
| ① | 테스트가 문서를 잘못 옮겼다 (선택자 변경·대기 누락·단언 오기) | **테스트 수정** — 자율 |
| ② | 코드가 문서를 어겼다 (진짜 회귀) | **코드 수정** — 자율, 금지목록 제외 |
| ③ | 문서가 낡았다 (기획이 바뀌었는데 문서가 안 따라옴) | **수정 금지. 멈추고 사람에게 보고** |

③이 없으면 자율 복구는 반드시 스펙을 갉아먹는다. 「테스트를 고쳐 통과시키기」가 언제나
가능하기 때문이다. 판정에는 **정본의 문장을 인용**해야 한다 — 인용 없는 수정은 금지다.

좌표가 없는 테스트(`좌표없음`)는 대조할 문서가 없으므로 ③ 판정 자체가 성립하지 않는다.
진단서가 그 경우 ③을 빼고 낸다.

## 2. 절차

1. `npm run test:e2e` — 녹색이면 종료.
2. `test-results/failures/INDEX.md` 를 열고, 각 `FAILURE.md` 를 읽는다.
3. ①②③ 을 판정한다. **정본 인용 필수.**
4. ③ → **즉시 정지.** 「문서는 X 라는데 코드는 Y 다. 어느 쪽이 지금 기획인가」를 사람에게 보고한다.
5. ①② → 수정한다. 금지 목록을 건드려야 통과한다면 **③으로 강등하고 정지**한다.
6. `npm test && npm run typecheck && npm run lint` 가 전부 녹색인지 확인한다.
7. 1로 돌아간다. **최대 3회.** 초과하면 ③ 취급하고 정지한다.

수정은 **건별로 커밋**한다 — 잘못된 복구를 되돌리기 쉬워야 한다.

## 3. 안전핀 넷

- **금지 목록** — 아래를 고쳐야만 통과한다면 그건 회귀 은폐다.
  - `src/domain/**/__snapshots__/**` (조립 스냅샷)
  - `tests/fixtures/terms/*.md` (실물 약관 원문)
  - `docs/**/시나리오/*.md` (정본 자체)
- **판정 근거 의무** — 정본 인용이 없으면 수정 금지.
- **3회 상한** — 고치고 다시 깨지기를 세 번 넘기면 원인 이해가 틀린 것이다.
- **건별 커밋** — 한 커밋에 여러 판정을 섞지 않는다.

## 4. 진단서에 무엇이 있나

실패 1건마다 `test-results/failures/<슬러그>/` 에 한 벌이 떨어진다.

| 파일 | 내용 |
|---|---|
| `FAILURE.md` | **이것부터 읽는다.** 정본 인용 · 액션 타임라인 · 실패 구간 증거 · 재현 좌표 · 판정 체크박스 |
| `timeline.json` | 콘솔·서버 액션 POST·요청 실패를 시각 순으로 |
| `server.log` | 실패한 액션 구간의 dev 서버 로그 (서버 액션 예외·Drizzle 에러가 여기 있다) |
| `before.png` | 실패한 액션 **직전** 화면 |
| `at-failure.png` | 실패 순간 화면 (full page) |
| `trace.zip` | `npx playwright show-trace` 로 되감기 |
| `pgdata/` | `E2E_DUMP_DB=1` 일 때만 — 실행 DB 통째 |

**판정에 가장 쓸모 있는 것은 `server.log` 다.** 이 프로젝트는 화면 조작이 전부 서버 액션
POST 라, 그 응답이 200 이었는지 500 이었는지가 ①(테스트 잘못)과 ②(회귀)를 가른다.

## 5. 재현

매 실행이 golden 스냅샷을 복사한 새 DB 에서 시작하므로, 재현에 필요한 건 두 줄뿐이다.

```bash
# FAILURE.md 의 「재현」 절에 적혀 있다
npm run test:e2e -- --grep "<좌표 또는 테스트 제목>"
```

golden 해시가 진단서의 것과 다르면 스키마나 시드가 그 사이에 바뀐 것이다 — 그 자체가 단서다.

`E2E_FAST=1` 로 돌린 실행은 DB 를 재사용하므로 결정론이 깨져 있다. 진단서가 그 경우
경고를 박는다. **판정 전에 `E2E_FAST` 없이 다시 확인한다.**

## 6. 사람이 하는 일

- 시나리오 문서에 흐름을 쓴다 (`## 시나리오 N — 제목` + `**전제**` `**흐름**` `**기대 결과**` `**경계·오류**`).
- 기획이 바뀌면 **문서를 먼저 고친다.** 순서가 반대면 안 된다.
- ③ 보고를 받으면 문서를 갱신하고 다시 돌린다.

> ⚠ **「테스트 통과시켜줘」라고 지시하지 않는다.** 판정을 건너뛰고 초록불을 목표로
> 삼으라는 뜻이 된다. 올바른 지시는 언제나 **「문서대로 맞는지 확인해줘」**다.
