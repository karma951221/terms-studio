# 테스트전략

> 상태: 초안 · 최종수정: 2026-09-27
> 분담의 이유는 아래 「결정 메모」. 2차 구현은 전 영역 TDD 로 진행했다 (2차구현_계획(아카이브) §1).

## 무엇을 어느 층에서 검증하나

| 층 | 도구 | 무엇을 | 방식 |
|---|---|---|---|
| `src/domain/**` | Vitest (node) | 규칙 전부 — 식 언어·채번·값 규칙·트리 편집·번호·참조·사전평가·조립 | 순수 함수. 주입(문맥·조회)은 스텁. 문서트리·조립 결과는 **스냅샷** |
| `src/db/repo/**` · `src/services/**` | Vitest + **인메모리 PGlite** | 저장·트랜잭션·역할 거부·2단 확인·영향 계산 | `createTestDb()` — 테스트 파일마다 새 DB, `pushSchema` 로 스키마 코드에서 DDL |
| `src/services/container.test.ts` | Vitest + PGlite | **영역을 가로지르는 흐름** — 채번 → 담보 → 공용조항 부착 제안·수락 → 문서 → 탑재 → 관계정보 → 삭제 영향 | 실제 조립 루트로 |
| `src/services/assembly.test.ts` | Vitest + PGlite | 관통 1 — 실제 서비스로 픽스처 구성 → preview complete | |
| `src/forms/**` | Vitest (node) | 폼 모델·리듀서·zod, 컴포넌트 마크업 | jsdom 없이 `renderToStaticMarkup` |
| `src/app/**` | `next build` + Playwright 소수 | 라우트 존재·서버 액션 입력 파싱·로그인 → 미리보기 스모크 | 화면이 깨졌나만 |

**분담 — Vitest 스냅샷이 대부분, Playwright 는 소수 정예.** 조립 · 조건 평가 · 파생 · 번호 계산은 문서트리 스냅샷(Vitest), 에디터 · 폼 렌더러 등 핵심 화면 흐름만 E2E.
— 왜: 핵심 로직이 전부 순수 데이터 변환이라 브라우저 없이 밀리초 단위 회귀가 되고, 조립을 E2E 로 보면 「조립이 틀렸다」와 「화면이 깨졌다」가 섞인다. 이 분리는 `src/domain` 순수층(ESLint import 차단)으로 구조에도 박혀 있다.

테스트 설명은 **시나리오 문장 그대로**(한국어) — [[QA/시나리오_작성규칙]] 역방향 대조가 곧 테스트 목록이다.

## 자동화 범위

- `npm test` (vitest) · `npm run typecheck` · `npm run lint` — 전부 녹색이 커밋 조건.
- 관통 1 은 `src/domain/assembly/assembly.test.ts` 스냅샷이 고정한다: 기본계약으로 대치된 보통약관 +
  특약 2벌(항 단위 생략·준용·통째, 본문 동일·제목만 다름) · 다중 항 참조 · 별표 번호 1 · issues 0 · complete true.
  조립 로직을 바꾸면 스냅샷 diff 로 영향이 드러난다.
- 시드(`npm run db:seed`)는 마지막에 `assembly.preview` 로 complete 를 확인한다 — 시드 데이터가 곧 회귀 픽스처.
- Playwright 관통 스모크는 로그인 → 상품 → 미리보기에서 대치 본문·특약 4벌·오류 패널 0건을 확인한다.
- **★ 실물 재현 (2026-09-07~08)** — 시드 정본이 실물 알파Plus(보통약관 52조·관 7 + 특약 4벌)다.
  `src/db/seed/real.test.ts` 가 시드 → 조립 → 원문(`tests/fixtures/terms/*.md`) 대조를 조 단위로 고정하고,
  `tests/e2e/alpha-plus.spec.ts` 가 상품모델링을 화면으로 수행한 뒤 미리보기 DOM 을 같은 기준으로 대조한다
  (하이브리드). 대조 기준·재료·갱신 절차는 [[QA/시나리오/실물재현_E2E_시나리오]].

- **E2E 관측·복구 장치 (2026-09-08)** — 매 실행이 golden 스냅샷을 복사한 새 DB 에서 시작하고(결정론),
  실패하면 `test-results/failures/<슬러그>/FAILURE.md` 에 정본 인용·액션 타임라인·서버 로그·스크린샷·
  재현 좌표·판정 체크박스가 한 장으로 떨어진다. 시나리오 문서가 정본이라 실패를 ①테스트 ②코드 ③문서로
  가른다 — 절차는 [[QA/E2E_복구절차]], 설계는 [[QA/E2E_관측복구_설계]].
  `npm run e2e:coverage` 가 시나리오 ↔ E2E 역방향 대조표를 낸다 (위 「시나리오 문장 그대로」의 기계화).
