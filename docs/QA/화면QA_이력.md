# 화면 QA 이력

> 상태: 초안 · 최종수정: 2026-09-09

실물 화면을 띄워 놓고 **무엇을 지적해서 어떻게 바뀌었는지**를 회차별로 남긴다.

화면의 **현재 모습**은 [[공통/화면/화면목록]] 아래 각 화면기획이 정본이다.
여기 남는 것은 두 가지뿐 — **왜 그렇게 됐나**, 그리고 **다음에 같은 판단을 다시 하지 않도록 굳은 규칙**.
되돌리기 어려운 결정은 [[README]] 에 ADR 로 따로 있다.

---

## 2026-09-09 · 1회차 — 구분자 탭 전면 · 목록 · 생성 화면 공통화 · 별표 화면

### 경위

실물 시드(알파Plus)를 얹은 화면을 브라우저에 띄워 놓고 한 항목씩 지적 → 수정 → 재확인을 반복했다.
**여러 세션이 같은 작업 트리에서 병행**했다 — 아래 B · C 는 다른 세션의 작업이고,
그 세션이 넘긴 요약과 코드를 함께 보고 **화면에 드러나는 것만** 골라 적었다.
도메인 · 저장소 · 시드 · E2E 변경은 이 문서 범위 밖이다 (해당 ADR 로 링크만 건다).

### A. 구분자 탭 (지시 → 반영)

| # | 지적 | 반영 | 근거 |
|---|---|---|---|
| A1 | 폼은 구분자 탭 말고 따로 분리 | 목록 · 생성에서 폼 제외, `/catalog/<폼코드>` 는 폼 탭으로 리다이렉트. `createStructAction` 폐기 | ADR-0031(아카이브 → [[기능/구분자/결정/ADR-0036-폼-구분자-문면-3층]]) |
| A2 | 노출여부를 라디오로 | 체크박스 → 2지선다 라디오 + 고른 값의 뜻풀이 한 줄. 생성 · 수정 · 폼 화면 넷 다 | 규칙 R2 · R3 |
| A3 | 옵션 설명이 없어 난감하다 | 고른 옵션의 뜻풀이를 라디오 바로 아래에. ⓘ 툴팁은 같은 말이라 걷음 | 규칙 R3 |
| A4 | 라벨과 표시명이 분리돼 있다 · 필드가 너무 많다 · 중요도가 안 보인다 | 「구분자명」으로 이름 통일, 설명 칸 제거, 선택지는 조건부 노출 | 규칙 R4 |
| A5 | 세로로 길어지지 않게 — 한눈에 다 들어와야 | 1열 스택을 버리고 **2열 그리드 복귀**(§2 L2). 화면 높이 470px → 190px | 되돌린 것 U1 |
| A6 | 유형을 바꿔도 구분자명 · 레벨은 남아야 | 유형별 `<form>` 셋 → **폼 하나 + 서버 액션 교체**. 유형별 칸은 `hidden` 이 아니라 실제로 뺀다 | 규칙 R7 |
| A7 | 구분자 목록의 노출 컬럼은 필요 없다 | 컬럼 · 필터 제거 (폼 목록에는 유지 — 거기선 값이 늘 있다) | — |
| A8 | 「종류」 · 「단일값」이 어색하다 | 「유형」 · 「일반」. 2026-09-06 Q-B 확정을 번복 | ADR-0032(아카이브 → [[기능/구분자/결정/ADR-0036-폼-구분자-문면-3층]]) |
| A9 | 목록에 수정시간 · 수정자 | 최종수정 · 수정자 컬럼. `discriminatorAudits` 로 한 판에 조회 | 규칙 R11 |
| A10 | 상세 헤더의 이름 · 코드 · 사용처가 어색하다 | 헤더에서 빼고 **코드를 첫 필드**로. 돌아가기가 헤더 줄로 (`EditShell` 의 `bareHead`) | — |
| A11 | 유형이 disabled 입력칸처럼 보인다 | 코드 · 유형 · 레벨을 `.ts-field-static`(칠 없는 글자)로 | 규칙 R5 |
| A12 | 사용처 탭이 자리를 너무 먹는다 | 좌우 2열 폐기 → 헤더 버튼 + 모달(`showModal`). 편집 모드에선 버튼을 감춘다 | 규칙 R9 |
| A13 | 편집 모드 행간이 부자연스럽다 | 편집 모드 행 여백 확대 · 값이 두 줄인 행은 라벨 상단 정렬 | 규칙 R10 |
| A14 | 새 구분자에 뒤로가기가 없다 → (1차) → 배치가 어색하다 | 제목 위 별도 줄 → **제목 줄 breadcrumb** 「구분자 › 새 구분자」 | 되돌린 것 U4 |
| A15 | 노출 기본값을 「항상 노출」로 · 문구도 | `defaultValue` 를 `true` 로. 「무조건/선택」 → 「항상 노출/선택 노출」 | 시드 5건이 전부 `alwaysExposed: true` (§9.1) |
| A16 | 타입도 라디오로 · 「예/아니오」 → 「참거짓」 · 날짜 제거 | 라디오 4종. 날짜는 **선택지에서만** 뺐다 (도메인 `date` 는 유지) | 규칙 R6 |
| A17 | 「선택형」 → 「목록값」 · 「선택형(복수)」 대신 list 체크박스 | 선택지 하나 + `list 타입` 체크박스. `enum` ↔ `list<enum>` 변환은 `_lib/fieldType` | 규칙 R12 |
| A18 | 체크박스와 선택지가 목록값에 딸린 게 안 보인다 | 라디오 아래 **카드**로 묶음(`.ts-field-card`). 「선택지」 → 「열거형변수」 | 규칙 R8 |
| A19 | 드롭다운 말고 검색되는 입력칸 | `Combobox` 신규 — 표시명으로 검색, 폼에는 코드가 실린다 | 규칙 R13 |
| A20 | 라디오 간격이 좁고 고른 게 잘 안 보인다 | 간격 12 → 20px, 고른 항목은 굵기 + 진한 색. **앱 전체 라디오 · 체크박스에 적용** | 규칙 R14 |

### B. 목록 · 생성 화면 공통화 (다른 세션)

| # | 무엇 | 결과 |
|---|---|---|
| B1 | 목록 화면 8개가 같은 조립을 손으로 반복 | `_components/ListPage` 로 모음 — 화면은 컬럼과 빈 상태만 기술한다. 구분자 · 공용조항 · 담보 · 문면 · 상품 · 별표 · 선택지 · 폼 |
| B2 | 컬럼을 강제하지 않는다 | 담보 · 상품 마스터에는 코드가 없다 — **도메인에 없는 값을 화면이 지어내지 않는다**. 낼 수 있는 컬럼만 각 화면이 적는다 |
| B3 | 생성 화면 머리 | `FormRow` + `CreateHead` — 2열 한 줄, 제출은 헤더 우측 |
| B4 | 「설명」을 늘 펴 두면 생성 폼이 필드마다 결정을 시킨다 | `NoteField` — 「주석」으로 이름을 바꾸고 **접어 둔다**. 값이 있으면 펴진 채 시작 |
| B5 | 목록에 최종수정 · 수정자 | 공용조항 · 문면 · 담보 등으로 확산. `formatDate` · `todayInSeoul` 를 `_lib/list` 로 |
| B6 | 표 안 링크의 밑줄 | `.ts-table a { text-decoration: none }` — 행마다 밑줄이 그어지면 괘선과 싸운다 |
| B7 | 한 화면에 목록이 둘일 때 | `ListFilterBar` 에 `queryKey` — 문면처럼 목록이 둘이면 검색 파라미터를 나눈다 |

### C. 별표 화면 (다른 세션)

별표 코드를 시스템 채번으로 바꾼 [[기능/별표/별표]] §3.1 이 화면까지 끌고 온 변경이다.
도메인 · 시드 · E2E 쪽(코드 21건 `APX01_INTEREST…` → `AX000001…`)은 그 ADR 이 정본이다.

| # | 무엇 | 결과 |
|---|---|---|
| C1 | 별표 목록이 **편집형 표**였다 — 행마다 입력칸과 저장 버튼 | 조회형 표로 접었다: `코드 · 이름(상세 링크) · 설명 · 최종수정 · 수정자`. 인라인 rename · setDescription · remove 액션도 함께 폐기 |
| C2 | 고치는 자리가 없다 | `/appendices/<code>` **상세 화면 신규** — `EditShell` 로 이름 · 설명 편집, 삭제는 영향 확인 2단, 사용처는 모달 |
| C3 | 등록 화면이 코드를 사람에게 물었다 | **코드 입력칸 제거.** 등록하면 채번된 코드로 상세로 이동. `NewAppendix` 에서 `code` 를 없애 **입력 경로 자체를 타입으로 막았다** |
| C4 | 코드 예시가 옛 규칙 | 관계정보 조회의 placeholder `APX1` → `AX000001` |

**오늘 만든 조각이 바로 재사용됐다** — 별표 상세는 `EditShell` 의 `extraActions` 에 `UsageDialog` 를 그대로 물렸다.
사용처를 모달로 뺀 판단(A12)이 구분자 한 화면의 사정이 아니었다는 뜻이다.

### 여기서 굳은 규칙

다음에 같은 판단을 반복하지 않도록. 어긋나야 할 이유가 생기면 그때 ADR 로 남긴다.

| | 규칙 | 왜 |
|---|---|---|
| **R1** | 한 실체를 두 목록에 두지 않는다. 입구는 하나다 | 「목록엔 없는데 만들 땐 있는」 상태가 가장 나쁘다 (ADR-0031) |
| **R2** | 2지선다는 체크박스가 아니라 라디오 | 체크박스는 꺼진 상태에 **이름이 없다**. 두 상태 중 하나를 고르는 일이라는 게 화면에 안 드러난다 |
| **R3** | 고를 때 읽어야 하는 설명은 툴팁이 아니라 그 자리에 | ⓘ 는 「궁금하면 보라」다. 고르는 근거는 숨기지 않는다. 같은 말을 툴팁과 본문에 두 번 적지 않는다 |
| **R4** | 같은 개념의 이름은 한 곳(`_lib/labels`)에서만 낸다 | 표시명 · 라벨 · 구분자명이 갈려 있었고, 노출 문구가 네 곳에 흩어져 있었다 |
| **R5** | 「지금은 못 고침」과 「여기선 못 고침」은 다른 옷을 입는다 | `.ts-field-locked`(회색 칸, 편집 누르면 입력칸이 됨) ↔ `.ts-field-static`(글자, 끝까지 안 바뀜) |
| **R6** | 화면에서 고를 수 있는 것과 표시할 수 있는 것을 가른다 | 날짜는 새로 못 고르지만 이미 날짜인 값은 「날짜」로 보여야 한다 (`SELECTABLE_TYPE_KINDS` ↔ `TYPE_LABEL`) |
| **R7** | 안 쓰는 칸은 `hidden` 이 아니라 **뺀다** | 숨은 칸의 `required` 가 보이지도 않는 이유로 제출을 막는다 |
| **R8** | 어떤 선택지를 골라서 나타난 칸은 그 아래 카드로 묶는다 | 흩어 놓으면 「이게 왜 생겼나」가 안 보인다. 반대로 **평범한 필드 하나를 카드로 싸면 딴 데서 온 조각처럼 보인다** |
| **R9** | 편집 중에는 부가 조작을 감춘다 | 편집 모드에서 해야 할 일은 저장 · 취소뿐이다 |
| **R10** | 편집 모드는 읽기 모드보다 행 여백이 넓다 | 글자 줄은 붙어 있어도 목록으로 읽히지만 테두리 있는 상자끼리는 그렇지 않다 |
| **R11** | 목록에는 최종수정 · 수정자를 낸다 | 여럿이 만지는 카탈로그에서 「언제 · 누가」가 없으면 손대도 되는지 판단이 안 선다. 도메인은 사용자를 모르므로 id → 이름은 화면이 붙인다 |
| **R12** | 화면이 받는 모양과 도메인 타입이 1:1일 필요는 없다 | 「목록값 + list 체크박스」 하나가 도메인의 `enum` · `list<enum>` 둘로 간다. 변환은 한 파일에 모은다 |
| **R13** | 항목이 늘어나는 선택은 검색되는 입력칸으로 | `<select>` 는 타이핑으로 못 좁힌다. `<datalist>` 는 표시명을 보이면서 코드를 실을 수 없다 |
| **R14** | 고른 항목은 표식 하나에만 기대지 않는다 | 라디오 동그라미만으로는 선택지가 여럿일 때 훑어서 안 보인다. 굵기 · 색을 함께 |
| **R15** | 도메인에 없는 값을 화면이 지어내지 않는다 | 담보 · 상품에는 코드가 없다. 컬럼을 맞추려고 빈 칸을 만들지 않는다 |
| **R16** | **코드는 사람에게 묻지 않는다.** 생성 화면에 코드 칸을 두지 않고, 생성 입력 타입에서 `code` 를 빼 경로 자체를 막는다 | 물으면 「다음 번호가 몇 번인지」를 사람이 찾아 중복을 피해야 한다. 채번이면 중복 거부 규칙도 함께 사라진다 ([[공통/기술/결정/ADR-0005-코드-표시명-이중체계]] · [[기능/별표/별표]] §3.1) |
| **R17** | **목록에서 인라인 편집하지 않는다.** 목록은 고르는 자리, 고치는 자리는 상세다 | 행마다 입력칸과 저장 버튼을 두면 목록이 표가 아니라 폼 더미가 된다. 별표(C1) 이전에 선택지(`/catalog/enums`)에서 같은 판단을 한 적이 있다 |

### 했다가 되돌린 것

같은 길을 다시 걷지 않도록 남긴다.

| | 시도 | 왜 버렸나 |
|---|---|---|
| **U1** | 생성 화면을 **1열 스택**(라벨을 값 위에)으로 | 세로가 두 배가 되어 「한눈에」가 깨진다. 2열 그리드(§2 L2)로 복귀 — 원칙이 이미 옳았다 |
| **U2** | 중요도 **2단**(주요는 크게 · 부가는 괘선 아래 작게) | 칸마다 생김새가 달라진 것이 먼저 눈에 걸렸다. **서식은 하나로 두고 순서로 중요도를 말한다** |
| **U3** | 「유형」을 **카드**로 감싸기 | 다른 필드는 다 한 줄인데 하나만 카드라 딴 데서 온 조각처럼 보였다. 카드는 **조건부로 딸려 나오는 묶음**에만 (R8) |
| **U4** | 뒤로가기를 제목 **위 별도 줄**에 | 줄 하나를 링크 하나에 쓰고 제목 · 조작 버튼이 다른 줄로 흩어진다. 제목 줄 breadcrumb 으로 |
| **U5** | 설명 칸을 부가 단에 **작게** | 혼자 서식이 달라 거슬린다. 결국 구분자에서는 **없앴고**, 생성 폼 전반에서는 **접었다**(B4) |
| **U6** | `scalar` 를 「단일값」으로 (2026-09-06 확정) | 폼이 목록에서 빠진 뒤 「무엇에 대한 단일」인지 근거가 사라졌다 → 「일반」 (ADR-0032) |

### 남은 것

- **Q-E. 「유형」이 세 가지를 가리킨다** — 내비 「유형」(선택지 · 폼) · 구분자의 「유형」 · 「타입」.
  ADR-0032(아카이브 → [[기능/구분자/결정/ADR-0036-폼-구분자-문면-3층]]) 이 **제안** 상태로 열려 있다.
- **「열거형변수」 ↔ 내비 「선택지」** — 필드는 열거형변수인데 탭 이름은 선택지다. 어느 쪽으로 통일할지 미정.
- **목록 컬럼 헤더는 아직 「표시명」** — 구분자 폼에서는 「구분자명」으로 통일했으나 목록은 전 화면 공통이라 손대지 않았다.
- **카드 · 콤보박스가 새 구분자에만 있다** — 구분자 수정 · 폼 편집의 같은 자리는 문구만 맞췄고 모양은 예전 그대로다.
- **`CreateForm` 이 `FormRow` · `CreateHead` 와 겹친다** — 같은 것을 두 세션이 각자 만들었다. 하나로 모을 것.
- **별표 화면기획 문서가 없다** — `02_UI/화면/` 에 관계정보 · 구분자 · 담보 · 유형만 있다. 별표 목록 · 상세 · 생성이 실물로 생겼으니 화면기획도 있어야 한다.
- **죽은 CSS** — `.ts-l2-split` 은 어디서도 안 쓴다. `.ts-l2-side` · `.ts-l2-side-title` 은 사용처 모달 안에서만 쓰이는데 이름도 스타일도 안 맞는다.
- 이번 회차는 **커밋되지 않았다** (2026-09-09 기준). 여러 세션의 변경이 한 트리에 섞여 있다.
