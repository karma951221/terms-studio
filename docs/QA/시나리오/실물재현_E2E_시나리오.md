# 실물재현 E2E 시나리오

> 상태: 초안 · 최종수정: 2026-09-28 (두 번째 상품 메리츠 · 공용조항 두 상품 공통으로 재편)

## 1. 목적

실물 `(무)알파Plus보장보험2604` 약관 — 보통약관 52조(관 7) + 특약 10벌(기본계약 = 일반상해80%이상후유장해) —
을 이 시스템의 데이터로 재현하고, **조립 결과가 원문과 같음을 자동으로 확인**한다. 같은 과정을 회귀 방지로 고정한다.
두 번째 상품 `무배당 메리츠 통합간편건강보험(연만기형)2607(통합간편심사형)` — 보통약관 54조 + 기본계약(일반상해사망) + 특약 표본 8 — 을 같은 방법으로 더했다(2026-09-28, [[QA/실물재현/메리츠_모델명세]]).
두 상품은 카탈로그 · 별표 마스터 · 공용조항(36건)을 함께 쓴다 — 두 원문에서 같은 글은 공용조항 하나, 낱말만 다르면 옵션.

## 2. 대조 기준

- 조 명 + 본문. **조 순서는 판정하지 않는다**(2026-09-28, [[QA/인수기준]] 허용 차이 ⑥) — 조를 다중집합으로 짝짓고(`diffArticlesUnordered`), 대신 조립 결과의 조 번호 · 조 참조 번호가 조립 순서와 맞는지 따로 본다(`referenceNumberIssues`). 관 제목 순서는 같아야 한다.
- 조·관 번호 참조는 조 명으로 정규화한다 — 가지번호를 쓰지 않으므로([[기능/문면/문면]] §3.2) 「제27조의1(」과
  「제28조(」은 같다고 본다.
- 공백은 전부 지우고 비교한다.
- ~~별표 번호는 남긴다 — 조립이 본문 등장 순으로 매긴 번호다.~~ → 2026-09-15 번호는 **지우고** 이름만 대조한다 (`【별표N(` → `【별표§(` · `compare.ts`) — 등장 순 자동 번호라 실물과 어긋나는 것이 허용 차이이기 때문이다 ([[기능/별표/결정/ADR-0063-별표-자동수집-자동번호]] · ADR-0030 대체 · [[QA/인수기준]] 실물 재현 인수 표 허용 차이 ②).
- 표·박스는 파싱양식의 fenced 블록 형태로 되돌려 비교한다. 표 셀도 인라인 노드라 셀 안의 조·별표 참조가
  계산 번호로 찍힌다 (2026-09-08).

기준 코드는 `src/domain/assembly/compare.ts`(순수층 — DB·React·`fs` 미사용, 파일 읽기는 호출자 몫).

① **Vitest** `src/db/seed/real.test.ts` — 실물 시드 적재 → 조립 미리보기 → 원문 대조.

`npm test` 로 돈다.

② **Playwright** `tests/e2e/alpha-plus.spec.ts` — 하이브리드: 마스터 재료(구분자·담보·별표·보통약관·담보약관 문면)는

조합 2 → 탑재(기본계약 담보 1 + 특약 담보 4, 일반상해사망보장은 부가유형 기본/추가로
구별) → 특약 그룹 생성·배치 → 조립 미리보기 → 보통약관 + 특약 4벌을 원문과 대조. 별도 테스트로 문면 편집기 최소
경로(관 안에 제1조(목적)를 화면으로 작성 → 시드 결과와 같은 렌더)도 확인한다.

③ **스모크** `tests/e2e/smoke.spec.ts` — 화면이 깨졌나만 본다([[QA/테스트전략]]). 조립이 맞는지는 ①·②의 몫.

- 보통약관은 **가져오기 화면이 없어** 시드로 넣는다(명세 §6 권고). 별표와 **보통약관이 쓰는 공용조항**(두 보통약관이 함께 쓰는 C0001 ~ C0019)은 보통약관 트리가 참조해 그보다 먼저 있어야 하므로 함께 시드다 — 그래서 공용조항 코드가 앞에 모여 있다(변환기가 검사). 화면 E2E 는 C0020 부터 친다.
- 따라 칠 데이터는 시드 JSON 정본을 그대로 읽는다(`_lib/seed.ts`) — 명세를 손으로 옮기면 두 벌이 갈린다. 코드는 시스템 채번이라 명세 §1 순서대로 만들면 명세의 코드가 나오고, 스펙이 그것을 확인한다.
- 에디터는 두 단계로 친다 — 뼈대(조 · 블록 · 조연결 · 조 자리 조건) → 문장(조 참조가 뒤 조를 가리킬 수 있어 대상이 먼저 있어야 한다). 화면 자리와 시드 노드는 조 안 문서 순서로 맞춘다.
- 문장 안 조건은 사람이 하는 대로 — 글을 골라 「조건식」, 가지 칩은 가지 칸에서 오른쪽 클릭 › 넣기.
- 판정 줄: 미리보기 화면(DOM)을 `renderedToLines` 와 같은 파싱양식으로 되돌린다(`_lib/compare.ts`). 시드로 조립한 결과와 글자까지 같음을 개발 중 확인했다(2026-09-28).

실행법:

- ①~③: `npm run test:e2e` — golden(알파Plus 전량 시드) DB, dev 서버 자동 기동. `tests/e2e/real/` 는 돌지 않는다.
- ④: `npm run test:e2e:real` (= `E2E_PROFILE=real playwright test`) — 바탕 DB(별표 + 보통약관) golden 을 새로 복사해 dev 서버를 띄우고 01 → 05 를 차례로 돈다(한 흐름 — 앞 파일이 만든 것을 뒤 파일이 쓴다). 약 3.5분(2026-09-28, 두 상품 61건 — 한 명령으로 둔다).
- 한 단계씩 고칠 때: 떠 있는 서버에 붙는다 — `E2E_PROFILE=real E2E_EXTERNAL=1 E2E_BASE_URL=http://localhost:<port> npx playwright test 04-templates`. 그 서버의 DB 가 01~03 을 거친 상태여야 한다. `E2E_DUMP=<폴더>` 면 05 가 화면에서 읽은 줄을 문서마다 남긴다.

## 5. 시드 갱신 절차

1. 원문 `.md`(파싱양식, `docs/_자료/파싱양식.md` 규칙)를 `tests/fixtures/terms`(다른 상품이면 그 아래 상품 폴더 — `메리츠/`)에 복사한다.
2. `scripts/terms/config.ts`에 등록한다(신규 특약이면 §6 참고).
3. `npm run terms:convert` 실행.
4. stdout 의 `[report]`(변환 못 한 참조 — 법령 인용은 의도된 미변환) · `[invalid]`를 확인한다.
5. `npm test` 로 `real.test.ts` 통과를 확인한다.
6. `rm -rf .data && npm run db:seed` 로 개발 DB를 다시 적재한다.

## 6. 새 담보를 추가할 때

1. 원문 파일을 `tests/fixtures/terms`에 복사한다.
2. `scripts/terms/config.ts`의 그 상품 담보약관 목록(`ALPHA_SPECIALS` · `MERITZ_SPECIALS`)에 항목을 추가한다 — `code` · `ownerCoverage` · `idPrefix` · `file` · (필요시) `slots` 오버레이 · `clauses`(공용조항 쓰임 — 원문 조 · 항 → 공용조항 · 옵션). 소멸 조는 담보 구조 유형(모델명세 §3.2)대로 조합한다. 변환기는 공용조항 렌더가 원문 자리와 글자 그대로 같을 때만 바꾸고, 다르면 `[report]` 로 남긴다.
3. `src/db/seed/data/coverages.json`에 담보(담보명 값)를, `products.json`의 `mounts`에 탑재(필요하면 `attributes`)를 추가한다.
4. `npm run terms:convert`로 변환한다.
5. `real.test.ts`의 `it.each` 목록과 `alpha-plus.spec.ts`의 `SPECIALS`·탑재(mount) 단계에 추가한다.
6. §5의 대조 절차로 확인한다.

## 7. E2E 작성 시 주의 (실제로 겪은 것)

- 같은 URL로 돌아오는 서버 액션 제출은 `waitForURL`이 즉시 풀린다 — POST 응답 + `networkidle`을 함께 기다린다(`submit` 헬퍼).
- 탑재는 새 상품담보의 값 화면으로 이동하므로, 다음 탑재를 위해 상품 페이지로 돌아온다.
- 그룹 제목은 입력칸 값이라 `hasText`로 못 찾는다 — 배치 버튼의 접근성 이름으로 폼을 잡는다.
- 문면 편집기의 넣기 · 조작 입구는 본문 위 툴바(`role=toolbar` 「약관 편집 도구」)이고, 오른쪽 클릭 메뉴는 같은 목록의 지름길이다 — `click({ button: "right" })` 뒤 `menuitem`(`menu` 헬퍼). 조건 넣기는 툴바 「조건식」에만 있다 (2026-09-27).
- 문면 편집기의 제목 · 문장 칸은 contenteditable(`role=textbox`)이다 — `fill` 뒤 Enter(제목) · Tab(문장)으로 초점을 옮겨야 편집본에 들어간다.
- 해시만 바꾸는 리다이렉트(`#appendices`)는 서버 데이터를 다시 받지 않는다 — 쿼리를 함께 바꿔야 새 목록이 보인다.
- 새 dev 서버는 화면을 처음 열 때 컴파일하고 JS 가 늦게 붙는다 — 그 전에 친 입력은 React 상태로 덮여 사라진다(빈 칸 제출). ④ 는 이동마다 `networkidle` 까지 기다린다(`_lib/app.ts` `open` · `arrive`).
- 문장 칸의 커서 끝은 `Meta+ArrowDown`(mac) · `Control+End` — `End` 는 접힌 줄의 끝일 뿐이다. 칩을 넣으면 칸이 새로 그려져 초점을 잃으므로 칩마다 다시 초점 → 끝.
- 이미 초점이 있는 칸에 `focus()` 는 자리를 다시 알리지 않는다 — 한 번 `blur()` 하고 잡는다.
- 새 박스는 제목 「용어풀이」로 선다 — 제목 없는 박스(원문 「【】」 없음)는 제목을 비워야 한다.

## 8. 알려진 한계

- 화면 E2E ④ 가 찾아 고친 것(2026-09-28): 조건 머리 줄에 담보속성이 없어 갱신형 조건을 만들 수 없었다([[기능/문면/문면]] §3.3) · 조 제목 자리에서 공용조항 블록을 넣을 수 없어 첫 자리가 공용조항인 조(준용규정)를 못 세웠다 · 담보속성 상세가 저장 뒤 서버 채번 코드 대신 「새 값」을 보였다(L2 편집 셸이 새 원본을 받지 않았다).
- 화면 E2E ④ 가 찾아 고친 것(2026-09-28 메리츠): 공용조항이 36건이 되자 툴바 「공용조항」 고르기 메뉴가 화면 밖으로 넘쳐 아래 줄을 누를 수 없었다(메뉴를 화면 높이 안에서 스크롤) · 운전기가 옵션 자리 메뉴를 옵션 코드로 찾았다(메뉴 줄은 옵션명 — 옵션 둘 이상인 공용조항에서 드러났다).
- 화면 E2E ④ 가 화면으로 넣지 않는 것: 별표 21 · 보통약관 두 벌 · 보통약관이 쓰는 공용조항 C0001 ~ C0019(시드). 둘째 행 이후 제목줄 · 옵션 있는 공용조항 블록 · 관이 있는 담보약관은 이 모델에 없어 운전기가 치지 않는다(만나면 멈춘다).

- 가지번호(제27조의1 등)는 순번으로 다시 매긴다 — 실물 번호 표기 자체는 재현하지 않는다.
- 종별 문구(1종/2종 행·「1종으로 가입한 경우」)는 이번엔 정적 텍스트다.
- 준용규정 조는 각 담보 문면이 상품의 준용규정 공용조항(알파Plus C0035 · 메리츠 C0036) 참조로 둔다(알파Plus 갱신형은 공용조항 안의 담보속성 조건) — 보통약관 조를 가리켜 상품마다 한 벌이다. 조립 자동 생성은 MVP 이후.
- 공용조항으로 따지 못하고 템플릿에 남긴 문구와 그 까닭은 모델명세 §9. 특약 조연결은 하지 않는다(실물에 준용 문장이 없어 조연결하면 없는 문장이 생긴다).
- 별표 5·6·9·16~19는 본문이 참조하지 않아 이름을 확인하지 못했다 — 자리표시 이름만 있다.
- 수술비 등 표 행이 반복·조건에 따라 달라지는 담보는 범위 밖(정적 표만 재현).
- 표에 제목줄이 둘 이상이면 파싱양식(markdown)으로 되돌릴 때 첫 줄만 구분선을 얻는다 — 대조가 그 차이를 못 본다.
  준용 판정은 행마다 제목줄 여부를 비교하므로 조립에는 영향이 없다.
