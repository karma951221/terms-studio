# 실물재현 E2E 시나리오

> 상태: 초안 · 최종수정: 2026-09-27 (문면 편집기 — 오른쪽 클릭 · 그 자리 편집)

## 1. 목적

실물 `(무)알파Plus보장보험2604` 약관 — 보통약관 52조(관 7) + 특약 4벌(일반상해사망보장 기본·추가,
일반상해80%이상후유장해 생활자금보장, 골절(치아파절 제외)진단비Ⅱ보장, 기본계약 = 일반상해80%이상후유장해) —
을 이 시스템의 데이터로 재현하고, **조립 결과가 원문과 같음을 자동으로 확인**한다. 같은 과정을 회귀 방지로 고정한다.

## 2. 대조 기준

- 조 순서 + 조 명. 조·관 번호 참조는 조 명으로 정규화한다 — 가지번호를 쓰지 않으므로([[기능/문면/문면]] §3.2) 「제27조의1(」과
  「제28조(」은 같다고 본다.
- 공백은 전부 지우고 비교한다.
- ~~별표 번호는 남긴다 — 조립이 본문 등장 순으로 매긴 번호다.~~ → 2026-09-15 번호는 **지우고** 이름만 대조한다 (`【별표N(` → `【별표§(` · `compare.ts`) — 등장 순 자동 번호라 실물과 어긋나는 것이 허용 차이이기 때문이다 ([[기능/별표/결정/ADR-0063-별표-자동수집-자동번호]] · ADR-0030 대체 · [[QA/인수기준]] 실물 재현 인수 표 허용 차이 ②).
- 표·박스는 파싱양식의 fenced 블록 형태로 되돌려 비교한다. 표 셀도 인라인 노드라 셀 안의 조·별표 참조가
  계산 번호로 찍힌다 (2026-09-08).

기준 코드는 `src/domain/assembly/compare.ts`(순수층 — DB·React·`fs` 미사용, 파일 읽기는 호출자 몫).

## 4. 검증 층

① **Vitest** `src/db/seed/real.test.ts` — 실물 시드 적재 → 조립 미리보기 → 원문 대조.
오류 0·완성본, 보통약관 52조(관 7, 기본계약 대치 포함) + 특약 4벌이 각각 원문과 조 단위로 같음을 확인한다.
`npm test` 로 돈다.

② **Playwright** `tests/e2e/alpha-plus.spec.ts` — 하이브리드: 마스터 재료(구분자·담보·별표·보통약관·담보약관 문면)는
시드가 넣고, **상품모델링은 화면으로** 수행한다 — 상품 생성 → 보통약관 템플릿 선택 → 세목 선택지 2(1종·2종)·유효
조합 2 → 탑재(기본계약 담보 1 + 특약 담보 4, 일반상해사망보장은 부가유형 기본/추가로
구별) → 특약 그룹 생성·배치 → 조립 미리보기 → 보통약관 + 특약 4벌을 원문과 대조. 별도 테스트로 문면 편집기 최소
경로(관 안에 제1조(목적)를 화면으로 작성 → 시드 결과와 같은 렌더)도 확인한다.

③ **스모크** `tests/e2e/smoke.spec.ts` — 화면이 깨졌나만 본다([[QA/테스트전략]]). 조립이 맞는지는 ①·②의 몫.

실행법: `npm run db:seed` 로 실물 시드를 넣은 뒤 `npm run test:e2e`(dev 서버 자동 기동).

## 5. 시드 갱신 절차

1. 원문 `.md`(파싱양식, `docs/_자료/파싱양식.md` 규칙)를 `tests/fixtures/terms`에 복사한다.
2. `scripts/terms/config.ts`에 등록한다(신규 특약이면 §6 참고).
3. `npm run terms:convert` 실행.
4. stdout 의 `[report]`(변환 못 한 참조 — 법령 인용은 의도된 미변환) · `[invalid]`를 확인한다.
5. `npm test` 로 `real.test.ts` 통과를 확인한다.
6. `rm -rf .data && npm run db:seed` 로 개발 DB를 다시 적재한다.

## 6. 새 담보를 추가할 때

1. 원문 파일을 `tests/fixtures/terms`에 복사한다.
2. `scripts/terms/config.ts`의 `SPECIALS`에 항목을 추가한다 — `code` · `ownerCoverage` · `idPrefix` · `file` · (필요시) `slots` 오버레이.
3. `src/db/seed/data/coverages.json`에 담보(담보명 값)를, `products.json`의 `mounts`에 탑재(필요하면 `attributes`)를 추가한다.
4. `npm run terms:convert`로 변환한다.
5. `real.test.ts`의 `it.each` 목록과 `alpha-plus.spec.ts`의 `SPECIALS`·탑재(mount) 단계에 추가한다.
6. §5의 대조 절차로 확인한다.

## 7. E2E 작성 시 주의 (실제로 겪은 것)

- 같은 URL로 돌아오는 서버 액션 제출은 `waitForURL`이 즉시 풀린다 — POST 응답 + `networkidle`을 함께 기다린다(`submit` 헬퍼).
- 탑재는 새 상품담보의 값 화면으로 이동하므로, 다음 탑재를 위해 상품 페이지로 돌아온다.
- 그룹 제목은 입력칸 값이라 `hasText`로 못 찾는다 — 배치 버튼의 접근성 이름으로 폼을 잡는다.
- 문면 편집기의 넣기 · 조작은 오른쪽 클릭 메뉴다 — `click({ button: "right" })` 뒤 `menuitem` 을 누른다(`menu` 헬퍼).
- 문면 편집기의 제목 · 문장 칸은 contenteditable(`role=textbox`)이다 — `fill` 뒤 Enter(제목) · Tab(문장)으로 초점을 옮겨야 편집본에 들어간다.
- 해시만 바꾸는 리다이렉트(`#appendices`)는 서버 데이터를 다시 받지 않는다 — 쿼리를 함께 바꿔야 새 목록이 보인다.

## 8. 알려진 한계

- 가지번호(제27조의1 등)는 순번으로 다시 매긴다 — 실물 번호 표기 자체는 재현하지 않는다.
- 종별 문구(1종/2종 행·「1종으로 가입한 경우」)는 이번엔 정적 텍스트다.
- 준용규정 조는 각 담보 문면에 실물 텍스트 그대로 둔다 — 조립 자동 생성은 MVP 이후.
- 공용조항은 이번 시드에 하나도 없다 — 소멸 조 문구가 담보마다 달라 옵션으로 못 묶었고, 특약 조연결도 하지 않았다(실물에 준용 문장이 없어 조연결하면 없는 문장이 생긴다).
- 별표 5·6·9·16~19는 본문이 참조하지 않아 이름을 확인하지 못했다 — 자리표시 이름만 있다.
- 수술비 등 표 행이 반복·조건에 따라 달라지는 담보는 범위 밖(정적 표만 재현).
- 표에 제목줄이 둘 이상이면 파싱양식(markdown)으로 되돌릴 때 첫 줄만 구분선을 얻는다 — 대조가 그 차이를 못 본다.
  준용 판정은 행마다 제목줄 여부를 비교하므로 조립에는 영향이 없다.
