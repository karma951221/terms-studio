# ADR-0072 — 참조 대상 식별: 조는 uuid · 항·호·목은 조 전체에서 유일한 P코드 · 조 제목 인라인 조건 · 조 자리 조건은 켜고 끄기만

> 상태: 채택 · 날짜: 2026-09-27 · 구현: 결정 1 · 3 의 `code` 필드 · 4(공존 유일 — 조건 가지 · 값별 분기 칸) · 5(채번 · 사본 재채번 · 이동 무재채번 · 직접 수정 명령) · 10(빈 코드 채우기)은 2026-09-30 (`src/domain/document/pcode.ts` · `src/domain/clause/pcode.ts`, 수용 기준 1 · 2 · 3 · 4 일부 = `pcode.test.ts`). 참조 대상 저장 전환 · 코드 수정 창 · 영향 건수 · 2a · 2b 는 미구현
>
> **개정** [[기능/문면/문면]] §3.5 조 참조 슬롯 — 참조 대상 저장 형태 `{ nodeId }` → `{ articleId }` · `{ articleId, code }`.
> **개정** [[기능/문면/문면]] §3.5 참조 덩어리 — 「사라진 대상은 덩어리에서 뺀다」는 유지, 사라짐 판정이 「uuid 노드가 없다」→「살아남은 트리에 그 조의 그 코드가 없다」.

> 기획: [[기능/문면/문면]] 조 참조 · 설계: [[공통/기술/데이터모델]] §문면 노드 식별.
> **개정 예정 (2026-09-30)** — 결정 3 「참조는 `{ articleId }` · `{ articleId, code }` 두 형태뿐」에 펼친 함수조항 안 노드와 값 한정이 더해진다: `{ 조, P코드, 안쪽 P코드?, 한정? }` — 함수조항 참조 노드도 P코드를 받고, switch 칸 · IF 가지의 같은 자리는 결정 4 대로 코드를 공유한다 ([[기능/문면/결정/ADR-0077-블록반복-세목선택지-열거목록-반복참조]] 결정 6 · 7). 이 ADR 은 코드 주석이 가리킬 구현 대상이라 옮기지 않고, 구현 때 결정 3 을 고친다(원본은 `_archive/`). 구현 순서는 이 ADR → 0076 → 0077.
> 코드(구현 대상): `src/domain/document/nodes.ts` `ArticleRefNode.targets` · `ArticleNode.title` · `CondBlockNode` · `src/domain/assembly/render.ts` articleRef · `src/domain/refs/graph.ts` article 간선.

## 맥락

terms-studio 는 모든 문서 노드를 uuid 로 채번하고, 조 참조 슬롯(`ArticleRefNode.targets: { nodeId }[]`)도 대상 노드 uuid 를 저장한다.

조건 분기(if/elif/else) 때문에 **「같은 1항」이 가지마다 다른 노드(다른 uuid)로 여러 벌** 생긴다. uuid 참조는 그중 한 벌만 가리키므로
다른 가지가 선택되면 대상이 사라져 `articleGone` 이 된다. 우회는 다중 대상에 가지별 노드를 전부 넣는 것이다 — 문면 §3.5 의 「사라진 대상은 덩어리에서 뺀다」 덕에 결과는 맞게 나온다.
그러나 작성자가 가지마다 찾아 넣어야 하고, 가지가 늘면 참조처를 전부 고쳐야 하며, 데이터상 「A 및 B」 두 대상이라 뜻이 틀리고, 빠뜨려도 검증이 없다.
사용자 판단: 그럴 바엔 공용조항을 새로 따게 되고 참조의 의의가 없어진다.

현행 약관시스템(레퍼런스)은 항·호·목에 **P코드**를 채번하고 조 전체에서 유일하며, 참조는 `A0300:P0500` 두 마디다. 가지마다 같은 자리의 항은 같은 P코드를 가져
참조 피커에 「1항」이 하나만 보이고, 들여쓰기 · 내어쓰기를 해도 참조가 깨지지 않는다.

## 결정

| # | 결정 | 내용 |
|---|---|---|
| 1 | **식별 두 층** | uuid 는 노드 정체성(편집 · 출처 추적)으로 유지. **참조의 정체성은 코드** |
| 2 | **조는 코드를 두지 않는다 — uuid 하나** | 전제: 모든 항목은 조 단위로 작성한다. 조의 변형은 조 안의 조건(항·호·목 단위)과 조 제목의 인라인 조건으로만 표현한다. 현행 시스템의 A코드는 도입하지 않는다 |
| 2a | **조 제목 = 인라인 노드 목록** | 조 제목을 본문과 분리된 필드로 두고 `string` → 인라인 노드 목록으로 바꿔 인라인 조건(`inlineCond`)을 허용한다. 실례: 납입면제 운영 시 「보험금 등의 지급절차」, 미운영 시 「보험금 지급절차」. 참조 표기(「제5조(보험금 등의 지급절차)」)는 조립 때 번호와 함께 제목 조건도 같은 문맥에서 풀어 찍는다. 편집기 미리보기는 분기를 안 풀므로 조건 제목임을 표시(예 「보험금 [등]의 지급절차」) |
| 2b | **조 자리의 조건 블록은 켜고 끄기만** | if 가지 하나. elif · else 는 저장 검증이 거부 — 조 둘이 한 자리를 번갈아 차지하면 uuid 참조 문제가 조 단위에서 재발하므로 |
| 2c | **조를 uuid 로 드는 다른 자리는 그대로** | 조연결 `linkedArticleId` · 상품 옵션 오버라이드 부착 위치 `through` · 상품 조 노출 끄기 `hiddenArticles` · 조만 가리키는 조 참조 |
| 3 | **항·호·목은 모두 `P` 코드, 조 전체에서 유일** | 단계(항/호/목)는 코드가 아니라 트리 위치로 정해진다. 참조는 `{ articleId }`(조) 또는 `{ articleId, code: "P0500" }`(항·호·목) 두 형태뿐. 번호(「제3조제2호」)는 조립 때 살아남은 트리에서 계산. 담보약관 · 공용조항에서 보통약관 조 · 항을 가리킬 때도 같은 형태 |
| 4 | **유일성 = 공존하는 노드끼리만** | 두 노드를 감싸는 가장 가까운 공통 조건 블록에서 **서로 다른 가지**에 있으면 배타 → 같은 코드 허용. 그 밖(분기 밖 ↔ 가지 안, 같은 가지 안, 중첩 포함)은 공존 → 중복 금지 |
| 5 | **채번** | **새 노드**(끼워 넣기 포함): 위치와 무관하게 공존하는 코드를 피한 쓰지 않은 다음 코드(100 단위). 코드 순서 ≠ 실제 순서 허용 — 이미 P0100 · P0200 사이에 끼우면 P0300. 기본 위치값 n×100 이 공존 코드와 겹치면 100 씩 올린다. **붙여넣기**: 항상 자동 재채번(새로 생긴 노드라 참조하는 곳이 없음). **이동으로 충돌**: 항상 충돌 표시 + 「코드 수정」 버튼 → 입력창, 기본값은 시스템 추천값. 이동 시 자동 재채번하지 않는다(참조 유무와 무관 — 사용자 결정). **직접 수정**: 사람이 코드를 바꿀 수 있다, 공존 중복이면 저장 거부. **형식**: `P` + 숫자, 기본 4자리 100 단위. P9900 을 넘으면 자릿수를 늘린다(P10000) — 막지 않는다 |
| 6 | **코드를 바꿀 때 참조는 따라가지 않는다** | 참조는 옛 코드를 그대로 둔다 — 같은 코드의 분기 짝이 남아 있으면 그 짝으로 해소, 없으면 `brokenRef`. 코드 수정 창에 「이 코드를 가리키는 참조 N건이 깨집니다」 영향 목록 경고(ADR-0049 와 같은 장치), 저장은 막지 않는다 |
| 7 | **들여쓰기 · 내어쓰기** | 코드가 조 전체 유일이고 경로가 두 마디라 코드 · 참조 경로 모두 불변 → 참조가 깨지지 않는다. 목보다 깊은 들여쓰기는 거부. (현재 domain 에 들여쓰기 명령은 아직 없다) |
| 8 | **참조 그래프** | 조 노드는 uuid 키 유지. 항·호·목 참조는 지금처럼 조로 올린 간선에 코드를 싣는다. 깨진 코드도 `brokenRef` |
| 9 | **참조 덩어리(문면 §3.5)와의 관계** | 「분기 · 생략으로 사라진 대상은 덩어리에서 빼고 전부 사라졌을 때만 `articleGone`」은 유지. 사라짐 판정만 「uuid 노드가 없다」→「살아남은 트리에 그 조의 그 코드가 없다」로 바뀐다 |
| 10 | **기존 데이터 전환** | 조마다 문서 순서대로 채번 규칙을 적용(배타 가지의 같은 위치 항은 같은 코드를 받음). 기존 `nodeId` 참조는 그 노드의 조 + 코드로. 조 자리 조건 블록에 elif · else 가 있는 기존 데이터는 전환 때 보고 |

## 이유

- **가지마다 같은 자리의 항은 같은 것이다.** 참조가 가리키는 것은 「제3조의 그 항」이지 특정 가지의 노드 한 벌이 아니다. 배타 가지끼리 코드를 공유하면 참조 하나가 어느 가지가 선택되든 살아남은 쪽으로 해소된다 — 다중 대상 우회(작성 부담 · 뜻 틀림 · 검증 없음)가 필요 없다.
- **조 전체 유일 + 두 마디 경로라 트리 모양이 바뀌어도 참조가 불변이다.** 들여쓰기 · 내어쓰기로 부모가 바뀌어도 코드도 경로도 그대로다. 단계는 트리 위치에서 계산한다.
- **조는 코드를 둘 이유가 없다.** 조의 변형은 조 안의 조건과 제목 인라인 조건으로 표현되고, 조 자리 분기를 켜고 끄기로 좁히면 한 자리에 조가 하나뿐이라 uuid 로 충분하다.
- **참조는 따라가지 않는다.** 같은 코드를 여러 가지가 공유하면 참조가 어느 쪽을 뜻했는지 알 수 없고, 다른 문서(담보약관 → 보통약관, 공용조항)까지 조용히 고치게 된다. 깨짐은 영향 목록으로 미리 보인다.
- **현행 시스템과 같은 모양**이라 현업이 익숙하고 이관 대응이 단순하다 — 다만 현행의 「항 코드를 바꾸면 하위 호·목 코드가 바뀌는」 버그(아래 대안 C 의 동기)는 구조적으로 생기지 않는다(코드를 노드별로 저장하고 경로는 계산하므로 문자열 치환이 없다).

## 버린 대안

- **A. uuid 유지 + 가지별 노드를 다중 대상으로 우회** — 작성 부담 · 데이터상 「A 및 B」라 뜻이 틀림 · 빠뜨려도 검증 불가.
- **B. 부모 안에서만 유일한 코드 + 3~4 마디 경로(`A:P:P:P`)** — 들여쓰기로 부모가 바뀌면 경로가 바뀌어 참조가 깨진다. 현행 시스템과도 다르다.
- **C. 항·호·목 prefix 분리(P/I/S 또는 H/M)** — 사용자가 제안했던 이유: 현행에서 항 코드를 바꾸면 하위 호·목 P코드가 중간에 바뀌는 버그. 버린 이유: 코드에 단계를 박으면 들여쓰기 때마다 자기 + 하위 전체 코드를 연쇄 재작성해야 해 버그 표면이 된다. terms-studio 는 코드를 노드별로 저장하고 경로는 계산하므로 문자열 치환 버그는 구조적으로 안 생긴다. 단계는 화면에서 트리로 계산해 표시(`P0200 · 호`)하면 된다.
- **D. 조에 A코드** — 조 제목만 다른 경우를 위해 조를 가지마다 복제하면 공존 · 재채번 · 이동 충돌 · 참조 깨짐 규칙이 조 단위에서 전부 다시 필요하고, 본문이 두 벌이 되어 한쪽만 고치는 사고가 난다. 제목 인라인 조건으로 대체.
- **E. 코드 변경 · 이동 시 참조 자동 추종** — 같은 코드를 여러 가지가 공유하면 참조가 어느 쪽을 뜻했는지 모른다. 다른 문서(담보약관 → 보통약관, 공용조항)까지 조용히 고치게 된다.

## 결과와 감수하는 비용

- 코드를 바꾸면 참조가 깨질 수 있다 — 코드 수정 창의 경고 · 영향 목록으로 보완.
- 조 자리에서 조를 갈아끼우는 분기는 쓸 수 없다 — 본문 전체가 다른 두 버전의 조가 한 자리를 번갈아 차지하는 실사례가 나오면 재검토.
- 코드 순서와 실제 순서가 어긋날 수 있다.
- 조 제목 타입 변경(`string` → 인라인 목록)으로 제목을 쓰는 곳 전부(목차 · 참조 라벨 · 실물 대조)가 영향을 받는다.
- [[기능/문면/문면]] §3.5 의 대상 저장 형태 · 사라짐 판정이 바뀐다(구현 때 §3.5 를 고친다).

## 수용 기준 — 필수 테스트

사용자가 「반드시 테스트 코드에」 요구했다. 구현 때 아래 일곱 묶음이 **그대로 테스트 코드가 되어야** 이 ADR 이 구현된 것으로 본다.

1. **분기 밖 충돌** — if 가지 항 둘 → P0100 · P0200, 분기 밖 항 → P0300, elif 가지 추가 후 항 셋 → **P0100 · P0200 · P0400**.
2. **역방향** — 그 상태에서 분기 밖에 항 추가 → **P0500** (elif 의 P0400 과 공존).
3. **붙여넣기** — 같은 조 1 · 2 · 3항(P0100 ~ P0300) 복사 → 조 끝 붙여넣기 시 겹치지 않게 재채번(P0400 ~ P0600) · 가지 안 붙여넣기는 분기 밖 코드 회피 · 같은 조건 블록의 다른 가지에 붙이면 같은 코드 재사용 가능 · 다른 조에 붙이면 그 조 기준 채번.
4. **이동 충돌** — 충돌 표시 + 추천값 계산 · 추천값으로 저장 시 해소 · 공존 코드 직접 입력 시 저장 거부.
5. **코드 변경** — 항 코드를 바꿔도 하위 호 · 목 코드와 그들을 가리키는 참조는 불변(현행 시스템 버그 방지) · 분기 짝이 있으면 참조가 짝으로 해소 · 없으면 `brokenRef` · 수정 창 영향 건수 = 실제 깨지는 참조 수.
6. **들여쓰기 · 내어쓰기** — 코드 · 참조 불변, 렌더는 새 단계 번호로 정상 해소 · 목보다 깊으면 거부.
7. **(조)** — 조 자리 조건 블록에 elif / else → 저장 거부 · 조 제목 인라인 조건이 조립 문맥대로 풀려 참조 라벨에 찍힘.
