## 맥락

현행 약관시스템은 「이 담보에 감액이 있으면」 같은 **담보 전체** 조건만 쓸 수 있다. 「유사암 쪽에만 감액이 있으면」처럼 세부보장 · 급부 하나를 가리키는 조건은 못 쓰고,
그래서 그런 담보는 동적 표 생성을 못 타고 손으로 쓴다 — 사용자가 「반드시 해결하고 싶은 아픈점」으로 꼽은 것.

기획에서 갈린 것 — (1) 급부를 **이름**으로 가리키나 **노드 id** 로 가리키나 → id(오타에 조용히 어긋나지 않게, ADR-0058 과 같은 원칙).
(2) 문면이 급부 특성을 **마스터 필드로 직접** 읽나, **구분자로만** 읽나 → 구분자로만(ADR-0036 유지 — 사용자가 「레벨별 구분자는 마스터에서 정의」로 방향을 잡음).
(3) 조건식 입력이 **텍스트**냐 **구조화**냐 → 구조화(「조건식 자체를 텍스트로 입력하는 게 별로다 — 좌변은 구분자만, 연산자는 드롭다운, 우변은 좌변 타입에 맞게」).
(4) 복합 조건 → 줄 추가 + 줄 사이 AND/OR, 괄호 없음(A 안).

## 결정

| # | 결정 | 내용 |
|---|---|---|
| 1 | **노드 한정자** | 구분자 참조에 `@<노드id>` 를 붙일 수 있다 — `D0012@<급부id>`. 뜻: 그 구분자를 **문맥 담보가 아니라 그 노드** 문맥에서 평가한다(집계 범위 = 그 노드의 하위 트리). 구분자 참조에만 붙는다 — 마스터 필드 직접 참조는 문면에 없다(ADR-0036). 저장은 id, 화면은 이름 칩 |
| 2 | **허용 범위** | **담보 약관 문서**에서만(문맥 담보가 있으므로). 보통약관 · 공용조항 문면에서는 오류. 문서 = 담보 하나(담보_기획 「문면은 담보가 1벌 소유」) |
| 3 | **검사** | 오류(막음): 노드가 문맥 담보 트리에 없음(끊어진 참조) · 노드 레벨 ≠ 구분자 레벨 · 문맥 담보 없는 문서. 경고(배지): 그 노드에 구분자가 읽는 값이 없음(「항상 거짓」) |
| 4 | **조건식 블록** | 툴바 「조건식」 → 블록 삽입. 블록 = `IF [조건] … / ELIF [조건] … / ELSE …` 가지. 가지 추가 · 삭제 · 순서. 지금의 조건 블록 · 가지 모델(ADR-0012) 그대로 — 라벨과 조작만 IF/ELIF/ELSE 로 |
| 5 | **조건 머리 줄** | 가지 머리에서 그 자리로 고친다 — 팝업 없음(2026-09-28, [[기능/문면/문면]] §6.2). **줄** = 좌변(구분자 칩만) · 연산자(드롭다운 — 좌변 타입이 정함) · 우변(좌변 타입별 입력 — bool `참/거짓` · enum 값 목록 · number 숫자 · date 날짜 · string 텍스트, 또는 **같은 타입 구분자** 칩). **줄 사이 `AND / OR`**, 괄호 없음, 왼쪽부터 순서대로. ⊕ 줄 추가 · ⊖ 줄 빼기 |
| 6 | **변수 목록** | 좌변 칸의 목록이 트리 순서로 묶인다 — **문맥 담보의 실제 노드**(담보 › 세부보장 › 급부)마다 묶음, 그 아래 **그 레벨의 구분자**. 노드 묶음의 구분자 = `@노드` 자동, 담보 뿌리 묶음 = 한정자 없음. 값이 없는 노드를 고르면 「⚠ 항상 거짓」. 담보 트리 레벨이 아닌 구분자(상품 · 세목)는 「구분자」 묶음 (2026-09-28 — 팝업 오른쪽 트리 패널에서 바뀜) |
| 7 | **텍스트 식 입력 폐지 (문면)** | 담보 약관 · 보통약관의 조건식 입력칸(텍스트)은 없앤다. 구분자 정의 화면([[기능/구분자/구분자]] §4.3)의 텍스트 식은 그대로 |
| 8 | **저장 형식** | 머리 줄이 만든 줄은 기존 AST(`compare` · `and` · `or`)로 저장. 새 노드 종류 없음. 소스 문법에 `@id` 만 추가. 줄로 풀 수 없는 기존 식(중첩 괄호 · 집계 직접 사용)은 **원문 읽기 전용 + 「줄로 다시 만들기」** |

## 이유

- **id 가 정체다.** 이름 매칭은 「유사암」 「유사암진단」 오타에 조용히 어긋난다 — 약관에서는 사고. 노드 삭제는 끊어진 참조 오류로 드러나고, 구조 정정(ADR-0075)의 저장 시 영향 목록에 문면이 뜬다.
- **ADR-0036 을 지키면서 edge case 가 풀린다.** 「유사암의 면책여부」는 새 참조 종류가 아니라 **기존 구분자 + 평가 시작 노드**다. 세부보장 · 담보 레벨의 집계는 구분자 정의(`any(급부.면책여부)`)가 이미 표현한다 — 문면에 집계 문법을 들일 필요가 없다.
- **트리에 잎이 한 종류면 트리가 짧다.** 마스터 필드까지 잎으로 내면 잎이 두 배가 되고 「구분자로 갈까 필드로 갈까」를 사용자가 매번 고른다.
- **구조화 입력이면 검사가 입력 시점에 끝난다.** 타입 불일치 · 미지 참조 · 문법 오류가 애초에 안 생긴다. 사용자가 텍스트 식 문법을 배우지 않는다.
- **줄 + AND/OR 로 실물은 충분하다.** 실물 복합 조건은 2~3줄 평면. 괄호가 필요한 건 마스터에서 구분자로 미리 묶는 것이 「어디에 뜻이 있나」를 한 곳에 둔다.

## 버린 대안

- **문면이 마스터 필드를 직접 읽는 ADR-0036 예외** — 기획 중 한 번 승인됐다가 「레벨별 구분자는 마스터에서 정의」 방향으로 철회. 시드 구분자(ADR-0065 §5)가 필요를 없앤다.
- **이름으로 노드 지목**(`세부보장["유사암"]`) — 오타 · 개명에 취약.
- **공유 문서에서 노드 지목** — 담보 약관은 담보 하나 소유라 경우가 없다. 보통약관은 논외.
- **텍스트 식 유지 / 고급 모드 토글**(C 안) — 줄 ↔ 텍스트 왕복 규칙이 입력을 무겁게 한다. 필요가 확인되면 그때.
- **한 줄만**(B 안) — 담보 전용 복합 조건을 위해 구분자 화면을 오가게 해 아픈점이 남는다.
- **우변에 아무 타입 구분자 허용** — 타입 검사(구분자 §3.1 명시 결과 타입)를 우회. 같은 타입만.
- **넣기 패널을 편집 화면 옆에 상시**(구분자 §4.3 식) — 문면 편집 화면은 이미 SidePanel 이 있어 세 칸이 된다.
- **조건 팝업(모달 + 트리 패널)** — 2026-09-27 까지의 구현. 유저 점검(2026-09-28)「조건식 버튼을 누르면 팝업이 아니라 블록이 삽입되어야 한다」 — 현행 시스템처럼 블록 머리에서 바로 고친다([[기능/문면/문면]] §6.2).

## 결과와 감수하는 비용

- **파서 · 포맷 · 참조 추출 확장** — `DiscriminatorRef` 에 선택적 노드 참조. `extractRefs` 가 한정자를 함께 뽑아 사용처 패널 · 구조 정정 영향에 잇는다.
- **평가기** — `coverage/evalContext` 의 집계 시작 노드를 참조별로 바꾼다. 마스터 문맥 사전평가 · 상품 조립 둘 다.
- **부품** — 조건 머리 줄(줄 편집 · 타입별 우변 · 변수 목록) · 칩 렌더. 읽기 모드의 가지 머리는 글자 한 줄. 담보 구분자 트리는 반복 표 셀의 슬롯 참조 칸만 쓴다.
- **기존 저장 식의 이행** — 평면 `compare`/`and`/`or` 로 떨어지는 식은 그대로 열린다. 아닌 식은 원문 읽기 전용 + 다시 만들기(§8). 시드 문면 중 해당 식 수는 설계에서 센다.
- **문면 조건식의 표현력이 평면 AND/OR 로 좁혀진다** — 의도된 제한. 넘는 건 구분자로.
- **인라인 조건**(문장 안 조건)도 같은 머리 줄을 쓴다 — 칩을 누르면 뜨는 칩 팝업 안에서 가지마다.
