## 맥락

2026-09-28 ~ 09-30 납입면제 기획 — 보통약관 템플릿 한 벌이 납입면제의 모든 경우를 감당해야 한다([[기능/함수조항/결정/ADR-0076-공용조항-함수조항-일원화-인자연결]] 맥락).
납입면제종은 세목 `waiver` 의 선택지다([[기능/상품/상품]] §3.2 · §3.9). 선택지마다 사유 묶음(`waiver.reasons`, 목록값(복수) E0001)이 다르고, 상품마다 종이 몇 개인지 모른다.

사유에 따라 갈리는 자리는 모양이 셋이다(알파Plus 원문 제27조의1 · 의2 · 의3).

| 자리 | 모양 |
|---|---|
| 납입면제 조 | **종마다 항**, 그 항 안에 **그 종의 사유마다 호** |
| 「…의 정의 및 진단확정」 조 | 적용 종 전체의 **사유 합집합** 가운데 정의 조에 싣는 값마다 — 같은 사유는 한 번 |
| 세부규정 · 면제 부가항 · 계약의 무효 · 부활 | 종들의 사유 묶음을 **한 번에** 보고 항 묶음을 켜고 끈다 + 종마다 생긴 항 · 호를 가리키는 참조 |

지금 문면으로는 못 쓴다 — 반복은 담보약관 템플릿의 **표 행 반복**뿐이고(ADR-0070 결정 10), 반복 블록은 자리만 있으며, 반복 안에 반복은 금지다([[기능/문면/문면]] §3.2).
현행 시스템은 이것을 **서수 구분자**(1번째 형 · 2번째 형)와 **개수 조건식**(「사유 묶음 1개면 제1항, 2개면 제1 · 2항」)으로 풀었다 — 반드시 피하라는 것이 사용자 요구다.

참조도 걸린다. 세부규정이 「제27조의1 제1항 제1호」처럼 종마다 생긴 호를 가리켜야 하는데, 몇 항 · 몇 호가 생길지 템플릿 시점에는 모른다.
또 공용조항이 펼친 항은 사용처 쪽 참조의 대상이 될 수 없다([[기능/함수조항/함수조항]] §3.1) — 사유별 문장을 함수조항으로 모으면 그 호를 가리킬 길이 막힌다.

## 결정

1. **템플릿은 사유 값으로 분기하지 않는다** — 사유별 분기는 함수조항 안에서만 한다(ADR-0076). 템플릿은 반복 + 함수조항 참조로 부른다.
2. **블록 반복을 연다** — 조 자리 · 항 아래 목록에 반복 블록이 서고, 본문(항 · 호 · 함수조항 참조 …)을 원소마다 복제한다. 원천은 셋이다.

   | 원천 | 원소 | 납입면제의 쓰임 |
   |---|---|---|
   | **세목 선택지** | 세목 범위 안 한 세목유형의 선택지 가운데 거르는 조건을 만족하는 것 | **납입면제종마다** = `waiver` 선택지 중 적용여부 = 예 |
   | **바깥 반복의 현재 원소의 목록** | 현재 원소가 가진 목록값(복수)의 값 | 현재 종의 사유마다 |
   | **목록값(복수)의 합집합** | 거른 세목 선택지들의 목록값(복수)을 합친 값 — 같은 값은 한 번. 열거값 필드로 거를 수 있다 | 사유 합집합 ∩ 정의조대상 = 예 |

   - 반복 이름은 「납입면제종마다」다 — 「형」은 무저해지 축(해약환급금 지급형 · 미지급형)과 겹친다.
   - 열거 원소의 순서는 **열거형에 정의된 순서**다(호 · 합집합 모두).
   - 원천은 구분자 + 반복 장치의 거르기로 선언한다 — 문면은 구분자만 본다([[기능/구분자/결정/ADR-0036-폼-구분자-문면-3층]] 유지). 원천 선언의 저장 모양은 구현 때 정한다.
   - 원소가 0 이면 블록을 통째로 펼치지 않는다(표 행 반복의 「행 0 이면 표 생략」과 같은 결).
3. **반복 안에서는 현재 원소만 읽는다** — 서수 구분자(n번째 종)와 개수 조건식을 **폐지**한다. 반복 본문은 「현재 종」(종형명 = 선택지 이름 · 사유) · 「현재 사유」만 본다. 현재 원소를 함수조항에 넘기는 것은 인자 연결이다(ADR-0076).
4. **반복은 한 단계까지 중첩한다** — 반복 안에 반복 하나. 안쪽 원천은 바깥 현재 원소의 목록이다 — 반복 표의 「세부보장 › 급부마다」 레벨 사슬(ADR-0070 결정 6)과 같은 모양. 두 단계 이상은 금지.
5. **넣기와 가리키기를 가른다.** 넣기(조항을 펼쳐 넣음)의 순환은 금지 — 기존 중첩 금지 그대로다. **가리키기(참조)의 순환은 허용**한다 — 조립이 펼치기(조건 · 반복 · 조항) → 빈 조 빼기 → 번호 → 참조 해소 순서라 참조는 완성된 트리 하나에서 해소된다.
6. **펼친 함수조항 안의 항 · 호 · 목도 참조 대상이다** — 저장은 **P코드**: `{ 조, P코드, 안쪽 P코드?, 한정? }`. `P코드` 는 사용처 조 안의 노드(함수조항 참조 노드도 P코드를 받는다), `안쪽 P코드` 는 그 함수조항 본문 안의 노드, `한정` 은 값 한정(결정 7).
   switch 칸 · IF 가지의 같은 자리 노드는 코드를 공유한다(ADR-0072 결정 4) — 칸을 고쳐도 참조가 살아남는다. 분기로 사라지면 기존 사라짐 규칙이다. ADR-0072 결정 3(참조 두 형태뿐)을 이렇게 넓힌다 — 코드 이행 전까지 ADR-0072 가 현행이다.
7. **반복으로 생긴 노드를 가리키는 참조.**
   - **반복 블록(여러 대상)을 가리키면** 조립 뒤 펼쳐진 것 전부다. 1개면 「제1항」, 여럿이면 여러 번호 표기([[기능/문면/문면]] §3.5), **0개면 조립 오류** — 좌표는 참조 자리.
   - **값 한정 참조** — 반복으로 생긴 노드를 「사유 = 현재 값」(반복 안에서) 또는 「사유 = 해당 값들」로 좁혀 가리킨다. 예: 세부규정 ① 「⟨사유 = 암 인 호⟩에도 불구하고」 → 종이 둘이면 「제1항 제1호 및 제2항 제1호」. **0개면 조립 오류.**
   - 생길 수 있는 노드를 하나하나 대상으로 걸지 않는다.
8. **펼친 뒤 항이 0개인 조는 조립이 조째 뺀다** — 함수조항 · 조건이 모두 「문구 없음」이 된 조. 편집 중에는 빈 조를 허용한다. 그 조를 가리키는 참조는 기존 사라짐 오류다.
9. **「납입면제 있음」 상품 구분자** — 적용 종(적용여부 = 예 인 `waiver` 선택지)이 있는가. 납입면제 세 조(납입면제 · 세부규정 · 정의 및 진단확정)를 조 자리 IF 로 감싼다. 세부규정의 고정 항(⑦ 제3자 합의) 때문에 빈 조 규칙(결정 8)으로는 빠지지 않아서다. 조 노출 토글은 쓰지 않는다.
10. **정의 조의 원천 = 사유 합집합 ∩ 정의조대상 = 예** — 제목 나열 슬롯과 본문 반복이 같은 원천을 쓴다. 교차 검사: 정의조대상 = 예인 값의 `정의(사유)` 칸이 「문구 없음」이면 **오류**, 정의조대상 = 아니오인 값의 칸에 문장이 있으면 **경고**.

## 이유

- **개수와 서수가 템플릿에서 사라진다.** 「몇 개면 몇 항」은 반복이 원소 수만큼 펼치면 저절로 맞는다. 서수 구분자는 원소 순서가 바뀌면 다른 종을 가리키는데, 현재 원소만 읽으면 그런 자리가 없다.
- **템플릿이 읽힌다.** 반복 두 줄 + 함수조항 한 줄이면 조의 모양이 한눈에 보이고, 템플릿에 사유 이름이 한 번도 나오지 않는다.
- **한 단계 중첩이 실물의 모양이다.** 납입면제 조는 종 › 사유 두 겹이고 세 겹 사례는 없다.
- **합집합 반복은 종 반복과 따로다.** 정의 조를 종 반복 안에 두면 두 종이 같은 사유를 가질 때 정의가 두 번 나온다. 원천에 정의조대상을 걸어 제목 나열과 본문이 어긋날 수 없게 한다.
- **가리키기 순환이 안전하다.** 참조는 펼치기 · 번호가 끝난 트리에서 해소되므로 무한히 돌지 않는다. 넣기 순환만 트리를 무한히 만든다.
- **P코드 저장이 칸 편집을 견딘다.** 조항 안 노드를 uuid 로 가리키면 switch 칸 하나를 고치거나 가지를 나눌 때 참조가 깨진다. 같은 자리 코드를 공유하면 어느 칸이 선택되든 살아남은 쪽으로 해소된다.
- **값 한정이 종 수와 무관한 참조를 만든다.** 「암 호」는 종마다 다른 번호로 생기지만 「사유 = 암」은 한 번 걸면 된다.
- **0 이면 오류여야 한다.** 가리킬 것이 없는데 빈 글을 찍으면 「제 조에 따라」 같은 틀린 문장이 남는다. 0 은 거의 늘 조건을 빠뜨린 작성 실수다.
- **빈 조는 조째 빠져야 한다.** 함수조항이 모두 「문구 없음」이면 제목만 남은 조가 찍힌다. 그렇다고 조마다 「내용이 있으면」 조건을 쓰게 하면 개수 조건이 돌아온다.
- **「납입면제 있음」은 구분자여야 한다.** 조 노출 토글은 상품 값에 근거가 없을 때 쓰는 장치다 — 납입면제 유무는 세목 값에서 나온다.

## 버린 대안

- **서수 구분자 · 개수 조건식(현행 시스템)** — 종 수가 늘 때마다 가지가 늘고, 순서가 바뀌면 조용히 다른 종을 가리킨다.
- **사유 가지를 템플릿에 인라인으로** — 현행 시스템에서 템플릿을 읽을 수 없게 됐다.
- **템플릿이 가지를 정의하고 사유 화면이 채움(현행 시스템)** — 한 문장을 보려면 화면 N 개를 오간다.
- **사유 열거값이 역할별 조항을 가리키는 매핑** — 한 역할의 문장이 사유 수만큼 흩어져 사유끼리 비교할 수 없다.
- **종마다 조건 블록을 미리 N 개** — 템플릿 시점에 종 수를 모른다. 결국 서수가 돌아온다.
- **반복 안 반복 무제한** — 실물에 없고 문맥 사슬 · 검사가 깊이만큼 복잡해진다.
- **(참조 노드 id, 조항 안 노드 id) 짝 저장** — uuid 라 칸 편집 · 가지 분할에서 깨진다. P코드와 두 벌이 된다.
- **생길 수 있는 노드를 하나하나 거는 참조(현행)** — 템플릿 시점에 몇 개인지 모른다.
- **펼친 노드 참조 금지 유지** — 사유별 문장을 함수조항으로 모으면 그 호를 가리킬 길이 없다.
- **납입면제 없음을 조 노출 토글로** — 세목 값에서 나오는 사실을 상품이 손으로 맞춰야 한다.
- **정의 조 원천 = 사유 합집합 전부 + 조립이 약관표시명으로 걸러 냄** — 숨은 중복 제거라 무엇이 빠지는지 안 보인다.

## 결과와 감수하는 비용

- **ADR-0070 결정 10 이 개정된다** — 코드 이행 때 결정 10 줄을 고치고(원본은 `_archive/`), 결정 7 「이후」 목록에서 블록 반복 · 상품 문맥 반복(세목 선택지 쪽)을 뺀다.
- **ADR-0072 결정 3 이 개정된다** — ADR-0072 구현(P코드 채번)이 이 ADR 의 참조보다 먼저다. 구현 순서는 ADR-0072 → 0076 → 0077.
- **조립 파이프라인** — ② 에 반복 블록 펼치기(한 단계 중첩) · switch · 내부 변수가 들고, 번호 앞에 빈 조 빼기가 들며, ⑥ 참조 해소가 P코드 · 값 한정 · 반복 대상을 푼다. `structure` 오류(반복 블록 미지원)는 사라진다([[기능/조립산출/조립산출]] §3.1).
- **문면 편집기** — 반복 블록 넣기 · 원천 고르기 · 「현재 종」 · 「현재 사유」 · 반복 블록 · 값 한정을 조 참조 대상으로 고르기가 생긴다. 편집기 번호는 반복 블록을 항 하나로 센다 — 실제 번호는 조립이 매긴다.
- **종별 문구 유즈케이스**([[00_시작/도메인모델]] §3)가 같은 장치로 답해진다 — 납입면제종마다 + 현재 종의 종형명. 표 안 종마다 행(메리츠 제2조)은 다음 기획이다.
- **남은 것** — 종 축 한정 참조 · 표 안 종마다 행 반복 · 나열 슬롯의 저장 · 편집 모양은 [[기능/문면/문면]] §5 미결.
