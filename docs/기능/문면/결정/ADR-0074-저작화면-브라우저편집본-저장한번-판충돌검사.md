# ADR-0074 — 조문 저작 화면도 저장 한 번: 브라우저 편집본 + 저장 때 판 충돌 검사

>
> 화면: [[기능/문면/문면]] §3.8 · §4.3. 원칙: `CLAUDE.md` 「화면 편집 원칙」 · [[공통/화면/디자인원칙]] §2 L2(저장 단위) · §1.7(경로 — 편집 중 이동 확인).

## 맥락

조문 저작 화면(`/documents/<id>`, L3)은 편집을 **트리 명령 하나 = 저장 하나**로 처리한다. 폼마다 있는 저장 버튼이나 조작 아이콘을 누르는 순간 원본 문서가 바뀐다.
이 방식은 CLAUDE.md 원칙 「한 편집 화면의 변경사항은 저장 한 번으로 반영한다」와 어긋난다.
편집 중에 경로 링크를 눌러도 「버립니까?」 확인이 없고, 되돌릴 방법도 없다. 조 하나를 지우면 그 즉시 원본에서 사라진다.
2026-09-27 문서 재편 때 이 불일치가 미결로 올라왔다. 선택지는 「구조 명령은 즉시 저장」 예외로 두는 것(상품모델링 특약 탭 명령 즉시 저장 — [[기능/상품/상품]] §3.8 과 같은 결)과 저장 한 번으로 고치는 것이었다.

## 결정

1. **저작 화면도 저장 한 번이다.** 읽기 모드에서 시작한다. `편집`을 누르면 같은 자리의 버튼이 `저장`으로 바뀐다. `취소`는 편집한 내용을 버린다.
2. **편집 중인 내용은 브라우저의 편집본에 둔다.**
   - `편집`을 누르면 원본 트리와 그 **판 번호**를 받아 브라우저에 편집본을 만든다.
   - 편집 중의 모든 트리 명령(추가 · 삭제 · 이동 · 복제 · 글자 · 제목 · 슬롯 · 참조 · 가지 · 조연결 · 옵션 · 표)은 브라우저에서 편집본에 곧바로 적용된다. 적용은 순수 도메인 `applyCommands` 로 하고, 명령 단위의 검사도 그 자리에서 한다.
   - 적용한 명령은 **명령 목록**으로 쌓는다.
   - 화면(가운데 본문 · 목차 · 우측 패널의 검증 목록 · 미리보기)은 편집 중이면 편집본을 그린다.
3. **`저장` = 명령 목록 + 시작 판 번호를 서버로 보낸다.**
   - 서버는 원본의 판이 시작 판과 같은지 확인하고, 원본에 명령을 다시 적용한 뒤 **문서 전체를 검증**한다. 검증은 지금의 저장 검증(구조 · 참조 대상 · 공용조항 · 식 · 슬롯 · 반복 표)을 그대로 쓴다.
   - 모두 통과하면 한 번에 반영하고 판을 올린다. 그다음 읽기 모드로 돌아간다.
   - 검증 오류가 있으면 저장을 거부하고 편집을 계속한다. 오류는 해당 노드와 고칠 위치로 안내한다. 서버가 최종 검증자다.
4. **판이 다르면 저장을 거부한다** — 「다른 사람이 먼저 저장했습니다」.
   - 편집본은 브라우저에 그대로 남는다. 새로 연 원본에 옮겨 적는 것은 사람이 한다. 자동 병합은 하지 않는다.
   - 잠금은 두지 않는다. 누구나 `편집`을 누를 수 있다.
5. **편집 중에 떠나려 하면 확인한다.**
   - 경로 링크 · ✕ · `취소`는 「고친 내용을 버립니까?」 확인을 거친다 (디자인원칙 §1.7).
   - 새로고침 · 창 닫기에는 브라우저 경고(`beforeunload`)를 띄운다. 편집본을 로컬 저장소에 백업하지는 않는다 — 떠나면 사라진다.
6. **편집본 밖의 조작은 읽기 모드의 더보기 메뉴에 둔다** — 템플릿 삭제 · 복제. 편집 중에는 쓸 수 없다. 담보약관의 대응 보통약관 지정은 편집에 포함한다(문서의 속성이다).
7. **조립 · 다른 화면은 원본만 본다.** 편집본은 편집하는 그 브라우저 탭에만 있다.

## 이유

- 조문 편집은 조 여러 개를 오가는 긴 작업이다. 중간 상태(조를 옮기다 만 상태, 참조를 끊었다 다시 잇기 전 상태)가 원본에 드러나면, 조립과 다른 사람의 화면이 반쯤 고친 문서를 본다.
- **브라우저 편집본**을 쓰면 DB 에는 판 번호 하나만 늘어난다. 편집본 테이블 · 잠금 · 만료 규칙이 필요 없다. 명령 모델이 순수 도메인이라 브라우저와 서버가 같은 코드로 명령을 적용한다.
- **명령 목록을 서버에서 다시 적용**하면 서버가 최종 검증자로 남고, 보내는 양도 작다. 시작 판이 같다는 전제에서는 편집본 트리를 통째로 보내는 것과 결과가 같다.
- **판 충돌 검사**를 쓰는 이유: 저작자는 적고 문서는 여러 벌이라, 같은 문서를 동시에 편집하는 일은 드물다. 드문 충돌을 막으려고 잠금 관리 비용을 늘 지는 것보다, 충돌이 난 쪽이 한 번 다시 하는 편이 싸다.

## 버린 대안

- **구조 명령은 즉시 저장하는 예외(상품 §3.8 과 같은 결)**: 구현 비용은 없지만 중간 상태 노출 문제가 그대로 남고, 원칙에 예외가 하나 더 생긴다.
- **서버 편집본(DB 사본 + 문서 잠금)**: 지금의 서버 렌더 화면을 거의 그대로 쓸 수 있고, 새로고침에도 편집본이 남는다. 대신 편집본 테이블 · 잠금 · 관리자 해제가 필요하고, 잠금을 켠 채 떠나면 다른 사람이 막힌다. 한 번 이 안으로 정했다가 같은 날 사용자가 브라우저 편집본으로 바꿨다.
- **잠금 기록만 서버에**: 충돌은 원천적으로 없다. 하지만 편집 내용은 새로고침으로 사라지는데 잠금은 남으므로, 만료 규칙이나 관리자 해제가 필요하다.

## 결과와 감수하는 비용

- **저작 화면을 클라이언트 컴포넌트 중심으로 다시 짠다.** 지금은 서버 렌더 · 쿼리 모드(`?mode=edit&node=…`) · 폼마다 서버 액션이다. 편집 상태가 브라우저로 오므로 다음이 바뀐다.
  - 본문 · 목차 · 우측 패널 · 조건 팝업이 편집본을 받아 그린다.
  - 폼의 「〔… 저장〕」 버튼은 편집본에 넣는 조작이 된다 — 지금은 가운데 그 자리 편집 · 그 자리 팝업의 확인 · 본문 위 툴바(오른쪽 클릭 메뉴는 지름길)다(우측 패널 폼 · 「적용」 없음, [[기능/문면/문면]] §4.3).
  - 편집 중 미리보기에 필요한 조립 재료(고른 상품의 공유 마스터 · 상품 고유분)를 상품을 고를 때 서버에서 한 번 받아 둔다([[기능/문면/문면]] §3.9, 2026-10-10).
- **새로고침하면 편집 중인 내용이 사라진다** — 브라우저 경고로만 막는다.
- **문서에 판 번호가 생긴다**(스키마 변경 · 마이그레이션). 원본을 바꾸는 다른 경로(복제 · 시드 · 다른 화면의 조연결 해제 등)도 판을 올려야 한다.
- **삭제 확인 카드의 성격이 바뀐다.** 지금은 확인하면 원본에서 곧바로 사라진다. 앞으로 사라지는 것은 편집본이고, 저장해야 확정된다. 그래서 카드 문구도 「저장하면 사라집니다」 결로 바꾼다. 다른 문서가 이 조를 참조하고 있다는 영향 목록은 저장 때 서버가 다시 검사한다.
- **E2E · 시나리오의 편집 흐름이 바뀐다.** 모든 흐름에 「편집 → 조작 → 저장」 단계가 들어간다.
