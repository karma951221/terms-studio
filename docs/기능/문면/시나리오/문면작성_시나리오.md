# 문면작성 시나리오

> 상태: 초안 · 최종수정: 2026-09-27
> 관련 기획: [[기능/문면/문면]] · [[기능/공용조항/공용조항]] · [[기능/문면/결정/ADR-0012-문면-노드트리-구조편집기]] · [[공통/기술/결정/ADR-0013-식언어-통일]] · [[기능/문면/결정/ADR-0074-저작화면-브라우저편집본-저장한번-판충돌검사]]

구조 편집기에서 담보약관·보통약관 마스터 문면을 작성하는 흐름.
모든 흐름은 **편집 → 조작 → 저장**이다 ([[기능/문면/결정/ADR-0074-저작화면-브라우저편집본-저장한번-판충돌검사]]) — `편집`을 누르면 원본과 그 판으로 브라우저 편집본이 생기고, 조작(추가 · 삭제 · 이동 · 폼의 「적용」)은 편집본에만 들어간다. `저장` 한 번에 서버가 판 확인 · 전체 검증 뒤 반영하고 읽기 모드로 돌아간다. 저장 전에는 원본(조립 · 다른 화면)이 바뀌지 않는다.
실물 기준: 알파Plus 수술비 특약(갱신형 파생 실증 — [[00_시작/도메인모델]] §7).

## 시나리오 1 — 조·항 구조 잡기와 슬롯 칩 삽입

**전제**: 수술비 담보 마스터 존재. 담보 레벨 구분자(예: 지급률)와 const 구분자
「평균공시이율」(string, 마스터 값 입력됨) 정의돼 있음.
**흐름**:
1. 담보약관 템플릿 화면(읽기 모드)에서 `편집` → 빈 문서 노드 하나의 편집본.
2. 조 블록 추가 → 조 명 입력(「보험금의 지급사유」). 번호 입력란은 없음 — 번호는 계산값.
3. 조 아래 항 블록 추가, 항 아래 호·목 블록 추가 — 문서>조>항>호>목 허용 자식 규칙 안에서만 추가됨.
4. 항 블록 안에서 문장 편집 → 문장 중간에 슬롯(값 참조) 칩 삽입 — 참조 대상으로 담보 레벨 구분자 경로 선택.
5. 다른 문장에 const 구분자 「평균공시이율」 슬롯 삽입.
6. 조 블록을 드래그(또는 이동 조작)로 다른 조 앞으로 이동 → 이후 조들의 표시 번호가 순서대로 다시 매겨짐.
7. `저장`.
**기대 결과**: 트리 구조(조>항>호>목)와 문장·칩이 저장 한 번에 저장됨. 번호는 어디에도 저장되지 않고 화면 표시만 계산.
평균공시이율이 마스터에서 바뀌면 이 문면의 렌더에 반영됨(템플릿은 참조만).
**경계·오류**:
- 허용 자식 규칙 위반(예: 목 아래 항)은 추가하는 그 자리에서 거부 — 편집본은 그대로, 사유 배너. 저장 때 서버가 문서 전체를 다시 검증한다.
- 상품담보명·상품명을 찍는 이름 치환 슬롯은 존재하지 않음 — 슬롯 대상 목록에 이름이 나오지 않아야 한다.
- ⚠ 미결: 슬롯 값 포맷 규칙(number → 「2.50%」 등 표시 형식을 누가 정하나) — [[00_시작/도메인모델]] §7.

## 시나리오 2 — 인라인 조건: 갱신형이면 「최초계약일」

**전제**: 수술비 담보에 담보 레벨 구분자 「갱신여부」(boolean) 부착·정의됨.
**흐름**:
1. 항의 문장 안에 인라인 조건 칩 삽입.
2. 조건식 입력: `갱신여부 = true` (식 언어는 파생식과 한 벌 — [[공통/기술/결정/ADR-0013-식언어-통일]]).
3. 참 분기 텍스트 「최초계약일」, else 분기 텍스트 「계약일」 입력.
4. `저장`.
**기대 결과**: 한 문면으로 「수술비」/「갱신형 수술비」 탑재분의 어구 차이가 표현됨.
문장 흐름 안에 인라인 조건 노드가 앉고, 분기 텍스트가 각각 저장됨.
**경계·오류**:
- 인라인 조건 안에 다시 인라인 조건 삽입 시도 → **막힘** (인라인 중첩 금지 —
  [[기능/문면/문면]]). 이중 분기가 필요하면 항을 쪼개 블록 조건으로 풀도록 안내.
- 조건식 자리에 boolean 결과가 아닌 식 입력 → 거부 (타입 검사는 언어 밖 규칙 — [[공통/기술/결정/ADR-0013-식언어-통일]]).

## 시나리오 3 — 블록 조건: 갱신형 수술비의 보험기간 조 추가

**전제**: 시나리오 2 의 문면. 조가 5개 있는 상태(제1조~제5조로 표시).
**흐름**:
1. 조가 서는 자리에 조건 블록(if) 추가, 조건식 `갱신여부 = true`.
2. 조건 블록 안에 「보험기간」 조 작성 — 조 단위 on/off.
3. 사전평가 뷰(→ [[기능/문면/시나리오/사전평가_시나리오]])나 전체 뷰에서 이후 조들의 번호 확인.
4. `저장`.
**기대 결과**: 갱신형 탑재분에서만 보험기간 조가 살고, 조건 해소 후 남은 조에 순서대로
번호가 매겨져 **이후 조 번호가 밀린다** (실물: 갱신형 수술비). 비갱신 탑재분은 조가 빠지고 번호가 당겨짐.
**경계·오류**:
- 블록 조건의 중첩은 허용 — 조건 블록 안에 다시 조건 블록이 설 수 있어야 한다.
- if / elif / else 모드 전부 지원돼야 한다 ([[00_시작/도메인모델]] §3).

## 시나리오 4 — 조 참조·별표 참조 슬롯

**전제**: 시나리오 3 의 문면(분기로 사라질 수 있는 조 포함). 별표 마스터에
「화상 분류표」 등이 불변 코드로 등록돼 있음. 보통약관 마스터(알파Plus) 존재.
**흐름**:
1. 문장 안에 조 참조 슬롯 삽입 → 같은 문서의 조 목록에서 대상 조 선택. 슬롯에는 조 id 만 저장.
2. 다른 문장에 보통약관 조 참조 슬롯 삽입 → 대응 보통약관의 조 선택 (담보약관에서 참조하는 두 번째 종).
3. 별표 참조 슬롯 삽입 → 별표 마스터 목록에서 코드 선택.
4. `저장`.
**기대 결과**: 본문에 번호 텍스트가 박히지 않음. 렌더 시 조 참조는 그 조의 계산된 번호(+조 명)로,
별표 번호는 책자 조립 시 본문 등장 순으로 계산됨 — 같은 별표라도 책자마다 번호가 다를 수 있다.
**경계·오류**:
- 번호를 직접 타이핑해 참조하는 경로가 유일한 방법이 되면 안 됨 — 밀리는 순간 오참조.
- 참조 대상 조가 분기로 사라지는 탑재분 → 조립 시점 오류 + 좌표 보고 (편집 화면 몫 아님 — 경계 확인).
- ⚠ 미결: 조·별표 참조 슬롯의 렌더 표기 형태(「제3조(보험금의 지급사유)」·「【별표13(화상 분류표)】」 등)
  — 구현 전 실물 조사 대기 ([[기능/문면/문면]]).

## 시나리오 5 — 공용조항 block/inline 배치와 부착 검사

**전제**: 공용조항 마스터에 「특별약관의 소멸」(block — 항 목록) · 준용 문구(inline) 정의됨.
소멸 공용조항의 식이 담보 레벨 구분자 X 를 읽음(요구 구분자 — 식에서 자동 추출).
편집 중인 담보에는 X 가 미부착.
**흐름**:
1. 조 블록 추가(조 명 「특별약관의 소멸」 — 조는 항상 사용처 소유), 그 안에 직접 쓴 항 하나 작성.
2. 항 자리에 공용조항 block 참조 추가 → 붙이는 시점 부착 검사 발동: 미부착 요구 구분자 X 를 찾아 **부착을 제안**.
3. 수락 → 그 자리에서 X 가 담보에 부착되고 참조가 성립.
4. 직접 쓴 항과 block 참조의 순서를 조정.
5. 다른 조의 문장 안에 공용조항 inline 참조 삽입.
6. 공용조항 정의에 옵션이 있으면 이 사용처에서 옵션을 수동 선택.
7. `저장` — 옵션 미선택이 남으면 서버가 저장을 거부하고 그 참조로 안내한다.
**기대 결과**: 출력은 배치 순서 그대로(직접 항 ↔ block 참조 섞임 순서 보존).
사용처에는 연결만 저장 — 공용조항 마스터를 고치면 쓰는 곳 전부에 전파.
**경계·오류**:
- 2에서 부착 제안을 거절하면 **참조 추가가 성립하지 않음** ([[기능/공용조항/결정/ADR-0010-공용조항-참조바인딩]]).
- 사용처에서 공용조항 문장을 자유 수정하는 경로 없음 — 다른 문구가 필요하면 옵션 선택 또는 별도 공용조항.
- 공용조항 안에 공용조항 참조(중첩) → 막힘 (MVP 이후 로드맵).
- 조 제목을 포함하는 block 은 없음 — block 은 항 단위뿐.

## 시나리오 6 — 조연결: 대응 보통약관 조 선택

**전제**: 시나리오 5 까지의 담보약관 문면 + 보통약관 마스터(알파Plus) 존재.
준용규정 조는 공용조항 참조로 구성됨.
**흐름**:
1. 담보약관의 각 조에서 조연결 UI 열기 → 대응 보통약관 조 선택.
2. 조의 메타 확인 — 조 명 · 조연결 두 가지뿐 (그 외 메타 없음).
3. `저장`.
**기대 결과**: 각 조가 대응 보통약관 조의 id 를 안다. 「생략하기」는 여기서 표시·판정하지 않음 —
조립 시점에 조건 해소가 끝난 렌더 결과의 리터럴 비교로 탑재분별 자동 판정 ([[기능/조립산출/조립산출]] §3.5).
**경계·오류**:
- 수동 생략 플래그 UI 가 존재하면 안 됨 (기각된 대안 — [[기능/조립산출/조립산출]] §3.5).
- 사소한 문구 차이는 생략되지 않는 것이 정상(리터럴 완전 동일 기준) — 동일성은
  공용조항 참조로 구조적으로 확보하는 것이 따름 전략.
- 조합 옵션 정의·준용 문구 자동 생성은 P7 — 이 화면은 「대응 조 선택」까지 (실물:
  갱신형 수술비의 준용규정 내용 차이는 조건 분기로 감당).

## 시나리오 7 — 보통약관 마스터 작성

**전제**: 보통약관 마스터 목록에 알파Plus 1벌. 상품·기본계약 지정은 아직 없음(P5 이전).
**흐름**:
1. 보통약관 마스터 목록에서 알파Plus 선택 → 편집 화면 (목록 + 선택의 최소형).
2. 담보약관과 같은 구조 편집기로 조·항 작성, 공용조항 참조·슬롯 삽입.
3. 담보 레벨 구분자를 읽는 조건 블록 작성.
4. `저장`.
**기대 결과**: 3의 조건은 편집 화면에서 **미결**로 표시됨 — 보통약관 문맥의 담보 레벨 참조는
기본계약으로 해소되는데([[기능/조립산출/조립산출]] §3.2) 기본계약 지정이 상품모델링(P5)이라
해소는 조립 시점. 편집 화면에서는 평가 불가.
**경계·오류**:
- 공용조항의 부착 검사 시점이 담보약관과 다름 — 보통약관은 참조 추가 시점이 아니라
  **상품모델링에서 기본계약을 지정하는 순간** 검사.
- 기본계약 미지정·값 미입력은 조립 오류 + 좌표 보고 (편집 화면에서 막지 않음).

## 시나리오 8 — 저장 한 번: 검증 거부 · 판 충돌 · 버립니까

**전제**: 조가 있는 담보약관 템플릿. 같은 템플릿을 두 사람(A · B)이 각자 브라우저로 연다. 잠금은 없다.
**흐름**:
1. A 가 `편집` → 조 하나를 복제하고 사본의 조 명을 고친다 (편집본에만).
2. A 가 경로의 「담보약관 템플릿」을 누른다 → 「고친 내용을 버립니까?」 → 「계속 편집」.
3. B 가 `편집` → 다른 조의 조 명을 고치고 `저장` — 반영되고 판이 오른다.
4. A 가 `저장`.
5. A 가 편집 취소(✕) → 「고친 내용을 버립니까?」 → 「버리기」.
**기대 결과**: 4에서 A 의 저장은 「다른 사람이 먼저 저장했습니다」로 거부되고, A 의 편집본은 화면에 그대로 남는다(자동 병합 없음).
5 뒤 읽기 모드는 B 가 저장한 원본을 보인다. A 가 옮겨 적으려면 다시 `편집`해 새 판에서 시작한다.
**경계·오류**:
- 저장 때 전체 검증에 걸리면(예: 없는 구분자를 읽는 조건식) 저장이 거부되고 편집이 계속된다 — 오류 목록의 「고칠 자리로」가 그 노드를 우측 패널에 싣는다. 원본 · 판은 그대로.
- 편집 중 새로고침 · 창 닫기는 브라우저 경고. 편집본은 로컬에 백업되지 않는다 — 떠나면 사라진다.
- 다른 문서가 조연결 · 보통약관 조 참조로 가리키던 조를 지우는 저장은 깨질 참조를 보이고 확인(「참조 N건 끊고 저장」)을 받는다.
- 템플릿 삭제 · 복제는 읽기 모드의 더보기에만 있다 — 편집 중에는 없다.
