# 문면

> 상태: 초안 · 최종수정: 2026-09-27

## 1. 한 줄

보험 약관의 조문(보통약관 템플릿 · 담보약관 템플릿)을 조 · 항 · 호 · 목 노드 트리로 쓰는 구조 편집기다.
문면은 마스터가 소유하고, 상품마다 다른 문장은 문장 수정이 아니라 **조건 · 치환 슬롯 · 참조**로 미리 감당한다.
약관 작성자가 담보 설계 뒤 · 상품 조립 전에 쓴다. 화면 용어는 「보통약관 템플릿」 · 「담보약관 템플릿」 · 「조문」이다 ([[공통/화면/화면단어]]).

## 3. 규칙

### 3.1 소유와 문서 종류

- **문면은 마스터 소유다.** 상품모델링은 문면을 고치지 못한다 — 상품 간 차이는 값이 가른다 ([[기능/문면/결정/ADR-0003-문면-마스터소유-분기책임]]).
- **담보약관 템플릿** = 담보 하나가 한 벌 소유(특별약관). 담보 상세에서 만든다 — 그 담보에 이미 있으면 거부. 이름은 담보 상세의 기본값 「<담보명> 특별약관」.
- **보통약관 템플릿** = 여러 벌, 상품이 하나를 고른다. 이름은 유일(중복 거부).
- **대응 보통약관** — 담보약관 템플릿은 보통약관 템플릿 한 벌을 지정한다. 조연결 · 보통약관 조 참조의 대상은 그 템플릿의 조로 한정된다.
  해제는 조연결 · 보통약관 조 참조가 0건일 때만. 아직 안 골랐으면 이 담보를 탑재한 상품이 쓰는 템플릿을 **제안값**으로 보이고, 저장해야 확정된다 ([[공통/기술/결정/ADR-0004-null없음-미입력상태]]).
- 문서에 확정 · 게시 상태는 없다. 이력 · 확정은 MVP 이후 ([[공통/기술/결정/ADR-0026-이력개정-이력일자-작업본확정]]).
- **문서 삭제는 관리자만**, 영향(함께 사라지는 조 · 깨질 참조 — 다른 문서의 조연결 · 보통약관 조 참조 · 상품의 템플릿 선택 · 담보의 문서 연결 · 옵션 오버라이드)을 본 뒤 ([[공통/화면/결정/ADR-0019-모드폐지-역할권한]]). 편집자 요청은 서버가 거부한다. 참조가 남아 있어도 지워지고, 그 참조는 깨진 참조가 된다.
- **문서 복제** — 담보약관 → 문면 없는 담보, 보통약관 → 새 이름. 문서 안 조 참조는 사본의 대응 노드를 가리키고, 외부 참조(보통약관 조 참조 · 조연결 · 공용조항 · 별표 · 구분자)는 그대로 둔다.
  — 왜: 내부 참조가 원본을 읽으면 사본의 조를 고쳐도 참조 문장이 원본 조 번호를 찍는다 — 조용히 틀린 문서다. 트리를 통째로 복제하므로 대응 노드는 반드시 있다.
  진입점은 저작 화면 읽기 모드의 더보기 「복제」 — 담보약관은 템플릿이 없는 담보를 골라 그 담보에 연결까지 한다.

### 3.2 노드 트리

문서 = 깊이를 고정하지 않은 노드 트리, **허용 자식은 규칙 표**로 건다 ([[기능/문면/결정/ADR-0012-문면-노드트리-구조편집기]]).
노드 id 는 트리 안에서 유일하다(조건 가지 포함).
관 · 표 · 박스는 허용 자식 규칙의 확장이다 — 저장 구조(jsonb 트리 한 덩어리)는 그대로다.

| 부류 | 노드 |
|---|---|
| 구조 | 문서 · 관 · 조 · 항 · 호 · 목 · 표 · 박스 |
| 블록 자리 동적 | 조건 블록(IF/ELIF/ELSE) · 공용조항 block 참조 · 반복 블록(자리만) |
| 인라인 | 문장(텍스트런) · 치환 슬롯 · 문장 안 조건 · 조 참조 슬롯 · 별표 참조 슬롯 · 공용조항 inline 참조 · 구조 표기(반복 표 셀 전용) · 문장 안 반복(자리만) |

| 자리 | 올 수 있는 것 |
|---|---|
| 문서 | 조 · 관 · 조건 블록 |
| 관 | 조 · 조건 블록 |
| 조 | 항 · 조건 블록 · 공용조항 block 참조 · 표 · 박스 (반복 블록) |
| 항 · 호 · 목의 문장 자리 | 인라인 전부 |
| 항 아래 목록 | 호 · 조건 블록 · 표 · 박스 |
| 호 아래 목록 | 목 · 조건 블록 |
| 조건 가지 안 | 그 조건 블록이 서 있는 자리와 같다 (투명) |

- **번호는 저장하지 않는다 — 계산값이다.** 관 「제N관」, 조 「제N조」(관을 넘어 문서 전체 연속), 항 ①…⑳, 호 「1.」, 목 「가.」. 항이 하나뿐인 조는 항 마커를 찍지 않는다. 가지번호(제N조의M)는 두지 않는다 — 실물의 가지번호 조는 순번으로 다시 매긴다.
  편집기의 번호는 전체 뷰(조건 해소 전) 번호이고, 공용조항 block 참조는 항 하나로 센다 — 실제 번호는 조립이 조건 해소 뒤 다시 매긴다.
  — 왜: 가지번호는 개정으로 조를 끼워 넣을 때 생기는 표기인데 이력 · 개정은 MVP 이후라 규칙을 세울 근거가 없다. 참조는 슬롯이라 순번을 따라간다. 대가로 실물 대조의 조 번호는 순서로만 맞는다(실물 「제27조의1」 → 「제28조」) — 대조는 조 명으로 한다.
- **조의 메타는 조 명 · 조연결뿐이다.** 조 명은 평문이다 — 조 제목에 인라인 조건을 허용하는 것은 [[기능/문면/결정/ADR-0072-참조대상-조uuid-조전체유일P코드]] 결정 2a, **미구현**.
- **조연결** — 담보약관 템플릿의 조에만, 조당 최대 하나, 대상은 대응 보통약관의 조. 보통약관 템플릿의 조에는 둘 수 없다.
- **표** — 제목(선택) · 열 너비 %(1~100 정수, 빈칸은 자동) · 행(제목줄 여부 + 셀). 서식은 **제목줄 여부 · 열 너비 둘뿐**이고 노드 필드로 저장한다(화면 클래스명 같은 값은 저장하지 않는다).
  **셀은 인라인 노드 목록**이라 셀 안에도 조 · 별표 참조가 선다. 불변식(열 하나 이상 · 행마다 셀 수 = 열 수 · 너비 1~100 정수)은 도메인 한 곳(`tableIssues`)에 두고 명령과 저장 검증이 같이 쓴다.
  — 왜: 셀이 평문이면 「번호는 계산값」이 표 안에서만 깨진다 — 실물 제2조 용어정의 표가 「제27조의1(보험료의 납입면제)」을 부른다.
  셀에 참조 · 구조 표기가 있는 표는 행을 글자로 되돌리지 않는다 — 제목 · 너비만 고치고 셀 내용은 셀 단위로 넣는다.
- **박스** — 【용어풀이】 같은 제목 + 줄 목록. 번호 없음.
- 표 · 박스는 항 · 호 · 목 **뒤에 붙는 번호 없는 블록**이다. 준용 판정은 표 · 박스를 각각 한 비교 단위로 보고, 표는 **열 수 · 너비까지** 비교한다 — 같은 글자라도 서식이 다르면 다른 조다 ([[기능/조립산출/조립산출]] §3.5).
- **중첩** — 블록 조건끼리는 중첩 허용, 문장 안 조건 안에 문장 안 조건은 금지(항을 쪼개 블록 조건으로 푼다). 반복 안에 반복 금지.
- **반복 블록 · 문장 안 반복은 자리만 있다.** 편집기에서 넣을 수 없고, 데이터에 있으면 「아직 지원하지 않는다」로 보이며 조립은 오류를 낸다. MVP 의 반복은 표 행 반복 하나뿐이다 (§3.7 · [[기능/구분자/결정/ADR-0070-dict구분자-구조읽기규칙-반복표-담보문서-MVP]] 결정 10).

### 3.3 조건 분기

- **블록 조건** — 구조 노드가 서는 자리에 대신 선다. 조 자리면 조 단위 켜고 끄기다. 가지 순서 = 평가 순서, `ELSE` 는 마지막에 하나까지. 마지막 남은 가지는 지울 수 없다 — 블록째 지운다.
- **조 자리 조건 블록은 IF 하나(켜고 끄기)만** — ELIF · ELSE 는 저장 거부 (ADR-0072 결정 2b). **미구현** — 지금은 조 자리에도 ELIF · ELSE 가 저장된다.
- **문장 안 조건** — 문장 흐름 안의 인라인 분기. 넣을 때 「참일 때」 · 「아닐 때」 두 가지로 시작한다.
- **조건식은 결과가 boolean 인 식**이고 식 언어는 파생식과 한 벌이다 ([[공통/기술/결정/ADR-0013-식언어-통일]]).
  참조할 수 있는 것은 **구분자**(어느 레벨이든) · 담보속성(`exist` · `=` · `≠` 만 — [[기능/담보속성/결정/ADR-0015-담보속성-복원]]) · 내장 경로.
  **마스터 필드를 직접 부르면 저장 거부** — 필드를 문면에 내려면 투영 구분자를 만든다 ([[기능/구분자/결정/ADR-0036-폼-구분자-문면-3층]] · [[기능/마스터/결정/ADR-0037-입력항목-코드마스터-유저정의폼-MVP이후]]).
- **조건식은 구조화 팝업으로만 만든다** — 텍스트 식 입력은 없다 ([[기능/문면/결정/ADR-0066-구분자-노드한정자-조건식-구조화팝업]] 결정 5 · 7).
  - 줄 = 좌변(구분자 칩만) · 연산자 · 우변(좌변 타입별 입력 또는 **같은 타입** 구분자 칩).
  - 연산자는 좌변 타입이 정한다 — boolean `= ≠` · number · date `= ≠ < <= > >=` · string · enum `= ≠`. `list<enum>` 좌변은 연산자가 없어 고를 수 없다.
  - 우변 입력 — boolean 참/거짓 · enum 값 목록 · number 숫자 · date 날짜 · string 글자.
  - 줄 사이는 `그리고 / 또는`, 괄호 없음, 왼쪽부터 차례로 묶는다(`(a 그리고 b) 또는 c`). 저장은 기존 식 AST(`compare` · `and` · `or`)다.
  - 팝업이 줄로 풀지 못하는 식(괄호 · `not` · 집계 직접 사용 · 담보속성 비교)은 **원문 읽기 전용 + 「다시 만들기」**.
- **노드 한정자 `@노드`** — 구분자를 문맥 담보가 아니라 그 세부보장 · 급부 노드에서 평가한다(집계 범위 = 그 노드의 하위). 저장은 노드 id, 화면은 이름 (ADR-0066 결정 1~3).
  - 담보약관 템플릿에서만 쓴다. 오류: 문맥 담보가 없는 문서 · 노드가 담보 트리에 없음(끊어진 참조) · 노드 레벨 ≠ 구분자 레벨.
  - 경고(팝업 안): 그 노드에 구분자가 읽는 값이 없다 — 「항상 거짓」.
  - 담보 구조 정정으로 노드가 사라지면 이 문면이 끊어진 참조가 된다 ([[기능/담보/결정/ADR-0075-담보구조정정-상세편집하나-저장시영향확인]]).

### 3.4 치환 슬롯

- 값 슬롯은 **구분자 하나**를 찍는다. 결과 타입(구분자의 명시 타입)이 **string · enum 인 구분자만** — enum 은 표시명으로 찍힌다(코드는 저장 · 식 전용). number · boolean · date · list<enum> 은 후보에서 거르고 저장 검증이 거부한다.
- **표시 형식 규칙은 없다.** 문면에 찍을 값은 처음부터 string 으로 정의한다(「2.5%」는 string 값이다). number 는 식(비교 · 집계) 전용이다. 같은 값을 문면에도 찍고 식에서도 쓰면 string 구분자와 number 구분자를 따로 두고, 둘의 일치는 사람이 지킨다(도구가 검사하지 않는다).
  — 왜: 형식 속성은 정의 · UI · 변환기가 붙는 과한 장치이고, 자리마다 형식이 다르면 같은 값이 다르게 찍혀 리터럴 비교(생략 · 준용 판정)가 흔들린다. 막지 않고 toString 으로 흘리면 `2.5` · `true` 같은 출력이 남는다.
- 식 · 담보속성 · 마스터 필드는 슬롯에 못 쓴다. 이름 슬롯은 없다 — 상품명 · 상품담보명은 문서 제목 같은 메타 자리에만 선다.

### 3.5 조 참조 · 별표 참조

- **번호를 부르는 자리는 전부 참조 슬롯이다** — 번호는 계산값이라 텍스트로 박으면 밀리는 순간 오참조가 된다.
- **조 참조 슬롯**
  - 대상은 조 · 항 · 호 · 목, **여럿**(덩어리 하나). 대상 0건은 거부. 범위는 「이 템플릿」 또는 「대응 보통약관」 — 후자는 담보약관에서만.
    — 왜: 항 · 호 · 목 번호도 계산값이라, 조건으로 항이 빠지면 텍스트로 박은 「제2항」은 조용히 틀린다(실물의 같은 조 안 「제N항」 참조 31건).
  - 연결어는 「및」 · 「또는」 둘뿐(기본 「및」) — 그 밖의 값은 저장 검증이 거부한다. 쉼표뿐인 나열도 「및」으로 쓴다. 연결어는 마지막 세그먼트 앞에만 붙고 나머지는 쉼표로 잇는다.
    — 왜: 실물의 연결어는 둘뿐이다. 열어 두면 같은 뜻의 문장이 상품마다 다르게 찍히고 검증 · 대조 규칙이 는다.
  - 구간은 **조립 시점의 계산 번호로** 판정한다 — 살아남은 대상을 작성 순서대로 보며 인접한 둘이 같은 상위(조 · 항 · 호) 아래 같은 종류이고 번호가 직전 +1 이면 한 구간. **셋 이상**이면 「A부터 B까지」, 둘이면 낱개(「A 및 B」). 역순 · 건너뜀은 구간이 아니다.
    — 왜: 어느 대상이 분기로 빠지는지가 상품마다 달라 저장 시점에는 연속인지 모른다 — 작성자가 구간 여부를 고르게 하면 분기 뒤 틀린 표기가 된다. 「A부터 B까지」는 사이에 생략된 것이 있을 때 뜻이 있어 둘은 낱개가 실물 관행이다.
  - 상위 경로는 앞 대상과 같은 만큼 생략한다 — 첫 대상은 슬롯 자리 기준, 다음은 직전 대상 기준, 구간 끝은 구간 시작 기준이라 자기 단계만 남는다(같은 조면 「제1항」, 다른 조면 「제35조(해약환급금) 제1항」). 조 명 괄호는 항상. 「보통약관 」 접두는 덩어리당 한 번.
    — 왜: 접두 생략을 문장 · 접속어로 판정하면 노드 트리에 문장 경계가 없어 기준이 흔들린다. 작성자가 덩어리를 만들면 판정할 것이 없다.
  - 편집기 미리보기는 같은 규칙(`referenceChunkLabel`)이되 **전체 뷰 번호**라 분기를 반영하지 않는다. 대상이 사라졌으면 「(연결 끊김 N건)」.
  - 조립은 분기 · 생략으로 사라진 대상을 덩어리에서 빼고 남은 대상의 당겨진 번호로 다시 판정한다. **대상 전부**가 사라졌을 때만 조립 오류 `articleGone`(상품이 노출을 끈 조면 `articleHidden`) — issue 는 대상마다, 오류 마커는 자리에 하나.
    — 왜: 조건 문면은 원래 상품마다 조가 빠지라고 있다. 부분 탈락을 오류나 경고로 두면 정상 상품이 「완성본 아님」이 되거나 경고로 도배된다.
  - 실물 원문의 나열(「제17조, 제18조, 제19조」 · 「제10호, 제11호」)과 조립 표기(「제17조부터 제19조까지」 · 「제10호 및 제11호」)의 차이는 실물 대조에서 정규화해 비교한다 — 허용 차이 ⑤ ([[QA/인수기준]] · `compare.ts` `normalizeEnumeration`).
  - 대상 식별은 지금 노드 id(`{ nodeId }`)다. 조는 uuid · 항 · 호 · 목은 조 전체에서 유일한 P코드(`{ articleId, code }`)로 바꾸는 것은 ADR-0072 — **미구현** (P코드 채번 · 배타 가지 코드 공유 · 이동 충돌 · 코드 수정 창 전부).
- **별표 참조 슬롯** — 별표 코드 하나만 저장한다. 편집기에는 번호가 없고 「【별표 이름】」으로 보인다. 번호는 조립이 책자마다 매긴다 ([[기능/별표/결정/ADR-0063-별표-자동수집-자동번호]] · [[기능/별표/별표]]).
- **참조 대상은 추가할 때와 저장할 때 두 번 검증한다** — 없는 조 · 대응 보통약관 밖 조 · 없는 별표 · 없는 공용조항은 거부.
- **같은 문서의 조 참조가 가리키는 노드는 지울 수 없다** — 참조처를 보여 주고 거부한다. 다른 문서가 가리키는 것(담보약관의 조연결 · 보통약관 조 참조)은 삭제 확인에 보이고 지워진다 — 그쪽은 깨진 참조가 된다.

### 3.6 공용조항 참조

- block 참조는 조 안 항 자리에, inline 참조는 문장 안에 선다. 공용조항 본문은 여기서 고치지 않는다 (공용조항 feature).
- **옵션 선택은 사용처인 이 문서가 소유한다.** 넣을 때는 미선택이어도 되고, 저장 검증이 미선택을 거부한다 ([[기능/공용조항/공용조항]] §3.2). 담보약관의 옵션은 담보 마스터 안에서 다 정해야 한다 — 남으면 담보 상세가 경고한다 ([[기능/상품/상품]] §3.6 · [[기능/담보/담보]] §3.5).
- 요구 구분자가 카탈로그에 없는 공용조항은 참조 추가가 성립하지 않는다 ([[기능/공용조항/공용조항]] §3.4 검사 ②).
- block 참조의 「비교 제외」(준용 판정에서 이 참조가 만든 항을 뺀다) — 모델 · 조립에는 있고 **편집기 칸은 미구현**.
- **준용규정 조는 MVP 동안 작성자가 담보약관에 쓴다** — block 공용조항 「준용규정」 참조 + 제외 조 목록은 보통약관 조 참조 슬롯 ([[기능/조립산출/조립산출]] §3.5). 「생략하기」는 조립의 자동 판정이라 편집기에 수동 생략이 없다 ([[기능/조립산출/조립산출]] §3.5).

### 3.7 반복 표

담보약관 템플릿의 표에 **행 반복**을 건다 (ADR-0070 결정 6).

- 깊이 1 = 세부보장마다, 깊이 2 = 세부보장 › 급부마다. 머리글이 아닌 행이 **템플릿**이고, 문맥 담보의 key 조합마다(세부보장 순 → 급부 순) 복제된다.
- **구조 표기** 칩(`[세부보장명]` · `[급부 N 급부명]`)이 그 행의 노드 표기로 바뀐다.
- 템플릿 셀 안의 한정자 없는 구분자 참조는 **그 행 노드**(자기 또는 조상 중 구분자 레벨의 노드)에서 평가한다. `@노드` 참조는 고정 노드 그대로.
- **바깥 key 열은 세로 병합이 자동**이다 — 템플릿 행이 하나일 때, 바깥 레벨 구조 표기만 든 열은 같은 노드가 이어지는 동안 합친다. 그 밖의 병합은 없다.
- key 조합이 0 이면 **표를 통째로 생략**한다.
- 저장 검사 — 오류(저장 거부): 문맥 담보 없는 문서의 반복 표 · 반복 깊이 밖 레벨의 구조 표기 · 행보다 아래 레벨을 한정자 없이 참조 · 반복 표 밖 구조 표기. 경고(저장은 됨): 템플릿 행에 구조 표기 · 참조가 하나도 없음 — 「모든 행이 같아집니다」.
- 동적 표(최초지급금액표 생성 · 셀 계산 · 가로 병합)는 MVP 밖이다 ([[QA/인수기준]] MVP 범위).

### 3.8 저장과 검증

- **저작 화면은 저장 한 번이다** ([[기능/문면/결정/ADR-0074-저작화면-브라우저편집본-저장한번-판충돌검사]]). 읽기 모드에서 시작하고, `편집`이면 원본 트리와 **판 번호**를 받아 브라우저에 **편집본**을 만든다.
- 편집은 전부 **편집 명령**이다 — 트리 명령(추가 · 삭제 · 이동 · 복제 · 글자 · 제목 · 슬롯 · 참조 · 가지 · 조연결 · 옵션 · 표) + 템플릿 이름 + 대응 보통약관 지정.
  명령은 브라우저에서 순수 도메인(`applyEdit`)으로 편집본에 곧바로 적용되고 **명령 목록**에 쌓인다. 원본은 저장 전까지 바뀌지 않는다 — 조립 · 다른 화면은 원본만 본다.
  - 복제는 새 id 를 매기므로 매긴 사본 id 를 명령에 싣는다 — 서버가 같은 id 로 다시 적용해야 사본을 가리키는 뒤 명령이 성립한다.
- **명령은 건드린 자리를 그 자리에서 검사한다** — 거부되면 편집본은 그대로, 본문 위에 사유 배너.
- **`저장` = 명령 목록 + 시작 판을 서버로.** 서버가 ① 판이 같은지 확인하고 ② 원본에 명령 목록을 다시 적용한 뒤 ③ **문서 전체**를 검증해 ④ 한 트랜잭션으로 반영하고 판을 올린다. 서버가 최종 검증자다.
  - 전체 검증 = 구조(허용 자식 · 중첩 · id · 가지) · 참조 대상 · 공용조항 · 식(문법 · boolean · 구분자만 · `@노드`) · 슬롯 타입 · 반복 표 오류. 오류가 하나라도 있으면 저장 거부 — 편집은 계속되고 오류마다 「고칠 자리로」(그 노드를 우측 패널에).
  - 보통약관 템플릿 이름이 겹치면 거부.
  - **판이 다르면 거부** — 「다른 사람이 먼저 저장했습니다」. 편집본은 화면에 남고 자동 병합은 없다. 잠금은 없다.
  - **다른 문서가 가리키던 조가 사라지는 저장**(그 문서의 조연결 · 보통약관 조 참조)은 깨질 참조를 보이고 확인을 받는다 — 확인하면 저장되고 그쪽은 깨진 참조가 된다.
- **판은 문서 행을 바꾸는 모든 저장이 올린다** — 저작 화면의 저장 · 복제로 만든 새 문서(판 1) · 시드 적재 · 서비스의 명령 적용 · 이름 · 대응 보통약관.
- 검증 목록(반복 표 경고 포함)은 「템플릿 전체」 패널에 보인다 — 편집 중이면 편집본을 서버 저장 검증과 같은 코드(`validateDocument`)로 검사한 것이다.
### 3.9 사전평가

- **담보약관 템플릿만** 돈다. 문맥 = 그 담보의 **마스터 값**. 상품 · 세목 레벨 구분자와 담보속성 조건은 **미결**이다 (조립 때 정해진다 — [[기능/문면/결정/ADR-0003-문면-마스터소유-분기책임]] 결정 3).
- 보통약관 템플릿은 담보 레벨 문맥이 없어 평가하지 않는다 ([[기능/조립산출/조립산출]] §3.2) — 상품 조립 미리보기가 그 몫이다.
- 가지 판정은 참 · 거짓 · 미결 · 오류 넷. 앞 가지가 참이면 뒤는 거짓, 앞이 미결 · 오류면 뒤는 미결. **거짓 가지만 톤다운**하고 번호에서 빼서 이후 번호가 당겨져 보인다 — 미결 · 오류는 톤다운하지 않는다.
- 구분자가 읽는 마스터 값이 미입력이면 그 가지는 「오류 — 미입력」으로 보인다.
- **실시간이 아니라 눌러서 돈다.** 가상 값 시뮬레이션은 없다. 톤다운은 잠금이 아니다 — 톤다운된 가지도 편집할 수 있다. 뷰 상태는 쿼리일 뿐 저장하지 않는다.
- 반복 표는 담보 마스터 구조(세부보장 · 급부)로 펼쳐 보인다.

## 4. 화면

좌측 내비 「약관 조문」 아래 **보통약관 템플릿**(`/documents?kind=general`) · **담보약관 템플릿**(`/documents?kind=coverage`) 두 항목이 같은 route 를 쓴다.
담보약관 템플릿은 담보 상세(`/coverages/<id>`)의 「템플릿 생성」(편집 중에만) · 「담보약관 템플릿 열기 →」, 관계정보 · 공용조항 · 별표 사용처의 좌표 링크(`?node=`)로도 들어온다.

### 4.1 조회 (`/documents?kind=general|coverage`) — L1

| 구성 | 보통약관 템플릿 | 담보약관 템플릿 |
|---|---|---|
| 제목 줄 | 「보통약관 템플릿」 + `+` (→ `/documents/new`) | 「담보약관 템플릿」 — `+` 없음 (담보 상세에서 만든다) |
| 검색 | 제목 | 제목 |
| 열 | 제목(→ 저작) · 최종수정 · 수정자 | 제목(→ 저작) · 담보(「담보 열기」 → 담보 상세) · 대응 보통약관(「있음」 → 그 템플릿 / 「없음」) · 최종수정 · 수정자 |
| 페이저 | 50건 · 「총 N건」 | 같음 |

| 상태 | 표시 |
|---|---|
| `kind` 없음 · 잘못됨 | 다른 쿼리는 두고 `kind=general` 로 보낸다 |
| 목록이 빔 — 보통약관 | 빈 상태: 「여러 벌 존재하며 상품이 그중 하나를 선택해 쓰는 문서」 · 예 「상해보험 표준약관」 · 「새 보통약관 템플릿 만들기」 |
| 목록이 빔 — 담보약관 | 빈 상태: 「담보 하나가 소유하는 특별약관 문서 — 여기서 직접 만들지 않는다」 · 담보 목록으로 |
| 검색 결과 없음 | 「이 조건에 맞는 … 이 없습니다」 |

### 4.2 새 보통약관 템플릿 (`/documents/new`)

- 경로 `보통약관 템플릿 › 새 보통약관 템플릿`, 제출은 헤더 우측. 칸은 **제목** 하나(필수).
- 이름이 이미 있으면 같은 화면에 오류 배너. 만들면 빈 문서의 저작 화면으로 간다.

### 4.3 저작 (`/documents/<id>`) — L3

전폭 화면. 세로는 바 한 줄 + 남는 높이, 가로는 **목차 196 / 본문 / 우측 패널 360**.

```
┌ 담보약관 템플릿 › 일반상해사망 특별약관   조 5 · 검증 오류 0 / 노드 87   〔더보기▾〕〔편집〕 ┐
├──────────────┬───────────────────────────────────────┬────────────────────────┤
│ 제1조(보험금…) │        일반상해사망 특별약관               │ 사전평가 · 미리보기       │
│ 제2조(…)      │  제1조(보험금의 지급사유)                  │  담보 마스터 값을 문맥으로… │
│ 제3조(…)      │   ① 회사는 … 〔치환〕 … 【별표 장해분류표】  │  〔미리보기〕             │
│               │  │IF 갱신여부 = 참                        │                         │
│  (조만)        │  │ ② …                                  │  (편집 모드면 여기가       │
│               │  ┆ELSE                                   │   고른 자리의 폼)          │
│               │  ┆ ② …                                  │                         │
└──────────────┴───────────────────────────────────────┴────────────────────────┘
```

**구성**

| 자리 | 내용 |
|---|---|
| 바 | 경로가 곧 제목 줄 — `보통약관 템플릿 › 제목` / `담보약관 템플릿 › 제목`, 앞 마디는 그 종류 목록으로 ([[공통/화면/디자인원칙]] §1.7). 규모 「조 N · 검증 오류 N / 노드 N」(편집 중이면 편집본). 오른쪽 끝 — 읽기: 〔더보기 ▾〕(복제 · 템플릿 삭제) · 〔편집〕 / 편집 중: 「편집 중 · 고친 것 N건 — 저장해야 반영」 · ✕(편집 취소) · 〔저장〕(고친 것이 있을 때만) |
| 목차 | **조만** 싣는다(관 · 조건 블록 안 조까지 펼쳐 순서대로). 「제N조(조 명)」, 현재 조 표시. 조가 없으면 「조 없음」 |
| 본문 | 명조로 그린 문서 한 벌 — 제목 · 관 · 조(조연결이 있으면 조 위에 「조연결 — 보통약관 제N조(…)」) · 항 · 호 · 목 · 표 · 박스. 블록 조건은 가지마다 괘선 + 머리 칩(`IF` 실선 · `ELIF` · `ELSE` 파선), 문장 안 조건은 점선 밑줄 + tooltip, 슬롯 · 참조는 글자 칩, 반복 표는 템플릿 행 왼쪽에 「세부보장마다」 · 「급부마다」 띠 |
| 우측 패널 | 모드와 선택에 종속된다 — 탭이 없다 (아래 상태 표) |

**상태** — 모드 · 선택 · 편집본은 브라우저 상태다(쿼리가 아니다). 쿼리는 들어오는 길만 — `?node=`(그 자리 표시 · 그 조로 스크롤) · `?view=eval`(미리보기를 켠 채) · `?del=1` · `?dup=1`(더보기의 확인 카드) · `?error=`.

| 상태 | 본문 | 우측 패널 |
|---|---|---|
| 읽기 (기본) | 조작 없음 | 「사전평가 · 미리보기」 — 설명 한 줄 + 〔미리보기〕 |
| 읽기 · 평가 후 (`view=eval`) | 거짓 가지 톤다운(흐림 · 취소선), 칩 뒤 「· 참/거짓/미결/오류」, 번호는 거짓 가지를 빼고 당겨짐, 슬롯에 값 | 조건 블록마다 가지별 「식 · 판정」 + 「채택 분기」, 그 아래 **결과 조문** 한 벌(반복 표는 펼침 · 행 0 이면 회색 「표 생략됨」). 버튼은 〔평가 결과 지우기〕 |
| 읽기 · 보통약관 | 조작 없음 | 빈 상태 — 「보통약관은 담보 레벨 문맥이 없어 여기서 평가하지 않는다」 + 「상품 조립 미리보기로 →」 |
| 빈 문서 | 「아직 조가 하나도 없다 — 조립해도 아무것도 만들지 않는다」 · 예 · 「편집을 누르고 여기에 추가로 시작 · 다 쓰면 저장」 | 모드대로 |
| 편집 · 선택 없음 | 블록 행마다 오른쪽 끝 아이콘, 인라인 글자는 점선 밑줄 버튼, 표 셀마다 ＋, 조건 칩은 버튼 | **「템플릿 전체」** — 템플릿 이름 〔이름 적용〕 · 대응 보통약관(담보약관만, 제안값이면 배지 「제안값 — 적용하고 저장해야 확정」) 〔대응 보통약관 적용〕 · 여기에 추가(조 · 관 · 조건 블록) · 저장 검증 목록(편집본, 「고칠 자리로」) · 담보약관이면 〔편집본 미리보기〕 |
| 편집 · 노드 선택 | 고른 자리 표시 | 제목(「제3조(면책)」 + 종류) · 「← 템플릿 전체로」(선택 해제) · 조작 아이콘 · **그 노드의 폼** (아래 표) |
| 편집 · 조건 가지 선택 | 칩 밑줄 | 「조건 가지」 — 조건식(팝업) 〔수정〕 · 사전평가 판정(켰으면) · 가지 안 여기에 추가 · 가지 삭제 🗑 |
| 편집 · 표 셀 선택 | 그 셀 ＋ 강조 | 「N행 M열 셀」(반복 템플릿 행이면 표시) + 셀 여기에 추가(펼침) + 「표 속성」 폼 |
| 노드 삭제 확인 | — | 확인 카드가 패널 전체를 차지 — 「제N조(…) 삭제 — 저장하면 사라집니다」, 함께 사라지는 것(항 2 · 호 5 …) · 저장하면 깨질 다른 문서의 참조(조연결 · 보통약관 조 참조, 고치러 가는 링크 — 저장 때 다시 확인) · 〔삭제〕 / 〔취소〕. 이 문서의 조 참조가 가리키면 〔삭제〕 대신 참조처 목록(「그 자리로」) |
| 명령 거부 | 본문 위 사유 배너 — 「적용하지 못했다 — …」, 편집본 그대로 | — |

| 조 | 조 제목 〔제목 적용〕 · 조연결(담보약관만 — 대응 보통약관의 조 목록 · 「연결 없음」, 보통약관 미지정이면 안내) 〔조연결 적용〕 · 여기에 추가(항 · 조건 블록 · 공용조항(조 단위) · 표 · 박스) |

| 별표 참조 슬롯 | 별표 선택(「이름(코드)」) 〔별표 적용〕 |
| 공용조항 참조 | 옵션마다 선택지 select(「— 미선택 —」 포함) 〔옵션 적용〕. 공용조항이 없으면 「깨진 참조」 배너 |

「여기에 추가」는 접힌 메뉴 — 종류를 고르고 그 종류에 필요한 칸(제목 · 표 · 박스 줄 · 문장 · 슬롯 참조 · 구조 표기 · 조건식 · 참/아닐 때 문장 · 참조할 조 · 별표 · 공용조항)을 채운 뒤 ＋(편집본에 추가). 쓰지 않는 칸은 비워 둔다.

**조건 팝업** (조건식 칸 · 가지 칩을 누르면 뜨는 모달 — ADR-0066 결정 5 · 6)

```
┌ 조건 편집 ─────────────────────────────────┬ 〔담보 구분자〕〔구분자〕 ───────┐
│ [감액여부 @유사암 ⓧ] [ = ▾] [ 참        ▾] │ 🔍 [검색        ]                │
│            [ 그리고 ▾ ]                    │ ▾ 암진단비            (담보)      │
│ [면책15세이상     ⓧ] [ = ▾] [ 거짓      ▾] ⊖│     감액여부  면책여부            │
│ [+ 조건 추가]                              │   ▾ 유사암  [감액]    (세부보장)   │
│ ⚠ 2번 줄: 「진단급부」 에 값이 없어 항상 거짓 │     감액여부  면책여부            │
```

| 자리 | 동작 |
|---|---|
| 좌변 | 구분자 칩만 — 타이핑 없음. 빈 칸을 누르면 포커스, 트리 잎 더블클릭으로 채움, ⓧ 로 비움 |
| 연산자 | 좌변 타입이 목록을 정한다. 좌변이 비면 잠김 |
| 우변 | 좌변 타입별 입력. 우변에 포커스를 두고 트리를 찍으면 구분자 칩 — 타입이 다르면 「타입이 다르다 (boolean ≠ number)」로 거부 |
| 담보 구분자 탭 (담보약관만) | 뿌리 = 문맥 담보, 가지 = 실제 세부보장 · 급부, 잎 = 그 노드 레벨의 구분자. 노드 아래 잎 = `@노드` 자동, 뿌리 아래 잎 = 한정자 없음. 값이 든 노드에 배지(감액 · 면책). 반복 표 템플릿 셀 안이면 맨 위에 「현재 행」 가지(한정자 없음) |
| 구분자 탭 | 담보 트리 레벨이 아닌 구분자(상품 · 세목)까지 평면 목록 + 검색. 보통약관이면 이 탭만 |
| 빠른 조건 | 담보 레벨 boolean 구분자 「X = 참」을 한 번에 넣는다 |
| 검사 | 빈 좌변 · 우변 · 연산자 부적합 · 타입 불일치 · 끊어진 참조는 오류로 확인 잠금, 「항상 거짓」은 경고 |
| 못 여는 식 | 원문 읽기 전용 + 〔다시 만들기〕(빈 줄에서 시작) |
| 확인 · 취소 | 확인은 칸의 식만 바꾼다 — 편집본에 넣는 것은 그 폼의 적용 버튼(가지면 〔수정〕), 원본 반영은 바의 〔저장〕. 취소는 버린다. 칸 옆 ⓧ 는 식을 비운다(= 그 밖의 경우) |

**유저액션**

| 누르면 | 무엇이 되나 |
|---|---|
| 바 〔편집〕 | 원본 트리 · 판을 새로 받아 편집본을 만들고 편집 모드로. 같은 자리 버튼이 〔저장〕. 평가 결과는 지운다 |
| 바 〔저장〕 | 명령 목록 + 시작 판을 서버로 — 판 확인 · 재적용 · 전체 검증 뒤 한 번에 반영하고 읽기 모드로. 거부면 편집 계속(§3.8) |
| 바 ✕ | 편집 취소 — 고친 것이 있으면 「고친 내용을 버립니까?」 뒤 읽기 모드(지금 원본을 새로 받는다) |
| 경로 앞 마디 · 화면 밖 링크 (편집 중) | 고친 것이 있으면 「고친 내용을 버립니까?」 뒤 이동. 새로고침 · 창 닫기는 브라우저 경고 — 편집본은 백업되지 않는다 |
| 바 〔더보기〕 › 복제 · 템플릿 삭제 (읽기 모드만) | 복제 카드 / 삭제 확인 카드 — 관리자: 삭제 뒤 그 종류 목록으로. 편집자: 거부 메시지 |
| 목차의 조 | 그 조로 스크롤, 현재 조 표시 |
| 〔미리보기〕 · 〔편집본 미리보기〕 · 〔평가 결과 지우기〕 | 사전평가를 켜고 끈다 — 편집 중이면 편집본을 평가한다. 읽기 모드는 `view=eval` 을 주소에 남긴다 |
| 행 ✎ · 인라인 글자 · 조건 칩 · 셀 ＋ | 그 자리를 우측 패널에 싣는다 |
| 행 ↑ · ↓ | 같은 부모 안에서 한 칸 이동, 번호 재계산 (끝이면 아무 일 없음) — 편집본 |
| 행 ⧉ | 바로 뒤에 사본 — 하위 트리 · 조연결 · 참조 대상을 그대로 복사, 사본 안 조 참조는 사본을 가리킨다 — 편집본 |

## 5. 미결

- **ADR-0072 구현** — 항 · 호 · 목 P코드(조 전체 유일 · 배타 가지 공유 · 채번 · 이동 충돌 · 코드 수정 창) · 조 제목 인라인 조건 · 조 자리 조건은 IF 하나. 결정은 났고 코드는 없다. 구현 때 ADR-0066 결정 4(IF/ELIF/ELSE)에 「조 자리 제외」 한 줄이 필요하다.
- **조건 블록 가지의 「여기에 추가」 메뉴가 자리와 어긋난다** — 가지 메뉴가 항상 조 안 자리(항 · 표 …) 또는 문장 자리를 준다. 조 자리(문서 · 관) · 호 목록 · 목 목록에 선 조건 블록의 가지에는 조 · 호 · 목을 넣을 수 없다(저장 거부). 조 단위 켜고 끄기를 화면에서 못 만든다 — 결함으로 본다.
- **담보속성 조건을 팝업으로 만들 길이 없다** — 팝업 좌변은 구분자뿐이라 `exist(attr.…) and attr.… = '…'`(시드의 갱신유형 조건)는 원문 읽기 전용으로만 보인다. 담보속성을 트리 · 목록에 올릴지, 투영 구분자로 대신할지.
- **적용하지 않은 폼 입력** — 폼 칸을 고치고 「적용」을 누르지 않은 채 다른 자리를 고르거나 저장하면 그 입력은 버려진다. 디자인원칙 §2 L3 의 「적용하지 않은 편집이 있다 — 적용 / 버리기」 물음은 아직 없다.
- **편집기에 없는 조작** — 문서 복제 · 가지 순서 바꾸기(도메인 명령은 있음) · 다른 부모로 이동 · 승격/강등 · 조건 블록 해제(남길 가지를 부모로) · 공용조항 block 참조 「비교 제외」 · 자기 조 참조 거부. 어느 것을 MVP 에 둘지.
- **미입력 값의 사전평가 표기** — 사전평가 시나리오 S2 는 「미결」, 코드는 「오류 — 미입력」. 둘 다 톤다운하지 않는 것은 같다. 표기를 하나로.
- **상품담보 미리보기**(사전평가 시나리오 S5 — 탑재된 상품담보 스냅샷 값으로 이 문면을 평가) — 문면 화면에는 없고 상품 조립 미리보기가 대신한다. 문면 화면에 둘지.
- 사전평가에서 `@노드` 줄에 어느 노드였는지(「(유사암 › 진단급부)」) 덧붙이는 표시 — 없다.
- **소유 담보로 가는 길** — 담보약관 템플릿에서 담보 상세로 가는 링크가 없다(경로는 목록뿐).
- **동적 표** — 최초지급금액표 생성 · 셀 계산 · 가로 병합은 MVP 밖(R02 첫 작업). 출발점은 아카이브한 ADR-0038 · 0039 · 0042 · 0058 (`_archive/2026-09-27_문서재편/06_결정/`) 과 동적표 기획 두 벌.
- **반복의 나머지** — 반복 블록 · 문장 안 반복 · 상품 문맥 반복(보통약관 · 별표에서 세목 › 담보) · 3층 이상 (ADR-0070 결정 7). 담보 구조를 바꿔도 문면의 평문 나열은 따라오지 않는다([[QA/인수기준]] MVP 범위 — 알려진 제한).
- **조건식 B · C 단계** — 값 비교(「감액 기간이 1년이면」 — 표 열 투영 + `max/min`)와 급부마다 문장 반복. 문법 자리만 예약.
- **종별 문구(세목 슬롯)** — 세목을 유형 필드 값으로 지목해 `N종(이름)`을 찍는 슬롯. MVP 이후.
- 0 · 2+ 모드에서 블록 안 조가 일반조항 조를 가리키는 표기(「제1절 제N조」?) — 실물 확인 전 잠정 (조립산출 준용 쪽).
- **실물 구간 표기 읽기** — `scripts/terms/refs.ts` 가 실물의 「제1항부터 제3항까지」를 참조로 읽지 않고 번호가 박힌 평문으로 둔다. 「→ 대상 셋」으로 읽어야 한다.
- 실물 대조에서 「나열 ↔ 구간」 차이를 허용하지 않기로 바뀌면 구간 여부를 슬롯 속성으로 두는 안을 다시 본다.
