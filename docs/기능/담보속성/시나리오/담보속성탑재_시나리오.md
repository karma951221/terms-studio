# 담보속성탑재 시나리오

> 상태: 초안 · 최종수정: 2026-09-01
> 관련 기획: [[기능/상품/상품]] · [[기능/담보속성/결정/ADR-0015-담보속성-복원]] · [[기능/상품/결정/ADR-0002-탑재-값스냅샷]]

## 시나리오 1 — 담보속성 카탈로그 편집
**전제**: 빈 카탈로그.
**흐름**:
1. 속성 종류 「갱신유형」 채번, 유효값 「갱신형」 등록 — 종류·유효값 모두 유저 편집 데이터(코드 아님).
2. 속성 종류 「부가유형」 채번, 유효값 「추가」 등록.
3. 갱신유형에 담보명 규칙 등록 — prefix 「갱신형 」. 부가유형에 suffix 「 추가」. 적용 순서 지정.
**기대 결과**: 카탈로그에 종류 2개와 각 유효값·담보명 규칙 저장. 이후 탑재 화면의 속성 선택지가 된다.
**경계·오류**: 사용 중(상품담보·식이 참조하는) 종류·유효값의 삭제는 프로덕션에서 서버 거부([[기능/구분자/구분자]] MVP 잠정 규칙 준용). 유효값 표시명 변경은 자유.

## 시나리오 2 — 탑재 = 담보 × 속성 값 조합 (sparse · 다중 탑재 · 중복 거부)
**전제**: 일반상해사망보장 담보 마스터. 시나리오 1의 카탈로그.
**흐름**:
1. 일반상해사망보장을 속성 없이 탑재 → 상품담보 1(속성 조합 = 없음).
2. 같은 담보를 부가유형 = 추가 로 탑재 → 상품담보 2. 같은 담보의 다중 탑재 성립.
3. 같은 담보를 다시 부가유형 = 추가 로 탑재 시도.
**기대 결과**: 1·2는 성공 — 상품담보는 담보 × 담보속성 값 조합으로 하나 결정되고, 각각 특별약관 한 벌이 나오는 단위다. 필요한 속성만 붙는다(sparse) — 갱신유형은 두 탑재분 모두 「미사용」.
**경계·오류**: 3은 같은 조합의 중복 탑재 — 서버가 거부(유일성). 새 속성 종류를 나중에 채번해도 기존 상품담보는 그 속성 미사용으로 남는다.

## 시나리오 3 — default 상품담보명 생성과 수동 변경
**전제**: 수술비 담보 마스터. 갱신유형 담보명 규칙 = prefix 「갱신형 」.
**흐름**:
1. 수술비를 갱신유형 = 갱신형 으로 탑재 → default 상품담보명 「갱신형 수술비」 생성(속성 조합 + 속성별 담보명 규칙).
2. 상품모델링에서 이름을 「갱신형 수술비Ⅱ」로 수동 변경.
**기대 결과**: 이름은 규칙으로 생성된 뒤 자유 변경 가능. 시나리오 2의 상품담보 2 는 부가유형 suffix 규칙으로 「일반상해사망보장 추가」가 된다.
**경계·오류**: 이름은 문서 제목 등 메타 자리에만 쓰인다 — 본문 문면이 상품담보명을 직접 부르는 참조는 없다([[00_시작/도메인모델]] §3).

## 시나리오 4 — 값 스냅샷과 필드 단위 수정
**전제**: 수술비 담보 레벨 구분자에 지급률 기본값 50%. 시나리오 3의 탑재 완료.
**흐름**:
1. 탑재 순간 마스터 값이 상품담보로 복사됨(스냅샷).
2. 마스터의 지급률을 60% 로 변경.
3. 이미 탑재된 「갱신형 수술비」의 값 확인 → 50% 유지.
4. 상품담보 쪽에서 지급률만 필드 단위로 70% 수정.
5. 같은 담보를 새로 탑재 → 새 탑재분은 60% 스냅샷.
**기대 결과**: 마스터 변경은 이미 탑재된 상품담보에 무영향, 이후 탑재분에만 반영. 공유되는 것은 구조뿐.
**경계·오류**: 마스터 기본값의 사후 복사 없음 — 탑재 시점 스냅샷 외의 두 번째 복사 시점은 존재하지 않는다([[00_시작/도메인모델]] §5).

## 시나리오 5 — 상품담보별 세목 부착과 기본계약 지정
**전제**: 유효 조합 3개 등록된 상품(세목구성 시나리오 3). 상품담보 여러 개 탑재됨.
**흐름**:
1. 「갱신형 수술비」에 적용 조합으로 (1종, 1형)·(2종, 1형)만 부착 — 상품담보마다 부착 세목이 다르고, 유저가 상품담보별로 설정한다.
2. 일반상해사망보장(상품담보 1)을 기본계약으로 지정.
**기대 결과**: 담보 적용범위가 세목 조합 단위로 저장. 기본계약 지정 순간 보통약관의 부착 검사가 돈다([[기능/조립산출/조립산출]] §3.2 평가 문맥) — 보통약관 문맥의 담보 레벨 참조가 기본계약으로 해소 가능한지 검사.
**경계·오류**: MVP 는 기본계약 정확히 1개 — 미지정·복수 지정 상태로는 조립이 성립하지 않는다([[00_시작/범위]]). ⚠ 미결: 세목 부착 UI 의 기본값·화면 흐름 ([[기능/상품/상품]]이 [[공통/화면/화면목록]] 몫으로 위임 — 화면기획 미작성).

## 시나리오 6 — 담보속성 조건식 (exist·=·≠)
**전제**: 수술비 담보약관 편집 화면. 카탈로그에 갱신유형(유효값: 갱신형).
**흐름**:
1. 인라인 조건에 `갱신유형 = 갱신형` 작성 → 저장됨(작성은 관대 — exist 가드 없이 허용).
2. `exist(갱신유형) and 갱신유형 = 갱신형` 작성 → 저장됨.
3. RHS 에 구분자 참조를 넣어 작성 시도.
4. 담보속성 LHS 에 `>` 등 다른 연산 작성 시도.
**기대 결과**: 담보속성 LHS 의 허용 연산은 `exist` · `=` · `≠` 셋뿐, RHS 는 그 속성의 유효값 리터럴만. 3·4는 작성 시점 거부.
**경계·오류**: 담보약관 편집 문맥에서 담보속성 조건은 사전평가 불가(미결 표시) — 속성은 탑재 때 정해져 마스터에 값이 없다. 전체 뷰·상품담보 미리보기([[기능/문면/문면]])로 확인. 미사용 속성의 =/≠ 평가 오류는 [[기능/조립산출/시나리오/조립오류_시나리오]] 참조.
