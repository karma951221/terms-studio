# ADR-0015 — 담보속성 실체 복원

> 상태: 채택 · 날짜: 2026-08-31

## 맥락

[[00_시작/도메인모델]] §1 은 「terms-lab 의 담보속성은 파생을 가르는 축이었다 — 새 모델에서는
별도 장치 없이 담보 부착 구분자의 **값 차이가 곧 탑재분의 구별**」이라고 정했었다
(2026-08-29). 상품담보명 생성은 「파생 축 구분자의 작명 메타」가 맡는 그림이었다.

P5 상품탑재 기획(2026-08-31)에서 이 그림의 빈틈이 드러났다 —

- **상품담보의 정체성이 흐릿하다.** 「같은 담보를 두 번 탑재했는데 값이 우연히 같으면?」
  값 차이 구별로는 유일성을 걸 수 없다.
- 무엇이 탑재분을 가르는 축인지가 **수많은 구분자 값 사이에 암묵적으로** 흩어진다 —
  「갱신형」은 정체성의 축이고 「지급률 50%」는 아닌데, 모델이 이를 구별하지 못한다.
- 문면 분기(갱신형 수술비)가 정체성 축을 읽으려면 결국 그 축이 식의 참조 대상이어야 한다.

## 결정

**담보속성을 별도 카탈로그 실체로 복원한다** (2026-08-29 결정 번복).

1. 담보속성 = **종류 + 종류별 유효값 목록.** 둘 다 유저가 수정 가능한 데이터다.
2. **상품담보 = 담보 × 담보속성 값 조합.** 조합이 상품담보를 하나 결정하고
   (특별약관 한 벌이 나오는 단위), 같은 조합의 중복 탑재는 서버가 거부한다.
3. **sparse 선택** — 상품담보는 필요한 속성 종류만 붙인다. 새 종류 채번은 이후
   상품담보의 형태만 바꾸고, 기존 상품담보는 그 속성 「미사용」으로 남는다.
4. **식의 참조 대상** — LHS 가 담보속성이면 `exist` · `=` · `≠` 세 연산만,
   RHS 는 그 속성의 유효값 리터럴만. 미사용 속성의 `=`/`≠` 평가는 **오류 + 좌표 보고**
   (작성은 가드 없이 허용하되 조용한 false 는 없다 — [[공통/기술/결정/ADR-0004-null없음-미입력상태]] 와 같은 결).
5. **작명의 재료** — default 상품담보명은 속성 조합에서 생성, 속성별 담보명 규칙도
   유저 정의. 「파생 축 구분자의 작명 메타」는 폐기하고 담보속성 정의로 옮긴다.

## 이유

- **정체성·유일성·참조가 한 실체로 선다.** 탑재분을 가르는 축이 명시적 실체가 되면
  중복 탑재 거부(유일성)와 식 참조(`갱신유형 = 갱신형`)가 자연스럽다.
- **현행 시스템과 개념이 이어진다** — 담보속성-담보 조합으로 상품담보를 만드는
  운영 개념([[기능/문면/결정/ADR-0003-문면-마스터소유-분기책임]]에도 이미 등장)을 그대로 쓴다.
- 별지·PV 로 확장할 때(현행의 특별조건부 담보처럼 문서 종류별 산출이 갈리는 경우)
  속성이 그 갈래를 담는 자리가 된다.

## 버린 대안

- **A. 값 차이가 곧 구별 (기존 결정 유지)** — 실체가 하나 적다. 기각: 유일성을 못 걸고,
  정체성 축이 암묵적이며, 「어떤 값 차이가 탑재분을 가르는가」를 시스템이 답할 수 없다.
- **B. 파생 축 구분자 + 작명 메타 (기존 절충안)** — 구분자에 「이건 정체성 축」 표식을
  얹는다. 기각: 속성은 담보 레벨 값이 아니라 **탑재 행위의 좌표**다 — 마스터에 값이 없고
  스냅샷도 아니어서 구분자의 값 체계(부착·스냅샷·미입력)와 결이 다르다. 억지로 얹으면
  구분자 규칙마다 예외가 생긴다.

## 결과와 감수하는 비용

- 카탈로그가 하나 늘고, 식 언어([[공통/기술/결정/ADR-0013-식언어-통일]])의 **참조 대상이 확장**된다 —
  언어 문법 자체는 그대로되, 담보속성 LHS 에만 허용 연산 제한(exist·=·≠)이 붙는다.
- 「구분자 값」과 「담보속성」의 개념 구분을 사용자가 배워야 한다 —
  속성 = 탑재를 가르는 좌표 / 구분자 = 문면이 묻는 값.
- 담보 마스터에는 속성 값이 없어 속성 조건은 상품담보 문맥에서만 정해진다 — 담보약관 저작 화면의 미리보기는
  고른 상품담보 문맥으로 조립한다([[기능/문면/문면]] §3.9, 2026-10-10 — 마스터 값 사전평가는 폐지).
