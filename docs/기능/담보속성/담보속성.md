# 담보속성

> 상태: 초안 · 최종수정: 2026-09-27

## 1. 한 줄

담보속성은 **탑재분을 가르는 축**의 카탈로그다 — 유형(갱신유형 · 부가유형 …)과 유형별 유효값(갱신형 · 비갱신형 …). 상품담보는 「담보 × 담보속성 값 조합」으로 하나 정해진다.
관리자 · 편집자가 상품을 모델링하기 전에 유형 · 값 · 명명 조각과 전역 **상품담보명 규칙**을 정해 두고, 상품모델링의 탑재가 이 카탈로그에서 값을 고른다.

## 3. 규칙

### 3.1 실체

- **유형 + 유형별 유효값.** 둘 다 사용자가 고치는 데이터다(코드 마스터가 아니다) (ADR-0015).
- **코드는 시스템 채번 · 불변** — 유형 `A0001`(전역), 유효값 `V01`(유형 안). 식 · 상품담보 조합 · 규칙 템플릿은 코드로 가리킨다.
- **이름** — 유형 이름은 전역 유일, 유효값 이름은 유형 안에서 유일, 빈 이름 불가. 이름은 언제든 바꾼다(코드 불변).
- **순서** — 유효값 순서는 유형 안의 데이터(그룹 안 정렬 3차 키). 유형 순서는 카탈로그 전역 하나이고 그룹 안 정렬 2차 키로만 쓰인다 — 작명에는 쓰지 않는다. 유형 순서를 바꾸는 화면은 없다(만든 순서).
  — 왜: 이름의 칩 순서는 상품담보명 규칙이 정한다. 정렬 순서와 이름 순서를 한 값에 묶지 않는다.
- 담보속성은 **담보 마스터 값이 아니다** — 탑재 행위의 좌표라 담보 화면 어디에도 나오지 않고, 담보 레벨 입력 항목으로도 두지 않는다 (ADR-0015 버린 대안 B).

### 3.2 상품담보를 가르는 축

- **상품담보 = 담보 × 담보속성 값 조합.** 같은 상품에 같은 조합을 두 번 탑재하면 서버가 거부한다 (ADR-0015).
- **sparse** — 필요한 유형만 붙인다. 새 유형을 만들면 이후 상품담보의 모양만 바뀌고 기존 상품담보는 그 유형 「미사용」으로 남는다.
- 탑재 · 조합 변경 화면은 [[기능/상품/상품]] 의 특별약관 탭 몫이다.
- 특별조건부(별지 · PV 용)는 MVP 에 만들지 않는다 — 약관 전용이라.

### 3.3 식의 참조 대상

- `attr.<유형코드>` 로 참조한다. 연산은 **`exist` · `=` · `≠` 셋뿐**이고 `=` · `≠` 의 오른쪽은 그 유형의 **유효값 코드 리터럴**만(구분자 참조 불가) — 작성 시점 거부 (ADR-0015).
- **작성은 관대 · 평가는 엄격** — `exist` 가드 없이 `attr.A0001 = 'V02'` 를 써도 되지만, 그 상품담보가 유형을 안 쓰면 평가가 **오류 + 좌표**다. `exist(attr.X)` 는 미사용이면 거짓 (ADR-0015 · ADR-0004).
- 담보약관 편집 문맥(사전평가)에서는 속성 값이 없다 — 상품담보 미리보기 · 조립에서 확인한다.

### 3.4 상품담보명 — 명명 조각 + 전역 규칙

- **명명 조각** — 유효값마다 조각 문자열 하나(예: 갱신형 → 「갱신형」, 비갱신형 → 빈칸). 앞뒤 공백은 저장 시 떼어낸다. prefix / suffix 구분은 없다 — 자리는 규칙이 정한다.
- **상품담보명 규칙은 카탈로그 전역 하나** — 칩을 순서대로 놓은 한 줄. 칩은 `[담보명]` 또는 `[유형코드]`, 칩 사이 공백 · 글자는 적은 그대로. 기본값 `[담보명]`.
  — 왜: 붙여쓰기(「골절수술비Ⅱ보장」)와 띄어쓰기(「일반상해사망보장 추가」)를 한 규칙에 담으려면 공백을 작성자가 쳐야 한다. 순서는 회사 규정이라 담보별로 다를 이유가 없고, 전역 하나가 순서 불일치를 막는다.
- **치환** — 유형 칩은 그 상품담보가 고른 유효값의 조각으로, 미사용 유형 · 빈 조각 · 규칙에 없는 유형은 빈 문자열. 연속 공백은 1칸, 앞뒤 공백 정리.
- 생성된 이름은 **default 상품담보명**이다 — 탑재할 때 한 번 만들고 사람이 고칠 수 있다. 규칙 · 조각을 고쳐도 이미 만든 이름은 바뀌지 않고, 상품모델링의 상품담보별 「이름 재생성」이 되맞춘다([[기능/상품/상품]]). 「Ⅱ」 · 「보장」은 담보명의 일부다 — 속성이 아니다.
- 유형을 새로 만들면 규칙에 칩을 넣어야 이름에 나온다 — 빠진 유형은 규칙 화면이 표시한다.
  — 왜: 빠뜨리면 그 유형이 이름에 조용히 안 나온다.

### 3.5 삭제

- 유형 삭제 · 유효값 삭제는 **파괴적** — 관리자만, 영향(사용처: 상품담보 조합 · 식 참조, 유형이면 딸린 유효값 목록) 확인 뒤. 편집자 요청은 서버가 거부한다 (ADR-0019).
- 지운 뒤 남는 상품담보 조합 · 식 참조는 **깨진 참조**로 오류 상태가 된다 — 조용히 사라지지 않는다.
- 이름 · 명명 조각 · 순서 변경은 자유(비파괴).

## 4. 화면

`/attributes` 껍데기 — 제목 「담보속성」, 하위 탭 **유형** · **상품담보명 규칙**(둘이라 탭을 둔다).

### `/attributes` — 유형 조회 (L1)

| 구성 | 내용 |
|---|---|
| 제목 줄 | 「유형」 + 오른쪽 `+`(→ `/attributes/new`) |
| 검색 | 코드 · 담보속성명 · 값 이름 |
| 컬럼 | 코드 · 담보속성명(→ 상세) · 값(앞 5개 「 · 」 연결, 넘으면 「… 외 N」) · 수 · 최종수정 · 수정자 |
| 페이저 | 50건 · 「총 N건」 |
| 빈 상태 | 「담보속성은 상품담보 이름과 조합을 가르는 값의 정의다.」 예: 「갱신유형: 갱신형 · 비갱신형」 + 새 유형 |

목록 행에는 입력칸 · 저장 버튼이 없다 — 고르는 자리다.

### `/attributes/new` — 생성

- 경로 `담보속성 › 새 담보속성 유형`, 제출은 헤더 오른쪽.
- 입력은 **담보속성명 하나** — 코드는 채번. 생성 뒤 상세로 가서 유효값을 넣는다.

### `/attributes/<code>` — 유형 상세 (L2)

- 헤더: 경로 `담보속성 › {담보속성명}` · 사용처(`UsageDialog`, 개수) · `편집`(→ `저장`) · 삭제.
- 본문: 코드(고정) · 담보속성명 · **유효값 표**(순서 · 코드 · 값 이름 · 명명 조각 · 사용 수). 유효값이 없으면 「유효값이 없으면 이 유형은 상품담보 조합에 쓰이지 못한다.」

| 상태 · 누르면 | 결과 |
|---|---|
| 읽기 | 표는 글자. 조각이 비면 「없음」 |
| `편집` | 담보속성명 · 값 이름 · 명명 조각이 입력칸, 행마다 ↑ ↓ 와 삭제. 표 아래 값 추가 줄(값 이름 · 명명 조각 · 추가, Enter 로도) |
| 값 추가 | 표 끝에 「새 값」 행(코드 자리에 「새 값」) — 저장 전엔 ✕ 로 추가 취소 |
| `저장` | 담보속성명 · 값 이름 · 조각 · 추가 · 순서를 한 번에 |
| 저장된 값의 삭제 | 확인(영향) 뒤 **바로 실행** — 저장과 별개. 관리자만 |
| 삭제 (헤더) | 유형 삭제 확인 — 딸린 값 N개가 함께 사라진다 · 영향 목록. 관리자만 |

### `/attributes/template` — 상품담보명 규칙 (L2)

- 헤더: 경로 `담보속성 › 상품담보명 규칙` · `편집`(→ `저장`).
- 본문: **템플릿** 한 줄(고정폭, 저장은 코드 칩 `[A0001]`) · **지금 이름**(칩 코드를 유형 이름으로 바꿔 보인 템플릿) · **쓸 수 있는 칩**(`[담보명]` · `[A0001](갱신유형)` …) · **템플릿에 없는 유형**(있을 때만, 경고 배지).
- 저장 한 번. 이미 만든 상품담보명은 바뀌지 않는다.

## 5. 미결

- **템플릿 검사 없음** — 없는 유형 코드 · 닫히지 않은 괄호를 적어도 저장된다(그 칩은 빈 문자열로 치환). 저장 시 경고할지.
- **유형 순서 화면** — 그룹 안 정렬 2차 키인데 바꾸는 화면이 없다(서비스 `reorderAttributeKinds` 만).
- 상세 **저장이 여러 서비스 호출**(이름 · 값마다 · 순서)이라 중간에 거부되면 앞의 변경은 이미 저장돼 있다 — 한 트랜잭션으로 묶을지.
- 저장된 유효값 삭제가 저장과 별개로 즉시 실행된다 — 「저장 한 번」 원칙과의 관계(더보기 메뉴 · 삭제 표시 후 저장 반영 등)를 정할지.
- **조건 팝업에서 담보속성 조건을 못 만든다** — 조건식 입력이 구조화 팝업(구분자만)으로 바뀌어, `attr.X` 조건은 시드 문면에만 있고 새로 넣을 길이 없다. [[기능/문면/문면]] 과 함께 정한다.
- 담보약관 편집 문맥의 담보속성 조건 사전평가 — 마스터에 값이 없어 미결로 표시한다(ADR-0015 결과).
- 시나리오 [[기능/담보속성/시나리오/담보속성탑재_시나리오]] S1 · S3 은 옛 작명 문법(prefix / suffix · 적용 순서)과 모드 문구로 적혀 있다 — 조각 + 전역 규칙으로 다시 쓴다.

### 6.1 이 기능의 ADR

| ADR | 한 줄 |
|---|---|

### 6.2 결정 메모

| 결정 | 왜 | 버린 안 |
|---|---|---|
| 상품담보명 = 유효값별 **명명 조각** + 카탈로그 전역 **칩 규칙** 한 줄, 공백 · 글자는 작성자가 친 그대로 (§3.4) | 붙여쓰기 · 띄어쓰기를 한 규칙에 담으려면 공백을 작성자가 쳐야 한다. 순서는 회사 규정이라 전역 하나가 불일치를 막는다 | 유효값별 prefix / suffix + 유형 순서대로 나열 + 공백 1칸 자동(2026-09-04 잠정 문법) · 유효값별 템플릿 겹싸기(안 / 바깥 방향을 따로 정해야 한다) · 담보별 템플릿(순서 불일치) |
| 유형 순서는 정렬(그룹 안 2차 키)에만 쓰고 작명에는 쓰지 않는다 (§3.1) | 이름 규칙과 정렬 규칙을 한 값에 섞지 않는다 | 유형 순서로 조각을 나열 |
