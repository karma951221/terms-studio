# 담보속성

> 상태: 초안 · 최종수정: 2026-09-28

## 1. 한 줄

담보속성은 **탑재분을 가르는 축**의 카탈로그다 — 유형(갱신유형 · 부가유형 …)과 유형별 유효값(갱신형 · 비갱신형 …). 상품담보는 「담보 × 담보속성 값 조합」으로 하나 정해진다.
관리자 · 편집자가 상품을 모델링하기 전에 유형 · 값 · 값별 **상품담보명 표기**와 전역 **상품담보명 규칙**을 정해 두고, 상품모델링의 탑재가 이 카탈로그에서 값을 고른다.

## 3. 규칙

### 3.1 실체

- **유형 + 유형별 유효값.** 둘 다 사용자가 고치는 데이터다(코드 마스터가 아니다) (ADR-0015).
- **코드는 시스템 채번 · 불변** — 유형 `A0001`(전역), 유효값 `1` · `2` …(유형 안, 순번 그대로). 지운 값의 번호는 다시 쓰지 않는다(시퀀스). 식 · 상품담보 조합 · 규칙 템플릿은 코드로 가리킨다 (2026-09-28 — 옛 `V01` 은 마이그레이션 0017 이 `1` 로 바꿨다).
  — 왜: 유효값 코드는 사람이 부르는 이름이 아니라 순번이다. `V` · 0 채움은 뜻을 더하지 않고, 순서 칸과 코드 칸이 같은 것을 두 번 보였다.
- **이름** — 유형 이름은 전역 유일, 유효값 이름은 유형 안에서 유일, 빈 이름 불가. 이름은 언제든 바꾼다(코드 불변).
  상세 저장은 **최종 유효값 목록으로 한 번에 검사**한다 — 이름 A↔B 맞바꾸기 · 빠지는 값의 이름 받기가 된다 (도메인 `reviseAttributeKind`, 점검 2026-09-27 D1).
- **순서** — 유효값 순서 = **코드 순**(`1` · `2` …, 숫자 순) — 따로 순서 값이 없고 바꾸는 기능도 없다. 새 값은 끝에 붙는다. 그룹 안 정렬 3차 키도 이 순서다. 유형 순서는 카탈로그 전역 하나이고 그룹 안 정렬 2차 키로만 쓰인다 — 작명에는 쓰지 않는다. 유형 순서를 바꾸는 화면은 없다(만든 순서).
  — 왜: 이름의 칩 순서는 상품담보명 규칙이 정한다. 정렬 순서와 이름 순서를 한 값에 묶지 않는다.
- 담보속성은 **담보 마스터 값이 아니다** — 탑재 행위의 좌표라 담보 화면 어디에도 나오지 않고, 담보 레벨 입력 항목으로도 두지 않는다 (ADR-0015 버린 대안 B).

### 3.2 상품담보를 가르는 축

- **상품담보 = 담보 × 담보속성 값 조합.** 같은 상품에 같은 조합을 두 번 탑재하면 서버가 거부한다 (ADR-0015).
- **sparse** — 필요한 유형만 붙인다. 새 유형을 만들면 이후 상품담보의 모양만 바뀌고 기존 상품담보는 그 유형 「미사용」으로 남는다.
- 탑재 · 조합 변경 화면은 [[기능/상품/상품]] 의 상품담보 탭 몫이다.
- 특별조건부(별지 · PV 용)는 MVP 에 만들지 않는다 — 약관 전용이라.

### 3.3 식의 참조 대상

- `attr.<유형코드>` 로 참조한다. 연산은 **`exist` · `=` · `≠` 셋뿐**이고 `=` · `≠` 의 오른쪽은 그 유형의 **유효값 코드 리터럴**만(구분자 참조 불가) — 작성 시점 거부 (ADR-0015).
- **작성은 관대 · 평가는 엄격** — `exist` 가드 없이 `attr.A0001 = '2'` 를 써도 되지만, 그 상품담보가 유형을 안 쓰면 평가가 **오류 + 좌표**다. `exist(attr.X)` 는 미사용이면 거짓 (ADR-0015 · ADR-0004).
- 담보약관 편집 문맥(사전평가)에서는 속성 값이 없다 — 상품담보 미리보기 · 조립에서 확인한다.

### 3.4 상품담보명 — 값별 상품담보명 표기 + 전역 규칙

- **상품담보명 표기** — 유효값마다 상품담보명에 그 값 대신 들어갈 말 하나(예: 갱신형 → 「갱신형」, 비갱신형 → 빈칸 = 붙지 않음). 앞뒤 공백은 저장 시 떼어낸다. prefix / suffix 구분은 없다 — 자리는 규칙이 정한다. 코드 식별자는 `fragment` 그대로.
  — 왜: 「명명 조각」은 만든 사람만 아는 말이었다. 화면은 무엇이 어디에 들어가는지로 부른다 — 칸 이름 옆 ⓘ 「상품담보명에 이 값 대신 들어갈 말 — 비우면 붙지 않는다」 (2026-09-28).
- **상품담보명 규칙은 카탈로그 전역 하나** — 칩을 순서대로 놓은 한 줄. 칩은 `[담보명]` 또는 `[유형코드]`, 칩 사이 공백 · 글자는 적은 그대로. 기본값 `[담보명]`.
  — 왜: 붙여쓰기(「골절수술비Ⅱ보장」)와 띄어쓰기(「일반상해사망보장 추가」)를 한 규칙에 담으려면 공백을 작성자가 쳐야 한다. 순서는 회사 규정이라 담보별로 다를 이유가 없고, 전역 하나가 순서 불일치를 막는다.
- **치환** — 유형 칩은 그 상품담보가 고른 유효값의 표기로, 미사용 유형 · 빈 표기 · 규칙에 없는 유형은 빈 문자열. 연속 공백은 1칸, 앞뒤 공백 정리.
- 생성된 이름은 **default 상품담보명**이다 — 탑재할 때 한 번 만들고 사람이 고칠 수 있다. 규칙 · 표기를 고쳐도 이미 만든 이름은 바뀌지 않고, 상품모델링의 상품담보별 「이름 재생성」이 되맞춘다([[기능/상품/상품]]). 「Ⅱ」 · 「보장」은 담보명의 일부다 — 속성이 아니다.
- 유형을 새로 만들면 규칙에 칩을 넣어야 이름에 나온다 — 빠진 유형은 규칙 화면이 표시한다.
  — 왜: 빠뜨리면 그 유형이 이름에 조용히 안 나온다.

### 3.5 삭제

- 유형 삭제 · 유효값 삭제는 **파괴적** — 관리자만, 영향(사용처: 상품담보 조합 · 식 참조, 유형이면 딸린 유효값 목록) 확인 뒤. 편집자 요청은 서버가 거부한다 (ADR-0019).
- 유효값 삭제는 상세 편집의 **편집 중 변경**이다 — 행 앞 ⊖ 로 표에서 빼고, 확인은 **저장할 때** 빠진 값 전부의 사용처를 합쳐 한 번 (점검 2026-09-27 D2 · [[공통/화면/디자인원칙]] §2 L2).
- 지운 뒤 남는 상품담보 조합 · 식 참조는 **깨진 참조**로 오류 상태가 된다 — 조용히 사라지지 않는다.
- 이름 · 상품담보명 표기 변경은 자유(비파괴).

## 4. 화면

`/attributes` 껍데기 — 제목 「담보속성」, 하위 탭 **유형** · **상품담보명 규칙**(둘이라 탭을 둔다).

### `/attributes` — 유형 조회 (L1)

**한 행 = 유효값 하나** (2026-09-28) — 갱신유형의 비갱신형 · 갱신형이 각각 한 행이다. 유형은 행마다 적는다. 값이 없는 유형은 값 칸이 「—」 · 「값 없음」인 한 행.

| 구성 | 내용 |
|---|---|
| 제목 줄 | 「유형」 + 오른쪽 `+`(→ `/attributes/new`) |
| 검색 | 코드 · 담보속성명 · 값 이름 · 상품담보명 표기 — 유형으로 맞으면 그 유형의 값 행 전부, 값으로 맞으면 그 행만 |
| 컬럼 | 담보속성 코드 · 담보속성명(→ 유형 상세) · 값 코드 · 값 이름 · 상품담보명 표기(ⓘ) · 최종수정 · 수정자(둘 다 유형의 것). 개수 컬럼은 없다 |
| 순서 | 유형 순 → 유형 안 코드 순 |
| 페이저 | 50행 · 「총 N건」(값 행 수) |
| 빈 상태 | 「담보속성은 상품담보 이름과 조합을 가르는 값의 정의다.」 예: 「갱신유형: 갱신형 · 비갱신형」 + 새 유형 |

목록 행에는 입력칸 · 저장 버튼이 없다 — 고르는 자리다.

### `/attributes/new` — 생성

- 경로 `담보속성 › 새 담보속성 유형`, 제출은 헤더 오른쪽.
- 입력은 **담보속성명 하나** — 코드는 채번. 생성 뒤 상세로 가서 유효값을 넣는다.

### `/attributes/<code>` — 유형 상세 (L2)

- 헤더: 경로 `담보속성 › {담보속성명}` · `편집`(→ `저장`) · 삭제. 사용처는 두지 않는다 — 관계정보 메뉴 (2026-10-01).
- 본문: 코드(고정) · 담보속성명 · **유효값 표**(코드 · 값 이름 · 상품담보명 표기 ⓘ). 순서 칸 · 사용 수 칸은 없다 — 코드가 곧 순서이고, 사용처는 관계정보 메뉴가 본다. 읽기에서 유효값이 없으면 「유효값이 없으면 이 유형은 상품담보 조합에 쓰이지 못한다.」

| 상태 · 누르면 | 결과 |
|---|---|
| 읽기 | 표는 글자. 표기가 비면 「—」 |
| `편집` | 값 행 표([[공통/화면/디자인원칙]] §2 L2 「값 행 표」) — 담보속성명 · 값 이름 · 상품담보명 표기가 입력칸, 행 앞 ⊖ 「행 삭제 · {값 이름}」, 마지막 행 아래 ⊕ 「행 추가 · 값」. 코드가 곧 순서라 끌기 손잡이는 없다. 제목 「유효값」 옆에 개수를 두지 않는다 |
| ⊕ 「행 추가 · 값」 | 표 끝에 빈 「새 값」 행(코드 자리에 「새 값」)이 생기고 그 값 이름 칸에 커서가 간다. 저장 전엔 ⊖ 로 추가 취소. 아무것도 적지 않은 새 행은 저장에서 빠진다. 저장하면 다음 번호를 받는다 |
| 저장된 값의 ⊖ | 「행 삭제 · {값 이름}」 — 저장할 때 삭제된다. 표에서만 빠지고 편집 취소(✕)로 되돌아간다 — 그 자리의 확인은 없다 |
| `저장` | 담보속성명 · 값 이름 · 표기 · 추가 · 빼기를 **한 트랜잭션**에. 뺀 값이 있으면 먼저 확인 대화상자 — 「값을 빼면 그 값을 쓰는 곳이 깨질 수 있다」 · 깨질 참조(빠진 값 전부 합계) · 「값 N개 삭제하고 저장」. 편집자는 서버 거부. 거부 · 대화상자 취소면 아무것도 저장되지 않는다 |
| 삭제 (헤더, 읽기에서만) | 유형 삭제 확인 — 딸린 값 N개가 함께 사라진다 · 영향 목록. 관리자만. 편집 중에는 꺼진다(tooltip 「저장하거나 취소한 뒤 실행」, 디자인원칙 §2 L2) |

### `/attributes/template` — 상품담보명 규칙 (L2)

- 헤더: 경로 `담보속성 › 상품담보명 규칙` · `편집`(→ `저장`).
- 본문: **템플릿** 한 줄(고정폭, 저장은 코드 칩 `[A0001]`) · **지금 이름**(칩 코드를 유형 이름으로 바꿔 보인 템플릿) · **쓸 수 있는 칩**(`[담보명]` · `[A0001](갱신유형)` …) · **템플릿에 없는 유형**(있을 때만, 경고 배지).
- 저장 한 번. 이미 만든 상품담보명은 바뀌지 않는다.

## 5. 미결

- **템플릿 검사 없음** — 없는 유형 코드 · 닫히지 않은 괄호를 적어도 저장된다(그 칩은 빈 문자열로 치환). 저장 시 경고할지.
- **유형 순서 화면** — 그룹 안 정렬 2차 키인데 바꾸는 화면이 없다(서비스 `reorderAttributeKinds` 만).
- **조건 팝업에서 담보속성 조건을 못 만든다** — 조건식 입력이 구조화 팝업(구분자만)으로 바뀌어, `attr.X` 조건은 시드 문면에만 있고 새로 넣을 길이 없다. [[기능/문면/문면]] 과 함께 정한다.
- 담보약관 편집 문맥의 담보속성 조건 사전평가 — 마스터에 값이 없어 미결로 표시한다(ADR-0015 결과).
- 시나리오 [[기능/담보속성/시나리오/담보속성탑재_시나리오]] S1 · S3 은 옛 작명 문법(prefix / suffix · 적용 순서)과 모드 문구로 적혀 있다 — 상품담보명 표기 + 전역 규칙으로 다시 쓴다.

| 상품담보명 = 유효값별 **상품담보명 표기** + 카탈로그 전역 **칩 규칙** 한 줄, 공백 · 글자는 작성자가 친 그대로 (§3.4) | 붙여쓰기 · 띄어쓰기를 한 규칙에 담으려면 공백을 작성자가 쳐야 한다. 순서는 회사 규정이라 전역 하나가 불일치를 막는다 | 유효값별 prefix / suffix + 유형 순서대로 나열 + 공백 1칸 자동(2026-09-04 잠정 문법) · 유효값별 템플릿 겹싸기(안 / 바깥 방향을 따로 정해야 한다) · 담보별 템플릿(순서 불일치) |

| 유효값 코드 = 유형 안 순번 `1` · `2` …, **코드 순 = 순서** — 순서 값 · 순서 바꾸기 없음 (§3.1, 2026-09-28 · 마이그레이션 0017) | 코드와 순서 칸이 같은 것을 두 번 보였다. 코드는 조합 · 식이 담으므로 불변이어야 하고, 그러면 순서도 코드에 묶는 편이 단순하다 | `V01` 코드 + 별도 순서 컬럼(↑↓) · 코드를 표시 순서로 다시 매기기(조합 · 식이 담은 코드가 깨진다) |
| 조회 한 행 = 유효값 하나 · 「수」 컬럼 없음 (§4, 2026-09-28) | 값이 무엇인지가 목록에서 바로 보여야 한다 — 「값 앞 5개 · 외 N」 미리보기와 개수는 한 번 더 눌러야 알았다 | 유형 한 행 + 값 미리보기 · 개수 |
