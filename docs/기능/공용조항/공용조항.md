# 공용조항

> 상태: 초안 · 최종수정: 2026-09-27

## 1. 한 줄

여러 약관 템플릿(담보약관 · 보통약관)이 공통으로 쓰는 문구를 한 곳에 정의해 두고 **참조로** 가져다 쓰는 문구 템플릿이다 — 「특별약관의 소멸」 · 「준용규정」처럼 특약마다 반복되는 조의 항.
작성자가 공용조항을 정의 · 수정하고, 문면 작성자가 약관 템플릿에 참조를 끼우며, 상품 모델러가 보통약관 자리의 옵션을 상품별로 바꾼다.

## 3. 규칙

### 3.1 동작

- **참조다.** 문장은 공용조항 마스터에 살고 사용처에는 참조 노드만 있다. 고치면 쓰는 곳 전부에 전파된다.
  — 왜: 사용처에 복사하면 표준문구를 고칠 때 담보 수만큼 반복해 고친다. 값은 스냅샷이지만 문면은 마스터 소유 · 전파가 이 프로젝트의 결이다.
- **사용처는 보통약관과 담보약관 둘 다다.**
- **유형 둘** — 「문구」(inline, 문장 안에 끼는 문장 조각) · 「항」(block, 항 하나 또는 항 목록 — 호 · 목을 품는다). 유형은 생성 때 정하고 그 뒤 화면에서 바꾸지 않는다. 두 유형의 재사용 범위는 같은 세 검사로 정해진다(아래).
- **조는 항상 사용처 소유다.** 공용조항 본문에 조 노드를 둘 수 없다 — 조 제목을 품은 공용조항은 없다. 한 조 안에 직접 쓴 항과 「항」 공용조항 참조가 섞이면 **배치 순서 그대로** 출력된다.
- **중첩 금지(MVP)** — 공용조항 안에 공용조항 참조를 둘 수 없다. 인라인 조건 안의 인라인 조건도 거부.
  — 왜: 현행 시스템은 중첩을 허용하는데 구현이 까다롭고 버그가 많았다(의뢰인 증언). 중첩은 MVP 이후 로드맵에 있다.
- **큰 차이는 별도 공용조항으로 딴다.** 항 구성이 다른 수준(소멸 조의 사망형 / 일반형)이면 옵션이 아니라 공용조항을 따로 만든다. 옵션은 문구 수준 대안 전용.
- 준용 · 생략 판정의 「같은 문구」는 같은 공용조항 참조로 확보한다 — [[기능/조립산출/조립산출]] §3.5 준용 · 생략 판정.

### 3.2 옵션

- 다를 수 있는 문구는 **옵션**이다 — 정의에 옵션 자리와 선택지(대안)를 두고 **사용처가 수동으로 고른다.** 사용처가 문장을 자유롭게 고치지는 못한다. 자동으로 갈릴 자리는 옵션이 아니라 조건식으로 쓴다.
- 옵션 하나는 **선택지 2개 이상**이어야 성립한다. 선택지가 1개면 본문에 넣을 수 없고, 저장 때 거부된다.
  이 하한은 **저장 뒤 최종 개수**로 본다 — 선택지 2개인 옵션에서 하나를 빼고 새 것을 더하는 교체(최종 2개)는 된다. — 왜: 빼기부터 돌리면 중간 개수가 1이 돼 거부됐다 (점검 2026-09-27 H2 ②). 저장은 선택지를 **더한 뒤 뺀다**.
- 옵션 정의에 **기본 선택지는 없다** — 사용처가 반드시 명시로 고른다.
- 참조 추가는 선택이 없어도 성립하고, **미선택은 사용처 문서를 저장할 때** 오류다.
  — 왜: 참조를 넣을 때 고르게 하면 작성 흐름이 다이얼로그로 끊기고, 조립까지 미루면 발견이 늦다. 문서 저장이 그 사이의 자연스러운 검사 시점이다.
- 기본 선택은 **사용처 문서 마스터**가 소유하고, 같은 공용조항을 한 문서에 여러 번 참조하면 선택은 참조마다 따로다.
- **오버라이드는 그 상품의 보통약관 자리만** — 상품모델링 보통약관 탭에서 공용조항 참조 자리마다 고른다. 담보약관 안의 옵션은 담보 마스터에서 다 정하고, 미결정은 담보 상세가 「공용조항 옵션 미결정 N」 배지로 경고한다. 해소 순위는 오버라이드 > 마스터 기본, 늘 유효 선택지 안에서. ([[기능/상품/상품]] §3.6)
  — 왜: 값에 근거 없는 상품별 차이는 조건식으로 쓸 수 없고, 옵션 하나 때문에 보통약관을 따로 두는 것은 과하다.
- **상품별 변주의 경계** — 「문면은 마스터 소유, 상품별 변주는 기본계약 연동뿐」의 예외는 옵션 오버라이드와 보통약관 조 노출 토글([[기능/상품/상품]] §3.6) 둘뿐이다. 문장을 고치는 오버라이드로 넓히지 않는다.
- 옵션 · 선택지 삭제는 정의 수정이다(편집자 가능). 옵션을 더해 생긴 미선택 · 선택지를 빼 생긴 깨진 선택은 사용처 재검사 목록에 오르고, 해소 전 조립은 오류 + 좌표. 본문이 아직 쓰는 옵션은 뺄 수 없다.
- 옵션별 오버라이드 사용처는 관계정보가 역조회한다(§4.4 다른 화면).

### 3.3 참조 — 늦은 바인딩

- 공용조항은 평가 문맥을 갖지 않는다. 조건식 · 값 슬롯은 **사용처 문서의 문맥**에서 해소된다 — 담보약관이면 그 담보 값, 보통약관이면 기본계약 상품담보 값, 상품 · 세목 레벨은 조립 때. 문맥 표는 [[기능/조립산출/조립산출]] §3.2 평가 문맥. (ADR-0010)
- 어느 레벨의 구분자든 읽을 수 있다. 문면처럼 **구분자만** 읽는다 — 마스터 필드를 직접 읽지 않는다. (ADR-0010 · [[기능/구분자/결정/ADR-0036-폼-구분자-문면-3층]])
- **요구 구분자는 선언하지 않는다** — 정의를 저장할 때 조건식 · 슬롯이 읽는 구분자를 뽑아 둔다. 상세 화면이 늘 보여준다. (ADR-0010)
- 값 슬롯은 string · enum 결과만 받는다. ([[기능/문면/문면]] §3.4)

### 3.4 세 검사

| 검사 | 묻는 것 | 시점 | 실패하면 |
|---|---|---|---|
| **① 정의 유효** | 식 문법 · 조건식은 boolean · 슬롯은 string/enum · 읽는 구분자 · 별표가 있음 · 옵션은 선택지 2개 이상 · 조 노드 없음 · 중첩 없음 · 조 참조는 보통약관 마스터 대상만 | 공용조항 저장 | 저장 거부 |
| **② 사용처 문맥** | 공용조항 · 요구 구분자가 지금 있는가 · 선택한 옵션이 유효 선택지인가 | 문면에 참조를 넣을 때 · 공용조항을 고친 뒤(재검사) · 기본계약 지정 때 | 삽입: 참조 미성립 · 재검사: 목록에 오름(저장은 막지 않음) · 기본계약 지정: 지정은 성립, 결과는 오류 목록(정본은 [[기능/상품/상품]]) |
| **③ 실행 시 해소** | 값 미입력 · 옵션 미선택 · 유효 집합 밖 · 참조 대상이 분기로 사라짐 · 세목 범위 없음 · 기본계약 미지정 | 상품 미리보기 · 조립 | 조립 오류 + 좌표 |

— 왜: 세 검사는 답이 나오는 시점이 다르다 — 정의는 저장 때, 문맥은 삽입 · 기본계약 때, 값은 상품이 있을 때. 한 시점에 몰면 「미입력이면 삽입 불가」(작성이 값 입력 뒤로 밀림)거나 「전부 조립 때」(발견이 늦음)가 된다.

- **미입력이라는 이유로 참조 삽입을 막지 않는다** — 미입력은 ③ 이다. 정의 · 삽입 시점에는 상품이 없어 알 수도 없다.
- **공용조항을 고치면 사용처 전부에 ① + ② 를 다시 돌린다** — 결과는 재검사 목록(깨진 구분자 참조 · 미선택 · 깨진 옵션 선택). 저장은 막지 않는다. 복구 경로는 구분자 정의 변경과 같은 장치다. ([[기능/구분자/결정/ADR-0049-정의변경-경고허용-영향목록-복구재검사]])
- ② 의 **레벨 문맥 검사**(요구 구분자의 레벨을 이 문서 문맥이 해소하는가 — 담보약관은 담보 이하를 문서 자신이, 보통약관은 기본계약 담보 트리에 자리가 있는가)와 **반복 원소 검사**(반복 원소를 읽는 공용조항은 반복 본문 안에만)는 **미구현.** 지금 ② 는 존재 · 옵션만 본다.
- 요구 구분자 줄마다 「어느 문맥에서 해소되나」(문서 자신 · 기본계약 · 조립)를 붙이는 표시는 **미구현.**

### 3.5 조 참조

- 공용조항 안의 참조 슬롯이 가리킬 수 있는 것은 **문맥과 무관하게 고정되는 대상**뿐 — 별표, 그리고 보통약관 마스터의 조 · 항 · 호 · 목(MVP 는 보통약관 1벌).
- **사용처 문서 자신의 조를 가리키는 구절은 공용조항에 두지 않는다**(① 에서 거부) — 그 항은 사용처 문면에 직접 쓰고, 공통 부분만 「항」 공용조항으로 따서 뒤에 놓는다. 예: 「특별약관의 소멸」의 ⑴ 「제3조(보험금의 지급사유)의 … 소멸합니다」는 담보약관에 직접, ⑵ 「소멸된 경우 … 지급합니다」는 공용조항 「소멸 시 지급」. 조 전체를 공용조항 하나로 따려다 ⑴ 이 걸리면 조를 항 단위로 가른다. 중첩이 와도 이 제한은 그대로다.
  — 왜: 허용하면 사용처가 「대상 역할」을 넘겨 주는 인자 전달이 참조 슬롯에 되살아난다(ADR-0010 이 버린 대안). 실물의 문맥 의존 구절은 항 하나라 사용처에 남겨도 손해가 작다.

### 3.6 코드 · 권한

- 코드는 시스템 채번 · 불변 — 공용조항 `C0001`, 옵션 `O01`, 선택지 `V01`(소속 안에서 유일). 이름은 바꿔도 참조가 안 깨진다. ([[공통/기술/결정/ADR-0005-코드-표시명-이중체계]])
- 공용조항명은 중복 불가.
- 삭제는 **관리자만** · 사용처(깨질 참조) 확인 후. 삭제 뒤 사용처의 참조 노드는 깨진 참조로 남는다. ([[공통/화면/결정/ADR-0019-모드폐지-역할권한]])

### 4.2 `/clauses/new` — 생성

| 칸 | 내용 |
|---|---|
| 경로 | `공용조항 › 새 공용조항`, 헤더 오른쪽 생성 버튼 |
| 공용조항명 | 필수 |
| 유형 | 문구 / 항 라디오 (설명 붙음) |
| 본문 | 노드 트리 JSON — 유형에 맞는 최소 예시로 채워져 있고, 유형을 바꾸면 예시도 바뀐다. 사람이 고친 뒤로는 따라 바뀌지 않는다 |
| 주석 | 선택 |

생성하면 검사 ① 을 돌리고 통과하면 상세로 간다. 실패는 머리 오류 배너. 본문을 JSON 으로 받는 것은 구조 편집기로 옮기기 전까지의 통로다.

### 4.3 `/clauses/<code>` — 상세 (L2)

**구성.** 제목 줄은 경로 `공용조항 › <공용조항명>`. 그 아래 접히는 기본 정보(코드 · 공용조항명 · 유형 — 접으면 이름만), 본문은 두 단 — 왼쪽 **기재내용**, 오른쪽 **옵션**.
헤더 오른쪽: `편집` · `사용처 N`(모달) · 🗑(삭제).

**상태.**

| 상태 | 기재내용 (왼쪽) | 옵션 (오른쪽) |
|---|---|---|
| 읽기 | 조판된 문면(명조). 슬롯 · 조 참조(「제○조」) · 별표 · 옵션 자리(〔옵션명〕)는 칩, 조건은 식 머리 칩 | 옵션명과 선택지 목록 |
| 편집 | 구조 편집기 — 툴바 `+ 항`, 줄마다 문구 칸 · 위/아래 · 빼기 · 줄 끝 `+ 호` / `+ 목`. 줄을 **우클릭**하면 「옵션 넣기」 메뉴(선택지 2개 미만인 옵션은 흐리게, 옵션이 없으면 「오른쪽에서 먼저 만드세요」). 「문구」 유형은 문장 한 칸 | 옵션명 · 선택지 이름 고치기, ✕ 로 빼기, `옵션 추가` · `선택지 추가`(Enter 또는 +) |
| 빈 본문 | 「본문이 비어 있다 — 참조해도 아무 조문도 나오지 않는다」 + 예시 | 「옵션 없음 — 사용처가 고를 것이 없다」 |

**유저액션.**

| 누르면 | 결과 |
|---|---|
| `편집` | 기재내용 · 옵션 · 공용조항명이 수정 가능해지고 버튼이 `저장`으로 |
| `저장` | 화면 전체 변경을 **한 트랜잭션**에 반영 — 새 옵션을 먼저 만들고 → 본문(옵션 자리 코드 교체) → 옵션마다 이름 → 선택지 추가 → 선택지 이름 → 선택지 삭제 → 뺀 옵션 삭제 순. 어느 단계든 거부(검사 ① 실패 등)면 이름 · 새 옵션까지 전부 롤백 · 거부 메시지(다시 저장해도 옵션 순번이 타지 않는다), 통과하면 요구 구분자 재추출 + 사용처 재검사 |
| ✕ / 경로 링크 (편집 중) | 「고친 내용을 버립니까?」 |
| `사용처 N` | 모달: 사용처 표(약관 템플릿 · 소유 모델링 · 선택 「어조: 사망」) → 검사 ① 요약(요구 구분자 · 조 참조 · 별표 참조 수) → 검사 ② 재검사 목록(문제 있는 사용처마다 이슈, 「사용처 문서에서 보기」) → 검사 ③ 영향 받는 상품(→ 상품 미리보기) → 「관계정보에서 보기 →」 |
| 🗑 | 편집자는 거부. 관리자는 깨질 사용처 목록 확인 → 삭제 → `/clauses` |

**미구현(화면).** 조건 블록 · 인라인 조건 · 값 슬롯 · 조 참조 · 별표 참조를 넣는 도구(편집기는 기존 조건 블록을 「저장된 대로 둔다」로만 보인다 — 지금은 생성 때 JSON 으로만 넣는다) · **선택지 문구**(선택지를 고르면 옵션 자리에 들어가는 문장 — 화면은 선택지 이름만 받는다) · 복제 · 옵션 · 선택지 순서 변경. 서비스에는 복제(`duplicate`) · 순서(`reorderOptions` · `reorderOptionValues`) · 선택지 문구(`setOptionValueBody`)가 있다.

## 5. 미결

- 검사 ② 의 「기본계약 담보 트리에 자리가 있는가」가 MVP 에서 빈 검사(최소 구조가 있으면 늘 통과)가 되는지 — 구현 때 확인.
- 보통약관이 2벌 이상(배상책임 템플릿, MVP 이후)이 되면 「보통약관 조 참조는 문맥 무관」이 깨진다 — 그때 조 참조 규칙과 보통약관 문맥의 기본계약 해소([[기능/조립산출/조립산출]] §3.2 평가 문맥)를 다시 본다.
- 공용조항 중첩은 MVP 이후 구현이 로드맵에 있다(생략 판정의 「동일성은 공용조항으로 확보」를 강화). 조 참조 제한은 중첩이 와도 그대로.
- 선택지 문구 편집을 상세 화면 어디에 둘지 — 지금 화면으로 만든 선택지는 문구가 비어 있어 골라도 아무 글자도 들어가지 않는다.

### 6.2 결정 메모

| 결정 | 왜 | 버린 안 |
|---|---|---|
| 공용조항은 참조 — 고치면 전파 | 표준문구 개정 때 담보 수만큼 고치지 않게. 문면은 마스터 소유 · 전파가 이 프로젝트의 결 | 사용처에 복사 |
| 다를 수 있는 문구는 옵션(수동 선택) · 자동 갈림은 조건식 · 항 구성 차이는 별도 공용조항 | 옵션이 항 구성까지 품으면 옵션이 문면이 된다. 사용처 자유 수정은 전파를 깬다 | 사용처 자유 수정 · 큰 차이도 옵션으로 |
| 조는 사용처 소유 · 「항」 공용조항은 항 단위 · 섞이면 배치 순서대로 | 항 단위라 조 소유를 따질 필요가 없다 | 조 제목을 품은 공용조항 |
| 중첩 금지(MVP) | 현행 시스템이 허용했다가 구현이 까다롭고 버그가 많았다 | 중첩 허용 |
| 옵션 미선택은 사용처 문서 저장 때 검사 · 기본 선택은 사용처 문서 소유 | 삽입 때 강제하면 작성이 끊기고 조립까지 미루면 늦다 | 삽입 시 선택 강제 · 조립 오류로만 |
| 상품별 옵션 오버라이드 — 보통약관 자리만, 유효 선택지 안에서 | 값에 근거 없는 상품별 차이는 조건식으로 못 쓰고, 옵션 하나로 보통약관을 가르는 것은 과하다. 예외는 옵션 · 조 노출 토글뿐 | 오버라이드 없음 · 문장 수정 오버라이드 · 담보약관 자리 오버라이드(상품 §3.6) |
| 사용 조건은 세 검사(정의 · 사용처 문맥 · 실행) — 미입력은 삽입을 막지 않는다 | 답이 나오는 시점이 다르다. 미입력으로 막으면 작성이 값 입력 뒤로 밀린다 | 단순 공용문구만 · 값을 다 채워야 삽입 · 검사 없이 조립 오류만 |
| 사용처 자신의 조를 가리키는 구절은 공용조항에 두지 않는다 | 문맥 의존 참조는 인자 전달을 되살린다. 실물은 항 하나라 사용처에 두는 손해가 작다 | 문맥 의존 조 참조 + 사용처가 대상 역할 제공 |
| 상세 저장 = 한 트랜잭션 · 선택지는 더한 뒤 뺀다 (§3.2 · §4.3, 2026-09-27 점검 D1) | 저장이 서비스 여러 번이라 본문이 거부돼도 이름 · 새 옵션이 남았고, 다시 저장하면 옵션을 한 번 더 만들었다(H1). 액션 전체를 `saveOnce` 로 감싼다. 선택지 하한(2개)만 순서에 걸리므로 최종 한 벌 연산 대신 추가 → 이름 → 삭제 순으로 충분하다(중간 개수 ≥ 최종 개수) | 옵션 한 벌을 최종 상태로 검사하는 도메인 연산 · 액션만 트랜잭션으로 감싸기(선택지 교체는 여전히 거부) |
