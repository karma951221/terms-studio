# ADR-0010 — 공용조항 참조: 늦은 바인딩 + 요구 구분자 자동 추출

> 상태: 채택 · 날짜: 2026-08-31
>
> 개정 반영: 2026-09-14 (§1 · §2) — 원본은 _archive/2026-09-27_문서재편/06_결정/
> 옛 결정 4 · 5(붙이는 시점의 부착 검사 · 부착 제안 · 미부착 담보 재검사)는 [[기능/공용조항/공용조항]] §3.4 세 검사로 대체됐다. 부착 관계 자체가 [[기능/마스터/결정/ADR-0037-입력항목-코드마스터-유저정의폼-MVP이후]] 로 MVP 이후다.

## 맥락

[[기능/공용조항/공용조항]] §3.1 동작이 공용조항을 **참조**로 정하고, 자동으로 갈려야 하는 자리는
옵션이 아니라 **조건식**이 맡는다고 정했다. 조건식과 치환(슬롯)은 구분자 경로를 읽는다.

그런데 공용조항은 담보 하나에 매이지 않는다 — 여러 담보약관이 같은 공용조항을 참조한다.
**「어느 담보의 값을 읽나」** 가 [[기능/공용조항/공용조항]] 의 마지막 미결이었다.

여기에 [[기능/담보/담보]] 의 노출여부 규칙이 얹힌다 (결정 당시 — 노출여부 · 부착은 ADR-0037 로 MVP 이후).

| 노출여부 | 값 자리 |
|---|---|
| 무조건 노출 | 그 레벨 **모든** 실체에 존재 |
| 선택적 노출 | **부착한** 실체에만 존재 |

선택적 노출 구분자를 읽는 공용조항을, 그 구분자를 부착하지 않은 담보가 쓰면
**값 자리 자체가 없다.** 이것은 [[공통/기술/결정/ADR-0004-null없음-미입력상태]] 의 「미입력」과 다른 사태다 —
미입력은 자리가 있는데 안 채운 것이고, 이쪽은 자리가 없는 것이다. 미입력 처리(오류 + 좌표 보고)에
흡수되지 않으므로 별도 규칙이 필요하다.

## 결정

1. **늦은 바인딩** — 공용조항은 평가 문맥을 소유하지 않는다. 조건식·슬롯의 참조는
   **사용처 문서의 문맥에서 해소된다.** 같은 공용조항이 담보 A 의 문서에서는 A 의 값으로,
   B 의 문서에서는 B 의 값으로 평가된다.
   - **조건식과 치환은 같은 규칙이다.** [[00_시작/도메인모델]] §3 에서 이름 슬롯이 불필요하다고 정리돼
     치환도 값 참조뿐이므로, 둘을 가를 이유가 없다.
2. **참조 범위를 제한하지 않는다** — 어느 레벨의 구분자든 참조할 수 있다.
3. **요구 구분자는 선언하지 않고 식에서 자동 추출한다.** 공용조항 정의를 저장할 때
   조건식·슬롯이 읽는 구분자 집합이 곧 그 공용조항의 요구 구분자다.
   공용조항 정의 화면은 이 목록을 항상 보여준다.
4. **검사는 세 검사다** — ① 정의 유효(정의 저장) ② 사용처 문맥(참조 삽입 · 기본계약 지정) ③ 실행 시 해소(미리보기 · 조립).
   상세는 [[기능/공용조항/공용조항]] §3.4 세 검사.
5. **역방향도 같은 장치로** — 이미 쓰이는 공용조항의 정의를 고치면 그 공용조항을 참조하는 사용처 전부에
   ① + ② 를 다시 돌려 **재검사 목록**을 보여준다. 저장은 막지 않는다.
   [[기능/구분자/구분자]] 의 **사용처 추적(역인덱스)** 을 그대로 쓴다.
6. **미입력 값은 [[공통/기술/결정/ADR-0004-null없음-미입력상태]] 그대로** — 검사 ③, 조립 시 오류 + 좌표 보고.
   ② 는 미입력을 보지 않는다. 두 검사는 다른 사태를 본다.

## 이유

- **표현력을 잃지 않는다.** 담보 전용 값으로 갈리는 공용조항 문구가 실물에 있다 —
  갱신형 파생의 준용규정 내용 차이([[00_시작/도메인모델]] §7 실증 ②).
- **노출여부 규칙이 무의미해지지 않는다.** 참조를 무조건 노출로 제한하면, 갈리는 문구를
  공용조항으로 만들기 위해 담보 전용 값을 억지로 무조건 노출로 승격시키게 된다.
  그러면 모든 담보의 모델링 화면이 남의 담보 값으로 오염된다.
- **검사 장치가 이미 있다.** 사용처 추적 역인덱스가 P1 범위다. 새 인프라가 아니다.
- **붙이는 순간이 가장 싼 발견 시점이다.** 구성 실수는 값 실수가 아니어서,
  조립 직전에 발견하면 담보약관 편집으로 되돌아가야 한다 — 그래서 검사 ② 가 삽입 시점에 선다.

## 버린 대안

- **A. 무조건 노출 구분자 + const 만 참조 허용** — 정의 시점에 강제하면 참조가 항상 성립하고
  검사 장치가 필요 없다. 기각: 위 「표현력」·「노출여부」 이유. 갈리는 문구마다 별도 공용조항을
  따야 해서 「큰 차이는 별도 공용조항으로」([[기능/공용조항/공용조항]] §3.1 동작)와 겹쳐 공용조항 수가 불필요하게 늘어난다.
- **B. 인자 전달 (함수 시그니처)** — 공용조항이 파라미터를 선언하고 사용처가 담보마다
  다른 구분자를 연결한다. 가장 유연하고 계약이 명시적이다. 기각: 사용처마다 바인딩 입력이 늘고
  개념이 하나 는다. **담보마다 다른 구분자를 꽂아야 하는 실사례가 아직 없다** — 같은 개념을
  같은 코드로 읽는다. 늦은 바인딩 위에 나중에 얹을 수 있는 확장이라 되돌리기도 비싸지 않다.
- **C. 열되 검사 없이 조립 때 오류** — 미입력 처리에 얹는다. 기각: 위 「발견 시점」 이유.

## 결과와 감수하는 비용

- 구현 지점이 셋 생긴다 — 정의 저장 시 요구 구분자 추출 · 참조 삽입 시 검사 ② ·
  공용조항 수정 시 기존 사용처 재검사.
- **공용조항을 고치는 일이 다른 담보약관을 깨뜨릴 수 있다** — 전파의 이면이다.
  재검사가 즉시 드러내지만, 수정자가 자기 담보 밖의 영향을 감당해야 하는 부담은 남는다.
- 「이 공용조항을 쓰려면 이 구분자를 해소할 문맥이 있어야 한다」는 계약이 **식 안에 암묵적으로** 존재한다.
  자동 추출로 보여줄 뿐 선언이 아니다 — 정의 화면의 요구 구분자 목록 상시 표시로 보완한다.
