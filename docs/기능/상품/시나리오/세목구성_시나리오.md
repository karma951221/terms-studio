# 세목구성 시나리오

> 상태: 초안 · 최종수정: 2026-09-01
> 관련 기획: [[기능/상품/상품]] · [[기능/상품/결정/ADR-0006-세목-축모델]]

## 시나리오 1 — 상품 생성과 보통약관 마스터 선택
**전제**: 보통약관 마스터(알파Plus 보통약관 템플릿)가 존재. 상품 없음.
**흐름**:
1. 상품 생성 — `(무)알파Plus보장보험2604` 입력 → 상품 생성됨.
2. 보통약관 마스터 목록에서 알파Plus 보통약관 템플릿 선택 → 상품에 연결.
**기대 결과**: 상품이 보통약관 마스터 1개를 참조. 상품별 문면 변주 없음 — 보통약관 내용은 마스터 소유, 상품별 차이는 기본계약 연동뿐.
**경계·오류**: 보통약관 템플릿은 1개만 선택 가능 — 다중 보통약관(배상책임 담보류)은 MVP 이후 유예([[00_시작/범위]]).

## 시나리오 2 — 종·형 축과 세목유형 구조체 폼
**전제**: 세목유형 정의 존재(납입면제유형·무저해지유형·계약전환형·영위업종적용형·납입형태). 시나리오 1의 상품.
**흐름**:
1. 종 축에 선택지 추가 — 납입면제유형 선택 → 납입면제유형 구조체의 폼이 뜬다(유형 하나 = 구조체 하나, 폼 = 그 구조체).
2. 1종(보험료 납입면제 미적용형)·2종(보험료 납입면제형) 등록 — 뼈대 `(축, 번호, 이름, 세목유형 참조, 유형 구조체 값)` 저장.
3. 형 축에 무저해지유형의 1형(해약환급금지급형)·2형(해약환급금미지급형), 계약전환형의 4형(계약전환형) 등록.
**기대 결과**: 한 축(형)에 여러 유형(무저해지유형·계약전환형)이 공존. 유형을 고르는 단위는 종형 번호 하나하나. 다른 유형을 고르면 폼 필드가 바뀐다.
**경계·오류**: 한 유형은 한 축에만 걸칠 수 있다 — 종 축에 이미 걸린 납입면제유형을 형 축 선택지에 다시 걸면 거부. 번호 없는 축(보험료가벼운납입형류)은 MVP 밖.

## 시나리오 3 — 유효 조합 명시 등록 (카테시안 아님)
**전제**: 시나리오 2의 축 구성(종 1·2 / 형 1·2·4).
**흐름**:
1. 유효 조합 등록 화면 진입 — 축별 번호를 하나씩 골라 조합을 만든다.
2. (1종, 1형)·(2종, 1형)·(2종, 4형) 3개만 명시 등록.
**기대 결과**: 상품세목 = 등록한 3개 조합만. 축 번호의 카테시안 곱(2×3=6)이 자동 생성되지 않는다. 유형이 엇갈리는 조합((2종, 4형))도 의미는 같다 — 축마다 하나씩 고른 것. 문면 표기는 `제2종(보험료 납입면제형)` 처럼 번호 + 유형명 병기.
**경계·오류**: 등록하지 않은 조합((1종, 4형) 등)은 상품에 존재하지 않는다 — 이후 화면(세목 부착 등)의 선택지에 나타나지 않음. 제약 엔진 없음 — 명시 등록이 곧 제약이므로, 잘못된 조합을 등록해도 시스템이 막지 않는다. 등록 실수는 관계정보 뷰·미리보기로 잡는다.

## 시나리오 4 — 고지유형은 상품 레벨 enum
**전제**: 시나리오 3의 상품. 고지유형 enum 구분자(유효값: 일반심사·간편심사·건강고지)가 상품 레벨에 부착돼 있음.
**흐름**:
1. 상품 레벨 구분자 값 입력 폼(P1 폼 렌더러)에서 고지유형 = 간편심사 선택 → 저장.
**기대 결과**: 고지유형은 상품 구분자 값으로 저장 — 세목 축·조합 어디에도 나타나지 않는다.
**경계·오류**: 세목유형 후보 목록에 고지유형 없음(세목유형이 아니다 — 2026-08-29 확정). 「특정 고지유형에서는 기본납입형만」 같은 상품 구분자 값 ↔ 세목 구성 간 제약도 엔진이 아니라 사람이 유효한 조합만 등록하는 것으로 표현된다.

## 시나리오 5 — 축 일부·전부 미사용 상품
**전제**: 새 상품 2개 — 하나는 종 축만 사용, 하나는 축 둘 다 미사용(0종 0형).
**흐름**:
1. 종 축만 등록한 상품에서 유효 조합 등록 → 조합은 종 번호 하나로 구성.
2. 0종 0형 상품은 축 등록 없이 세목 구성을 마친다.
**기대 결과**: MVP 세 경우 모두 성립 — ① 종·형 둘 다 ② 하나만 ③ 둘 다 미사용. 0종 0형 상품도 담보 탑재·조립까지 정상 진행.
**경계·오류**: 종·형이 아닌 번호 없는 축은 MVP 에서 다루지 않는다 — 등록 경로 없음.
