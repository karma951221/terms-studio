# 상품

> 상태: 초안 · 최종수정: 2026-09-30

## 1. 한 줄

상품 하나 = 약관 책자 한 권. 상품모델링 화면은 탭 셋이다 — 무엇인가(기본정보: 상품정보 · 세목), 무엇을 얹는가(상품담보: 기본계약 · 특별약관 표 · 그룹), 어떤 글이 되는가(약관: 보통약관 작성 · 담보별 미리보기).
담보를 상품에 탑재하면 마스터 값이 **스냅샷**으로 복사된 상품담보가 생기고, 상품담보 하나가 특약 문서 한 벌이 된다. 문면은 여기서 고치지 않는다.

## 3. 규칙

### 3.1 상품

- 상품의 뼈대는 **상품명 + 보통약관 템플릿 참조**다. 상품 코드는 없다. 상품명은 비울 수 없고 상품끼리 겹칠 수 없다.
- 상품 복제는 없다 — 개정판은 새 상품으로 만든다.
- 상품 삭제는 파괴적이다 — **관리자만**, 영향 목록(상품담보 · 세목 선택지 · 그룹 · 사라질 값 행 수) 확인 뒤 하위가 연쇄 삭제된다. 편집자 요청은 서버가 거부한다 (ADR-0019).
- 상품 레벨 값은 「상품 × 상품 레벨 마스터 필드」 자리다 (ADR-0037). 구분자 부착은 없다.
- **상품정보 = 상품명 + 상품 레벨 폼 둘** (2026-09-28) — 공시이율 `disclosure`{평균공시이율 `avg_rate` 숫자, 단위 %} · 상품특성 `feature`{갱신형여부 `renewable` · 태아보장여부 `fetal` · 단체계약여부 `group_contract` 참거짓(태아 · 단체는 기본 아니오), 고지유형 묶음}.
  고지유형을 세목이 아니라 상품 레벨 enum 으로 둔 결정(ADR-0006)의 구현이다. 폼 · 필드는 마스터 코드(배포)고 선택지 값은 열거형(데이터)이라 늘릴 수 있다.
- **고지유형은 하나를 고르고 딸린 칸만 연다** (2026-10-01) — 계약은 일반심사 · 간편심사 · 건강고지 중 하나다.
  고지유형 `notice_kind` 목록값 E0005(일반심사 · 간편심사 · 건강고지, 기본 일반심사) →
  간편심사면 간편심사구분 `review_scope` E0006(단일심사 · 통합간편심사) + 간편심사유형 `review_type` 목록값(복수) E0003(3.0.5 ~ 3.10.5) — 단일심사면 하나(라디오), 통합간편심사면 2개 이상(체크박스) ·
  건강고지면 건강고지유형 `notice_type` 목록값(복수) E0004(6년 ~ 10년 건강고지형) 1개 이상.
  조건이 맞지 않는 칸은 보이지 않고 미입력으로 세지 않으며, 고지유형을 바꿔 저장하면 딸린 칸의 값을 지운다. 규칙은 저장 때 서버가 막는다([[기능/마스터/마스터]] §3.4).
  — 왜: 옛 상품모델링 화면이 상품 단위로 받던 사실들이다. 상품 한 권에 하나라 세목 축을 타지 않는다. 지금 문면이 읽는 구분자는 없다 — 읽게 되면 상품 레벨 구분자로 붙인다.
  시드는 원문이 밝힌 값만 넣는다 — 평균공시이율 2.50%(두 보통약관 용어 정의) · 메리츠 간편심사 · 통합간편심사 3.0.5 ~ 3.10.5 · 갱신형(특약 전부 갱신형). 태아 · 단체는 두 상품 모두 아니오, 알파Plus 는 일반심사.

### 3.2 세목

- **선택지** = `(축, 번호, 이름, 세목유형, 그 유형 폼의 값)`. 축은 종 · 형 둘이고 번호 없는 축은 MVP 밖이다. 번호는 1 이상 정수로 필수, 같은 축 안에서 유일. 이름 필수 (ADR-0006).
- **세목유형 = 세목(plan) 레벨 코드 폼 넷** — 납입면제 `waiver` · 무저해지 `no_surrender` · 계약전환 `conversion` · 영위업종적용 `business_type`. 유형을 더하거나 필드를 바꾸는 것은 배포다 ([[기능/마스터/마스터]] §3.1).
  사용자가 만드는 것은 유형이 아니라 선택지와 조합이다.
- 한 유형은 한 축에만 걸친다. 한 축에는 여러 유형이 공존할 수 있다 (ADR-0006).
- 선택지는 **제 유형 폼의 값만** 갖는다. 다른 폼의 필드 값은 거부된다.
- 저장된 선택지의 축과 유형은 바꿀 수 없다 — 바꾸려면 지우고 새로 만든다. 번호 · 이름 · 값은 고친다.
- 종형명은 유형 필드가 아니라 **선택지 이름**이다. 표기는 `제1종(보험료납입면제미적용형)`. 문면은 반복 「납입면제종마다」 안에서 번호 · 이름을 따로 찍는다 — `builtin.plan.number` · `builtin.plan.name`(원문 「2종(보험료 납입면제형)」, 2026-09-30).
- **유효 조합은 명시 등록**이다 — 카테시안 자동 생성이 없다. 사용 중인 축마다 선택지 하나씩, 같은 구성은 중복 거부. 선택지가 없는 상품(0종 0형)은 조합 0건이 정상이다 (ADR-0006). 조합은 고치지 않고 빼고 넣는다.
- 저장이 기존 선택지 · 조합을 지우게 되면 파괴적이다 — **관리자만**, 영향(값 행 수 · 보험종목 · 종·형 조합 · 세목 부착) 확인 뒤 연쇄 삭제 (ADR-0019).
- **선택지는 기본값으로 태어난다** — plan 폼 필드마다 코드 `defaultValue`(납입면제 적용여부 = 아니오 · 무저해지 유형 = 표준해약환급금지급형 · 계약전환 = 아니오 · 영위업종 = 아니오)를 두고, 새 선택지 폼은 그 값으로 프리필된다(저장해야 값이 된다). 기본값을 바꾸는 것은 배포다 — 유저가 편집하는 세목 마스터 값도, 재사용 세목 마스터(「무저해지형」 목록)도 두지 않는다. `/master` 는 기본값을 글자로 보이기만 한다. **미구현** — plan 폼에 `defaultValue` 가 없어 새 행은 빈 폼에서 시작한다.
  — 왜: 기본값은 상품마다 달라지지 않는 사실상 상수다. 「납입면제1형 · 2형」처럼 사유만 다른 형은 값 묶음 + 선택지 이름으로 충분하다.
- **납입면제종 = 적용여부 = 예 인 `waiver` 선택지** — 보통약관 템플릿은 그 위로 블록 반복(「납입면제종마다」)해 종마다 항을 펼친다(§3.9 — 블록 반복 구현 2026-09-30, [[기능/문면/문면]] §3.7). 그래서 종의 순서 · 수를 템플릿이 묻지 않는다.
- **상품담보별 세목 부착은 저장되지만 MVP 조립은 읽지 않는다** — 보통약관 · 특약 · 공용조항이 모두 상품 범위(유효 조합에 등장하는 선택지)를 본다. 선택지는 있는데 조합이 0건이면 조립 `noPlan` 오류. 평가 규칙은 [[기능/조립산출/조립산출]] §3.2.

### 3.3 탑재 · 상품담보

- **상품담보 = 담보 × 담보속성 값 조합** — 필요한 속성만 붙인다(sparse). 같은 상품에 같은 조합은 중복 거부 (ADR-0015).
- **탑재는 값 스냅샷이다** — 담보 → 세부보장 → 급부의 마스터 값이 「노드 × 마스터 필드」 좌표 그대로 복사된다(미입력은 미입력 그대로). 이후 마스터 값 변경은 이 상품담보에 흘러들지 않는다 (ADR-0002).
- 구조(트리)는 공유다 — 상품담보는 구조를 바꿀 수 없다. 마스터의 구조 정정은 담보 상세 저장과 같은 트랜잭션에서(그리고 조회 · 조립 전에 다시) 맞춰진다: 추가 노드는 미입력 자리, 삭제 노드는 스냅샷 값 행 삭제 (ADR-0002 · ADR-0075).
- 탑재 때 **default 상품담보명**을 작명 틀(값별 상품담보명 표기 + 칩 템플릿)로 짓는다. 이후 수동으로 고칠 수 있고, 틀을 고친 뒤 기존 이름을 되맞추는 길은 「작명 규칙으로 다시 짓기」 하나다 ([[기능/담보속성/담보속성]] §3.4).
- 탑재는 **절을 고른다** — 기본계약 / 특약 (ADR-0021). 기본계약 절로 탑재하면 탑재 + 기본계약 지정이 한 번에 된다(이미 기본계약이 있으면 탑재 전에 거부).
- 탑재 해제는 파괴적이다 — **관리자만**, 영향(세부보장 · 급부 · 세목 부착 · 그룹 배치 · 값 행 수) 확인 뒤 연쇄 삭제. **기본계약이면 거부** — 지정을 먼저 해제한다 (ADR-0019).
- 상품담보 복제는 없다 — 값 복사 시점은 탑재 한 번뿐이다. 그래서 「탑재 당시 값으로 되돌리기」도 없다.
  — 왜: 탑재 당시 값은 어디에도 남기지 않는다. 당시 값이 필요해지면 이력(ADR-0026, MVP 이후)의 일이다.
- 탑재 뒤 담보속성 조합 수정 — 서비스는 있다(중복 거부 · 이름 재생성 선택). 화면은 **미구현**.

### 3.4 스냅샷 값

- **소유** — 값 · 담보속성 조합 · 상품담보명 · 세목 부착은 상품담보 것(복사본). 구조 · 노드 이름 · 문면 · 필드 정의 · enum 표시명 · 공용조항 정의와 유효 옵션 · 별표 마스터 · 작명 틀은 지금 마스터를 따른다 — 값 자리의 라벨이 바뀌어도 값은 그대로다.
- 한 제출 = 한 트랜잭션 — 하나라도 거부되면 아무것도 안 바뀐다. 타입 · 유효값 불일치는 거부.
- 스냅샷 값의 명령은 셋 — **미저장 변경 취소 · 값 비우기 · 현재 마스터 값 가져오기**(지금 마스터 값을 채움 · 확인 없이 편집 중 변경으로). 「되돌리기」라는 명령은 없다. 「값 지우기」는 「값 비우기」의 옛 이름이다.
  - 가져오기 아이콘은 **마스터와 다른 필드에만** 붙는다 — tooltip 「현재 마스터 값 가져오기 · 마스터 90 · 이 값 80」. 마스터 값을 helper text 로 깔지 않는다.
  - 비우기는 미입력(조립이 막힌다), 가져오기는 명시 값 — 결과가 달라 한 버튼에 두지 않는다.
  — 왜: 남아 있는 기준값은 지금 마스터 값뿐이라 「되돌리기」는 없는 과거를 약속한다. 편집 중 변경이 되면 취소로 되돌릴 수 있어 확인 팝업이 필요 없다.
  **미구현** — 지금 화면은 「마스터 값으로 되돌리기」 + 확인 카드이고, 비우기는 폼 단위 하나다.

### 3.5 기본계약

- 상품당 **정확히 1개** (MVP). 두 번째 지정은 거부 — 바꾸려면 해제 → 지정 (ADR-0021).
- 지정하려면 보통약관 템플릿이 선택돼 있어야 한다. 지정하면 그 상품담보의 특약 그룹 배치가 풀린다.
- 보통약관이 담보 레벨에서 읽는 값 · 담보속성은 기본계약 상품담보에서 온다 ([[기능/조립산출/조립산출]] §3.2). 0개면 `noBaseContract`, 2개 이상(옛 데이터)이면 「하나만 남기고 해제」 오류 — 조립이 이 오류로 멈춘다.
- 지정 시 검사가 돈다 — 실패는 **거부가 아니라 오류 목록**이다. 해제는 막지 않는다. 해제된 상품담보는 특약 절(상품담보 탭의 특별약관 표)로 돌아간다.

### 3.6 보통약관

- 상품이 보통약관에 대해 하는 일은 넷뿐이다 — **템플릿 선택 · 기본계약 · 공용조항 옵션 오버라이드 · 조 노출**. 문면 수정은 없다 (ADR-0003). 템플릿은 하나(다중 보통약관은 MVP 밖).
  상품별 변주의 예외는 **옵션 선택 · 조 노출** 둘뿐이다 — 문장을 고치는 오버라이드로 넓히지 않는다.
- **템플릿 교체 · 해제**는 조 노출 · 옵션 오버라이드를 함께 초기화한다(둘 다 템플릿 노드에 매달린 설정). 잃을 것이 있으면 세어(숨긴 조 N · 오버라이드 K) 확인 카드를 보이고, 확인하면 한 트랜잭션으로 비우고 바꾼다. 같은 템플릿을 다시 고르면 잃는 것이 없다.
  역할 관문은 없다 — 편집자도 한다. 확인 카드는 서비스의 `dryRun` 으로 묻는다 — 화면이 「잃을 것」을 따로 계산하지 않는다(술어가 둘로 갈리면 화면만 조용히 틀린다).
  옵션 오버라이드가 있으면 교체를 거부하던 옛 규칙은 폐지됐다.
- **조 노출** — 템플릿의 조를 상품별로 끌 수 있다. 기본은 전부 노출. 상품이 갖는 것은 「조 id → 노출여부」뿐이고 템플릿에 없는 조 id 는 거부. 쓰기는 상품 · 템플릿 조 조회와 한 트랜잭션이다(검사와 쓰기 사이의 템플릿 교체로 낡은 숨김 행이 생기지 않게).
  — 왜: 「이 상품엔 이 조가 필요 없다」는 상품 값에 근거가 없어 조건식으로 쓸 수 없다.
  - 즉시 저장이라 ✕ 취소가 없다 — 되돌리기는 「다시 켜기」다.
  - 끈 조는 조립에서 빠지고 조 번호가 순연된다.
  - 끈 조를 조참조 · 준용하면 `articleHidden` 오류 + 좌표. 참조 덩어리의 대상이 일부만 숨겨졌으면 남은 대상으로 표기하고 오류가 아니다.
  - 특약 조가 숨긴 조에 조연결돼 있으면 준용 대신 오류 + 그 조 문면 전체 출력.
- **옵션 오버라이드는 보통약관 자리만** — 공용조항 참조 노드 하나가 한 자리다. 담보약관의 옵션은 담보 마스터가 다 정한다(미결정은 담보약관 문면의 저장 검사가 잡는다). 상품담보 값 화면에는 옵션 UI 가 없다 ([[기능/함수조항/함수조항]] §3.2).
  — 왜: 담보약관은 담보가 소유한다 — 조정은 소유자 화면에서. 탑재분마다 옵션을 열면 같은 담보의 문구가 갈라지는 통로가 하나 더 생긴다.
  - 정의의 유효 옵션 집합 안에서만 고른다. 마스터 기본과 합친 결과로 검사하고 **마스터와 다른 값만** 저장한다 — 전부 같아지면 행을 지운다. 그래서 「마스터 기본으로」를 남긴 부분 선택도 저장된다.
  - 자리(`nodeId`)에 걸린 공용조항과 코드가 다르면 거부 — 조립은 오버라이드를 `nodeId` 로만 얹으므로 어긋난 행이 남으면 그 자리에 조용히 적용된다.
- 별표는 상품이 갖지 않는다 — 조립이 참조된 별표를 등장 순으로 모아 번호를 매긴다 (ADR-0063 · [[기능/별표/별표]]).

### 3.7 특약 그룹

- 특약 배치는 **그룹핑**이다 — 그룹 제목이 책자에 찍히고 상품담보를 소속시킨다. 상품담보는 한 그룹에만 속한다.
- 그룹 안 순서는 자동 — **담보 → 담보속성 종류 → 유효값** 오름차순(미사용 속성이 앞). 같은 담보의 탑재분 뭉침은 정렬의 귀결이다. 수동 순서는 없다.
- 한 그룹 = 한 보통약관 템플릿. MVP 는 그룹 템플릿이 상품 템플릿과 같아야 한다.
- 그룹 삭제는 값을 잃지 않는다 — 소속 상품담보가 미배치로 돌아간다. 확인 카드는 거치되 편집자도 한다.
- 그룹 사이 순서 — 서비스는 있다. 화면은 **미구현**.

### 3.8 저장 단위 · 화면 공통

- 상세는 **탭 셋** — 기본정보(상품정보 · 세목) · 상품담보(기본계약 · 특별약관 표 · 그룹) · 약관(둘째 줄 하위 탭 **보통약관 작성 · 담보별 미리보기**) (2026-09-28 「안 2」).
  — 왜: 보통약관 탭에 템플릿 선택 · 기본계약 탑재 표 · 기본계약 목록 · 세 패널이 한데 쌓여 「본문만 집중해서 보고 싶은데 흐트러진다」(사용자 QA 2026-09-28). 층이 다른 일(값 입력 · 무엇을 얹나 · 글 확인)을 탭으로 가르고, 글을 보는 두 자리는 약관 탭 아래로 모은다.
- **기본정보 탭은 한 편집 화면** — 읽기로 열리고 `편집` → 상품명 · 상품 레벨 값 · 세목(두 탭) → `저장` 하나. 한 트랜잭션.
- **상품담보 · 약관 탭의 조작은 명령이라 즉시 저장** — 탑재/해제 · 이름 · 세목 부착 · 그룹(상품담보), 템플릿 교체 · 조 노출(보통약관 작성). 저장 = 재평가라 미리보기가 바로 맞는다. 옵션 오버라이드는 폼 하나 = 저장 하나.
- **탭은 URL**(`?tab=basic|coverages|terms`, 약관은 `&sub=general|special`) — 탭 간 초안은 없다. 그래서 기본정보 편집 중 고친 것이 있으면 **탭 링크도 경로 링크 · 취소처럼 「고친 내용을 버립니까?」** 를 거친다. 고친 것이 없으면 묻지 않고, 기본정보를 떠나면 편집이 풀린다.
  — 왜: 기본정보는 「문서를 쓰는 입력」이라 화면 편집 원칙(저장 하나)이 그대로 서고, 다른 탭의 조작은 누르는 순간 의미가 완결되는 명령이라 저장 = 재평가로 서버 한 벌만 진실을 갖는다. 탭이 URL 인 것은 오류 좌표의 「고치러 가기」와 확인 카드(`?confirm=`)가 주소로 도착해야 해서다.
- 옛 주소 `?tab=general|special` 은 지금 사는 자리로 redirect — 보통약관 → 약관 › 보통약관 작성, 특별약관 → 상품담보(`&pc=` 가 있으면 약관 › 담보별 미리보기), 탑재 · 그룹 확인 카드(`confirm=pc:|detach:|group:`)는 상품담보. 나머지 쿼리는 싣는다.
- 상세의 제목 줄은 경로 「상품 › {상품명}」 — 돌아가는 길은 경로 하나. 완결성 · 입력률은 표시하지 않는다 ([[공통/화면/디자인원칙]] §1.7 · §9.2).
- URL 의 좌표(`?pc=` · `?option=` · `?art=`)는 이 상품 것일 때만 믿는다.

### 3.9 납입면제 — 종 · 사유 (2026-09-30, `waiver` 폼 검사만 구현)

- **납입면제종은 세목 선택지, 사유 묶음은 그 선택지의 `waiver.reasons`**(목록값(복수) E0001)다. 「형」은 무저해지 축(해약환급금 지급형 · 미지급형)과 겹쳐 납입면제 쪽은 「종」이라 부른다.
  보통약관 템플릿은 종마다 항 · 그 안에 사유마다 호, 정의 및 진단확정 조는 사유 합집합 ∩ 정의조대상마다 펼친다 — [[기능/문면/결정/ADR-0077-블록반복-세목선택지-열거목록-반복참조]] 템플릿 스케치.
- **세목은 E0001 값을 고르기만 한다** — 면책 · 표시명은 상품에서 바꾸지 않는다. 면책은 값을 나눠 표현하고(「암(유사암제외)·면책」 · 「·무면책」), 약관표시명 · 면책여부 · 정의조대상은 열거값 필드다([[기능/열거형/결정/ADR-0078-열거값-유저정의필드-값나누기]]). 무면책 상품은 「·무면책」 값을 고른다.
  — 왜: 면책은 그 값의 사실이라 한 곳(열거값)에만 산다. 종마다 다른 면책도 값 선택으로 된다.
- **납입면제가 없는 상품** = 적용 종이 없다. 상품 구분자 **「납입면제 있음」**(적용여부 = 예 인 `waiver` 선택지가 있는가)이 납입면제 세 조를 조 자리 IF 로 감싸 뺀다 — 조 노출 토글(§3.6)은 쓰지 않는다.
  — 왜: 납입면제 유무는 세목 값에서 나오는 사실이다. 토글은 상품 값에 근거가 없을 때 쓰는 장치다.
- **`waiver` 폼 검사** — 적용여부 = 예면 사유를 1개 이상 고른다(저장 거부). 사유 미입력도 0개다. 기본정보 저장 · 세목 선택지 값 제출이 저장된 값 위에 제출을 얹은 최종 상태로 판정하고, 오류 문구에 종목(「제2종(…) — …」)을 싣는다 — 폼 교차 규칙([[기능/마스터/마스터]] §3.4).
- 1형 적립 중지(원문 제27조의1 ④)는 템플릿의 상품 범위 조건이다 — 종 조합을 보지 않는다.

## 4. 화면

### 4.1 `/products` — 상품 조회 (L1)

| 구성 | 내용 |
|---|---|
| 제목 줄 | 「상품」 + 오른쪽 `+`(새 상품) |
| 검색 | 상품명 |
| 표 | 상품명(상세 링크) · 보통약관(지정됨 / 미지정). 페이저 「총 N건」 · 50건 |
| 빈 상태 | 「상품은 약관 책자 1권의 단위다 …」 + 새 상품 만들기. 검색 결과 없음은 한 줄 |

### 4.2 `/products/new` — 새 상품

상품명 한 칸 + 생성. 생성하면 그 상품의 기본정보 탭으로 간다. 빈 이름 · 중복 이름은 같은 화면에 오류.

### 4.3 `/products/<id>` — 공통 헤더

| 자리 | 읽기 | 편집(기본정보 탭만) |
|---|---|---|
| 왼쪽 | 경로 「상품 › {상품명}」 — 「상품」은 목록 링크 | 같음. 고친 것이 있으면 링크를 누를 때 「고친 내용을 버립니까?」 |
| 오른쪽 | `[편집]`(기본정보 탭에서만) `[더보기 ▾]` — 미리보기 · 상품 삭제 | `[취소] [저장]` — 같은 자리 · 같은 규격 |
| 아래 | 탭 기본정보 · 상품담보 · 약관 (`?tab=`). 약관이면 둘째 줄 보통약관 작성 · 담보별 미리보기 (`&sub=`) | 같음. 고친 것이 있으면 다른 탭을 누를 때 「고친 내용을 버립니까?」 — 버리면 그 탭으로 가고 편집이 풀린다 |

- 상품 삭제 → `?confirm=product` 확인 카드(영향 목록) → 실행하면 목록으로.
- 「고친 것」은 편집 시작(서버 값)과 초안의 내용 비교다 — 입력했다 되돌리거나 조합을 껐다 켜면 고친 것이 아니다.
  — 왜: 탭이 URL 이라 탭을 옮기면 기본정보 본문이 내려가 초안이 사라진다. 전에는 탭 링크에 확인이 없어 초안이 조용히 사라졌고, 헤더는 본문 없는 `[취소] [저장]` 로 남았다(점검 M21).

### 4.4 `?tab=basic` — 기본정보

구성 (위에서 아래로):

| 섹션 | 읽기 | 편집 |
|---|---|---|
| 상품정보 | 항목 · 값 표 — 상품명(입력창 모양 · 읽기 전용) · 평균공시이율 · 「상품특성」 줄 아래 갱신형여부 · 태아보장여부 · 단체계약여부 · 간편심사유형 · 건강고지유형. 빈 값은 「—」 | 셀에서 바로 입력(숫자 · 예/아니오 · 목록값 select). 상품명을 비우면 칸 아래 오류 |
| 세목 › 보험종목 정의 | 종·형 · 보험종목명 · 값 열들 | 선택 · 구분(종/형) · 번호 · 보험종목명 · (세목유형) · 값 열들 |
| 세목 › 종·형 조합 | 저장된 조합만 | 후보 전부 + 「사용」 체크 |

- 상품정보의 항목은 상품 레벨 마스터 폼을 선언 순서대로 편다(§3.1). 폼이 둘 이상이면 필드가 둘 이상인 폼 앞에 폼 이름 줄을 끼운다.
- 값 열 = 표에 나온 종목들의 세목유형 폼 필드 합집합. 폼이 둘 이상 섞이면 「납입면제 적용여부」처럼 폼 이름을 붙인다. 입력 부품은 마스터 타입대로(boolean 예/아니오 · list<enum> 체크박스). 빈 값은 「—」.
- 세목유형 열은 세목 레벨 폼이 둘 이상일 때만 편집 표에 선다. 구분 · 세목유형은 **새 행만** 고칠 수 있다.
- 조합 후보 — 종과 형이 다 있으면 종 × 형, 한 축만 있으면 선택지마다 하나.
- 세목의 두 탭을 오가도 편집 초안은 유지된다.
- 마스터 사용처에서 `?option=<선택지>&field=<경로>` 로 오면 그 행 · 셀을 강조하고 화면 가운데로 스크롤한다.

| 유저액션 | 결과 |
|---|---|
| `편집` | 저장된 값으로 초안을 만들고 편집 상태로. 헤더가 `[취소] [저장]` |
| 보험종목 추가 | 초안에 빈 행 하나 — 종 축 · 그 축의 다음 번호 · 첫 세목유형 · 빈 값 |
| 행 선택 → 선택 삭제 | 선택했을 때만 버튼이 선다. 초안에서 그 행과 그 행을 쓰는 조합을 뺀다 |
| 조합 체크 / 해제 | 초안의 사용 조합을 넣고 뺀다. 등록 버튼 없음 |
| `취소` | 고친 것이 있으면 「고친 내용을 버립니까?」 → 버리면 읽기로. 고친 것이 없으면 바로 읽기로 |
| `저장` | 빈 상품명 · 번호 · 이름은 화면이 먼저 막고 해당 칸에 표시. 서버가 전체를 검증해 한 트랜잭션으로 저장 → 읽기로 |
| `저장` — 기존 종목 · 조합이 지워지는 경우 | 「저장하면 아래 항목이 삭제된다」 카드(보험종목 · 종·형 조합 · 세목 부착 · 사라질 값 행) → 「삭제 반영 후 저장」(관리자) / 「돌아가기」 |
| `저장` — 거부 | 입력을 유지하고 사유 배너(번호 중복 · 한 유형 두 축 · 축/유형 변경 · 조합 규칙 · 이름 중복 · 편집자의 삭제 등) |

빈 상태: 종목 0 — 읽기 「정의된 보험종목이 없다. 편집을 눌러 추가한다.」 · 편집 「보험종목 추가로 첫 행을 만든다.」 / 조합 — 「보험종목을 먼저 정의한다.」 · 「사용하는 조합이 없다. 편집을 눌러 조합을 고른다.」

### 4.5 `?tab=coverages` — 상품담보

| 섹션 | 내용 |
|---|---|
| 기본계약 `#base-contract` | 기본계약 검사 결과(오류 목록) + 탑재 표 + 탑재 폼(담보 검색 입력 — 서버에서 이름 · 담보코드로 찾는다, 50건 넘으면 「더 쳐서 좁힌다」 · 담보속성별 select → 「기본계약에 탑재」). 이미 기본계약이 있으면 탑재 폼 대신 「변경하려면 먼저 해제하세요」. 이 표에 얹은 것이 곧 기본계약이다 — 따로 지정 · 해제하는 절은 없다(2026-10-01, 표를 한 번 더 보여줄 뿐이었다) |
| 특별약관 | 탑재 표 + 탑재 폼(→ 「특별약관에 탑재」) |
| 특약 그룹 N개 | 그룹마다: 제목 입력 + ✓ 저장 · 삭제 아이콘 · 소속 상품담보(배치 해제 ✕) · 미배치 상품담보 검색 입력(「배치할 상품담보 · 그룹」) + ＋ 배치. 아래 「새 그룹 제목」 + 그룹 추가 · 미배치 목록 한 줄 |

**탑재 표** (기본계약 · 특별약관 두 절이 같은 모양, 2026-09-27 — 옛 상품모델링 화면의 표를 따른다 · 2026-09-28 담보 묶음):

- **한 행 = 상품담보 하나.** 담보 : 상품담보 = 1 : N — 같은 담보를 두 벌 탑재하면(일반상해사망보장 기본 · 추가) 두 행이고, 담보속성 조합이 둘을 가른다.
- **같은 담보의 상품담보는 이어 놓는다** — 묶음 순서는 그 담보가 처음 탑재된 순서, 묶음 안은 탑재 순. 담보코드 · 담보명 칸은 **묶음 첫 행에만** 찍고 뒤 행은 빈칸(윗줄 괘선을 흐리게). 검색 · 페이지로 걸러져도 **보이는 행** 기준으로 같은 규칙이다 — 보이는 묶음의 첫 행은 늘 코드를 갖는다.
- 제목은 절 이름만(「기본계약」 · 「특별약관」 — 2026-10-01 「보통약관 기본계약」에서 줄임) — 개수는 표 아래 페이저 「총 N건」 (L1 목록과 같은 부품 · 50건).
- 표마다 위에 **「담보 검색」** — 담보코드 · 담보명 · 상품담보명 · 담보속성 조합(`갱신유형=갱신형` 의 어느 조각이든)을 거른다. 입력하면 URL 로 간다 — 특별약관 `?mq=`(페이지 `?mpage=`) · 기본계약 `?bq=`(`?bpage=`). 한 표의 페이저는 다른 표의 검색어를 싣는다. 맞는 것이 없으면 「「…」에 맞는 상품담보가 없습니다.」. 확인 카드는 검색에 가려진 행의 것이어도 뜬다.

| 열 | 내용 · 조작 |
|---|---|
| 담보코드 | `COV000002` — 담보 마스터 링크(tooltip 담보명). 담보가 없어졌으면 「—」 ([[기능/담보/담보]] §3.1). 묶음 첫 행에만 |
| 담보명 | 담보 마스터 이름. 묶음 첫 행에만 |
| 담보속성 | `갱신유형=갱신형 · 부가유형=추가` — 종류 순. 붙인 속성이 없으면 「—」 |
| 상품담보명 | 작명 틀 결과(예: 「일반상해사망보장 추가」). 이름 입력 + ✓ 저장 · 「미리보기」(특약 절만 — 약관 › 담보별 미리보기로). 「값 →」 링크는 없다 — 행마다 줄이 어긋나고 잘못 누르면 화면이 바뀌었다(2026-10-01) |
| 세목 부착 | 유효 조합 select + ＋ 부착 (조합 0건이면 비활성) |
| 조작 | 작명 규칙이 지금 지어 줄 이름이 다르면 「작명: …」 · 「작명 규칙으로 다시 짓기」(즉시 덮어씀) · 탑재 해제(`?tab=coverages&confirm=pc:<id>` 확인 카드) |

| 유저액션 | 결과 |
|---|---|
| 담보 + 담보속성 고르고 탑재 | 상품담보 생성 · 스냅샷 · default 이름 → **그 상품담보 값 화면으로 이동**. 중복 조합이면 상품담보 탭에 오류 |
| 탑재 해제 | 확인 카드(영향 목록) → 관리자 실행. 기본계약이면 「지정을 먼저 해제하세요」 |
| 그룹 삭제 | `?tab=coverages&confirm=group:<id>` 카드 — 「상품담보 N건 미배치로」 → 실행 |
| 「미리보기」 | 약관 › 담보별 미리보기(`?tab=terms&sub=special&pc=<id>`)로 간다 |

빈 상태: 절에 상품담보 0 — 「아직 {절} 담보가 없다. 오른쪽에서 담보를 골라 탑재한다.」 · 그룹에 소속 0 — 「배치된 상품담보 없음」.

| 상태 | 표시 |
|---|---|
| 기본계약 0건 | 「기본계약을 하나 지정하세요 — 보통약관이 담보 레벨 값을 읽는 자리는 기본계약에서 온다」. 보통약관 작성의 미리보기에서 담보 레벨 참조 자리에 오류 마커 |
| 기본계약 2건+(옛 데이터) | 오류 배너 「하나만 남기고 해제하세요」 |

**미구현**: 부착된 세목 조합의 표시와 부착 해제 UI(서비스 · 확인 경로는 있다) · 담보속성 조합 수정 · 그룹 순서 변경.

### 4.6 `?tab=terms&sub=general` — 약관 › 보통약관 작성

보통약관 본문에만 집중하는 자리다 — 다른 것은 두지 않는다 (2026-09-28).

| 자리 | 내용 |
|---|---|
| 위 한 줄 | 「보통약관 템플릿」 검색 입력(「미지정」 포함) + 「템플릿 저장」 · 오른쪽 카운트 `N조 중 M 노출 · 오버라이드 k · 오류 e · 별표 b(자동)` |
| 아래 | 화면 높이를 채우는 세 패널(목차 · 원문 모델 · 미리보기) |

**세 패널** — 단위는 **관**(템플릿 최상위 관. 관이 없는 문서는 「전체」, 관이 섞인 문서의 관 밖 조는 「관 밖 조 제N조 ~ 제M조」).

| 패널 | 보이는 것 | 조작 |
|---|---|---|
| 목차(좌) | 관 제목 › 조(체크박스 + 템플릿 번호 + 제목). 끈 조는 취소선 · 흐리게. 고른 조 강조 | 체크 = 노출 토글(즉시 저장 · 실패 사유는 체크 옆). 조 제목 = 그 조를 고른다 — **서버를 다시 부르지 않는다**, 주소만 `&art=<조>` 로 맞춘다(replaceState) |
| 약관 — 원문(가운데) | 고른 조의 관을 템플릿 **모델** 그대로 — 조건 블록 · 조건식(구분자 표시명) · 슬롯 칩 · 조 참조(템플릿 번호) · 별표 참조(별표 이름). 공용조항은 머리 띠 상자 「공용조항 (이름)」 + 「공용조항에서 고치기 →」 안에 **그 공용조항의 모델**(글 · 슬롯 · 옵션 자리 = 선택지 전부 + 이 상품이 고른 것 ✓ · 조건 · 참조, [[기능/함수조항/함수조항]] §4.4). 끈 조는 자리에 남아 흐리게 + 「노출 끔」 | 공용조항 상자의 모델 아래 옵션 선택 → 저장(그 상자가 든 조로 돌아온다). 마스터 기본을 옆에 · 다르면 「오버라이드」 배지 + ↺(오버라이드 지우기) |
| 미리보기 — 평가(오른쪽) | 조립 결과를 같은 관으로 자른 것 — 조건식 평가 · 끈 조 제외 · 번호 순연. 위에 이 관의 오류 목록 + 다른 문서의 `articleHidden` | 오류 링크 — 이 패널에 있는 노드는 그 자리로, 특약 오류는 그 상품담보 화면으로 |

- 고른 조로 가운데 · 오른쪽이 함께 스크롤한다. 목차에서 조를 안 골랐거나 없는 조면 첫 조.
- 서버는 관마다 가운데 · 오른쪽을 미리 그려 두고 화면은 고른 조의 관만 붙인다 — 목차로 관을 옮겨도 새로고침이 없다(2026-09-28 사용자 QA). 새 창 · 새 탭(수정키)은 진짜 주소로 열린다.
- 템플릿 줄 오른쪽 카운트의 오류 수는 **문서 전체** 스코프다(관 필터 없음) — 관을 옮겨 다니지 않고 「이 상품 보통약관의 오류 수」를 본다.
- 템플릿 교체 · 해제로 잃을 것이 있으면 `?tab=terms&sub=general&confirm=template:<새 id>` 확인 카드 — 「템플릿을 「…」로 바꾸면 아래 설정이 초기화된다」 + 숨긴 조 N · 옵션 오버라이드 K → 「「…」로 교체」 / 취소(템플릿 · 설정 그대로).

| 상태 | 표시 |
|---|---|
| 템플릿 미지정 | 세 패널 대신 「보통약관 템플릿을 고르면 여기에 목차 · 원문 · 미리보기가 선다.」 |
| 조립 불가 | 오른쪽 패널에 「조립할 수 없다 — 사유」 |

### 4.7 `?tab=terms&sub=special` — 약관 › 담보별 미리보기

| 자리 | 내용 |
|---|---|
| 왼쪽 | 특약 상품담보 목록(`&pc=<id>` 링크, 고른 것 강조). 0건이면 「특약 상품담보가 없다 — 상품담보 탭에서 탑재한다.」 |
| 오른쪽 | 고른 한 건 — **보통약관 + 준용까지 계산된** 특별약관 문면. 머리 「오류 e / 조 n」 · 오류 목록. 별표 번호는 이 특약만의 임시 번호(책자 번호는 조립 미리보기 링크). 안 골랐으면 「왼쪽에서 상품담보를 골라 미리보기」 |

- `?pc=` 는 특약 절의 상품담보일 때만 믿는다 — 기본계약 · 없는 id 는 안 고른 것으로. 기본계약의 글은 보통약관 작성의 미리보기가 제자리다.

### 4.8 `/products/<id>/coverages/<pcId>` — 상품담보 값

| 구성 | 내용 |
|---|---|
| 경로 | 「상품 › {상품명} › {상품담보명}」 — 상품명은 상품담보 탭으로 |
| 머리 | 「담보 마스터: {담보명}」 링크 |
| 미입력 | 미입력 자리 목록 `노드 › 경로` + 「고치러 가기」(그 노드 폼 앵커). 없으면 섹션 없음 |
| 값 | 담보 상세와 같은 중첩 카드 (2026-09-27) — 담보 카드(담보 레벨 값) ⊃ 세부보장 카드 그리드(넓으면 2열) ⊃ 급부 카드. 접지 않는다. 필드가 없는 레벨은 이름만. 세목 레벨 값은 여기 없다(기본정보 탭) |
| 상품담보 미리보기 | 매 요청 실시간 계산(저장 안 함) — 조 수 · 조립 검사 한 줄 · 「완성본 아님」 배너 · 오류 목록 · 문면 |

- 지금 실물은 **노드마다 폼 · 저장**이고, 손댄 스냅샷 칸 옆 ↺ 「마스터 값으로 되돌리기」는 확인 카드를 거친다. 폼마다 「비우기」.
- **미구현** — 와이어프레임 §20.3 검토안(헤더 `[편집] [더보기 ▾]` · 읽기로 시작 · 편집/저장 하나) · §3.4 의 「현재 마스터 값 가져오기」(이름 · 확인 폐지) · 머리 한 줄 「값은 탑재 시점의 복사본이다 · 문면 · 구조 · 이름은 지금 마스터를 따른다」.

### 4.9 `/products/<id>/preview` — 조립 미리보기

저장된 산출본을 보여 주는 책자 전체 미리보기 — 「실행 / 다시 실행」 · 오래된 결과 배지 · 조연결 판정. 경로 「상품 › {상품명} › 미리보기」. 화면 규칙은 [[기능/조립산출/조립산출]].

## 5. 미결

- **템플릿 교체 · 해제의 역할** — 구현은 편집자 + 확인 카드(역할 관문 없음). 옛 유저액션은 「옵션 오버라이드가 있으면 관리자만」이었다. 어느 쪽이 정본인지 정하지 않았다.
- **기본계약 지정 시 검사의 대상** — 지금은 「템플릿 선택 · 정확히 1개 · 요구 참조」까지. 보통약관이 담보 레벨 이하에서 읽는 값 · 참조가 기본계약 담보 트리에 자리가 있는가([[기능/함수조항/함수조항]] §3.4 검사 ②의 보통약관 판)를 더할지.
- **빈 관의 출력 정책** — 편집 목차에는 두고 최종 출력에서 뺄지. 실물 사례 · 관 번호 정책 확인 뒤.
- **좁은 화면의 세 패널** — 접기 · 겹치기 미정.
- **상품담보 탭 상세** — 세목 부착 UI · 작명 미리보기 · 그룹 편집.
- **상품담보 값 화면의 「마스터와 다른 필드 N」** — 2026-09-14 결정은 헤더 카운트(지금 마스터 값과 다른 명시 값의 수) + 목록에서 골라 가져오기였고, 와이어프레임 §20.3 검토안(2026-09-16)은 헤더 카운트를 뺐다. 어느 쪽으로 갈지. 마스터 값이 미입력인 자리에 가져오기 아이콘을 붙일지도(가져오면 스냅샷도 미입력이 된다).
