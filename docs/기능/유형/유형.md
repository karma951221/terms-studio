# 유형

> 상태: 초안 · 최종수정: 2026-09-27

## 1. 한 줄

**열거형변수**(목록값 타입이 고르는 값의 정의)를 관리하는 화면이다. 마스터 필드의 `목록값` · `목록값(복수)` 타입이 여기 정의를 가리키고, 값은 데이터라 **배포 없이** 편집자가 늘리고 고친다.
구분자는 「무엇을 묻나」, 유형은 「어떤 값으로 답하나」다.

## 3. 규칙

### 3.1 열거형변수와 값

- 열거형변수 = 코드 · 이름 · 값 목록. 값 = 코드 · 이름 · 순서.
- **코드는 자동 채번 · 불변** — 열거형변수 `E0001` 부터, 값은 그 열거형변수 안에서 `V01` 부터. 유저가 입력하지 않는다 (ADR-0005).
- 저장 · 식 · 값 행은 **값 코드**를 쓰고, 화면은 이름을 쓴다. 이름은 언제든 바꿔도 식 · 저장 값이 안 깨진다 (ADR-0005).
- 열거형변수 이름은 전체에서 중복 거부. 값 이름은 그 열거형변수 안에서 중복 거부 — 앞뒤 공백 · 연속 공백 · 대소문자를 무시하고 비교한다 (화면과 서버가 같은 규칙).
- **상세 저장은 최종 값 목록으로 한 번에 검사한다** — 값 이름 A↔B 맞바꾸기, 다른 값이 비우거나 빠지며 내놓는 이름 받기가 된다. 중복은 저장 뒤 목록에서 겹칠 때만이다. — 왜: 한 단계씩(개명 → 추가 → 삭제) 검사하면 최종 상태가 유효해도 중간 상태에서 「중복」으로 거부됐다 (점검 2026-09-27 H2 ①). 도메인 `reviseEnum`.
- 값 순서 = 값 폼 선택지의 표시 순서. 저장 값에 영향 없다.
- **값 추가는 자유** — 코드 배포 없이 즉시 선택지가 는다 (ADR-0037 §5). 값에 「사용중지」 상태는 없다 — 추가와 삭제뿐.
- 누가 쓰나 — 마스터 필드의 타입(`목록값 ▸ 열거형변수`)과 구분자의 명시 결과 타입. 마스터 필드는 코드라 그 참조는 배포로만 끊긴다 ([[기능/마스터/마스터]]).

### 3.2 삭제 — 관리자

| 삭제 | 누가 | 지금 코드의 결과 |
|---|---|---|
| 값 | **관리자** — 편집자 요청은 서버 거부 | 상세 편집에서 ✕ 로 빼고 **저장할 때** 영향(그 값을 고른 저장 값 수 · 깨질 참조, 빠진 값 전부를 합쳐서) 확인 뒤 삭제 — **그 값을 고른 값 행도 함께 지운다** |
| 열거형변수 | **관리자** — 편집자 요청은 서버 거부 | 영향(값 전부 · 이 타입을 쓰는 마스터 필드 좌표 · 값 행 수) 확인 뒤 삭제 — **그 필드들의 값 행도 지운다** |

- 값 삭제가 목록값(복수) 자리에 닿으면 배열에서 그 원소만 빼고, **그래서 빈 배열이 된 행만** 지운다(미입력). 원래부터 빈 배열이던 행(명시적 「(선택 없음)」)은 그 값을 고른 적이 없으니 건드리지 않는다 — 확인창의 「그 값을 고른 저장 값 수」와 실제로 지우는 행이 같다 (점검 2026-09-27 M17).
- 두 단계 확인 — 관리자 첫 요청은 영향 목록을 돌려주고, 확인해야 실행한다 ([[공통/화면/결정/ADR-0019-모드폐지-역할권한]]).
- 기획 규칙(〔D-P1-17〕 마스터 필드가 쓰는 열거형변수는 삭제 거부 · 〔D-P1-18〕 지운 값을 고른 저장 값은 오류 상태로 남김)과 코드가 다르다 — §5 미결.

## 4. 화면

좌측 내비 「기준 데이터」 그룹의 둘째 항목 「유형」. 하위 탭은 열거형변수 하나뿐이라 탭 줄 없이 제목만 선다. `/types` 는 `/types/enums` 로 보낸다.

### 4.1 `/types/enums` — 조회 (L1)

```
유형                                                              〔+〕
🔍[ 코드 · 열거형변수 이름 · 값 ]              기준일 2026-09-27 🔒 미확정 포함 꺼짐 🔒
┌───────┬──────────────┬────────────────────────────────┬───────┬────────────┬──────┐
│ 코드   │ 열거형변수 이름 │ 값                              │사용처 ▾│ 최종수정    │ 수정자│
├───────┼──────────────┼────────────────────────────────┼───────┼────────────┼──────┤
│ E0001 │ 납입면제사유   │ (사망)(장해)(암진단)(뇌졸중)(급성심근경색) +2 │ 1     │ 2026-09-12 │ admin│
│ 총 N건                                                              ‹ › │
└──────────────────────────────────────────────────────────────────────────┘
```

| 자리 | 내용 |
|---|---|
| 제목 줄 | 「유형」 + `+`(새 열거형변수). 검색어가 있으면 생성 화면 이름 칸에 넘긴다(`?q=`) |
| 검색 | 코드 · 이름 · **값 이름**까지 부분 일치 — 「간편심사」를 치면 그 열거형변수가 나온다. 디바운스 300ms · `?q=` |
| 기준일 · 미확정 포함 | 자리만 있고 잠김 (이력은 MVP 이후) |
| 컬럼 | 코드 · 열거형변수 이름(→ 상세) · 값(순서대로 칩 앞 5개 + 「+N」, 전체는 툴팁) · 사용처(머리글 필터 있음 · 없음 — 이 열거형변수를 타입으로 쓰는 마스터 필드 수, 0 이면 「—」) · 최종수정 · 수정자 |
| 페이저 | 50행 · `?page=` |

| 상태 | 표시 |
|---|---|
| 0건 | EmptyState — 「열거형변수는 목록값 타입이 고르는 값의 정의다.」 + 예시(심사유형: 일반심사 · 간편심사) + 「새 열거형변수」 |
| 필터 결과 0 | 「이 조건에 맞는 열거형변수가 없습니다.」 |

### 4.2 `/types/enums/new` — 생성

제목 줄은 경로 `유형 › 새 열거형변수`, 제출(「생성」)은 헤더 오른쪽. 생성하면 상세로 간다.

| 칸 | 입력 |
|---|---|
| 열거형변수 이름 | 텍스트 · 필수. 목록 검색어가 넘어오면 프리필 + 「제안」 배지 |
| 값 | 값 표 — 순서 · 값 이름(표 안에서 바로 적는다) · 위 · 아래 · 빼기. 표 머리 「+」 가 빈 행을 넣는다. 처음부터 빈 행 둘 |

- 값 칸에서 Enter — 다음 행으로, 마지막 행이면 새 행 (한글 조합 중에는 무시).
- **중복 값**은 행에 「중복된 값입니다.」 + 브라우저 검증으로 「생성」을 막는다.
- 빈 행은 지금 `required` 로 막힌다 — 쓰지 않을 빈 행은 「빼기」로 지워야 생성된다 (§5 미결).

### 4.3 `/types/enums/<code>` — 상세 · 수정

제목 줄은 경로 `유형 › {이름}`, 코드는 옆의 메타(mono) ([[공통/화면/디자인원칙]] §1.7). 읽기 모드로 시작하고 「편집」 → 「저장」 하나로 이름 · 값 이름 · 순서 · 새 값 · 값 빼기를 함께 반영한다 — 한 트랜잭션이라 거부되면 아무것도 남지 않는다.

| 칸 | 읽기 | 편집 |
|---|---|---|
| 열거형변수 이름 | 잠긴 칸 | 입력 |
| 값 표 | 순서 · 값 이름 · 사용 수(식 · 조건식이 그 값을 비교하는 곳의 수, 0 이면 「—」) | + 조작 열: 위 · 아래 · ✕(저장된 값은 「빼기 — 저장할 때 삭제」, 새 값은 「추가 취소」). 머리 「+」 가 빈 행을 넣는다 |

| 모드 | 헤더 오른쪽 |
|---|---|
| 읽기 | 「사용처 N」(이 열거형변수를 타입으로 쓰는 마스터 필드, 0 이면 「아무 구분자 · 필드도 이 열거형변수를 타입으로 쓰지 않는다.」) · 「편집」 · 🗑 |
| 편집 | ✕ · 「저장」 · 🗑(비활성, tooltip 「저장하거나 취소한 뒤 실행」) |

| 조작 | 결과 |
|---|---|
| 「+」 · 마지막 행에서 Enter | 빈 행 추가 + 포커스. **빈 채로 남은 새 행은 저장 때 버린다** |
| 위 · 아래 | 순서 바꿈 — 저장 때 반영 |
| ✕ | 그 행만 표에서 뺀다 — 편집 중 변경이라 확인이 없고 ✕(편집 취소)로 되돌아간다. 저장된 값은 저장할 때 삭제된다 |
| 저장 | 이름 · 최종 값 목록(새 값은 발급 코드로 제출 순서 유지)을 **한 트랜잭션**에 반영한다. 뺀 저장된 값이 있으면 먼저 확인 대화상자 — 「값을 빼면 저장된 값이 사라질 수 있다」 · 사라질 값 행 · 깨질 참조(빠진 값 전부 합계) · 「값 N개 삭제하고 저장」. 편집자는 서버 거부. 거부 · 대화상자 취소면 아무것도 저장되지 않고 편집 유지 + 사유 |
| 🗑 (읽기에서만) | 열거형변수 삭제 — 관리자 · 영향 확인 뒤 목록으로. 편집 중에는 꺼진다 — 즉시 실행 명령이라서 (디자인원칙 §2 L2) |

| 상태 | 표시 |
|---|---|
| 없는 코드 | 경로 `유형 › <코드>` + 「찾을 수 없습니다.」 |

## 5. 미결

- **삭제 규칙이 기획과 코드에서 갈린다.** 기획(구분자_액션 〔D-P1-17〕 · 〔D-P1-18〕 · ADR-0049 §2 표)은 「마스터 필드가 타입으로 쓰는 열거형변수는 삭제 거부」 · 「지운 값을 고른 저장 값은 연쇄 삭제하지 않고 오류 상태로」인데, 코드는 관리자 확인 뒤 **삭제를 허용하고 해당 값 행을 지운다**. 어느 쪽을 정본으로 할지 결정 필요 — 결정되면 ADR.
- **생성 화면의 빈 행** — [[공통/화면/디자인원칙]] §2 L2 는 「빈 행은 제출 때 버린다」인데 생성 값 표는 빈 행을 `required` 로 막는다(상세는 버린다). **미구현**.
- 값 「사용중지」 상태 — 삭제 거부가 잦으면 재검토 (MVP 는 추가 · 삭제뿐).
- 유저 정의 폼(폼 하위 탭 · 필드 편집기 · 선택 필드)은 MVP 이후 — 입력 항목은 코드 마스터다 ([[기능/마스터/결정/ADR-0037-입력항목-코드마스터-유저정의폼-MVP이후]]).
