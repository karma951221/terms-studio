# ADR-0021 — 기본계약 수(0 / 1 / 2+)가 보통약관 구조를 정한다 · 조연결 = 대치

> 상태: 채택 · 날짜: 2026-09-06 · 구현: 대치 형태(결정 1 의 주계약 기본계약 1개 · 결정 3 · 5 의 수동 준용규정과 최소형 · 결정 6) — `src/domain/assembly/base.ts` · `booklet.ts` · `application.ts`. **미구현**: 절 형태(결정 1 · 2 · 4), 결정 1 의 `noBlock`, 결정 3 의 잠금 · `linkTargetGone`, 결정 5 의 위치 호칭
>
> **개정됨** 결정 1 · 2 · 4 · 5 와 이유 · 버린 대안 C · D · 결과(결정 3 은 덧붙임) — 형태 = 계약형태 + 블록 수, 절 형태의 제1절은 템플릿 조별 판정, 준용규정 자동 생성 예약 해제 — [[기능/조립산출/결정/ADR-0082-제1절-자동판정-준용하기-독립특약]] (2026-10-07). 원본은 `_archive/2026-10-07_ADR-0021-절형태판정-원본/`.
> 제목의 「기본계약 수(0 / 1 / 2+)」는 옛 표현이다(번호 · 파일명 · 제목은 그대로 둔다) — 형태는 결정 1 대로 계약형태 + 블록 수가 정한다.
> 2026-09-14 개정 전 원본은 `_archive/2026-09-27_문서재편/06_결정/`.

## 맥락

「기본계약 문면이 보통약관 조가 되는 경로」([[00_시작/도메인모델]] §7)가 미결이었다. 실물 두 벌을 대조했다 —
알파Plus(기본계약 1개)는 기본계약 담보의 지급사유·세부규정이 보통약관 제3·4조로 일반조항 사이에
그대로 들어가 있고, 내Mom같은어린이보험 2604(기본계약 2개)는 보통약관이 제1절 일반조항 /
제2절 보장조항으로 갈리고 제2절에 기본계약별 블록(1-1·1-2, 각각 제1조부터 재시작)이 반복된다.
기본계약이 없는 상품(독립특약)도 같은 절 구조를 쓴다. 한 규칙으로는 둘을 표현할 수 없었다.

## 결정

1. **형태는 상품의 계약형태와 블록 수로 정한다.** 블록은 제2절에 실리는 보장 단위다 — 주계약이면 기본계약 상품담보들,
   독립특약이면 문면이 있는 탑재 상품담보 전부(담보의 특약 그룹 값은 보지 않는다).
   주계약: 기본계약 0 → 오류 `noBaseContract` · 1 → **대치 형태**(절 없음, 결정 3) · 2+ → **절 형태**.
   독립특약: 기본계약 지정 → 오류 `unsupported` · 블록 0 → 오류 `noBlock` · 1 이상 → 절 형태(블록 하나도 — 판정 없이 연결 조 위임, ADR-0082 결정 7).
   블록 수는 조건 해소 · 블록 빈 조 빼기 뒤에 센다(ADR-0082 결정 2). 상품모델링이 담보를 「기본계약 / 특별약관」 섹션으로 나눠 받으므로 수는 미리 안다.
2. **보통약관 마스터(템플릿)는 평평한 조 목록이다.** 절 구조(제1절 일반조항 / 제2절 보장조항)는 마스터에
   두지 않고 **조립이 형태에 따라 만든다.** 절 형태의 제1절은 최종 트리(템플릿 + 이 상품의 쓰이는 사본 · 노출 끔)에
   템플릿 조별 판정을 얹은 것이다 — 블록이 조연결하지 않은 조는 마스터 문구, 조연결한 조는 판정 결과([[기능/조립산출/결정/ADR-0082-제1절-자동판정-준용하기-독립특약]]).
   제2절은 블록을 블록 순서대로 싣는다(블록마다 제1조부터). 대치 형태는 절을 만들지 않는다.
   템플릿에 위임 문장 · 위임 조 표시를 두지 않는다 — 연결될 조도 마스터 문구를 쓴다(ADR-0082 결정 1).
3. **대치 형태의 대치는 조연결 자체다.** 기본계약 조가 조연결된 보통약관 조는 항상 그 기본계약 조로
   찍힌다. 토글·옵션 없음. 조연결 없는 기본계약 조는 안 찍히고 경고.
   대치 자리(기본계약 조가 조연결된 보통약관 조)는 상품이 조 사본을 만들 수 없다 — 잠금(ADR-0082 결정 10, 미구현).
   연결 대상 보통약관 조가 이 상품 최종 트리에 없으면(조건 · 노출 끔) 오류 `linkTargetGone` — 미구현(지금은 노출 끔만 `articleHidden` 오류이고, 조건으로 빠지면 그 기본계약 조가 조용히 빠진다).
4. **절 형태의 블록 조는 ADR-0082 판정 결과를 따른다** — 공통 · 전체항 합침이면 생략, 위임이면 블록마다 자기 조, 특칙이면 그대로,
   공통항 분리면 준용 문구 + 전용 항(ADR-0082 결정 6). 특칙 블록 조와 위임 블록 조(블록 하나 포함)는
   [[기능/조립산출/결정/ADR-0020-준용-항단위-자동판정]] 판정을 타지 않는다 — 위임 조는 제1절에 비교할 마스터가 없다.
   기본계약 2+ 상품의 **특약** 조는 ADR-0020 판정기로 실제로 찍힌 제1절과 비교되고, 위임된 조에 연결한 특약 조는 판정 없이 통째로 찍힌다. 절 형태에 대치는 없다.
5. **준용규정 조는 작성자가 담보 문면에 쓴 것이 정본이다** — 「항」 함수조항 「준용규정」 참조 + 제외 조 목록 항(보통약관 조 참조 슬롯).
   조립은 준용규정 조가 없는 담보 문면에만 최소형 한 조를 끝에 붙인다(`application.ts`). 절 형태에서는 그 문서 전체 참조를 위치 호칭으로 찍는다
   — 블록 「제1절 일반조항」 · 기본계약 2+ 의 특약 「보통약관 제1절 일반조항」(미구현).
   자동 생성 여부는 후속 기획으로 보류한다 — 절 형태 구현에 묶지 않고 전환을 예약하지 않는다([[기능/조립산출/조립산출]] §5).
6. issues 에 severity(error / warning)를 둔다. warning 은 `complete` 를 깨지 않는다.

## 이유

- 마스터에 절 구조나 모드를 명시하면 상품과 어긋나는 경우가 생기고 그때마다 오류 규칙이 필요하다.
  상품이 이미 아는 사실(계약형태 · 기본계약 · 탑재 상품담보 수)로 구조를 유도하면 어긋날 것이 없다.
- 「대치 토글」은 처음 후보였으나, 조연결이 있는데 대치하지 않을 이유가 실물에 없었다. 토글은
  켜고 끄는 사람의 실수만 늘린다. 조연결 = 대치로 단순화했다.
- 블록 모델은 출력 위치가 다른 담보약관이라 블록용 문면을 따로 쓰지 않는다. 다만 제1절의 연결 조 내용은
  블록끼리의 판정이 정한다 — 그 규칙은 ADR-0082. 블록이 갖지 않는 조(지급하지 않는 사유 등)는 연결이 없어 제1절 마스터로 남는다(실물과 같다).

## 버린 대안

- **A. 보통약관 조에 「기본계약 조로 대치」 토글** — 기각: 위 이유. 켜져 있는데 연결이 없거나
  꺼져 있는데 연결이 있는 상태를 전부 다뤄야 한다.
- **B. 마스터에 「기본계약 조 삽입 자리」 + 판정** — 기본계약 조를 자리에 순서대로 넣고 동일 조만
  생략. 기각: 위치가 자리 하나로 고정돼 알파Plus 처럼 조가 흩어진 실물을 못 담고, 블록 모델과
  섞여 두 메커니즘이 된다.
- **C. 마스터에 절 구조·블록 자리 노드를 명시** — 기각: 모드-마스터 불일치 오류 3종이 생기고
  마스터 작성자가 모드를 알아야 한다. 템플릿에 위임 조 표시 · 위임 문장을 두는 안도 같은 이유로 버렸다 — ADR-0082 버린 대안.
- **D. 준용규정 조를 문면이 쓰되 식 언어에 「출력 위치」 내장 경로 추가** — 기각: 작성자가 모드를
  신경 써야 하고 식 언어에 문맥 종류가 하나 더 들어간다. (출력 위치가 대치 · 블록 · 특약으로 여럿이 됐다 — 작성_위치 재검토는 [[기능/조립산출/조립산출]] §5 보류.)

## 결과와 감수하는 비용

- 상품모델링 화면이 「기본계약 / 특별약관」 두 섹션으로 갈린다 ([[기능/상품/상품]]).
- 같은 템플릿이 상품의 계약형태와 블록 구성(탑재 · 조연결 · 조건 해소 결과)에 따라 다르게 조립된다.
  템플릿 저작자는 위임 문장을 쓰지 않는다 — 연결될 조도 마스터 문구를 쓰고(연결 0 · 일부 연결일 때 찍힌다) 위임 문구는 시스템이 만든다.
  독립특약 템플릿은 한 벌이고 주계약 템플릿과 겸용하지 않는다(ADR-0082 결정 13).
- 절 형태는 2026-10-07 기획 확정(ADR-0082) · 미구현이다 — 지금 코드는 대치 형태만 조립하고 기본계약 2+ 는 `unsupported`,
  독립특약은 기본계약 없이 템플릿 + 사본을 그대로 찍는다. 파이프라인은 단수로 하드코딩하지 않는다.
- 준용규정 조가 담보 문면마다 산다(정본). 자동 생성은 후속 기획으로 보류 — 전환을 예약하지 않는다.
- 조 번호가 블록 안에서 재시작하므로 조 좌표에 블록 이름공간이 필요하다 → 오류 좌표 체계
  ([[기능/조립산출/조립산출]] — `Coordinate.section`) — 표시는 「제1절」 / 「제2절 1.」(미구현).
