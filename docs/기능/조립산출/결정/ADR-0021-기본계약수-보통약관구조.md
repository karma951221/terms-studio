# ADR-0021 — 기본계약 수(0 / 1 / 2+)가 보통약관 구조를 정한다 · 조연결 = 대치

> 상태: 채택 · 날짜: 2026-09-06
>
> 개정 반영: 2026-09-14 (결정 5) — 원본은 _archive/2026-09-27_문서재편/06_결정/
> 결정 5(준용규정 조는 조립이 붙인다 · 문면에 쓰지 않는다)는 MVP 동안 「수동 문면이 정본 · 조립은 생성하지 않음」이 됐다. 자동 생성은 0 · 2+ 모드 구현 때로 유예 — [[기능/조립산출/조립산출]] §3.5 준용 · 생략 판정 · §6.2.

## 맥락

「기본계약 문면이 보통약관 조가 되는 경로」([[00_시작/도메인모델]] §7)가 미결이었다. 실물 두 벌을 대조했다 —
알파Plus(기본계약 1개)는 기본계약 담보의 지급사유·세부규정이 보통약관 제3·4조로 일반조항 사이에
그대로 들어가 있고, 내Mom같은어린이보험 2604(기본계약 2개)는 보통약관이 제1절 일반조항 /
제2절 보장조항으로 갈리고 제2절에 기본계약별 블록(1-1·1-2, 각각 제1조부터 재시작)이 반복된다.
기본계약이 없는 상품(독립특약)도 같은 절 구조를 쓴다. 한 규칙으로는 둘을 표현할 수 없었다.

## 결정

1. **모드는 상품의 기본계약 수로 정한다** — 상품모델링이 담보를 「기본계약 / 특별약관」 섹션으로
   나눠 받으므로 수는 미리 안다. 0 = 독립특약, 1 = 주계약(대치), 2+ = 주계약(블록).
2. **보통약관 마스터는 평평한 조 목록이다.** 절 구조(제1절 일반조항 / 제2절 보장조항)는 마스터에
   두지 않고 **조립이 모드에 따라 만든다.** 0·2+ 모드는 마스터 조 목록을 제1절로, 담보(0) 또는
   기본계약(2+) 블록을 제2절로 자동 생성한다. 1 모드는 절을 만들지 않는다.
3. **1 모드의 대치는 조연결 자체다.** 기본계약 조가 조연결된 보통약관 조는 항상 그 기본계약 조로
   찍힌다. 토글·옵션 없음. 조연결 없는 기본계약 조는 안 찍히고 경고.
4. **블록 안 조와 특약 조는 같은 판정기**([[기능/조립산출/결정/ADR-0020-준용-항단위-자동판정]])로 제1절 일반조항과
   비교된다. 0·2+ 모드에 대치는 없다.
5. **준용규정 조는 MVP 동안 작성자가 담보 문면에 쓴다** — block 공용조항 「준용규정」 참조 + 제외 조 목록 항(보통약관 조 참조 슬롯).
   조립은 준용규정을 생성하지 않는다(소유자는 문면 하나). 출력 위치(특약 / 블록)에 따라 문구가 달라지는 자동 생성은
   0·2+ 모드 구현 때 옮기고, 그때 수동 문면을 걷어내는 전환을 한 번에 한다 ([[기능/조립산출/조립산출]] §3.5).
6. issues 에 severity(error / warning)를 둔다. warning 은 `complete` 를 깨지 않는다.

## 이유

- 마스터에 절 구조나 모드를 명시하면 상품과 어긋나는 경우가 생기고 그때마다 오류 규칙이 필요하다.
  상품이 이미 아는 사실(기본계약 수)로 구조를 유도하면 어긋날 것이 없다.
- 「대치 토글」은 처음 후보였으나, 조연결이 있는데 대치하지 않을 이유가 실물에 없었다. 토글은
  켜고 끄는 사람의 실수만 늘린다. 조연결 = 대치로 단순화했다.
- 블록 모델은 「출력 위치만 다른 특약」이라 새 판정 규칙이 생기지 않는다. 실물의 블록이 제1절과
  같은 조(지급하지 않는 사유)를 안 갖는 것이 생략 판정의 결과와 일치한다.

## 버린 대안

- **A. 보통약관 조에 「기본계약 조로 대치」 토글** — 기각: 위 이유. 켜져 있는데 연결이 없거나
  꺼져 있는데 연결이 있는 상태를 전부 다뤄야 한다.
- **B. 마스터에 「기본계약 조 삽입 자리」 + 판정** — 기본계약 조를 자리에 순서대로 넣고 동일 조만
  생략. 기각: 위치가 자리 하나로 고정돼 알파Plus 처럼 조가 흩어진 실물을 못 담고, 블록 모델과
  섞여 두 메커니즘이 된다.
- **C. 마스터에 절 구조·블록 자리 노드를 명시** — 기각: 모드-마스터 불일치 오류 3종이 생기고
  마스터 작성자가 모드를 알아야 한다.
- **D. 준용규정 조를 문면이 쓰되 식 언어에 「출력 위치」 내장 경로 추가** — 기각: 작성자가 모드를
  신경 써야 하고 식 언어에 문맥 종류가 하나 더 들어간다. (MVP 의 수동 문면은 1 모드뿐이라 출력 위치가 하나 — 이 문제가 없다.)

## 결과와 감수하는 비용

- 상품모델링 화면이 「기본계약 / 특별약관」 두 섹션으로 갈린다 ([[기능/상품/상품]]).
- 같은 마스터가 상품의 기본계약 수에 따라 다르게 조립된다 — 마스터는 모드를 염두에 두고 작성한다
  (예: 0/2+ 용 제3조는 「제2절 보장조항에서 정합니다」). 이는 마스터가 여러 벌이고 상품이 고르는
  기존 모델로 흡수된다.
- MVP 구현은 1 모드만이다 ([[00_시작/범위]]). 0·2+ 는 기획 확정·구현 유예. 단 파이프라인은 단수로
  하드코딩하지 않는다.
- 준용규정 조가 담보 문면마다 산다 — 자동 생성으로 옮기는 날 한 번에 걷어내는 전환 작업을 빚진다.
- 조 번호가 블록 안에서 재시작하므로 조 좌표에 블록 이름공간이 필요하다 → 오류 좌표 체계
  ([[기능/조립산출/조립산출]] — `Coordinate.section`).
