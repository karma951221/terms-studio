# ADR-0016 — 조립 오류: 실행 경로 탐지 · 부분 조립 + 오류 좌표

> 상태: 채택 · 날짜: 2026-08-31

## 맥락

조립이 만나는 오류(미입력 값 참조 · 미사용 담보속성 참조 · 분기로 사라진 조를 가리키는
조 참조)를 언제 탐지하고 어떻게 보여줄지가 P6 기획의 첫 쟁점이었다.
「아무도 확인 안 한 값으로 약관이 조립되지 않는다」([[공통/기술/결정/ADR-0004-null없음-미입력상태]])와
「조용히 틀린 문서가 나가는 경로를 남기지 않는다」([[기능/문면/문면]] 참조 무결성)를
지키면서, 미입력이 수십 건인 초기 모델링 단계에서도 미리보기가 쓸모 있어야 한다.

## 결정

1. **조립은 구체 문맥의 실행이다.** 특정 상품의 실제 값(상품 구분자 · 스냅샷 · 담보속성)으로
   문서트리를 만들며, **오류는 실행이 실제로 밟은 자리에서만 탐지한다.**
   조건에 걸려 밟지 않은 분기 안쪽은 평가하지 않는다 — 거기 있는 미입력·깨질 수 있는
   참조는 이 상품의 오류가 아니다.
2. **가능한 분기 조합 전체에 대한 정적 검사는 만들지 않는다.** 「어떤 분기를 타면 참조가
   깨질 수 있음」류의 경고는 전상품이 그 분기를 피해 가는 정상 상태까지 오류로 만들어
   사용자를 괴롭힌다.
3. **부분 조립** — 오류를 만나도 중단하지 않고 그 자리에 **오류 마커 노드**를 심고
   끝까지 조립한다.
4. 결과는 미리보기(본문에 마커) + **오류 목록 패널**: 항목마다 좌표(상품담보 → 조 → 위치)와
   원인을 담고, 클릭하면 해당 위치로 이동한다. 오류가 1건이라도 있으면 결과물에
   **「완성본 아님」** 을 명시한다.

## 이유

- **수정 사이클이 짧다.** 오류 전부를 한 번의 조립으로 모아 보므로,
  고치고 → 재조립 → 다음 오류 식의 순차 발견이 없다.
- 초기 모델링(미입력 다수) 단계에서도 문서의 전체 모양을 볼 수 있다.
- 원칙 훼손이 없다 — 오류 있는 결과물은 「완성본 아님」으로 명시되므로
  확인 안 된 값이 완성본으로 나가는 경로는 여전히 없다.

## 버린 대안

- **A. 오류 시 조립 중단** — 엄격하지만 초기 단계에 미리보기를 전혀 못 보고,
  오류를 하나씩만 발견한다.
- **B. 가능세계 정적 검사** (모든 분기 조합 lint) — 이론상 안전하나, 실제로는 도달하지 않는
  조합의 경고가 쏟아져 신호가 죽는다. 사용자 부담 판단으로 기각 (2026-08-31).

## 결과와 감수하는 비용

- 어떤 상품도 밟지 않은 분기의 결함은 **그 분기를 밟는 상품이 처음 생길 때까지 잠복**한다 —
  정적 검사를 버린 대가다. 상품담보 미리보기·전체 뷰([[기능/문면/문면]])가 편집 시점의
  눈 검증으로 보완한다.
- 오류 마커가 문서트리의 노드 종류로 하나 늘고, 좌표(노드 경로) 체계가 조립기의
  공식 출력이 된다 — 관계정보 뷰·완결성 조회와 좌표 표현을 공유해야 한다.
