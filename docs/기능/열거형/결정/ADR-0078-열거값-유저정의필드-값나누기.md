# ADR-0078 — 열거값에 유저 정의 필드 · 면책은 값을 나눠 표현 · 값 추가는 재검사 · 값 삭제는 「없는 값」 오류

## 맥락

2026-09-28 ~ 09-30 납입면제 기획. 납입면제사유는 열거형 E0001 이고, 세목 `waiver` 선택지(납입면제종)가 사유 묶음(`waiver.reasons`, 목록값(복수))을 고른다.
사유마다 문장이 달라지는 것은 역할 함수조항의 switch 로 풀었지만([[기능/함수조항/결정/ADR-0076-공용조항-함수조항-일원화-인자연결]]), 사유에 딸린 **사실**이 셋 남았다.

- **약관표시명** — 호 · 정의 조 제목에 찍히는 이름(「암(유사암제외)」). 관리 이름(「암(유사암제외)·면책」)과 다를 수 있다.
- **면책 여부** — 암은 면책기간(암보장개시일)이 있는 상품과 없는 상품(무면책)이 있다. 면책이면 면제 부가항 · 세부규정 ①~③ · 무효 · 부활의 암보장개시일 문구가 따라온다.
- **정의 조 대상** — 질병 진단 사유는 「…의 정의 및 진단확정」 조에 정의가 실리고, 후유장해 사유는 실리지 않는다.

한때 면책을 「상품 × 사유」 값(열거값에 기본값, 상품이 사유마다 스냅샷으로 조정)으로 두었다. 그러면 상품모델링에 사유마다 한 줄인 표가 생기고, 한 상품 안에서 종마다 면책이 다르면 표현할 수 없으며, 같은 값을 두 곳(열거값 · 상품)이 들고 있게 된다.

열거값 삭제도 정본이 갈려 있었다 — 기획(ADR-0049 · 〔D-P1-18〕)은 「지운 값을 고른 저장 값은 오류 상태로 남김」, 코드는 관리자 확인 뒤 값 행을 지웠다.

## 결정

1. **면책은 값을 나눠 표현한다** — 「암(유사암제외)·면책」 · 「암(유사암제외)·무면책」은 서로 다른 E0001 값이다. 후유장해도 상해및질병80%(호 2개) · 상해80% · 질병80% … 처럼 값으로 가른다. **한 값이 호 여러 개를 낼 수 있다**(상해및질병 = 상해 호 + 질병 호).
2. **열거형 값에 유저 정의 필드를 둔다** — 열거형마다 필드(이름 · 타입)를 선언하고 값마다 채운다. 타입은 우선 **문자열 · 참거짓** 둘. 빈 칸 = 미입력(읽으면 조립 오류 `notEntered`).
   - 필드는 열거형 정의의 일부라 **참조로 전 상품에 전파**된다 — 상품이 필드 값을 조정하는 길은 없다.
   - 필드 삭제 · 타입 변경 → 그 필드를 읽는 곳(함수조항 슬롯 · 내부 변수 · IF · 반복 거르기) 재검사. 저장은 막지 않는다(ADR-0049).
   - 권한은 [[공통/화면/결정/ADR-0019-모드폐지-역할권한]] 기준 — 필드 추가 · 값 입력은 편집자, 필드 삭제 · 타입 변경은 관리자 + 영향 확인.
   - E0001 필드: **약관표시명**(문자열) · **면책여부**(참거짓) · **정의조대상**(참거짓).
   - **분류용 필드(암계열 · 장해계열 등)는 두지 않는다** — 실무 사례가 없다. 항 묶음은 함수조항 내부 변수의 값 나열(`사유들.있음(암 값들)`)로 가른다.
3. **세목 납입면제종은 E0001 값을 고르기만 한다** — 면책 · 표시명을 상품에서 바꾸지 않는다. 면책 상품은 「·면책」 값을, 무면책 상품은 「·무면책」 값을 고른다.
4. **열거값 추가 → 재검사 목록** — 그 열거형 값을 나열한 IF · 내부 변수(`.있음(값…)`) · 값 한정 참조와, 새 값이 미배정인 switch 를 재검사 목록에 올린다. 열거값 저장은 막지 않는다.
5. **열거값 삭제 → 「없는 값」 오류** — 지운 코드를 쓰던 자리(저장 값 · switch 칸 · IF · 내부 변수 · 값 한정)에 코드를 남기고 「없는 값」 오류로 둔다. 조용히 지우지 않는다 — ADR-0049 · 〔D-P1-18〕을 정본으로 삼는다.
6. **값 나누기 = 옛 값 개명 + 새 값 추가** — 「암(유사암제외)」을 면책 · 무면책으로 나누면 옛 값을 「·면책」으로 개명하고 「·무면책」을 새로 더한다. 삭제를 쓰지 않으므로 기존 선택 · 참조가 그대로 산다.

## 이유

- **값으로 나누면 한 곳에만 산다.** 면책은 그 값의 사실이라 값 이름 · 필드에 붙고, 상품은 값을 고르는 일만 한다. 종마다 다른 면책(한 종은 면책, 다른 종은 무면책)도 값 선택으로 그대로 된다.
- **필드는 사유에 딸린 사실을 문장 밖에 둔다.** 약관표시명이 필드면 호 · 제목 나열 · 정의가 같은 이름을 찍고, 이름을 고치면 전 상품에 퍼진다.
- **정의조대상이 필드여야 정의 조 원천이 선언이 된다.** 조립이 약관표시명으로 조용히 걸러 내면 무엇이 빠지는지 안 보인다([[기능/문면/결정/ADR-0077-블록반복-세목선택지-열거목록-반복참조]] 결정 10).
- **분류용 필드는 새 값을 강제로 분류하게 하지만 실무에 그런 사례가 없다.** 대신 값을 나열한 곳이 새 값을 놓치는 위험은 값 추가 재검사가 드러낸다.
- **「없는 값」이 조용한 삭제보다 안전하다.** 값 행을 지우면 상품의 선택이 사라져도 아무도 모르고, 조건이 말없이 거짓이 된다. 코드를 남기면 좌표가 있는 오류가 된다.
- **개명 + 추가는 참조를 살린다.** 옛 값을 지우고 둘을 새로 만들면 그 값을 고른 모든 상품 · 조항이 「없는 값」이 된다.

## 버린 대안

- **상품 × 사유 오버라이드(스냅샷)** — 상품모델링에 사유 표가 생기고, 종마다 다른 면책을 못 쓰며, 같은 사실을 두 곳이 든다.
- **열거값 속성 기본값 + 상품 조정** — 위와 같고, 기본값과 상품 값 중 어느 쪽이 산출을 정했는지가 안 보인다.
- **/master 코드 폼으로 사유 속성 정의** — 사유는 배포 없이 늘어야 하는 데이터다(ADR-0037 결정 5).
- **분류용 필드(암계열 · 장해계열 · 상해관련 · 고의제외대상)로 IF · 한정을 가름** — 실무 사례 없음. 값 나열 + 추가 재검사로 충분하다.
- **값 삭제 시 값 행 연쇄 삭제(옛 코드, 2026-09-30 걷음)** — 조용한 손실이다.

## 결과와 감수하는 비용

- **/enums 화면이 커진다** — 필드 정의와 값 × 필드 입력 표. 「편집 → 저장 하나」 원칙 안에서 그린다(와이어프레임 미정 — [[기능/열거형/열거형]] §5).
- **값 수가 는다** — 면책 · 무면책, 장해 조합마다 값이 생긴다. 값 순서 = 조문 순서라(ADR-0077) 순서를 바꾸면 산출이 바뀐다.
- **값을 나열한 함수조항은 값을 더할 때 사람이 고친다** — 재검사 목록이 알려 주지만 고치는 것은 작성자다.
