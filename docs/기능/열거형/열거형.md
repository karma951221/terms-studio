# 열거형

> 상태: 초안 · 최종수정: 2026-09-30

## 1. 한 줄

**열거형변수**(목록값 타입이 고르는 선택지 목록)를 관리하는 화면이다. 마스터 필드의 `목록값` · `목록값(복수)` 타입과 구분자의 명시 결과 타입이 여기 정의를 가리키고, 값은 데이터라 **배포 없이** 편집자가 늘리고 고친다.
구분자는 「무엇을 묻나」, 열거형변수는 「어떤 값으로 답하나」다. 화면 이름은 「열거형」, 다루는 실체의 이름은 「열거형변수」다.

## 3. 규칙

### 3.1 열거형변수와 값

- 열거형변수 = 코드 · 이름 · 값 목록. 값 = 코드 · 이름 · 순서.
- **코드는 자동 채번 · 불변** — 열거형변수 `E0001` 부터, 값은 그 열거형변수 안에서 `V01` 부터. 유저가 입력하지 않는다 (ADR-0005).
- 저장 · 식 · 값 행은 **값 코드**를 쓰고, 화면은 이름을 쓴다. 이름은 언제든 바꿔도 식 · 저장 값이 안 깨진다 (ADR-0005).
- 열거형변수 이름은 전체에서 중복 거부. 값 이름은 그 열거형변수 안에서 중복 거부 — 앞뒤 공백 · 연속 공백 · 대소문자를 무시하고 비교한다 (화면과 서버가 같은 규칙).
- **상세 저장은 최종 값 목록으로 한 번에 검사한다** — 값 이름 A↔B 맞바꾸기, 다른 값이 비우거나 빠지며 내놓는 이름 받기가 된다. 중복은 저장 뒤 목록에서 겹칠 때만이다. — 왜: 한 단계씩(개명 → 추가 → 삭제) 검사하면 최종 상태가 유효해도 중간 상태에서 「중복」으로 거부됐다 (점검 2026-09-27 H2 ①). 도메인 `reviseEnum`.
- 값 순서 = 값 폼 선택지의 표시 순서. 저장 값에 영향 없다.
  블록 반복 · switch 가 들어오면 값 순서가 **조문 순서**도 된다 — 사유 반복(호 · 정의 조)과 switch 칸이 열거형 순서를 따른다(**미구현**, [[기능/문면/결정/ADR-0077-블록반복-세목선택지-열거목록-반복참조]]). 순서를 바꾸면 산출이 바뀐다.
- **값의 유저 정의 필드** (2026-09-30) — 열거형마다 필드(이름 · 타입 — 우선 문자열 · 참거짓)를 선언하고 값마다 채운다. 필드 코드는 그 열거형 안에서 자동 채번(`F01` …) · 불변, 이름은 언제든 바꾼다(ADR-0005). 필드 이름은 그 열거형 안에서 중복 거부(값 이름과 같은 비교). 빈 칸 = 미입력 — 저장 값에 키를 두지 않는다(읽으면 조립 `notEntered`). 참조라 전 상품에 전파되고 상품이 조정하는 길은 없다. 필드 추가 · 이름 · 값 입력은 편집자, 필드 삭제 · 타입 변경은 관리자 + 영향 확인([[공통/화면/결정/ADR-0019-모드폐지-역할권한]]) — 확인창은 필드마다 「값 N개의 입력이 지워진다」와 그 필드를 읽는 곳(깨질 참조)을 보인다. 타입을 바꾸면 옛 타입 값은 버린다. 저장은 막지 않고 읽는 곳을 재검사한다 — 읽는 곳은 함수조항 식의 필드 읽기(`arg.사유.F01` · `.거르기(F01 = …)` — 조건 · 슬롯 · 내부 변수, 2026-09-30 구현): 확인창의 깨질 참조로 서고, 저장 뒤 「재검사 N건」 목록에 오른다.
  E0001 납입면제사유의 필드: **약관표시명** · **면책여부** · **정의조대상**. 분류용 필드(암계열 · 장해계열)는 두지 않는다 — 실무 사례가 없다 ([[기능/열거형/결정/ADR-0078-열거값-유저정의필드-값나누기]]).
  — 왜: 사유에 딸린 사실(표시명 · 면책 · 정의 조 대상)을 문장 밖 한 곳에 두면 호 · 제목 · 정의가 같은 값을 읽고, 고치면 전 상품에 퍼진다.
- **값 나누기 = 옛 값 개명 + 새 값 추가** (2026-09-30) — 면책처럼 한 사유의 변형은 값을 나눠 표현한다(「암(유사암제외)·면책」 · 「·무면책」). 나눌 때 옛 값을 개명하고 새 값을 더한다 — 삭제를 쓰지 않아 기존 선택 · 참조가 산다. 한 값이 호 여러 개를 낼 수 있다(상해및질병80% = 상해 호 + 질병 호).
- **값 추가는 자유** — 코드 배포 없이 즉시 선택지가 는다 (ADR-0037 §5). 값에 「사용중지」 상태는 없다 — 추가와 삭제뿐.
- 누가 쓰나 — 마스터 필드의 타입(`목록값 ▸ 열거형변수`)과 구분자의 명시 결과 타입. 마스터 필드는 코드라 그 참조는 배포로만 끊긴다 ([[기능/마스터/마스터]] §3.1).
- 폼과 달리 **열거형변수는 데이터**다 — 그래서 기본정보 셋 가운데 폼만 읽기 전용이고 열거형은 만들고 고치고 지운다.

### 3.2 삭제 — 관리자

| 삭제 | 누가 | 지금 코드의 결과 |
|---|---|---|
| 값 | **관리자** — 편집자 요청은 서버 거부 | 상세 편집에서 ✕ 로 빼고 **저장할 때** 영향(그 값을 고른 저장 값 수 · 깨질 참조, 빠진 값 전부를 합쳐서) 확인 뒤 삭제 — **그 값을 고른 값 행은 코드를 남긴 채 「없는 값」 오류가 된다** |
| 열거형변수 | **관리자** — 편집자 요청은 서버 거부 | 영향(값 전부 · 이 타입을 쓰는 마스터 필드 좌표 · 값 행 수) 확인 뒤 삭제 — **그 필드들의 값 행도 지운다** |

- 두 단계 확인 — 관리자 첫 요청은 영향 목록을 돌려주고, 확인해야 실행한다 ([[공통/화면/결정/ADR-0019-모드폐지-역할권한]]).
- **값 삭제는 「없는 값」 오류다** (2026-09-30, [[기능/열거형/결정/ADR-0078-열거값-유저정의필드-값나누기]] 결정 5) — 값 행을 지우지 않는다. 지운 코드는 저장 값(목록값 · 목록값(복수)의 원소)에 그대로 남고, 읽는 곳마다 「없는 값 V03 — {열거형변수}(E0001)에서 지워진 값입니다」 오류가 된다(ADR-0049 · 〔D-P1-18〕).
  - 값 폼(상품 기본정보 · 세목 · 담보 값 카드) — 읽기 · 편집 모두 **「없는 값 V03」 오류 칩**. 목록값(복수)은 칩의 빼기로 지우고, 목록값은 다른 값을 고르면 풀린다. 다른 체크를 켜고 꺼도 칩은 남는다 — 빼기로만 지운다. 고치지 않고 저장하면 그 항목에 같은 오류로 막힌다.
  - 조립 — 그 자리를 읽는 조건식 · 슬롯 · 집계가 `brokenRef` 오류. 원천 좌표 = 그 값을 고친 곳(상품 · 세목 선택지 · 상품담보 노드의 값 자리).
  - 확인창은 「값을 빼면 그 값을 고른 자리가 「없는 값」 오류가 된다」 · 「그 값을 고른 저장 값 N건이 「없는 값」 오류로 남는다」.
  - 그 값을 비교하는 조건식 · 구분자 식은 깨진 참조로 남는다(사용처 · 관계정보). 함수조항 내부 변수 · 인자 비교(`.있음('V01')` · `arg.사유 = 'V01'`)도 같다(2026-09-30 구현). switch 칸 · 값 한정 참조는 그 기능이 들어올 때 같은 규칙을 따른다(미구현).
  — 왜: 조용히 지우면 상품의 선택이 사라져도 아무도 모르고 조건이 말없이 거짓이 된다.
- 〔D-P1-17〕 마스터 필드가 쓰는 열거형변수는 삭제 거부 — 코드는 관리자 확인 뒤 허용한다. §5 미결.

### 3.3 값 추가 — 재검사 (2026-09-30)

- 값을 더해 저장하면 그 열거형의 값 코드와 비교하는(`= 'V02'`) **조건식 · 슬롯 · 구분자 식**을 **재검사 목록**으로 보인다 — 상세 화면 편집 본문 아래 「재검사 N건」(형태 · 좌표 · 고치러 가기 링크). 한 자리가 값을 여럿 비교해도 한 줄. 값 저장은 막지 않는다 (ADR-0078 결정 4). 목록이 비면 아무것도 보이지 않는다.
- 구분자 식이 마스터 필드를 직접 비교하는 것(`feature.review_type = 'V01'`)도 그 값의 사용처다 — 참조 그래프가 값 간선을 낸다(값 삭제 영향에도 든다).
- 함수조항 내부 변수(`.있음(값…)` · `= '값'`)와 인자 비교(`arg.사유 = 'V02'`)도 같은 목록에 오른다(형태 「내부 변수」 · 「조건식」, 2026-09-30 구현). 값 한정 참조 · 새 값이 미배정인 switch 는 그 기능이 들어올 때 오른다(**미구현**).
- 필드를 빼거나 타입을 바꿔 저장하면(관리자 확인 뒤) 그 필드를 읽는 함수조항 식(`.필드` · `.거르기(필드 = …)`)도 같은 「재검사 N건」 목록에 오른다 (ADR-0078 결정 2, 2026-09-30 구현). 미배정 값이 실제 조립에서 switch 에 닿을 때만 조립 오류다 ([[기능/함수조항/함수조항]] §3.7).
  — 왜: 값을 나열한 곳은 새 값을 조용히 놓친다. 분류 필드로 막는 대신 드러내는 쪽을 택했다.

### 4.2 `/enums/new` — 생성

제목 줄은 경로 `열거형 › 새 열거형변수`(「열거형」 → `/enums`), 제출(「생성」)은 헤더 오른쪽. 생성하면 상세로 간다.

| 칸 | 입력 |
|---|---|
| 열거형변수 이름 | 텍스트 · 필수. 목록 검색어가 넘어오면 프리필 + 「제안」 배지 |
| 값 | 값 표 — 순서 · 값 이름(표 안에서 바로 적는다) · 위 · 아래 · 빼기. 표 머리 「+」 가 빈 행을 넣는다. 처음부터 빈 행 둘 |

- 값 칸에서 Enter — 다음 행으로, 마지막 행이면 새 행 (한글 조합 중에는 무시).
- **중복 값**은 행에 「중복된 값입니다.」 + 브라우저 검증으로 「생성」을 막는다.
- 빈 행은 지금 `required` 로 막힌다 — 쓰지 않을 빈 행은 「빼기」로 지워야 생성된다 (§5 미결).

### 4.3 `/enums/<code>` — 상세 · 수정

제목 줄은 경로 `열거형 › {이름}`(「열거형」 → `/enums`), 코드는 옆의 메타(mono) ([[공통/화면/디자인원칙]] §1.7). 읽기 모드로 시작하고 「편집」 → 「저장」 하나로 이름 · 필드 · 값 이름 · 순서 · 새 값 · 값 빼기 · 필드 칸을 함께 반영한다 — 한 트랜잭션이라 거부되면 아무것도 남지 않는다.

| 칸 | 읽기 | 편집 |
|---|---|---|
| 열거형변수 이름 | 잠긴 칸 | 입력 |
| 필드 표 (이름 칸 아래, 제목 「필드」) | 순서 · 필드 이름 · 타입(문자열 · 참거짓). 필드가 없으면 「필드가 없다 — …」 한 줄 | 이름 입력 · 타입 고르기 + 조작 열: 위 · 아래 · ✕(저장된 필드는 「빼기 — 저장할 때 삭제」). 머리 「+」(필드 추가)가 빈 행을 넣는다. 빈 채로 남은 새 필드 행은 저장 때 버린다. 필드를 빼거나 타입을 바꾸면 값 표의 그 열 입력도 초안에서 비운다 |
| 값 표 | 순서 · 값 이름 · **필드마다 한 열**(문자열은 글, 참거짓은 예 · 아니오, 빈 칸은 「—」) · 사용 수(식 · 조건식이 그 값을 비교하는 곳의 수, 0 이면 「—」) | 필드 칸 — 문자열은 입력칸, 참거짓은 미입력 · 예 · 아니오 고르기. + 조작 열: 위 · 아래 · ✕(저장된 값은 「빼기 — 저장할 때 삭제」, 새 값은 「추가 취소」). 머리 「+」 가 빈 행을 넣는다. 입력률 카운트는 두지 않는다 |

| 모드 | 헤더 오른쪽 |
|---|---|
| 읽기 | 「사용처 N」(이 열거형변수를 타입으로 쓰는 마스터 필드, 0 이면 「아무 구분자 · 필드도 이 열거형변수를 타입으로 쓰지 않는다.」) · 「편집」 · 🗑 |
| 편집 | ✕ · 「저장」 · 🗑(비활성, tooltip 「저장하거나 취소한 뒤 실행」) |

| 조작 | 결과 |
|---|---|
| 「+」 · 마지막 행에서 Enter | 빈 행 추가 + 포커스. **빈 채로 남은 새 행은 저장 때 버린다** |
| 위 · 아래 | 순서 바꿈 — 저장 때 반영 |
| ✕ | 그 행만 표에서 뺀다 — 편집 중 변경이라 확인이 없고 ✕(편집 취소)로 되돌아간다. 저장된 값은 저장할 때 삭제된다 |
| 저장 | 이름 · 최종 값 목록(새 값은 발급 코드로 제출 순서 유지)을 **한 트랜잭션**에 반영한다. 뺀 저장된 값이 있으면 먼저 확인 대화상자 — 「값을 빼면 그 값을 고른 자리가 「없는 값」 오류가 된다」 · 「없는 값」이 될 저장 값 수 · 깨질 참조(빠진 값 전부 합계) · 「값 N개 삭제하고 저장」. 편집자는 서버 거부. 거부 · 대화상자 취소면 아무것도 저장되지 않고 편집 유지 + 사유. 새 값을 더했으면 저장 뒤 편집 본문 아래 「재검사 N건」(§3.3, ✕ 로 닫는다). 저장된 필드를 빼거나 타입을 바꿨으면 확인 대화상자 「필드를 빼거나 타입을 바꾸면 값마다 넣은 입력이 지워진다」 · 필드마다 「필드 「X」 — 값 N개의 입력이 지워진다」 · 「필드 N개 바꾸고 저장」(값 빼기와 겹치면 값 대화상자에 필드 줄을 잇는다). 편집자는 서버 거부 |
| 🗑 (읽기에서만) | 열거형변수 삭제 — 관리자 · 영향 확인 뒤 목록(`/enums`)으로. 편집 중에는 꺼진다 — 즉시 실행 명령이라서 (디자인원칙 §2 L2) |

| 상태 | 표시 |
|---|---|
| 없는 코드 | 경로 `열거형 › <코드>` + 「찾을 수 없습니다.」 |

## 5. 미결

- **열거형변수 정의 삭제** — 기획(〔D-P1-17〕 · ADR-0049 §2 표)은 「마스터 필드가 타입으로 쓰는 열거형변수는 삭제 거부」, 코드는 관리자 확인 뒤 허용하고 값 행을 지운다(§3.2). 값 삭제는 「없는 값」으로 정했다(ADR-0078) — 정의 삭제도 같은 결로 갈지.
- **시나리오 문장이 옛 규칙** — [[기능/구분자/시나리오/구분자정의_시나리오]] 시나리오 2 「경계·오류」는 값 삭제를 「프로덕션 거부 · 개발 모드 연쇄 삭제」로 적는다(모드 폐지 · 「없는 값」 이전). 시나리오는 사람이 고친다 — 그때까지 E2E `tests/e2e/enum-missing-value.spec.ts` 는 좌표를 달지 않는다.
- **생성 화면의 빈 행** — [[공통/화면/디자인원칙]] §2 L2 는 「빈 행은 제출 때 버린다」인데 생성 값 표는 빈 행을 `required` 로 막는다(상세는 버린다). **미구현**.
- 값 「사용중지」 상태 — 삭제 거부가 잦으면 재검토 (MVP 는 추가 · 삭제뿐).
- **값 순서 재검토 트리거** — 두 상품에서 서로 거꾸로인 사유 쌍이 나오면 상품별 순서(또는 값 분할)를 다시 본다(§3.1).
