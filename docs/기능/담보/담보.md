# 담보

> 상태: 초안 · 최종수정: 2026-09-27

## 1. 한 줄

담보는 재사용되는 보장 단위의 **마스터**다 — 담보 › 세부보장 › 급부 3층 구조와 이름, 각 층의 값(기본값), 담보약관 템플릿 1벌을 소유한다.
상품 설계자가 상품에 탑재하기 전에 만들어 두고, 탑재된 뒤에도 구조를 고친다. 탑재 · 상품담보 · 담보속성 조합은 [[기능/상품/상품]] · [[기능/담보속성/담보속성]] 의 일이다.

## 3. 규칙

### 3.1 트리

- **담보 › 세부보장 › 급부 3층.** 단순 담보(각 1개)도 같은 3층의 최소 사례다. 구조는 마스터 소유이고 탑재한 모든 상품이 공유한다 (ADR-0002).
- **최소 구조** — 담보는 세부보장 1개 이상, 세부보장은 급부 1개 이상. 생성이 세부보장 1 · 급부 1 을 함께 만든다(원자적). 마지막 하나의 삭제는 관리자도 거부한다.
- **이름** — 담보명은 전역 유일, 세부보장명 · 급부명은 형제 사이에서 유일(다른 부모 아래 같은 이름은 허용). 빈 이름은 저장 거부.
  이름은 뼈대 속성이다 — 값이 아니라 스냅샷 대상이 아니고, 이름 수정은 탑재 여부와 무관하게 편집자가 한다.
- **순서는 데이터** — 형제 순서가 곧 문면 수록 순서 · 반복 표 행 순서 · 집계 순회 순서다.
- 세부보장 · 급부의 **부모 이동은 없다** — 값 행의 소속 이관 규칙이 없다.
- 담보명에 담보속성 값(기본계약 · 갱신형 …)이 들어가면 **경고**한다. 저장은 막지 않는다 — 담보속성은 탑재할 때 정한다.
- **담보 자체 상태(미사용 · 적용 · 확정)는 없다.** 「고쳐도 되는가」는 탑재 상품담보 수가 답한다 (ADR-0075).

### 3.2 구조 정정 — 편집 하나 · 저장 시 영향 확인

생성 뒤에도 구조를 고친다. **탑재 여부와 상관없이 담보 상세의 `편집` 하나에서** — 카드 위 조작(⊕ 추가 · ↑↓ 순서 · ✕ 삭제 · 이름 인라인)이 초안에 담기고
담보명 · 값과 함께 저장 한 번에 들어간다 (ADR-0075). 갈림은 입구가 아니라 저장이 한다 — 「이미 저장된 값 · 참조를 없애는가」(ADR-0019)와 탑재 상품담보 수(계산, 상태 아님).

| 변경 | 누가 | 저장할 때 |
|---|---|---|
| 이름 | 편집자 | 확인 없음. 탑재 스냅샷의 이름도 같은 트랜잭션에서 따라온다 |
| 추가 · 순서 | 편집자 | 미탑재면 확인 없음. **탑재됐으면** 먼저 영향 확인(탑재 상품담보 목록) — 「구조 바꾸고 저장」. 추가 노드는 탑재분에 **미입력 자리**로 생기고, 순서는 탑재 상품의 조문 수록 순서가 따라 바뀐다 |
| 삭제 | **관리자만** | 파괴적 — 늘 먼저 영향 확인(「세부보장·급부 N개 삭제하고 저장」). 마스터 · 탑재 스냅샷 값 행이 연쇄 삭제된다. 영향이 비어도 절차는 같다 |

- 편집자가 삭제를 섞어 저장하면 **서버가 거부**한다 — 「세부보장 · 급부 삭제는 관리자만 할 수 있다」 배너. 화면 숨김이 아니라 서버 거부다 (ADR-0019).
- 영향 = 소실될 마스터 값 행 수 · 깨질 문면 참조 · 함께 지워질 하위 · 탑재 상품담보별 스냅샷 소실 행.
- **확인 전엔 아무것도 저장하지 않는다.** 확인하면 담보명 · 구조 · 탑재 스냅샷 동기화(추가 = 미입력 · 삭제 = 값 행 삭제 · 이름 · 순서 갱신) · 값이 **한 트랜잭션**이고,
  어느 단계가 거부되면(값 쓰기 포함) 전부 롤백 · 편집 유지 + 배너. 저장 전에 계획 전체를 메모리에서 돌려 부분 저장을 막는다 (ADR-0075 · ADR-0002).
  — 왜: 영향은 초안이 정해진 뒤에야 정확하다(초안 기준 소실 행). 편집 전에 영향을 보이던 별도 「구조 편집」 화면은 입구를 둘로 나눴다 (§6.2).
- **형제 이름 규칙은 최종 트리 하나다** — 저장 뒤 트리에서 같은 부모 아래 이름이 겹치지 않으면 된다. 그래서 형제 이름 A↔B 맞바꾸기, ✕ 한 형제의 이름을 새 노드 · 개명에 다시 쓰기가 된다. 다시 쓴 이름의 노드는 **새 노드**다 — 지운 노드의 값 · 탑재 스냅샷 값은 따라오지 않는다(삭제 영향 확인에 이미 실린다). 편집기의 이름 옆 표시(빈 이름 · 형제 중복)와 서버 검사가 같은 규칙이다.
  — 왜: 전에는 서버가 이름 → 추가 → 삭제를 한 단계씩 검사해, 화면은 저장 버튼을 켰는데 서버가 중간 상태의 이름 충돌로 거부했다(「지운 형제 이름 재사용 = 거부」, 점검 2026-09-27 H2 ③). 적용은 ⓪ 바뀌거나 지워질 노드의 이름을 자리표로 비움 → 추가 → 삭제 → 새 이름 → 순서라, 중복 거부는 최종 트리에서도 겹칠 때뿐이다 (`applyStructurePlanTo`).
- 담보약관 템플릿이 있어도 구조 수정을 막지 않는다. 사라진 노드를 가리키는 반복 · 슬롯 · `@노드` 조건은 **오류 상태**로 드러나고 문면에서 고친다 (ADR-0075).
- **담보 삭제** — 관리자만. 영향: 하위 세부보장 · 급부, 마스터 값 행, 담보약관 템플릿, 탑재 상품담보(마스터를 잃는다) (ADR-0019).

### 3.3 값 — 노드 × 마스터 필드

- 값 자리는 **노드 × 그 레벨의 마스터 필드**다. 부착 · 노출여부 · 선택 필드는 없다 — 그 레벨 필드는 모든 노드에 늘 있고, 안 쓰는 항목은 미입력으로 둔다 (ADR-0037).
- 지금 레벨별 필드 ([src/domain/master/catalog.ts](../../../src/domain/master/catalog.ts)) —

  | 레벨 | 폼 · 필드 |
  |---|---|
  | 담보 | 담보 기본 `coverage_basic.claim_name` 「보험금명」(조문 지급 문장에 찍는 보험금 이름 — 담보명과 다른 값) |
  | 세부보장 | 없음 |
  | 급부 | 보험금지급 `pay`(면책여부 · 지급률 · 최초1회한) · **감액** `reduction` · **면책** `exemption` (여는 폼 — §3.4) |

- **미입력은 상태다.** 기본값은 프리필로만 들어오고 저장해야 명시 값이 된다. 명시 값 → 미입력으로 되돌리는 「값 비우기」가 있다 (ADR-0004).
- 마스터 값을 고쳐도 이미 탑재된 상품담보의 값에는 **소급되지 않는다** — 새로 탑재하는 분부터 반영된다 (ADR-0002).
- 값 쓰기는 타입 검사 + 경로별 규칙(`validateSlotValue`)을 탄다 — 담보 마스터와 상품담보 스냅샷이 같은 검사다.
- **구조 모양에 따라 더 묻는 값은 없다** — 세부보장이 하나든 여럿이든 급부가 받는 값은 급부 레벨 폼뿐이다. 지급사유 · 가입금액 기준 문구는 담보약관(문면) 몫이다.
  — 왜: 문구를 값으로 받으면 상품마다 다시 적게 된다. 문구는 문면이 소유한다.

### 3.4 급부 특성 — 감액 · 면책

급부 레벨 **시스템 시드 폼** 둘이다. 폼 값이라 스냅샷 · 값 저장소 · 식 참조를 그대로 탄다 (ADR-0065).

- **여는 폼** — 급부에서 폼을 **열지 않음 = 그 특성 없음.** 연 폼의 자리만 완결성 · 식에 잡힌다. 열었다가 닫으면 그 값을 지운다 (ADR-0065 §4). 별도 「감액 여부」 필드는 없다.
  — 왜: 「감액 없음」과 「아직 안 적음」(ADR-0004)을 필드 하나 없이 가른다. 구간이 없는 것을 곧 100% 로 읽으면 아직 안 적은 감액이 조용히 100% 로 나간다.
- **감액** `reduction` —

  | 필드 | 타입 | 규칙 |
  |---|---|---|
  | `periods` 구간 | `table{ 기간: period, 지급률: percent }` | 사람은 **끝 경계만** 적는다 — 한 행 = 「직전 경계 ~ 이 경계 미만」(반열림: 경계 달은 다음 구간에 든다), 첫 행 시작은 **보장개시일**(계약일, 갱신형은 최초계약일). 기간은 `3M` · `1Y` · `1Y6M` · `12` 로 받아 개월 정수로 저장. **엄격 오름차순**(중복 — `1Y` 와 `12M` 포함 — · 역전 · 0 거부). 열고 0행이면 저장 거부 |
  | `after_rate` 이후 지급률 | 정수 0~100 | 마지막 경계 이후 지급률. 기본 100 — 표에 「이후 100%」 행을 적지 않는다 |
  | `new_only` 신규계약만 적용 | boolean | 기본 켬 |

  — 왜: 끝 경계만 적으니 구간 사이 공백이 생길 수 없고, 겹침 검사가 「엄격 오름차순」 하나로 준다. 반열림은 실물 조문의 세는 법(시작일 포함 · 계약해당일 전일까지)과 같다.
- **「이후 지급률」은 기본 숨김** (2026-09-27) — 값이 100(기본값)이면 편집 화면에서 칸 대신 감액 카드 안의 작은 링크 「이후 지급률 바꾸기」만 보이고, 누르면 칸이 펼쳐진다(다시 접기 없음). 읽기 모드는 100 이면 표시하지 않는다. 저장된 값이 100 이 아니면(또는 그 자리에 오류가 있으면) 숨기지 않는다. 숨긴 동안에도 프리필 규칙은 같다 — 숨긴 채 저장하면 100 이 명시 값으로 실린다(디자인원칙 §9.1 「저장이 곧 확인」). 마스터 필드 속성 `hiddenByDefault` 로 표시하고 폼 렌더가 그걸 본다 — 지금은 이 필드 하나에만 붙는다.
  — 왜: 현업에서 이후 지급률은 거의 늘 100 이라 칸이 보이면 매번 확인할 거리만 늘고, 드문 예외는 링크 한 번으로 연다.
- 경계는 날짜가 아니라 **개월 수**다 — 월말 · 윤년의 실제 경과일은 표가 아니라 약관 조문(보장개시일 · 계약해당일)이 정한다. 표는 「n개월」 · 「n년」 글자만 찍는다.
- 지급률은 **셀에 찍을 표시값**(% 정수 0~100, 0 = 그 구간 지급 없음)이다 — 기본 지급률(`pay.rate`)에 곱하는 계수가 아니고 반올림도 없다.
  — 왜: 실물 표(10% · 50%)에 소수가 없고, 곱이 없으면 반올림 규칙이 필요 없다.
  표시 문구(「보험가입금액의 n%」 · 머리글 「계약일부터 n개월 미만」)는 문면 몫이다.
- **면책** `exemption` — `months` 기간(개월 수, 입력 칸 옆에 「n년 n개월」 해석) · `age15_only` 15세 이상만 적용(기본 끔) · `new_only` 신규계약만 적용(기본 켬). 표가 아니다 (ADR-0065 §6).
- **표 입력**(`table` 필드) — 첫 행 머리글, 셀 타이핑, 기간 셀 아래 해석 힌트(`1Y` → 「1년」), 엑셀 붙여넣기(포커스한 셀부터 덮고 모자란 행은 늘린다 · 줄 → 행 · 탭 → 열 · 첫 줄이 머리글과 같으면 버림 · `%` 제거), 행 추가 · 삭제. 해석 실패 셀은 「n행 기간: '…' 를 해석할 수 없습니다」로 저장 거부.
  행별 파생 범위 칸 · 붙여넣기 전용 영역 · 「감액 없음으로」 버튼은 두지 않는다 — 표 + 토글 + 힌트가 같은 정보를 준다.
- **상품별 값** — 탑재 때 스냅샷으로 복사되고 상품담보에서 값만 바꾼다. 구간을 늘리고 줄이는 것, 마스터에 없던 감액 폼을 여는 것도 값 편집이다. 어느 급부가 있느냐(구조)는 마스터 소유다 (ADR-0002).
- **시스템 폼 잠금**(키 · 레벨 · 시스템 필드 삭제 · 타입 변경 불가) — `system` 표식만 있다. 폼을 화면에서 편집하는 경로가 MVP 에 없어 잠금 검사는 **미구현** (ADR-0065 §3).
- **식이 읽는 길** — 시드 구분자가 폼 값을 투영한다: 급부 `감액여부 = exist(reduction.periods)` · 감액신규만 · 면책여부 · 면책기간 · 면책15세이상, 세부보장 · 담보 `감액여부` · `면책여부 = any(급부 …)` (ADR-0065 §5).
  담보약관 조건식은 `감액여부@<노드>` 로 세부보장 · 급부 하나를 가리킨다 — 구분자 · 조건식 쪽 규칙은 [[기능/구분자/구분자]] · [[기능/문면/문면]].

### 3.5 문면과 이어지는 곳

- 담보는 **담보약관 템플릿 1벌**을 소유한다(없어도 된다 — 문면 없는 담보는 조립에서 문서를 내지 않는다). 담보 상세 화면에는 담보약관 템플릿이 없다 — **담보약관 템플릿 메뉴**가 입구다 (2026-09-27, §6.2).
- 담보약관의 **공용조항 옵션은 담보 마스터 안에서 다 정한다** ([[기능/상품/상품]] §3.6). 미결정 옵션은 문면 저장 검사가 잡는다 — 담보 상세 헤더에는 배지가 없다.
- **반복 표** — 담보약관 템플릿의 표는 「세부보장마다」 · 「세부보장 › 급부마다」 행을 반복할 수 있고, 행은 이 트리의 순서 · 노드를 그대로 따른다. 세부보장 · 급부를 더하면 표가 따라온다 (ADR-0070 결정 6 · 10).
  문장 · 블록 반복(`forBlock` · `inlineFor`)은 저장 자리만 있고 조립은 오류를 낸다.
- 표 행 · 셀의 **정체는 노드 id** 다 — 이름이 같아도 다른 세부보장 · 급부면 다른 행이고, 병합하지 않는다.
- **최초지급금액표**(감액 구간으로 경계 합집합 표를 만드는 동적 표) · 편집값으로 그리는 실시간 산출 표 · 구조 판별(세부보장 1개 = A · 세부보장 여럿에 급부 하나씩 = B · 그 밖 = C → 문면 구분 배치 초기 제안)은 **MVP 밖**이다 — 감액 입력과 조건식만 있다 ([[QA/인수기준]] MVP 범위).
  구조 유형(A/B/C)을 사람이 고르는 입력은 두지 않는다 — 판별은 트리 모양에서 하고 저장하지 않는다.

### 3.6 중첩 카드 — 담보 ⊃ 세부보장 ⊃ 급부

- 담보 마스터 화면은 **카드를 쌓는다** — 담보 카드 ⊃ 세부보장 카드 ⊃ 급부 카드. 카드마다 **이름 + 그 노드 레벨의 마스터 값 폼**. 담보명은 담보 카드의 이름이다(따로 기본정보 영역이 없다).
  필드가 없는 레벨(지금 세부보장)은 폼 자리 없이 이름만. 급부 카드 안의 감액 · 면책 폼 카드는 「⊕ 열기 / ⊖ 닫기」(§3.4).
- **편집 모드의 구조 조작** — 카드 라벨 옆 ⊕(자식 추가: 담보 카드 「+ 세부보장」 · 세부보장 카드 「+ 급부」), 카드 머리 오른쪽 ↑ ↓ ✕, 이름 인라인.
  형제가 하나뿐이면 ✕ 는 잠긴다(「최소 구조 — 세부보장 1개 · 급부 1개는 있어야 한다」). 새 카드는 값 폼이 없다 — 저장한 뒤에야 값 자리가 생긴다. ✕ 로 뺀 기존 카드는 초안에서 사라진다(되돌리려면 편집 취소).
- **접기** — 담보 카드는 늘 펼침. 세부보장 · 급부 카드는 (화면을 연 때) 형제가 둘 이하면 펼침, 셋 이상이면 접힘. 카드 머리에 ▸ / ▾. 접힌 카드는 **이름만** 보인다 — 미입력 개수 · 입력률 카운트를 두지 않는다(화면 편집 원칙 2026-09-15). 미입력 표시는 펼친 폼의 그 칸 옆에만.
  접어도 폼은 내려가지 않아 미저장 입력이 남는다.
- **주석(설명) · 사용처는 화면에 없다** — 주석 값은 데이터에 남고 저장이 그대로 보존한다(지우지 않는다). 탑재 수는 헤더 배지가 보인다.

### 3.7 결정됐지만 미구현

- **상품담보 값 화면을 같은 카드 부품의 값 모드로** — 이름 잠금 · ⊕ · ⊖ 없음 · 특성 카드만 편집 · 「기본값과 다름 · [기본값으로]」. 지금 상품담보 화면은 따로 그린다 ([[기능/상품/상품]]).
  테마는 현행 모델링 화면(둥근 흰 카드 · 옅은 그림자 · 파란 ⊕ · 빨간 ⊖ · 밑줄 입력 · 토글) — 지금 담보 카드는 앱 공통 토큰(얇은 괘선 · 흰 카드)이다.
- **복제** — 담보 복제(트리 · 마스터 값, 문면 제외, 이름 「<원본> 사본」) · 세부보장 복제(하위 급부까지, 원본 바로 뒤) · 급부 복제 (ADR-0075 결정 4 가 전제로 둠). 서비스 · 화면 모두 없다.

## 4. 화면

### `/coverages` — 조회 (L1)

| 구성 | 내용 |
|---|---|
| 제목 줄 | 「담보」 + 오른쪽 `+`(새 담보) |
| 검색 | 담보명 |
| 컬럼 | 담보명(→ 상세) · 최종수정 |
| 페이저 | 50건 · 「총 N건」 |
| 빈 상태 | 「담보는 재사용되는 보장 단위의 마스터다 …」 + 「새 담보 만들기」. 검색 결과가 없으면 「이 조건에 맞는 담보가 없습니다.」 |

코드 · 담보분류 · 상태 · 수정자 컬럼은 없다 — 담보 마스터 스키마에 그 값이 없고, 화면이 지어내지 않는다.

### `/coverages/new` — 생성

- 경로 `담보 › 새 담보`, 제출은 헤더 오른쪽.
- 담보명 · 세부보장명 · 급부명 · 설명. **세부보장명은 담보명을, 급부명은 세부보장명을 타이핑에 맞춰 따라간다** — 그 칸을 직접 고치면 그때부터 따라가지 않는다.
- 「세부보장 1 · 급부 1 이 함께 생성됩니다 (최소 구조).」 — 구조를 더 짜는 것은 생성 뒤 상세 화면 `편집` 의 카드에서.
- 생성 → 상세. 거부(담보명 중복 · 빈 이름)는 배너.

### `/coverages/<id>` — 상세 (L2 · 한 화면)

탭이 없다. 위에서 아래로 **헤더 · 구조(중첩 카드)** 다. 담보약관 템플릿은 이 화면에 없다(§3.5).

| 자리 | 무엇 |
|---|---|
| **헤더** | 경로 `담보 › {담보명}`, 「탑재 상품담보 N」 배지(구조를 고치면 영향이 가는 근거). 오른쪽 `편집`(→ `저장`) · 삭제 |
| **구조** | 담보 카드 ⊃ 세부보장 카드 ⊃ 급부 카드 — 카드마다 이름 + 그 레벨의 값 폼 (§3.6) |

- **편집 입구는 하나** — `편집` 을 누르면 모든 카드의 이름 · 값 · 구조 조작이 한꺼번에 입력기가 된다. 저장 한 번이 담보명 · 구조 · 모든 카드의 값을 담는다. 취소하면 모든 카드가 저장값으로 돌아간다.
- 편집 중 ✕ 로 뺀 것이 있으면 담보 카드 머리 아래 「저장 시 삭제 N개 — 영향을 확인한 뒤 저장된다 (관리자).」
- 담보명에 담보속성 값이 들어가면 담보 카드 머리 아래 경고 한 줄(§3.1).
- 담보속성(갱신유형 · 기본계약 · 추가 …)은 이 화면에 없다.
- 관리자에게는 필드 라벨 옆에 코드 칩 `폼키.필드키`(→ `/master/<경로>`). `?node=<level>:<id>&field=<폼키.필드키>` 로 들어오면 **그 카드(와 부모)를 펼치고** 필드 행을(필드가 없으면 카드를) 스크롤 · 강조한다 — 마스터 화면 · 오류 메시지의 진입 좌표. `?node=` 없이 `?field=` 만 오면 그 필드를 가진 첫 카드. `?tab=` 은 옛 좌표라 무시한다.

**조작**

| 누르면 | 결과 |
|---|---|
| `편집` | 모든 카드가 입력기로 — 이름 인라인 · 값 입력 · ⊕ · ↑ ↓ · ✕ |
| `저장` | 담보명 · 구조 · 값을 **한 트랜잭션**에. 삭제가 섞이거나 탑재된 담보의 구조가 바뀌면 먼저 영향 확인 대화상자(§3.2) — 삭제가 섞였는데 편집자면 서버 거부 배너. 어느 단계가 거부되든(값 쓰기 포함) 전부 롤백 · 편집 유지 + 배너 |
| 취소 | 변경이 있으면 「고친 내용을 버립니까?」 — 계속 편집 / 버리기 |
| 삭제 (읽기에서만) | 담보 삭제 확인(영향 목록) — 관리자만 실행. 편집 중에는 꺼진다(tooltip 「저장하거나 취소한 뒤 실행」, 디자인원칙 §2 L2) |
| ▸ / ▾ | 카드 접기 · 펼치기 (읽기 · 편집 모두) |
| 경로 앞 마디 | 편집 중 변경이 있으면 「고친 내용을 버립니까?」 확인 뒤 이동 |
| 코드 칩 (관리자) | 마스터 화면의 그 필드로 |

## 5. 미결

- **담보명의 담보속성 값 검사** — 경고로 뒀다. 유효값 목록과 대조해 거부까지 갈지.
- 탑재된 담보의 **순서 변경을 편집자에게** 둔 것 — 조문 수록 순서 변경을 파괴로 본다면 관리자로 올린다 (ADR-0075 열어 둔 것).
- 값 · 참조가 없는 노드의 삭제를 편집자에게 열지 — ADR-0019 경계 개정 사안.
- 저장 시 영향 목록에 문면 조연결 · 보통약관 준용까지 실을지.
- 「신규계약만 적용 = 끔」의 실제 처리(기존 계약 소급의 시점 · 주체) · 면책 나이 일반화(다른 나이가 나오면 토글 → 「n세 이상」 숫자 칸) · 지급률 소수 %(실물에 12.5% 류가 나오면 정수 제한을 푼다).
- 표 출력(최초지급금액표)이 MVP 로 들어올 때 — 머리글 기준일 문구(「계약일부터」 / 「최초계약일부터」 / 「보장개시일부터」)를 값으로 고를지 · 같은 경계를 두 급부가 `1Y` · `12M` 으로 다르게 적었을 때 머리글 표기 · `18M` 을 「1년 6개월」 / 「18개월」 중 무엇으로 · 인쇄 폭 초과.
- 편집 중 **코드 칩**은 「버립니까?」 확인 없이 화면을 떠난다 — 경로 링크와 같은 확인을 붙일지.
- 시스템 폼에 필드가 더해졌을 때 이미 탑재된 스냅샷에 자리가 생기는가.
- `exemption.months` 의 마스터 설명은 「화면은 3M · 1Y 로 받는다」인데 입력은 숫자(개월)다 — 설명을 고치거나 `period` 입력으로 바꾼다.
- 시나리오 [[기능/담보/시나리오/담보트리_시나리오]] S6(모드 분기) · [[기능/담보/시나리오/담보값입력_시나리오]] S1 · S2(노출여부 · 부착)는 옛 규칙이다 — 편집 하나 + 저장 시 영향 확인 · 노드 × 마스터 필드로 다시 쓴다.

| 감액 경계 = 보장개시일부터의 **개월 수** · 반열림 · 사람은 끝 경계만 적는다 · 엄격 오름차순 (§3.4) | 실물 조문의 세는 법과 같고, 월말 · 윤년은 표 밖으로 나간다. 끝만 적으면 공백이 생길 수 없어 검사가 하나로 준다 | 날짜 · 일수(90일 · 365일)로 저장 · 닫힌 구간 `[시작, 끝]`(경계일이 두 구간에 든다) · 시작 · 끝 · 계수 3열 입력 · 겹침 허용(뒤 구간 우선) |
| 마지막 경계 이후는 표 밖 「이후 지급률」 칸, 비우면 100 (§3.4) | 실물 대다수는 감액 뒤 정상 지급 — 붙여넣기 한 줄(`1Y \| 50%`)이 곧 「1년 미만 50%, 이후 100%」 | 「이후 100%」 행을 사람이 명시(한 줄이 두 줄) · 기간 빈칸 행 = 이후 값(행마다 빈칸 검사가 생긴다) |
| 「이후 지급률」은 입력 화면에서 기본 숨김 — 100 이 아니면 보이고, 「이후 지급률 바꾸기」 링크로 편다. 필드 속성 `hiddenByDefault` (§3.4, 2026-09-27 사용자 결정) | 현업에서 이후 지급률은 보통 100 이라 입력 화면에 보이지 않는 게 일반적이다. 값 자체는 남겨 드문 예외(이후 80% 등)를 받는다. 숨긴 채 저장하면 100 명시 — 프리필 규칙을 바꾸지 않는다 | 항상 보임(매번 보는 칸이 하나 는다) · 필드를 없애고 100 고정(예외를 못 적는다) |
| 폼 열림 = 감액 · 면책 있음, 열고 0행 = 거부 (§3.4) | 없음 · 미입력 · 값 3상태를 필드 하나 늘리지 않고 가른다 | 「감액 여부」 boolean 필드 · 구간 공백 = 감액 없음(100%) |
| 구간 지급률 = 셀에 찍을 % 정수 표시값, 반올림 없음 (§3.4) | 실물 표에 소수가 없고, 곱이 없으면 반올림 규칙이 필요 없다 | 기본 지급률에 곱하는 계수 · 소수 % + 소수 첫째 자리 반올림 |
| 상품별 감액 = 스냅샷 값 편집 (§3.4) | ADR-0002 의 귀결 — 감액은 급부 마스터 값이다 | 상품별 구간을 마스터 오버라이드(라이브)로 |
| 기간은 `3M` · `1Y` 로 받고 해석을 옆에 보인다 (§3.4) | 엑셀 원본이 그렇게 적혀 있고, 파서가 M · Y 둘뿐이라 실패가 드물다. 해석을 보여 「1년까지 / 1년부터」 혼동을 없앤다 | — |
| 특성 입력 = 표 + 토글 + 힌트 한 줄 (§3.4) | 같은 정보를 준다 — 사용자: 복잡하게 만들 필요 없다 | 행별 파생 범위 칸 · 「이후」 파생 행 · 별도 붙여넣기 영역 · 「감액 없음으로」 버튼 |
| 구조 유형(A/B/C)을 고르지 않고 · 구조별로 더 묻는 값도 없다 (§3.3 · §3.5) | 선택은 트리와 어긋날 수 있는 중복 입력이다. 문구는 문면 소유라 값으로 받으면 상품마다 재입력 | A/B/C 선택 버튼 · B 구조에서 세부보장 카드에 지급사유 문구 |
| 입력 화면은 담보 마스터, 상품담보는 같은 부품의 값 모드 (§3.6 · 값 모드는 §3.7 미구현) | 이름 · 구조가 마스터 소유라 이름 입력은 마스터에만 선다. 화면이 둘이면 「어디서 무엇을 고치나」를 두 번 배운다 | 상품모델링의 급부 목록 + 선택 급부 폼(코덱스 초안) · 독립 「표 하나 뽑는 도구」(값이 문면과 이어지지 않는다) |
| 입력 화면 테마 = 현행 모델링 화면(둥근 카드 · 파란 ⊕ · 빨간 ⊖ · 밑줄 입력 · 토글) (§3.7, 미구현) | 사용자가 이미 쓰는 화면이라 학습 비용이 없다. [[공통/화면/디자인원칙]] 은 이 기준으로 고친다(후속) | 디자인원칙 「카드 안 쓴다 · 그림자 안 쓴다」 그대로 |
| 값 폼은 노드마다 따로 띄우고 **모든 카드에 동시에** 둔다 — 접어도 내리지 않는다. 취소하면 세대를 올려 전부 새로 띄운다 (§3.6 · §4 상세) | 폼 인스턴스 하나를 노드가 이어 쓰면 A 의 초안이 B 로 제출되거나 A 로 돌아오면 입력이 사라졌다(점검 H4). 한 화면이 되자 노드 전환이 없어져 노드별 초안 보관(탭 시절 `value-drafts` 의 byNode)이 필요 없어졌다 | 접힌 카드의 폼을 내리고 초안을 따로 보관(보관 코드가 다시 생긴다) · 편집 상태를 EditShell 저장 데이터에 싣기(폼 모델이 서버 액션으로 넘어간다) |
| 담보 상세는 탭 없는 한 화면 — 헤더 · 중첩 카드(카드마다 이름 + 값 폼). 주석 · 사용처는 화면에서 뺀다(주석 값은 보존) (§3.6 · §4, 2026-09-27 사용자 결정) | 탭 넷은 한 객체의 구조와 값을 네 곳에 흩었다 — 값을 고치려면 구조 트리에서 노드를 골라 다른 탭으로 가야 했다. 카드가 구조와 값을 한자리에 보인다. 탑재 수는 헤더 배지가 이미 보인다 | 탭 넷 유지(기본 · 담보 · 세부보장 · 급부) · 트리 + 선택 노드 폼 두 칸 · 기본정보 영역(담보명 · 주석)을 카드 위에 따로 |
| 구조 편집 입구는 상세의 `편집` 하나 — 탑재된 담보도 카드에서 고치고 저장 시 영향 확인 (§3.2 · ADR-0075, 2026-09-27 사용자 결정) | 입구가 둘이면 「이 담보는 어디서 급부를 더하나」를 담보마다 다시 묻는다. 영향은 초안이 정해진 뒤 저장 때 보는 것이 정확하다 | 탑재된 담보는 별도 「구조 편집」 화면(ADR-0052 결정 2) · 탑재된 담보는 이름만 |
| 담보 상세에서 담보약관 템플릿 띠(제목 · 조 N · 만들기 · 열기)와 「공용조항 옵션 미결정 N」 배지를 뺀다 (§3.5 · §4, 2026-09-27 사용자 결정) | 담보약관 템플릿 메뉴와 입구가 둘이라 혼란스럽고, 띠의 「만들기」는 오류가 났다 | 띠 유지 |
| 세부보장 · 급부 카드는 형제 셋 이상이면 접어서 연다, 접힌 카드는 이름만 (§3.6, 2026-09-27 사용자 결정) | 급부가 많은 담보(수술비 1~7종)도 한 화면에 들어온다. 카운트는 화면 편집 원칙이 금한다 | 늘 펼침 · 접힌 카드에 미입력 개수 |
| 면책은 표가 아니다 — 기간 + 「15세 이상만」 토글 (§3.4) | 실물은 「기간만」 · 「15세 이상이면 기간」 둘뿐 | `조건 \| 기간` 표(초기값 `x>=15 \| 3M`) · 면책을 범위 밖으로 |
| 상세 저장 = 한 트랜잭션 · 구조는 최종 트리로 검사 — 형제 이름 맞바꾸기 · 지운 형제 이름 재사용 허용 (§3.2 · §4, 2026-09-27 점검 D1) | 값 쓰기가 거부돼도 담보명 · 구조가 이미 저장돼 있었고(H1), 화면 검사(최종 상태)와 서버 검사(한 단계씩)가 달라 저장 버튼이 켜진 채 거부됐다(H2 ③). 액션 전체를 `saveOnce` 로 감싸고, 계획 적용은 이름을 먼저 비워 최종 상태만 검사한다. DB 형제 이름 유일 인덱스도 저장 때 이름을 먼저 비워 맞바꾸기를 받는다 | 거부 유지 + 화면이 미리 표시하고 문서에 적기(`plan.test` 옛 의도) · 액션만 트랜잭션으로 감싸기 |
