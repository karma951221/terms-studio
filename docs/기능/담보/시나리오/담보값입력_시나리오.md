# 담보값입력 시나리오

> 상태: 초안 · 최종수정: 2026-09-01
> 관련 기획: [[기능/담보/담보]] (노출여부) · [[기능/구분자/구분자]] (값의 존재 규칙)

## 시나리오 1 — 무조건 노출 구분자의 자동 표시

**전제**: 담보 레벨 구분자 「갱신유형」이 **무조건 노출 ☑** 로 정의돼 있다.
담보 마스터에 일반상해사망·수술비가 있다.
**흐름**:
1. 일반상해사망의 모델링(값 입력) 화면 진입 → 갱신유형 폼이 자동으로 떠 있다.
2. 수술비 화면 진입 → 같은 폼이 자동으로 떠 있다.
3. 새 담보를 추가로 생성 → 그 화면에도 자동으로 뜬다.
**기대 결과**: 무조건 노출 구분자는 그 레벨 **모든** 실체의 화면에 항상 나타난다 —
담보별 부착 조작이 필요 없다.
**경계·오류**: 무조건 노출 구분자는 + 버튼 목록에 나타나지 않는다 (이미 모두에 있음).

## 시나리오 2 — 선택적 노출 구분자를 + 버튼으로 부착

**전제**: 담보 레벨 구분자 「수술급여기준」(수술비 전용 값)이 **무조건 노출 ☐** (선택적 노출)로
정의돼 있다.
**흐름**:
1. 수술비 모델링 화면 진입 → 수술급여기준 폼이 기본으로는 보이지 않는다.
2. **+ 버튼**으로 구분자 목록을 열어 수술급여기준을 찾아 추가.
3. 폼이 화면에 나타나고, 담보 ↔ 구분자의 **부착 관계가 데이터로 저장**된다.
**기대 결과**: 부착 이후 수술비 화면에는 이 폼이 계속 나타난다.
일반상해사망 화면에는 여전히 나타나지 않는다 (부착 안 함).
**경계·오류** — **부착 해제 규칙** (2026-09-01 확정, 삭제 가드와 같은 결):
- 해제 시점에 그 담보 문맥에서 이 구분자를 읽는 사용처(담보 문면 조건식·슬롯,
  이 구분자를 요구하는 공용조항 참조, 파생식)를 검사한다.
- 사용처가 있으면: 프로덕션 서버 거부. 개발 모드는 깨질 참조 목록 표시 + 확인 후 해제
  (깨진 참조는 오류 상태).
- 사용처가 없으면: 해제 허용하되, 입력된 값 행이 있으면 「값 N건 삭제」 경고 + 확인 후 연쇄 삭제.

## 시나리오 3 — 완결성 조회는 부착된 것만 대상

**전제**: 수술급여기준이 수술비에만 부착돼 있고 값은 미입력 상태다.
갱신유형(무조건 노출)도 두 담보 모두 미입력이다.
**흐름**:
1. 일반상해사망의 완결성 조회 실행.
2. 수술비의 완결성 조회 실행.
**기대 결과**:
- 일반상해사망: 갱신유형 미입력만 보고된다. **수술급여기준은 나타나지 않는다** —
  수술비 전용 값이 남의 담보 경고로 뜨는 오염이 구조적으로 없다.
- 수술비: 갱신유형·수술급여기준 미입력 2건이 보고된다.
**경계·오류**: 부착됐으나 미입력인 값을 조립·평가가 참조하면 오류 + 좌표 보고 —
완결성 조회는 사전 안내이고, 미입력 차단의 최종 방어선은 평가 시점이다.

## 시나리오 4 — 담보 마스터 값 입력과 미입력 상태

**전제**: 수술비에 수술급여기준(기본값 있음)·갱신유형(기본값 없음)이 부착돼 있다.
**흐름**:
1. 수술급여기준 폼 열기 → 기본값이 **프리필로만** 보인다 (저장 전까지 미입력 상태).
2. 확인 후 저장 → 명시 값이 된다.
3. 갱신유형은 채우지 않고 화면을 나간다 (중간 저장).
**기대 결과**:
- 값 자리는 **명시 값 또는 미입력** 둘뿐 — 기본값이 저장소로 자동 유입되는 경로는 없다.
- 미입력 상태로도 중간 저장은 언제나 허용된다.
- 이후 탑재 시 스냅샷은 미입력 상태도 그대로 복사한다.
**경계·오류**: ⚠ 미결: 담보 마스터 값 입력 화면의 구성 — [[기능/담보/담보]] 열어 둔 문제,
[[기능/담보/담보]] 화면기획과 합류 예정.
