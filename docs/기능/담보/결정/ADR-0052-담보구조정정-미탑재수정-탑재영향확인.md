# ADR-0052 — 담보 구조 정정: 미탑재 담보는 구조 수정 허용 · 탑재된 담보는 영향 확인 명령 · 담보 자체 상태는 MVP 에 없다

## 맥락

2026-09-06 담보 상세 화면 QA 에서 구조(세부보장 · 급부의 추가 · 삭제 · 순서)를 수정 화면에서 뺐고, 2026-09-07 에 서버 액션에서도 실제로 뺐다.
그래서 지금은 **생성 뒤 구조를 바꿀 방법이 없다.** 그런데 [[기능/담보/담보]] 트리 편집 규칙 · 담보_액션(아카이브) §세부보장 · §급부 ·
[[기능/담보/시나리오/담보트리_시나리오]] S6 은 생성 뒤 구조 변경을 전제하고, 화면기획은 대체 경로를 Q-A 로 미뤄 두었다.

리뷰 F07 이 짚은 것 — 급부 하나를 빠뜨린 것을 생성 뒤에 발견하는 것은 **정상적인 작업 과정**이다. 「새 담보로 다시 만들기」가 답이면
문면 · 값 · 상품 탑재 · 조연결을 옮기는 절차까지 따라와야 하는데, 담보 복제는 문면을 제외하고(담보_액션 D-P2-4) 문면 복제는 따로 있어([[기능/문면/문면]] 「문면 문서 복제」)
「처음부터 문면까지 다시 쓰기」가 실제 경로가 된다. 구조 편집을 숨긴 것이 문제를 없애지는 않았다.

같은 리뷰 §5 가 남긴 것 — [[공통/화면/디자인원칙]] 의 담보 상태(미사용 · 적용 · 확정)와 담보_액션 「자체 상태 없음」이 어긋나 있다.
구조 정정 경로를 정하면서 「담보에 상태가 있는가」도 같이 닫는다 — 둘 다 「이 담보를 지금 고쳐도 되는가」의 답이기 때문이다.

## 결정

리뷰 §7 의 추천안을 그대로 채택한다.

1. **미탑재 담보는 생성 뒤에도 구조를 고친다.** 탑재 상품담보가 0 인 담보는 상세 화면 편집 모드에서 세부보장 · 급부의 **추가 · 삭제 · 순서 변경**을 허용한다.
   규칙은 생성 화면과 같다 — 최소 구조(세부보장 1 · 급부 1) · 형제 이름 중복 금지 · 순서는 데이터. 추가 · 순서는 편집자도 할 수 있다.
   **삭제는 미탑재여도 파괴적**이다 — ADR-0019 의 2026-09-05 경계(담보 노드 삭제 = 실체 · 구조를 없애는 것)를 그대로 따라 **관리자만**, 영향 목록(소실될 마스터 값 행 · 깨질 문면 참조 · 함께 지워질 하위) 확인 후 허용.
   영향이 비어 있어도 절차는 같다 — 규칙을 두 벌로 만들지 않는다.
   문면(담보약관)이 이미 있어도 구조 수정을 막지 않는다 — 문면의 반복 · 슬롯이 사라진 노드를 가리키면 **오류 상태**로 드러난다 (ADR-0019 §2 「깨진 참조는 조용히 사라지지 않는다」).
2. **탑재된 담보의 구조 변경은 별도 명령 「구조 편집」이다.** 탑재 상품담보가 1 이상인 담보는 편집 모드의 트리에 구조 조작이 없고, 대신 트리 머리에 「구조 편집 →」 명령이 선다.
   명령은 **영향 목록**을 먼저 보여준다 — 탑재 상품담보(상품 · 상품담보명) · 스냅샷 값 자리 · 문면 조연결 · 참조. 그 위에서 추가 · 삭제 · 순서를 바꾸고 저장한다.
   - **추가 노드는 비파괴** — 기존 탑재분에 그 노드의 값 자리가 **미입력**으로 생긴다 (마스터 기본값의 사후 복사 없음, ADR-0002 결). 편집자도 할 수 있다.
   - **순서 변경은 비파괴** — 값 · 참조가 사라지지 않는다. 다만 탑재된 상품의 문면 수록 순서가 바뀌므로 영향 목록(상품 목록)은 보여준다. 편집자도 할 수 있다 (D-P2-6 개정).
   - **삭제 노드는 파괴적** — 마스터 값 행 · 탑재 스냅샷 값 행이 연쇄 삭제되고 참조가 깨진다. **관리자만**, 영향 목록(소실될 값 행 수 · 깨질 참조 · 함께 지워질 하위) 확인 후 허용.
     편집자의 요청은 서버가 역할로 거부한다 (ADR-0019 §3 — 화면 숨김이 아니라 서버 거부). [[기능/담보/담보]](2026-09-14 확정된 전제)와 같은 문장.
3. **「탑재됐는가」의 기준은 계산이다** — 탑재 상품담보 수 > 0. 담보에 이를 뜻하는 상태 값을 두지 않는다 (§담보 상태).
4. **담보 복제 · 문면 복제는 그대로 둔다** — 「복제 → 수정 → 교체」는 구조 정정의 경로가 아니라 「비슷한 담보를 하나 더 만드는」 경로다. 관계는 한 줄 —
   담보 복제(D-P2-4)는 트리 · 마스터 값만 복사하고, 문면이 필요하면 [[기능/문면/문면]] 「문면 문서 복제」로 대상 담보에 따로 붙인다.

### 담보 상태 (리뷰 §5 잔여)

**MVP 에 담보 자체 상태(미사용 · 적용 · 확정)는 없다.** [[기능/담보/담보]] 「담보에 자체 상태가 없다」를 유지한다.

- 「탑재 가능 여부 · 작업 중 여부」는 상태가 아니라 **계산**으로 보여준다 — 탑재 상품담보 수 · 「입력 n / 값 자리 m」(디자인원칙 §9.2 · §9.6) · 완결성 조회.
  「미사용(탑재 조회에 안 잡힘)」이 막으려던 것 — 만들다 만 담보를 상품이 집는 일 — 은 탑재 화면이 카운트를 보여주는 것으로 대신한다.
- 「확정(더 못 고침)」은 [[공통/기술/결정/ADR-0026-이력개정-이력일자-작업본확정]] 의 작업본 / 확정 2상태가 **MVP 이후**에 맡는다. 리뷰 §6 「현재 수정 가능 상태를 확정으로 표시하지 않는다」 —
  MVP 화면에는 자물쇠(⌧)가 설 자리가 없다. ADR-0026 이 구현되면 「확정 행은 편집자가 수정 불가 · 관리자 해제 후 수정」이 곧 잠금이고, 그때 글리프를 준다.
- 디자인원칙 §2 L1 「담보 상태 글리프」 · L3 「담보약관 확정 자물쇠」 · Q13 · Q19 는 이 결정으로 **MVP 이후(ADR-0026 시점)** 로 옮긴다 — 문장은 디자인원칙 소유자가 고친다.

## 실물 (2026-09-14 코드 대조 — 코드는 고치지 않았다)

- `src/services/coverage.ts` — **구조 편집 API 는 서비스 층에 전부 살아 있다.** 비파괴: `addSubCoverage` · `addBenefit` · `renameSubCoverage` · `renameBenefit` ·
  `reorderSubCoverages` · `reorderBenefits` (editor 가능 · 탑재 여부를 보지 않는다). 파괴적: `removeSubCoverage` · `removeBenefit` · `remove` — `destructive()` 2단
  (editor → forbidden · admin → `needsConfirmation(Impact)` · `{ confirm: true }` → 실행 + 값 행 연쇄 삭제). 최소 구조 위반은 precheck 에서 admin 도 거부(`minimumStructure`).
- `Impact`(`src/domain/coverage/impact.ts` `nodeDeleteImpact`) = 소실될 **마스터** 값 행 수 · 깨질 참조(`UsageSource`) · 함께 지워질 하위 이름.
  **탑재 상품담보 목록 · 스냅샷 값 행 수는 아직 안 센다** — 결정 2 의 영향 목록이 요구하는 것과의 차이.
- `src/services/product.ts` `syncStructure` / `src/domain/product/mount.ts` `diffStructure` — 조회 · 조립 전에 스냅샷 노드를 마스터 트리와 대조해
  없는 노드는 빈 값으로 추가 · 사라진 노드는 값 행 삭제 · 이름 / 순서 갱신. 결정 2 의 「추가 노드는 미입력 자리」 · 「삭제는 값 행 연쇄」가 이미 이 경로다.
- `src/app/(app)/coverages/[id]/CoverageEditor.tsx` — 헤더 주석 「구조는 여기 없다 (2026-09-06 확정)」. `StructureTree` 는 읽기 전용, 편집 모드에서 이름만 인라인.
  `src/app/(app)/coverages/edit-actions.ts` 의 서버 액션은 `rename` · `renameSubCoverage` · `renameBenefit` · `remove`(담보) 만 부른다 — 추가 · 순서 · 노드 삭제 액션이 **없다**.
- 따라서 구현은 「서비스 위에 서버 액션 · 화면 조작을 되돌리는 것」이고, 새로 만드는 것은 ① 탑재 수 분기 ② 「구조 편집」 명령 화면 ③ Impact 에 탑재 상품담보 · 스냅샷 값 행 추가, 셋이다.

## 이유

- **구조 불변은 값 스냅샷을 지키는 규칙이지 실수를 못 고치게 하는 규칙이 아니다.** ADR-0002 가 공유하는 것은 「구조」이고, 그 구조가 바뀔 때의 규칙(추가 = 미입력 · 삭제 = 연쇄)은
  2026-08-30 부터 있었다. 화면에서 뺀 것은 QA 의 「구조가 안 보인다」 문제였지 규칙의 철회가 아니었다.
- **미탑재 / 탑재 분기는 이미 있는 기준이다.** ADR-0019 의 파괴적 판정 「이미 저장된 값이나 참조를 없애는가」 — 미탑재 담보의 추가 · 순서는 아무것도 없애지 않는다.
  탑재분이 있으면 스냅샷 값 자리와 문면 수록 순서가 걸리니 영향을 보여주는 것이 맞다.
- **상태 대신 계산.** 「탑재 가능」을 상태로 두면 편집자가 상태를 올리는 것을 잊거나 잘못 올리는 두 번째 실수 경로가 생긴다. 탑재 수 · 완결성은 이미 세고 있고 거짓말을 못 한다.
- **인수기준** — 리뷰 §8 「담보 구조 정정: 생성 후 누락 급부를 발견해도 문면을 처음부터 다시 쓰지 않고 정정을 완료할 수 있다」. 결정 1 · 2 가 이 문장을 그대로 만족한다.

## 버린 대안

- **ⓐ 경로 없음 — 새 담보로 다시 만든다(담보 복제 → 수정 → 상품에 교체)** — 리뷰 §7 두 번째 후보. 교체 시 값 · 담보속성 · 적용범위 · 조연결 승계 결정이 따라와 **반드시 싸지 않다**.
  문면은 복제 대상도 아니라 「문면까지 다시 쓰기」가 된다. 인수기준 위반.
- **ⓒ 판본 작업본(ADR-0026) 도입 뒤 미확정 작업본일 때만 구조 편집** — 리뷰 §7 세 번째 후보. 이력 · 작업본 기능 전체가 선행 조건이 된다. F07 「이력 · 작업본 기능 전체를 선행 조건으로 삼을 필요는 없다」.
- **ⓑ 관리자 전용 「구조 편집」 별도 화면** — 화면기획 Q-A 의 후보. 미탑재 담보의 급부 하나 추가에도 관리자가 필요해진다. 기준을 역할이 아니라 「탑재됐는가 · 없애는가」로 두는 편이 ADR-0019 와 맞는다.
- **담보 상태 3값을 MVP 에 넣는다**(디자인원칙 2026-08-30 안) — 도메인 · 스키마 · 서비스 · 탑재 조회 필터가 다 생기고, 「확정」은 ADR-0026 과 중복이다. 계산으로 대신한다.
- **탑재 가능 여부만 상태로**(미사용 / 적용 2값) — 편집자가 올려야 하는 스위치가 하나 생긴다. 탑재 화면의 카운트가 같은 정보를 준다.

## 결과와 감수하는 비용

- 담보 상세 화면에 **탑재 수로 갈리는 두 모양**이 생긴다 — 미탑재면 트리에 추가 · 삭제 · 순서 조작, 탑재면 「구조 편집 →」 명령. [[기능/담보/담보]] 기본 탭 · 인수기준 개정.
- 「구조 편집」 명령 화면(영향 목록 + 트리 편집기)이 하나 는다 — 화면기획 §1 에 절 하나. 화면목록 · 와이어프레임 갱신은 그 화면기획 뒤.
- `Impact` 에 탑재 상품담보 목록 · 스냅샷 값 행 수를 더해야 한다 — 코드 몫. `syncStructure` 는 그대로 쓴다.
- [[기능/담보/담보]] 세부보장 · 급부의 전제 · 거부 열이 「탑재분 있으면 개발 모드」에서 미탑재 / 탑재 분기로 바뀐다. D-P2-6(순서 변경 = 구조 변경 → 거부) 은 「영향 표시 후 허용」으로 개정.
  [[기능/담보/시나리오/담보트리_시나리오]] S6 은 모드 분기 → 탑재 분기로 다시 쓴다 (시나리오 문서는 이번에 손대지 않았다).
- 디자인원칙 §2 L1 상태 글리프 · L3 확정 자물쇠 · Q13 · Q15 · Q19 · §9 「미사용 담보는 탑재 조회에 안 잡힌다」가 MVP 이후로 밀린다 — 소유자가 고친다.
- 문면이 있는 미탑재 담보의 구조 삭제는 참조를 깨뜨릴 수 있다 — 오류 상태로 드러나고 문면에서 고친다. 「담보를 만들며 문면을 같이 쓰다 급부를 뺀」 경우가 이 비용을 낸다.
- 미탑재 담보에서 방금 만든 빈 급부를 지우는 데도 관리자가 필요하다 — 1인 MVP(현재 사용자 = 관리자)에서는 체감 비용이 없고, 역할이 갈리면 그때 「값 · 참조 없는 노드 삭제는 편집자」로 좁힐 수 있다 (열어 둔 것).

## 열어 둔 것

- 「구조 편집」 명령의 영향 목록에 **문면 조연결 · 보통약관 준용**까지 실을지 — 조연결은 노드가 아니라 문서에 걸려 삭제 노드와 무관할 수 있다. 화면기획에서 정한다.
- 탑재된 담보의 **순서 변경**을 편집자에게 허용한 것(결정 2)은 추천안 밖의 판단이다 — 「없애지 않는다」 기준으로 비파괴로 봤다. 문면 수록 순서가 바뀌는 것을 파괴로 본다면 관리자로 올린다.
- 세부보장 · 급부의 **부모 이동**(D-P2-8 미제공)은 이 결정에서도 열지 않는다 — 값 행 소속 이관 규칙이 없다.
- 값 행 · 참조가 없는 노드의 삭제를 편집자에게 열지 — ADR-0019 경계(노드 삭제 = 파괴적)를 좁히는 일이라 그 ADR 의 개정으로 다룬다.
