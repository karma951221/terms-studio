## 맥락

옛 사내 시스템은 **서수 구분자**(1번째 · 2번째 … 5번째)를 썼다 — 같은 구분자를 서수마다 다시 채번했고, 세부보장 · 급부 레벨 구분자는 아예 없었다.
담보마다 담보 › 세부보장 › 급부 트리 모양이 달라서 「세부보장 하나 · 급부 하나」를 가리킬 공통 이름을 만들 수 없었기 때문이다. 서수가 다섯에서 끝나 그보다 큰 담보는 손으로 썼다.

이 시스템도 같은 벽에 닿는다.

- **함수조항은 트리 모양을 모른다.** 어느 담보약관에 들어갈지 모르는 채 쓰이므로 「세부보장 둘째의 급부 하나」를 본문에서 가리킬 수 없다.
- 그러나 **담보약관 템플릿은 담보 하나가 한 벌 소유**한다([[기능/담보/담보]] §3.5). 템플릿 안에서는 트리가 알려진 문맥이다 — 작성자가 「세부보장 01 의 급부 2 의 지급률」이라고 자유롭게 말할 수 있다.
- 마스터는 레벨마다 **어떤 잎이 있는가**(필드 · 구분자 · 타입 · 기본값)만 정하고, **가지가 몇 개이고 어느 가지를 쓰는가**는 담보마다다. 이 둘을 가르면 서수 구분자가 필요 없다.

지금 담보약관이 노드 하나를 가리키는 길은 `@노드` 한정자(ADR-0066)뿐이고 저장은 노드 id 다. id 는 담보 복제 · 문서 복제마다 새로 나 템플릿을 그대로 옮길 수 없고, 사람이 읽을 이름이 아니다.
함수조항 인자는 구분자 하나만 연결할 수 있어 「세부보장 01 의 감액 여부」를 넘길 길이 없다.

## 결정

1. **잎 = 레벨별 구분자 (그대로).** 입력은 마스터 필드이고, 값의 출처는 마스터 필드 기본값(프리필) → 담보 노드 값 → 탑재 스냅샷을 상품담보에서 고친 값 순이다. 탑재는 값 스냅샷이다 — 뒤의 담보 값 변경은 이미 탑재된 상품담보로 흐르지 않는다(ADR-0002 그대로).
2. **노드 키.** 세부보장 · 급부마다 그 담보 안에서만 뜻이 있는 키를 둔다 — 옛 시스템의 세부보장코드 · 급부번호와 같은 자리다.
   - 세부보장 `01` · `02` …(두 자리, 99 를 넘으면 자릿수를 늘린다), 급부 `1` · `2` …(그 세부보장 안). 형제 사이에서 유일하다.
   - **채번 = 비어 있는 가장 작은 번호** — `01` · `03` 이 있으면 새 세부보장은 `02`.
   - **지운 키는 다시 쓴다** — 실수로 `02` 를 더했다 지우고 다시 더하면 다시 `02` 이고, `02` 를 가리키던 참조가 다시 이어진다. 재사용에 영향 확인 대화상자를 두지 않는다.
   - **사람이 키를 고치지 않는다.** 순서 바꾸기(↑↓)는 키를 바꾸지 않는다.
   - **담보 복제는 키를 그대로 옮긴다** — 템플릿을 고쳐 쓰지 않고 복사할 수 있다. 문서 복제도 키 경로를 그대로 옮기고, 새 담보에 그 키가 없으면 끊어진 참조로 드러난다.
   - **상품담보의 스냅샷 노드는 같은 키를 갖는다** — 키는 이름처럼 뼈대 속성이다(값이 아니다).
3. **`@노드` 한정자의 저장 = 키 경로** (ADR-0066 결정 1 개정). 세부보장은 `01`, 급부는 `01` › `2`. 화면은 「세부보장 01 · 이름 › 급부 1 · 이름 › 구분자」. 문맥 담보 트리에 없는 키 = 끊어진 참조 오류(지금과 같다). 허용 범위(담보약관 템플릿만) · 레벨 검사 · 「항상 거짓」 경고는 그대로다.
4. **함수조항은 값(잎) 인자만 받는다** — 노드 타입 인자는 두지 않는다. 담보약관에서는 값 인자를 **키 경로 + 그 레벨의 구분자**에 연결한다(「세부보장 01 › 감액 여부」 · 「세부보장 01 › 급부 2 › 지급률」).
   - 기본 연결은 구분자만 적는다. 담보 레벨 구분자의 기본 연결은 지금처럼 걸린다. **세부보장 · 급부 레벨 구분자의 기본 연결은 키 경로가 없어** 사용처가 키를 고를 때까지 비어 있다 — 문서 저장에서 `argUnbound`(조 참조 인자와 같은 결, ADR-0083). 담보 트리 반복 안은 결정 8.
   - 보통약관 · 문맥 담보가 없는 자리에서는 키 경로 연결이 없다.
   - 프리셋(ADR-0084)은 키 경로를 담지 않는다 — 함수조항 안의 조합이라 담보를 모른다. 하위 레벨 구분자 인자는 「사용처가 채움」이다.
5. **담보 트리 위의 블록 반복** — 원천 「세부보장마다」 · 「세부보장 › 급부마다」를 더한다(담보약관 템플릿만, 트리 순서). 반복 안에서 조건 · 인자는 「현재 세부보장 › 잎」 · 「현재 급부 › 잎」을 읽는다. 중첩은 지금처럼 한 단계 — 「세부보장마다」 안에 「현재 세부보장의 급부마다」. 반복 표의 레벨 사슬(ADR-0070 결정 6)과 같은 사슬이다.
   **담보 트리 반복과 세목 반복(납입면제종마다 등)은 섞어 중첩하지 않는다 — 저장 오류.** 한 단계 중첩은 같은 계열 안에서만(종 › 사유, 세부보장 › 급부). 담보 값은 종마다 달라지지 않아(상품담보 값 하나) 섞어도 같은 글이 되풀이될 뿐이고, 커서 둘(세목 · 노드)이 겹치면 평가 · 인자 연결 · 조 참조 규칙이 커진다. 담보약관에서 종에 따라 문장이 갈리면 조건식으로 쓴다. 실물 사례가 나오면 연다.
6. **값 패널** — 담보약관 템플릿 편집기 우측 패널(미리보기 · 검증)에 「구분자」 탭을 더한다. 미리보기에서 고른 상품담보에 대해 이 템플릿이 읽거나 연결한 잎을 키 경로 + 이름으로 늘어놓고 지금 값을 보인다. 미입력 · 끊어진 키는 ⚠ + 좌표(조립 오류와 같은 표기). 설명은 구분자의 기존 「주석」(ⓘ)이다. 검수용 스냅샷 비교는 범위 밖이다.
7. **고르기는 담보 구분자 트리 하나** — 「담보 › 세부보장 01 · 이름 › 급부 1 · 이름 › 구분자」. 조건 머리 줄의 변수 칸(ADR-0066 결정 6)과 함수조항 인자 칸이 같은 트리를 쓴다. 급부가 하나뿐인 세부보장도 급부 층을 보인다 — 키는 늘 보인다.
8. **트리 반복 안의 기본 연결은 현재 노드로 저절로 푼다** — 하위 레벨 구분자를 기본 연결로 둔 인자를 담보 트리 반복 안에 넣으면, 그 구분자의 레벨이 감싼 반복의 현재 노드(또는 그 조상)의 레벨일 때 저절로 「현재 세부보장 / 현재 급부 › 그 구분자」가 된다. 반복 레벨보다 아래 레벨(「세부보장마다」 안의 급부 레벨 구분자)이면 결정 4 대로 `argUnbound`. 그 자리에서 키 경로로 바꿔 연결할 수 있다. 반복 표(한정자 없는 참조는 행 노드에서 평가) · 반복 안 조건의 규칙과 같다.
9. **반복 표 구조 표기 「급부 N」의 N 은 트리 순번 그대로다** — 산출 글은 순번, 키는 가리키는 데(저장값)만 쓴다. 「표기 = 순서, 정체 = 키」. 편집기 화면에는 키 + 이름을 함께 보인다. 키는 재사용 · 빈 번호(1 · 3)가 생겨 약관에 찍히면 실물과 어긋난다.
10. **트리 반복 안 노드를 가리키는 조 참조에 키 한정** — [[기능/문면/결정/ADR-0077-블록반복-세목선택지-열거목록-반복참조]] 결정 7 값 한정 참조와 같은 모양 · 같은 화면 · 같은 검사: 「세부보장 = 01 인 것」 · 「01 · 02」 · (반복 안이면) 「현재 세부보장」. 저장은 대상마다 `restrict: { keys: ["01"] }` · 급부는 키 경로 문자열 `"01.2"`(세부보장 키는 그 아래 급부 전부를 고른다). 펼친 대상 0개(키가 사라짐 등)면 조립 오류, 같은 회차 안 참조는 그 회차 사본, 반복 안 대상의 연결어 필수 — 모두 기존 규칙 그대로. 실물에 「제1항(○○진단비)에서 정한 …」처럼 특정 세부보장 것만 가리키는 문장이 있다.

11. **이행** — 기존 담보는 지금 형제 순서대로 키를 채운다(`01` · `02` …, `1` · `2` …). 저장된 `@<노드id>` 는 그 노드의 키 경로로 바꾼다. 시드는 다시 붓는다.

## 이유

- **문맥이 있는 곳에서만 가리킨다.** 트리 모양은 담보약관 템플릿만 안다. 함수조항을 노드에 묶지 않고 템플릿이 키 경로로 잎을 골라 값만 넘기면, 함수조항은 어느 담보에 넣어도 같은 시그니처다.
- **서수가 사라진다.** 「n번째」가 아니라 「세부보장 02」를 가리키므로 순서를 바꿔도 같은 노드다. 세부보장 · 급부 레벨 구분자를 서수만큼 다시 만들 필요가 없고 다섯의 한계도 없다.
- **키는 담보 안에서 읽힌다.** 옛 시스템의 세부보장코드 · 급부번호와 같은 모양이라 현업이 그대로 읽고, 템플릿의 참조가 사람 말로 보인다.
- **재사용이 실수를 되돌린다.** 잘못 더한 노드를 지우고 다시 더하면 같은 키 — 그 키를 가리키던 참조가 그대로 산다. 다른 뜻의 노드가 키를 이어받는 위험은 사용자가 감수한다 — 약관을 한 번 읽으면 드러난다.
- **복제가 그대로 된다.** id 저장은 담보 · 문서를 복제할 때마다 참조를 새 id 로 다시 매겨야 하고, 매기지 못한 것은 조용히 원본을 가리킨다.

## 버린 대안

- **노드 id 저장 유지(ADR-0066 결정 1)** — 복제마다 참조를 다시 매겨야 하고, 화면 밖(오류 좌표 · 값 패널)에서 사람이 읽을 이름이 없다.
- **순번(위치) 저장** — ↑↓ 한 번에 말없이 다른 노드를 가리킨다(ADR-0070 이 버린 이유 그대로).
- **오르기만 하는 키(지운 키를 다시 안 씀)** — 담보코드 · P코드와 같은 규칙이지만, 실수로 더한 노드를 지우면 그 번호가 영영 빈다 — 되돌릴 길이 없다.
- **함수조항에 노드 인자** — 함수조항이 트리 모양을 알게 된다. 사용자 방향은 「함수조항은 잎만 참조한다」이다.
- **키 직접 수정** — 중복 · 형식 검사와 「바꾼 키를 가리키던 참조」 규칙이 생긴다. 채번 + 재사용으로 충분하다.
- **살아 있는 상속(상품담보가 담보 값을 따라감)** — ADR-0002 가 버린 라이브 오버라이드다. 마스터를 고치면 판매 설계된 상품이 바뀐다.
- **서수 구분자(옛 시스템)** — 같은 구분자를 서수마다 채번하고, 순서가 바뀌면 다른 노드를 가리키며, 서수 수에 한계가 있다. ADR-0077 이 세목 쪽에서 폐지한 것과 같다.
- **트리 반복 안에서도 하위 레벨 기본 연결 = `argUnbound`** — 반복 안에서 늘 손으로 「현재 세부보장」을 연결해야 한다. 기본 연결이 지우려던 같은 연결의 반복이다.
- **구조 표기 번호를 키로** — 지운 키 재사용 · 빈 번호가 산출 글에 찍혀 실물과 어긋난다.
- **담보 트리 반복과 세목 반복을 섞은 중첩(두 커서 동시)** — 담보 값은 종마다 같아 글만 되풀이되고, 평가 · 연결 · 참조 규칙이 커서 둘 몫으로 커진다.
- **키 한정 없음** — 반복 밖 참조가 늘 펼친 것 전부라, 특정 세부보장 것만 가리키려면 반복 대신 손으로 나눠 써야 한다.
- **키 재사용 때 영향 확인** — 지운 키를 다시 쓰는 저장마다 묻게 된다. 실수 되돌리기가 주된 쓰임이라 묻지 않는다.

## 결과와 감수하는 비용

- **데이터** — 세부보장 · 급부에 키 칸(형제 유일), 스냅샷 노드에도 같은 키. 구조 저장(`applyStructurePlan`)이 새 노드에 빈 가장 작은 키를 매긴다 — 최종 트리 기준이라 같은 저장에서 지운 노드의 키도 빈 번호다. 탑재 스냅샷 동기화가 키를 옮긴다.
- **식 · 문면** — `DiscriminatorRef` 의 노드 참조가 키 경로가 된다(소스 표기는 구현 때 — 예 `D0007@01.2`). 조립은 스냅샷 노드를 키로 찾는다(지금은 마스터 노드 id 역조회). 참조 추출 · 관계정보 · 구조 정정 영향이 키 경로를 센다.
- **함수조항** — 구분자 연결에 키 경로 · 「현재 세부보장 / 현재 급부」가 생기고, 기본 연결이 하위 레벨 구분자이면 사용처마다 연결해야 한다(저장 검증이 빠뜨림을 잡는다).
- **반복** — 블록 반복 원천 둘, 복제 id 접미사 `@원소` 의 원소가 노드 키다.
- **편집기** — 담보 구분자 트리 · 변수 목록 · 인자 칸의 묶음 머리가 키를 보이고, 우측 패널에 「구분자」 탭이 선다. 담보 카드 머리의 레벨 라벨이 순번에서 키로 바뀐다.
- **조 참조** — 값 한정(`restrict`)에 `keys` 가 더해진다. 반복 블록 원소가 노드 키라 한정 해소가 원소 키를 거른다.
- **위험** — 지운 키를 다른 뜻의 노드가 이어받으면 옛 참조가 말없이 새 노드를 읽는다. 값 패널 · 미리보기로 보이고, 막지는 않는다.
