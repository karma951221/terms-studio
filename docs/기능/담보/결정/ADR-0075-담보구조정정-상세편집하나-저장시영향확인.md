# ADR-0075 — 담보 구조 정정: 상세 편집 하나 · 저장 시 영향 확인 · 담보 자체 상태는 MVP 에 없다

> 상태: 채택 · 날짜: 2026-09-27
>
> 맥락: ADR-0052(2026-09-14, 아카이브)를 번복한다 — 그 결정 2 「탑재된 담보의 구조 변경은 별도 명령 「구조 편집」」을 버리고, 나머지(생성 뒤 구조 정정 · 삭제는 관리자 · 담보 자체 상태 없음)는 이 ADR 이 이어받는다.
> 전제: [[공통/화면/결정/ADR-0019-모드폐지-역할권한]](파괴적 = 관리자 · 영향 확인 · 서버 거부) · [[기능/상품/결정/ADR-0002-탑재-값스냅샷]](구조는 마스터 소유 · 값만 스냅샷).
> 기능 문서: [[기능/담보/담보]] §3.2 · §4 「상세」.

## 맥락

ADR-0052 는 구조 정정 경로를 **탑재 수로 갈랐다** — 미탑재 담보는 상세 화면 편집 모드의 트리에서, 탑재된 담보는 트리 머리의 「구조 편집 →」 로 가는
별도 화면(`/coverages/<id>/structure`, 위에 영향 블록 · 아래에 같은 트리 편집기)에서. 그래서 담보 상세에는 탑재 수로 갈리는 두 모양이 있었고,
같은 급부 하나를 더하는 일이 담보에 따라 다른 화면 · 다른 저장 버튼으로 갔다.

2026-09-27 기획 세션에서 담보 상세를 탭 넷(기본 · 담보 · 세부보장 · 급부)에서 **탭 없는 한 화면(중첩 카드)** 으로 바꾸기로 했다 — 담보 카드 ⊃ 세부보장 카드 ⊃ 급부 카드,
카드마다 이름 + 그 레벨의 값 폼. 구조와 값이 한 화면에 같이 보이자 「구조만 따로 고치는 화면」이 설 자리가 없어졌다. 구조 편집 화면이 보이던 영향(탑재 상품담보 ·
스냅샷 값 행)은 편집 전에 볼 필요는 없고 **저장하기 전에** 보면 된다 — 영향은 무엇을 바꾸는지가 정해진 뒤에야 셀 수 있기 때문이다.

## 결정

1. **생성 뒤에도 구조를 고친다 — 탑재 여부와 상관없이 담보 상세의 `편집` 하나에서.** 세부보장 · 급부의 추가 · 순서 · 이름 · 삭제는 카드 위 조작(⊕ · ↑↓ · ✕ · 이름 인라인)으로
   초안에 담기고, 담보명 · 값과 함께 **저장 한 번 · 한 트랜잭션**에 들어간다. 규칙은 생성 화면과 같다 — 최소 구조(세부보장 1 · 급부 1) · 형제 이름 중복 금지(최종 트리 기준) · 순서는 데이터.
   - **추가 · 순서는 비파괴** — 편집자도 한다. 탑재분에는 추가 노드가 **미입력** 자리로 생기고(마스터 기본값의 사후 복사 없음, ADR-0002), 순서는 탑재 상품의 조문 수록 순서가 따라 바뀐다.
   - **삭제는 파괴적** — 마스터 값 행 · 탑재 스냅샷 값 행이 연쇄 삭제되고 참조가 깨진다. **관리자만**, 영향 확인 뒤. 편집자의 저장은 서버가 역할로 거부한다 (ADR-0019 — 화면 숨김이 아니라 서버 거부).
     미탑재여도 영향이 비어도 절차는 같다.
   - 담보약관 템플릿이 있어도 구조 수정을 막지 않는다 — 사라진 노드를 가리키는 반복 · 슬롯 · `@노드` 조건은 **오류 상태**로 드러나고 문면에서 고친다.
2. **영향은 저장할 때 확인한다.** 초안에 삭제가 섞이거나, **탑재된 담보**의 구조(추가 · 삭제 · 순서)가 바뀌면 저장이 아무것도 쓰기 전에 영향 대화상자를 띄운다 —
   소실될 마스터 값 행 · 깨질 참조 · 함께 지워질 하위 · **탑재 상품담보별 스냅샷 소실 행**. 확인하면 구조 적용과 **탑재 스냅샷 동기화**(추가 = 미입력 · 삭제 = 값 행 삭제 · 이름 · 순서 갱신)가
   담보명 · 값 쓰기와 같은 트랜잭션에서 일어나고, 어느 단계가 거부되면 전부 롤백된다. 이름만 바뀐 저장은 확인 없이 스냅샷 이름까지 맞춘다.
3. **「탑재됐는가」의 기준은 계산이다** — 탑재 상품담보 수 > 0. 담보에 이를 뜻하는 상태 값을 두지 않는다. 화면은 헤더의 「탑재 상품담보 N」 배지로 영향의 근거를 늘 보인다.
4. **담보 복제 · 문면 복제는 구조 정정의 경로가 아니다** — 「비슷한 담보를 하나 더 만드는」 경로다. 담보 복제는 트리 · 마스터 값만 복사하고, 문면이 필요하면 [[기능/문면/문면]] 「문면 문서 복제」로 따로 붙인다.

### 담보 상태

**MVP 에 담보 자체 상태(미사용 · 적용 · 확정)는 없다.** 「탑재 가능 · 작업 중」은 상태가 아니라 계산(탑재 상품담보 수 · 완결성 조회)으로 보이고,
「확정(더 못 고침)」은 [[공통/기술/결정/ADR-0026-이력개정-이력일자-작업본확정]] 의 작업본 / 확정 2상태가 **MVP 이후**에 맡는다 — 그때까지 화면에 자물쇠 자리는 없다.
[[공통/화면/디자인원칙]] 의 담보 상태 글리프 · 담보약관 확정 자물쇠는 그 시점으로 유예한다.

## 이유

- **편집 입구가 하나면 규칙이 하나다.** 탑재 수로 갈리던 두 모양은 「이 담보는 어디서 급부를 더하나」를 담보마다 다시 묻게 했다. 갈림의 실제 근거(탑재분이 영향을 받는다)는
  입구가 아니라 **저장 시 확인**에 두면 충분하다 — 탑재가 0 이면 확인이 뜨지 않을 뿐 조작은 같다.
- **영향은 초안이 정해진 뒤에 정확하다.** 구조 편집 화면의 영향 블록은 「지금 탑재 상황」만 보였고, 실제 소실 행은 저장 직전 확인에서야 나왔다. 저장 시 확인 하나가 둘을 다 준다.
- **원자성은 이미 있다.** 서비스 `applyStructurePlan` 이 계획 적용 · 값 행 정리 · 탑재 스냅샷 동기화를 한 트랜잭션에서 하고, 상세 저장은 `saveOnce` 로 담보명 · 구조 · 값을 한 트랜잭션에 묶는다 (점검 2026-09-27 H1 · D1).
  별도 화면을 두면 같은 트랜잭션 경로가 두 벌이 된다.
- **구조 불변은 값 스냅샷을 지키는 규칙이지 실수를 못 고치게 하는 규칙이 아니다** (ADR-0052 에서 이어짐). 생성 뒤 급부 하나를 빠뜨린 것을 발견하는 것은 정상적인 작업 과정이다.
- **상태 대신 계산** — 「탑재 가능」을 상태로 두면 올리는 것을 잊거나 잘못 올리는 두 번째 실수 경로가 생긴다. 탑재 수 · 완결성은 이미 세고 있고 거짓말을 못 한다.

## 버린 대안

- **탑재된 담보는 별도 「구조 편집」 명령 화면**(ADR-0052 결정 2) — 영향 블록을 먼저 보이는 장점이 있지만, 한 화면(중첩 카드) 안에서 구조와 값이 같이 보이는데 구조만 다른 화면으로
  보내면 입구가 둘이 된다. 영향은 저장 시 확인이 더 정확하다(초안 기준 소실 행). 편집 중 이동은 「버립니까?」 확인까지 요구했다.
- **탑재된 담보는 편집 모드에서 이름만** — 구조 정정 경로가 다시 사라진다(ADR-0052 가 고친 문제).
- **탑재된 담보의 구조 변경은 관리자만** — 추가 · 순서는 아무것도 없애지 않는다(ADR-0019 의 파괴적 판정 기준). 역할이 아니라 「없애는가」로 가른다.
- **경로 없음 — 새 담보로 다시 만든다(복제 → 수정 → 상품에 교체)** — 교체 시 값 · 담보속성 · 적용범위 · 조연결 승계가 따라와 반드시 싸지 않고, 문면은 복제 대상도 아니라 「문면까지 다시 쓰기」가 된다.
- **판본 작업본(ADR-0026) 도입 뒤 미확정 작업본일 때만 구조 편집** — 이력 · 작업본 기능 전체가 선행 조건이 된다.
- **담보 상태 3값을 MVP 에 넣는다** · **탑재 가능 여부만 상태로(2값)** — 도메인 · 스키마 · 탑재 조회 필터가 생기거나 편집자가 올려야 하는 스위치가 생긴다. 계산으로 대신한다.

## 결과와 감수하는 비용

- `/coverages/<id>/structure` 화면 · 「구조 편집 →」 링크 · 그 저장 액션이 없어졌다. 상세 저장 하나가 탑재된 담보의 구조까지 받는다(`edit-actions.ts`).
- 탑재된 담보에서 급부 하나를 더해도 저장 때 확인 대화상자가 한 번 뜬다(탑재 상품담보 목록) — 비파괴 변경에도 확인 한 번을 치르는 비용. 대신 영향을 모르고 저장하는 일이 없다.
- 편집 중에는 영향 목록이 화면에 늘 떠 있지 않다 — 헤더의 「탑재 상품담보 N」 배지가 「이 담보를 고치면 상품에 영향이 간다」의 근거다.
- 미탑재 담보에서 방금 만든 빈 급부를 지우는 데도 관리자가 필요하다 — 1인 MVP(현재 사용자 = 관리자)에서는 체감 비용이 없고, 역할이 갈리면 「값 · 참조 없는 노드 삭제는 편집자」로 좁힐 수 있다 (ADR-0019 개정 사안).
- 열어 둔 것 — 영향 목록에 문면 조연결 · 보통약관 준용까지 실을지 · 탑재된 담보의 순서 변경을 파괴로 볼지(관리자로 올릴지) · 세부보장 · 급부의 부모 이동(값 행 소속 이관 규칙이 없어 열지 않는다).
