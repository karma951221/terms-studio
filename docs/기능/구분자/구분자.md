# 구분자

> 상태: 초안 · 최종수정: 2026-09-27

## 1. 한 줄

조문이 묻는 개념 하나에 이름을 붙인 **식**이다 — 마스터 필드와 다른 구분자에 연산을 걸어 조문(조건식 · 반복 · 값 슬롯)에 값을 내보낸다.
편집자가 `/catalog` 에서 배포 없이 만들고 고친다. 조문은 입력 항목을 직접 보지 않고 구분자만 본다.

## 3. 규칙

### 3.1 구분자가 갖는 것

| 항목 | 규칙 |
|---|---|
| 코드 | `D0001` 식 **자동 채번 · 불변**. 유저가 입력하지 않는다 (ADR-0005) |
| 구분자명 | 자유롭게 바꾼다 — 식은 코드로 저장되니 안 깨진다. **같은 레벨에서 완전히 같은 이름은 거부** |
| 부착 레벨 | 상품 · 세목 · 담보 · 세부보장 · 급부 중 하나 — 식이 평가되는 자리(집계의 뿌리). **채번 뒤 못 고친다** — 고치려면 새로 만든다 (현재 코드, §5 미결) |
| 식 | 하나. 결과가 곧 값이다 — 종류(일반 · 상수 · 파생) 구분은 없다 (ADR-0036) |
| 결과 타입 | `string · number · boolean · date · enum · list<enum>`, 목록값이면 열거형변수까지. 명시하면 검사가 식의 추론 타입과 대조해 다르면 거부한다. 지금 코드는 **선택** — 미지정이면 추론 타입을 쓴다 (§5 미결). 명시하는 이유 — 추론만 하면 식을 고쳤을 때 타입이 조용히 바뀌어 조문 슬롯이 깨진다 |
| 설명 | 화면 이름은 「주석」. 「이 값은 **무엇을 근거로** 결정되는가」를 쓰는 자리(「상품 구조에서 직접 결정」 · 「급부 면책여부의 집계」). 목록 · 검색 결과 · 상세에서 식 옆에 같이 보인다 (§3.6) |

- **식은 데이터다** — 구분자 정의에 저장되고 화면에서 읽힌다. 새 구분자를 만드는 데 개발 요청이 없다.
  — 왜: 사내 기존 시스템은 파생 로직을 구분자마다 개발자에게 요청해 코드에 심었다 — 기획자가 식을 다시 볼 수 없고 손코드가 버그 · 중복의 원천이 됐다.
- 구분자는 입력을 받지 않는다 — 값 행 · 노출여부 · 기본값이 없다. 값은 조립 · 사전평가 때 매번 식으로 계산한다.
- 구분자 복제는 없다 — 중복 채번의 가장 쉬운 길이라서 (§3.6).
- **조문이 묻는 개념으로 딴다.** 입력 쪽 이름(면책여부)과 조문 쪽 이름(면책구분)이 달라도 된다 — 구분자가 그 번역층이다 (ADR-0036).

### 3.2 식이 부를 수 있는 것

- **마스터 필드** `폼키.필드키` · **다른 구분자** 코드 · 담보속성 `attr.X` · 내장 경로 `builtin.<레벨>.name` (ADR-0036 · [[기능/마스터/마스터]] §3.2).
- **같은 레벨은 그대로, 하위 레벨은 집계 안에서만, 상위 레벨은 거부** — 필드는 폼의 레벨로, 구분자는 그 구분자의 부착 레벨로 판정한다. MVP 는 상위 → 하위 방향만 — 하위가 상위 값을 스칼라로 받는 것은 MVP 이후.
  — 왜 구분자 참조를 여나: `면책구분` 을 정의해 두고 `지급구분 = 면책구분 and …` 로 쌓는 편이 식을 매번 펼쳐 쓰는 것보다 읽기 쉽고, 같은 로직이 여러 구분자에 복제되지 않으며, 추적이 구분자 단위로 끊어져 보인다.
- **집계** `any · all · sum · count · exist · not exist`. 집계 범위 = 부착한 노드의 하위 트리 — 따로 범위 문법이 없다. 담보 레벨 `any(pay.exempt)` 는 그 담보 아래 급부 전부, 세부보장 레벨이면 그 세부보장 아래 급부만.
  — 왜: 「어디 붙였나」가 곧 「무엇을 훑나」다. 사내 기존 시스템은 순회가 「담보의 모든 세부보장」으로 고정돼 세부보장 단위 조건식이 불가능했고 담보별 예외처리가 폭발했다 — 세부보장 단위 순회가 핵심 개선이다.
- **자기 참조 · 순환은 거부**. 평가는 참조 순서(위상 순)대로 풀고 깊이 제한은 없다. 순환은 검사와 평가 두 시점에서 거부한다.
- **세목 레벨 구분자는 세목 폼 하나의 필드만 읽는다** — 세목 선택지는 세목유형(폼) 하나만 가지므로, 두 폼을 읽는 식은 어느 선택지에서도 자리가 없다. 구분자 참조를 타고 들어가서도 같다.
- 없는 코드 · 없는 담보속성 값을 부르면 거부.
- 형제 · 다른 담보를 읽는 식은 없다 — 사내에서도 알려진 사례가 없다(2026-08-29 확인). 필요해지면 그때 참조 문법을 연다.
- **별칭**(식이 필드나 구분자 하나뿐) — 허용 + 경고. 조문이 필드를 직접 못 보니 필드 하나를 조문에 내는 길이 투영 구분자(`담보명 = coverage_basic.claim_name`)다.
  — 왜 경고인가: MVP 는 데이터가 없고 기획이 바뀌는 단계라 「값 하나에 이름 둘」을 막으면 실험이 막힌다. 막아도 `X and true` 같은 사실상 별칭은 못 막는다. 되돌아오는 길은 §3.6.
- **미입력을 참조하면 오류 + 좌표**를 낸다 — 조용히 넘어가지 않는다 (ADR-0004 · [[기능/조립산출/조립산출]]).

### 3.3 검사 — 저장 전 · 두 등급

「검사」 버튼으로 돌리고, 저장할 때 서버가 다시 막는다. 타이핑 중 자동 검사는 없다 — 매 키마다 파서가 돌고 한글 조합 중간 상태에 오류가 깜빡인다.

| 등급 | 항목 | 효과 |
|---|---|---|
| **오류** | 문법 · 명시 타입 ≠ 추론 타입 · 목록값인데 열거형변수 미선택 · 상위 참조 · 집계 없는 하위 참조 · 세목 폼 둘 · 없는 코드 · 자기 참조 · 순환 · **이 구분자를 (전이적으로) 참조하는 다른 구분자가 깨짐** | 저장 거부. 문구에 어느 구분자가 왜 깨지는지 (ADR-0049 §1) |
| **경고** | 별칭 · 식 · 타입 변경으로 깨질 **조문** 사용처 — 슬롯이 string · enum 밖이 됨([[기능/문면/문면]] §3.4) · 조건식이 읽던 타입이 바뀜. 참조하는 구분자를 거쳐 닿는 사용처까지 본다 | 저장된다. 확인창 없음. 상세 제목 옆 배지 |

- 자기 참조 · 순환 · 참조하는 구분자 검사는 **수정에서만** — 생성 때는 코드가 없어 아무도 새 구분자를 부를 수 없다.
- 오류가 있으면 경고는 내지 않는다 — 고칠 것은 오류 하나씩이다.
- 경고는 저장하지 않고 **읽을 때 계산**한다. 목록의 경고 칸은 별칭만 — 깨질 사용처는 구분자마다 그래프를 봐야 해서 상세에서만 본다.
- 두 층의 이유 — 구분자끼리는 정의 시점에 확실히 알고, 조문 · 상품이 실제로 깨지는지는 조립이 봐야 안다 (ADR-0049).
- 경고가 쌓여도 저장은 된다 — 목록의 「경고」 머리글 필터로 거른다.

### 3.4 변경 · 삭제

| 변경 | 누가 | 규칙 |
|---|---|---|
| 구분자명 · 주석 | 편집자 | 자유 (구분자명은 같은 레벨 중복만 거부) |
| 식 · 결과 타입 | 편집자 | §3.3 검사. 소실될 값이 없다 — 이후 평가부터 반영 |
| 부착 레벨 | — | 못 바꾼다 (현재 코드) |
| 삭제 | **관리자** | 편집자 요청은 서버가 거부. 관리자는 영향(깨질 조문 참조) 확인 뒤 삭제 — 남은 참조는 **깨진 참조 오류 상태**로 남는다 (ADR-0019 · ADR-0049 §2) |

- 깨진 것을 고치는 길은 원인 화면의 기존 편집 액션이다 — 식 변경 · 참조 제거 · 값 저장. 오류 좌표의 원천은 「고치면 사라지는 곳」 — 구분자 식이 원인이면 구분자 편집기다 (ADR-0049 §4).

### 3.5 dict — 문맥 트리를 dict 로 읽는 규칙

- **dict 는 새 구분자 종류가 아니다.** 가지 = 부착 레벨, key = **문맥 트리의 실제 노드**(상품세목 · 상품담보 · 스냅샷 세부보장 · 스냅샷 급부), 잎 = 그 레벨의 구분자. 원칙: 트리의 노드는 문맥 주입 실체, 마스터는 스키마 + 기본값 (ADR-0070 결정 1).
- 구조 상수 다섯 층(`LEVEL_STRUCTURE`): 상품 → 세목(세목명) · 세목 → 담보(상품담보명) · 담보 → 세부보장(세부보장명) · 세부보장 → 급부(「급부 N 급부명」, N 은 1부터) · 급부(잎). 자식 제공자는 MVP 에 담보 · 세부보장 둘만 — 상품 · 세목은 인터페이스만 (결정 2).
- key 의 정체는 **노드 id**다. 「세부보장코드 · 급부순번」은 표기 · 정렬일 뿐이다 (결정 3).
- 특정 key 의 값은 **`@노드` 한정자** 하나로 꺼낸다 — `D0102@<노드id>` ([[기능/문면/결정/ADR-0066-구분자-노드한정자-조건식-구조화팝업]] · 결정 4).
- 가지는 참조할 수 없고 조문 쪽 집계 문법도 없다. `max(감액비율)` · `count(급부)` 가 필요하면 **그 레벨의 구분자**로 정의한다 — 세부보장 레벨 잎 = 급부 잎의 집계 (결정 5).
- 이 규칙 위의 **반복 표**(담보 약관 템플릿의 세부보장 › 급부 행 반복 · 구조 표기 칩 · 행 문맥 평가 · 바깥 key 세로 병합 · 행 0 이면 표 생략)는 [[기능/문면/문면]].

### 3.6 중복 예방 — 막지 않고 근거 · 재사용 경로를 보증한다

- 시스템은 개념 중복을 「막는다」고 보증하지 않는다. 보증하는 것은 셋 — 구분자를 만들 때 **기존 구분자를 검색하고**, 각 구분자가 **무엇을 근거로 결정되는지**(식 · 설명 · 사용처)를 읽고, 새로 만드는 대신 **기존 개념을 직접 참조하는 쪽으로 돌아갈 수 있다**. 같은 개념인지는 사람이 판단한다 — 시스템은 후보를 보인다.
  — 왜: 같은 결과를 내는 두 식이 다른 업무 개념일 수 있고(체증 · 체감납 vs 보험료 가벼운 납입형 — [[00_시작/문제정의]] S2 · S4), 코드 자동 채번은 식별자 충돌만 막을 뿐 개념 중복을 판별하지 않는다.
- 구조 장치는 그대로다 — 코드 자동 채번 · 같은 레벨 구분자명 완전 중복 거부 · 복제 없음 · 「조문이 묻는 개념으로 딴다」(§3.1). 별칭은 허용 + 경고(§3.2).
- 생성 흐름 — **미구현** (넣기 패널에 검색이 없다):
  1. 구분자명 · 설명을 치는 동안 넣기 패널 「구분자」 탭이 **이름 · 설명 · 식 본문**(코드 · 표시명 둘 다)으로 기존 구분자를 찾아 같은 · 하위 레벨부터 보인다 — 레벨 배지 · 결과 타입 · 식 한 줄 · 사용처 수.
  2. 결과 줄마다 「이 구분자를 쓰기」 — 생성을 접고 그 구분자 상세로 간다. 조문에서 「새 구분자」로 들어왔으면 그 슬롯 · 조건식에 **직접 참조**로 꽂는다.
  3. 별칭으로 저장된 구분자 상세에는 경고 배지 옆 「직접 참조로 바꾸기」 — 사용처를 원 구분자로 옮기고 이 구분자를 삭제한다(삭제는 관리자).
- 검사의 **정보** 등급 — **미구현**. 「같은 식의 구분자 D0003(면책구분)이 있습니다」 · 「같은 필드 · 구분자를 참조하는 구분자 N건」. 저장을 막지도, 배지로 남지도 않는다 — 검색으로 가는 손잡이다.
  — 왜 경고가 아닌가: 같은 식이 다른 개념일 수 있어, 경고로 올리면 다른 두 개념이 영원히 경고를 달고 「경고 있음」 필터가 별칭과 섞인다.
- 중복은 생길 수 있다 — 사후 정리는 별칭 경고 필터 + 「직접 참조로 바꾸기」로 하고, 병합 도구는 만들지 않는다.

## 4. 화면

좌측 내비 첫 단계 「기본정보」의 항목 「기본정보」가 이 기능을 [[기능/마스터/마스터]]와 탭으로 묶는다 — 탭 **`열거형 | 폼 | 구분자`** 의 셋째(열거형 `/master/enums` · 폼 `/master` · 구분자 `/catalog`, 탭은 URL). 기능 · 주소 · 문서는 따로다 ([[기능/마스터/마스터]] §4 · §6.2). 내비 항목은 첫 탭(열거형)으로 가고 `/catalog…` 에서도 현재 위치다.
상세 · 생성의 경로 첫 마디는 「기본정보」이고 구분자 탭(`/catalog`)으로 간다.

### 4.1 `/catalog` — 조회 (L1)

```
기본정보                                                         〔+〕
열거형 폼 [구분자]
🔍[ 코드 · 구분자명 ]                          기준일 2026-09-27 🔒 미확정 포함 꺼짐 🔒
┌────────┬───────┬────────────────┬──────────┬──────┬────────────┬──────┐
│ 레벨 ▾ │ 코드   │ 구분자명         │ 결과 타입  │ 경고 ▾│ 최종수정    │ 수정자│
├────────┼───────┼────────────────┼──────────┼──────┼────────────┼──────┤
│ 세목    │ D0002 │ 납입면제여부      │ 참거짓    │ —    │ 2026-09-17 │ 홍길동│
│ 담보    │ D0001 │ 담보명           │ 문자열    │ 별칭  │ 2026-09-12 │ 홍길동│
│ 총 N건                                                   ‹ › │
└──────────────────────────────────────────────────────────────┘
```

| 자리 | 내용 |
|---|---|
| 제목 줄 | 「기본정보」 + `+`(새 구분자). 걸린 레벨 필터를 생성 화면으로 물려준다(`?level=`). 아래에 탭 줄 `열거형 \| 폼 \| 구분자`(구분자가 현재) |
| 검색 | 코드 · 구분자명 부분 일치. 디바운스 300ms · URL `?q=` |
| 기준일 · 미확정 포함 | 자리만 있고 잠김 — 이력 기능은 MVP 이후 ([[공통/기술/결정/ADR-0026-이력개정-이력일자-작업본확정]]) |
| 컬럼 | **레벨(1열 · 머리글 필터)** · 코드 · 구분자명(→ 상세) · 결과 타입(명시한 것만, 미지정은 「—」) · 경고(머리글 필터 있음 · 없음, 별칭 배지) · 최종수정 · 수정자 |
| 정렬 | 레벨 깊이순(상품 → 급부), 같은 레벨 안은 코드순. 레벨 1열은 「1열 = 코드」 규칙의 예외 (ADR-0070 개정) |
| 사용처 칸 | 없다 — 행마다 그래프를 훑는 비용 때문. 상세에서만 본다 |
| 페이저 | 50행 · `?page=` |

| 상태 | 표시 |
|---|---|
| 구분자 0건 | EmptyState — 「구분자는 조문이 묻는 개념 하나에 이름을 붙인 식이다 …」 + 예시(`담보명 = 담보.담보명 · 면책구분 = any(급부.보험금지급.면책여부)`) + 「새 구분자 만들기」 |
| 필터 결과 0 | 「이 조건에 맞는 구분자가 없습니다.」 |
| 서버 거부로 돌아옴 | `?error=` 배너 |

### 4.2 `/catalog/new` — 생성

제목 줄은 경로 `기본정보 › 새 구분자`(「기본정보」 → `/catalog`), 헤더 오른쪽에 「검사」 · 「생성」. 왼쪽 폼 + 오른쪽 **넣기 패널(상시)**.

| 칸 | 입력 | 비고 |
|---|---|---|
| 구분자명 | 텍스트 · 필수 | |
| 레벨 | 라디오 다섯 | 기본 담보(시드 최다) 또는 목록에서 넘어온 레벨. 힌트 「식이 평가되는 자리다. 채번 뒤에는 고칠 수 없다」 |
| 식 | mono 입력 · 필수 | 코드로 쓴다(예 `coverage_basic.claim_name` · `any(pay.exempt)`). 넣기 패널이 커서 자리에 넣는다 |
| 결과 타입 | 셀렉트(선택) | 목록값이면 「복수」 토글 + 열거형변수 셀렉트가 나타난다 |
| 주석 | 텍스트 | |

| 조작 | 결과 |
|---|---|
| 검사 | 폼 아래 「검사 결과」 — 오류(빨강) · 경고(노랑) · 추론 타입. 좌표가 있는 줄은 그 자리로 가는 링크. 검사 뒤 값을 바꾸면 「오래되었습니다 — 다시 검사」 |
| 생성 | 채번 → 상세로. 거부면 같은 화면 + 사유 배너 |

### 4.3 넣기 패널 (생성 · 수정 공통)

탭 셋, 항목을 **더블클릭 또는 Enter** 로 식 입력의 커서 자리에 넣는다. 패널이 **상시**인 것은 식을 쓰는 동안 참조할 것을 계속 봐야 해서다 — 다이얼로그 피커는 열고 닫는 동안 식을 가린다.

| 탭 | 내용 |
|---|---|
| 마스터 필드 | 폼별 트리. 지금 레벨보다 **상위** 폼은 흐리게 + 비활성(「상위 레벨은 참조할 수 없다」). 같은 레벨은 경로 그대로, **하위** 레벨은 타입에 맞는 집계로 감싸 넣는다 — 참거짓 `any( )` · 숫자 `sum( )` · 그 밖 `exist( )`. 커서가 이미 집계 괄호 안이면 경로만 |
| 구분자 | 같은 · 하위 레벨 구분자(자기 제외). 하위는 같은 규칙으로 감싼다 |
| 연산 | `any() · all() · sum() · count() · exist() · not exist()` · `and · or · not` · `= ≠ > <` … 집계는 괄호 안에 커서 |

### 4.4 `/catalog/<code>` — 상세 · 수정

제목 줄은 경로 `기본정보 › {구분자명}`(「기본정보」 → `/catalog`) ([[공통/화면/디자인원칙]] §1.7). 읽기 모드로 시작하고 「편집」 → 「저장」 하나로 전부 반영한다.

| 칸 | 읽기 | 편집 |
|---|---|---|
| 코드 | 글자(mono) | 못 고침 |
| 구분자명 | 잠긴 칸 | 입력 |
| 레벨 ⓘ | 글자 | 못 고침 |
| 식 ⓘ | 잠긴 칸(mono) | mono 입력 + 오른쪽 넣기 패널 |
| 결과 타입 ⓘ | 명시 타입 한 줄(`목록값(복수) · 해약환급금유형`), 미지정이면 「미지정 (추론: …)」 | 셀렉트 + (목록값이면) 복수 · 열거형변수 |
| 주석 | 잠긴 칸 | 입력 |

| 모드 | 헤더 오른쪽 |
|---|---|
| 읽기 | 제목 옆 경고 배지 · 「사용처 N」 · 「편집」 · 🗑 |
| 편집 | 「검사」 · ✕ · 「저장」 · 🗑(비활성, tooltip 「저장하거나 취소한 뒤 실행」) — 「사용처」는 감춘다. 검사 결과는 폼 아래 |

**사용처 모달** (「사용처 N」 — N = 조문 사용처, 참조하는 구분자를 거쳐 닿는 것 포함):

| 묶음 | 내용 |
|---|---|
| 조문 사용처 | 형태(조건식 · 치환 슬롯 · 노드 한정자 …) · 좌표(링크). 다른 구분자를 거쳐 닿으면 「… 을 거쳐」. 머리에 「N / 전체 참조 M」. 0 이면 「아무 조문도 이 구분자를 읽지 않는다.」 + 「약관 템플릿에서 쓰러 가기 →」 |
| 참조하는 구분자 | 코드 · 구분자명(링크) · 경유 경로 (전이적) |
| 영향 받는 상품 | 상품(→ 미리보기) · 경유 |

| 조작 | 결과 |
|---|---|
| 편집 → 저장 | 구분자명 · 주석 · 식 · 결과 타입을 **한 트랜잭션**에 (이름 → 주석 → (타입 해제) → 식 → 타입 순). 서버가 §3.3 오류로 거부하면 앞 단계까지 전부 롤백 · 편집 유지 + 사유 |
| ✕ · 경로 링크(편집 중) | 변경 있으면 「고친 내용을 버립니까?」 |
| 🗑 (읽기에서만) | 툴팁에 닿는 조문 수. 편집자는 거부, 관리자는 영향 확인 후 삭제 → 목록. 편집 중에는 꺼진다 — 즉시 실행 명령이라서 (디자인원칙 §2 L2) |

| 상태 | 표시 |
|---|---|
| 없는 코드 | 경로 `기본정보 › <코드>` + 「찾을 수 없습니다.」 |

`/catalog/enums` 는 `/master/enums` 로 리다이렉트한다 ([[기능/마스터/마스터]] §4.4).

## 5. 미결

- **결과 타입 명시 필수** — 결정(§6.2)은 「유저가 명시한다」인데 코드는 선택(미지정이면 추론). 필수로 올릴지 결정 필요.
- **부착 레벨 변경** — 결정(§6.2 · ADR-0049 §2)은 「바꿀 수 있고 경고」인데 코드는 「채번 뒤 불변 — 고치려면 새로 만든다」(바꾸면 조문 사용처의 뜻이 조용히 달라진다). 어느 쪽을 정본으로 할지 결정 필요 — 지금은 코드대로 불변.
- **경고 상세 화면**(원인 → 깨진 조문 → 영향 받는 상품 · 줄마다 「고치러 가기」 · 「해당 상품 재검사」 · 같은 원인 묶기 — ADR-0049 §3) — **미구현**. 지금은 검사 결과의 좌표 링크와 사용처 모달의 세 묶음이 대신한다.
- **중복 예방 흐름**(§3.6) — 넣기 패널 구분자 탭의 검색, 「이 구분자를 쓰기」, 정보 등급 검사 줄, 별칭의 「직접 참조로 바꾸기」 — **미구현**.
- **표시명 토큰** — 식 입력에 표시명(`급부.면책여부`)을 보이고 저장은 코드로 하는 것 — **미구현**. 지금은 코드를 그대로 쓴다.
- 검사 결과의 참조 줄마다 「마스터에서 보기」 · 「구분자 열기」 — **미구현**.
- 참조하는 구분자가 남은 구분자의 삭제 — 거부로 올릴지 (ADR-0049 열어 둔 것 ①). 세목 범위가 바뀌는 식 수정을 경고로 둘지 오류로 올릴지 (③).
- 구분자 생성 시 설명 필수 여부(근거 없는 채번을 막는 가장 싼 장치지만 「임시」 설명이 쌓일 위험 — 실물 이관 뒤) · 「직접 참조로 바꾸기」의 범위(조문 사용처만 옮기나, 이 별칭을 참조하는 다른 구분자의 식까지 고치나).
- 별칭 · 레벨 변경 경고를 데이터가 쌓인 뒤 오류로 올릴지.
- 수치 집계 `max` · `min` (ADR-0036 · ADR-0037).
- dict: 상품 문맥 반복 · 입력 dict(열거형 key) · `buildShapeTree` 처분 (ADR-0070 열어 둔 문제).
- 구분자 유효값 목록 · fallback · 검증 규칙(A 형) · 하위 → 상위 스칼라 참조 — MVP 이후.

### 6.2 결정 메모

| 결정 | 왜 | 버린 안 |
|---|---|---|
| 식은 데이터 — 구분자 정의에 저장 (§3.1) | 파생 로직이 블랙박스 손코드로 쌓이지 않고, 새 구분자에 개발 요청이 없다 | 구분자마다 개발자가 코드에 심기(사내 기존 방식) |
| 집계 범위 = 부착 노드의 하위 트리, 범위 문법 없음 (§3.2) | 「어디 붙였나」 = 「무엇을 훑나」 · 세부보장 단위 순회 | 순회 고정(담보의 모든 세부보장) · 별도 범위 지정 문법 |
| 형제 · 다른 담보 참조 없음 (§3.2) | 알려진 사례가 없다(2026-08-29) | — (필요해지면 연다) |
| 구분자가 같은 · 하위 레벨 구분자를 참조 · 순환 거부 · 위상 순 평가 (§3.2) | 재사용 · 복제 방지 · 추적이 구분자 단위로 끊어진다 | 구분자 → 구분자 참조 금지(「다단 파생 MVP 제외」) |
| 결과 타입은 명시 · 추론과 대조 (§3.1) | 식 변경으로 타입이 조용히 바뀌어 슬롯이 깨지는 것을 잡는다 | 추론만 |
| 검사는 「검사」 버튼 + 저장 때 서버, 두 등급 (§3.3) | 타이핑 중 검사는 비용 · 한글 조합 깜빡임 | 타이핑 중 즉시 검사 |
| 별칭 허용 + 경고 — 「별칭형 파생 금지」(2026-09-01) 폐기 (§3.2) | MVP 는 실험을 막지 않는다 · 투영 구분자는 필드를 조문에 내는 유일한 통로 | 별칭 · 레벨 변경을 오류로 · 별칭 금지 복원(`X and true` 같은 사실상 별칭은 못 막는다) |
| 넣기 패널 상시 (§4.3) | 식이 가려지지 않는다 | 다이얼로그 피커 |
| 중복은 막지 않고 검색 · 근거 · 재사용 경로를 보증 (§3.6) | 개념 동일성은 「무엇을 근거로 결정되나」라 사람이 안다 | 자동 병합(다른 개념을 합치면 못 나눈다) · 채번 승인 · 의미 유사 자동 제시(MVP 밖) · 설명 없으면 저장 거부(열어 둠) |
| 같은 식 · 같은 참조 후보는 정보 등급 (§3.6) | 경고로 올리면 다른 개념이 영원히 경고를 단다 | 경고 등급 |
| 상세 저장 = 한 트랜잭션 (§4.4, 2026-09-27 점검 D1) | 저장이 서비스 여러 번이라 식이 거부돼도 구분자명 · 주석 · 해제한 명시 타입이 남았다(H1). 액션 전체를 `saveOnce` 로 감싸 거부면 롤백 — 순서에 따라 결과가 갈리는 곳이 아니라 최종 한 벌 연산은 두지 않는다 | 식 + 타입을 한 번에 검증 · 저장하는 서비스(전부 최종 한 벌 연산) · 해제 전 식 사전 검사(순환 · 의존 거부는 못 막았다) |
