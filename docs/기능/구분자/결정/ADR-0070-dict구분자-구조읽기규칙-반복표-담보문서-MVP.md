## 맥락

사용자가 「dict 타입 구분자」를 새로 기획하자고 했다 — 트리에서 key 는 안 보이고, value 는 primitive 타입 구분자 또는 다시 dict. 목적은
**「스키마가 상품담보에 따라 다른 경우」에 유연하게 대응하는 것**이었다. 질문을 이어가며 뜻이 좁혀졌다.

1. 처음엔 「열거형 key 를 상품담보가 골라 넣는 입력 dict」(피보험자 구분별 감액 `{ 일반: {기간, 비율}, 고령: {…} }`)로 읽혔고, 그 전제로 key 제약 = 열거형 · 입력 UI = 첫 열이 열거형인 표 · 중첩 한 단계까지 정했다.
2. 그런데 「첫 시드가 무엇인가」에서 실물이 드러났다 — **담보모델링에서 이미 정의된 구조**(담보 아래 세부보장 몇 개, 세부보장 아래 어떤 급부, 급부의 감액 · 면책 값)를 dict 트리로 보고 싶은 것이고,
   key 는 「세부보장코드 · 급부순번」이다. 즉 dict 는 **입력이 아니라 문맥 구조의 투영**이다. 담보마다 스키마가 다르다 = 담보마다 세부보장 · 급부 **수가 다르다**.
3. 이어서 「담보 ↔ 상품담보(문맥 주입 실체)」 구분을 세목에도 적용하자는 논의가 붙었다 → [[기능/상품/상품]] §3.2(세목 기본값).

이 투영을 문면이 쓰려면 **반복**(key 마다 행)이 필요하다. 그런데 사흘 전 ADR-0068(흡수 → [[QA/인수기준]] MVP 범위) 이 반복 · 동적 표를 MVP 밖으로 보냈다 — 이유는 「동적 표의 입력 규칙 · 표 스키마 복잡도(L 이상)」였다.

## 결정

| # | 결정 | 내용 |
|---|---|---|
| 1 | **dict 는 실체가 아니라 읽기 규칙** | 새 구분자 종류 · 가지 구분자 행 · 부모 필드를 만들지 않는다. **가지 = 부착 레벨**, **key = 문맥 트리의 실제 노드**(상품세목 · 상품담보 · 스냅샷 세부보장 · 스냅샷 급부), **잎 = 그 레벨의 구분자**(시드 · 유저 구분 없음). 마스터는 스키마와 기본값만 댄다. 원칙 한 줄: **트리의 노드는 언제나 문맥 주입 실체, 마스터는 스키마 + 기본값** |
| 2 | **다섯 층 구조 상수** | 레벨 → 자식 레벨 · key 표기 규칙을 코드 상수로 선언한다: product→plan(세목명) · plan→coverage(상품담보명) · coverage→subCoverage(세부보장명) · subCoverage→benefit(「급부 N」 + 급부명, N = order) · benefit(잎). **자식 제공자**(노드 → 자식 노드들)는 레벨별 인터페이스이고 MVP 구현은 coverage · subCoverage 둘(문맥 담보 스냅샷). plan · product 제공자(종·형 조합의 탑재)는 인터페이스만 |
| 3 | **key 의 정체는 노드 id** | 저장은 ADR-0066 그대로 `D0102@<노드id>`. 「세부보장코드 · 급부순번」은 **화면 표기와 반복 표 정렬 기준**이다. `SubCoverage` 에 코드 필드를 새로 두지 않는다 |
| 4 | **key 지정 = `@노드` 하나** | dict 에서 「특정 key 의 값을 꺼내기」는 새 표기(`[key]`)가 아니라 기존 노드 한정자다. 같은 뜻에 표기 둘을 두지 않는다 |
| 5 | **가지는 참조 불가 · 문면 집계 문법 없음** | 가지는 구분자가 아니니 코드가 없다. `max(감액비율)` · `count(급부)` 가 필요하면 **그 레벨의 시드 구분자**로 코드에 더한다(세부보장 레벨 잎 = 급부 잎의 집계). ADR-0066 「집계는 구분자 정의에」 유지 |
| 6 | **반복 표** | `TableNode` 에 `repeat?: { depth: 1 \| 2 }` — 문맥 노드에서 내려가는 깊이(담보 문서: 1 = 세부보장마다, 2 = 세부보장 › 급부마다). 머리글 행은 그대로, **나머지 행이 템플릿**으로 key 조합마다 복제. 인라인 노드 `structKey { level }` 가 key 표기 칩. 반복 행 안의 한정자 없는 구분자 참조는 **현재 행 노드의 자기-또는-조상 중 구분자 레벨과 같은 노드**에서 평가하고, 행 레벨보다 아래 레벨 참조는 오류. **바깥 key 열은 세로 병합 자동**(같은 노드가 이어지는 동안 rowSpan), 그 외 병합은 이번 범위 밖([[기능/담보/담보]] §3.5). key 조합이 0 이면 **표 노드 통째로 생략**. 행 안 미입력 셀은 지금 슬롯 규칙(조립 오류 → 자리 안내). 담보 약관 문서에서만(ADR-0066 §2 와 같은 선) |
| 7 | **범위 (MVP)** | 담보 문서의 세부보장 › 급부 반복 표 · `DictType` 자리 선언. **이후**: 상품 문맥 반복의 세목 › 담보(보통약관 · 별표 — 세목 선택지 · 열거 목록 위 블록 반복은 ADR-0077 로 들어왔다) · 입력 dict(열거형 key · 첫 열 열거형 표 UI) · 문장 반복 · 3층 이상 중첩 · dict 안 `table` · 붙박이 최초지급금액표(ADR-0042 · 0058) 대체 |
| 8 | **조회 화면은 평면 표 · 레벨 1열** (2026-09-27 개정) | `/catalog` 은 평면 표다. **레벨이 1열**이고 그 머리글이 필터, 행은 **레벨 깊이순**(상품 → 급부) · 같은 레벨 안 코드순. 모양(레벨 구조)은 레벨 컬럼 + 정렬로 읽는다 — 가지 트리는 두지 않는다. 조회 공통 규칙(검색 · 필터 · 페이저)은 유지 |
| 9 | **타입 자리** | `src/domain/types.ts` 에 `DictKeyRule`(`node(level)` \| `enum(enumCode)`) · `DictType`(key · value 재귀)을 선언하고 구조 상수가 이 타입으로 적힌다. `Discriminator` · `DiscriminatorResultType` · 식 파서 · 저장 형식은 **바뀌지 않는다** |
| 10 | **ADR-0068 결정 2 번복** (2026-09-30 개정 — ADR-0077) | 반복이 MVP 로 돌아온다 — **표 행 반복**(결정 6)과 **블록 반복**(`forBlock` — 세목 선택지 · 열거 목록 원천, 한 단계 중첩, ADR-0077). `inlineFor` 는 여전히 자리만. 결정 1(최초지급금액표 생성기 · 셀 계산)은 별개로 그대로 MVP 밖. 결정 3 · 4(대표 변형 한정 · 「구조 변경은 문면 수정 동반」 제한)는 **M01 에서 재검토** — 반복 표가 있으면 구조 변형이 대표 변형에 들어올 수 있으나 이 ADR 은 정하지 않는다 |

## 이유

- **번복 사유 — 복잡도의 원천이 사라졌다.** ADR-0068 이 반복을 뺀 이유는 「동적 표의 입력 규칙 · 표 스키마(속성 5개로 부족)」였다. dict 를 **구조 투영**으로 읽으면 반복의 key 집합은 새 입력이 아니라
  **담보모델링이 이미 만든 구조**에서 오고, 값은 ADR-0065 시드 폼에서 온다. 새 입력 UI · 새 스키마가 없다. 남는 것은 표의 `repeat` 속성과 행 문맥 평가뿐이다.
- **아픈점이 여기 있다.** ADR-0066 이 적은 「세부보장 · 급부 하나를 가리키는 담보는 동적 표를 못 타고 손으로 쓴다」와 ADR-0068 의 알려진 제한 「구조 변경은 문면 수정을 동반」이
  같은 것이다. 반복 표가 있으면 세부보장 · 급부를 더해도 표가 따라온다.
- **실체를 만들지 않아야 정보가 한 곳에 산다.** 가지를 구분자 행으로 시드하면(접근 2) 식 없는 · 참조 불가한 구분자에 검사 · 사용처 · 삭제 규칙마다 예외가 붙고, 담보 트리 정보가 마스터와 카탈로그 두 곳에 산다.
  읽기 규칙이면 ADR-0066 의 `@노드` 평가기 · 트리 패널을 그대로 확장한다.
- **id 가 정체다.** 급부순번은 `reorderBenefits`(ADR-0075) 한 번에 다른 급부를 가리키게 된다. ADR-0066 이 이름 지목을 버린 이유와 같다.
- **다섯 층을 선언하되 두 층만 구현한다.** 상품 문맥 반복의 추가분은 dict 문제가 아니라 「문맥 없는 템플릿에서 반복하기」와 「붙박이 표를 대체할 것인가」라는 별개 결정이다.
  반복 원천을 「문맥 노드에서 깊이 N」 + 레벨별 자식 제공자로 두면 나중에 제공자 하나(탑재)로 열린다.
- **행 0 이면 표를 생략한다.** 「없으면 없다」가 ADR-0004 와 결이 같고, 표 앞 문장은 이미 있는 조건식(`exist(담보.감액여부)`)으로 감싼다.

## 버린 대안

- **입력 dict(열거형 key 를 상품담보가 골라 넣음)** — 기획 초반의 해석. 첫 시드가 담보 구조 투영으로 드러나 MVP 에서 빠짐. key 규칙 `enum` 자리는 타입에 남긴다.
- **key 마다 타입이 다른 가변 스키마를 정의에 둠** — 가변 key 에 타입을 누가 정하나가 남는다. 타입은 잎(구분자)이 들고 온다.
- **가지를 구분자 행으로 시드 · `parentCode`** (접근 2) — 위 이유.
- **저장 정체 = 세부보장코드 · 급부순번** — 순서 변경에 깨짐. 세부보장 코드 채번 규칙도 새로 필요.
- **`[key]` 표기를 `@노드` 와 병존** — 같은 뜻에 표기 둘. 검사 · 사용처 · 구조 정정 영향을 두 번 만든다.
- **가지 자체를 `exist(가지)` 로 참조** — 「가지의 결과 타입」 개념을 다시 끌어온다. `any(잎…)` 잎을 하나 더 만들면 된다.
- **팝업에 집계 선택기(`max · min · count · exist`)** — ADR-0066 §8 「집계 직접 사용」 번복. 뜻은 구분자 한 곳에.
- **표당 반복 한 겹(담보 문면은 세부보장만, 급부는 세부보장 문면에서)** — 표가 세부보장 수만큼 쪼개지고 작성이 번거롭다. 실약관 보장내용 표는 한 표 · 겹반복이다.
- **빈 표 = 머리글만 / 조립 오류** — 실약관에 없는 모양 · 작성자에게 조건 강제. 생략이 ADR-0004 결.
- **다섯 층 전부 이번에(상품 문맥 반복 포함)** — 위 이유. 열어 둔 문제로.
- **문장 · 항목 반복(「일반은 50%, 고령은 30%」)** — 연결어 규칙([[기능/문면/문면]] §3.5 가 둘로 좁힌 이유)과 얽힌다. 실약관의 「구분별 …」은 거의 표.
- **`table` 을 dict 가 흡수** — 감액 구간(행 = 구간)은 열거형 key 가 없다. 「순서 있는 구간」과 「이름으로 찾는 항목」은 다른 질문. 병존.
- **3층 이상 중첩 · dict 안 `table`** — 이번 시드에 없다. 타입은 재귀로 열어 둔다.

## 결과와 감수하는 비용

- **ADR-0068 이 사흘 만에 일부 번복**된다 — 결정 2 만. 결정 1 은 유지, 결정 3 · 4 는 M01 로. ADR-0068 상태 줄과 [[실행/MVP_개발현황]] §2.8 · §4 에 반영. R02 항목은 「최초지급금액표 출력」으로 좁혀진다.
- ADR-0066 §2 「담보 약관 문서만」 · §6 트리 패널은 유지되고 **「현재 행」 가지**(한정자 없는 잎)가 반복 셀에서 맨 위에 추가된다.
- 산출본 표에 `rowSpan` 이 생긴다 — 출력기(HTML · 미리보기)에 병합 렌더가 붙는다. 그 외 병합(가로 · 「같으면」)은 이후 — 표 출력(최초지급금액표)과 함께.
- 조회 화면 `/catalog` 은 레벨 1열 평면 표가 된다 — 코드 1열 규칙([[공통/화면/디자인원칙]] §2 L1)의 예외 (「개정」).
- 대표 변형(M01)에 「세부보장 · 급부 수 변형」을 넣을지 판단할 수 있게 된다. 넣으면 인수표의 알려진 제한 4 가 지워진다.

## 구현 메모 (2026-09-27)

설계([[기능/구분자/구분자]])가 정하지 않고 구현 중 판단한 것들 — 놓치지 않도록 여기 남긴다. 커밋 `a7918ee`..`ad3edee`.

1. **급부 key 표기는 「급부 {order+1} 이름」** — `order` 는 0-based 저장값이고, 사람이 세는 순번(1부터)으로 보이려고 화면·산출본 표기에서만 1 을 더한다. 저장 · 비교는 그대로 `order`.
2. **바깥 key 세로 병합은 템플릿 행이 1줄인 표에서만** 자동으로 된다. 템플릿이 여러 줄이면(한 세부보장 안에 행이 둘 이상) 그 병합은 「그 외 병합」 범위라 이번엔 하지 않는다 — 함께 이후 과제로.
3. **행 안 집계 참조는 허용, 행 레벨보다 아래 레벨의 직접 참조만 오류.** 즉 `count(급부구분자)` 처럼 행(세부보장)에서 그 아래 레벨(급부)을 **집계해** 묻는 것은 되고, 한정자 없이 그 아래 레벨 구분자를 직접 가리키는 것만 §2.6 넷째 줄의 오류다.
4. **「모든 행이 같아집니다」 경고는 저장을 막지 않는다** — `services.document.validate` 에서만 뜨는 경고고, 도메인 저장 경로 자체는 막지 않는다(§2.6 표의 경고 등급 그대로).
5. **별도 HTML 내보내기가 없어** `rowSpan` 은 미리보기(`RenderedDoc`)와 편집기 렌더(`StaticNodes`)에만 반영했다 — 설계 §3.3 이 말한 「HTML 내보내기도 같은 경로」는 그 기능이 생기면 자동으로 같은 경로를 탄다.
6. **「표 생략됨」 자리표시는 편집기 미리보기(사전평가)에서만** 보인다 — 조립 산출본에는 표 노드 자체가 없다(설계 §3.1 그대로, 명확히 기록).
7. **셀 선택은 `?node=<표>&cell=<행>-<열>` 쿼리**로 뒀다 — `setTable` 이 만드는 텍스트 노드 id 가 셀 표식과 겹쳐서 셀 id 를 못 쓴다. 칩(구조 표기)·슬롯이 이미 든 표는 행 textarea 가 잠기고 셀의 「＋」로만 더 추가한다.
8. **`/catalog` 칸에 「사용처」를 넣지 않는다** — 행별로 그래프를 훑어야 하는 계산 비용 때문. 사용처는 상세 화면에서만 본다 (2026-09-27 사용자 확인).
9. **편집기 for 띠는 인라인 스타일**로 넣었다 — 당시 `globals.css` 에 다른 작업(외부)의 미커밋 변경이 있어 같은 파일을 건드리면 충돌하므로 회피했다. 후속 정리 대상(아래 열어 둔 문제).

## 개정 (2026-09-27) — 결정 8 번복: `/catalog` 은 다시 평면 표

같은 날 오전 커밋 `a051919` 로 들어간 5층 모양 트리를 오후 UI 검토 세션에서 사용자가 보고 되돌렸다.

**무엇이 바뀌나**

- `/catalog` 은 **평면 표**다. **레벨이 1열**이고 그 컬럼 머리글이 곧 필터다(다른 목록과 같은 문법 — 머리글 필터). **경고 필터도 다시 경고 컬럼 머리글로** 돌아간다(트리 때 옮겼던 「검색 옆 별도 필터 줄」은 없어짐).
- 행 정렬은 **레벨 깊이순**(상품 → 세목 → 담보 → 세부보장 → 급부), 같은 레벨 안에서는 코드순. 트리가 주던 「레벨별로 모여 보인다」는 정렬이 대신한다.
- 나머지 칸(코드 · 구분자명 · 결과 타입 · 경고 · 최종수정 · 수정자)과 「사용처 칸 없음」(구현 메모 8 의 사용자 확인)은 그대로.
- `ShapeTree` 컴포넌트와 CSS 는 지웠다. 순수 함수 `buildShapeTree`(`src/domain/catalog/shapeTree.ts`)는 **당분간 남긴다** — 화면에서 쓰지 않는다(아래 열어 둔 문제).

**왜** — 사용자: 「너무 많아서 보기 힘든데」. 다섯 가지가 겹겹이 펼쳐지면 구분자 수가 적어도 가지 머리 · 들여쓰기가 먼저 눈에 걸려 훑기 어렵다.
결정 8 의 이유였던 「모양을 보인다」는 조회 화면의 일이 아니었다 — 조회는 찾고 거르는 곳이고, 모양(레벨 구조)은 레벨 컬럼 + 깊이순 정렬로 충분히 읽힌다.
dict 읽기 규칙(결정 1 ~ 6)은 화면 모양과 무관하므로 영향이 없다.

**버린 대안**

- **트리 유지(오전 구현 그대로)** — 위 이유.

**감수하는 비용**

- 레벨이 1열이라 [[공통/화면/디자인원칙]] §2 L1 「1열은 항상 조회대상의 코드」에서 벗어난다 — 묶음 기준 열을 앞에 두는 예외로 L1 절에 적었다(마스터의 「폼」 1열과 같은 결, [[기능/마스터/마스터]] §4.1).
- 오전 구현의 트리 코드 일부(CSS · 컴포넌트)가 반나절 만에 사라졌다. `buildShapeTree` 는 테스트와 함께 남아 있어 쓰는 곳 없는 코드가 된다.
