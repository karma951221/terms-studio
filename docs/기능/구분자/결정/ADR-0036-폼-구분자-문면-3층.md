# ADR-0036 — 값의 체계는 3층: 폼(입력) → 구분자(식) → 문면 (ADR-0035 번복)

> 상태: 채택 · 날짜: 2026-09-12
> 개정 반영: 2026-09-27 ADR-0037 · [[기능/마스터/마스터]] §3.1 · §3.2 (1층 = 코드 폼 › 필드, 참조 경로 `폼키.필드키`) · [[기능/구분자/구분자]] §3.1 · §3.2 (구분자 참조 · 결과 타입 명시) — 원본은 _archive/2026-09-27_문서재편/06_결정/
>
> 같은 날 채택한 ADR-0035(아카이브) 를 **번복**한다. 구분자 실체는 남고, 대신 입력과 구분자의 역할을 가른다.
> 1층(입력)의 모양은 [[기능/마스터/결정/ADR-0037-입력항목-코드마스터-유저정의폼-MVP이후]] · [[기능/마스터/마스터]] §3 이 정한다 — 이 ADR 의 정본은 2층(구분자 = 식) · 3층(문면은 구분자만)이다.

## 맥락

ADR-0035 는 구분자 실체를 없애고 폼 하나에 필드 종류 셋(상수 · 입력 · 파생)을 두는 안이었다.
문서 반영 직후 의뢰인이 다시 봤을 때 걸린 것은 **문면 편집기에서 조건식을 쓰는 순간**이었다 —
「보험금지급 폼의 면책여부 필드」처럼 폼 필드를 조건식이 직접 부르는 게 어색하다.
문면이 묻는 개념(면책구분 · 최대지급률 …)과 모델링 화면이 받는 입력(면책여부 · 지급률 …)은 같은 층이 아니다.

## 결정

**값의 체계를 세 층으로 가른다.**

| 층 | 실체 | 하는 일 | 갖는 것 |
|---|---|---|---|
| 1 | **입력 마스터** (코드 폼 › 필드) | 모델링 화면에 드러나는 입력 항목 | 폼(레벨 하나) › 필드(타입 · 기본값) — 코드가 정본 (ADR-0037 · [[기능/마스터/마스터]] §3.1) |
| 2 | **구분자** | 마스터 필드(와 다른 구분자)에 연산을 걸어 문면이 묻는 개념에 이름을 붙인다 | 이름 · 부착 레벨 · 결과 타입 · **식 하나** |
| 3 | **문면** | 조건식 · 반복 · 값 슬롯 | **구분자만** 참조 |

1. **입력 항목은 입력 하나뿐이다.** 필드 종류(상수 · 입력 · 파생)는 없다. 필드는 `타입` · `기본값(선택, 프리필)` 을 갖는다.
   - ~~상수 필드~~ — 마스터가 정하는 값은 **입력 필드 + 기본값**으로 둔다. 사람이 굳이 고치지 않을 뿐, 값 자리는 노드마다 있다.
   - ~~파생 필드~~ — 계산은 구분자의 일이다. 입력은 「모델링에서 드러나는 양식」에만 충실한다.
   - 입력 항목을 유저가 정의하는 것(폼 편집 · 선택 필드 · 노출여부)은 MVP 이후다 — 입력 마스터는 코드다 (ADR-0037).
2. **구분자는 식 하나다.** 필드를 그대로 잇든(`pay.rate`) 계산하든(`sum(pay.rate)`) 같은 자리에 쓴다.
   **결과 타입은 정의에 명시하고 검사가 식의 추론 타입과 대조한다** ([[기능/구분자/구분자]] §3.1 · §3.3).
   유효값 목록을 먼저 정하고 값마다 규칙을 붙이는 모양(fallback · 검증)은 **MVP 이후** (2차기획_목록(아카이브)).
   - 식은 **마스터 필드와 다른 구분자**를 참조한다 — 같은 레벨은 그대로, 하위 레벨은 집계 안에서만, 상위 금지, 자기 참조 · 순환 거부 ([[기능/구분자/구분자]] §3.2).
   - **항등 투영(`구분자 = 폼키.필드키`)은 허용**한다 — 문면이 구분자만 보기로 했으니 필드 하나를 문면에 내려면 투영 구분자가 유일한 길이다.
     이건 중복 채번이 아니라 층 사이의 통로다. 구분자 사이 별칭도 허용하고 경고만 낸다 ([[기능/구분자/구분자]] §3.2).
   - 참조 경로는 `폼키.필드키`. 레벨 접두어 없음 — 폼의 레벨이 곧 순회 범위다 ([[기능/마스터/마스터]] §3.2).
   - **하위 레벨 필드는 집계 안에서만** (`any · all · sum · count · exist · not exist`). 집계 없이 쓰면 정의 시점 거부.
   - 값 자리는 모든 노드에 있다(노드 × 마스터 필드). **미입력을 참조하면 오류 + 좌표.**
   - **MVP 는 상위 → 하위 방향만.** 하위 구분자가 상위 값을 스칼라로 받는 것은 MVP 이후.
   - 구분자는 입력을 받지 않으므로 노출여부 · 기본값이 없다. 부착 레벨은 식이 어디서 평가되는지(집계의 뿌리)다.
3. **문면이 시스템에서 값을 받는 길은 구분자 하나다.** 조건식 · 반복 · 값 슬롯 전부. 마스터 필드를 문면에서 직접 고르는 길은 없다.
   사람이 고르는 갈림은 **공용조항 옵션**(참조하는 자리에서 유저가 선택 — [[기능/공용조항/공용조항]] §3.1 동작 · [[기능/공용조항/공용조항]] §3.2 옵션)으로 남는다.
   계산되는 것은 구분자, 사람이 고르는 것은 옵션 — 둘 다 산다.

## 이유

- **조건식이 읽히는 단위와 입력이 받는 단위가 다르다.** 「면책구분 = 면책」은 문면 작성자의 말이고, 「보험금지급.면책여부 = 예」는 모델링 담당자의 말이다.
  구분자가 그 번역층이다. 폼에 파생 필드를 두면 번역이 입력 양식 안에 섞인다.
- **입력이 단순해진다.** 입력 필드만 있으니 종류 라디오 · 상수값 · 식 입력이 없다. 모델링 화면이 받는 것과 입력 정의가 1:1 이다.
- **구분자 종류 분류는 그래도 사라진다.** ADR-0035 가 얻으려던 것(일반 · 상수 · 파생 4종 폐지, ADR-0032 「유형」 충돌 소멸)은 그대로 얻는다 —
  구분자는 전부 식이고, 폼은 전부 입력이다.

## 버린 대안

- **ADR-0035 (폼 단일 실체 · 필드 종류 셋)** — 조건식이 폼 필드를 직접 부른다. 번복.
- **문면 값 슬롯만은 폼 필드 직접 참조 허용** — 문면이 두 층을 보게 되어 「문면은 구분자만 본다」가 깨진다. 슬롯도 투영 구분자를 거친다.
- **구분자에 유효값 목록 + 값마다 규칙 (A 형)** — fallback · 검증에 쓸모가 있으나 MVP 밖. 식 결과가 곧 값(B 형)으로 시작한다.
- **폼 상수 필드 유지** — 사람이 안 고칠 값이라도 입력 필드 + 기본값으로 같은 효과. 필드 종류 축을 없애는 쪽이 더 단순하다.

## 결과와 감수하는 비용

- **투영 구분자가 많이 생긴다.** 문면에 내는 필드마다 구분자 하나. 채번 수는 ADR-0001 이 기대한 만큼 줄지 않는다 —
  대신 문면 쪽 이름과 입력 쪽 이름이 갈려도 된다는 자유를 얻는다.
- **평균공시이율 같은 값에 모델링마다 값 자리가 생긴다.** 기본값 프리필로 채우지만, 미입력 검사 · 스냅샷 대상이 된다.
- **코드 이행** — `DiscriminatorKind` 4종 → 입력 마스터(코드) · 구분자(식) 두 실체. `scalar` · `const` 구분자는 마스터 필드로, `derived` 는 구분자로.
  구분자 화면은 남되 유형 컬럼 · 종류 선택이 빠지고 식이 중심이다.
- ADR-0035 의 문서 반영은 이 ADR 로 다시 고쳤다. 같은 날 두 번 뒤집은 기록은 남긴다 —
  「조건식이 무엇을 부르는가」를 먼저 물었어야 했다.
