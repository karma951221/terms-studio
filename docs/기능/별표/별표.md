# 별표

> 상태: 초안 · 최종수정: 2026-09-30

## 1. 한 줄

약관 끝에 싣는 표 · 서식(장해분류표 · 화상 분류표 …)의 **전상품 공용 마스터**다. 별표는 코드 · 이름 · 주석뿐이고,
조문은 코드로만 부르며 번호(「【별표2(장해분류표)】」)는 책자를 조립할 때 계산된다. 약관 작성자가 조문에서 별표를 부르기 전에 등록한다.
내비 그룹 **「정적 마스터」** 의 하위로 박스([[기능/박스/박스]])와 나란히 선다(§3.4, [[기능/공용조항/결정/ADR-0076-공용조항-함수조항-일원화-인자연결]] 결정 11).

## 3. 규칙

### 3.1 마스터

- **코드는 시스템이 채번한다** — `AX` + 6자리 순번, `AX000001` 부터. 자리수를 넘으면 늘어난다(`AX1000000`). 등록 뒤 코드는 바뀌지 않는다. 생성 입력 타입(`NewAppendix`)에 `code` 가 없어 사람이 코드를 넣는 경로 자체가 없다.
  — 왜: 코드는 참조의 정본이고 사람이 지을 것은 이름이다. 사람이 코드를 지으면 「다음 번호 찾기 · 중복 피하기」가 유저 몫이 된다.
- 순번은 오르기만 한다 — 지운 코드는 다시 태어나지 않는다. 이름을 먼저 검사하고 채번하므로 거절된 등록이 순번을 태우지 않는다. 순번 출처는 카탈로그 · 공용조항과 같은 `code_sequences`(kind `appendix`, 전역).
- 시드(`appendices.json`)의 `code` 는 채번 결과와 대조하는 기대값이다 — 로더가 `expectCode` 로 순서가 어긋나지 않았는지 검사한다.
- **이름은 비울 수 없다**(앞뒤 공백은 정리). 이름 중복은 허용한다 — 별표는 코드로 식별한다.
- 주석은 자유 글자.
- 별표 **내용(표 본문) 출력은 MVP 밖**이다 — 코드 · 이름 · 주석만.
- 상품과 무관한 전상품 superset 이다. 상품은 별표 목록을 갖지 않는다.

### 3.2 조문의 참조와 번호

- 조문(문면 · 공용조항 본문)은 **별표 참조 슬롯**에 코드 하나만 저장한다. 번호를 글자로 박는 경로는 없다. 없는 코드는 참조 추가 · 저장 때 거부된다 ([[기능/문면/문면]] §3.5).
- **번호는 조립이 매긴다** ([[기능/별표/결정/ADR-0063-별표-자동수집-자동번호]]) —
  그 상품의 보통약관 + 탑재한 상품담보 문면이 참조하는 별표의 합집합을 모아, **본문 등장 순**(보통약관 → 특약 그룹 순 → 그 안에서 조 순)으로 1 부터 번호를 붙인다.
  같은 별표라도 책자마다 번호가 다를 수 있다. 사람이 순서를 정하는 자리는 없다.
- 담보약관 하나의 미리보기는 보통약관 + 그 담보약관만 훑으므로 책자 전체와 번호가 다를 수 있다.
- 저작 화면에는 번호가 없다 — 「【별표 이름】」으로 보인다.
- 실물 알파Plus 와 번호가 다른 것은 원문 대조의 허용 차이로 둔다 ([[QA/인수기준]] 실물 재현 인수 표 허용 차이).

### 3.3 삭제

- **관리자만**, 영향을 본 뒤에 지운다 ([[공통/화면/결정/ADR-0019-모드폐지-역할권한]]). 편집자 요청은 서버가 거부한다.
- 영향 = 이 별표를 부르는 자리(문서의 별표 참조 · 공용조항 본문의 별표 참조). **참조가 남아 있어도 지워진다** — 그 참조는 깨진 참조가 되어 문서 저장 검증 · 조립에서 오류로 드러난다.

### 3.4 정적 마스터

ADR-0076 결정 11 — **구현**. 내비 그룹 「정적 마스터」 = 별표 · 박스 (`src/app/_lib/menu.ts`, 약관 조문 앞 — 조문의 재료).

- 둘 다 여러 곳이 쓰는 고정 내용이고, 부르는 방식이 다르다.

  | 하위 | 참조 방식 | 조문에서 | 예 |
  |---|---|---|---|
  | **별표** | 간접참조 — 본문은 가리키기만 한다 | 「【별표2(장해분류표)】를 준용하여」 · 내용은 약관 끝에 실린다(§3.2) | 장해분류표 |
  | **박스** | 직접참조 — 놓인 자리에 내용 전체가 들어간다 | 조 자리 · 항의 호 목록 자리 · 공용조항 본문 안 | 【제외대상 특별약관】 · 암 정의 박스 · 【용어풀이】 |

- **정적 마스터 안에는 참조를 두지 않는다** — 박스 안 「제2항」 · 「제44조」는 고정 글이다. 조가 밀리면 틀린다 — 기존 한계([[QA/인수기준]] 허용 차이 ⑦).
  — 왜: 박스는 받는 값도 품는 참조도 없는 고정 글이라 함수조항(인자 · switch)과 성격이 다르다. 참조를 품게 하면 박스가 다시 조항이 된다.
- 박스의 규칙 · 화면은 [[기능/박스/박스]]. 실물의 박스 공용조항은 박스 마스터로 옮겼다(2026-09-30).

## 4. 화면

좌측 내비 「정적 마스터 › 별표」.

### 4.1 조회 (`/appendices`) — L1

| 구성 | 내용 |
|---|---|
| 제목 줄 | 「별표」 + `+` (→ `/appendices/new`) |
| 검색 | 코드 · 별표 이름 |
| 열 | 코드 · 별표 이름(→ 상세) · 주석(없으면 「없음」) · 최종수정 · 수정자 |
| 페이저 | 50건 · 「총 N건」 |

목록에서 고치거나 지우지 않는다 — 목록의 일은 찾아서 들어가는 것이다.

| 상태 | 표시 |
|---|---|
| 별표가 하나도 없음 | 빈 상태 — 「별표는 책자가 참조한 표 · 서식을 모아 마지막에 수록하는 독립 마스터다」 · 예 「장해분류표」 · 「새 별표 만들기」 |
| 검색 결과 없음 | 「이 조건에 맞는 별표가 없습니다」 |

### 4.2 새 별표 (`/appendices/new`)

- 경로 `별표 › 새 별표`, 제출은 헤더 우측.
- 칸: **별표 이름**(필수 · 첫 칸) · 주석(라벨이 보이는 접힌 행, 마지막). 코드 칸은 없다 — 폼 아래 「코드는 시스템이 AX000001 부터 붙이고, 등록 뒤에는 바뀌지 않는다」.
- 이름이 비면 같은 화면 오류 배너. 만들면 **상세로** 간다 — 받은 코드를 보여 준다.

### 4.3 상세 (`/appendices/<code>`) — L2

| 자리 | 읽기 | 편집 |
|---|---|---|
| 제목 줄 | 경로 `별표 › <이름>` · 사용처(N) · 편집 · 삭제 🗑 | 경로(마지막 마디는 편집 중인 이름) · ✕ · 저장 · 삭제 🗑(비활성, tooltip 「저장하거나 취소한 뒤 실행」) |
| 코드 | 고정 글자(mono) — 편집에서도 못 고친다 | 같음 |
| 별표 이름 · 주석 | 잠긴 글자 | 입력칸 |

| 누르면 | 무엇이 되나 |
|---|---|
| 편집 | 이름 · 주석이 입력칸이 되고 같은 자리 버튼이 저장이 된다 |
| 저장 | 달라진 칸만 **한 트랜잭션**에 저장 — 바뀐 것이 없으면 잠김. 이름을 비우면 거부 메시지, 어느 칸이 거부되든 아무것도 저장되지 않는다 |
| ✕ · 경로 링크 (편집 중) | 고친 것이 있으면 「고친 내용을 버립니까?」 확인 |
| 사용처 (읽기에서만) | 다이얼로그 — 「사용처 N / 전체 참조 M」, 형태 · 좌표 표(좌표는 그 문서의 그 자리로 가는 링크). 0건이면 「아무 조문도 이 별표를 부르지 않는다 — 어느 책자에도 실리지 않는다」 + 「약관 템플릿에서 쓰러 가기 →」 |
| 삭제 🗑 (읽기에서만) | 관리자: 확인 다이얼로그(깨질 참조 목록) → 삭제 뒤 목록으로. 편집자: 거부 메시지. 편집 중에는 꺼진다 (디자인원칙 §2 L2) |

| 상태 | 표시 |
|---|---|
| 없는 코드 | 경로 `별표 › <코드>` + 「찾을 수 없습니다」 |

## 5. 미결

- **별표 내용(표 본문) 출력** — MVP 밖. 책자 끝에 무엇을 싣는지(이름만 · 표 본문) 정할 때 별표 노드 모델이 필요하다.
- **실물 번호 재현** — 알파Plus 는 본문 등장 순과 다른 번호(별표2 가 별표1 보다 먼저 · 특약 13 · 14 · 21)를 쓴다. MVP 는 허용 차이로 감수했다(ADR-0063). 재현이 요구되면 번호 규칙을 다시 연다.
- 삭제 대신 「사용 중지」를 둘지 — 지금은 참조가 있어도 관리자가 지울 수 있다.
