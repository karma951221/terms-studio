# 동적표

> 상태: 초안 · 최종수정: 2026-10-18 (구현 완료 — 도메인 · 문면 노드 · 조립 · DB · 서비스 · 화면 · 시드, §2 코드 위치 · §3 · §7) · 앞서 2026-10-17 (기획)

## 1. 한 줄

담보약관에 들어가는 **감액 지급금액 표**(「구 분」 + 감액 구간 열, 셀 「보험가입금액의 n%」)를 급부 종류마다 짜인 로직이 아니라 **정의 객체**로 만든다 — 행 기준 · 열 기준 · 머리글 템플릿 · 셀 템플릿을 정의에 적어 두면, 조립이 그 담보의 급부 · 감액 값으로 표를 펼친다.
작성자가 동적표를 정의하고(함수조항처럼 코드 · 이름 · 인자를 가진 재사용 단위), 담보약관 문면 작성자가 문면에 동적표 참조를 넣어 인자를 연결하며, 상품 미리보기 · 조립이 상품담보 스냅샷으로 표를 찍는다.

## 3. 규칙

### 3.1 정의

- **동적표는 독립 객체다** — 함수조항([[기능/함수조항/함수조항]])과 같은 뼈대: 코드 시스템 발급(`DT000001`…, 박스와 같은 접두 + 6자리 · `code_sequences` kind `dynTable`) · 이름 · **인자** · 본문 대신 **표 규칙**. 메뉴 「동적표」(약관 조문 — 함수조항 다음)에 목록이 있고, 사용처(담보약관 문면)는 참조만 둔다. 고치면 쓰는 곳 전부에 전파된다 — 저장이 사용처를 재검사한다(§3.6).
  — 왜: 같은 표 모양(감액 구간 열 · 「보험가입금액의 n%」)이 담보마다 되풀이된다. 문면 노드의 속성으로 두면 담보약관마다 머리글 · 셀 문구를 다시 적는다.
- **인자는 값 인자만** — 함수조항의 `ParamDef{name, type, default}` 를 그대로 쓴다. 조 참조 인자는 없다 — 저장 검사가 거부한다 ([[기능/담보/결정/ADR-0087-담보노드키-키경로참조-함수조항인자연결]]).
- **동적표는 담보속성 · 세목 · 구분자를 직접 읽지 않는다** — 템플릿 안 조건 · 값별 분기는 인자(`arg.X`)만 읽는다(셀 템플릿의 「해당보장의」 조건이 읽는 담보 구조 집계 하나만 예외 — §3.3). 기준일 낱말(「최초계약일」/「계약일」)은 인자(갱신형 여부)로 받아 템플릿 안 조건이 고른다. 구분자 · 세목 필드 · 담보속성을 읽으면 저장 검사 `structure`.
  — 왜: 함수조항과 같은 결이다([[기능/함수조항/함수조항]] §3.3) — 값이 어디서 오는지는 사용처가 정하고, 정의는 어느 담보에 들어갈지 모른다.
- **표는 세목 · 담보속성으로 갈리지 않는다** — 행 · 열은 담보 구조(급부)와 급부의 감액 값만으로 정한다.
- 정의의 칸 (`DynTable`, `types.ts`):

  | 칸 | 값 | 비고 |
  |---|---|---|
  | 행 기준 | `급부명` (고정 하나) | §3.2 |
  | 열 기준 `columnBasis` | `감액 구간`(`reduction`) 또는 `없음`(`none`) | §3.2 |
  | 구분 칸 머리글 `rowHeader` | 글, 기본 「구 분」 | |
  | 열 머리글 템플릿 `headers` | **첫 열** · **가운데 열** · **마지막 열** 세 벌 + 열 하나일 때 **단일 열** (`first · middle · last · single`) | §3.3 |
  | 셀 템플릿 `cell` | 인라인 노드, 기본 「보험가입금액의 {비율}%」(`defaultCellTemplate`) | §3.3 · §3.4 |

### 3.2 행 · 열

- **행 = 급부명** — 급부 하나가 한 행이고, 급부명이 같은 급부는 한 행으로 묶인다(세부보장이 달라도). 행 순서는 담보 트리 순서(세부보장 순 → 급부 순)로 처음 나온 자리다. 묶기 조건은 §3.4.
  — 왜: 약관에서 한 줄로 쓰고 싶은 급부는 작성자가 급부명을 같게 적는다 — 따로 보이려면 급부명을 다르게 적는다. 세부보장 칸을 따로 두거나 합치지 않는다.
- **열 = 감액 구간** — 그 담보 모든 급부의 감액 경계(`reduction.periods` 의 `end`)를 합친 집합(오름차순, 같은 개월 수는 하나)으로 나눈다. 경계 k 개면 열 k + 1 개. 열 수에 상한을 두지 않는다.
  — 왜: 머리글 템플릿이 첫 · 가운데 · 마지막 세 벌이라 n 열이 저절로 된다 — 상한은 규칙을 하나 더 만들 뿐 막을 이유가 없다.
- **열 기준 「없음」이거나 경계 합집합이 비면 열은 하나** — 머리글은 단일 열 템플릿(기본 「지급금액」)이고 비율 = 지급률이다. (갱신) 표 · 감액이 하나도 없는 담보가 이 모양이다. 급부가 하나도 없으면 머리글만 찍고 행은 없다.
- 머리글은 한 줄이다 — 위에 「지급금액」 머리를 따로 두지 않는다. 펼친 뒤 열이 고정이라 colSpan 은 쓰지 않는다.
- **면책(`exemption`)은 표에 나오지 않는다** (ADR-0065 §6).

### 3.3 머리글 · 셀 템플릿과 인자

- **템플릿은 조의 인라인 노드다** — 글(`text`) · 슬롯(`slot`) · 인라인 조건(`inlineCond`) · 값별 분기(`inlineSwitch`) · 조사(`particle`). 문면 · 함수조항의 인라인 노드와 같은 모양이고, 그 밖(조 참조 · 별표 참조 · 옵션 자리)은 저장 검사 `structure`. 조건 · 분기의 대상은 `arg.X`(값별 분기는 열거형 인자 · 칸 값은 그 열거형의 값) — **표 슬롯은 조건에서 읽을 수 없다.**
- **표 슬롯은 슬롯 노드의 내장 경로 `builtin.table.<슬롯>`** 이다(`DYN_TABLE_SLOTS`, [[공통/기술/식언어]] §3). 파서가 둘째 토막 `table` 을 받고, 펼침이 평가 전에 글로 바꿔 끼우므로 평가 문맥에는 오지 않는다 — 동적표 템플릿 밖(문면 · 함수조항)에서 쓰면 `brokenRef`. 템플릿마다 쓸 수 있는 슬롯(`DYN_TABLE_ALLOWED_SLOTS` — 어기면 저장 검사 `structure`):

  | 슬롯 (편집기 칩) | 경로 | 값 | 쓰는 템플릿 |
  |---|---|---|---|
  | `{경계}` | `builtin.table.boundary` | 이 열의 끝 경계 — `formatPeriod`(「1년」 · 「3개월」). 마지막 열은 끝이 없어 그 열이 시작하는 마지막 경계 | 첫 · 가운데 · 마지막 |
  | `{앞경계}` | `builtin.table.prevBoundary` | 가운데 열의 시작 경계 | 가운데 |
  | `{비율}` | `builtin.table.rate` | 그 행 · 그 열의 셀 비율(§3.4, % 수) | 셀 |

  단일 열 템플릿에는 표 슬롯이 없다.
- 열 하나 = 단일 열, 열 둘 = 첫 + 마지막, 열 셋 이상 = 첫 + 가운데(열마다) + 마지막.
- 감액 표 정의의 머리글 예(〔기준일〕 = 조건 `arg.갱신형` → 「최초계약일」, 그 밖 「계약일」 — 시드 `DT000001`):

  | 템플릿 | 글 | 「갱신형」 · 경계 {1년} 일 때 |
  |---|---|---|
  | 첫 열 | 〔기준일〕부터 {경계}경과시점 전일 이전 | 최초계약일부터 1년경과시점 전일 이전 |
  | 가운데 열 | 〔기준일〕부터 {앞경계}경과시점 이후 〔기준일〕부터 {경계}경과시점 전일 이전 | — |
  | 마지막 열 | 〔기준일〕부터 {경계}경과시점 이후 | 최초계약일부터 1년경과시점 이후 |
  | 단일 열 | 지급금액 | — |

- **셀 슬롯 `{비율}`** = 그 행 · 그 열의 셀 비율(§3.4). 기본 셀 템플릿 「보험가입금액의 {비율}%」.
- **「해당보장의」 접두는 셀 템플릿 안 인라인 조건이다** — 조건은 기존 집계 `count(builtin.subCoverage.name) >= 2`(그 담보의 세부보장 수, distinct — [[공통/기술/식언어]] §5). 새 내장값은 두지 않는다. 조립이 이 조건을 **담보 문맥**에서 평가한다(§3.6).
  — 왜: 세부보장 수는 담보 구조라 세목 · 담보속성이 아니다(§3.1 「갈리지 않는다」에 걸리지 않는다). 인자로 받으면 담보마다 사람이 세어 연결해야 한다. 집계가 이미 있어 내장값을 새로 만들 이유가 없다.
- **담보마다 다른 머리글 꼬리(주요치료비 단서문구 — 「「2대질환」으로 진단확정 시」)는 글 인자 하나다** — 머리글 템플릿 끝에 `{arg.단서}` 를 두고 문면이 그 담보의 글을 연결한다. 별도 장치는 없다(표본 정의 A′, `fixture.ts`).
  — 왜: 질환명이 담보마다 달라 시스템이 만들 수 없고, 인자 하나로 된다.
- 노드 id 는 정의 전체(머리글 네 벌 + 셀)에서 유일하다. 펼친 노드의 id 는 「참조 id / 템플릿 노드 id @ 행 · 열」(머리글 행은 `h`) — 표 슬롯은 같은 id 의 글 노드가 된다.

### 3.4 셀 계산과 묶기

- **열 j 의 감액비율** — 열 j 의 구간 [b(j−1), b(j)) 에서 급부 g 의 감액비율 = g 의 `reduction.periods` 중 `end ≥ b(j)` 인 첫 행의 `rate`, 없으면 `after_rate`(기본 100). 감액 폼을 열지 않은 급부는 모든 열 100. 마지막 열(끝 없음)은 `after_rate`.
  — 왜: 경계를 합치면 한 급부의 구간이 여러 열로 쪼개진다 — 제 경계가 없는 열도 그 열을 덮는 자기 구간의 비율로 채운다(제 90일 경계가 없는 급부의 첫 열 = 1년 구간 비율).
- **셀 비율 = `pay.rate` × 감액비율 / 100** — 정수가 아니면 소수 한 자리까지 **버림**해 그대로 찍는다. 반올림하지 않는다.
  — 왜: 감액 지급률은 급부 지급률에 곱하는 비율이다([[기능/담보/담보]] §3.4). 곱이 없으면 지급률 20% 급부의 감액 50%(→ 10%)를 쓸 수 없다.
- **`pay.rate` 미입력** — 그 행이 `notEntered`(좌표는 행 단위 — §3.6), 셀은 빈 글로 두고 표 구조는 그대로 돌려준다.
- **묶기는 열마다 셀 비율이 모두 같을 때만** — 급부명이 같아도 어느 열에서든 비율이 다르면 묶지 않고 급부마다 따로 행을 찍고(트리 순서 그대로), 급부명마다 경고 `dynTableMergeConflict` 하나(첫 급부와 처음 갈린 급부 · 갈린 열 · 두 비율)를 낸다. 면책만 다른 급부는 묶인다(면책은 표에 없다).
  — 왜: 표에 나오는 값이 다른 급부를 한 행으로 찍으면 한쪽 값이 조용히 사라진다. 막지 않고 경고하는 것은 작성자가 급부명을 고치면 풀리는 일이라 조립을 멈출 일이 아니기 때문이다.
- 읽는 창구는 `reductionPeriods(read)`(급부 하나의 감액 구간 — 폼을 안 열었으면 없음) · `pay.rate` — 조립이 급부 노드 문맥에서 읽어 `DynBenefit[]` 로 넘긴다.

### 3.5 문면 삽입과 (갱신) 표

- **삽입 노드 `dynTableRef{tableCode, bindings}`** — 담보약관 문면의 잎 블록 노드, 조 자리 · 항 아래 목록에 선다([[기능/문면/문면]] §3.2 · §3.6). 편집기는 툴바 「동적표」 · 오른쪽 클릭 「아래에 동적표 추가…」(함수조항 추가 옆) · 조 끝 「동적표 추가…」로 넣고, 「인자 연결 고치기…」(명령 `setDynTableBindings`)로 연결을 고친다. 보통약관 문서에는 메뉴가 서지 않는다. 넣지 않으면 사람이 정적 표로 직접 쓴다.
- **인자 연결은 함수조항과 같은 `Binding`** — 상수 · 구분자. 갱신형 여부는 문면이 담보속성 갱신형을 읽는 구분자로 연결한다(동적표는 속성을 모른다 — §3.1). 구분자로 연결한 인자는 조건에 구분자 코드로 남아 사용처 문맥에서 늦게 평가된다. 연결도 기본 연결도 없으면 `argUnbound`.
- **문맥은 담보약관(상품담보)** — 급부 집합은 그 상품담보 스냅샷의 담보 트리 전체 급부다. 보통약관 문맥에 넣으면 `structure` 오류다(저장 검사 거부 · 조립은 오류 마커).
- **(갱신) 표는 두 번째 정의 + 문면 조건 노드** — 열 기준 「없음」 · 셀 「보험가입금액의 {비율}%」(감액이 없어 비율 = 지급률)인 정의(시드 `DT000002`)를 따로 두고, 문면이 갱신형 조건 블록 안에 넣는다. 조립에 「항상 생성 · 갱신형만 노출」 같은 특수 규칙을 두지 않는다.
  — 왜: 조건 노드로 이미 쓸 수 있는 일을 조립 규칙으로 두면 문면에 보이지 않는 표가 생긴다.

### 3.6 조립 · 검사 · 오류 좌표

- **펼침** — 조립(`Walker.dynTable`)이 `dynTableRef` 를 만나면 급부 열거(세부보장 순 → 급부 순) → 경계 합집합 → 행 묶기 → 셀 계산 → 머리글 · 셀 템플릿 바꿔 쓰기(인자 연결 → `rewriteInlines`, 함수조항과 같은 자리 · 표 슬롯 → 글) → 기존 `RTable` 로 낸다. 셀 · 머리글 인라인은 **담보 문맥**에서 평가한다(행 노드 문맥이 아니다 — 반복 블록 안에 있어도) — 「해당보장의」 조건이 담보의 세부보장 수를 세기 때문이다. 렌더는 기존 정적 표 그대로다([[기능/조립산출/조립산출]] §3.1).
- **조립 오류 마커** — 보통약관(행 원천 없는 문맥) → `structure`, 없는 동적표 코드 → `brokenRef`, `argUnbound` · `brokenRef` → 표 대신 오류 마커 하나. 경고(`dynTableMergeConflict`) · `notEntered` 는 표를 찍고 이슈만 더한다.
- **저장 검사(동적표 정의, `checkDynTable`)** — 이름 있음 · 인자 표(이름 규칙 · 조 참조 인자 불가) · 템플릿이 읽는 `arg.X` 가 선언돼 있음(아니면 `brokenRef`) · 값별 분기 값이 그 열거형에 있음 · 표 슬롯이 그 템플릿에서 쓸 수 있는 것(§3.3 표) · 허용 노드 종류 · 식 문법(`syntax`) · 노드 id 유일 — 어기면 저장 거부. 저장이 통과하면 사용처 문서를 재검사해 결과를 돌려준다.
- **삽입 검사(문서 저장, `checkDynTableRef` · `dynTableGateFrom`)** — 바인딩 누락(`argUnbound`) · 타입 불일치 · 없는 인자에 연결 · 없는 동적표 · 보통약관 문맥 — 함수조항 참조의 문서 저장 검사와 같은 결([[기능/함수조항/함수조항]] §3.4).
- **삭제** — 함수조항과 같은 2단(`dynTable.delete`): 사용처가 있으면 영향(깨질 참조 좌표)을 보이고 확인 뒤 지운다. 사용처는 관계정보 그래프의 `dynTableRef` 간선으로 센다([[기능/관계정보/관계정보]]).
- **오류 좌표** — `nodePath` = 조 경로 + 참조 노드 id, `refPath` = 「동적표 <코드> › 행 <급부명>」(행 단위 — 갈린 열 번호와 두 비율은 경고 문구에). 원천은 셀 값이면 그 급부의 감액 · 지급률 값, 템플릿이면 동적표 정의(`/dyntables/<코드>`).
- 경고 `dynTableMergeConflict` 는 완성본을 깨지 않는다.

| 상태 | 화면 |

### 6.2 결정 메모

| 결정 | 왜 | 버린 안 |
|---|---|---|
| 동적표 = 독립 객체(코드 · 이름 · 인자 · 표 규칙), 문면엔 참조 노드 + 인자 연결 (§3.1 · §3.5, 2026-10-17 사용자 결정) | 같은 표 모양이 담보마다 되풀이된다 — 함수조항처럼 한 곳에서 고치고 전파한다 | 문면 표 노드의 속성으로 표 규칙을 적기 · 급부 종류마다 표 로직 |
| 행 = 급부명(같으면 한 행), 열 = 감액 구간(경계 합집합) (§3.2, 2026-10-17 사용자 결정) | 현행 표가 그렇게 읽힌다. 묶고 싶으면 급부명을 같게 — 작성자가 이미 쥔 손잡이다 | 세부보장 / 급부 2칸 · 세부보장 칸 합치기 · 세목 · 담보속성 축 |
| 기준일 낱말 = 머리글 템플릿 + 인자(갱신형 여부) + 조건 (§3.1 · §3.3, 2026-10-17 사용자 결정) | 동적표가 담보속성을 직접 읽으면 함수조항의 「인자만 읽는다」와 결이 갈리고, 정의가 어느 속성을 읽는지 숨는다 | 동적표가 담보속성 갱신형을 직접 읽기 · 기준일을 시스템 고정 문구로 |
| 표 슬롯 = 슬롯 노드의 내장 경로 `builtin.table.<슬롯>` · 조건에서 못 읽음 · 템플릿별 허용 표 (§3.3, 2026-10-18 구현 결정) | 템플릿이 조의 인라인 노드 그대로라 슬롯 노드 하나로 되고, 파서는 둘째 토막 하나만 더 받으면 된다. 펼침이 글로 바꿔 끼우므로 평가기 · 문맥은 모른다 | 표 슬롯 전용 노드 종류 · 템플릿 글 안 `{경계}` 문자열 치환 |
| 템플릿 = 조 인라인 노드 집합(글 · 슬롯 · 인라인 조건 · 값별 분기 · 조사), 인자 바꿔 쓰기는 `rewriteInlines` 공유 (§3.3 · §3.6, 2026-10-18 구현 결정) | 함수조항과 같은 편집기 · 같은 검사 · 같은 바꿔 쓰기를 그대로 쓴다 | 동적표 전용 템플릿 문법 |
| 열 수 제한 없음 (§3.2) | 머리글 템플릿 세 벌이라 n 열이 저절로 된다 | 최대 3열(현행 요건) |
| 같은 급부명 · 비율 다름 = 급부명마다 경고 `dynTableMergeConflict` 하나(첫 급부 vs 처음 갈린 급부) + 트리 순서대로 따로 찍기 (§3.4) | 급부명을 고치면 풀리는 일이라 조립을 멈출 일이 아니다. 값이 사라지지 않게 따로 찍는다 | 조립 오류로 막기 · 첫 급부 값으로 묶기 · 갈린 쌍마다 경고 |
| (갱신) 표 = 두 번째 정의 + 문면 조건 노드 (§3.5) | 조건 노드로 쓸 수 있는 일을 조립 규칙으로 두면 문면에 보이지 않는 표가 생긴다 | 조립의 「항상 생성 · 갱신형만 노출」 특수 규칙 |
| 주요치료비 단서문구 = 글 인자 하나 (§3.3) | 질환명이 담보마다 달라 시스템이 만들 수 없고, 인자 하나로 된다 | 담보 공통변수 같은 별도 장치 |
| 「해당보장의」 = 셀 템플릿 안 조건 `count(builtin.subCoverage.name) >= 2` — 기존 집계, 새 내장값 없음 · 조립이 담보 문맥에서 평가 (§3.3 · §3.6, 2026-10-18 구현 결정) | 세부보장 수는 담보 구조라 세목 · 담보속성 축이 아니다. 인자로 받으면 사람이 세어 연결한다. 집계가 이미 세부보장 수를 세므로 내장값을 더할 이유가 없다 | 인자로 받기 · 시스템 고정 접두 · 새 내장값 `builtin.coverage.subCoverageCount` |
| 셀 비율 = 지급률 × 감액비율 / 100, 소수는 한 자리까지 버림 · 반올림 없음 (§3.4, 2026-10-17 사용자 결정 — 셀 공식) | 곱이 없으면 지급률 20% × 감액 50% 를 쓸 수 없다. 반올림 규칙을 정할 실물 근거가 없다 | 감액 지급률을 셀 표시값으로 · 정수 반올림 |
| 오류 좌표는 행 단위 「동적표 <코드> › 행 <급부명>」, 열은 문구에 (§3.6, 2026-10-18 구현 결정) | 작성자가 고칠 자리는 급부(감액 · 지급률 값)라 행이면 닿는다. 열까지 좌표에 넣으면 같은 행의 이슈가 열마다 갈라진다 | 「› 열 n」까지 좌표에 |
| 사용처 · 삭제 영향은 관계정보 그래프(`dynTableRef` · `binding` 간선) (§3.6, 2026-10-18 구현 결정) | 함수조항 · 박스와 같은 길 — 역인덱스를 따로 두지 않는다 | 동적표 전용 사용처 표 |
| 체증 · 급부 형태 필드는 이번 범위 밖 (§5) | 형태 필드는 읽는 곳(체증 표)이 생길 때 같이 정해야 모양이 맞는다 | 형태 필드를 먼저 두기 |
