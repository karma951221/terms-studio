## 맥락

2026-09-28 ~ 09-30 납입면제 기획에서 보통약관 템플릿 **한 벌**이 납입면제의 모든 경우(없음 · 사유 조합 · 종마다 다른 사유 · 적립 · 무저해지)를 감당해야 했다.
납입면제사유는 열거형 E0001 이고(암(유사암제외) · 뇌졸중 … 후유장해 값들, [[기능/열거형/결정/ADR-0078-열거값-유저정의필드-값나누기]]), 사유에 따라 갈리는 문장이 여러 조에 흩어진다 — 납입면제 조의 호 · 면제 부가항 · 세부규정 · 「…의 정의 및 진단확정」 조 · 계약의 무효 · 부활.

현행 시스템의 두 방식이 다 아팠다.

1. 템플릿이 「가지」를 정의하고 사유 관리 화면마다 그 가지에 글을 채운다 — 한 문장을 보려면 템플릿과 사유 화면 N 개를 오가야 했고, 「사유 묶음 1개면 제1항, 2개면 제1 · 2항」 같은 **개수 조건 · 서수 구분자**가 생겼다.
2. 사유 가지를 템플릿에 전부 인라인으로 두었더니 if 가 쌓여 템플릿을 읽을 수 없었다.

사유별 문장을 **자리(역할)마다 한 조항에 모으고**, 템플릿은 「사유마다 → 그 조항(사유 ← 현재 사유)」 한 줄로 부르는 모양으로 모였다.
지금 공용조항(늦은 바인딩)으로는 이 모양을 못 만든다 — 반복의 현재 원소는 구분자가 아니라 넘길 길이 없고, 같은 문구를 보통약관(세목 값) · 담보약관(담보 값)이 쓰면 읽는 구분자가 다르다. ADR-0010 이 인자 전달을 버린 이유(「실사례가 아직 없다」)가 생겼다.

또 박스(【용어풀이】 · 【제외대상 특별약관】)는 공용조항 유형 「박스」였지만, 박스는 받는 값이 없고 참조도 품지 않는 고정 글이다. 함수조항에 넣어 두면 「인자 · 내부 변수 · switch 를 가진 조항」 목록에 성격이 다른 것이 섞인다.

## 결정

### 조항 모델

1. **함수조항 하나로 일원화한다.** 지금의 공용조항은 함수조항이 된다 — 인자 0개 = 고정 문장. 종류를 둘로 두지 않는다. 메뉴 · 경로 · 화면 단어도 「함수조항」으로 바꾼다(구현 2026-09-30 — 경로 `/functions`, 옛 `/clauses…` 는 넘김. 코드 식별자 `clause` · DB `clauses` 는 그대로).
2. **함수조항 = 인자 → 내부 변수 → 본문.**
   - **인자** — 조항 안에서 이름을 정하는 입력 선언. 마스터 구분자를 직접 읽지 않고 인자만 읽는다. 타입 = 구분자 타입(참거짓 · 목록값 · 목록값(복수) · 세목 선택지 목록 등) + 반복의 현재 원소. 목록값 인자의 선택지는 열거형을 타입으로 가리킨다(`사유: E0001`).
   - **인자 연결** — 넣는 자리에서 인자마다 그 문맥의 **구분자** · 반복의 **현재 원소** · **상수** 중 하나를 댄다. 누락 · 타입 불일치 = 문서 저장 오류.
   - **인자 기본 연결** — 선언 때 기본 구분자를 적어 두면 넣는 자리에서 저절로 걸리고, 다를 때만 바꾼다. 기본 연결 구분자를 바꾸거나 지우면 그 함수조항 정의와 기본 연결을 그대로 쓰는 사용처를 재검사한다.
   - **내부 변수** — 인자를 가공한 이름. 연산은 타입별로 몇 개뿐이다([[공통/기술/식언어]] §12): 세목 선택지 목록 `.사유합치기` · 목록값(복수) `.있음(값…)` · `.거르기(필드 = 값)` · `.비었음` · 목록값 `.필드` · `= 값` · 참거짓 `그리고 / 또는 / 아님`. **개수 연산은 없다.** 필요하면 타입별로 더한다.
   - **본문** — 조건 블록(IF/ELIF/ELSE) · switch · 옵션 · 글.
3. **옵션은 함수조항 안에서 선택지 문구를 직접 정의한다** — 열거형이 필요 없다. 넣는 자리에서 고르고 미선택 = 문서 저장 오류(지금 옵션 규칙 그대로). 옵션과 인자는 별개다 — 옵션은 사람이 손으로 고르고, 인자는 값을 연결한다.
4. **유형 = 출력 모양** — 문구(문장 조각) · 항(항 목록) · 호(호 목록) · 목(목 목록). 빈 목록이 될 수 있고, 한 값이 여러 개를 낼 수 있다. 유형과 넣는 자리가 맞아야 넣는다. 번호는 펼친 뒤 사용처에서 매긴다.
5. **switch 블록** — 대상 목록값(enum) 하나, 칸마다 값 여러 개.
   - 모든 값이 정확히 한 칸에 선다. 함수조항 저장 때 미배정 = 오류. 열거값 추가로 생긴 미배정 = 재검사 목록(열거값 저장은 막지 않음). 그 값이 실제 조립에서 switch 에 닿을 때만 조립 오류.
   - 「문구 없음」 칸을 명시로 둔다. default 칸은 없다 — 나머지를 한꺼번에 받으려면 IF 를 쓴다.
   - 칸 순서 = 열거형 값 순서. 블록 자리 · 문장 안 둘 다 선다 — 문장 안 switch 의 제약은 문장 안 조건과 같다.
   - 어디서든 쓸 수 있게 설계하되 **지금은 함수조항 안에서만** 연다. 목록(목록값(복수)) switch 는 두지 않는다 — 목록은 내부 변수 + IF 로.
   - switch 칸 · IF 가지의 같은 자리 항 · 호 · 목은 P코드를 공유한다([[기능/문면/결정/ADR-0072-참조대상-조uuid-조전체유일P코드]] 결정 4).
6. **다른 축도 인자로 받는다** — switch 는 인자 하나에만, 다른 인자는 칸 안 IF 로 읽는다.
7. **중첩** — 함수조항 안에 함수조항은 금지(그대로). 정적 마스터의 박스는 잎이라 함수조항 · 템플릿 어디에나 놓는다.
8. **단위 규칙은 경고다** — 「조 · 여러 항 단위, 두 곳 이상 사용」을 벗어나면(항 · 호 · 목 하나, 한 곳 사용) 경고만 하고 만들 수 있다.
9. **템플릿의 함수조항 상자는 접어 둔다** — 머리 줄 「이름(인자 ← 연결)」과 칸 머리만 보이고, 누른 칸만 펼친다. 미리보기 상품을 고르면 그 상품이 닿는 칸만 펼친다. 인자 0개 조항은 지금처럼 전체를 보인다.
10. **나머지 공용조항 규칙은 이어받는다** — 조 노드 금지(조는 사용처 소유) · 세 검사 · 코드 · 권한 · 참조 범위 · 전파. 세 검사의 뜻은 좁아진다 — ① 정의 유효에 「본문 · 내부 변수가 선언된 인자만 읽는가 · switch 배정」, ② 사용처 문맥은 「연결한 구분자가 그 문맥에 있나 · 타입이 맞나」, ③ 실행 시 해소는 연결한 값의 미입력 · 유효 집합 밖 · 미배정 값 도달.

### 정적 마스터

11. **메뉴 「정적 마스터」 — 하위 별표 · 박스.** 별표는 **간접참조**(본문이 가리키기만 하고 약관 끝에 실린다), 박스는 **직접참조**(놓인 자리에 내용이 들어간다). 박스는 공용조항 유형에서 빠져 여기로 온다.
    **정적 마스터 안에는 참조를 두지 않는다** — 박스 안 「제2항」은 고정 글이다(기존 한계 — [[QA/인수기준]] 허용 차이 ⑦).

## 이유

- **사유별 문장이 한 조항에 모인다.** `납입면제 호(사유)` 하나에 모든 사유의 호가 switch 칸으로 나란히 서서 사유끼리 비교된다 — 「템플릿 + 사유 화면 N 개」 문제가 풀린다. 템플릿에는 반복 두 줄 + 조항 한 줄만 남아 읽힌다.
- **반복의 현재 원소를 넘기는 길이 인자뿐이다.** 늦은 바인딩으로는 「지금 반복 중인 사유」를 읽을 방법이 없다.
- **인자만 읽어야 어디에 넣어도 같다.** 보통약관 · 담보약관이 같은 문구를 쓸 때 사용처가 제 구분자를 인자에 연결한다.
- **내부 변수가 템플릿의 if 를 조항 안으로 가둔다.** 세부규정은 「사유들 = 종들.사유합치기 · 암있음 = 사유들.있음(암 값들)」 두 줄로 항 묶음을 켜고 끈다. 사유합치기가 중복을 걷어내 현행의 앵커 중복 제거가 필요 없다. 개수 연산을 두지 않아 「몇 개면 몇 항」이 다시 생길 길을 막는다.
- **switch 는 새 값을 조용히 흘리지 않는다.** 모든 값이 정확히 한 칸이라 값을 더하면 미배정이 드러난다. default 칸이 있으면 새 값이 말없이 흘러든다.
- **옵션은 조항 안이 맞다.** 「기산일」 류 낱말 선택마다 열거형을 만들면 /enums 가 조항 전용 낱말 목록으로 찬다. 옵션은 사람이 고르는 문구 대안이라 값 연결(인자)과 성격이 다르다.
- **유형 = 출력 모양이라 자리 검사가 한 규칙이다.** 호 자리에는 호 목록을 내는 조항만 선다 — 박스 예외 같은 자리별 예외가 필요 없다.
- **기본 연결이 인자 전달의 실제 비용을 지운다.** ADR-0010 이 B 를 버린 실제 이유는 사용처마다 같은 연결이 는다는 것이었다(준용규정을 담보약관 50개가 쓰면 50번). 기본 연결이면 일상적인 경우는 늦은 바인딩만큼 편하고 계약은 시그니처로 남는다.
- **단위 규칙을 경고로 낮춘다.** 역할 함수조항(`납입면제 호` — 호 목록, 템플릿 한 곳)은 단위 규칙 밖이지만 사유별 문장을 모으는 것이 목적이다. 규칙은 조각 남발을 막는 안내로 남긴다.
- **상자를 접어야 템플릿이 읽힌다.** 역할 함수조항은 칸이 사유 수만큼이라 펼치면 인라인 가지를 둔 현행과 같아진다.
- **박스는 함수가 아니다.** 받는 값도 품는 참조도 없는 고정 글이라, 별표처럼 코드 · 이름 · 내용만 있는 정적 마스터가 제자리다. 직접참조(박스)와 간접참조(별표)를 한 메뉴에 두면 「여러 곳이 쓰는 고정 내용」이 한 곳에 모인다.

## 버린 대안

- **늦은 바인딩 유지(옛 ADR-0010)** — 반복의 현재 원소를 넘길 수 없고, 보통약관 · 담보약관이 같은 문구를 쓰면 한쪽에만 맞는다.
- **공용조항 · 함수조항 두 종류** — 인자 0개 함수조항이 곧 공용조항이라 같은 장치가 두 벌(목록 · 검사 · 사용처 상자)이 되고 「어느 쪽으로 만드나」라는 물음이 생긴다.
- **옵션을 목록값 인자 + 상수 연결로 흡수** — 낱말 옵션마다 열거형이 생기고, 사람이 고르는 것과 값을 연결하는 것이 한 칸에 섞인다.
- **기본 연결 없는 인자 전달(ADR-0010 B 원형)** — 사용처마다 같은 연결을 반복한다.
- **switch 의 default 칸** — 열거값을 더하면 새 값이 말없이 default 로 흘러든다.
- **목록 switch** — 목록은 값이 여럿이라 「어느 칸」이 정해지지 않는다. 내부 변수(`.있음`) + IF 로 대신한다.
- **분류용 열거값 필드로 IF 를 가름(암계열 · 장해계열)** — 실무 사례가 없다. 값 나열 IF 는 열거값 추가 재검사로 지킨다([[기능/열거형/결정/ADR-0078-열거값-유저정의필드-값나누기]]).
- **개수 연산** — 개수 조건식 폐지와 한 몸이다.
- **박스를 함수조항 유형으로 유지** — 인자 · switch 가 없는 고정 글이 함수조항 목록에 섞이고, 호 목록 자리에 박스 예외가 남는다.

## 결과와 감수하는 비용

- **코드 이행은 페이즈별이다.** 이름 · 경로 · 유형 · 단위 경고 · 박스(정적 마스터) · 인자 · 인자 연결은 끝났다(2026-09-30 — 옛 ADR-0010 아카이브 · 코드 주석 · 시드 기계 변환 포함). 내부 변수 · switch · 상자 접기는 [[기능/함수조항/함수조항]] §3.7 에 **미구현**으로 둔다.
- **넣는 자리의 입력이 는다** — 기본 연결이 없는 인자(반복의 현재 원소 · 상수)는 사용처마다 연결한다.
- **함수조항을 고치면 시그니처가 바뀔 수 있다** — 인자를 더하면(기본 연결이 없으면) 사용처 전부에 「인자 연결이 비었습니다」가 생긴다. 재검사 목록([[기능/구분자/결정/ADR-0049-정의변경-경고허용-영향목록-복구재검사]])이 드러낸다.
- **함수조항 화면의 단독 시험은 일부만 된다** — 인자에 값을 넣어 출력을 보되, 사용처 노드 · 보통약관 노드를 가리키는 참조는 번호 대신 자리표시로 보인다.
- **박스 안 참조는 여전히 못 쓴다** — 박스 줄의 조 번호는 고정 글이라 조가 밀리면 틀린다(허용 차이 ⑦ 그대로).
- **상품별 옵션 오버라이드**([[기능/상품/상품]] §3.6)는 옵션이 조항 안에 남으므로 그대로다.
