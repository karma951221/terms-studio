# 마스터

> 상태: 초안 · 최종수정: 2026-09-28

## 1. 한 줄

모델링이 받는 **입력 항목의 정본** — 코드에 고정된 **폼 › 필드**다. 유저는 `/master` 에서 읽기만 하고, 필드 하나를 짚어 어느 구분자 · 조문이 그 값을 읽는지, 어느 노드에 값 자리가 있는지 거슬러 본다.
담보 · 상품 화면의 값 폼(폼 카드)도 이 정본에서 그려진다. 항목을 더하거나 바꾸는 것은 배포다.
메뉴 이름은 「폼」이다. 필드의 `목록값` · `목록값(복수)` 타입이 가리키는 **열거형변수**(선택지 목록)는 데이터라 따로 관리한다 → [[기능/열거형/열거형]].

## 3. 규칙

### 3.1 정본 — 코드 폼 › 필드

- 마스터 = **폼 › 필드**, 전부 코드(`MASTER`)가 정본이다. 유저가 만들거나 고치거나 지우는 것은 없다 — 더하고 바꾸는 것은 **배포 + 마이그레이션** (ADR-0037).
- **폼** = `폼키`(전역 유일 · 불변 · **`enums` 는 예약어라 쓰지 않는다**) · 표시명 · **레벨 하나** · 설명 · 필드 목록. 같은 폼을 두 레벨에 걸지 않는다 — 필요하면 폼을 둘 만든다(필드 정의가 중복되는 비용은 감수).
  — 왜: 폼이 레벨과 독립이면 한 폼이 두 레벨에 서서 `any(폼.필드)` 가 어느 레벨을 훑는지 모호해지고 레벨 접두 규칙이 따라온다.
  — 왜 `enums` 예약: 옛 주소 리다이렉트 `/master/enums`(→ `/enums`)가 정적 세그먼트라 폼 상세 `/master/[폼키]` 보다 먼저 잡힌다 — 폼키가 `enums` 면 그 폼 상세에 갈 길이 없다. 테스트(`reserved.test.ts`)가 막는다.
- **필드** = `필드키`(폼 안 유일 · 불변) · 표시명 · 타입 · 기본값(선택) · 설명. 레벨은 따로 없고 폼의 레벨을 따른다.
- 순서는 코드의 선언 순서다 — 폼 순서 · 필드 순서. 폴더 · 옮기기 · 미분류 같은 정리 편집은 없다.
  — 왜: 가지 = 폼이면 「어떻게 묶을까」를 사람이 정할 일이 없고, 마스터의 폼과 값 폼의 카드가 같은 코드에서 나와 어긋날 수 없다.
- **타입**은 `string` · `number` · `boolean` · `date` · `enum` · `list<enum>` · `table`(스칼라 열의 행 목록). 일반 `list<T>` 는 없다 (ADR-0037 §7 · ADR-0065).
  `enum` 계열은 열거형변수를 가리킨다 — 값은 데이터라 배포 없이 는다 ([[기능/열거형/열거형]] §3.1).
- **시스템 폼 · 필드**(`system`) — 급부의 감액 · 면책. 키 · 레벨 · 타입을 잠그는 근거다 (ADR-0065 §3).
- **기본 숨김 필드**(`hiddenByDefault`) — 값이 기본값 그대로면 값 폼이 칸을 감추고 「{표시명} 바꾸기」 링크로 편다. 기본값과 다르면 보인다. 지금은 감액 `after_rate` 하나 ([[기능/담보/담보]] §3.4).
- 필드 설명에는 「무엇을 판단하기 위한 입력인가 · 어느 조문에서 쓰나」 두 줄을 적는다. 필드를 더하는 배포 요청(이슈 · 커밋 본문)에도 같은 두 줄을 남긴다.
  — 왜: 「왜 있나」가 없으면 같은 항목이 다른 이름으로 다시 생긴다 — 구분자 설명과 같은 이유 ([[기능/구분자/구분자]] §3.6).

### 3.2 필드 코드 `폼키.필드키`

- 필드 코드 = **`폼키.필드키`** (`waiver.applies` · `pay.rate`). 폼키가 전역 유일이라 코드도 전역 유일이다. 레벨은 코드에 없다 — 폼이 레벨을 안다.
  — 왜: `레벨.필드키` 는 한 레벨에 같은 필드키(`applies`)가 여러 폼에 나와 유일하지 않고, `레벨.폼키.필드키` 는 폼이 이미 아는 레벨을 되풀이한다.
- 이 코드 하나가 구분자 식의 참조 · 값 저장 좌표 · 오류 메시지 · 관리자 코드 링크 · 사용처 조회를 꿴다. 별도 번호(`F0012` 같은)는 두지 않는다 — 경로가 곧 코드다.
- 코드가 식 · 값 행 · 오류 · 칩에 박히므로 **코드 변경은 곧 마이그레이션**이다.
- 식 참조 규칙(같은 레벨 그대로 · 하위는 집계 · 상위 금지)은 **폼의 레벨**로 판정한다 → [[기능/구분자/구분자]] §3.
- **추적은 이 코드로 양방향이다.** 역방향(필드 → 구분자 → 조문 · 값 노드)의 진입점은 필드 상세(§4.3), 정방향(산출물 조각 → 조문 단위 · 분기 → 조건식 → 구분자 값 → 필드 값 → 노드 입력)의 진입점은 조립산출의 **출처 패널**이다 — 안 탄 분기와 그 이유도 보인다. 출처는 **저장하지 않고 볼 때 재계산**한다 ([[기능/조립산출/조립산출]], 출처 패널 **미구현**).
  — 왜: 조립이 결정적이라 같은 입력이면 같은 추적이 나온다. 저장하면 산출본 스키마가 커지고 입력이 바뀐 뒤 낡은 추적이 남는다.
- **오류 메시지는 코드를 품는다** — 「구분자 X 평가 실패: `pay.rate` 미입력 (급부 ○○)」처럼 구분자 코드와 필드 코드가 박히고, 거기서 필드 상세 · 입력 화면으로 간다. 코드 링크는 **미구현** (§5).

### 3.4 값 자리

- **값 자리 = 노드 × 마스터 필드.** 그 레벨에 서는 폼의 필드 전부가 **모든 노드에 항상** 있다 — 부착 · 노출여부가 없다 (ADR-0037 §4).
- **선택 필드**(`MasterField.optional` — 보험금지급의 면책여부 · 지급률, 2026-09-27): 자리는 있지만 값이 없으면 **화면에 안 보이고 미입력으로 세지 않는다**(`countedSlotsOf`).
  읽기 모드는 값이 있을 때만 행이 서고, 편집 모드는 그 폼 아래 「⊕ {라벨}」로 더하고 라벨 옆 ⊖ 로 뺀다(값을 지운다). 어느 필드가 선택인지는 마스터 코드가 정한다 — 유저가 붙이지 않는다.
  식이 읽는 뜻은 그대로다 — 값 없는 선택 필드를 직접 읽으면 미입력이다(여는 폼의 「자리 없음」과 다르다).
- 세목만 다르다 — 세목 선택지는 제 세목유형(폼키) 폼의 값 자리만 갖는다.
- **여는 폼**(`optional` — 감액 · 면책): 값 행이 하나도 없으면 자리 자체가 없다. 미입력으로 세지 않고, 「열지 않음 = 감액 · 면책 없음」이다 (ADR-0065 §4).
- 값 자리는 **미입력**으로 태어난다. null 은 없다. 기본값은 폼 프리필일 뿐 저장소로 자동 유입되지 않는다 (ADR-0004).
- **폼 교차 규칙**(`MasterForm.rules`, 2026-09-30) — 필드 하나의 타입으로는 안 보이는 필드 사이의 뜻을 마스터 코드가 규칙으로 든다. 값 쓰기(상품 기본정보 저장 · 세목 선택지 값 제출)가 **최종 상태**(저장된 값 + 이번 제출)로 돌리고, 어기면 저장 거부 — 오류는 고칠 필드(`refPath`)와 종목 이름으로 안내한다.
  지금 규칙은 하나 — `waiver` 「적용여부 = 예면 납입면제사유 1개 이상」(미입력도 0개, [[기능/상품/상품]] §3.9). 적용여부가 미입력이면 규칙이 서지 않는다(미입력은 상태다).

### 3.5 값 폼 — 폼 하나가 카드 하나

- 노드 레벨에 서는 폼이 코드 순서대로 **카드** 하나씩 선다. 카드 제목 = 폼 표시명 — 마스터의 폼과 1:1. 폼 설명은 제목 옆 ⓘ tooltip 이다(2026-09-27 — 제목 줄에 늘어놓지 않는다).
  노드 카드(담보 상세 · 상품담보 값 화면의 담보 · 세부보장 · 급부 카드) 안에서는 폼 카드를 겹치지 않는다 — 필드 행이 노드 카드 본문에 바로 서고, 폼이 둘 이상 보일 때만 폼마다 작은 제목 한 줄([[기능/담보/담보]] §3.6, 2026-09-27).
- 타입별 입력은 매핑 하나로 그린다 — 문자열 · 숫자 · 날짜는 입력칸, 참거짓은 「예 · 아니오」 라디오, 목록값은 셀렉트, 목록값(복수)은 체크박스, `table` 은 표 입력(붙여넣기: 줄 = 행, 탭 = 열 · 기간은 `3M` · `1Y`).
- **프리필은 보이는 제안이다** — 기본값이 칸에 들어가 있고 「미입력」 + 「제안값 · 저장해야 확정」 배지가 선다. 저장해야 명시 값이 된다 (ADR-0004). 읽기 모드에는 「미입력」 배지가 없다 — 빈 칸은 빈 칸으로 보인다(2026-09-27).
- **저장 값 그대로인 칸은 제출하지 않는다** — 사람이 손대지 않은 저장 값은 변경 없음이다. 명시적 빈 목록 `[]` 도 그대로 남는다. 저장 값이 없는 프리필 칸은 여기 들지 않는다 — 보인 제안을 두고 저장하면 명시 값으로 실린다(저장이 곧 확인, [[공통/화면/디자인원칙]] §9.1).
  — 왜: 폼을 거친 값을 통째로 다시 쓰면 `[]` 가 빈 초안 = 미입력으로 읽혀 지워졌다(점검 2026-09-27 H3). 손대지 않은 칸을 다시 쓸 이유가 없다.
- **여는 폼(감액 · 면책)은 더하기 전엔 자리가 없다** (2026-09-27) — 닫힌 여는 폼은 읽기 모드에서 보이지 않고, 편집 모드에서는 폼 맨 아래 한 줄 「⊕ 감액」 · 「⊕ 면책」으로 선다. 연 폼은 제목 옆 ⊖ 로 닫는다 — 닫으면 그 폼의 값을 지운다.
- **관리자에게만** 필드 라벨 옆 작은 ⓘ 코드 링크 — tooltip 이 코드(`waiver.applies`), 누르면 그 필드의 마스터 상세. 라벨 옆에 코드를 글자로 늘어놓지 않는다(2026-09-27 — 필드 이름이 두 번 보였다). 편집자에게는 안 보인다 (ADR-0019). 칩이 서는 곳은 **담보 상세 값 폼**뿐이다 — 상품 기본정보의 세목 값은 표 칸이라 칩이 없고, 「입력 화면 →」으로 오면 그 칸만 강조한다 (2026-09-27 점검 D21 ②).
  — 왜: 코드는 오류 메시지에서 입력 자리를 찾는 추적용이고 추적은 관리자의 일이다. 편집자 화면을 코드로 어지럽히지 않는다.
- `?field=<코드>` 로 들어오면 그 필드 행을 강조하고 화면 가운데로 스크롤한다 — 마스터 값 노드 목록의 「입력 화면 →」이 이 길이다.
- 값 폼은 바깥 편집 화면(담보 상세 · 상품)의 저장 흐름에 얹힌다 — 저장 한 번이 화면의 변경을 다 담는다. 입력률 · 완결성 카운트는 없다.
- 탑재 스냅샷을 손댄 칸의 「마스터 값으로 되돌리기」는 [[기능/상품/상품]] §3.4.

## 4. 화면

좌측 내비 첫 단계 「기본정보」 그룹의 둘째 항목 「폼」 (열거형 → 폼 → 구분자 순, [[공통/화면/화면목록]]). 탭 줄 없이 제목만 선다. 내비는 `/master…` 어디서나 「폼」을 현재 위치로 칠한다.
**편집 · 저장 · 삭제 조작이 어디에도 없다** — 역할 구분 없이 같은 화면이다.
상세의 경로 첫 마디는 메뉴 이름 「폼」이고 조회(`/master`)로 간다.

### 4.1 `/master` — 조회 (L1)

```
폼 ⓘ
🔍[ 코드 · 표시명 · 폼 ] 〔검색〕
┌──────────┬──────────────┬──────────────┬────────────────────┐
│ 폼        │ 표시명        │ 타입          │ 코드                │
├──────────┼──────────────┼──────────────┼────────────────────┤
│ 납입면제   │ 적용여부      │ 참거짓        │ waiver.applies     │
│          │ 납입면제사유   │ 목록값(복수)   │ waiver.reasons     │  ← 같은 폼 연속 행은 폼 칸 하나
│ 무저해지   │ 유형          │ 목록값        │ no_surrender.type  │
│ 총 N건 · 1/1                                      이전  다음    │
└────────────────────────────────────────────────────────────────┘
```

| 자리 | 내용 |
|---|---|
| 제목 줄 | 「폼」 + ⓘ InfoTip(코드에 고정된 입력 항목 · 고치지 않는다 · 폼 하나 = 모델링 카드 하나 · 코드가 식 참조 · 값 좌표 · 오류 메시지에 쓰인다). `+` 는 없다 — 만들 것이 없는 화면 |
| 검색 | GET `?q=` + 「검색」 버튼. 코드 · 필드 표시명 · 폼 표시명 · 폼키 **부분 일치, 대소문자 무시**. 검색어를 바꾸면 1쪽으로 |
| 표 | 행 = 필드, 코드 순서. 컬럼 `폼 · 표시명 · 타입 · 코드` — 1열이 코드가 아닌 것은 L1 규칙의 예외(묶음 기준 열이 앞, [[공통/화면/디자인원칙]] §2 L1). 사람이 먼저 찾는 것은 「어느 폼의 무슨 항목」이고 코드는 복사 · 추적용이다 |
| 폼 칸 | 같은 폼의 연속 행을 한 칸으로 병합 — 되풀이하면 폼 › 필드 계층이 안 보인다. 폼이 페이지 경계에 걸리면 다음 쪽 첫 행에 다시 선다. 툴팁 「폼 · 레벨」 |
| 타입 칸 | 타입만(`목록값` · `목록값(복수)`). 어느 열거형인지는 툴팁과 상세 — 한 칸이 두 가지를 말하지 않게 |
| 페이저 | 20행 · `?page=` · 「총 N건」 |

| 상태 | 표시 |
|---|---|
| 코드에 폼이 하나도 없음 | 「정의된 입력 항목이 없습니다 — 코드에 폼을 더하면 여기 보입니다」 |
| 검색 결과 0 | 「맞는 항목이 없습니다」 |

| 조작 | 결과 |
|---|---|
| 행(필드 칸 · 코드 칸 · 빈 자리) 클릭 | 필드 상세 `/master/<폼키.필드키>` |
| 폼 칸 클릭 | 폼 상세 `/master/<폼키>` |
| 옛 주소 `/master?field=<코드>` · `?form=<폼키>` | 새 상세 주소로 리다이렉트 (둘 다 오면 필드) — 오류 메시지 · 칩 · 북마크 보존 |

상세 주소 `/master/<…>` 는 필드 코드와 폼키를 같은 자리에서 받는다 — `.` 이 있으면 필드, 없으면 폼이다.

### 4.2 `/master/<폼키>` — 폼 상세

제목 줄은 경로 `폼 › 납입면제`(「폼」 → `/master`) ([[공통/화면/디자인원칙]] §1.7). 읽기 전용 — 편집 버튼이 없다.

| 자리 | 내용 |
|---|---|
| 정체 | 코드(폼키 + ⧉ 복사) · 레벨 배지 · 설명(없으면 「(없음)」) |
| 필드 표 | 표시명 · 코드 · 타입(목록값 계열은 `▸ 열거형변수` 링크 → `/enums/<코드>`) · 기본값(없으면 「—」). 행 → 필드 상세. 필드 0 이면 「필드 없음」 |
| 서는 곳 | 「{레벨} 노드 N」 + 목록 링크 — 상품 · 세목은 「상품 목록 →」, 담보 · 세부보장 · 급부는 「담보 목록 →」. 세목은 이 폼을 세목유형으로 고른 선택지만 센다 |

### 4.3 `/master/<폼키.필드키>` — 필드 상세

제목 줄은 경로 `폼 › 납입면제 › 적용여부` — 폼 마디가 폼 상세로 간다. 추적의 **역방향 진입점**이다 (§3.2) — 입력을 고치기 전에 「이 필드가 어느 조문까지 번지나」를 본다. 정방향(산출물 조각 → 입력)은 [[기능/조립산출/조립산출]]의 출처 패널.

| 자리 | 내용 |
|---|---|
| 정체 | 코드 ⧉ · 폼(링크 → 폼 상세) + 레벨 배지 · 타입(목록값 계열은 열거형변수 링크) · 기본값 · 설명 |
| 사용처 — 구분자 | 이 코드를 식에서 읽는 구분자 — 구분자명(→ `/catalog/<코드>`) · 레벨 · `= 식`. 그 아래 「└ 조문」: 그 구분자를 읽는 조문 좌표(조건식 · 치환 슬롯, 링크) · 「└ 참조하는 구분자」. 0 이면 「이 필드를 읽는 구분자가 없습니다」 |
| 사용처 — 값 노드 | 이 필드의 값 자리가 있는 노드 **전부, 미입력 포함** — 어디가 비었느냐가 추적에서 더 중요하다. 라벨 가나다순 · 20건 페이저(`?page=`, 마지막 쪽을 넘으면 마지막 쪽으로). 0 이면 「아직 이 레벨의 노드가 없습니다」. 탑재 스냅샷 값은 넣지 않는다 |

값 노드 한 행 = 노드 경로 · 값 · 「입력 화면 →」.

| 레벨 | 노드 경로 | 「입력 화면 →」 |
|---|---|---|
| 상품 | 상품명 | `/products/<id>?field=<코드>` |
| 세목 | 상품명 › 세목 선택지 | `/products/<id>?option=<선택지>&field=<코드>` |
| 담보 · 세부보장 · 급부 | 담보 › 세부보장 › 급부 | `/coverages/<id>?node=<레벨:id>&field=<코드>` |

값 표기 — 목록값은 값 표시명, 미입력은 「미입력」, 명시적으로 빈 목록은 「(선택 없음)」, `table` 은 「N행」.

| 조작 | 결과 |
|---|---|
| ⧉ | 코드를 클립보드로 + 「복사했습니다」 |
| 폼 링크 · 경로의 폼 마디 | 폼 상세 |
| 열거형변수 링크 | 그 열거형변수 상세 `/enums/<코드>` ([[기능/열거형/열거형]] §4.3) |
| 구분자 · 조문 링크 | 구분자 상세 · 조문 편집 화면의 그 좌표 |
| 「입력 화면 →」 | 위 표의 화면 — 도착 화면이 그 필드를 강조 · 스크롤 |

| 상태 | 표시 |
|---|---|
| 코드에 없는 키(배포로 사라진 코드의 북마크 등) | 경로 `폼 › <키>` + 「찾을 수 없습니다」 |

## 5. 미결

- **값 노드 머리의 「명시 값 n · 미입력 m」** — 코드(`FieldDetail`)가 아직 보인다. 입력 관리는 숫자 없이 목록으로만 안내한다는 규칙([[공통/화면/디자인원칙]] §9.2)과 어긋나 **제거 대상**이다.
- **깨진 참조 배지** — 없는 코드를 참조하는 구분자를 사용처에서 오류 배지로 보이는 것. 서비스(`fieldUsage`)가 그 데이터를 주지 않아 **미구현**.
- **오류 메시지의 코드 링크**(§3.2 — 「`pay.rate` 미입력」의 코드가 마스터 필드 상세로, 노드가 입력 화면으로) — 앱 안에서 `/master` 로 가는 링크는 담보 상세 값 폼의 관리자 칩뿐이다. **미구현**, [[기능/조립산출/조립산출]]과 함께.
- 탑재 스냅샷 값을 값 노드 목록에 넣을지 — MVP 이후. 넣으면 같은 노드가 두 번 보인다.
- **오류를 발견하는 곳** — 시스템 안 산출물 미리보기인지, 내보낸 파일(hwp · pdf)인지. 후자면 출처 패널 앞에 「조항 번호 · 문장으로 시스템 안 자리를 찾는」 검색 단계가 하나 더 붙는다. 실물을 만들어 봐야 안다 (2026-09-13).
- 세목 노드 경로 표기 — 지금은 「상품명 › 세목 선택지」 한 줄. 종 · 형 축이 늘면 다시 본다.
- 수치 집계 `max` · `min` — ADR-0037 열린 문제.
- **목록값(복수)의 「(선택 없음)」 입력** — 명시적 빈 목록 `[]` 은 미입력과 다른 상태인데(ADR-0004), 화면에서 만들 수 없다: 체크를 모두 끄면 미입력이 된다. 저장된 `[]` 도 편집 중에는 빈 체크박스로 보여 미입력과 구별되지 않는다(저장은 §3.5 규칙으로 보존된다). 규칙은 「선택 없음」을 명시하는 상태를 두는 쪽(점검 D3 (a)) — **미구현**.
- `src/forms/model.ts` 의 `formProgress`(「값 자리 N 중 M 입력」)는 쓰는 곳이 없다 — 지울 코드.
- 유저 정의 폼(폼 생성 · 필드 편집기 · 선택 필드)은 MVP 이후 — 입력 항목은 코드 마스터다 ([[기능/마스터/결정/ADR-0037-입력항목-코드마스터-유저정의폼-MVP이후]]).

### 6.2 결정 메모

| 결정 | 왜 | 버린 안 |
|---|---|---|
| 마스터 = 코드 폼 › 필드, 정리 편집 없음 (§3.1) | 가지 = 폼이면 묶음을 사람이 정할 일이 없고, 마스터와 값 폼 카드가 같은 코드에서 나와 어긋나지 않는다 | 데이터 정리 트리 + 편집 규칙 여섯(폴더 · 옮기기 · 미분류 · 깊이 3 · 검색 중 편집 없음 …) — 첫 정리 한 번을 위한 장치 |
| 폼은 레벨 하나 (§3.1) | 식 참조의 레벨 모호함과 레벨 접두 규칙이 통째로 사라진다 | 폼은 레벨과 독립, 레벨별 폼 목록을 따로 — 두 레벨에 필요하면 폼 둘이 싸다 |
| 필드 코드 `폼키.필드키` (§3.2) | 트리 · 칩 · 식 참조 · 값 좌표 · 오류가 같은 두 토막 | `레벨.필드키`(유일하지 않다) · `레벨.폼키.필드키`(레벨 되풀이) · 불투명 번호 `F0012`(식별자 둘) |
| 추적 — 역방향은 필드 상세, 정방향은 출처 패널 · 출처는 재계산 (§3.2) | 값 하나를 짚으면 출처가 하나([[00_시작/문제정의]] S3)를 화면으로 갚는다 | 추적을 산출본과 함께 저장 · 마스터 화면을 레벨별 폼 다섯 개로 |
| 코드 링크는 관리자에게만 (§3.5) | 추적은 관리자의 일 · 역할이 스위치 | 누구나 토글 |
| 코드 링크는 담보 상세 값 폼에만 (§3.5, 2026-09-27 점검 D21 ②) | 세목 값은 기본정보 표 칸이다 — 자리 찾기는 「입력 화면 →」의 칸 강조가 맡는다 · 최소 변경 | 세목 표 칸에도 칩(D21 ①) — 상품 쪽에서도 마스터로 되돌아가는 왕복이 생기지만 표가 코드로 어지러워진다 |
| 값 노드 목록은 미입력 포함 · 숫자 요약 없음 (§4.3) | 추적에서는 어디가 비었느냐가 중요 · 입력 관리는 목록으로 | 명시 값만 · 탑재 스냅샷 값도 (같은 노드가 두 번) |
| `/master` = L1 목록 + 별도 상세, 제목 줄은 경로 (§4, 2026-09-27) | 다른 조회 화면(목록 → 상세)과 같은 문법 | 두 칸(목록 + 상세 한 화면) — 목록을 보며 상세를 보던 편의는 잃는다 |
| 목록 컬럼 `폼 · 표시명 · 타입 · 코드` · 폼 칸 병합 · 타입 칸은 타입만 (§4.1) | 먼저 찾는 것은 「어느 폼의 무슨 항목」 · 되풀이는 계층을 가린다 · 한 칸 한 뜻 | 코드 1열 · 폼을 행마다 되풀이(2026-09-16) · 타입 칸에 열거형 이름 또는 「목록: 이름」 |
| 저장 값 그대로인 칸은 제출하지 않는다 (§3.5, 2026-09-27) | `[]` 가 값 폼을 한 번 거치면 지워지던 것(점검 H3)을 규칙을 바꾸지 않고 막는 최소 방어(점검 D3 (c)). 「(선택 없음)」 입력(D3 (a))은 §5 | `[]` 를 미입력과 같게 본다(D3 (b) — ADR-0004 가 둘을 다른 상태로 본다) |
| `coverage_basic.claim_name` 의 라벨은 「보험금명」 — 필드 코드는 그대로 (§3.3, 2026-09-27) | 값은 조문이 「…을 ○○로 지급합니다」에 찍는 보험금 이름(사망보험금 · 골절진단비)이라 담보명(「골절(치아파절 제외)진단비Ⅱ보장」)과 다르다. 같은 「담보명」 라벨이 담보 카드 제목 아래 다른 값으로 두 번 보였다(브라우저 점검 2026-09-27). 코드는 값 좌표 · 구분자 식이 쓰므로 두고 라벨만 바꾼다 | 「담보명」 유지 · 「청구명」(청구 서식 이름으로 읽힌다) · 「약관 표기 담보명」(담보명과 또 헷갈린다) · 필드 코드도 `benefit_name` 으로(값 행 · 식 마이그레이션 비용) |
| 필드 단위 선택(+) — `MasterField.optional`, 면책여부 · 지급률 (§3.4, 2026-09-27) | 급부 카드마다 면책여부 · 지급률 칸이 늘 떠 있어 안 쓰는 급부도 화면이 길었다(사용자 피드백 2026-09-27). 감액 · 면책의 「⊕ 폼」과 같은 문법을 필드에 내려 필요한 급부만 더한다. 값 없는 선택 필드는 「안 씀」이라 미입력으로 세지 않는다 · 정하는 것은 마스터 코드(ADR-0037 의 유저 정의 선택 필드는 여전히 MVP 이후) | 늘 보임(지금까지) · 폼 전체를 여는 폼으로(보험금지급을 통째로 ⊕ — 둘 중 하나만 쓰는 급부가 많다) · `hiddenByDefault`(기본값이 있어야 숨는다 · 면책여부 · 지급률은 기본값이 없다) |
| `pay.first_only`(최초1회한) 삭제 (§3.3, 2026-09-27) | 필요 없는 칸이라는 사용자 판단(2026-09-27). 실물 재현 2차에서 「최초 1회에 한하여」 문면의 변형 트리거로 더했지만 그 변형은 아직 미검증이고 쓰는 구분자 · 문면이 없다. 값 행은 마이그레이션 0016 이 지운다(화면에선 안 보여도 스냅샷 드리프트 · 지울 값 행 수에 잡히므로). 「최초 1회에 한하여」가 가르는 소멸 조는 담보 구조 유형으로 템플릿이 조합한다([[QA/실물재현/알파플러스_모델명세]] §3.2, 2026-09-28) — 필드 · 플래그가 필요 없다 | 필드를 두고 숨김 · 선택 필드로(칸은 안 보여도 필요 없는 자리가 남는다) · 값 행을 남김(알 수 없는 경로 행이 셈에 새다) |
| 필드 설명 · 배포 요청에 근거 두 줄 (§3.1) | 「왜 있나」가 없으면 같은 항목이 다른 이름으로 다시 생긴다 | — |
