# 마스터

> 상태: 초안 · 최종수정: 2026-09-27

## 1. 한 줄

모델링이 받는 **입력 항목의 정본** — 코드에 고정된 **폼 › 필드**다. 유저는 `/master` 에서 읽기만 하고, 필드 하나를 짚어 어느 구분자 · 조문이 그 값을 읽는지, 어느 노드에 값 자리가 있는지 거슬러 본다.
담보 · 상품 화면의 값 폼(폼 카드)도 이 정본에서 그려진다. 항목을 더하거나 바꾸는 것은 배포다.
둘째 탭 `/master/enums` 는 **열거형변수**(목록값 타입이 고르는 선택지 목록)를 관리한다 — 필드의 `목록값` · `목록값(복수)` 타입이 여기 정의를 가리키고, 값은 데이터라 **배포 없이** 편집자가 늘리고 고친다.
구분자는 「무엇을 묻나」, 열거형변수는 「어떤 값으로 답하나」다.

## 3. 규칙

### 3.1 정본 — 코드 폼 › 필드

- 마스터 = **폼 › 필드**, 전부 코드(`MASTER`)가 정본이다. 유저가 만들거나 고치거나 지우는 것은 없다 — 더하고 바꾸는 것은 **배포 + 마이그레이션** (ADR-0037).
- **폼** = `폼키`(전역 유일 · 불변 · **`enums` 는 예약어라 쓰지 않는다**) · 표시명 · **레벨 하나** · 설명 · 필드 목록. 같은 폼을 두 레벨에 걸지 않는다 — 필요하면 폼을 둘 만든다(필드 정의가 중복되는 비용은 감수).
  — 왜: 폼이 레벨과 독립이면 한 폼이 두 레벨에 서서 `any(폼.필드)` 가 어느 레벨을 훑는지 모호해지고 레벨 접두 규칙이 따라온다.
  — 왜 `enums` 예약: 탭 경로 `/master/enums` 가 정적 세그먼트라 폼 상세 `/master/[폼키]` 보다 먼저 잡힌다 — 폼키가 `enums` 면 그 폼 상세에 갈 길이 없다. 테스트(`reserved.test.ts`)가 막는다.
- **필드** = `필드키`(폼 안 유일 · 불변) · 표시명 · 타입 · 기본값(선택) · 설명. 레벨은 따로 없고 폼의 레벨을 따른다.
- 순서는 코드의 선언 순서다 — 폼 순서 · 필드 순서. 폴더 · 옮기기 · 미분류 같은 정리 편집은 없다.
  — 왜: 가지 = 폼이면 「어떻게 묶을까」를 사람이 정할 일이 없고, 마스터의 폼과 값 폼의 카드가 같은 코드에서 나와 어긋날 수 없다.
- **타입**은 `string` · `number` · `boolean` · `date` · `enum` · `list<enum>` · `table`(스칼라 열의 행 목록). 일반 `list<T>` 는 없다 (ADR-0037 §7 · ADR-0065).
  `enum` 계열은 열거형변수를 가리킨다 — 값은 데이터라 배포 없이 는다 (§3.6).
- **시스템 폼 · 필드**(`system`) — 급부의 감액 · 면책. 키 · 레벨 · 타입을 잠그는 근거다 (ADR-0065 §3).
- **기본 숨김 필드**(`hiddenByDefault`) — 값이 기본값 그대로면 값 폼이 칸을 감추고 「{표시명} 바꾸기」 링크로 편다. 기본값과 다르면 보인다. 지금은 감액 `after_rate` 하나 ([[기능/담보/담보]] §3.4).
- 필드 설명에는 「무엇을 판단하기 위한 입력인가 · 어느 조문에서 쓰나」 두 줄을 적는다. 필드를 더하는 배포 요청(이슈 · 커밋 본문)에도 같은 두 줄을 남긴다.
  — 왜: 「왜 있나」가 없으면 같은 항목이 다른 이름으로 다시 생긴다 — 구분자 설명과 같은 이유 ([[기능/구분자/구분자]] §3.6).

### 3.2 필드 코드 `폼키.필드키`

- 필드 코드 = **`폼키.필드키`** (`waiver.applies` · `pay.rate`). 폼키가 전역 유일이라 코드도 전역 유일이다. 레벨은 코드에 없다 — 폼이 레벨을 안다.
  — 왜: `레벨.필드키` 는 한 레벨에 같은 필드키(`applies`)가 여러 폼에 나와 유일하지 않고, `레벨.폼키.필드키` 는 폼이 이미 아는 레벨을 되풀이한다.
- 이 코드 하나가 구분자 식의 참조 · 값 저장 좌표 · 오류 메시지 · 관리자 코드 칩 · 사용처 조회를 꿴다. 별도 번호(`F0012` 같은)는 두지 않는다 — 경로가 곧 코드다.
- 코드가 식 · 값 행 · 오류 · 칩에 박히므로 **코드 변경은 곧 마이그레이션**이다.
- 식 참조 규칙(같은 레벨 그대로 · 하위는 집계 · 상위 금지)은 **폼의 레벨**로 판정한다 → [[기능/구분자/구분자]] §3.
- **추적은 이 코드로 양방향이다.** 역방향(필드 → 구분자 → 조문 · 값 노드)의 진입점은 필드 상세(§4.3), 정방향(산출물 조각 → 조문 단위 · 분기 → 조건식 → 구분자 값 → 필드 값 → 노드 입력)의 진입점은 조립산출의 **출처 패널**이다 — 안 탄 분기와 그 이유도 보인다. 출처는 **저장하지 않고 볼 때 재계산**한다 ([[기능/조립산출/조립산출]], 출처 패널 **미구현**).
  — 왜: 조립이 결정적이라 같은 입력이면 같은 추적이 나온다. 저장하면 산출본 스키마가 커지고 입력이 바뀐 뒤 낡은 추적이 남는다.
- **오류 메시지는 코드를 품는다** — 「구분자 X 평가 실패: `pay.rate` 미입력 (급부 ○○)」처럼 구분자 코드와 필드 코드가 박히고, 거기서 필드 상세 · 입력 화면으로 간다. 코드 링크는 **미구현** (§5).

- 세목 폼 넷이 곧 **세목유형**이다 — 세목 선택지가 폼키로 폼 하나를 고른다.
- 세목 폼 필드의 기본값(상품 §3.2 — 선택지는 기본값으로 태어난다)은 **미구현** — `MASTER` 의 세목 폼에 `defaultValue` 가 없다. 프리필 동작은 [[기능/상품/상품]].

### 3.4 값 자리

- **값 자리 = 노드 × 마스터 필드.** 그 레벨에 서는 폼의 필드 전부가 **모든 노드에 항상** 있다 — 부착 · 노출여부 · 선택 필드가 없다 (ADR-0037 §4).
- 세목만 다르다 — 세목 선택지는 제 세목유형(폼키) 폼의 값 자리만 갖는다.
- **여는 폼**(`optional` — 감액 · 면책): 값 행이 하나도 없으면 자리 자체가 없다. 미입력으로 세지 않고, 「열지 않음 = 감액 · 면책 없음」이다 (ADR-0065 §4).
- 값 자리는 **미입력**으로 태어난다. null 은 없다. 기본값은 폼 프리필일 뿐 저장소로 자동 유입되지 않는다 (ADR-0004).

### 3.5 값 폼 — 폼 하나가 카드 하나

- 노드 레벨에 서는 폼이 코드 순서대로 **카드** 하나씩 선다. 카드 제목 = 폼 표시명 — 마스터의 폼과 1:1.
- 타입별 입력은 매핑 하나로 그린다 — 문자열 · 숫자 · 날짜는 입력칸, 참거짓은 「예 · 아니오」 라디오, 목록값은 셀렉트, 목록값(복수)은 체크박스, `table` 은 표 입력(붙여넣기: 줄 = 행, 탭 = 열 · 기간은 `3M` · `1Y`).
- **프리필은 보이는 제안이다** — 기본값이 칸에 들어가 있고 「미입력」 + 「제안값 · 저장해야 확정」 배지가 선다. 저장해야 명시 값이 된다 (ADR-0004).
- **저장 값 그대로인 칸은 제출하지 않는다** — 사람이 손대지 않은 저장 값은 변경 없음이다. 명시적 빈 목록 `[]` 도 그대로 남는다. 저장 값이 없는 프리필 칸은 여기 들지 않는다 — 보인 제안을 두고 저장하면 명시 값으로 실린다(저장이 곧 확인, [[공통/화면/디자인원칙]] §9.1).
  — 왜: 폼을 거친 값을 통째로 다시 쓰면 `[]` 가 빈 초안 = 미입력으로 읽혀 지워졌다(점검 2026-09-27 H3). 손대지 않은 칸을 다시 쓸 이유가 없다.
- 여는 폼 카드는 「⊕ 열기」 · 「⊖ 닫기」 — 닫으면 그 폼의 값을 지운다.
- **관리자에게만** 필드 라벨 옆 코드 칩(`waiver.applies`) — 누르면 그 필드의 마스터 상세. 편집자에게는 안 보인다 (ADR-0019). 칩이 서는 곳은 **담보 상세 값 폼**뿐이다 — 상품 기본정보의 세목 값은 표 칸이라 칩이 없고, 「입력 화면 →」으로 오면 그 칸만 강조한다 (2026-09-27 점검 D21 ②).
  — 왜: 코드는 오류 메시지에서 입력 자리를 찾는 추적용이고 추적은 관리자의 일이다. 편집자 화면을 코드로 어지럽히지 않는다.
- `?field=<코드>` 로 들어오면 그 필드 행을 강조하고 화면 가운데로 스크롤한다 — 마스터 값 노드 목록의 「입력 화면 →」이 이 길이다.
- 값 폼은 바깥 편집 화면(담보 상세 · 상품)의 저장 흐름에 얹힌다 — 저장 한 번이 화면의 변경을 다 담는다. 입력률 · 완결성 카운트는 없다.
- 탑재 스냅샷을 손댄 칸의 「마스터 값으로 되돌리기」는 [[기능/상품/상품]] §3.4.

### 3.6 열거형변수와 값

- 열거형변수 = 코드 · 이름 · 값 목록. 값 = 코드 · 이름 · 순서.
- **코드는 자동 채번 · 불변** — 열거형변수 `E0001` 부터, 값은 그 열거형변수 안에서 `V01` 부터. 유저가 입력하지 않는다 (ADR-0005).
- 저장 · 식 · 값 행은 **값 코드**를 쓰고, 화면은 이름을 쓴다. 이름은 언제든 바꿔도 식 · 저장 값이 안 깨진다 (ADR-0005).
- 열거형변수 이름은 전체에서 중복 거부. 값 이름은 그 열거형변수 안에서 중복 거부 — 앞뒤 공백 · 연속 공백 · 대소문자를 무시하고 비교한다 (화면과 서버가 같은 규칙).
- **상세 저장은 최종 값 목록으로 한 번에 검사한다** — 값 이름 A↔B 맞바꾸기, 다른 값이 비우거나 빠지며 내놓는 이름 받기가 된다. 중복은 저장 뒤 목록에서 겹칠 때만이다. — 왜: 한 단계씩(개명 → 추가 → 삭제) 검사하면 최종 상태가 유효해도 중간 상태에서 「중복」으로 거부됐다 (점검 2026-09-27 H2 ①). 도메인 `reviseEnum`.
- 값 순서 = 값 폼 선택지의 표시 순서. 저장 값에 영향 없다.
- **값 추가는 자유** — 코드 배포 없이 즉시 선택지가 는다 (ADR-0037 §5). 값에 「사용중지」 상태는 없다 — 추가와 삭제뿐.
- 누가 쓰나 — 마스터 필드의 타입(`목록값 ▸ 열거형변수`)과 구분자의 명시 결과 타입. 마스터 필드는 코드라 그 참조는 배포로만 끊긴다 (§3.1).
- 폼과 달리 **열거형변수는 데이터**다 — 그래서 마스터 안에서 이 탭만 생성 · 편집 · 삭제가 있다.

### 3.7 열거형변수 삭제 — 관리자

| 삭제 | 누가 | 지금 코드의 결과 |
|---|---|---|
| 값 | **관리자** — 편집자 요청은 서버 거부 | 상세 편집에서 ✕ 로 빼고 **저장할 때** 영향(그 값을 고른 저장 값 수 · 깨질 참조, 빠진 값 전부를 합쳐서) 확인 뒤 삭제 — **그 값을 고른 값 행도 함께 지운다** |
| 열거형변수 | **관리자** — 편집자 요청은 서버 거부 | 영향(값 전부 · 이 타입을 쓰는 마스터 필드 좌표 · 값 행 수) 확인 뒤 삭제 — **그 필드들의 값 행도 지운다** |

- 값 삭제가 목록값(복수) 자리에 닿으면 배열에서 그 원소만 빼고, **그래서 빈 배열이 된 행만** 지운다(미입력). 원래부터 빈 배열이던 행(명시적 「(선택 없음)」)은 그 값을 고른 적이 없으니 건드리지 않는다 — 확인창의 「그 값을 고른 저장 값 수」와 실제로 지우는 행이 같다 (점검 2026-09-27 M17).
- 두 단계 확인 — 관리자 첫 요청은 영향 목록을 돌려주고, 확인해야 실행한다 ([[공통/화면/결정/ADR-0019-모드폐지-역할권한]]).
- 기획 규칙(〔D-P1-17〕 마스터 필드가 쓰는 열거형변수는 삭제 거부 · 〔D-P1-18〕 지운 값을 고른 저장 값은 오류 상태로 남김)과 코드가 다르다 — §5 미결.

## 4. 화면

좌측 내비 「기준 데이터」 그룹의 첫 항목 「마스터」 (마스터 · 구분자 순). 하위 탭 **`폼 | 열거형변수`** — 탭은 URL 이다(폼 `/master` · 열거형변수 `/master/enums`). 제목은 두 탭 모두 「마스터」, 탭 줄은 제목 줄 아래.
폼 탭(§4.1 ~ §4.3)에는 **편집 · 저장 · 삭제 조작이 어디에도 없다** — 역할 구분 없이 같은 화면이다. 열거형변수 탭(§4.4 ~ §4.6)은 데이터라 만들고 고친다.
열거형변수 상세 · 생성의 경로 첫 마디 「마스터」는 열거형변수 탭(`/master/enums`)으로 간다. 옛 주소 `/types` · `/types/enums…` · `/catalog/enums` 는 `/master/enums…` 로 보낸다.

### 4.1 `/master` — 조회 (L1)

```
마스터 ⓘ
[폼] 열거형변수
🔍[ 코드 · 표시명 · 폼 ] 〔검색〕
┌──────────┬──────────────┬──────────────┬────────────────────┐
│ 폼        │ 표시명        │ 타입          │ 코드                │
├──────────┼──────────────┼──────────────┼────────────────────┤
│ 납입면제   │ 적용여부      │ 참거짓        │ waiver.applies     │
│          │ 납입면제사유   │ 목록값(복수)   │ waiver.reasons     │  ← 같은 폼 연속 행은 폼 칸 하나
│ 무저해지   │ 유형          │ 목록값        │ no_surrender.type  │
│ 총 N건 · 1/1                                      이전  다음    │
└────────────────────────────────────────────────────────────────┘
```

| 자리 | 내용 |
|---|---|
| 제목 줄 | 「마스터」 + ⓘ InfoTip(코드에 고정된 입력 항목 · 고치지 않는다 · 폼 하나 = 모델링 카드 하나 · 코드가 식 참조 · 값 좌표 · 오류 메시지에 쓰인다). `+` 는 없다 — 만들 것이 없는 화면. 아래에 탭 줄 `폼 | 열거형변수`(폼이 현재) |
| 검색 | GET `?q=` + 「검색」 버튼. 코드 · 필드 표시명 · 폼 표시명 · 폼키 **부분 일치, 대소문자 무시**. 검색어를 바꾸면 1쪽으로 |
| 표 | 행 = 필드, 코드 순서. 컬럼 `폼 · 표시명 · 타입 · 코드` — 1열이 코드가 아닌 것은 L1 규칙의 예외(묶음 기준 열이 앞, [[공통/화면/디자인원칙]] §2 L1). 사람이 먼저 찾는 것은 「어느 폼의 무슨 항목」이고 코드는 복사 · 추적용이다 |
| 폼 칸 | 같은 폼의 연속 행을 한 칸으로 병합 — 되풀이하면 폼 › 필드 계층이 안 보인다. 폼이 페이지 경계에 걸리면 다음 쪽 첫 행에 다시 선다. 툴팁 「폼 · 레벨」 |
| 타입 칸 | 타입만(`목록값` · `목록값(복수)`). 어느 열거형인지는 툴팁과 상세 — 한 칸이 두 가지를 말하지 않게 |
| 페이저 | 20행 · `?page=` · 「총 N건」 |

| 상태 | 표시 |
|---|---|
| 코드에 폼이 하나도 없음 | 「정의된 입력 항목이 없습니다 — 코드에 폼을 더하면 여기 보입니다」 |
| 검색 결과 0 | 「맞는 항목이 없습니다」 |

| 조작 | 결과 |
|---|---|
| 행(필드 칸 · 코드 칸 · 빈 자리) 클릭 | 필드 상세 `/master/<폼키.필드키>` |
| 폼 칸 클릭 | 폼 상세 `/master/<폼키>` |
| 옛 주소 `/master?field=<코드>` · `?form=<폼키>` | 새 상세 주소로 리다이렉트 (둘 다 오면 필드) — 오류 메시지 · 칩 · 북마크 보존 |

상세 주소 `/master/<…>` 는 필드 코드와 폼키를 같은 자리에서 받는다 — `.` 이 있으면 필드, 없으면 폼이다.

### 4.2 `/master/<폼키>` — 폼 상세

제목 줄은 경로 `마스터 › 납입면제` ([[공통/화면/디자인원칙]] §1.7). 읽기 전용 — 편집 버튼이 없다.

| 자리 | 내용 |
|---|---|
| 정체 | 코드(폼키 + ⧉ 복사) · 레벨 배지 · 설명(없으면 「(없음)」) |
| 필드 표 | 표시명 · 코드 · 타입(목록값 계열은 `▸ 열거형변수` 링크 → `/master/enums/<코드>`) · 기본값(없으면 「—」). 행 → 필드 상세. 필드 0 이면 「필드 없음」 |
| 서는 곳 | 「{레벨} 노드 N」 + 목록 링크 — 상품 · 세목은 「상품 목록 →」, 담보 · 세부보장 · 급부는 「담보 목록 →」. 세목은 이 폼을 세목유형으로 고른 선택지만 센다 |

### 4.3 `/master/<폼키.필드키>` — 필드 상세

제목 줄은 경로 `마스터 › 납입면제 › 적용여부` — 폼 마디가 폼 상세로 간다. 추적의 **역방향 진입점**이다 (§3.2) — 입력을 고치기 전에 「이 필드가 어느 조문까지 번지나」를 본다. 정방향(산출물 조각 → 입력)은 [[기능/조립산출/조립산출]]의 출처 패널.

| 자리 | 내용 |
|---|---|
| 정체 | 코드 ⧉ · 폼(링크 → 폼 상세) + 레벨 배지 · 타입(목록값 계열은 열거형변수 링크) · 기본값 · 설명 |
| 사용처 — 구분자 | 이 코드를 식에서 읽는 구분자 — 구분자명(→ `/catalog/<코드>`) · 레벨 · `= 식`. 그 아래 「└ 조문」: 그 구분자를 읽는 조문 좌표(조건식 · 치환 슬롯, 링크) · 「└ 참조하는 구분자」. 0 이면 「이 필드를 읽는 구분자가 없습니다」 |
| 사용처 — 값 노드 | 이 필드의 값 자리가 있는 노드 **전부, 미입력 포함** — 어디가 비었느냐가 추적에서 더 중요하다. 라벨 가나다순 · 20건 페이저(`?page=`, 마지막 쪽을 넘으면 마지막 쪽으로). 0 이면 「아직 이 레벨의 노드가 없습니다」. 탑재 스냅샷 값은 넣지 않는다 |

값 노드 한 행 = 노드 경로 · 값 · 「입력 화면 →」.

| 레벨 | 노드 경로 | 「입력 화면 →」 |
|---|---|---|
| 상품 | 상품명 | `/products/<id>?field=<코드>` |
| 세목 | 상품명 › 세목 선택지 | `/products/<id>?option=<선택지>&field=<코드>` |
| 담보 · 세부보장 · 급부 | 담보 › 세부보장 › 급부 | `/coverages/<id>?tab=<레벨>&node=<레벨:id>&field=<코드>` |

값 표기 — 목록값은 값 표시명, 미입력은 「미입력」, 명시적으로 빈 목록은 「(선택 없음)」, `table` 은 「N행」.

| 조작 | 결과 |
|---|---|
| ⧉ | 코드를 클립보드로 + 「복사했습니다」 |
| 폼 링크 · 경로의 폼 마디 | 폼 상세 |
| 열거형변수 링크 | 열거형변수 탭의 그 열거형변수 상세 (§4.6) |
| 구분자 · 조문 링크 | 구분자 상세 · 조문 편집 화면의 그 좌표 |
| 「입력 화면 →」 | 위 표의 화면 — 도착 화면이 그 필드를 강조 · 스크롤 |

| 상태 | 표시 |
|---|---|
| 코드에 없는 키(배포로 사라진 코드의 북마크 등) | 경로 `마스터 › <키>` + 「찾을 수 없습니다」 |

### 4.4 `/master/enums` — 열거형변수 조회 (L1)

```
마스터                                                            〔+〕
폼 [열거형변수]
🔍[ 코드 · 열거형변수 이름 · 값 ]              기준일 2026-09-27 🔒 미확정 포함 꺼짐 🔒
┌───────┬──────────────┬────────────────────────────────┬───────┬────────────┬──────┐
│ 코드   │ 열거형변수 이름 │ 값                              │사용처 ▾│ 최종수정    │ 수정자│
├───────┼──────────────┼────────────────────────────────┼───────┼────────────┼──────┤
│ E0001 │ 납입면제사유   │ (사망)(장해)(암진단)(뇌졸중)(급성심근경색) +2 │ 1     │ 2026-09-12 │ admin│
│ 총 N건                                                              ‹ › │
└──────────────────────────────────────────────────────────────────────────┘
```

| 자리 | 내용 |
|---|---|
| 제목 줄 | 「마스터」 + `+`(새 열거형변수) — `+` 는 이 탭에만 선다. 검색어가 있으면 생성 화면 이름 칸에 넘긴다(`?q=`). 아래에 탭 줄(열거형변수가 현재) |
| 검색 | 코드 · 이름 · **값 이름**까지 부분 일치 — 「간편심사」를 치면 그 열거형변수가 나온다. 디바운스 300ms · `?q=` |
| 기준일 · 미확정 포함 | 자리만 있고 잠김 (이력은 MVP 이후) |
| 컬럼 | 코드 · 열거형변수 이름(→ 상세) · 값(순서대로 칩 앞 5개 + 「+N」, 전체는 툴팁) · 사용처(머리글 필터 있음 · 없음 — 이 열거형변수를 타입으로 쓰는 마스터 필드 수, 0 이면 「—」) · 최종수정 · 수정자 |
| 페이저 | 50행 · `?page=` |

| 상태 | 표시 |
|---|---|
| 0건 | EmptyState — 「열거형변수는 목록값 타입이 고르는 값의 정의다.」 + 예시(심사유형: 일반심사 · 간편심사) + 「새 열거형변수」 |
| 필터 결과 0 | 「이 조건에 맞는 열거형변수가 없습니다.」 |

### 4.5 `/master/enums/new` — 열거형변수 생성

제목 줄은 경로 `마스터 › 새 열거형변수`(「마스터」 → `/master/enums`), 제출(「생성」)은 헤더 오른쪽. 생성하면 상세로 간다.

| 칸 | 입력 |
|---|---|
| 열거형변수 이름 | 텍스트 · 필수. 목록 검색어가 넘어오면 프리필 + 「제안」 배지 |
| 값 | 값 표 — 순서 · 값 이름(표 안에서 바로 적는다) · 위 · 아래 · 빼기. 표 머리 「+」 가 빈 행을 넣는다. 처음부터 빈 행 둘 |

- 값 칸에서 Enter — 다음 행으로, 마지막 행이면 새 행 (한글 조합 중에는 무시).
- **중복 값**은 행에 「중복된 값입니다.」 + 브라우저 검증으로 「생성」을 막는다.
- 빈 행은 지금 `required` 로 막힌다 — 쓰지 않을 빈 행은 「빼기」로 지워야 생성된다 (§5 미결).

### 4.6 `/master/enums/<code>` — 열거형변수 상세 · 수정

제목 줄은 경로 `마스터 › {이름}`(「마스터」 → `/master/enums`), 코드는 옆의 메타(mono) ([[공통/화면/디자인원칙]] §1.7). 읽기 모드로 시작하고 「편집」 → 「저장」 하나로 이름 · 값 이름 · 순서 · 새 값 · 값 빼기를 함께 반영한다 — 한 트랜잭션이라 거부되면 아무것도 남지 않는다.

| 칸 | 읽기 | 편집 |
|---|---|---|
| 열거형변수 이름 | 잠긴 칸 | 입력 |
| 값 표 | 순서 · 값 이름 · 사용 수(식 · 조건식이 그 값을 비교하는 곳의 수, 0 이면 「—」) | + 조작 열: 위 · 아래 · ✕(저장된 값은 「빼기 — 저장할 때 삭제」, 새 값은 「추가 취소」). 머리 「+」 가 빈 행을 넣는다 |

| 모드 | 헤더 오른쪽 |
|---|---|
| 읽기 | 「사용처 N」(이 열거형변수를 타입으로 쓰는 마스터 필드, 0 이면 「아무 구분자 · 필드도 이 열거형변수를 타입으로 쓰지 않는다.」) · 「편집」 · 🗑 |
| 편집 | ✕ · 「저장」 · 🗑(비활성, tooltip 「저장하거나 취소한 뒤 실행」) |

| 조작 | 결과 |
|---|---|
| 「+」 · 마지막 행에서 Enter | 빈 행 추가 + 포커스. **빈 채로 남은 새 행은 저장 때 버린다** |
| 위 · 아래 | 순서 바꿈 — 저장 때 반영 |
| ✕ | 그 행만 표에서 뺀다 — 편집 중 변경이라 확인이 없고 ✕(편집 취소)로 되돌아간다. 저장된 값은 저장할 때 삭제된다 |
| 저장 | 이름 · 최종 값 목록(새 값은 발급 코드로 제출 순서 유지)을 **한 트랜잭션**에 반영한다. 뺀 저장된 값이 있으면 먼저 확인 대화상자 — 「값을 빼면 저장된 값이 사라질 수 있다」 · 사라질 값 행 · 깨질 참조(빠진 값 전부 합계) · 「값 N개 삭제하고 저장」. 편집자는 서버 거부. 거부 · 대화상자 취소면 아무것도 저장되지 않고 편집 유지 + 사유 |
| 🗑 (읽기에서만) | 열거형변수 삭제 — 관리자 · 영향 확인 뒤 목록(`/master/enums`)으로. 편집 중에는 꺼진다 — 즉시 실행 명령이라서 (디자인원칙 §2 L2) |

| 상태 | 표시 |
|---|---|
| 없는 코드 | 경로 `마스터 › <코드>` + 「찾을 수 없습니다.」 |

## 5. 미결

- **값 노드 머리의 「명시 값 n · 미입력 m」** — 코드(`FieldDetail`)가 아직 보인다. 입력 관리는 숫자 없이 목록으로만 안내한다는 규칙([[공통/화면/디자인원칙]] §9.2)과 어긋나 **제거 대상**이다.
- **깨진 참조 배지** — 없는 코드를 참조하는 구분자를 사용처에서 오류 배지로 보이는 것. 서비스(`fieldUsage`)가 그 데이터를 주지 않아 **미구현**.
- **오류 메시지의 코드 링크**(§3.2 — 「`pay.rate` 미입력」의 코드가 마스터 필드 상세로, 노드가 입력 화면으로) — 앱 안에서 `/master` 로 가는 링크는 담보 상세 값 폼의 관리자 칩뿐이다. **미구현**, [[기능/조립산출/조립산출]]과 함께.
- 탑재 스냅샷 값을 값 노드 목록에 넣을지 — MVP 이후. 넣으면 같은 노드가 두 번 보인다.
- **오류를 발견하는 곳** — 시스템 안 산출물 미리보기인지, 내보낸 파일(hwp · pdf)인지. 후자면 출처 패널 앞에 「조항 번호 · 문장으로 시스템 안 자리를 찾는」 검색 단계가 하나 더 붙는다. 실물을 만들어 봐야 안다 (2026-09-13).
- 세목 노드 경로 표기 — 지금은 「상품명 › 세목 선택지」 한 줄. 종 · 형 축이 늘면 다시 본다.
- 수치 집계 `max` · `min` — ADR-0037 열린 문제.
- **목록값(복수)의 「(선택 없음)」 입력** — 명시적 빈 목록 `[]` 은 미입력과 다른 상태인데(ADR-0004), 화면에서 만들 수 없다: 체크를 모두 끄면 미입력이 된다. 저장된 `[]` 도 편집 중에는 빈 체크박스로 보여 미입력과 구별되지 않는다(저장은 §3.5 규칙으로 보존된다). 규칙은 「선택 없음」을 명시하는 상태를 두는 쪽(점검 D3 (a)) — **미구현**.
- `src/forms/model.ts` 의 `formProgress`(「값 자리 N 중 M 입력」)는 쓰는 곳이 없다 — 지울 코드.
- **열거형변수 삭제 규칙이 기획과 코드에서 갈린다.** 기획(구분자_액션 〔D-P1-17〕 · 〔D-P1-18〕 · ADR-0049 §2 표)은 「마스터 필드가 타입으로 쓰는 열거형변수는 삭제 거부」 · 「지운 값을 고른 저장 값은 연쇄 삭제하지 않고 오류 상태로」인데, 코드는 관리자 확인 뒤 **삭제를 허용하고 해당 값 행을 지운다** (§3.7). 어느 쪽을 정본으로 할지 결정 필요 — 결정되면 ADR.
- **열거형변수 생성 화면의 빈 행** — [[공통/화면/디자인원칙]] §2 L2 는 「빈 행은 제출 때 버린다」인데 생성 값 표는 빈 행을 `required` 로 막는다(상세는 버린다). **미구현**.
- 열거형변수 값 「사용중지」 상태 — 삭제 거부가 잦으면 재검토 (MVP 는 추가 · 삭제뿐).
- 유저 정의 폼(폼 탭의 생성 · 필드 편집기 · 선택 필드)은 MVP 이후 — 입력 항목은 코드 마스터다 ([[기능/마스터/결정/ADR-0037-입력항목-코드마스터-유저정의폼-MVP이후]]).
