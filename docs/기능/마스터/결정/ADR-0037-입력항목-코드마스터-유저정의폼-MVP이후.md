# ADR-0037 — MVP 의 입력 항목은 코드 마스터다 · 유저 정의 폼은 MVP 이후

> 상태: 채택 · 날짜: 2026-09-12
> 개정 반영: 2026-09-27 [[기능/마스터/마스터]] §3.1 · §3.2 · §4 (§1 · §2 · §3 — 마스터 = 코드 폼 › 필드, 코드 `폼키.필드키`, 조회 페이지는 읽기 전용) · ADR-0065 (§7 — `table` 필드 타입) — 원본은 _archive/2026-09-27_문서재편/06_결정/
> 개정 반영: 2026-09-27 [[기능/마스터/마스터]] §3.4 · §6.2 (§4 — **마스터 코드가 정하는 선택 필드**(`MasterField.optional` — 면책여부 · 지급률)는 MVP 에 들어왔다. 유저가 붙이는 선택 필드는 여전히 MVP 이후)
>
> [[기능/구분자/결정/ADR-0036-폼-구분자-문면-3층]] 의 **1층(폼)을 대체**한다. 2층(구분자 = 식) · 3층(문면은 구분자만)은 그대로다.
> 유저 정의 폼 · 노출여부([[기능/담보/담보]] 2026-08-30)는 MVP 이후로 미뤄진다.

## 맥락

ADR-0036 으로 「폼(유저 정의 입력 양식) → 구분자(식) → 문면」 3층을 정한 직후, 담보 트리(담보 › 세부보장 › 급부)를 폼으로 대체할 수 있는지가 올라왔다.
답은 「가능하지만 중첩 · `list<T>` · 뼈대 속성 · 부착 레벨을 전부 다시 정의해야 한다」였고, 트리는 트리로 남기기로 했다.

그 대화에서 물음이 한 번 더 바뀌었다 — **입력 항목을 유저가 정의하는 것 자체가 MVP 에 필요한가.**
유저 정의 폼은 필드 편집기 · 선택 필드 · 폼 노출여부 · 부착 관계 · 타입 변경 가드 · 유형 > 폼 화면을 끌고 온다.
MVP 의 목표는 실물(알파Plus) 재현을 빠르게 끝내는 것이고, 재현에 필요한 입력 항목은 시드 다섯 벌(납입면제 · 무저해지 · 계약전환 · 영위업종적용 · 갱신여부)로 이미 알려져 있다.

## 결정

**MVP 에서 입력 항목은 코드에 고정된 마스터다.** 유저 정의 폼 기획은 접고 MVP 이후로 보낸다.

1. **코드 마스터.** 입력 항목은 코드에 고정된 **폼 › 필드**다 — 폼은 상품 · 세목 · 담보 · 세부보장 · 급부 중 레벨 하나에 서고, 필드는 폼의 레벨을 따른다
   ([[기능/마스터/마스터]] §3.1). 항목을 더하거나 바꾸는 것은 **배포 + 마이그레이션**이다.
2. **마스터 조회 페이지.** 마스터를 읽기 전용으로 보여준다. 편집은 없다. 좌측 내비에서 「유형 > 폼」 자리를 대신한다 — 모양은 [[기능/마스터/마스터]] §4.
3. **구분자는 ADR-0036 그대로 식 하나다.** 참조 경로만 **`폼키.필드키`** (`pay.rate` · `waiver.applies`, [[기능/마스터/마스터]] §3.2) 가 된다.
   집계 규칙 · 하위 레벨은 집계 안에서만 · 미입력은 오류 · 상위 → 하위만 · 항등 투영 허용 — 전부 유지.
   **문면(조건식 · 반복 · 슬롯)은 구분자만 본다** — 유지.
4. **MVP 이후로 보내는 것.** 유저 정의 폼 · 필드 편집기 · 유저가 정하는 선택 필드 · 폼 노출여부(무조건 / 선택 부착) · 폼 부착 관계 · 유형 > 폼 탭.
   (2026-09-27 — 어느 필드가 선택인지를 **마스터 코드가** 정하는 `optional` 필드는 MVP 에 있다. 자리는 여전히 모든 노드에 있고, 값이 없으면 화면에 안 보이고 미입력으로 세지 않을 뿐이다 — [[기능/마스터/마스터]] §3.4.)
   마스터 필드는 **모든 노드에 항상 있다.** 안 쓰는 항목은 미입력으로 둔다 — 완결성 조회가 실행 기반(실제 타는 분기만, ADR-0016)이라
   안 쓰는 미입력이 경고로 뜨지 않는다.
5. **열거형변수는 남는다.** 값이 데이터라 배포 없이 늘릴 수 있고, 마스터 필드의 enum 타입이 이걸 가리킨다.
6. **MVP 마스터의 내용**은 지금 시드(`src/db/seed/data/discriminators.json`)가 쓰는 항목을 그대로 옮긴다 —
   **세목(`plan`) 레벨**: 납입면제 {적용여부 boolean · 납입면제사유 list<enum>} · 무저해지 {유형 enum} · 계약전환 {전환여부 boolean} · 영위업종적용 {적용여부 boolean} —
   이 넷이 3차구현의 **세목유형 4종의 구조체**다 (시드 `level: "plan"`). 세목 레벨 마스터 = 이 네 묶음이고, 세목유형 선택지 · 유효 조합 장치는 그대로 둔다.
   상품 레벨은 시드 기준 비어 있다 (평균공시이율 같은 값이 필요해지면 그때).
   담보 레벨의 갱신여부(D0001)는 담보속성이라 마스터에 넣지 않는다 ([[기능/담보/담보]]). 급부 · 세부보장 항목(지급률 · 면책여부 · 감액기간 …)은
   실물 재현 나머지 특약이 요구하는 것을 그때 코드로 더한다.
7. **타입.** 마스터가 코드니 타입은 코드 타입 그대로다 — `string` · `number` · `boolean` · `date` · `enum` · `list<enum>` · `table`(스칼라 열의 행 목록, [[기능/담보/결정/ADR-0065-table필드타입-급부시드폼-감액면책-시드구분자]]).
   일반 `list<T>` 는 MVP 밖이다.
   ADR-0036 의 「일단 목록」(`int` · `float` · … · `boolean` 없음)과 그 열린 문제는 **유저 정의 폼을 다시 열 때의 문제**로 넘어간다.

## 이유

- **속도.** 유저 정의 폼이 끌고 오는 화면과 가드가 MVP 재현에 기여하지 않는다. 필요한 항목은 이미 다 안다.
- **단순함.** 폼 이름 · 노출여부 · 부착 관계 · 선택 필드가 없으면 「값 자리」는 「노드 × 마스터 필드」 하나로 결정된다. 완결성 · 스냅샷 · 좌표가 다 단순해진다.
- **문제정의 S1 은 반만 지킨다.** 「구분자를 추가할 때 코드를 건드리지 않는다」는 MVP 에서 **구분자(식)와 열거형변수 값**에만 성립한다.
  입력 항목 추가는 배포다. 기존 시스템의 아픔(구분자마다 개발 요청)에서 「문면이 묻는 개념」 쪽은 여전히 데이터로 풀리고, 「입력 항목」 쪽만 유예한다.
  이 유예는 [[00_시작/문제정의]] S1 옆에 적는다.

## 버린 대안

- **유저 정의 폼 유지 (ADR-0036 1층)** — 필드 편집기 · 선택 필드 · 노출여부 · 가드가 MVP 안에 들어온다. 재현 속도와 맞바꿀 만큼의 가치가 MVP 에 없다.
- **레벨마다 마스터 하나 + 필드는 데이터로 (읽기 B)** — 폼 이름 · 노출여부는 사라지지만 필드 편집 UI · 타입 변경 가드는 그대로 필요하다. 코드 마스터보다 느리다.
- **담보 트리를 폼으로 대체** — 중첩 · `list<T>` · 뼈대 속성 · 부착 레벨을 다 다시 정의해야 하고 P2 · P8 이 그 위에 서 있다. 트리는 트리로 둔다.

## 결과와 감수하는 비용

- **입력 항목 추가 = 배포 + 마이그레이션.** 실물 재현 나머지 특약(수술비 등)이 새 항목을 요구하면 코드 작업이다. MVP 이후 유저 정의 폼을 열 때
  마스터를 시드 데이터로 바꾸는 이행이 한 번 더 필요하다.
- **선택 필드 · 노출여부가 없어** 안 쓰는 항목이 모든 노드의 값 폼에 보인다. 실행 기반 완결성 덕에 경고는 안 뜨지만 화면은 길어진다.
  항목 수가 시드 기준 한 자릿수라 MVP 에서는 감수한다.
- **코드 이행** — `DiscriminatorKind` 의 `struct` · `scalar` · `const` 와 구분자 부착(노출여부) · 유형 > 폼 화면 · `StructCreateForm` 을 걷고,
  코드 마스터 + 마스터 조회 페이지 + 구분자(식)만 남긴다. 값 저장은 「노드 × 마스터 필드」. 순서는 [[실행/개발순서]] P1.
- 2026-09-12 하루에 ADR-0035 → 0036 → 0037 로 세 번 옮겨 갔다. 남는 것은 **구분자 = 식 · 문면은 구분자만 · 트리는 트리**고,
  버린 것은 **입력 항목의 유저 정의**다. 그 둘을 헷갈리지 않게 이 ADR 이 정본이다.
