# 박스

> 상태: 초안 · 최종수정: 2026-09-30

## 1. 한 줄

【용어풀이】 · 【제외대상 특별약관】 · 암 정의 박스처럼 **놓인 자리에 내용이 그대로 들어가는 고정 글**의 전상품 공용 마스터다.
메뉴 「정적 마스터」의 하위로 별표([[기능/별표/별표]])와 나란히 선다 — 별표는 본문이 가리키기만 하고(간접참조), 박스는 그 자리에 편다(직접참조).
약관 작성자가 박스를 만들어 두면 템플릿 · 공용조항 본문의 조 자리 · 항 뒤 · 호 뒤에 박스 참조로 놓는다.

## 3. 규칙

### 3.1 마스터

- **코드는 시스템이 채번한다** — `BX` + 6자리 순번, `BX000001` 부터. 등록 뒤 바뀌지 않는다. 생성 입력(`NewBox`)에 `code` 가 없다. 순번은 오르기만 한다(별표 §3.1 과 같은 규칙).
- **이름은 비울 수 없고 중복될 수 없다**(앞뒤 공백 정리 뒤 비교).
  — 왜: 넣을 때 이름으로 고른다. 별표는 코드로만 부르고 이름이 표기에 쓰이지 않아 중복을 허용하지만, 박스는 고르는 목록에서 이름이 곧 구분이다.
- **제목**(【…】 머리)은 비워도 된다 — 실물 박스에 제목 없는 것이 있다.
- **줄은 하나 이상**이고 줄마다 글 한 줄이다. 가운데 빈 줄은 간격으로 남고, 줄 칸 끝의 빈 줄은 버린다.
- **박스 안에는 참조 · 슬롯 · 옵션을 두지 않는다** — 줄은 글뿐이다. 박스 안 「제2항」 · 「제44조」는 고정 글이라 조가 밀리면 틀린다(기존 한계, [[QA/인수기준]] 허용 차이 ⑦). (ADR-0076 결정 11)
  — 왜: 박스는 받는 값도 품는 참조도 없는 고정 글이다. 참조를 품게 하면 박스가 다시 조항이 된다.
- 상품과 무관한 전상품 superset 이다.

### 3.2 박스 참조와 조립

- 문서 · 공용조항 본문은 **박스 참조**(`boxRef`)에 박스 코드만 저장한다. 내용을 복사하지 않는다 — 박스를 고치면 모든 사용처가 바뀐다.
- 박스 참조가 서는 자리 = 조 자리(항 사이 · 조 끝) · 항의 호 목록 자리(항 · 호 뒤). 조건 블록 가지 안이면 그 자리를 물려받는다. 문장 안 · 목 목록 자리 · 문서 직속에는 서지 않는다.
- **박스는 잎이다** — 공용조항(함수조항) 본문에도 놓는다(「항」 공용조항의 항 자리 · 호 뒤). 공용조항 안 공용조항 중첩 금지에 걸리지 않는다. 「문구」 공용조항(문장 안)에는 없다. (ADR-0076 결정 7)
- 없는 박스를 가리키면 문서 저장 · 공용조항 저장이 거부된다(brokenRef).
- **조립**은 박스 참조를 박스 마스터의 제목 · 줄로 바꿔 정적 박스로 싣는다 — 번호가 없고 항 · 호 번호에 들지 않는다. 펼친 공용조항 안의 박스 참조도 사용처 자리에서 같다.
  조립 사이에 박스가 지워졌으면 그 자리가 brokenRef 오류 마커다.
- 박스 마스터는 조립 입력이다 — 박스를 고치면 모든 상품 미리보기가 오래된 것이 된다(조립 입력 스탬프 `boxes`, [[기능/조립산출/조립산출]] §3.6).
- 박스 공용조항(공용조항 유형 「박스」, [[기능/공용조항/공용조항]] §3.1)은 **아직 공존한다** — 실물 시드의 박스 공용조항을 박스 마스터로 옮기고 유형 「박스」를 지우는 것은 다음 이관 단계다(§5).

### 3.3 삭제

- **관리자만**, 영향을 본 뒤에 지운다 ([[공통/화면/결정/ADR-0019-모드폐지-역할권한]], 파괴적 액션 `box.delete`). 편집자 요청은 서버가 거부한다.
- 영향 = 이 박스를 놓은 자리(문서의 박스 참조 · 공용조항 본문의 박스 참조). **참조가 남아 있어도 지워진다** — 그 참조는 깨진 참조가 되어 문서 저장 검증 · 조립에서 오류로 드러난다(별표와 같은 규칙).

## 4. 화면

좌측 내비 「정적 마스터 › 박스」 (정적 마스터 = 별표 · 박스).

### 4.1 조회 (`/boxes`) — L1

| 구성 | 내용 |
|---|---|
| 제목 줄 | 「박스」 + `+` (→ `/boxes/new`) |
| 검색 | 코드 · 박스 이름 · 제목 |
| 열 | 코드 · 박스 이름(→ 상세) · 제목(없으면 「없음」) · 줄 수 · 최종수정 · 수정자 |
| 페이저 | 50건 · 「총 N건」 |

| 상태 | 표시 |
|---|---|
| 박스가 하나도 없음 | 빈 상태 — 「박스는 놓인 자리에 내용이 그대로 들어가는 고정 글이다」 · 예 「【용어풀이】 보험연도」 · 「새 박스 만들기」 |
| 검색 결과 없음 | 「이 조건에 맞는 박스가 없습니다」 |

### 4.2 새 박스 (`/boxes/new`)

- 경로 `박스 › 새 박스`, 제출은 헤더 우측.
- 칸: **박스 이름**(필수 · 첫 칸) · 제목 · **줄**(여러 줄 글 — 한 줄이 박스의 한 줄). 코드 칸은 없다 — 폼 아래 「코드는 시스템이 BX000001 부터 붙이고, 등록 뒤에는 바뀌지 않는다」.
- 이름이 비거나 겹치거나 줄이 없으면 같은 화면 오류 배너. 만들면 **상세로** 간다.

### 4.3 상세 (`/boxes/<code>`) — L2

| 자리 | 읽기 | 편집 |
|---|---|---|
| 제목 줄 | 경로 `박스 › <이름>` · 사용처(N) · 편집 · 삭제 🗑 | 경로 · ✕ · 저장 · 삭제 🗑(비활성) |
| 코드 | 고정 글자(mono) — 편집에서도 못 고친다 | 같음 |
| 박스 이름 · 제목 · 줄 | 잠긴 글자 | 입력칸 (줄은 여러 줄 글) |
| 미리보기 | 박스 그대로(【제목】 + 줄) | — |

| 누르면 | 무엇이 되나 |
|---|---|
| 저장 | 이름 · 제목 · 줄을 **한 번에** 검사하고 한 트랜잭션에 저장 — 거부되면 아무것도 저장되지 않는다 |
| 사용처 (읽기에서만) | 다이얼로그 — 형태 · 좌표 표(좌표는 그 문서의 그 자리로 가는 링크). 0건이면 「아무 조문도 이 박스를 놓지 않는다」 + 「약관 템플릿에서 쓰러 가기 →」 |
| 삭제 🗑 (읽기에서만) | 관리자: 확인 다이얼로그(깨질 참조 목록) → 삭제 뒤 목록으로. 편집자: 거부 메시지 |

| 상태 | 표시 |
|---|---|
| 없는 코드 | 경로 `박스 › <코드>` + 「찾을 수 없습니다」 |

### 4.4 넣기 (문면 · 공용조항 편집기)

- 툴바 「구조 넣기」의 **「박스」** — 누르면 버튼 아래 작은 메뉴에 박스마다 한 줄(「이름(코드)」), 고르면 지금 자리 바로 뒤에 박스 참조가 선다(조 자리 · 항 · 호 뒤). 박스가 없으면 「박스가 없다 — 정적 마스터 › 박스에서 만든다」 팝업.
- 오른쪽 클릭 메뉴 「아래에 박스 추가…」 · 조의 「박스 추가…」는 같은 자리에 고르기 팝업.
- 편집기 안 박스 참조는 머리 띠 「박스 · 이름(코드)」(박스 화면으로 가는 링크) + 【제목】 + 줄로 그린다 — 내용은 편집기에서 고치지 않는다(박스 화면에서).

## 5. 미결

- **박스 공용조항 이관** — 실물 시드의 박스 공용조항(두 실물 C0020 ~ C0100 류 99건, 옵션 있는 4건은 선택지마다 박스를 따로)을 박스 마스터로 옮기고, 사용처를 박스 참조로 바꾸고, 공용조항 유형 「박스」 · 툴바 「박스 공용조항」 자리를 지운다. 공용조항 코드가 당겨져 E2E · 인수기준 · 모델명세의 C코드를 함께 고친다.
- 정적 마스터 아래 두 메뉴의 경로 — 지금은 `/appendices` · `/boxes` 그대로 두고 메뉴만 묶었다.

## 6. 결정

### 6.1 이 기능의 ADR

없음. 정적 마스터 · 박스의 뼈대는 [[기능/공용조항/결정/ADR-0076-공용조항-함수조항-일원화-인자연결]] 결정 11 (§6.3).

### 6.2 결정 메모

| 결정 | 왜 | 버린 안 |
|---|---|---|
| 박스 코드는 시스템 채번 `BX000001` · 순번 kind `box` (§3.1) | 별표 · 공용조항과 같은 규칙 — 코드는 참조의 정본 | 박스 공용조항의 C코드를 그대로 씀(공용조항 순번과 섞인다) |
| 박스 이름 유일 (§3.1) | 넣을 때 이름으로 고른다 | 별표처럼 중복 허용 |
| 줄 = 글 배열 — 슬롯 · 옵션 자리 없음 (§3.1) | 정적 마스터는 참조를 품지 않는다(결정 11). 옵션이 있던 박스 공용조항은 선택지마다 박스를 따로 만든다 | 박스 줄에 값 슬롯 · 옵션 자리를 남김(박스가 다시 조항이 된다) |
| 문면 노드 `boxRef` 를 새로 둠 — 옛 문면 박스 노드(`box`, 제목 + 줄 인라인 사본)와 박스 공용조항 참조는 공존 (§3.2) | 사본은 고쳐도 사용처에 퍼지지 않는다. 공존은 이관(§5) 전까지 기존 문서 · 조립 결과를 그대로 두기 위해서 | 옛 `box` 노드에 코드 칸을 더함(사본 · 참조 두 뜻이 한 노드에 섞인다) |
| 상세 저장 = 이름 · 제목 · 줄 한 번에 (`saveBox`) | 편집 화면 하나 = 저장 하나(디자인원칙 §2 L2). 칸마다 서비스를 나누면 뒤가 거부될 때 앞만 남는다 | 별표처럼 칸마다 서비스 + 액션의 `saveOnce` |
