# ADR-0026 — 이력·개정: 이력일자 기준 시점 조회(as-of) · 실체 단위 · 작업본 + 불변 확정 행

> 상태: 채택 (구현은 MVP 이후) · 날짜: 2026-09-06

## 맥락

[[공통/화면/결정/ADR-0019-모드폐지-역할권한]] 은 「누가 언제 무엇을 바꿨나」와 「개정일자를 가진 판본의 공존」에
답하지 않았다. 실무의 개정은 시행일자별 약관 묶음이다 — 2604 판 상품은 개정 뒤에도 그때의
보통약관·담보 문면으로 재조립돼야 한다. 산출물 스냅샷 회귀 비교([[00_시작/범위]] 유예)도 같은 기반을 쓴다.

## 결정

1. **이력일자 기준 시점 조회(as-of).** 확정된 이력 행마다 **이력일자**(시작일)가 있고, 조립·조회는
   기준일 D 를 받아 각 실체의 「D 이하 최신 확정 행」을 고른다. 상품모델링의 이력일자가 그 상품
   조립의 기본 D. 조회·생성 화면에 기준일 선택 UI (기본 = 오늘).
2. **이력 단위는 실체 전체.** 문면 문서 한 벌 · 공용조항 하나 · 구분자 정의 하나 · 담보 트리 하나 ·
   보통약관 한 벌 · 별표 하나 · 상품모델링 한 벌이 각각 행 하나. 노드·필드 단위 이력은 없다.
3. **작업본 + 확정.** 실체마다 작업본 하나가 있어 자유롭게 저장·수정한다. **「이력 확정(일자 선택)」**
   을 누르면 그 시점 내용이 **확정 행**이 된다 — 같은 실체에 같은 일자가 이미 있으면 거부 +
   「동일 이력이 있습니다」. 조립·조회는 확정 행만, 편집 화면은 작업본을 본다.
   - **레코드 상태 = 확정 / 미적용(미확정 작업본).** 조회·조립은 확정 상태만 본다. 미적용 레코드는
     검색창의 **「미확정 포함」 토글**(기본 꺼짐)을 켜야 조회된다.
   - **확정은 관리자 권한이다** (ADR-0019 결). 확정 적용·확정 해제는 관리자만. 확정 행은 편집자가
     수정할 수 없다 — 관리자만 해제(→ 미적용) 뒤 수정한다.
4. **삭제는 종료다** (잠정 — 2026-09-06 제안, 반대 없음): 실체 삭제는 「종료 확정(일자)」이며 그 이후
   기준일에서 보이지 않는다. 옛 기준일의 조립은 깨지지 않는다. ADR-0019 의 파괴적 액션 가드는
   작업본·종료 확정에 그대로 적용된다.
5. 변경 이력(누가 언제)은 확정 행의 메타(확정자 · 확정 시각)로 충족한다. 작업본 저장마다의 로그는
   두지 않는다.

## 이유

- 판본 확정 버튼으로 전체 그래프를 굳히는 안(A)은 ㉢의 「특정 D 만 허용」 축소판이고, 작업 중 상태와
  소급 개정을 표현하지 못한다.
- 마스터별 판본 번호(B)는 참조마다 어느 버전을 가리키는지 적어야 해 그래프가 버전을 타고 얽힌다.
  as-of 는 참조를 코드로만 적고 시점이 해소한다.
- 저장마다 새 불변 행(하루 한 번 저장)은 편집 실무에 맞지 않는다 — 작업본이 그 사이를 흡수한다.

## 버린 대안

- **A. 전체 그래프 판본 확정** · **B. 마스터별 판본 번호** — 위 이유.
- **기준일 = 이력일자 자동 매칭 저장** (같은 날이면 덮어쓰기, 아니면 새 행) — 기준일을 잘못 두고 저장하면
  조용히 새 판이 생긴다. 기각.
- **저장마다 새 행** — 같은 날 두 번째 저장 불가. 기각.

## 결과와 감수하는 비용

- 유일성 제약이 (코드, 이력일자)로, 모든 조회·관계정보·완결성·Impact 가 as-of 가 된다. 테스트에
  시점 축이 하나 는다.
- 작업본과 확정 행이 다를 때 조립 결과가 편집 화면과 다르다 — 화면이 「미확정 변경 있음」을 표시한다.
- 구현은 MVP 이후. MVP 데이터 모델은 이 결정을 막지 않게 — 실체 식별을 코드로, 행 단위 스냅샷 가능한
  저장 형태(문서 = 트리 JSON 1건 등)를 유지한다.
