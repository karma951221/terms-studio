# ADR-0013 — 식 언어 통일: 문면 조건식 = 파생식 한 벌

> 상태: 채택 · 날짜: 2026-08-31

## 맥락

식이 등장하는 자리가 둘이다.

| 자리 | 예 | 결과 |
|---|---|---|
| 파생 구분자의 식 ([[00_시작/도메인모델]] §2) | `보험금지급.면책여부 = any(급부별.면책여부)` | 값 |
| 문면 조건식 ([[기능/문면/문면]]) | `if 갱신여부 = true → 「최초계약일」` | 분기 선택 (boolean) |

둘 다 구분자를 경로로 참조하고, 비교하고, and/or 로 잇고, 집계(any·all·sum·count·exist·not exist)를
쓸 수 있어야 한다. 별개 언어로 만들면 파서·평가기·참조 추출을 두 벌 만들고
문법이 미묘하게 갈라질 위험이 있다.

## 결정

**문면 조건식과 파생식은 같은 식 언어 한 벌을 쓴다** — 문법 · 파서 · 평가기 · 참조(요구 구분자)
추출까지 공유한다. 조건식은 「결과가 boolean 인 식」일 뿐 별개 언어가 아니다.

- 평가 문맥 규칙은 언어 밖의 일이다 — 문면 조건식은 사용처 문서의 문맥
  ([[기능/공용조항/결정/ADR-0010-공용조항-참조바인딩]] 늦은 바인딩 · [[기능/조립산출/조립산출]] §3.2 평가 문맥),
  파생식은 부착점 하위 트리([[기능/구분자/구분자]] §3.2). 언어는 문맥을 모른다.
- 종별 문구 메커니즘(P7)의 세목 존재·개수 조건도 이 언어에 얹는다.

## 이유

- **구현이 한 벌로 준다** — 파서·평가기·참조 추출은 공용조항 부착 검사(ADR-0010)에
  이미 필요한 기계다.
- 문면 조건식 안에서도 집계를 바로 쓸 수 있다 — 실사례: `any(급부별.면책여부)` 로 면책 조 on/off.
- 문법이 하나라 사용자가 배우는 것도 하나다. 두 언어의 미묘한 차이는 조용한 오염원이다.

## 버린 대안

- **별도의 단순 조건 DSL** — 조건식을 비교·논리만으로 제한해 더 단순하게 만들 수 있다.
  기각: 기계 두 벌 + 집계를 조건식에서 못 쓰는 표현력 손실. 단순화의 이득이 중복 비용을
  못 넘는다.

## 결과와 감수하는 비용

- 언어의 요구가 두 소비처의 합집합이 된다 — 언어를 확장할 때마다 문면 조건과 파생
  양쪽 영향을 함께 검토해야 한다.
- 「조건식 자리에는 boolean 결과 식만」 같은 타입 검사가 언어 밖 규칙으로 필요하다.
