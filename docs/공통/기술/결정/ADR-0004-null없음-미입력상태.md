# ADR-0004 — null 없음 · 미입력은 상태 · 기본값은 프리필 전용

> 상태: 채택 · 날짜: 2026-08-30

## 맥락

의뢰인의 실제 고민: "null 을 허용할지 말지. 모든 필드에 기본값을 넣는 것도 힘들고."
terms-lab 은 「nullable 없음 + 기본값 대체 + 미입력은 상태」였다.

## 결정

- **null 은 타입 체계에 없다.** 조건식·파생식은 null 을 받는 경우가 없다.
- **값 자리는 기본값 지정 여부와 무관하게 항상 「미입력」 상태로 태어난다.**
  저장소의 값 자리는 둘뿐: 명시 입력된 값 / 미입력.
- **기본값은 선택 항목, 역할은 폼 프리필뿐.** 폼을 미리 채워 보여주는 제안 — 사람이 보고
  저장해야 명시 값이 된다. 기본값이 저장소로 자동 유입되는 경로는 없다.
- **평가·조립이 문지기다.** 미입력을 참조하면 false/0 으로 슬쩍 취급하지 않고
  명시적 오류 + 좌표 보고. 사전평가에서 미입력 분기는 「미결」 표시. 조립 전 완결성 조회 제공.

## 이유

- null 허용 → 모든 식이 3치 논리가 되고 식 작성자마다 null 처리를 떠안는다 —
  유효값 로직이 사람 손에 흩어지던 원래 문제의 재림.
- 기본값 강제 → 약관 도메인 최악의 실패는 「값이 없어 조립이 멈추는 것」이 아니라
  **「아무도 확인 안 한 기본값으로 조립이 조용히 성공하는 것」** (면책여부 기본값 false 가
  흘러들어 면책 조항이 소리 없이 빠진 약관). 입력 부담도 크다.
- 프리필 방식이면 저장소의 모든 값에 「사람이 한 번은 보고 저장했다」가 보장된다 —
  명시/유입 구분 추적 자체가 필요 없어진다.
- 미입력이 값이 아니라 상태인 실무적 차이: 식 문법에 아예 등장하지 않는다.
  중간 저장은 언제나 허용(막으면 작업이 지옥).
