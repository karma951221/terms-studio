문면 조건식과 파생식이 **같은 언어 한 벌**을 쓴다 (ADR-0013). 조건식은 「결과가 boolean 인 식」일 뿐이다.
언어는 문맥(어느 실체의 값을 읽나·하위 트리가 무엇인가)을 모른다 — 문맥은 평가 시점에 주입된다.

## 1. 한눈에

```
any(cov_pay.exempt) and (notexist(attr.add) or attr.add = 'plus')
count(builtin.plan.name) > 1
cov_pay.since < d'2026-01-01' and not renew
```

- 저장되는 식은 **코드 기반 소스 문자열**이다. 편집기는 표시명으로 보여주고 코드로 되돌려 저장한다
  (`format(expr, displayName)` — [[기능/구분자/구분자]] 「코드 + 표시명 이중 체계」).
- 산술(`+ - * /`)은 없다 (MVP). 문자열 연결·함수 호출도 없다.
  → ~~**2026-09-12 제안** ADR-0040(아카이브) — 동적 표 셀 계산(ADR-0039)의 선행 조건으로 산술을 더한다. 구현 P7.~~
  → **2026-09-13 보류** — 동적 표 셀 계산이 도메인 코드 붙박이로 옮겨져(ADR-0042(아카이브)) 산술이 선행 조건에서 빠졌다. 산술 · 문자열 연결 · 함수 호출은 여전히 없다.
- `null` 은 문법에 없다 — 미입력은 값이 아니라 상태라 식에 등장하지 않는다 (ADR-0004).

## 2. 어휘

| 부류 | 표기 | 비고 |
|---|---|---|
| 코드(식별자) | `[A-Za-z_가-힣ㄱ-ㆎ][A-Za-z0-9_가-힣ㄱ-ㆎ]*` | 대소문자 구분. 시스템 채번 코드가 오는 자리 |
| 예약어 | `and` `or` `not` `true` `false` `any` `all` `sum` `count` `exist` `notexist` `attr` `builtin` | 전부 소문자. 코드로 쓸 수 없다 |
| 문자열 | `'…'` | 안의 `'` 는 `\'`, `\` 는 `\\` |
| 숫자 | `-?[0-9]+(\.[0-9]+)?` | 음수는 리터럴의 일부 (단항 마이너스 연산 아님) |
| boolean | `true` `false` | |
| 날짜 | `d'YYYY-MM-DD'` | 실재하는 날짜만 (`d'2026-02-30'` 은 문법 오류). 값은 그 문자열 |
| 비교 연산자 | `=` `≠` `!=` `<` `<=` `>` `>=` | `!=` 는 `≠` 로 정규화 |
| 괄호 | `(` `)` | |
| 공백 | 스페이스·탭·개행 | 토큰 구분 외 의미 없음 |

enum 값은 **`'코드'` 문자열 리터럴**로 쓴다 (`prod.notice = 'simple'`). 별도 enum 리터럴은 없다.

## 3. 참조 경로

| 형태 | 뜻 | AST `Ref.kind` | 예 |
|---|---|---|---|
| `<구분자코드>` | const · 파생 구분자 (값 하나) | `discriminator` (field 없음) | `avg_rate` |
| `<구분자코드>.<필드코드>` | 구조체 구분자의 필드 | `discriminator` (field 있음) | `cov_pay.exempt` |
| `builtin.<레벨>.<속성>` | 내장 경로 — 뼈대 속성 ([[기능/담보/담보]] 「이름의 정체」) | `builtin` | `builtin.subCoverage.name` |
| `attr.<속성종류코드>` | 담보속성 (ADR-0015) | `attr` | `attr.renew_type` |
| `<구분자코드>@<노드id>` | 노드 한정자 — 그 구분자를 문맥 담보가 아니라 **그 노드**(담보 마스터 노드 id) 문맥에서 평가 (ADR-0066 §1). 담보 약관 문면에서만 · 구분자 참조에만 | `discriminator` (`node` 있음) | `D0007@3f1a…` |

- 구분자 경로는 **두 단계까지** — 구조체 중첩 금지([[00_시작/도메인모델]] §2)와 같은 결. 세 단계는 문법 오류.
- `builtin` 의 레벨은 부착 레벨 5개 `product · plan · coverage · subCoverage · benefit` 중 하나 (`types.ts` `AttachLevel`).
  속성 코드는 문법이 제한하지 않는다 — MVP 는 `name` 만 쓰고, 타입 조회·문맥이 안다.
  기획의 `세부보장.이름` · `급부.이름` 표기는 각각 `builtin.subCoverage.name` · `builtin.benefit.name` 이다
  (표시명 변환 훅이 한글로 보여준다).
- `attr` · `builtin` · `arg` 는 **네임스페이스 예약어**다. 채번 코드가 이 단어일 수 없다. `arg.<이름>` 은 함수조항 인자 참조다(§12).
- 형제·타 담보 참조 문법은 없다 ([[기능/구분자/구분자]] §3.2 — 필요해지면 그때 연다).
- 노드 한정자는 문맥 담보 **안**의 노드만 가리킨다 — 타 담보는 여전히 없다.

## 4. 문법과 우선순위

```
expr      := or
or        := and ( 'or' and )*
and       := compare ( 'and' compare )*
compare   := unary ( cmpOp unary )?          ← 연쇄 불가: a = b = c 는 문법 오류
unary     := 'not' unary | primary
primary   := literal | aggregate | ref | '(' expr ')'
aggregate := aggOp '(' path ')'              ← 인자는 경로 하나 (리터럴·식 불가)
aggOp     := 'any' | 'all' | 'sum' | 'count' | 'exist' | 'notexist'
```

| 우선순위 (세게 묶임 → 약하게) | 연산 | 결합 |
|---|---|---|
| 1 | `not` | 오른쪽 (`not not a`) |
| 2 | `= ≠ < <= > >=` | 없음 (연쇄 금지) |
| 3 | `and` | 왼쪽 |
| 4 | `or` | 왼쪽 |

- `not a = b` 는 **`(not a) = b`** 다 — `not` 이 비교보다 세게 묶인다. 「a 가 b 가 아니다」는 `a ≠ b` 또는 `not (a = b)` 로 쓴다.
  (`(not a) = b` 는 `a` 가 boolean 이 아니면 타입 검사가 잡는다.)
- `a or b and c` 는 `a or (b and c)`.

## 5. 집계 6종

인자는 참조 경로 하나. **범위 = 문맥의 하위 트리** — 언어에 범위 문법이 없고, 문맥의 `children(ref)` 가
「경로의 부착 레벨에 맞는 후손 실체들」을 열거한다. 부착점이 곧 범위다.

| 집계 | 경로 타입 | 결과 | 빈 범위 | 미결 처리 |
|---|---|---|---|---|
| `any(p)` | boolean | boolean | `false` | 하나라도 `true` 면 `true` (나머지 미결이어도) |
| `all(p)` | boolean | boolean | `true` | 하나라도 `false` 면 `false` |
| `sum(p)` | number | number | `0` | 하나라도 미결이면 미결 |
| `count(p)` | 스칼라 (list<enum> 불가) | number — **distinct** 개수 | `0` | 하나라도 미결이면 미결 |
| `exist(p)` | 아무 타입 | boolean — 값 자리를 가진 하위 실체가 하나라도 있는가 | `false` | 자리 있는 실체가 하나라도 있으면 `true` |
| `notexist(p)` | 아무 타입 | `not exist(p)` | `true` | 〃 |

- 하위 실체의 값 자리가 **미입력**이면 오류 `notEntered` (exist 도 마찬가지 — 자리를 읽는 순간 미입력은 오류다).
  값 자리가 **없는** 실체는 `any·all·sum·count` 에서는 오류 `notAttached`, `exist·notexist` 에서는 「없음」으로 센다.
- 하나라도 오류면 오류 (오류 > 미결). 문맥이 하위 트리를 열거할 수 없으면(`children` → `undefined`) 미결.
- `notexist` 는 한 단어다. `not exist(p)` 도 문법상 성립하며 뜻이 같다.

## 6. 담보속성 (ADR-0015 · [[기능/상품/상품]])

담보속성 `attr.X` 는 **세 형태로만** 쓸 수 있고, 파서가 문법 차원에서 건다.

| 허용 | 뜻 | 평가 |
|---|---|---|
| `exist(attr.X)` · `notexist(attr.X)` | 이 상품담보가 속성 X 를 쓰는가 | 미사용이면 `false` — 오류 아님 |
| `attr.X = '값'` | 속성 값 비교 | 미사용이면 **오류 `unusedAttribute`** (조용한 false 없음) |
| `attr.X ≠ '값'` | 〃 | 〃 |

- RHS 는 **문자열 리터럴만** (구분자 참조·다른 타입 불가). 타입 검사가 유효값 목록을 알면 목록 밖 리터럴은 `typeMismatch`.
- `attr.X` 단독 · 비교의 오른쪽 · `< <= > >=` · `any/all/sum/count` 인자 → 전부 문법 오류.
- 미사용 담보에서 분기를 건너뛰려면 작성자가 명시적으로 `exist(attr.X) and attr.X = '값'` 을 쓴다 —
  `and` 의 왼쪽이 `false` 면 오른쪽은 평가하지 않는다 (§8).
- 담보 마스터 편집 문맥에서는 속성이 없으므로 **미결**.

## 7. 타입 규칙 (`checkTypes` · `checkCondition`)

타입은 `types.ts` 의 필드 타입 6종 + `attribute`. 타입 조회 함수(`TypeResolver`)는 주입받는다 — 조회되지 않는 참조는 `brokenRef`.

| 자리 | 규칙 | 위반 |
|---|---|---|
| **조건 자리** (if/elif · 인라인 조건) | 결과가 boolean | `typeMismatch` |
| `= ≠` | 양변 같은 종류. enum 은 같은 enum 끼리 또는 string 리터럴(코드)과. list<enum> 은 비교 불가 | `typeMismatch` |
| `< <= > >=` | number 끼리 · date 끼리만 | `typeMismatch` |
| `and or not` | 피연산자 boolean | `typeMismatch` |
| `any all` | 경로 boolean → boolean | `typeMismatch` |
| `sum` | 경로 number → number | `typeMismatch` |
| `count` | 경로 스칼라 → number | `typeMismatch` |
| `exist notexist` | 경로 아무 타입 → boolean | — |
| 담보속성 | §6 | `typeMismatch` |

- 오류는 하위 식마다 **모아서 한 번에** 보고한다. 오류 난 하위 식은 타입 「모름」으로 두어 연쇄 오류를 내지 않는다.
- 파생식의 결과 타입 = `checkTypes` 가 돌려주는 타입. 파생 구분자 정의의 타입과 일치해야 한다 (검사는 catalog 몫).
- **별칭형 파생 금지** — `isAliasExpression(expr)` 가 true (식이 참조 하나뿐) 면 정의 저장을 거부한다 ([[기능/구분자/구분자]]).

## 8. 평가 규칙 (`evaluate`)

결과는 셋 중 하나 — `{kind:'value'}` · `{kind:'undetermined', reason: 경로}` · `{kind:'error', issue}`.

| 상황 | 결과 |
|---|---|
| 입력된 값 자리 | 값 |
| 미입력 값 자리 (ADR-0004) | **오류 `notEntered`** |
| 값 자리 없음 — 미부착 / 삭제 | **오류 `notAttached`** / `brokenRef` |
| 문맥이 그 레벨을 모름 (편집 문맥의 상품 레벨·담보속성) | **미결** |
| 런타임 타입 불일치 (list 비교 · boolean 에 `<` …) | 오류 `typeMismatch` |

논리는 3치 논리가 아니라 **「결정 가능하면 결정, 아니면 미결」** 이다.

| 식 | 규칙 |
|---|---|
| `a and b` | 왼쪽 먼저. 왼쪽 `false` → `false` (오른쪽 평가 안 함). 한쪽 `false` 면 다른 쪽이 미결이어도 `false`. 둘 다 `true` → `true`. 그 외 미결 |
| `a or b` | 왼쪽 먼저. 왼쪽 `true` → `true` (오른쪽 평가 안 함). 한쪽 `true` 면 다른 쪽이 미결이어도 `true`. 둘 다 `false` → `false`. 그 외 미결 |
| `not a` | 미결·오류 그대로 전파 |
| 비교 | 한쪽 오류 → 오류, 한쪽 미결 → 미결 |
| 우선순위 | **오류 > 미결 > 값** — 평가한 자리에 오류가 있으면 미결로 덮지 않는다 |

오류 좌표: `Issue.at = { ...문맥.coordinate, refPath }`. 집계 하위 실체에서 난 오류는 **그 하위 문맥의 좌표**를 쓴다.

## 9. 오류 규칙 요약

| 단계 | 오류 종류 (`IssueKind`) | 어디서 |
|---|---|---|
| 파싱 | `syntax` (메시지에 0-기반 문자 위치) | `parse` → `Rejection{reason:'invalid', issues}` |
| 타입 검사 | `typeMismatch` · `brokenRef` | `checkTypes` → `Rejection{reason:'invalid', issues}` |
| 평가 | `notEntered` · `notAttached` · `brokenRef` · `unusedAttribute` · `typeMismatch` | `evaluate` → `{kind:'error', issue}` |

## 10. 인터페이스 (요약 — 상세는 코드 주석)

```ts
parse(src, coordinate?): Result<Expr>
format(expr, displayName?: (ref) => string): string       // parse(format(parse(s))) ≡ parse(s)
extractRefs(expr): ExtractedRef[]                         // {ref, path, aggregate?} — 등장 순·중복 제거
requiredDiscriminatorCodes(expr): Code[]                  // 구분자 코드만 (담보속성·내장 제외)
isAliasExpression(expr): boolean
checkTypes(expr, resolve, {coordinate?, expect?}): Result<ExprType>
checkCondition(expr, resolve, coordinate?): Result<ExprType>   // expect boolean
evaluate(expr, ctx: EvalContext): EvalResult

interface EvalContext {
  lookup(ref: ValueRef): {kind:'slot', slot} | {kind:'undetermined'} | {kind:'missing', issue?:'notAttached'|'brokenRef'}
  attribute(code): {kind:'value', value} | {kind:'unused'} | {kind:'undetermined'}
  children(ref: ValueRef): EvalContext[] | undefined     // 집계 범위. undefined = 열거 불가(미결)
  coordinate?: Coordinate
}
```

## 11. 대안과 버린 이유

- **`not` 을 비교보다 약하게 (Python 식 `not a = b` ≡ `not (a = b)`)** — 사용자 직관에는 가깝다.
  기각: 2차 구현 계획 §3.2 의 우선순위(`not > 비교 > and > or`)를 따른다. `≠` 가 있어 실용 손실이 작고,
  잘못 쓰면 타입 검사가 잡는다.
- **`exist(p)` 를 미입력 자리도 「있음」으로** — 자리의 존재만 묻는 연산이니 값을 안 읽어도 된다.
  기각: 「미입력을 참조하면 오류」(ADR-0004) 의 예외를 만든다. 담보속성의 `exist` 가 unused 를 false 로 보는 것과
  달리 구분자에는 「미사용」에 해당하는 상태가 `missing` 뿐이라, `missing` = 없음 · 미입력 = 오류로 갈랐다.
- **담보속성 규칙을 타입 검사에서만** — 파서를 단순하게 둘 수 있다. 기각: 허용 형태가 셋뿐이라 문법으로 거는 편이
  AST 를 단순하게 하고(`attr` 단독 노드가 존재하지 않음), 편집기가 파싱 즉시 오류를 보여줄 수 있다. 타입 검사·평가기도
  손으로 만든 AST 를 대비해 같은 규칙을 다시 검사한다.
- **enum 리터럴 전용 표기 (`#simple` 등)** — 기각: 코드 기반 저장이라 문자열 리터럴로 충분하고, 타입 검사가 enum ↔ string 을 맞춘다.

## 12. 함수조항의 인자 · 내부 변수 (2026-09-30 — 구현)

[[기능/함수조항/결정/ADR-0076-공용조항-함수조항-일원화-인자연결]]. 함수조항 본문의 조건 · 슬롯은 구분자가 아니라 **인자 · 내부 변수**를 읽는다. 내부 변수는 인자를 가공한 이름이고, 연산은 타입별로 아래뿐이다.

| 타입 | 연산 | 결과 | 뜻 |
|---|---|---|---|
| 세목 선택지 목록 | `.합치기(폼.필드)` (화면 말 「사유합치기」) | 목록값(복수) | 목록 안 선택지들의 그 열거 필드 값(`waiver.reasons`)을 모은 값 — 같은 값은 한 번, 열거형 순서 |
| 목록값(복수) | `.있음('값', …)` | 참거짓 | 나열한 값 중 하나라도 목록에 있으면 참 |
| 목록값(복수) | `.거르기(필드 = 값)` | 목록값(복수) | 열거값 필드가 그 값인 원소만 남긴 목록 |
| 목록값(복수) | `.비었음` | 참거짓 | 빈 목록인가 |
| 목록값 | `.필드` · `= '값'` | 필드 타입 · 참거짓 | 값 하나의 열거값 필드 읽기([[기능/열거형/결정/ADR-0078-열거값-유저정의필드-값나누기]]) · 특정 값과 같은가 |
| 참거짓 | `and` · `or` · `not` (화면 말 그리고 · 또는 · 아님) | 참거짓 | 논리 연산 |

- **개수 연산은 없다** — 개수 조건식 폐지([[기능/문면/결정/ADR-0077-블록반복-세목선택지-열거목록-반복참조]] 결정 3)와 한 몸이다. §5 의 `count` 는 구분자 식 전용으로 남는다. 필요한 연산은 타입별로 더한다.
- **표기(구현)** — 필드 읽기 · 연산은 인자 · 내부 변수 뒤에만 붙고 사슬로 잇는다: `arg.종들.합치기(waiver.reasons).거르기(F02 = true).비었음`. 필드는 **필드 키**(`F01`)로 저장하고 화면은 필드 이름을 보인다(ADR-0005 — 내부 변수 표 · 고르기가 바꿔 적는다). 연산 인자는 연산마다 모양이 정해져 있다 — 합치기는 `폼.필드` 하나, 있음은 문자열 값 하나 이상(쉼표), 거르기는 `필드 = 리터럴`. 비었음은 괄호 없이(`()` 도 받는다).
  AST 는 `{ kind: "member", target, field }` · `{ kind: "call", op, target, … }`. 타입 검사는 열거형 모양(값 · 필드 — `CheckOptions.enums`)과 세목 폼 필드 타입(`planField`)으로 본다 — 없는 필드 · 없는 값 = brokenRef, 제 타입이 아닌 연산 · 필드 타입과 다른 거르기 값 = typeMismatch.
- **경계** — 필드 읽기 · 연산은 문맥 플래그(`params`)가, 내부 변수는 `locals` 플래그가 있어야 선다(구분자 식 · 문면 식 = structure 오류). 함수조항 식에서는 `count` 도 거부한다(개수 연산 없음). 평가기는 이 모양을 모른다 — 조립이 함수조항을 펼칠 때 사용처 문맥에서 값으로 바꾼다([[기능/함수조항/함수조항]] §3.7 「내부 변수 구현」). 빈 필드 값을 읽으면 `notEntered`, 거르기도 같다.
- 값을 나열하는 연산(`.있음(값…)` · `= '값'`)은 열거값을 더하면 재검사 목록에 오르고, 필드를 읽는 연산(`.필드` · `.거르기`)은 필드 삭제 · 타입 변경 때 오른다(ADR-0078 — 참조 그래프 간선).
- **인자 참조(구현)** — 소스 표기 `arg.<이름>`, AST 는 참조 `{ kind: "param", name }`(`attr.` · `builtin.` 과 같은 모양, 두 토막). 인자는 집계 · 노드 한정자를 받지 않는다(문법 오류).
  쓸 수 있는 자리는 **타입 검사의 문맥 플래그**(`CheckOptions.params` — 함수조항 본문의 선언 인자 타입)가 가른다 — 플래그가 없는 구분자 식 · 문면 식에서는 `structure` 오류, 선언되지 않은 이름은 `brokenRef`.
  평가기는 인자를 모른다 — 조립이 함수조항을 펼칠 때 인자 연결(구분자 · 상수)로 바꿔 쓴다(평가까지 남으면 `structure` 오류). 세목 선택지 목록 인자는 비교 · 조건 자리에 서지 않는다(가공은 내부 변수 몫).
- **내부 변수(구현)** — 소스 표기 `var.<이름>`(예약어 `var`), AST 는 참조 `{ kind: "local", name }`. 저장 모양은 함수조항 정의의 `locals: [{ 이름, 식 }]` — 앞에 선언한 것만 읽는다(순서대로 평가, 뒤 이름 · 자기 자신 = 오류).
