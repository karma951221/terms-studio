# 데이터모델

> 상태: 초안 · 최종수정: 2026-09-27 (문면 노드 식별 — ADR-0072, 설계 반영 대기)
> 정본은 `src/db/schema/*.ts` (drizzle). 이 문서는 무엇이 어디 사는지의 지도다.

## 저장 구조 — 원칙

- **코드(불변)와 id(uuid)는 다르다.** 코드는 참조·식·저장의 정본(ADR-0005), id 는 저장소 행 식별자.
  코드는 `code_sequences (kind, scope, next)` 에서 원자적으로 채번하고 삭제된 순번은 재사용하지 않는다.
  구분자 `D0001` · 필드 `F01`(구조체 안) · enum `E0001` · enum 값 `V01` · 공용조항 `C0001` · 옵션 `O01` · 담보속성 `A0001` · 유효값 `V01`.
  별표만 유저 입력 코드(리뷰 대상 R5).
- **값 자리는 한 테이블이다.** `entity_values (owner_kind, owner_id, discriminator_code, field_code, value jsonb)` —
  **미입력 = 행 없음**(ADR-0004), null 값 행은 없다. 소유자는 부착 5레벨 실체(product · plan · coverage · subCoverage · benefit)와
  탑재 스냅샷 실체(productCoverage · productSubCoverage · productBenefit · productPlan). 탑재 = 행 복사(ADR-0002).
- **선택적 노출 부착도 한 테이블이다.** `entity_attachments (owner_kind, owner_id, discriminator_code)`. 부착 여부 = 정의의 `always_exposed` ∨ 이 행.
- **영역 간 FK 는 걸지 않는다.** 값·부착 테이블은 소유자 id 를 FK 없이 갖는다. 삭제 연쇄는 서비스가 한다.
  영역 안(담보 → 세부보장 → 급부, 공용조항 안 옵션 등)에는 FK cascade 를 쓴다.
- **문면은 문서 1행 = 트리 jsonb 1건.** 노드 id 는 트리 안에서 유일. 번호는 저장하지 않는다(ADR-0012).
  참조 대상 식별은 아래 §문면 노드 식별 (2026-09-27 · 설계 반영 대기).
- 모든 테이블에 감사 자리(`created_at/updated_at/created_by/updated_by`) — 이력·개정 기획(2차기획 목록)의 발판.
- 표준 Postgres 만. PGlite 전용 기능 금지 (서버 Postgres 이관 대비).

## 문면 노드 식별 — 참조 대상 (2026-09-27 · 설계 반영 대기)

> [[기능/문면/결정/ADR-0072-참조대상-조uuid-조전체유일P코드]] 결정. **현재 코드는 아직 옛 형태**(`ArticleRefNode.targets: { nodeId }[]` · `ArticleNode.title: string` · 조 자리 조건 블록 elif · else 허용) —
> 구현은 다음 작업 단위(`src/domain/document/nodes.ts` · `src/domain/assembly/render.ts` articleRef · `src/domain/refs/graph.ts` article 간선).

- **식별 두 층.** 노드 uuid 는 정체성(편집 · 출처 추적), **참조의 정체성은 코드**.
- **조**는 코드가 없다 — uuid 하나. 조를 uuid 로 드는 자리(조연결 `linkedArticleId` · 옵션 오버라이드 `through` · `product_hidden_articles.article_id` · 조만 가리키는 조 참조)는 그대로.
- **항 · 호 · 목 노드에 `code` 필드** — `P` + 숫자(기본 4자리 100 단위, P9900 을 넘으면 자릿수 확장). 단계는 코드가 아니라 트리 위치.
  **조 전체에서 유일하되 공존하는 노드끼리만** — 가장 가까운 공통 조건 블록의 서로 다른 가지에 있으면 배타라 같은 코드 허용, 그 밖(분기 밖 ↔ 가지 안 · 같은 가지 · 중첩)은 중복 금지(저장 거부).
- **`ArticleRefNode` 대상 = `{ articleId, code? }`** — `code` 없으면 조, 있으면 그 조의 항 · 호 · 목. 번호는 조립 때 살아남은 트리에서 계산.
  참조 그래프는 조 uuid 키 · 항 · 호 · 목 참조는 조로 올린 간선에 코드를 싣는다. 해소 실패(코드 없음)는 `brokenRef`.
- **`ArticleNode.title` = 인라인 노드 목록**(`string` 에서 변경) — 인라인 조건 허용.
- **조 자리 `CondBlockNode` 는 if 가지 하나** — elif · else 는 저장 검증이 거부.
- **전환**: 조마다 문서 순서대로 채번(배타 가지의 같은 위치 항은 같은 코드) · 기존 `nodeId` 참조 → 그 노드의 조 + 코드 · 조 자리 elif · else 가 있는 데이터는 전환 때 보고.

## 예약된 자리 — 산출본 (2026-09-09 · 구현 MVP 이후)

다중산출은 산출본을 저장한다 — **상품당 최신 1벌 덮어쓰기, 조립트리와 파일 둘 다**
([[기능/조립산출/조립산출]] R7 · [[기능/조립산출/결정/ADR-0034-다중산출-1급-조립결정성]]).
테이블은 아직 만들지 않는다. **자리와 이유만 여기 남긴다** — 현행 시스템이
「결과를 담을 모델이 애초에 없어 스키마부터 새로 만든」 사태를 반복하지 않기 위해서다.

| 예약 테이블 | 담을 것 | 비고 |
|---|---|---|
| `booklet_outputs` | product_id UQ · booklet(조립트리) · complete · 오류 요약 · 산출 시각 · run_id | 상품당 1행. 덮어쓴다 — 회차 이력 없음 |
| `booklet_files` | booklet_output_id FK · 서식 · 위치/바이트 | 서식(`.docx`/PDF)은 [[00_시작/범위]] 에서 MVP 밖 |
| `assembly_runs` | 시작·종료 · 대상 건수 · 성공/오류/실패 건수 | 산출본은 덮어쓰지만 **실행 이력까지 버릴 이유는 없다** (열린 문제) |

500쪽 조립트리를 jsonb 로 그대로 넣을지(압축 · 외부 오브젝트 저장)는 산출본 실물을 보고 정한다 —
이 판단이 남아 있으므로 컬럼 타입까지는 지금 못박지 않는다.

## 마이그레이션 원칙

- 스키마는 TS 코드가 정본. `npm run db:generate` 로 `drizzle/` 에 SQL 을 생성하고 `db:migrate`/시드가 적용한다.
- 테스트는 마이그레이션 파일에 의존하지 않는다 — `pushSchema` 로 스키마 코드에서 바로 DDL 을 만든다.
  마이그레이션 파일은 실제 파일 DB(`.data/pgdata`)와 배포용이다.
- 개발 DB 는 PGlite 파일, 프로덕션은 Postgres 호환(미정). 같은 마이그레이션을 그대로 쓴다.
- **Q1(마이그레이션 대비)**([[00_시작/범위]]): 코드 불변 + 값 테이블 단일 + 감사 자리로 기존 데이터 이관의 원천 봉쇄는 없다. 변환 규칙은 대체 시점에.
