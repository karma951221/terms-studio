# ADR-0019 — 개발/프로덕션 모드 폐지 · 역할(권한)로 대체

> 상태: 채택 · 날짜: 2026-09-04 (경계 확정 2026-09-05)

## 맥락

[[00_시작/도메인모델]] §5 는 파괴적 변경(삭제·타입 변경·구조 변경)의 허용 여부를
**전역 모드 스위치 하나**(개발 / 프로덕션)로 갈랐다. 같은 삭제 액션이 모드에 따라
「허용 + 연쇄 삭제」와 「사용 중이면 거부」로 갈려 **규칙이 두 벌**이었고, 변경·삭제의
정식 규칙은 「MVP 후 이력·개정 규칙과 동시 기획」으로 미뤄져 있었다
([[기능/구분자/구분자]] 잠정 규칙, 2026-08-30).

2026-09-04 MVP 제외 목록 재검토에서 이 잠정 규칙을 정식 규칙으로 올리기로 하면서
(선택지: 잠정 유지 / 이력만 추가 / 정식 규칙), 그 정식 규칙의 모양을 다시 봤다.

## 결정

1. **개발/프로덕션 모드 개념을 없앤다.** 전역 모드 스위치, 모드 전환 액션, 전환 시점 검사,
   모드별로 갈리던 거부 규칙을 전부 폐지한다.
2. **변경·삭제 규칙은 한 벌이다** — 지금까지의 개발 모드 규칙이 유일한 규칙이 된다:
   - 삭제·타입 변경·구조체 필드 삭제·enum 값 삭제·구조(트리) 삭제·부착 해제 등
     **파괴적 액션**은 영향 범위(소실될 값 행·깨질 참조 목록)를 보여주고 **확인 후 허용**한다.
   - 깨진 참조는 조용히 사라지지 않고 **오류 상태**로 남아 관계정보 뷰·조립 오류에 드러난다.
   - 최소 구조 위반(담보의 마지막 세부보장 등)은 여전히 서버가 거부한다.
   - 구조체 필드 추가는 비파괴 — 기존 저장분에 미입력 자리가 생긴다 (변경 없음).
3. **파괴적 액션은 「관리자」 역할만 실행할 수 있다.** 기준은 하나 —
   **「이미 저장된 값이나 참조를 없애는가」.** 역할은 MVP 에서 관리자 · 편집자 2종.
   편집자는 생성·조회·수정·부착·탑재·값 입력을 하고, 파괴적 액션은 서버가 역할로 거부한다
   (화면 숨김이 아니라 서버 거부 — 숨김 ≠ 잠금 원칙 유지).
4. 따라서 **인증·권한 분리는 MVP 로 승격**한다 ([[00_시작/범위]] 「나중으로 미루는 것」에서 삭제).
   MVP 는 1인 사용이므로 로그인 화면은 최소형이어도 되지만, **역할 검사는 서버(도메인 계층)에
   처음부터 들어간다.**

## 이유

- 모드는 「언제」를, 역할은 「누가」를 가른다. 파괴적 변경의 위험은 시점이 아니라 판단 주체의
  문제였다 — 영향 목록을 보고 판단할 사람이 누구인지가 핵심이다.
- 규칙이 한 벌이면 액션 명세·시나리오·서버 검증이 절반으로 준다.
- 권한 분리는 어차피 로드맵에 있었다([[공통/기술/기술스택]] 제약). 모드의 서버 거부 골격이
  「권한 체계의 앞선 모습」이라고 이미 적어 두었으므로, 앞선 모습을 걷어내고 본체를 넣는 것이다.

## 버린 대안

- **개발계 / 운영계 분리 (두 데이터 공간 + 이관)** — 이관 검사 하나로 규칙이 단순해지고
  이관 = 판본이라 이력·개정이 따라온다. 그러나 운영계를 살아 있는 두 번째 DB 로 두면
  참조 그래프 복사·운영계 마스터 판본 관리가 생겨 값이 효익을 넘는다. 운영계를 불변
  스냅샷 묶음으로 축소하면 효익만 남지만, 그 모양은 결국 「판본 확정」 기능이지 분리가 아니다
  → 판본·개정은 별도 기획으로 남기고 분리는 하지 않는다.
- **모드 유지 + 권한을 위에 얹기** — 두 장치가 겹쳐 규칙이 다시 두 벌이 된다. 기각.
- **잠정 규칙 유지** — MVP 관통에는 충분하지만, 알파Plus 이후에도 이 시스템으로 편집을
  이어가려는 의도와 맞지 않는다.

## 결과와 감수하는 비용

- **이력·개정(판본)은 이 결정이 답하지 않는다.** 역할은 기록을 남기지 않는다.
  이력·개정 규칙은 2차기획_목록(아카이브) 에 별도 항목으로 남긴다.
- 문서 전파 범위가 넓다 — [[공통/화면/유저액션_작성원칙]] 296 액션의 「전제」열에 적힌 모드 제약,
  [[공통/화면/시나리오/역할권한_시나리오]], [[QA/인수기준]] 「모드 (P1)」 행,
  [[실행/개발순서]] P1 「개발/프로덕션 모드 골격」 이 전부 역할 기준으로 바뀌어야 한다.
  핵심 문서(도메인모델·구분자_기획·범위·용어사전·인수기준·시나리오)는 2026-09-04 반영,
  액션 명세는 2차 구현 후 리뷰에서 일괄 전파한다.
- 관리자 전용 경계 — **2026-09-05 확정**: 파괴적 = 「실체·정의·구조를 없애는 것」
  (구분자·필드·enum 값·공용조항·문서·별표·담보 노드·상품·탑재·담보속성 삭제, 타입 변경, 부착 해제).
  **값 비우기(명시값 → 미입력)·공용조항 옵션/선택지 삭제·특약 그룹 삭제/배치 해제는 편집자도 가능**
  — 자기 값을 지우는 일상 조작이거나 값 손실이 없고, 옵션 삭제로 깨지는 사용처 선택은 재검사(optionInvalid)로
  드러난다. 버린 대안: 셋 다 관리자(편집자가 값을 못 지움) · 옵션 삭제만 관리자(참조를 깨뜨리므로).
- 1인 사용 MVP 에서 역할 검사는 「현재 사용자 = 관리자」 고정으로 동작한다.
  로그인·사용자 관리 화면의 완성도는 MVP 인수 조건이 아니다.
