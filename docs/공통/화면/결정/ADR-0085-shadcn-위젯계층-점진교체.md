# ADR-0085 — 위젯 계층은 shadcn(Tailwind v4 · Radix) · 화면은 점진 교체

> 상태: 채택 · 날짜: 2026-10-12

## 맥락

화면은 날 `<button>` · `<input>` · `<select>`(2026-10-12 기준 약 109 · 98 · 52곳)에 `globals.css` 의 **요소 선택자**(`button {…}`)를 덧씌워 그린다.
Button · Input · Select 같은 위젯 계층이 없고, `src/app/_components` 는 셸(ListShell · EditShell)과 직접 구현한 위젯 몇 개(Combobox · MoreMenu · Confirm · Toggle)뿐이다.
디자인원칙 §5(반경 3px · 그림자 없음)와 §1.6(22×22)이 겹쳐 위젯이 사각형이고 딱딱하다는 사용자 평가가 나왔다(2026-10-12).
현행 모델링 시스템(MUI)의 깔끔함이 비교 기준이다. 색 · 글꼴 테마는 그대로 둔다.

## 결정

1. **위젯 계층은 shadcn** — Radix 기반, `src/components/ui/` 에 복사해 우리 코드로 둔다. 일반 아이콘은 `lucide-react`, 도메인 기호(ƒ · 자물쇠 등, 디자인원칙 §1.2)는 `icons.tsx` 에 남긴다.
2. **Tailwind v4 를 preflight 없이** 들인다(theme · utilities 만). shadcn 변수는 `--ts-*` 토큰에 잇는다 — 테마의 정본은 계속 `--ts-*` 다.
3. **형태는 B안** — 반경 6px · 컨트롤 높이 32px · 표 행 32px · 그림자는 떠 있는 요소(메뉴 · 대화상자 · 팝오버 · 툴팁)만 · 포커스 링. 디자인원칙 §1.4 · §1.6 · §5 가 정본.
4. **점진 교체** — `globals.css` 요소 선택자를 `button:not([data-slot])` 처럼 좁혀 shadcn 위젯(`data-slot` 이 붙는다)에 닿지 않게 하고, 날 태그 화면은 그대로 둔다.
   0단계 기반 → 1단계 공통 셸 · 위젯(`_components`, props 유지) → 2단계부터 기능별로 날 태그를 위젯으로 바꾸며 그 영역의 레거시 CSS 를 지운다. 끝나면 요소 선택자 규칙은 0.

## 이유

- 위젯 계층이 비어 있어 갈아낄 기존 위젯이 거의 없다 — 복사형 shadcn 은 소유 · 수정이 자유롭고 런타임 의존이 Radix 프리미티브뿐이다.
- 메뉴 · 대화상자 · 팝오버의 키보드 · 포커스 관리는 Radix 가 맡는다. 직접 구현한 MoreMenu · Confirm 에서 매번 다시 풀던 문제다.
- 토큰을 `--ts-*` 에 이으면 다크 모드 · 문서 세계(명조)가 그대로 따라온다.
- 요소 선택자를 `data-slot` 으로 가르면 래퍼 클래스(`.legacy`) 없이 두 체계가 한 화면에 공존한다 — 한 번에 깨지는 화면이 없고 단계마다 E2E 로 확인한다.

## 버린 대안

- **MUI 직접 도입** — 현행 시스템과 가장 닮지만 CSS-in-JS(emotion)가 전역 CSS 체계와 충돌하고 무겁다. 사용자가 말한 「슬롭 느낌」이 그대로 온다.
- **자체 CSS 로 MUI 느낌만 차용** — 의존성은 없지만 메뉴 · 대화상자 접근성을 계속 직접 만든다. 위젯 계층을 처음부터 쓰는 비용이 shadcn 복사보다 크다.
- **헤드리스(Base UI · Radix) + 자체 CSS** — shadcn 과 같은 결과를 Tailwind 없이 내지만, 스타일을 다 직접 쓴다.
- **전면 일괄 교체** — 날 태그 260여 곳 · 요소 선택자를 한 번에 걷는다. 빠르지만 E2E 복구 폭이 커서 버렸다.
- **형태 A(현행) · C(반경 10px · 알약 버튼 · 세그먼트 탭)** — 2026-10-12 시안 비교에서 B 선택. 표 행은 36px(B 원안) 대신 32px — 긴 목록 화면의 밀도 손실을 줄인다.

## 결과와 감수하는 비용

- 과도기 동안 한 화면에 두 체계(날 태그 + 위젯)가 섞여 보일 수 있다 — 1단계 셸 교체가 끝나면 앱 전체 인상은 B 로 바뀐다.
- shadcn 기본 클래스의 `font-medium`(500)은 맑은 고딕에 없다(디자인원칙 §3 · §8) — 복사할 때 400 / 700 으로 고친다.
- 빌드에 Tailwind(PostCSS) 단계가 생긴다. `src/domain` 순수층에는 영향 없다.
- 디자인원칙 §5 · §8 의 「반경 3px 고정 · 그림자 · 카드 안 씀」은 위젯에 한해 이 ADR 로 바뀐다. 섹션은 여전히 카드가 아니라 괘선 + 제목이다.
