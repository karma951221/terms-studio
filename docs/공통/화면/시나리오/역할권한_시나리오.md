## 시나리오 1 — 편집자: 파괴적 액션은 서버가 거부
**전제**: 편집자 역할. 담보 「수술비」(세부보장 1종수술~7종수술)가 상품에 탑재되어 있음.
**흐름**:
1. 담보 마스터에서 세부보장 삭제 등 파괴적 액션 시도 → 서버가 **역할**로 거부, 사유 반환.
2. 화면을 우회해 API 를 직접 호출해도 동일하게 거부된다.
**기대 결과**: 잠금은 화면 숨김이 아니라 서버 검증이다 — 숨김 ≠ 잠금.
**경계·오류**: 파괴적이지 않은 작업은 편집자도 허용 — 표시명 변경, enum 값 추가, 구조체 필드 추가, 구분자 값 입력·수정, 부착·탑재.

## 시나리오 2 — 구조 추가 → 기존 상품담보에 빈 값 (편집자 가능)
**전제**: 수술비 담보가 탑재된 상품 존재.
**흐름**:
1. 담보 마스터에 세부보장 「8종수술」 추가 → 허용 (비파괴).
2. 이미 탑재된 상품담보에 추가 노드의 값 자리가 빈 값(미입력)으로 나타난다.
3. 마스터 기본값은 자동 복사되지 않는다 — 탑재 시점 스냅샷 외의 두 번째 복사 시점을 만들지 않는다.
4. 새 값 자리는 완결성 조회에 미입력으로 잡힌다.
**기대 결과**: 구조 변경이 기존 상품담보에 확인 안 된 값을 흘려 넣지 않는다.
**경계·오류**: 미입력을 채우기 전 조립 → 오류 + 좌표 보고.

## 시나리오 3 — 관리자: 구조 삭제 → 영향 목록 확인 후 값 행 연쇄 삭제
**전제**: 관리자 역할. 삭제 대상 세부보장이 상품담보 값 행을 갖고, 문면 반복문·조건식이 그 트리를 순회·참조 중.
**흐름**:
1. 세부보장 삭제 시도 → 영향 목록(소실될 값 행 수 · 식·문면 사용처)을 돌려주고 확인을 요구한다.
2. 확인 후 삭제 → 상품담보의 해당 값 행이 함께 삭제된다.
3. 남은 깨진 참조는 조용히 사라지지 않고 오류 상태로 표시된다 (관계정보 뷰 · 조립 오류).
**기대 결과**: 삭제의 파장이 전부 드러난다 — 조용한 파손 없음.
**경계·오류**: 최소 구조를 위반하는 삭제(담보의 마지막 세부보장, 세부보장의 마지막 급부) → 관리자도 거부.

## 시나리오 4 — 역할이 유일한 스위치
**전제**: 관리자 1명, 편집자 1명.
**흐름**:
1. 같은 삭제 요청을 두 역할이 보낸다.
2. 편집자는 역할 거부, 관리자는 영향 목록 → 확인 → 실행.
**기대 결과**: 파괴적 액션 허용 여부를 가르는 스위치는 역할 하나다. 시점·환경·데이터셋 단위 모드는 없다.
**경계·오류** (2026-09-04 확정):
- 역할은 사용자에 붙는다. MVP 1인 사용 동안 현재 사용자 = 관리자 고정.
- 파괴적 액션의 목록은 [[공통/화면/유저액션_작성원칙]] 각 파일에서 액션별로 표시한다 (리뷰 시 전파).
