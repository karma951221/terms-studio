# 유저액션 작성 원칙

> 상태: 초안 · 최종수정: 2026-09-27
>
> 근거: [[공통/화면/디자인원칙]] §11.2 결정 메모(유저액션 명세의 축). 옛 액션 명세 파일(`02_UI/유저액션/*_액션.md`)과 그 색인은 기능 문서 §4 로 흡수됐다 — 원본은 `_archive/2026-09-27_문서재편/02_UI/유저액션/`.

유저액션은 사람이 이 시스템에서 **할 수 있는 일**이다. 각 기능 문서([[_템플릿/기능]]) §4 화면의 「유저액션」이 정본이다 — 따로 파일을 두지 않는다.

## 무엇이 여기 있고 무엇이 없나

| 유저액션에 쓰는 것 | 쓰지 않는 것 (있어야 할 곳) |
|---|---|
| 사람이 일으키는 행위 하나하나 · 전제 · 결과 · 거부 조건 | **왜 그런 규칙인가** → 기능 문서 §3 · ADR |
| 조회 액션 (바꾸는 것 없이 보는 것) | **대표 흐름 · 기대결과 서사** → `기능/<f>/시나리오/` |
| 서버가 거부하는 조건 (역할 · 중복 · 참조 무결성) | **결정의 맥락 · 버린 대안** → `결정/` ADR |

한 문장을 쓰면서 「이건 흐름인데」 싶으면 그건 시나리오 몫이다. **액션은 목록이지 서사가 아니다.**

## 단위

- **의도 하나 = 액션 하나.** 저장소 상태를 바꾸는 의도 하나가 한 행이다. 클릭 · 드래그 같은 제스처가 아니라 「무엇을 바꾸려 하나」로 쓴다 — 다만 기능 문서 §4 는 route 별이므로 그 화면에서 **무엇을 누르면** 그 의도가 일어나는지를 같은 행에 적는다.
- **조회도 액션이다** — 사용처 추적 · 사전평가 · 미리보기처럼 바꾸지 않고 보는 것도 적고, 결과에 `바뀜 없음 — <무엇이 보이나>` 를 쓴다.
- 용어는 [[00_시작/용어사전]] · 화면 낱말은 [[공통/화면/화면단어]] 를 따른다.

## 표 형식

```markdown
| 액션 | 누르는 것 | 전제 | 결과 | 거부 | 근거 |
|---|---|---|---|---|---|
| 구분자 생성 | 조회 화면 `+` → 생성 화면 `저장` | 표시명 · 레벨 · 결과 타입 · 식 | 정의 1건 추가, 코드 자동 채번 | 식 검사 오류 | [[기능/구분자/구분자]] §3.3 |
```

- **전제** — 이 액션이 가능하려면 있어야 하는 상태. 역할 제약(관리자만)도 여기.
- **결과** — 저장소에 **무엇이 바뀌나**. 즉시 저장 명령인지, 편집 화면의 `저장` 에 포함되는지를 가른다([[공통/화면/디자인원칙]] §2 L2 저장 단위).
- **거부** — 서버가 막는 조건. 「화면에서 숨김」은 거부가 아니다.
- **근거** — ADR · 시나리오 링크. 없으면 비운다(= 근거 없는 액션 신호).
- 없어진 액션은 적지 않는다 — 결론만 쓴다. 왜 없어졌는지는 ADR 과 커밋 메시지가 갖는다.

## 화면 편집 원칙과 맞춘다

유저액션은 [[공통/화면/디자인원칙]] 과 `CLAUDE.md` 「화면 편집 원칙」에 어긋나게 쓰지 않는다.

- 상세 화면은 읽기 전용으로 열린다. `편집` → 고치고 → 같은 버튼이 `저장`. 한 편집 화면의 변경은 저장 한 번.
- 입력률 · 「값 자리 N 중 M」 · 진행 막대를 결과로 쓰지 않는다. 필요한 입력은 해당 항목과 수정 위치로 안내한다.
- 돌아가는 길은 제목 줄 경로 하나다. 편집 중이면 경로 링크도 「버립니까?」 확인.
- 파괴적 액션의 확인은 잃는 것을 이름과 개수로 말한다(디자인원칙 §9.5).

## 완전성 검사

**① 체크리스트 훑기** — 실체마다 아래 9종을 훑고, 해당 없으면 **「해당없음 — 이유」**를 적는다. 그냥 빠뜨리지 않는다.

`생성` · `조회` · `수정` · `삭제` · `관계 맺기(참조 · 탑재)` · `관계 끊기` · `순서 변경` · `상태 전이` · `복제`

**② 시나리오 역방향 대조** — 기능의 `시나리오/` 모든 단계가 어떤 액션 하나에 대응해야 한다.

- 대응할 액션이 없는 시나리오 단계 = **액션 누락**
- 대응하는 시나리오도 근거도 없는 액션 = **유령 기능** (지우거나 결정으로 올린다)
