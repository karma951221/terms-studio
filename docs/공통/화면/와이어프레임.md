# 와이어프레임 — 지금 이렇다 · 될 모습

> 상태: 초안 · 최종수정: 2026-09-16 (§20.2 기본정보 구현 반영 · §14 마스터 왼쪽 표+페이저)
> **2026-09-27 — 기록 문서로 둔다.** 그림은 2026-09-16 `main` 기준이라 그 뒤 결정(상세 경로 제목 줄 · L1 제목 줄 · 내비 단계 묶음 · 홈 `/` · `/catalog` 평면 표 등)이 빠져 있다.
> 화면의 정본은 각 기능 문서 §4 — 목록은 [[공통/화면/화면목록]]. 여기와 어긋나면 기능 문서가 이긴다.
>
> 기준: `main` (b7c5b55) · 될 모습의 정본: [[기능/마스터/결정/ADR-0037-입력항목-코드마스터-유저정의폼-MVP이후]] ·
> 레이아웃 근거: [[공통/화면/디자인원칙]] §2 · 라벨 출처: [[공통/화면/화면단어]] · `src/app/_lib/labels.ts`

**이 문서는 두 가지를 적는다.**

1. **지금 이렇다** — `main` 에 있는 화면을 있는 그대로 옮긴 그림 (`b7c5b55` 기록).
2. **될 모습** — 2026-09-12 에 확정된 값의 체계 3층 기획이 그 화면을 어떻게 바꾸는가.

2026-09-09 까지 이 문서는 1번만 적었다. **2026-09-12 로 실물을 그 기획에 맞춰 고치는 작업이 시작되니**
바뀌는 화면마다 될 모습 그림을 나란히 둔다. 실물 그림은 지우지 않는다 — 무엇을 무엇으로 바꾸는지가 같은 자리에서 읽혀야 한다.

「이렇게 되어야 한다」의 정본은 여전히 `02_UI/화면/*_화면기획` 과 `06_결정/ADR-*` 이고,
이 문서는 **그 둘을 화면 그림으로 옮긴 것**이다. 지금과 될 모습의 대조표는 §23.

> **2026-09-12 — 값의 체계 3층, 입력 항목은 코드 마스터.**
> 정본은 [[기능/마스터/결정/ADR-0037-입력항목-코드마스터-유저정의폼-MVP이후]] (2층 · 3층은 [[기능/구분자/결정/ADR-0036-폼-구분자-문면-3층]] 그대로) · [[기능/구분자/구분자]].
>
> - **1층 입력 마스터** — 상품 · 세목 · 담보 · 세부보장 · 급부 다섯 레벨의 입력 항목이 **코드에 고정**된다. 유저가 정의하지 않고, 추가 · 변경은 배포다.
>   읽기 전용 **마스터 조회** 화면(§14 — 신규 · 실물 없음)이 그 트리를 보여준다.
> - **2층 구분자** — 마스터 필드에 건 **식 하나**다 (참조 경로 `레벨.필드` — `급부.지급률` · `세목.납입면제.적용여부`). 종류 분류가 없고 결과 타입은 식에서 나온다.
>   구분자 화면 셋(§4 ~ §6)은 남되 **유형 · 타입 · 열거형변수 · 노출 · 기본값 칸이 빠지고 「구분자명 · 레벨 · 식 · 주석」 넷**만 남는다.
> - **3층 문면** — 조건식 · 반복 · 값 슬롯은 **구분자만** 참조한다 (§18).
> - **MVP 이후로 보낸 것** — 유저 정의 폼 · 필드 편집기 · 선택 필드 · 노출여부 · 부착 관계 · 유형 > 폼 탭.
>   폼 화면 셋(§11 ~ §13)은 **걷힌다.** 열거형변수(§8 ~ §10)는 값이 데이터라 MVP 에 그대로 남는다.
> - 마스터 필드는 **모든 노드에 항상 있다.** 담보 상세 · 상품 상세 · 상품담보 값의 값 폼은 그 레벨의 마스터 필드 전부를 그리고,
>   「+ 부착 가능」 · 「부착 해제」가 사라진다 (§15.3 · §20.2 · §20.3).
>
> 2026-09-12 하루에 ADR-0035(구분자 폐지) → 번복, ADR-0036 1층(유저 정의 폼) → ADR-0037 로 대체됐다.
> **이 문서의 될 모습은 전부 ADR-0037 기준**이다 — 0035 · 0036 1층으로 적었던 될 모습은 남겨 두지 않는다.

> **주의 — 「지금」 그림은 화면 QA 2회차 구현 전의 화면이다.** 이 문서를 그린 뒤(`b7c5b55`) 화면 QA
> 1 · 2회차의 코드가 `main` 에 들어왔다 — 공용 조각(`ListPage` · `FormRow` · `RadioGroup` ·
> `Combobox` · `NoteField` · `UsageDialog`)이 생겼고, 구분자 탭 · 별표 · 담보속성 화면이 바뀌었다.
> 그림과 실물이 갈린 자리는 §23 에 모았다 — 그림을 다시 그리는 일은 아직 안 했다.

**지금** — 리다이렉트뿐인 셋(`/` · `/types` · `/catalog/enums`)과 아직 실물이 없는 마스터 조회를 빼면 **화면 26개**다.
그중 화면기획이 있는 것은 13개 — 나머지 13개는 이 문서가 유일한 그림이다 (§24).

**될 모습** — 폼 화면 셋(§11 ~ §13)이 걷히고 마스터 조회 하나가 서서 **화면 24개**가 된다.
화면기획이 있는 것은 10개(폼 셋이 빠진다), 마스터 조회를 더해 **14개가 이 문서만 그림을 가진 화면**이다.
마스터 조회는 [[공통/화면/화면목록]] 「화면기획이 아직 없는 화면」에 이미 올라 있다.

화면을 가로질러 보고 싶으면 뒤의 두 절이 빠르다 — **§25 공용 조각 지도**(무엇이 어디까지 퍼졌나) ·
**§26 화면을 잇는 길**(막다른 화면은 어디인가).

## 2. 공통 껍데기 (`(app)/layout.tsx`)

로그인 뒤 모든 화면이 이 안에 들어간다. 세션이 없으면 `currentActor()` 가 `/login` 으로 보낸다.

```
┌────────────┬──────────────────────────────────────────────────────────┐
│terms-studio│                                                          │
│            │                                                          │
│ 구분자      │                                                          │
│ 유형        │                                                          │
│ 담보        │                    본문 (.ts-main)                        │
│ 공용조항     │                    최대폭 1160 · 패딩 20/24/32            │
│ 문면        │                    L3(문면 저작)만 전폭                    │
│ 별표        │                                                          │
│ 상품        │                                                          │
│ 담보속성     │                                                          │
│ 관계정보     │                                                          │
│            │                                                          │
│ ──────     │                                                          │
│ 홍길동 · 관리자│                                                        │
│ 〔로그아웃〕  │                                                          │
└────────────┴──────────────────────────────────────────────────────────┘
  168px 고정
```

- 현재 위치는 **주칠 + 좌측 괘선**(`aria-current="page"`) 하나로만 표시한다 (§1.3).
- 하단에 현재 사용자 이름 · 역할(관리자 · 편집자) + 로그아웃 폼.
- 내비 순서는 코드의 `NAV` 배열 그대로다 — 구분자 · 유형 · 담보 · 공용조항 · 문면 · 별표 · 상품 · 담보속성 · 관계정보.

**될 모습 — 내비에 「입력항목」이 선다** (이름 · 경로는 제안, ADR-0037 열린 문제).

```
│ 구분자      │   ← 2층: 마스터 필드에 건 식
│ 유형        │   ← 열거형변수 하나만 남는다 (폼 하위 탭은 걷힌다)
│ 입력항목(제안)│   ← 1층: 마스터 조회 (§14) · 경로 `/master` (제안)
│ 담보        │
│ …           │
```

- **「유형 > 폼」 자리를 대신하는 화면**이므로 유형 바로 아래에 세운다. 항목 수는 그대로 아홉이다 — 폼 하위 탭이 걷히고 최상위 하나가 는다.
- 이름은 **「입력항목」을 제안**한다. 「마스터」는 담보 마스터 · 상품 마스터와 부딪히고, 「폼」은 MVP 이후로 보낸 실체 이름이다.
  1층이 먼저 읽히게 「입력항목 · 구분자 · 유형」 순으로 놓는 안도 있다 — **정하지 않았다** (「열어 둔 질문」 W-E).

│ 코드    │ 표시명                      │ 종류 ▾  │ 레벨 ▾  │ 노출 ▾    │
├────────┼────────────────────────────┼─────────┼─────────┼───────────┤
│ D0007  │ 갱신여부                     │ 단일값   │ 담보    │ 선택      │
│ D0003  │ 납입면제                     │ 폼      │ 담보     │ 무조건     │
│ D0011  │ 보험기간                     │ 파생    │ 담보     │ —        │
├────────┴────────────────────────────┴─────────┴─────────┴───────────┤
│ 총 11건 · 1/1                                                        │  여러 페이지일 때만 이전 · 다음
└──────────────────────────────────────────────────────────────────────┘
```

- **검색**은 버튼 없이 반영된다 — 디바운스 300ms · IME 조합 중에는 멈춘다 · URL `?q=` 에 `replace` 로 싣는다 (`ListFilterBar`).
- **컬럼 헤더가 곧 필터**다. `▾` → 팝오버에서 값 하나. 걸리면 `▼` 로 바뀌고 칩이 생긴다.
  칩이 **2개 이상**일 때만 「모두 지우기」가 나온다.
- **기준일 · 미확정 포함은 자리만 있고 잠겨 있다** (`disabled`, tooltip 「이력 기능 준비 중」) — [[공통/기술/결정/ADR-0026-이력개정-이력일자-작업본확정]].
- 표 컬럼은 **코드 · 표시명 · 종류 · 레벨 · 노출** 다섯이다. 최종수정 · 수정자는 없다.
- 종류 필터의 선택지는 **단일값 · 폼 · 상수 · 파생** — 폼이 이 목록에 그대로 나온다.
- 페이지 크기 50. 빈 목록이면 EmptyState(무엇인지 + 예시 + 「새 구분자 만들기」), 필터 탓 0건이면 한 줄.
- URL 이 상태의 정본 — `?q=&kind=&level=&exposure=&page=`. `+` 버튼은 걸린 `kind` · `level` 을 생성 화면으로 물려준다.

— 될 모습 —

```
┌──────────────────────────────────────────────────────────────────────┐
│ 구분자                                                          〔+〕 │  tooltip 「새 구분자」
├──────────────────────────────────────────────────────────────────────┤
│ 🔍[코드 · 구분자명          ]        〔모두 지우기〕 기준일[2026-09-12] ☐미확정 포함│
│ 레벨: 담보 ✕                                                          │  걸린 필터 칩 (0개면 줄 없음)
├────────┬───────────────────────────────┬────────┬────────────┬──────┤
│ 코드    │ 구분자명                       │ 레벨 ▾ │ 최종수정    │ 수정자│
├────────┼───────────────────────────────┼────────┼────────────┼──────┤
│ D0007  │ 면책구분                        │ 담보    │ 2026-09-12 │ 홍길동│
│ D0011  │ 최대지급률                      │ 담보    │ 2026-09-12 │ 홍길동│
│ D0012  │ 감액기간문구                    │ 급부    │ 2026-09-11 │ 김편집│
├────────┴───────────────────────────────┴────────┴────────────┴──────┤
│ 총 11건 · 1/1                                                        │
└──────────────────────────────────────────────────────────────────────┘
```

- **유형 컬럼 · 유형 필터가 없다** — 구분자는 전부 식이라 가를 축이 없어졌다 ([[기능/구분자/구분자]] 배너).
  남는 컬럼은 **코드 · 구분자명 · 레벨 · 최종수정 · 수정자** 다섯이고, 컬럼 필터는 **레벨 하나**뿐이다.
- **식은 컬럼에 세우지 않는다.** L1 은 남는 폭을 한 컬럼만 먹게 하고(디자인원칙 §2 L1) 그 자리는 구분자명이다 —
  mono 식을 옆에 세우면 둘 다 잘린다. 식은 상세(§6)에서 본다. (목록에서 식이 보여야 한다는 요구가 서면 결정 사항 — 「열어 둔 질문」 W-F)
- 노출 컬럼은 **지금도 없다** (2026-09-09). 될 모습에서는 노출이라는 개념 자체가 없어진다.
- 검색(코드 · 구분자명 부분 일치 · 디바운스 300ms) · 필터 칩 · 기준일 · 페이저는 **그대로**다 — 조회 공통 규칙은 이번 기획에 안 걸린다.
- URL 은 `?q=&level=&page=` 로 준다 — `kind` · `exposure` 가 없어진다. `+` 는 걸린 `level` 만 생성 화면으로 물려준다.
- 빈 상태의 예시 문구도 식으로 바뀐다 — 「예: 면책구분 = `any(급부.면책여부)`」.

## 5. 새 구분자 (`/catalog/new`)

**개정 대상** (2026-09-12 · ADR-0037) — 될 모습은 이 절 뒤쪽에 그렸다.

— 지금 —

```
┌──────────────────────────────────────────────────────────────────────┐
│ 새 구분자                                                             │
│ (◉) 단일값   ( ) 폼   ( ) 상수   ( ) 파생                              │  라디오 1줄로 고른다
├──────────────────────────────────────────────────────────────────────┤
│ 표시명       [                          ]                             │  ← 고른 종류의 폼 하나만 보인다
│ 레벨         [ 담보                  ▾ ] 〔제안〕                       │    (나머지 셋은 hidden 으로 DOM 에 남는다)
│ 타입         [ 문자열                ▾ ]                              │
│ 선택지 (타입이 선택형일 때만) [ —      ▾ ]                              │  항상 보인다
│ 무조건 노출   ☐                                                       │
│ 설명         [                          ]                             │
│                                          〔단일값 구분자 생성〕         │  제출은 폼 하단
└──────────────────────────────────────────────────────────────────────┘
```

종류마다 폼이 다르다 (칸 이름은 실물 그대로).

| 종류 | 칸 | 제출 버튼 |
|---|---|---|
| 단일값 | 표시명 · 레벨〔제안〕 · 타입 · 선택지 · 무조건 노출 ☐ · 설명 | 「단일값 구분자 생성」 |
| 폼 | 표시명〔제안〕 · 레벨〔제안〕 · 노출 ☐무조건 · 설명 (`StructCreateForm`) | 「폼 생성」 |
| 상수 | 표시명 · 값 · 설명 (**레벨 없음**) | 「상수 구분자 생성」 |
| 파생 | 표시명 · 레벨〔제안〕 · 식(mono) · 설명 | 「파생 구분자 생성」 |

- `KindPicker` 는 4개 폼을 **전부 렌더해 두고 `hidden` 으로 가린다** — 종류를 바꿔도 입력이 살아 있는 이유이자,
  안 보이는 칸의 `required` 가 DOM 에 남는 이유이기도 하다.
- 레벨의 기본값은 `coverage`(담보)이고 옆에 〔제안〕 배지가 붙는다 (§9.1).

— 될 모습 —

```
← 구분자 목록
┌──────────────────────────────────────────────────────────────────────┐
│ 새 구분자                                                  〔만들기〕  │  제출은 헤더 우측 (화면 QA 2회차)
├──────────────────────────────────────────────────────────────────────┤
│ 구분자명  [ 면책구분                    ]                              │  ← 폼은 내용 영역 폭의 절반 (§2 L2)
│ 레벨 ⓘ    [ 담보                    ▾ ] 〔제안〕                       │  ⓘ 「식이 평가되는 자리 — 집계의 뿌리」
│ 식        [ any(급부.면책여부)                    ]                    │  mono · 자유 타이핑
│           ┌──────────────────────────────┐                          │  ← 자동완성 (타이핑 중에만)
│           │ 급부.면책여부        참거짓     │                          │     레벨.필드 · 타입을 같이 보인다
│           │ 급부.지급률          숫자       │                          │
│           │ 세목.납입면제.적용여부  참거짓    │                          │
│           └──────────────────────────────┘                          │
│           집계 any · all · sum · count · exist · not exist            │  도움줄 (한 줄, 민무늬)
│ 주석      [                              ]                            │
└──────────────────────────────────────────────────────────────────────┘
```

- **유형 라디오(단일값 · 폼 · 상수 · 파생)가 없어진다.** 칸은 **구분자명 · 레벨〔제안〕 · 식 · 주석** 넷 — 지금의 「파생」 폼 하나만 남는 셈이다.
  `KindPicker` 도 `StructCreateForm` 도 걷힌다 (§25).
- 타입 · 열거형변수 · 노출 · 기본값 칸은 **없다.** 구분자는 입력을 받지 않는다 — 결과 타입은 식에서 나온다.
- **식은 자유 타이핑 + 자동완성**이다 (mono). 자동완성은 마스터 조회(§14)가 가진 트리를 그대로 읽어 `레벨.필드` 경로를 제안하고,
  화면에는 **표시명 경로**(`세목.납입면제.적용여부`)를 보이되 저장은 코드 경로(`plan.exemption.applied`)로 한다 ([[공통/기술/결정/ADR-0005-코드-표시명-이중체계]]).
- **검사는 저장할 때 한다** — 파서(문법) · 참조(그런 마스터 필드가 있나) · 타입 세 가지. 실패하면 폼에 머물고 배너 한 줄
  (「급부.지급률 — 그런 입력 항목이 없다」 · 「하위 레벨 필드는 집계 안에서만 쓸 수 있다」). 타이핑 중에는 막지 않는다 (§1.5 — 마찰은 되돌릴 수 없는 곳에만).
- 레벨 기본값 `담보` + 〔제안〕 배지는 그대로다. 조회에 걸린 레벨 필터가 있으면 그것이 넘어온다 (§9.1).
- 「설명」은 화면에서 **주석**으로 부른다 ([[공통/화면/화면단어]]) — 도메인 용어는 그대로 설명이다.

## 6. 구분자 상세 · 수정 (`/catalog/<code>`)

**개정 대상** (2026-09-12 · ADR-0037) — 될 모습은 이 절 뒤쪽에 그렸다.

— 지금 —

```
← 구분자 목록
┌──────────────────────────────────────────────────────────────────────┐
│ 갱신여부  D0007  사용처 3                        〔편집〕 〔🗑〕        │  헤더 = 이름 · 코드 · 메타 · 조작
├───────────────────────────────────────┬──────────────────────────────┤
│ 종류      단일값                        │ 사용처  3 / 전체 참조 41       │  우측 aside (.ts-l2-split, 40%)
│ 레벨 ⓘ    담보                          │ ┌──────┬───────────────────┐│
│ 표시명    [ 갱신여부              ]      │ │ 형태  │ 좌표              ││
│ 설명      [                      ]      │ ├──────┼───────────────────┤│
│ 노출 ⓘ    ☐ 무조건 — 이 레벨의 모든        │ │조건식 │ 담보약관 › 제3조… ││
│           모델링에 값 자리를 만든다        │ │치환   │ 보통약관 › 제5조… ││
│ 타입      [ 예/아니오            ▾ ]     │ └──────┴───────────────────┘│
│ 기본값 ⓘ  [ 예                   ▾ ]     │                              │
└───────────────────────────────────────┴──────────────────────────────┘
```

- **읽기 모드가 기본**이다. 값은 회색 칸(`.ts-field-locked`), 「편집」을 눌러야 입력기가 된다 (§2 L2).
- 편집 모드 헤더: `〔✕〕 〔저장〕 〔🗑〕` — 저장은 변경이 있을 때만 활성, ✕ 는 변경이 있으면 「계속 편집 / 버리기」 팝업.
- 저장 · 삭제가 값을 잃게 하면 **먼저 세어 보여준다** (`ts-dialog`: 「사람이 입력한 값 N건이 사라진다」 · 함께 삭제 · 깨질 참조 — §9.5).
- 종류 · 레벨은 회색 칸이지만 **편집 모드에서도 안 바뀐다** (읽기 전용).
- 종류별로 아래 칸이 갈린다.

| 종류 | 추가로 보이는 것 |
|---|---|
| 단일값 | 노출 ☐ · 타입(+선택형이면 선택지 셀렉트) · 기본값(타입을 따르는 입력기) |
| 폼 | 노출 ☐ · **필드 표(읽기 전용: 코드 · 표시명 · 타입 · 기본값)** + 「폼 탭에서 편집 →」 |
| 상수 | 값 |
| 파생 | 식 (mono) |

- 폼 코드로 들어와도 **리다이렉트되지 않는다** — 이 화면이 읽기 전용 표로 받는다.
- 사용처가 0건이면 aside 가 「아무 문면 · 식도 이 구분자를 읽지 않는다」 + 「문면에서 쓰러 가기 →」.
- 사용처 좌표는 누르면 그 자리(문면 · 상품 …)로 간다 (`coordinateHref`).

— 될 모습 —

```
← 구분자 목록
┌──────────────────────────────────────────────────────────────────────┐
│ 면책구분                              〔사용처 3〕 〔편집〕 〔🗑〕        │  사용처는 모달 (`UsageDialog`)
├──────────────────────────────────────────────────────────────────────┤
│ 코드      D0007                                                       │  못 고침 (시스템 채번)
│ 구분자명  [ 면책구분                    ]                              │
│ 레벨 ⓘ    담보                                                        │  못 고침 — 편집 모드에서도
│ 식        [ any(급부.면책여부)                    ]                    │  mono · 편집의 첫 자리
│           담보 레벨에서 평가 · 결과 참거짓                              │  저장된 식에서 읽어 주는 한 줄 (민무늬)
│ 주석      [                              ]                            │
└──────────────────────────────────────────────────────────────────────┘

  〔사용처 3〕 →  ┌ 사용처 — 면책구분 (D0007) ──────────────────┐
                │ 형태    │ 좌표                              │
                │ 조건식  │ 수술비 담보약관 › 제3조 ①           │
                │ 반복    │ 수술비 담보약관 › 제4조 ② (급부마다) │
                │ 슬롯    │ 보통약관 › 제5조 ③                 │
                └────────────────────────────────────────────┘
```

- **칸은 넷이다** — 구분자명 · 레벨(못 고침) · 식 · 주석. 코드는 헤더 아래 첫 행에 민무늬로 선다 (지금의 `main` 이 이미 그렇다).
  종류 · 타입 · 열거형변수 · 노출 · 기본값 칸과 「폼 탭에서 편집 →」 · 필드 표가 **전부 없어진다**.
- **식이 첫째 편집 대상**이다. 편집 모드에서 mono 입력칸이 되고 자동완성은 생성 화면(§5)과 같은 것을 쓴다.
  저장할 때 파서 · 참조 · 타입 검사를 다시 돌린다.
- 식 아래 한 줄은 **저장된 식이 무엇인지 읽어 준 것**이다 — 「담보 레벨에서 평가 · 결과 참거짓」. 사람이 고치는 칸이 아니다.
  결과 타입을 정의에 적을지 식에서 뽑을지는 아직 열려 있다 (ADR-0037 열린 문제).
- **사용처는 문면(조건식 · 반복 · 값 슬롯)뿐이다.** 값 행이 없으니 「이 구분자의 값 N건」이라는 목록도, 부착된 모델링 목록도 없다.
  0건이면 모달이 「아무 문면도 이 구분자를 읽지 않는다」 + 「문면에서 쓰러 가기 →」.
- **삭제 팝업의 문구가 바뀐다.** 셀 것이 값이 아니라 참조다 —
  「구분자 **면책구분(D0007)** 을 삭제한다. 이 구분자를 읽는 문면 **3곳**의 참조가 깨진다. 되돌릴 수 없다.」 + 좌표 목록 + 〔취소〕 〔삭제〕.
  지금의 「사람이 입력한 값 N건이 사라진다」 줄은 **없어진다** (§9.5 의 「잃는 것을 세어 보여준다」는 그대로).
  삭제는 관리자만 — 편집자가 누르면 서버가 역할로 거부한다 ([[공통/화면/결정/ADR-0019-모드폐지-역할권한]]).
- **식을 고쳐 결과 타입이 바뀌면** 저장 전에 같은 모양의 팝업으로 깨질 문면 사용처를 보여주고 관리자가 확인한다 ([[기능/구분자/구분자]] 변경·삭제 규칙).
- 폼 코드(`/catalog/<폼코드>`)로 들어오는 길은 사라진다 — 폼이라는 실체가 없다.

### 13.1 MVP 이후의 그림 — 유저 정의 폼 · 선택 필드

> **MVP 의 화면이 아니다.** 2026-09-12 에 ADR-0036 1층으로 그렸다가 같은 날 ADR-0037 로 **MVP 이후**가 됐다.
> 유저 정의 폼을 다시 열 때 여기서 출발하라고 남긴다 — 정본은 [[기능/마스터/마스터]] · 2차기획_목록(아카이브).
> **MVP 의 값 폼은 이 그림이 아니라** 「그 레벨의 마스터 필드 전부」다 (§15.3 · §20.2 · §20.3 의 될 모습).

```
← 폼 목록
┌──────────────────────────────────────────────────────────────────────────┐
│ 보험금지급                                     〔사용처〕 〔✕〕 〔저장〕 〔🗑〕 │  편집 모드 헤더
├──────────────────────────────────────────────────────────────────────────┤
│ 코드     D0004                                                            │  못 고침
│ 폼 이름  [ 보험금지급            ]                                         │
│ 레벨 ⓘ   급부                                                             │  못 고침
│ 노출 ⓘ   ☑ 무조건 — 이 레벨의 모든 모델링에 이 폼이 선다                       │
│ 주석     [                       ]                                        │
├──────────────────────────────────────────────────────────────────────────┤
│ 필드  3                                                                   │
│ ┌────┬─────┬──────────┬─────┬────────┬──────────┬──────────┬──────┬─────┐│
│ │순서 │ 코드 │ 필드 이름  │ 선택 │ 타입    │ 열거형변수 │ 기본값 ⓘ  │ 사용  │조작 ││
│ ├────┼─────┼──────────┼─────┼────────┼──────────┼──────────┼──────┼─────┤│
│ │ 1  │ F01 │[지급률  ] │ 필수 │ float  │ —        │ [ 100  ] │ 3 · ƒ2│↑↓🗑 ││
│ │ 2  │ F02 │[면책여부 ] │ 필수 │ enum   │ 여부 ▾   │ [ 아니오▾]│ 3 · ƒ1│↑↓🗑 ││
│ │ 3  │ F03 │[감액기간 ] │ 선택 │ string │ —        │ [       ] │ 1 · ƒ1│↑↓🗑 ││
│ └────┴─────┴──────────┴─────┴────────┴──────────┴──────────┴──────┴─────┘│
│ 필드 추가 ─────────────────────────────────────────────────────────────── │  편집 모드에서만 · 인라인
│   필드 이름   [                    ]                                       │
│   선택 필드   ☐ 선택 ⓘ  + 로 넣은 자리에만 값 자리가 생긴다                      │
│   타입        [ string       ▾ ]   (enum 이면) 열거형변수 [ ▾ ] 〔새 열거형변수〕  │
│   기본값 ⓘ    [                ]                                            │
│                                                          〔취소〕 〔추가〕   │
└──────────────────────────────────────────────────────────────────────────┘
```

- **종류 선택은 없다** — 폼의 필드는 전부 입력이다. 상수는 기본값으로, 계산은 구분자 탭(§4 ~ §6)으로.
- **타입 셀렉트**: `int` · `float` · `string` · `enum` · `list<string>` · `list<enum>` (2026-09-12 「일단」 목록 — `boolean` · `date` 는 ADR-0036 열린 문제.
  그림의 「면책여부 enum 여부」는 그 열린 문제가 닫히기 전의 임시 표기다).
- **선택 필드** 체크. 표의 「선택」 컬럼이 필수 / 선택을 보여준다.
- **사용** 컬럼은 값 행 수 · 이 필드를 참조하는 구분자 수(`ƒn`) 둘을 같이 보여준다 — 필드를 지우면 구분자가 깨지기 때문.
- 「새 열거형변수」 는 지금처럼 같은 화면의 모달.
- 담보 상세(§15.3)의 급부 탭 값 폼에서는 필수 필드만 서고, 선택 필드(감액기간)는 「+ 필드 추가」 로 넣은 급부에만 값 자리가 생긴다.
  — **MVP 는 이와 다르다**: 선택이 없으니 급부 레벨 마스터 필드가 전부 서고, 안 쓰는 것은 미입력으로 둔다 (§15.3 될 모습).
- 구분자 예: 담보 레벨 `면책구분 = any(보험금지급.면책여부 = 예)` · 급부 레벨 투영 `감액기간문구 = 보험금지급.감액기간`. 문면은 이 둘만 본다.
  — **MVP 의 참조 경로는 `폼.필드` 가 아니라 `레벨.필드`** 다: `any(급부.면책여부)` · `급부.감액기간` (ADR-0037).

> **2026-09-16 왼쪽 칸을 트리 → 표 + 페이저로** (사용자 요청 「코드 조회는 테이블 형태로, 페이징 되게」). 두 칸은 유지하고 왼쪽만 L1 표가 됐다.
>
> ```
> │ 🔍[ 코드 · 표시명 · 폼        ] 〔검색〕 │  ← GET `?q=` (다른 목록과 같은 필터바)
> │ 코드                 표시명    폼      타입              │
> │ waiver.applies       적용여부  납입면제  참거짓           │  ← 행 = 필드 (폼 › 필드를 코드 순서대로 평탄화)
> │ waiver.reasons       납입면제사유 납입면제 목록값(복수) ▸ 납입면제사유 │
> │ …                                                        │
> │ 총 9건 · 1/1                          이전  다음          │  ← ListShell 페이저 · 20행 · 파라미터 `?fp=` (`?page=` 는 오른쪽 값 노드 페이저)
> ```
> - 표시명 셀 → `?field=`, 폼 셀 → `?form=`. 선택된 행은 `aria-current` 강조. 접힘은 사라졌다.
> - 검색 · 페이지 · 선택은 서로를 잃지 않는다 — 상세 안의 링크도 `q` · `fp` 를 실어 보낸다. `fp` 없이 `?field=` 로 들어오면 그 행이 있는 페이지를 편다.
> - 위 「페이저를 두지 않고」 판단(W-E)은 이로써 닫힌다 — 필드가 코드에 고정돼 있어도 늘어나면 한 화면에 안 들어간다.

**무엇인가** — 상품 · 세목 · 담보 · 세부보장 · 급부 다섯 레벨이 **어떤 입력 항목을 받는지** 읽는 화면이다.
값이 아니라 **항목의 목록**이고, 값은 담보 상세(§15.3) · 상품 상세(§20.2) · 상품담보 값(§20.3)에서 채운다.
구분자(§4 ~ §6)의 식이 참조할 수 있는 것이 정확히 여기 있는 것들이라, **식을 쓰기 전에 여는 화면**이기도 하다.

**레이아웃 — L1(조회)에 얹되 필터 · 페이저가 없다.** 1열이 코드(mono)인 표라는 점에서 L1 이고,
항목이 코드에 고정돼 한 화면에 다 들어가므로 **페이저를 두지 않고 컬럼 필터도 두지 않는다** (거를 것이 없다).
필터바 자리에는 검색 하나만 남는다. L2 로 보지 않는 이유는 고칠 것이 하나도 없기 때문이다 — L2 는 값을 만지는 자리다(디자인원칙 §2).
넷째 레이아웃을 만들지 않으려는 판단이고, L1 의 「페이징 · 컬럼 필터」에서 면제하는 것이 맞는지는 열어 둔다 (W-E).

- **조작이 하나도 없다.** 〔+〕 · 〔편집〕 · 〔🗑〕 · ↑↓ 가 없고 값은 전부 민무늬다. 읽기 전용을 형태로 말하는 자리라
  행에 옅은 바탕(`surface-2`)을 깔고 제목 줄 옆에 자물쇠(⌧)를 둔다 (§1.2 — 「⌧ 가 보이면 여기서 못 고친다」).
- **1열은 코드 경로**다 (mono). 화면의 식 · 자동완성이 보여주는 표시명 경로(`세목.납입면제.적용여부`)와 저장되는 코드 경로
  (`plan.exemption.applied`)가 **같은 줄에서 짝지어 읽히는 유일한 자리**다 ([[공통/기술/결정/ADR-0005-코드-표시명-이중체계]]).
  위 그림의 코드는 시드의 표시명에 붙인 **예시**다 — 실제 코드는 구현에서 정한다.
- **묶음 행**(납입면제 · 무저해지 …)은 값 자리가 아니다. 값 자리는 잎(`.applied` · `.reasons`)뿐이고, 묶음은 경로의 한 마디다.
  타입 칸에 「(묶음)」이라 적어 둔다 — 「구조체」는 화면에 쓰지 않는다 ([[공통/화면/화면단어]]).
- **타입 라벨은 화면단어 사전**을 따른다 — 참거짓 · 문자열 · 숫자 · 날짜 · 목록값 · 목록값(복수).
  코드 타입(`boolean` · `string` · `number` · `date` · `enum` · `list<enum>`)은 화면에 안 나온다.
- **열거형변수 칸은 링크**다 → 열거형변수 상세(§10). 값이 데이터라 배포 없이 늘어나는 쪽이 저기다.
- **필드 행을 누르면 사용처 모달**(`UsageDialog`)이 뜬다 — 「이 필드를 읽는 구분자 N」. 거기서 구분자 상세(§6)로,
  구분자 상세의 사용처에서 문면으로 간다. 마스터 필드 → 구분자 → 문면 **두 단계 역방향 조회**가 이 화면에서 시작한다
  ([[기능/구분자/구분자]] 사용처 추적 · [[00_시작/문제정의]] S3).
- **빈 레벨은 지우지 않는다.** 레벨 다섯이 항상 보여야 「여기에는 아직 항목이 없다」가 읽힌다 — 빈 레벨은 EmptyState 한 줄로 둔다.
- 「설명」은 코드가 가진 문서라 유저 메모(「주석」)와 다르다 — 이 화면에서만 **설명**으로 부른다. 사전에 올릴 후보 (「열어 둔 질문」 W-E).
- 들어오는 길은 셋 — 좌측 내비 「입력항목」(§2) · 구분자 생성 · 상세(§5 · §6)의 식 자동완성에서 「입력항목에서 보기 →」 ·
  값 폼(§15.3 · §20.2 · §20.3)의 필드 라벨 ⓘ.

**MVP 마스터의 내용** (ADR-0037 §6 — 시드 `src/db/seed/data/discriminators.json` 가 쓰는 항목 그대로)

| 레벨 | 항목 | 필드 · 타입 |
|---|---|---|
| 상품 | — | 시드 기준 **비어 있다** |
| 세목 | 납입면제 | 적용여부 `참거짓` · 납입면제사유 `목록값(복수)`(열거형변수 납입면제사유) |
| 세목 | 무저해지 | 유형 `목록값`(열거형변수 해약환급금유형) |
| 세목 | 계약전환 | 전환여부 `참거짓` |
| 세목 | 영위업종적용 | 적용여부 `참거짓` |
| 담보 · 세부보장 · 급부 | — | **예정** — 지급률 · 면책여부 · 감액기간 등, 실물 재현 나머지 특약이 요구할 때 코드로 더한다 |

**세목 레벨 마스터 = 세목유형 4종(3차구현)의 구조체**다 — 세목유형 선택지 · 유효 조합을 만드는 장치(상품 상세 §20.2 의 세목 절)는 그대로 두고,
그 세목 노드가 받는 입력 항목만 마스터로 선다.

값 탭(담보 · 세부보장 · 급부)은 좌 목록 + 우 값 폼이다. 담보 탭은 노드가 하나라 좌측 목록이 없다.

```
├──────────────────┬───────────────────────────────────────────────────┤
│ 1 일반상해사망 2/3 │ 일반상해사망 — 값                                   │
│ 2 후유장해    0/3 │  ┌ 납입면제 ─────────────────────────────┐         │
│                  │  │ 면책여부 [ 예 ▾ ]   면제사유 [      ▾ ] │         │
│                  │  └──────────────────────────〔🗑 부착 해제〕┘        │
│                  │  부착 가능    〔+ 갱신여부〕 〔+ 고지유형〕            │  편집 모드에서만
└──────────────────┴───────────────────────────────────────────────────┘
```

- 좌측 목록의 `2/3` 은 「값 자리 3 중 2 입력」 (§9.2 목표 구배).
- **탭 전환은 클라이언트 상태**다 — 탭을 옮겨도 편집 모드와 변경분이 남는다. URL `?tab=` 은 `replaceState` 로 따라만 간다.
- **구조(세부보장 · 급부의 추가 · 삭제 · 순서)는 여기 없다.** 담보를 만들 때 정한다.
- 담보명에 담보속성 값(예: 「상해」)이 섞이면 경고 한 줄이 뜬다 — 막지는 않는다.
- 문면이 없고 편집 모드면 그 자리에서 「문면 제목 [ ] 〔문면 생성〕」이 나온다.

— 될 모습 (값 탭) —

```
├──────────────────┬───────────────────────────────────────────────────┤
│ 1 일반상해사망 2/4 │ 일반상해사망 — 값                                   │
│ 2 후유장해    0/4 │  지급률     [  50 ] %                              │  세부보장 레벨 마스터 필드 전부
│                  │  면책여부   [    ▾ ]                               │  안 쓰는 항목은 미입력으로 둔다
│                  │  감액기간   [      ]                               │
│                  │  감액비율   [      ] %                             │
└──────────────────┴───────────────────────────────────────────────────┘
```

- **그 레벨의 마스터 필드를 전부 그린다** (§14). 마스터 필드는 모든 노드에 항상 있으므로
  **「+ 부착 가능」 · 〔🗑 부착 해제〕 · 폼 이름 머리(`┌ 납입면제 ─┐`)가 전부 없어진다.**
  값 폼은 폼 목록이 아니라 **필드 목록** 하나다.
- 좌측 카운트는 「입력 n / **필드** m」이다 — 부착이 없으니 분모가 「부착 m」에서 「그 레벨의 필드 수」로 바뀐다.
  숫자 자체는 노드마다 같아진다 (같은 레벨이면 필드 수가 같다).
- **안 쓰는 항목이 화면에 남는 것은 감수한다** (ADR-0037). 완결성 경고는 실행 기반이라
  실제 타는 분기가 읽지 않는 미입력은 뜨지 않는다 ([[기능/조립산출/결정/ADR-0016-조립-부분조립-오류좌표]] · [[기능/구분자/구분자]] 값의 존재 규칙).
- 필드 라벨 옆 ⓘ 에 마스터의 설명을 싣고, 누르면 마스터 조회(§14)의 그 행으로 간다.
- 탭 구성(기본 · 담보 · 세부보장 · 급부) · 편집 흐름 · 저장 하나는 **그대로**다 ([[기능/담보/담보]]).

## 18. 문면 저작 (`/documents/<id>`) — L3

전폭 화면. 세로는 바 한 줄 + 남는 높이 하나, 가로는 **196 / 남는 폭 / 360** 이다.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ 일반상해사망 특별약관  특별약관  조 5 · 검증 오류 0 / 노드 87   ← 문면 목록  〔✎〕│  ✎ = 편집 (편집 모드면 ✕ · ✓)
├───────────────┬──────────────────────────────────────┬───────────────────────┤
│ 제1조(보험금)   │            일반상해사망 특별약관         │  사전평가 · 미리보기    │
│ 제2조(지급사유) │                                       │   (읽기 모드)          │
│ 제3조(면책)    │  제1조(보험금의 지급사유)                 │  ─────────────────    │
│ 제4조(준용)    │   ① 회사는 … 〔갱신여부〕 … 【별표 1】 … │  · 조건 가지 판정       │
│ 제5조(소멸)    │     1. …                              │  · 슬롯 값 채움         │
│               │     2. …                              │  · 결과 문면            │
│               │  ┌ when: D0007 = 예 ────────────────┐  │                       │
│               │  │ ② …                             │  │  (편집 모드면 여기가    │
│               │  └─────────────────────────────────┘  │   고른 자리의 폼)      │
│  (조만 싣는다) │            명조 · 44em                 │                       │
└───────────────┴──────────────────────────────────────┴───────────────────────┘
   196px                    남는 폭                              360px
```

- **읽기 모드에는 본문에 조작이 하나도 없다.** 편집 모드에서만 행 오른쪽 끝에 아이콘이 붙는다 —
  `〔✎ 고치기〕 〔↑〕 〔↓〕 〔⧉ 복제〕 〔🗑〕`, 전부 tooltip 이 붙는다.
- 우측 패널은 **모드와 선택에 종속**된다.

| 상태 | 우측 패널 |
|---|---|
| 읽기 | **「사전평가 · 미리보기」** — 설명 한 줄 + 〔미리보기〕 버튼. 누르면 `?view=eval` 로 돌고, 그때부터 버튼이 〔평가 결과 지우기〕가 된다 |
| 읽기 · 평가 후 | 조건식마다 「식 · 참 / 거짓 / 미결(사유) / 오류」 + 「채택 분기: …」, 그 아래 **결과 문면** 한 벌 |
| 읽기 · 보통약관 | 빈 상태 — 「보통약관은 담보 레벨 문맥이 없어 여기서 평가하지 않는다」 + 「상품 조립 미리보기로 →」 |
| 편집 · 선택 없음 | **「문면 전체」** — 안내 한 줄 · 문면 이름 저장 · (담보약관이면) 대응 보통약관 저장〔제안값 — 저장해야 확정〕 · 「여기에 추가」 · 저장 검증 N / 노드 M · 문면 삭제 🗑 |
| 편집 · 노드 선택 | 제목(「제3조(면책)」 + 종류) · 「← 문면 전체로」 · 이동 · 복제 · 삭제 · **그 노드의 폼** + 자리별 「여기에 추가」 |
| 편집 · 조건 가지 선택 | 「조건 가지」 — 조건식 · 가지 안의 「여기에 추가」 · 가지 삭제 |
| 삭제 확인 중 | 확인 카드 하나가 패널을 통째로 차지한다 |

- 「여기에 추가」는 접힌 `<details>` 메뉴다. **고른 자리에 따라 넣을 수 있는 종류가 다르다.**

| 자리 | 넣을 수 있는 것 |
|---|---|
| 문면 전체 | 조 · 관 · 조건 블록 |
| 관 | 조 · 조건 블록 |
| 조 · 조건 블록 안 | 항 · 조건 블록 · 공용조항(조 단위) · 표 · 박스 |
| 항 · 문장 자리 | 문장 · 치환 슬롯 · 문장 안 조건 · 조 참조 · 별표 참조 · 공용조항(문장 안) |
| 항 아래 | 호 · 조건 블록 · 표 · 박스 |
| 호 아래 | 목 · 조건 블록 |

- 모드 · 선택 · 현재 조는 **전부 쿼리**(`?mode=edit&node=…&art=…&view=eval&confirm=…`)다. 클라이언트 상태가 없다.
- 사전평가는 **담보약관(특별약관)에만** 있다 — 보통약관은 담보 레벨 문맥이 없다 ([[기능/조립산출/조립산출]] §3.2 평가 문맥).
  실시간이 아니라 **눌러서 돈다** — 패널의 주 행동이라 아이콘이 아니라 텍스트 버튼이다 (§1.6 예외).
- 목차는 **조만** 싣는다 (§2 L3 — 「목차는 이동 수단이지 구조 설명서가 아니다」).
- **여기서 소유 담보로 가는 길이 없다.** 담보약관을 열어 놓고도 담보 상세로 못 간다 — 문면 *목록*에는 「담보 열기」가 있는데
  저작 화면 상단바에는 「← 문면 목록」뿐이다 (§26).

**될 모습 (ADR-0037) — 문면이 고르는 것은 구분자뿐이다.**

조건식 · 반복 · 치환 슬롯이 참조 대상을 고르는 자리에는 **구분자 목록만** 뜬다. 마스터 필드(`급부.지급률`)를
문면에서 직접 고르는 길은 없다 — 필드 하나를 문면에 내려면 구분자 탭에서 투영 구분자(`감액기간문구 = 급부.감액기간`)를 만든다.

```
│               │  ┌ when: D0007 면책구분 = 예 ──────┐  │  칩은 구분자 코드 + 구분자명으로 읽는다
│               │  │ ② …                           │  │
│               │  └───────────────────────────────┘  │
│               │   ① … 〔D0012 감액기간문구〕 …        │  치환 슬롯도 구분자
│               │                                      │  편집 패널의 조건식 자리:
│               │                                      │   참조 [ 구분자 ▾ ] ← 구분자만 나열
│               │                                      │   〔입력항목에서 보기 →〕 (§14)
```

- 칩의 mono 경로 노출(디자인원칙 §0 「L3 는 구분자 경로를 mono 로」)은 **구분자 코드**를 찍는다. 식(`any(급부.면책여부)`)은
  구분자 상세(§6)에서 본다 — 문면 위에 식을 펴면 문면이 주인공이 아니게 된다.
- 사전평가가 「미결」로 표시하는 자리는 그대로다. 미입력을 참조한 오류 좌표는 이제 **노드 × 마스터 필드**를 가리킨다
  (「상품담보 X 의 급부.지급률 미입력 — 제3조 분기 평가 불능」).

## 19A. 상세 화면 공통 개편안 — 버튼과 편집 흐름

> 2026-09-16 검토안. §20.2 기본정보에서 먼저 검토하며, 이전 화면 기록의 폼별 저장·아이콘 버튼 혼용보다 이 안을 우선한다. 코드는 추가 수정하지 않는다.
>
> **2026-09-19** — 「목록 / 상세」 경로는 원칙으로 확정해 앱 전체에 적용했다: 경로가 곧 제목 줄, 마지막 마디만 진하게, 「← 목록으로」류 링크 제거
> ([[공통/화면/디자인원칙]] §1.7 · `f7c78f4`). 저장 단위는 [[기능/상품/상품]] §3.8 D 안 — 기본정보 탭은 저장 하나, 보통약관 · 특별약관 탭의 명령은 즉시 저장.
> 더보기 메뉴 통일 · 아래 표의 나머지 항목은 여전히 검토안이다.

```text
읽기   목록 / 상세                                     [편집] [더보기 ▾]
       이름과 저장된 내용

편집   목록 / 상세                                         [취소] [저장]
       수정 가능한 입력 · 행 추가
       행을 선택한 경우에만 [선택 삭제]
```

| 대상 | 줄이는 요소 | 수정할 와이어프레임 기준 |
|---|---|---|
| 공용조항 (§17) | 표시명 저장·설명 저장·옵션별 저장 | 이름·설명·옵션을 한 편집 흐름에서 수정하고 상단 저장 하나로 반영 |
| 별표 (§19) | 이름·출력명 칸마다 붙는 저장 | 목록에서는 읽기만, 상세에서 편집/저장. 출력명은 같은 폼의 필드 |
| 상품 기본정보 (§20.2) | 상품명 저장·세목별 저장·조합 등록·상단 조작 나열 | 보험종목 정의/종형 조합 두 탭, 저장 하나, 더보기 메뉴 |
| 상품담보 값 (§20.3) | 레벨별 저장·입력률·별도 되돌리기 카운트 | 같은 상세 프레임. 실제 값과 필요한 필드 조작만 표시 |
| 담보속성 (§21) | 표시명·속성값·명명 조각(현 「상품담보명 표기」)마다 저장 | 속성 상세의 한 편집 흐름에 모으고 상단에서 함께 저장 |

- 같은 동작은 같은 이름과 형태로 표현한다. 확인 없는 삭제 아이콘·체크 아이콘 저장·텍스트 저장을 섞지 않는다.
- 내용이 없는 섹션은 만들지 않는다. 빈 목록에는 안내 한 줄과 필요한 추가 동작 하나만 둔다.
- 페이지 제목·섹션 제목·폼 제목이 같은 말을 반복하면 한 번만 남긴다.
- 편집 중 상위 화면으로 이동할 때 미저장 내용을 조용히 버리지 않도록 한다. 세목의 두 탭 안에서는 입력을 그대로 유지한다.

### 20.2 상세 (`/products/<id>`) — 기본정보 검토안

> **2026-09-16 사용자 코멘트 반영.** 아래는 구현 지시 전 검토할 와이어프레임이다.
>
> **2026-09-16 구현 반영.** 아래 그림대로 구현했고, 실물이 그림과 다른 곳은 다음 넷이다.
> - 상단 경로는 「상품 / 상품 상세」 대신 **「상품 › {상품명}」** — 보통약관·특별약관 탭에서도 어느 상품인지 보여야 해서 꼬리를 상품명으로 둔다 (`.ts-crumb` 관례).
> - 종·형 표기는 앱 전체 관례대로 **「제1종(이름)」** (`planOptionLabel`). 그림의 「1종」은 축약이다.
> - 값 셀의 입력 부품은 마스터 타입을 따른다 — boolean 은 「예/아니오」 라디오, list<enum> 은 체크박스. 그림의 `[미적용 ▾]` 는 예시다.
> - 세목유형 열은 세목 레벨 폼이 둘 이상일 때만 편집 표에 보인다 (새 행만 활성). 하나면 자동.
> 상품명·세목을 한 번에 편집하고 저장한다. 입력률·완결성·진행 막대를 없애고 버튼 수와 형태를 정리했다.

#### 공통 상세 프레임 · 버튼 원칙

- 목록 이동은 상단 경로의 **상품** 링크 하나다. 별도 「목록으로」 버튼을 중복 배치하지 않는다.
- 읽기 상태의 상단 조작은 **편집 · 더보기** 두 개. 미리보기와 상품 삭제는 더보기 메뉴에 둔다.
- 편집 상태에서는 **취소 · 저장**만 표시한다. 같은 자리의 편집 버튼이 저장으로 바뀐다.
- 버튼은 높이 32px·모서리 4px·글자 13px·같은 테두리와 좌우 여백을 사용한다. 주 행동은 강조색만 달리한다.
- 더보기 안의 미리보기·삭제는 같은 높이·정렬의 텍스트 메뉴 항목이다. 링크형·채운 버튼·휴지통 아이콘을 한 줄에 섞지 않는다.
- 표의 각 행에 삭제 버튼을 반복하지 않는다. 편집할 때만 선택 체크박스와 **선택 삭제**를 표시한다.
- 단순 값 입력·조합 체크에 별도 「적용」·「등록」·「저장」 버튼을 붙이지 않는다.
- 위 프레임은 다른 상세 화면의 버튼 정리에도 적용한다. 탭·폼의 상세 배치는 해당 화면 검토에서 정한다.

#### A. 처음 열었을 때 — 읽기 상태

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 상품 / 상품 상세                                  [편집] [더보기 ▾]  │
│                                                     ┌─────────────┐ │
│                                                     │ 미리보기    │ │ ← 펼쳤을 때만
│                                                     │ 상품 삭제   │ │
│                                                     └─────────────┘ │
│ 기본정보       보통약관       특별약관                                │
├─────────────────────────────────────────────────────────────────────┤
│ 상품명   [ 알파Plus보장보험                              읽기 전용 ] │
│                                                                     │
│ 세목                                                                │
│ 보험종목 정의       종·형 조합                                       │
│ ─────────────                                                       │
│ 종·형    보험종목명                              보험료 납입면제     │
│ 1종      보험료납입면제미적용형                  미적용              │
│ 2종      보험료납입면제적용형                    적용                │
└─────────────────────────────────────────────────────────────────────┘
```

- 상품명은 입력창 형태를 유지하되 읽기 전용이다.
- 보험종목 정의에서 이름과 그 종목의 적용 내용을 함께 보여준다. 별도 「세목 선택지 값」 섹션을 만들지 않는다.
- 읽기 상태에는 추가·행 삭제·항목별 저장 버튼이 없다.
- 값이 없는 상품 레벨의 빈 섹션, 선택지 개수·유효 조합 개수·입력률 같은 보조 숫자는 표시하지 않는다.

#### B. 편집 — 화면 전체의 저장 버튼 하나

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 상품 / 상품 상세                                      [취소] [저장]  │
│ 기본정보       보통약관       특별약관                                │
├─────────────────────────────────────────────────────────────────────┤
│ 상품명   [ 알파Plus보장보험                                      ]   │
│                                                                     │
│ 세목                                                                │
│ 보험종목 정의       종·형 조합                                       │
│ ─────────────                                       [보험종목 추가] │
│ 선택  구분   번호   보험종목명                   보험료 납입면제     │
│ □     [종▾]  [1]    [보험료납입면제미적용형]      [미적용 ▾]         │
│ □     [종▾]  [2]    [보험료납입면제적용형  ]      [적용   ▾]         │
└─────────────────────────────────────────────────────────────────────┘
```

- 추가는 빈 초안 행 하나를 만든다. 종·형 구분·번호·이름과 해당 세목유형의 입력을 그 행에서 정의한다.
- 선택 삭제는 행을 선택했을 때만 나타나며, 선택한 행만 초안에서 제거한다. 평소에는 보험종목 추가만 표시한다.
- 화면 위의 저장 한 번이 상품명·종목 정의·세목 값·사용할 조합을 함께 반영한다. 취소는 초안을 버리고 읽기로 돌아간다.
- 저장 오류가 있으면 입력을 유지하고 해당 항목에 안내한다. 실제 저장 완료 뒤 읽기로 돌아간다.
- 저장으로 기존 데이터가 삭제되는 경우에만 삭제 대상·영향을 한 번 확인한다.

#### C. 종·형 조합 탭 — 선택만 하고 마지막에 함께 저장

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 상품 / 상품 상세                                      [취소] [저장]  │
│ 기본정보       보통약관       특별약관                                │
├─────────────────────────────────────────────────────────────────────┤
│ 상품명   [ 알파Plus보장보험                                      ]   │
│                                                                     │
│ 세목                                                                │
│ 보험종목 정의       종·형 조합                                       │
│                     ─────────                                       │
│ 사용     종·형 조합                                                  │
│ ☑        1종 · 보험료납입면제미적용형                                │
│ ☑        2종 · 보험료납입면제적용형                                  │
└─────────────────────────────────────────────────────────────────────┘
```

- 종만 정의했으면 종별 조합, 종과 형을 모두 정의했으면 「1종 · 1형」처럼 조합을 보여준다.
- 사용할 조합을 체크한다. 「조합 등록」 버튼이나 조합별 저장·삭제 버튼은 없다.
- 보험종목 정의 ↔ 종·형 조합을 오가도 초안을 유지한다. 읽기 상태에서는 저장된 조합만 보여준다.

「조립하기/조립 미리보기 →」 상단 강조 버튼 · 「목록으로」 중복 버튼 · 상단 휴지통 아이콘 · 상품명 저장 · 세목별 저장 · 조합 등록 · 완결성/값 자리 카운트 · 입력률 막대 · 내용 없는 상품 레벨 값 섹션.

### 20.3 상품담보 값 (`/products/<id>/coverages/<pcId>`)

> 2026-09-16 검토안: 헤더·버튼은 §20.2 공통 프레임을 적용하고 입력률 표시는 제거한다.

```
┌──────────────────────────────────────────────────────────────────────┐
│ 상품 / 상해사망(기본)                               [편집] [더보기 ▾] │
│ 담보 마스터: 일반상해사망보장 →                                          │
├──────────────────────────────────────────────────────────────────────┤
│ 입력 확인                                                             │
│  · 상해사망 › D0007 · 고치러 가기                                       │  앵커로 그 값 자리까지 간다
├──────────────────────────────────────────────────────────────────────┤
│ 담보 레벨 값        (읽기 기본 · 상단 편집/저장 흐름에 포함)              │
│ 세부보장 — 일반상해사망                                                 │
│    급부 — 사망보험금  (급부 레벨 폼들)                                   │
├──────────────────────────────────────────────────────────────────────┤
│ 상품담보 미리보기   오류 0 / 조 4                                        │
│  (조립된 특약 문면이 명조로)                                             │
└──────────────────────────────────────────────────────────────────────┘
```

값은 **탑재 시점의 스냅샷**이다 — 마스터 값은 필요한 필드에서 확인하고, 별도의 헤더 카운트는 두지 않는다
([[기능/상품/결정/ADR-0002-탑재-값스냅샷]]).

**될 모습 (ADR-0037).** 「담보 레벨 값 (노출 무조건인 담보 레벨 폼들)」이 **「담보 · 세부보장 · 급부 각 레벨의 마스터 필드 전부」**가 된다.

```
├──────────────────────────────────────────────────────────────────────┤
│ 담보 레벨 값                                                           │  마스터 필드 전부 · 부착 UI 없음
│ 세부보장 — 일반상해사망                                                 │
│    급부 — 사망보험금                                                   │
│      지급률  [ 100 ] % ↺  면책여부 [ 아니오 ▾ ]  감액기간 [    ]         │  ↺ = 마스터 값으로 되돌리기
└──────────────────────────────────────────────────────────────────────┘
```

- 값 자리가 **「노드 × 마스터 필드」** 하나로 결정된다 — 폼 이름 · 노출여부 · 부착 관계가 없으니 좌표도 그만큼 짧아진다.
- 스냅샷과 필드별 되돌리기(↺)는 유지한다. 별도의 「되돌릴 수 있는 필드 N」 카운트는 제거한다. 근거는 ([[기능/상품/결정/ADR-0002-탑재-값스냅샷]]).
- 미입력 좌표는 `상해사망 › 급부.지급률` 처럼 **레벨.필드**로 읽힌다 (지금은 `상해사망 › D0007`).
- 이 화면에 서는 레벨은 **담보 · 세부보장 · 급부 셋뿐**이다 — 세목 레벨 마스터 필드(납입면제 · 무저해지 …)의 값은
  상품 상세(§20.2)의 세목 절에서 세목 노드마다 입력한다.

## 23. 그림과 어긋난 것

**§1 ~ §22 의 그림은 `b7c5b55` 의 화면이다.** 그 뒤 화면 QA 1 · 2회차 구현이 `main` 에 들어오면서

「MVP 이후의 그림」으로 남기고 나머지는 걷었다.

**아직 안 맞는 것.** 담보 · 상품 목록에는 최종수정 · 수정자가 없다 — 마스터 스키마에 없는 값이라
화면이 지어내지 않는다. 담보 코드 · 담보분류 · 상태 컬럼도 같은 이유로 비어 있다.

## 25. 공용 조각 지도 — 무엇이 어디까지 퍼졌나

`main` 에 **실제로 있는** 조각과, 그것을 쓰는 화면. 어긋남의 절반은 「조각을 쓰는 화면」과
「손으로 조립한 화면」이 갈린 자리에서 난다.

| 조각 | 무엇 | 쓰는 화면 |
|---|---|---|
| `ListShell` | L1 한 판 — 제목 · 필터바 · 표 · 페이저 · 빈 상태 | 구분자 · 선택지 · 폼 · 담보 · 공용조항 · 문면(둘) · 별표 · 상품 — **목록 9벌** |
| `ListFilterBar` · `ColumnFilter` | 즉시 반영 검색(디바운스 · IME) + 컬럼 헤더 필터 + 칩 + 기준일 | **구분자 · 선택지 · 폼 셋뿐** |
| `EditShell` · `Field` | 읽기 → 편집 → 저장 흐름 · 영향 확인 팝업 · 삭제 | **구분자 상세 · 선택지 상세 · 폼 상세 · 담보 상세 넷뿐** |
| `EmptyState` | 무엇인지 + 예시 + 다음 행동 (§9.3) | `ListShell` 을 쓰는 목록 8화면 |
| `ErrorBanner` | 쿼리로 온 오류 한 줄 | 거의 모든 화면 (19곳) |
| `Confirm` | 잃는 것을 세어 보여주는 확인 카드 (§9.5) | 별표 · 담보속성 · 상품 상세 · 공용조항 상세 · 문면 저작 |
| `ConfirmActionButton` | 같은 확인을 아이콘 버튼 하나로 | 선택지 상세 · 폼 상세 |
| `InfoTip` | 라벨 옆 ⓘ | 구분자 상세 · 폼 상세 · 담보 상세 |
| `ValueForm` · `StructForm`(`@/forms`) | 구분자 값 입력 폼 | 상품 상세 · 상품담보 값 · 담보 상세 |
| `DefaultValueInput` | 타입을 따르는 기본값 입력기 | 구분자 상세 · 폼 상세 |
| `StructCreateForm` | 폼(구조체) 생성 폼 | 새 구분자(폼 종류) · 새 폼 — **같은 폼, 입구 둘.** ADR-0037 뒤에는 **입구가 없다 — 걷힌다** |
| `IssueList` | 오류 좌표 목록 | 상품 상세 · 상품담보 값 · 조립 미리보기 · 공용조항 상세 · 문면 저작 |
| `RenderedDoc` · `StaticTable`/`StaticBox` | 조립 결과 · 표 · 박스를 문서 세계로 | 조립 미리보기 · 상품담보 값 · 문면 저작 |
| `NavLink` | 현재 위치 주칠 | 좌측 내비 · 유형 하위 탭 |

**여기서 바로 읽히는 것 셋** —

1. **즉시 필터는 세 화면뿐이다.** 나머지 목록은 GET 폼이라 Enter(공용조항은 〔적용〕)를 눌러야 한다.
2. **편집 흐름(읽기→편집→저장)을 따르는 화면은 넷뿐이다.** 공용조항 상세 · 상품 상세 · 별표 · 담보속성은
   **폼마다 저장 버튼**이 따로 있는 옛 형태다.
3. 확인 카드가 두 갈래다 — 쿼리로 자리에 펴는 `Confirm` 과 `EditShell` 안의 `<dialog>`.

**될 모습 — 걷히는 조각 · 새로 쓰는 조각** (ADR-0037)

| 조각 | 될 모습 |
|---|---|
| `StructCreateForm` | **걷힌다.** 폼을 만드는 입구가 둘 다 없어진다 (§12) |
| `KindPicker` (새 구분자) | **걷힌다.** 유형 라디오가 없어지고 생성 폼이 하나다 (§5) |
| `DefaultValueInput` | **걷힌다.** 구분자에 기본값 칸이 없고, 마스터 기본값은 코드가 갖는다. 마스터 조회는 읽기 전용이라 입력기를 안 쓴다 |
| `ValueForm` · `StructForm`(`@/forms`) | **남되 입력이 바뀐다** — 「부착된 폼 목록」이 아니라 **그 레벨의 마스터 필드 목록**을 받아 그린다 (§15.3 · §20.2 · §20.3) |
| `ListPage` · `ListFilterBar` | 마스터 조회(§14)가 **검색만** 재사용한다 — 컬럼 필터 · 페이저 없이 |
| `UsageDialog` | 쓰는 자리가 하나 는다 — 마스터 조회의 「이 필드를 읽는 구분자 N」 (§14) |
| `EditShell` · `Field` | 마스터 조회는 **안 쓴다** (편집이 없다). 구분자 상세는 그대로 쓴다 |
| 식 편집기 (신규) | 구분자 생성 · 상세가 같이 쓰는 **mono 입력 + 자동완성 + 저장 시 검사** 한 벌. 지금 `main` 에 없는 조각이다 (§5 · §6) |
| 마스터 트리 (신규) | 레벨 › 묶음 › 필드를 읽기 전용으로 그리는 조각. 자동완성의 후보 목록도 같은 데이터를 읽는다 (§14) |

## 26. 화면을 잇는 길

내비 말고, 화면끼리 직접 잇는 링크만. **막다른 화면**을 찾으려고 그린 것이다.

```
구분자 목록 ─표시명─▶ 구분자 상세 ─「폼 탭에서 편집 →」─▶ 폼 상세
                        │        ◀─「구분자로 보기 →」──────┘
                        │                                  └─선택지─▶ 선택지 상세
                        └─사용처 좌표─▶ 문면 저작 · 공용조항 상세 · 상품담보 값

담보 목록 ─담보명─▶ 담보 상세 ─「담보약관 열기 →」─▶ 문면 저작(L3) ─「← 문면 목록」─▶ 문면 목록
                      ▲                                                          │
                      └────────────────「담보 열기」(담보약관 행)────────────────────┘

상품 목록 ─상품명─▶ 상품 상세 ─「값 →」─▶ 상품담보 값 ─「담보 마스터」─▶ 담보 상세
                      ├─「조립 미리보기 →」─▶ 조립 미리보기 ─오류 좌표─▶ 문면 저작 · 상품담보 값
                      ├─「담보속성 카탈로그 →」─▶ 담보속성
                      └─담보 열 링크─▶ 담보 상세

공용조항 목록 ─표시명─▶ 공용조항 상세 ─사용처 행─▶ 문면 저작
      └─「사용처 N건」─▶ 관계정보 ◀─그래프 노드 클릭─┐
                          └──────────────────────┘   (조회 대상이 바뀌며 제자리 순환)
```

**될 모습 — 구분자 ↔ 폼 왕복이 끊기고, 입력항목이 그 자리에 선다** (ADR-0037)

```
입력항목 (마스터 조회, §14) ─필드 행─▶ 〔사용처 모달〕 ─「이 필드를 읽는 구분자 N」─▶ 구분자 상세
        ▲          └─열거형변수 칸─▶ 열거형변수 상세
        │
        └─식 자동완성의 「입력항목에서 보기 →」── 구분자 생성 · 구분자 상세
                                                      └─사용처 좌표─▶ 문면 저작 · 공용조항 상세 · 상품담보 값

담보 상세 · 상품 상세 · 상품담보 값 ─필드 라벨 ⓘ─▶ 입력항목의 그 행
```

- **걷히는 길 둘** — 구분자 상세의 「폼 탭에서 편집 →」과 폼 상세의 「이 폼을 구분자로 보기 →」. 폼이라는 실체가 없어져 왕복할 곳이 없다.
  `/catalog/<폼코드>` → `/types/forms/<코드>` 리다이렉트도 같이 걷힌다.
- **새 화면의 진입 경로 셋** — ① 좌측 내비 「입력항목」(제안, §2) ② 구분자 생성 · 상세의 식 자동완성에서 「입력항목에서 보기 →」
  ③ 값 폼(담보 상세 · 상품 상세 · 상품담보 값)의 필드 라벨 ⓘ.
- **나가는 길 둘을 처음부터 갖춘다** — 필드 → 구분자(사용처 모달) · 필드 → 열거형변수 상세.
  「들어오는 길이 내비뿐인 화면」(별표 · 담보속성)을 하나 더 만들지 않으려는 것이고, W-D 를 그만큼 덜 남긴다.
- 「선택지 상세 · 폼 상세의 사용처가 글자다」(아래 표)에서 **폼 상세 줄은 사라진다.** 마스터 조회가 그 자리를 모달로 받는다.

- 오류 · 깨질 참조 좌표는 `coordinateHref` 한 곳이 링크를 만든다 — **문면 저작(`?node=`) · 공용조항 상세 · 상품담보 값**.
  좌표가 소유 실체를 모르면 링크를 만들지 않는다 (아는 만큼만 채워지는 좌표 — [[기능/조립산출/조립산출]] §3.4 오류 좌표).

**막다른 화면 · 끊긴 길** (전부 코드에서 확인한 것)

| 자리 | 무엇이 없나 |
|---|---|
| 문면 저작 (§18) | **소유 담보로 가는 링크가 없다.** 상단바는 「← 문면 목록」뿐 — 문면 *목록*에는 「담보 열기」가 있는데 저작 화면엔 없다 |
| 별표 (§19) | 화면 밖으로 나가는 링크가 **하나도 없다.** 사용처도, 어느 상품이 이 별표를 싣는지도 안 보인다 |
| 담보속성 (§21) | 마찬가지로 나가는 링크가 없다. 들어오는 길은 상품 상세의 「담보속성 카탈로그 →」 하나 |
| 담보 상세 (§15.3) | 「탑재 상품담보 N」이 **글자다** — 그 상품담보로 못 간다 (구분자 상세의 사용처 좌표는 링크인데) |
| 선택지 상세 (§10) · 폼 상세 (§13) | 헤더의 「사용처 N」이 글자다 — 쓰는 곳으로 못 간다 (폼 상세는 걷힌다 · 마스터 조회는 모달을 갖는다 — 위 될 모습) |
| 관계정보 (§22) | 들어오는 길이 **공용조항 둘뿐**이다. 구분자 · 별표 · 담보 화면에는 「관계정보 →」가 없다 |

**들어오는 길이 내비뿐인 화면** — 별표 · 담보속성.

## 열어 둔 질문

- [ ] **W-A. 이 문서를 언제 다시 그리나.** 화면이 바뀔 때마다 손으로 고치면 곧 어긋난다.
      후보 — ⓐ 화면 QA 회차마다 갱신 ⓑ 화면기획이 실물을 따라잡으면 이 문서는 폐기 ⓒ 그대로 둔다.
- [ ] **W-B. 화면기획 없는 화면(§24)의 우선순위.** 문면 저작(L3)이 가장 크고 가장 안 적혀 있다.
- [ ] **W-C. 상품 상세를 한 화면으로 계속 둘 것인가** (§20.2). 섹션 아홉이 세로로 쌓여 있고
      레이아웃 유형 셋(§2) 중 어디에도 속하지 않는다.
- [ ] **W-D. 끊긴 길(§26)을 어디까지 이을 것인가.** 문면 저작 → 담보, 담보 상세 → 상품담보,
      별표 · 담보속성의 사용처처럼 「여기서 쓰는 곳으로」가 없는 자리가 여섯이다.
      사용처를 모달로 내는 규칙(화면QA_이력 R9)이 이미 있으니 같은 조각으로 닫을 수 있다 —
      다만 어느 화면까지 사용처를 붙일지는 정해진 바 없다.
- [ ] **W-E. 마스터 조회의 경로 · 내비 이름 · 레이아웃** (§14). 이 문서는 경로 `/master` · 내비 「입력항목」 ·
      「L1 에 얹되 필터 · 페이저 없음」을 **제안**만 했다 — ADR-0037 열린 문제 그대로다.
      딸린 것 셋 — ⓐ 내비에서 유형 아래인가, 1층이 먼저 읽히게 맨 위인가 ⓑ L1 의 페이징 · 컬럼 필터 규칙에서 면제하는 것이
      디자인원칙 §2 의 「넷째 유형」에 해당하는가 ⓒ 마스터 필드의 「설명」을 화면단어 사전의 「주석」과 가를 것인가.
- [ ] **W-F. 구분자 목록에 식 컬럼을 세울 것인가** (§4). 지금 될 모습은 안 세운다 — 남는 폭을 구분자명이 먹는다(디자인원칙 §2 L1).
      식이 안 보이면 목록에서 구분자를 고르기 어렵다는 말이 나오면 그때 결정한다 (후보: 구분자명 아래 한 줄 · hover tooltip · 별도 컬럼).
