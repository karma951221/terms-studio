## 상세 화면 버튼 정리 — 2026-09-16 검토안

[[공통/화면/와이어프레임]] §20.2를 기본정보 개편 검토안으로 사용한다.

- 읽기 화면에는 편집·더보기만 둔다. **목록 이동은 경로**(2026-09-19 확정 → §1.7 · 앱 전체 적용 `f7c78f4`), 미리보기·삭제는 더보기 메뉴에 모은다(상품 상세만 적용 · 나머지는 검토안).
- 편집 중에는 같은 자리에 취소·저장을 둔다. 저장은 화면 전체에 하나다.
- 같은 조작군은 높이·테두리·모서리·글자·여백을 통일한다. 삭제만 휴지통 아이콘으로 따로 표현하지 않는다.
- 반복 제목·입력 없는 섹션·입력률·진행 막대·행마다 붙는 저장/삭제를 줄인다. 오류는 항목 옆에 표시한다.
- 보험종목 이름과 적용 내용을 함께 보여주고, 추가·선택 삭제는 편집 중에만 드러낸다.
- 먼저 와이어프레임을 검토한다. 이 검토안만으로 추가 코드 작업을 시작하지 않는다.

## 0. 한 문장

> **값이 어디서 왔는지 항상 보인다.**

모든 색·타이포·레이아웃·모션 결정은 이 문장에 복무한다. 복무하지 않는 결정은 뺀다.
근거는 [[00_시작/문제정의]] S3 — 「값 하나를 짚으면 어디서 결정됐는지 답이 하나로 나온다」.

방향의 이름은 **조판실(組版室)** 이다. 정밀한 사무 도구이되, 주인공은 만들어지는 문서다.

> 어디서 지켜지나 — **L2(수정)가 주 담당**이다. 값을 만지는 자리가 거기이기 때문이다.
> L3(저작)에는 별도 출처 검사 패널을 두지 않는다(2026-08-30 결정). 대신 L3는
> 조건식과 치환 슬롯이 참조하는 **구분자 경로를 mono 로 노출**하는 것으로 역할을 다한다.

## 1. 이 도구가 지켜야 할 조작 원칙

### 1.1 두 개의 타이포 세계 — 시스템 전체를 가르는 단 하나의 규칙

| | 도구 세계 | 문서 세계 |
|---|---|---|
| 어디 | 폼 · 테이블 · 트리 · 필터바 | 에디터 본문 · 미리보기 |
| 글꼴 | **맑은 고딕** | **명조** (Noto Serif KR) |
| 크기 / 행간 | 13px / 1.6 | 15px / **1.9** |
| 밀도 | 빽빽 (행 28px) | 넉넉 (측정폭 42~44자) |
| 성격 | 도구처럼 생겼다 | 책처럼 생겼다 |

경계는 **패널 경계**다. **미리보기는 앱 스킨을 입지 않는다.**

> 왜 — 산출물이 인쇄되는 약관 책자이고, 목적은 「유저가 약관 생성 결과를 이해하고
> 따라갈 수 있을 것」([[00_시작/문제정의]])이다. 결과물이 늘 결과물처럼 보여야 한다.
> CMS·내부도구 계열은 정확히 반대로 한다(미리보기가 앱 스킨을 입는다) — 거기를 따라가지 않는다.

2026-08-30 프리뷰에서 검증했다. 명조 미리보기와 고딕 도구 패널이 한 화면에 있어도 싸우지 않는다.
다크에서도 유지된다 — 두 세계의 구분은 **색이 아니라 타이포와 여백**이 하는 일이기 때문이다.

### 1.2 테두리가 없으면 못 고친다 — 값의 출처 문법

출처 3층([[00_시작/도메인모델]] §2)에 색을 주지 않는다. 색은 조건 분기·에러와 충돌하고,
곧 색 수프가 된다. **출처는 전적으로 형태가 말한다.**

| 출처 | 표현 |
|---|---|
| **직접값** (모델링 화면에서 사람이 정함) | 실선 테두리 입력 필드 |
| **파생값** (식으로 계산) | 테두리 없음 + 옅은 바탕 + 좌측 `ƒ` 표식 + 식 노출. 클릭하면 부착점으로 이동 |
| **const** (마스터 소유) | 테두리 없음 + 옅은 바탕 + 자물쇠 + 마스터 링크 |
| **스냅샷 · 마스터와 다름** (지금 마스터 값과 다른 명시 값) | **입력 필드 오른쪽 끝에 「현재 마스터 값 가져오기」(↓) 아이콘 버튼** — 편집 모드에서만. 마스터 값은 **tooltip 으로만** 준다 |
| **제안** (기본값 프리필, 저장 전) | 실선 테두리 + **옅은 글자** + 필드 오른쪽 끝 **「제안」 칩**. 손대면 보통 글자가 되고 칩이 사라진다 (§9.1) |

이 문법은 **값 레벨에서 끝나지 않는다.** 문서 레벨의 잠금(담보약관 `확정`)도 같은 자물쇠(⌧)를
쓴다(§2 L1) — 「⌧ 가 보이면 여기서 못 고친다」 하나만 배우면 값이든 문서든 통한다.

읽기전용에 **옅은 바탕**(`surface-2`)을 까는 이유 — 바탕 없이 두면 「빈 칸」으로 읽혀서
화면이 미완성처럼 보인다 (2026-08-30 프리뷰에서 확인). 바탕이 있으면 「잠긴 칸」으로 읽힌다.

**스냅샷 차이를 색으로 표시하지 않는 이유** (2026-08-30 개정) —
색은 「달라졌다」까지만 말하고 끝나지만, 가져오기 버튼은 **맞추는 방법을 그 자리에 준다.**
같은 자리에서 더 많은 일을 하므로 색 표시를 대체한다. 좁은 필드에서도 성립한다(20×20 아이콘 + tooltip).

**마스터 값을 helper text 로 깔지 않는다** (2026-08-30 결정) — 필드마다 한 줄이 더 붙으면
L2 의 「한눈에」가 무너진다. 가져오기 버튼 tooltip 에 넣는다 (「현재 마스터 값 가져오기 · 마스터 90 · 이 값 80」).

**「되돌리기」는 없다 — 명령은 셋이다** (2026-09-14, [[기능/상품/상품]] §3.4).
탑재 당시 값은 어디에도 남아 있지 않으므로([[기능/상품/결정/ADR-0002-탑재-값스냅샷]] — 값 복사는 탑재 한 번뿐) 「되돌릴」 과거가 없다.
스냅샷 값에 할 수 있는 일은 —

| 명령 | 결과 | 어디서 |
|---|---|---|
| **미저장 변경 취소** | 편집 중 고친 것 전부를 마지막 저장 상태로 | 화면의 ✕ (§2 L2) |
| **값 비우기** | 명시 값 → 미입력 | 편집 모드, 필드 단위 |
| **현재 마스터 값 가져오기** | **지금** 마스터 값을 필드에 채운다 (80 → 90). 누르면 그 자리에서 「이 값 80 → 마스터 90」 을 보여 주고 채운다 | 편집 모드, 필드 단위 ↓ 아이콘 — 마스터와 다른 필드에만 |

셋 다 **편집 중 변경**이라 저장에 포함되고 ✕ 로 되돌아간다 — 그래서 **확인 팝업이 없다**. 2026-08-30 에 「되돌리기는 확인 팝업을 거친다」고 했던 것은 저장 흐름 밖의 즉시 실행이었기 때문이고,
저장 흐름 안으로 들어온 지금은 §1.5(마찰은 되돌릴 수 없는 곳에만) 가 팝업을 뗀다.
헤더의 카운트는 **「마스터와 다른 필드 N」** — 세는 것은 지금 마스터 값과 다른 명시 값의 수(실물 `snapshotDrift` 그대로). N 을 누르면 그 목록(자리 · 이 값 · 마스터 값)에서 골라 가져온다.
가져온 뒤 저장하면 아이콘이 사라지고 N 이 줄어든다.

상품담보 화면 머리에는 소유를 한 줄로 — **「값은 탑재 시점의 복사본이다 · 문면 · 구조 · 이름은 지금 마스터를 따른다」** ([[기능/상품/상품]] §3.4 소유).

### 1.3 색은 강조와 현재 위치만 가리킨다

주칠(`mark`)은 **활성 탭 · 포커스 · 섹션 번호 · 카운트**에 쓴다.
브랜드 컬러가 아니고, **상태를 대신 말하지도 않는다** — 상태는 §1.2대로 형태가 말한다.

따름 — **파란 액센트를 쓰지 않는다.** 브랜드 컬러로 쓸 색을 시스템에 두지 않는다.

> 2026-08-30 개정 이력 — 처음에는 주칠의 뜻을 「사람이 손댐」으로 뒀으나,
> §1.2에서 그 역할을 스냅샷 자리의 아이콘 버튼(당시 「되돌리기」, 지금은 「현재 마스터 값 가져오기」)이 가져가면서 근거가 사라졌다. 액센트로 격하했다.
> 부수 효과: `mark`↔`error` 색 충돌(§10 Q1)의 위험도가 내려갔다 — 둘이 같은 의미장을 다투지 않는다.

### 1.4 밀도는 도구 쪽에만 적용된다

실무자가 하루 종일 쓰는 도구다. 도구 세계는 빽빽하게 간다 (행 28px, 폰트 13px).
**문서 세계는 이 규칙 밖이다** — 여기서 밀도를 올리면 §1.1이 깨진다.

### 1.5 마찰은 되돌릴 수 없는 곳에만 둔다

중복 채번은 사후에 못 지운다([[00_시작/문제정의]]) → **채번 순간에만 마찰을 둔다.**
나머지 조작은 마찰 없이 간다. 확인 다이얼로그를 습관적으로 붙이지 않는다.
같은 이유로 **저장 전의 조작에는 확인을 두지 않는다** — 값 비우기 · 마스터 값 가져오기 · 행 삭제는 ✕ 로 되돌아가므로 잃는 것이 없다(§1.2 · §2 L2).
확인은 잃는 시점에 한 번이다 — 저장 시 소실이 생기면 저장이 묻고(§9.5), 저장 흐름 밖의 즉시 실행 명령은 실행 전에 범위를 보인다(§2 L2 저장 단위).

### 1.6 조작은 아이콘 버튼으로. tooltip 은 의무다

밀도가 이 도구의 제약이다(§1.4). 텍스트 버튼은 자리를 많이 먹고, 한 화면에 여럿 놓이면
문면·폼보다 버튼이 먼저 눈에 띈다. **조작은 22×22 아이콘 버튼을 기본으로 한다.**

- **tooltip 없는 아이콘 버튼은 없다.** 무엇을 하는지 + 대상까지 적는다
  (예: 「현재 마스터 값 가져오기 · 마스터: 수술비(1~7종, 연간3회한)[상해] = 90 · 이 값 80」)
- 파괴적 조작은 `.danger` — 평소엔 뉴트럴이고 hover 에서만 `error` 로 물든다
- **글리프를 문자로 쓰지 않는다. 그린다** (2026-08-30 결정). 맑은 고딕에 없는 기호
  (`⌧` 자물쇠 · `⧉` 복사 등)는 심볼 폰트로 폴백돼 굵기·크기·베이스라인이 주변과 어긋난다.
  같은 줄의 CSS 로 그린 사각형 옆에 두면 그 하나만 다른 폰트처럼 보인다.
  **인라인 SVG** 또는 **SVG 마스크 + `currentColor`** 로 그린다 — 색은 상속되고 렌더는 어디서나 같다.
  이 함정에 2026-08-30 하루에 두 번 빠졌다(복사 아이콘, 자물쇠)
- **예외 둘** — ① 패널의 주 행동(L3 「미리보기」 실행 버튼)은 텍스트를 유지한다.
  아이콘으로 바꾸면 그 패널에서 무엇을 해야 하는지가 사라진다
  ② **확인 팝업 안의 버튼**(「저장하지 않고 나가기」·「계속 수정」·「삭제하고 참조 4건 끊기」)은 텍스트다. 확인을 아이콘으로 물으면 확인이 아니다

### 1.7 경로 — 상세 화면의 위치와 나가는 길 (2026-09-19)

**상세 화면(L2 · L3)은 몇 단계를 파고들든 경로가 곧 제목 줄이다** — `조회 › 상세1 › 상세2`.
앞 마디는 상위 화면으로 가는 링크(옅게), **마지막 마디(현재 화면)만 진하게 · 링크 아님**. 제목을 따로 두지 않는다.
결정과 버린 대안은 §11.2 결정 메모.

```
담보 › 골절진단비Ⅱ                              [편집] [🗑]
상품 › 알파Plus보장보험 › 일반상해사망보장(상품담보)
상품 › 알파Plus보장보험 › 미리보기
구분자 › 새 구분자                                  [생성]
```

- **첫 마디 = 상단 내비의 그 화면 이름**(담보 · 상품 · 구분자 · 폼 …). 「담보 목록」이 아니다. **조회 화면(L1)에는 경로가 없다** — 상단 내비의 현재 위치 표시(§1.3)가 그 역할.
- **상세 마디는 실체 이름.** 코드는 마디가 아니라 옆의 메타(mono). 편집 중에는 고치고 있는 이름을 따라간다.
- **돌아가는 길은 경로 하나.** 「← 목록으로」류 링크 · 화면 아래 돌아가기 링크를 두지 않는다.
- **탭은 단계가 아니다.** 상세2 에서 상세1 마디를 누르면 왔던 탭으로.
- **편집 중이면 경로 링크도 ✕ 와 같은 「저장하지 않은 변경 사항이 있습니다」 확인**을 거친다 (§2 L2 Q10). 확인은 화면 위쪽에 뜨는 모달이다 — 폼 아래에 붙으면 눈에 안 띈다(2026-10-01). 고친 것이 있을 때만 묻는다. 탭이 URL 이라 탭을 옮기면 초안이 사라지는 화면(상품 상세)은 탭 링크도 같다.
- 새로 만들기 「담보 › 새 담보」 · 못 찾음은 같은 경로(꼬리는 id) + 오류 배너 · 저작(L3) 바도 「담보약관 템플릿 › {제목}」(바의 글자 규격).

구현: `Breadcrumb`(`src/app/_components/Breadcrumb.tsx`) — `EditShell.path` · `CreateHead.path` 가 앞 마디를 받고 꼬리는 제목이다. CSS `.ts-path` · `.ts-crumb` · `.ts-crumb-current`.

### 1.8 참조 고르기는 검색 입력(콤보박스) 하나로 (2026-09-28)

**다른 실체를 가리키는 칸(별표 · 공용조항 · 구분자 · 담보 · 상품담보 · 템플릿 · 조 · 열거형 …)은 모두 같은 검색 입력으로 고른다** — 치면 좁혀지고 고르면 코드가 실린다.
항목이 늘면 `<select>` 는 훑어야 하고 타이핑으로 못 좁힌다(별표 참조 넣기 피드백). 결정과 버린 대안은 §11.2 결정 메모.

- **이름으로 보이고 코드로 실린다.** 줄은 「이름 ․ 흐린 코드」, 이름 · 코드 · 별칭 어디에 맞든 걸리고 **맞은 글자를 강조**한다. 띄어 친 낱말은 모두 맞아야 한다. 없으면 「일치하는 항목 없음」.
- **고르기 전엔 값이 그대로.** 친 글만 남기고 떠나면 원래 이름으로 돌아온다. 첫 항목을 미리 고르지 않는다 — 필수 칸은 비어 있으면 제출이 막히고, 팝업은 「…를 고른다」로 안내한다.
- **키보드:** ↑ ↓(끝에서 돌아감) · Home End · Enter 고르기 · Esc 목록 닫기 → 친 글 되돌리기 → 팝업 닫기 순 · Tab 닫고 다음 칸.
- **묶음 · 못 고르는 줄**은 목록 안에서 말한다 — 묶음 머리(예: 조건 변수의 「현재 행」 · 노드마다 · 담보속성), 못 고르는 줄은 흐리게 + 사유.
- **후보 출처:** 화면이 이미 받은 목록이면 화면에서 거르고, 계속 느는 마스터(상품담보 탑재의 담보)는 **서버에서 찾는다** — 250ms 기다렸다 마지막 검색어만, 앞 요청은 취소, 50건 넘으면 「더 있다 — 더 쳐서 좁힌다」.
- **여럿을 고르는 트리**(조 참조 대상)는 콤보박스가 아니라 트리 위에 검색칸을 두고 **같은 거르기 · 강조**를 쓴다 — 맞는 줄과 조상만 남기고 편다.
- **그대로 두는 `<select>`:** 몇 안 되는 고정 선택지와 값 고르기 — 연결어 · 범위 · 구조 표기 · 행 반복 · 결합 · 연산자 · 참/거짓 · 종·형 · 세목유형 · 담보속성 값 · 옵션 선택지 · 조회 필터. 크기 · 테두리 · 모서리는 검색 입력과 같다(같은 조작군).
- 툴바 「공용조항」의 버튼 아래 작은 메뉴(모달 없이 한 번에 넣기)는 메뉴라 그대로 둔다 — 팝업의 공용조항 칸은 검색 입력.

구현: `Combobox`(`src/app/_components/Combobox.tsx`) · 규칙은 순수 함수 `comboModel.ts`(거르기 · 강조 · 키 · 서버 조회기). 폼 칸이면 `name`(숨은 칸), 값 고르기면 `value` + `onChange`,
서버 조회는 `load(query, signal)` 또는 서버 컴포넌트용 `lookupUrl`(GET `?q=` → `{ options, more }`, 예: `/api/lookup/coverages`). 편집 화면 `Field` 는 `type="combo"`. CSS `.ts-combo*`.

## 2. 레이아웃 — 유형 3개가 전부

새 화면은 반드시 이 셋 중 하나에 배정된다. 넷째 유형이 필요하면 그건 결정 사항이다 → [[README]].

### L1 · 조회

```
┌────────────────────────────────────────┐
│ 검색 + 필터 바        (상단 고정, sticky) │
├────┬───────────────────────────────────┤
│코드│ 이름 · 속성들 …                     │
├────┴───────────────────────────────────┤
│ 페이지네이션 + 총 건수      (하단 고정)   │
└────────────────────────────────────────┘
```

- 필터바는 **스크롤해도 안 사라진다**. 필터 항목은 **표의 컬럼과 일치**시킨다 —
  거를 수 있는 것과 보이는 것이 어긋나면 사용자가 왜 안 걸리는지 모른다
- **1열은 항상 조회대상의 코드**. mono, 고정폭 104px — 코드는 식별자이므로 코드처럼 보인다
  — 예외 (2026-09-27): 행을 묶는 기준 열이 있으면 그 열이 앞에 선다. 구분자 조회는 **레벨**(깊이순 정렬, [[기능/구분자/결정/ADR-0070-dict구분자-구조읽기규칙-반복표-담보문서-MVP]] 개정) · 마스터는 **폼**(연속 행 병합, [[기능/마스터/마스터]] §4.1)
- 테이블은 **페이징**. 무한 스크롤 안 쓴다 (몇 건 중 몇 번째인지가 늘 보여야 한다)
- **얼룩무늬(zebra) 안 쓴다** — 괘선 하나로 충분하고, 없애면 행 높이를 줄일 수 있다
- 숫자 열은 우측 정렬 + `tabular-nums` → §10 Q3

**제목 줄은 제목 + 오른쪽 `+` 뿐이다** (2026-09-27 UI 검토 결정)

```
{화면 이름} ⓘ                                         [+]
```

- **개수를 제목 옆에 두지 않는다** — 「폼 4 · 필드 5」류. 페이저가 이미 「총 N건」을 보인다(§9.6 「조회 목록의 총 건수와 페이지 정보는 유지」는 페이저 자리 얘기다).
- **설명이 꼭 필요하면 제목 옆 ⓘ InfoTip** 에 한 줄. 제목 아래 안내 문장 줄을 두지 않는다.
- **하위 탭은 둘 이상일 때만.** 탭이 하나면 탭 줄을 지운다. 탭 줄은 제목 줄 아래 — 담보속성은 탭이 둘이라 선다. 탭 화면의 상세 · 새로 만들기의 경로 첫 마디도 내비 이름이다(§1.7). 탭은 한 기능 안의 갈래다 — 기능이 다르면 탭으로 묶지 않고 내비 그룹 아래 메뉴를 따로 세운다(「기본정보」 = 열거형 · 폼 · 구분자).
- 관계정보의 통계는 제목 줄로 올리지 않고 **본문 첫 줄**에 그대로 둔다.

**마스터 목록은 탑재분을 행으로 펼치지 않는다** (2026-08-30 결정)

담보 조회는 **담보 마스터**의 목록이다. `일반상해사망보장` 과 `일반상해사망보장 추가`,
`수술비` 와 `갱신형 수술비` 는 [[00_시작/도메인모델]] 대로 **같은 담보의 탑재 차이(담보속성)** 이지
별개 담보가 아니다. 두 행으로 늘어놓으면 목록이 마스터가 아니라 탑재분 목록이 된다.

따름 — **담보코드는 담보 마스터에만 있다.** 담보 마스터 `COV000001`(시스템 채번 · 옛 시스템과 같은 모양, 2026-09-27 — [[기능/담보/담보]] §3.1).
상품담보(탑재분)는 제 코드를 갖지 않고 **담보코드 + 담보속성 조합**으로 가른다(상품모델링 탑재 표, [[기능/상품/상품]] §4.5) —
「담보는 하나인데 탑재분마다 담보 코드가 있다」는 모순이 화면에 남지 않는다. (2026-08-30 의 접두 안 `CVR-` / `PCV-` 는 버렸다.)

**담보 조회의 컬럼** (2026-08-30 결정)

| 컬럼 | 비고 |
|---|---|
| 코드 | mono 고정폭 |
| 담보명 | **가변 — 남는 폭을 여기 하나만 먹는다** |
| **담보분류** | **담보 레벨 enum 구분자** (2026-08-30 확정). 상해 · 질병 · 상해및질병 · 비용손해 · 재물손해 · 배상책임 |
| **상태** | 미사용 · 적용 · 확정 |
| 최종수정 | mono |

세부보장 · 급부 · 탑재 수는 컬럼으로 두지 않는다 — 목록에서 판단에 쓰이지 않는다.

**남는 폭은 한 컬럼만 먹는다** (2026-08-30 결정). 고정 컬럼에만 폭을 주면 auto 테이블 레이아웃이
남는 폭을 **모든 컬럼에 나눠 준다** — 상태 컬럼이 82px 요청인데 240px 로 벌어져, 값과 다음 컬럼
사이가 텅 비고 hover 시 행이 끊겨 보였다. 가변 컬럼(담보명) 하나에 `width:100%` 를 주고
나머지는 `th`·`td` 양쪽에 폭을 박는다. 그러면 오른쪽 컬럼들이 서로 붙는다.

**enum 필터의 선택지를 화면에 박지 않는다** (2026-08-30 결정). 담보분류는 구분자이므로
유효값은 **구분자 정의에서 읽어 온다**. 값이 늘 때 화면 코드를 고쳐야 하면
[[00_시작/문제정의]] S1(구분자 추가에 코드를 안 건드린다)이 화면에서 깨진다.

### 담보 상태 — 미사용 · 적용 · 확정 (2026-08-30 확정 → 2026-09-14 MVP 이후로 유예)

> **2026-09-14 MVP 이후로 유예** — 담보 마스터에 상태를 두지 않는다([[기능/담보/결정/ADR-0075-담보구조정정-상세편집하나-저장시영향확인]] §담보 상태).
> 「탑재 가능 · 작업 중」은 실제 탑재 상태와 조립 검사 결과로 안내하고, 「확정(더 못 고침)」은 ADR-0026 작업본/확정이 MVP 이후에 맡는다.
> 아래 글리프 3종은 그때 다시 본다.

| 상태 | 뜻 | 상품모델링 탑재 조회 | 담보약관 수정 |
|---|---|---|---|
| **미사용** | 작업중이다 | **안 잡힌다** | 가능 |
| **적용** | 초안이 완성됐다 | 잡힌다 | 가능 |
| **확정** | 더 이상 못 고친다 | 잡힌다 | **불가** |

`미사용 → 적용 → 확정` 순서로 무거워진다. 확정으로 바꾸는 것은 권한이 갈리지만
**MVP 는 권한 분리를 다루지 않는다**.

**상태는 색이 아니라 글리프로 말한다** (§1.3 준수). 7px 사각형에서 자물쇠로, 무게가 올라간다:

| | 글리프 | 색 |
|---|---|---|
| 미사용 | 파선 빈 사각 `⊡` | `ink-3` |
| 적용 | 채운 사각 `■` | `ink-2` |
| 확정 | **자물쇠 `⌧`** | `ink` |

확정에 **const 필드와 같은 자물쇠**를 쓴다 — 이 시스템에서 ⌧ 는 이미 「여기서 못 고친다」를
뜻한다(§1.2). 값 레벨의 잠금과 문서 레벨의 잠금이 같은 글리프를 쓰면 배울 것이 하나로 준다.

미사용 행을 통째로 죽이지 않는다 — 미사용은 폐기가 아니라 **작성자가 지금 붙잡고 있는 것**이다.
글리프만으로 「아직 탑재에 못 쓴다」가 전달된다.

### L2 · 수정

유일한 제약은 **「한눈에」** 다. 여기서 나오는 것들 —

- **2열 필드 그리드.** 라벨은 좌측 고정폭 **120px**, 값은 우측.
  라벨을 값 위에 두지 않는다 — 세로 길이가 두 배가 되고 「한눈에」가 깨진다
  - 라벨은 행의 **위쪽**에 맞춘다 (2026-09-12). 값이 표 · 여러 줄이면 가운데 정렬은 라벨을 값 중간에 띄운다.
    한 줄 값 옆에서도 첫 줄과 나란해야 하므로 라벨에 입력칸 높이만큼의 위 여백을 준다.
  - **생성 폼은 내용 영역 폭의 절반**을 쓴다 (2026-09-12). 고정 px 로 잡으면 넓은 화면에서 왼쪽 구석에 뭉친다.
- `list<T>` 표 필드와 긴 텍스트만 **전폭**(colspan 2)
- 섹션은 **카드가 아니라 괘선 + 섹션명**
- **접기 없음. 한 객체의 필드를 탭으로 나누지 않는다.**
  - **접기의 예외** (2026-10-01 사용자 결정) — 본문이 주인공인 저작 화면(함수조항 상세)의 기본정보는 접히는 구획이다 — 접힌 줄 = 코드 · 이름, 열림은 브라우저가 기억 ([[기능/함수조항/함수조항]] §4.3).
  - **탭 분할의 예외** (2026-09-06 개정) — 한 화면이 **층이 다른 객체 여럿**을 담을 때(담보 상세: 구조 + 담보 · 세부보장 · 급부
    레벨별 값)는 **객체(층) 단위 탭**으로 가른다. 세로로 다 쌓으면 구조가 안 보인다는 것이 2026-09-06 담보 QA 의 결론.
    탭을 옮겨도 편집 모드 · 변경분은 유지되고 저장은 하나다. 첫 적용 [[기능/담보/담보]]
- 행 높이 28px 기준 → 한 화면에 필드 40개가 스크롤 없이 들어간다
- 헤더에 「마스터와 다른 필드 N」을 표시 (§1.2 · 스냅샷 화면만)
- **값의 출처를 보는 자리가 여기다** (§0)

**편집 흐름 — 읽기 모드가 기본이다** (2026-09-06 확정, 앱 전체의 수정 화면에 적용)

```
읽기 ──[편집]──▶ 편집 ──[저장 (변경 있을 때만 활성)]──▶ 저장 중(전부 disabled) ──▶ 읽기
                  └──[✕ 취소]── 변경 있으면 확인 팝업(Q10) ──▶ 읽기
```

- 들어가면 **읽기 모드**다. 필드는 잠긴 칸(§1.2 옅은 바탕)이고 조작 버튼은 없다.
- **우측 상단 「편집」** 을 누르면 편집 모드 — 그 자리의 버튼이 **「저장」** 으로 바뀌고 왼쪽에 취소(✕)가 붙는다 (Q7).
- **「저장」 은 변경이 생겨야 활성**된다. 아무것도 안 고쳤으면 눌러도 할 일이 없는 버튼을 살려 두지 않는다.
- **저장 중에는 저장 · 취소 · 필드 전부 disabled.** 끝나면 읽기 모드로 돌아간다. 거부되면 편집 모드에 머물고 사유 배너.
- 취소는 변경이 있을 때만 확인 팝업(「계속 수정」 / 「저장하지 않고 나가기」 — Q10, 2026-10-01 문구 변경). 변경이 없으면 바로 읽기 모드.
- **화면 하나에 「저장」 은 하나다.** 섹션마다 저장 버튼을 두던 방식(2026-09 초 구현 — 「섹션 하나 = 폼 하나 = 저장 하나」)을
  버린다. 어디까지가 한 번의 저장인지 사람이 세지 않게 한다.
- 파괴적 조작(삭제 · 타입 변경)은 별도 「위험 구역」 섹션에 모으지 않는다. **삭제는 헤더의 `.danger` 아이콘 버튼**(§1.6),
  **타입 변경은 편집 모드의 그 필드**에서 한다 — 저장 시 소실 건수를 든 확인 팝업(§9.5)이 마찰을 준다.
  따름 — 편집 모드에서 값이 바뀌면 그 화면은 client 상태를 가져야 한다 (dirty · 로딩). 서버 컴포넌트 + GET 폼만으로는 안 된다.

**저장 단위 — 무엇이 저장에 들어가고 취소가 무엇을 되돌리나** (2026-09-14)

화면의 변경은 셋 중 하나다 —

| 상태 | 예 | ✕ 취소가 | 저장이 |
|---|---|---|---|
| **편집 중 변경** | 입력칸의 값 · 표의 행 순서 · 조건 편집기 안의 줄 | 되돌린다 | 포함한다 |
| **문서에 적용된 미저장 변경** | 조건 편집 패널 「수정」으로 칩에 실린 조건식 · 표에 넣은 새 행 · 옮긴 행 | 되돌린다 | 포함한다 |
| **저장된 변경** | 「저장」 성공 뒤 | 못 되돌린다 | — |

- **행 추가 · 이동 · 삭제 · 옵션 선택 · 값 비우기 · 현재 마스터 값 가져오기 · 노드 이름 — 전부 화면 저장에 포함**된다. 그 자리의 확인창은 없다 — 저장 전이라 잃는 것이 없다(§1.5).
  잃는 것이 생기는 저장(사용 중인 enum 값을 뺀 채 · 타입 변경으로 값 소실)은 **저장이 §9.5 문법으로 묻는다**. 파괴적이면 관리자만([[공통/화면/결정/ADR-0019-모드폐지-역할권한]]).
- **즉시 실행 명령**(실체 삭제 · 탑재 해제 · 복제 · 이름 재생성 · 조립 실행 …)은 저장 흐름 밖이다. 실행 전에 「취소로 되돌릴 수 없다」와 영향 범위를 보인다.
  **편집 모드에서는 비활성** (tooltip 「저장하거나 취소한 뒤 실행」) — 편집 중 변경과 즉시 실행이 한 화면에 겹치지 않게 한다.
- **공통 인수 문구** — 모든 화면기획 · 시나리오가 이 둘로 판정한다:
  ① **「저장 실패 시 전체 제출 미반영」** — 여러 필드 · 행을 바꾼 뒤 한 값이 거부되면 아무것도 저장되지 않고 편집 모드에 머문다 (실물: 2026-09-14 `758c603`, 폼 한 제출 = 한 트랜잭션).
     편집 화면의 저장 액션은 서비스를 여러 번 불러도 **전체가 한 트랜잭션**이다(`saveOnce`) — 거부든 저장 시 확인 대화상자든 `ok` 가 아니면 앞 단계까지 롤백한다. 확인 대화상자가 떠 있는 동안 DB 에는 아무것도 없다.
     검사는 **최종 상태**로 한다 — 한 단계씩 검사하면 순서에 따라 결과가 갈리는 곳(열거형변수 · 담보속성 값 이름 맞바꾸기 · 담보 형제 노드 이름 · 공용조항 선택지 교체)은 최종 한 벌로 검사하거나 더한 뒤 뺀다 (2026-09-27 점검 D1).
  ② **「취소로 되돌릴 수 없는 명령은 실행 전에 그 범위를 표시」**.
- **값 행 표** (2026-10-01 사용자 결정, `src/app/_components/ValueRowsTable.tsx`) — 편집 화면에서 사람이 행을 더하고 빼고 옮기는 값 목록 표
  (열거형변수 값 · 필드, 새 열거형변수 값, 담보속성 유효값)는 한 모양이다.
  - **행 맨 앞 ⊖** 「행 삭제 · {이름}」(`.danger`) — 이름이 비면 「새 값」 같은 자리 이름. 초안에서만 뺀다 — 확인은 저장 시점(아래 저장 단위).
  - 이어서 **끌기 손잡이 ⋮⋮** 「순서 옮기기 · {이름}」 — 위아래로 끌면 지나가는 동안 순서 칸이 바로 바뀌고, 표 밖에 놓거나 Esc 면 제자리.
    키보드는 손잡이에서 ↑ ↓, 행 안 어디서든 Alt+↑ ↓(끝에서 돌지 않는다), 옮기면 「{이름} — N번째」를 알린다(aria-live). 순서가 곧 코드인 표(담보속성)는 손잡이가 없다.
  - **마지막 행 아래 ⊕** 「행 추가」 한 줄(⊖ 칸 아래) — 머리에 「개수 +」를 두지 않는다. 한 화면에 표가 둘이면 무엇의 행인지 붙인다(「행 추가 · 필드」 · 「행 추가 · 값」). 새 행의 첫 입력칸에 커서.
  - ↑ ↓ 버튼 · 행 끝 조작 열은 두지 않는다. 사용 수 열도 두지 않는다(읽기 포함, 아래 「사용처」) — 편집 중 판단은 저장 확인이 한다.
  - 읽기 모드에는 ⊖ · 손잡이 · ⊕ 가 없다.
- **사용처는 화면에 두지 않는다** (2026-10-01 사용자 결정) — 상세 헤더 「사용처 N」 버튼 · 사용처 모달 · 「사용처」 필드 행 · 「관계정보에서 보기」 줄 · 목록 · 값 표의 사용 수 열 · 탑재 수 배지를 두지 않는다.
  「이것을 누가 쓰나 · 어디까지 번지나」는 **관계정보 메뉴**([[기능/관계정보/관계정보]])가 본다. 안전장치는 그대로다 — 저장 · 삭제 확인의 깨질 참조 목록, 구분자 검사의 「깨질 사용처」 경고, 저장 뒤 재검사 목록.
- **빈 새 행은 생성 · 편집 모두 저장 때 버린다.** 생성에서도 빈 행을 `required` 로 막지 않는다 — 값 0 개여도 생성은 된다. 중복 값 거부는 그대로.

**화면 단어** (2026-09-06 확정) — 「실체」 · 「스칼라」 · 「구조체」 · 「enum」 을 화면에 쓰지 않는다.
실체 → **모델링**, 스칼라 → 단일값, 구조체 → 폼, enum → 선택지. 남겨 두는 낯선 단어(「레벨」 등)에는
라벨 옆 **ⓘ 아이콘 tooltip** 으로 한 줄 설명을 붙인다. 개발 용어는 코드 · 문서에 남고 화면에는 안 나온다 (§9 라벨 맵).
**실물 사전은 [[공통/화면/화면단어]]** (2026-09-09) — 같은 것을 가리키면 어디서나 같은 라벨.

### L3 · 저작(에디터)

```
┌──────┬──────────────────────────┬─────────┐
│ 목차 │ 에디터            ✕  ✎/✓ │ 읽기:   │
│ 조만 │ [조연결] 보통약관 제12조 · 준용│ 미리보기│
│      │ ① 조 본문                │         │
│      │ ┃[if 조건식 …생략] ⧉ ✕    │ 편집:   │
│      │ ┃  갈라지는 문장           │ 조건식  │
│ 220  │        (측정폭 44자)      │  340    │
└──────┴──────────────────────────┴─────────┘
```

**좁은 폭에서는 본문 폭이 먼저다** — 우측 패널을 먼저 접고(바의 〔패널〕로 본문 위에 연다), 그다음 목차를 줄인다. 바는 줄바꿈하지 않는다. 기준 폭은 [[기능/문면/문면]] §4.3.

**본문 정렬 — 조건 안팎이 동일하다.** 한 행은 3열이다:

```
[ 줄번호 24px ][ 조건 괘선 12px ][ 본문 1fr ]
```

괘선이 **자기 열을 차지**하므로 본문 열은 조건 안에 들어가도 밀리지 않는다.
조건 밖의 행은 괘선 열이 빈칸일 뿐이다. 2026-08-30 프리뷰에서 측정 확인 —
조건 안팎 6개 문단이 전부 같은 x 에서 시작한다.

- **조건 분기**는 괘선(`ink-3` 2px) + 조건식 라벨로만 표시한다. **배경색을 쓰지 않는다** — 명조 본문이 깨진다
  - `if` = 실선 / `else` · `elif` = 파선
  - 괘선을 `rule-strong`(옅음)으로 뒀더니 조건 구간의 시작·끝이 안 읽혔다 → `ink-3`로 올렸다 (2026-08-30)
- **인라인 조건**([[00_시작/도메인모델]] §3)은 본문 안에 **점선 밑줄**만. 배경 없음
- **치환 슬롯**은 `derived` 색 + 밑줄
- **조건 머리는 조건식 칩 하나**다. 식 전체를 mono 로 담는다
  - **읽기 모드에서는 길면 ellipsis** 로 자른다. 전체 문자열은 tooltip 으로 준다
  - **편집 모드에서는 자르지 않고 펼친다** (2026-08-30 결정) — 고치려면 다 보여야 한다.
    여러 줄로 감싸며, **짧은 칩은 자연 너비를 유지**한다 (`else` 가 빈 상자로 늘어나지 않게)
  - 칩을 조건식 편집기로 펼치는 카드 UI 를 한번 만들었다가 **되돌렸다** (2026-08-30) —
    카드가 문면 흐름을 끊어 조가 어디서 시작하는지 안 읽혔다. 조건식은 문면의 곁다리이지 주인공이 아니다
- **조작은 오른쪽 끝 아이콘 버튼**이다 — **복사(⧉) · 삭제(✕)** 둘뿐.
  별도 「조건식 수정」 버튼을 두지 않는다. 편집 진입 방법은 미결 → §10 Q8
- **모드 버튼은 하나다** (2026-08-30 결정). 읽기 모드에서 **「편집」**, 편집 모드에서 **「저장」**.
  누르면 반대 모드로 넘어간다 — 즉 **저장이 곧 모드 전환**이다
  - 읽기: 조건식 칩·본문 보이되 조작 없음
  - 편집: 오른쪽 끝 아이콘이 나타나고, 칩이 펼쳐지고, 본문에 편집 가능 표시가 붙는다
- **목차는 조만 노출한다** (2026-08-30 결정). 항·호로 내려가지 않고, 참조 별표도 싣지 않는다 —
  목차는 이동 수단이지 문서 구조 설명서가 아니다
- **조연결은 조 바로 위에 붙인다** (2026-08-30 결정). 우측 패널에서 내려왔다 —
  「이 조가 보통약관 어디를 따라가나」는 조를 읽는 순간 같이 읽혀야 하는 정보다
  - 읽기 모드에서는 테두리 없는 평문, **편집 모드에서만 수정 가능**(§1.2 문법 그대로)
- **모드 버튼은 아이콘 하나**(✎ 편집 / ✓ 저장)이고, 편집 모드에서 그 왼쪽에 **취소(✕)** 가 붙는다
- **담보약관 상태를 바에 띄운다** — MVP 이후: `확정` 잠금(⌧)은 ADR-0026 작업본/확정 구현 시점의 것이라 MVP 화면에 자물쇠 자리는 없다 (ADR-0052 §담보 상태). `확정` 이면 **편집 버튼 자리에 자물쇠(⌧)** 가 오고 눌리지 않는다
  (tooltip: 「확정된 담보약관이다. 더 이상 수정할 수 없다」) — 편집 모드에 들어갈 방법 자체가 없다.
  화면을 숨기는 게 아니라 조작을 없애는 것이고, 서버도 같이 거부한다([[00_시작/도메인모델]] §5)
- 좌·우 패널은 접을 수 있다. **중앙 에디터의 측정폭은 어떤 경우에도 유지**된다

**우측 패널은 모드에 종속된다. 탭이 없다** (2026-08-30 결정)

한 번에 하나만 보여 주므로 고를 것이 없다 — 지금 무엇을 하는 중인지가 패널을 정한다.

**읽기 모드 → 미리보기** — 실시간이 아니다. **명시적으로 실행한다**
   - **상품** 콤보박스 — 텍스트 입력에 **유사일치**하는 항목을 목록으로 보여준다 (코드·이름 둘 다 매칭)
   - **상품담보** 콤보박스 — 같은 방식
   - **「미리보기」 버튼** → 그 조합으로 **조건식 평가 결과**가 나온다
   - 평가 결과는 조건식마다 `식 · 참/거짓 · 채택된 분기`를 한 줄로 보여주고,
     그 아래에 **명조로 렌더된 결과 문면**을 붙인다. 탈락한 조는 취소선으로 남긴다 (왜 빠졌는지 보이게)
   - **문맥은 머리에 쓴다** (2026-09-14, 기획_UI_전반검토_2026-09-14(아카이브) §4) — 「마스터 사전평가」(상품 없이 식만)와 「상품담보 미리보기」(특정 탑재분의 실제 값)를 구별하고,
     결과 머리에 **고른 상품 · 탑재분 · 세목 범위 · 저장/미저장 기준**(저장된 값인지, 지금 편집 중인 값인지)을 한 줄로 박는다. 문맥이 없으면 결과가 아니라 「미검사」다(§9.2).

**편집 모드 → 조건식 편집기**

- 에디터의 조건식 칩을 **누르면** 그 조건이 여기 실린다. 칩은 선택 표시가 붙는다
- 한 줄 = `구분자 경로` + (`연산자` · `값`). 아래에 **조건 추가(＋)**
- **연결은 조건식마다 하나다** (2026-08-30 결정). 편집기 맨 위에 `연결 [AND|OR]` 토글이
  하나 있고, 모든 줄이 그것으로 이어진다. **한 조건식에서 AND 와 OR 를 섞을 수 없다**
  - 이유: 평평한 목록에서 `A AND B OR C` 는 괄호 없이 뜻이 하나로 안 정해진다.
    섞기를 막으면 우선순위 문제 자체가 사라진다 (§10 Q9 를 이 결정이 닫았다)
- **고친 즉시 칩에 반영하지 않는다** (2026-08-30 결정). 편집기 아래 **「수정」** 을 눌러야
  칩 텍스트가 갱신된다. 고치는 동안 칩이 계속 흔들리면 문면이 읽히지 않는다
  - 「수정」은 고친 것이 있을 때만 활성화된다
  - **「수정」은 저장이 아니다** — 칩에 실린 조건식은 **문서에 적용된 미저장 변경**이다(§2 L2 저장 단위). 문서 「저장」에 포함되고 ✕ 로 되돌아간다.
    「수정」을 안 누른 편집기 안의 줄은 편집 중 변경 — 다른 칩을 고르거나 저장을 누르면 「적용하지 않은 조건 편집이 있다 — 적용 / 버리기」를 묻는다
- 조건식이 없는 분기(`else`)를 고르면 「조건식을 갖지 않는다」로 답한다
- **에디터 본문에는 칩만 남는다** — 조건식 편집 UI 가 문면 흐름을 끊지 않는다.
  2026-08-30에 인라인 카드로 만들었다 되돌린 이유가 이것이고, 우측으로 옮겨서 해결했다
- 「커서를 가져다 대면」을 **hover 만으로는 구현할 수 없다** — 편집하려면 마우스를 우측 패널로
  옮겨야 하고 그 순간 선택이 풀린다. **hover 는 강조, 클릭은 고정**으로 나눴다

> **출처 검사 패널은 두지 않는다** (2026-08-30 결정). 값을 만지는 자리가 L2 이므로 거기가 담당한다.

## 6. 모션

**minimal-functional.** 100~150ms, `ease-out`. 하루 종일 쓰는 도구에서 애니메이션은 세금이다.

**예외 하나** — 미리보기 **평가 결과가 도착할 때**, 이번 평가로 달라진 구간(채택/탈락한 조,
값이 바뀐 슬롯)을 300ms 짧게 표시했다 지운다. 「무엇이 이 조합 때문에 달라졌나」를 눈으로
잇는 유일한 모션이고, §0에 직접 복무한다.

> 2026-08-30 개정 — 원래는 「값을 바꾸면 미리보기 문장이 실시간으로 하이라이트」였다.
> 미리보기가 **상품·상품담보를 고르고 버튼을 눌러 실행**하는 구조로 바뀌면서(§2 L3) 전제가 깨졌다.

## 9. 결정 부담 — UX 심리학 6원칙의 번역

**이 도구에는 퍼널이 없다.** 가입도 결제도 획득도 없고, 실무자가 하루 종일 붙잡고 있는
사내 도구다(§1.4). 소비자 서비스의 전환 장치를 글자 그대로 옮기면 옮길 대상이 없거나,
있어도 이 도구를 망친다.

옮기는 것은 장치가 아니라 그 아래의 발견이다 — 사람은 논리적으로 결정하지 않는다.
기본값은 「추천」으로 읽히고, 먼저 본 숫자가 이후 모든 것을 재는 자가 되고,
직접 만든 것은 버리기 어려워진다. 이 도구에서 그 발견이 쓰이는 자리는 하나다:
**결정 부담을 줄이고 · 결과를 보이게 하는 것.** 곧 §0(「값이 어디서 왔는지 항상 보인다」)에 복무한다.

> **설득이 아니라 부담 감소가 목적이다. 다크패턴은 쓰지 않는다** (2026-09-06 결정).
> 가짜 진행률 · 만들어낸 긴급성 · 거절 버튼에 죄책감을 심는 문구는 이 도구에 없다.
> 약관은 규제 산출물이고, 한 번 속인 화면은 그 뒤의 모든 숫자를 못 믿게 만든다 —
> §0 이 무너지면 이 도구의 존재 이유가 없다. → 버린 안은 §11.2 결정 메모

### 9.1 스마트 디폴트 — 빈 폼은 필드마다 결정을 시킨다

선택지 24종을 늘어놓은 잼 매대는 구매 3%, 6종 매대는 30%였다. 사람은 기본값을 70~90% 그대로 둔다 —
**기본값은 「추천」으로 읽힌다.**

**이 도구에서의 뜻** — 빈 폼은 결정 피로를 만들고 작업을 중간에 세운다. 그런데 이 도메인의 최악은
값이 없어 조립이 멈추는 것이 아니라 **「아무도 확인 안 한 기본값으로 조립이 조용히 성공하는 것」**
이다([[공통/기술/결정/ADR-0004-null없음-미입력상태]]). 그래서 프리필하되 **층을 가른다.**

- **구조 선택지는 프리필한다** — 새 구분자 폼의 타입·레벨, 조회의 기본 필터 범위와 정렬,
  새로 만든 담보의 상태(`미사용`). 가장 흔한 것을 미리 골라 둔다
- **도메인 값은 「보이는 제안」으로만 프리필한다** — 채워져 보이되 저장 전에는 미입력이고,
  **보인 제안을 그대로 두고 저장하면 그때 명시 값이 된다**(ADR-0004 — 저장이 곧 확인). 표시는 §1.2 「제안」. 저장 없이 기본값이 저장소로 유입되는 경로는 없다.
  - 제안된 자리는 「미입력」 + 「제안값 · 저장해야 확정」 표시. 저장하면 보통 값이 된다
  - 손대지 않은 제안도 저장에 실린다 — 칸마다 수락하게 하지 않는다.
    — 왜: 기본값을 두는 필드(신규계약만 적용 `✓` · 이후 지급률 `100` 등)는 현업에서 「으레 그렇다」고 보는 값이라, 확인 없이 성공해도 위험이 작다. 위험한 필드는 아래처럼 기본값을 두지 않는 것으로 막는다
  - **제안이 뜨는 필드 = 마스터 필드 정의에 `기본값` 이 있는 필드.** 면책여부처럼 조립 결과를 조용히 바꾸는 필드는 코드에서 기본값을 두지 않는 것으로 막는다 — 폼별 판단이 아니라 필드 정의가 답한다
- **신규 폼은 온 자리의 문맥을 갖고 온다** — 상품담보 밑에서 「새로 만들기」를 누르면 그 상품담보가
  미리 골라져 있고, 필터가 걸린 조회에서 넘어오면 그 필터 값이 폼에 들어온다.
  지금 새 상품 폼·새 구분자 폼은 문맥을 하나도 안 받는다
- 선택지가 많으면 자르지 말고 **좁혀서** 준다 — 구분자 콤보박스는 지금 레벨에 노출된 것부터 (§1.2)

> **하지 않는 것** — 미입력을 기본값으로 조용히 채워 저장하기. 「모든 필드에 기본값」도 하지 않는다.
> 프리필은 사람의 눈을 한 번 거치게 만드는 장치이지, 눈을 건너뛰는 장치가 아니다.

### 9.2 입력률 표시 폐기 — 필요한 내용을 직접 보여준다

2026-09-15 실제 화면 검토 후, 입력 칸을 세어 완결성·입력률·진행 막대로 표시하는 원칙을 폐기했다.
숫자가 실제 작업의 완성도를 설명하지 못하고 제목과 입력 폼을 번잡하게 만들었다.

- 일반 상세 화면과 입력 폼에 「값 자리 N 중 M 입력」, 「입력 M / N」, 입력률 막대를 두지 않는다.
- 읽기 상태에서는 저장한 내용을 보여주고, 편집 버튼을 누르면 수정할 수 있게 한다. 같은 버튼은 저장으로 바뀐다.
- 한 화면의 상품명·보험종목·세목 값·조합은 저장 한 번에 반영한다.
- 실제 오류와 필요한 입력은 해당 항목 및 수정 위치로 안내한다. 조립 실행 오류와 문서 검토 결과는 입력률과 구분한다.
- 기존 문서의 입력률 표시 지침보다 이 원칙이 우선한다.

**완료 표시는 세 가지다 — 이름과 숫자를 섞지 않는다** (2026-09-14). 같은 화면에 나란히 서도 된다. 화면 라벨 「완결성」은 쓰지 않는다.

| 목적 | 표기 | 뜻 |
|---|---|---|
| **입력 관리** | 숫자 없음 — **미입력 목록**(항목 + 「고치러 가기」) | 문서에 필요한지와 무관하게 자리를 본다. 입력률 · 진행 막대는 없다(위) |
| **조립 검사** | 「현재 상품 문맥: 오류 a · 경고 b · 평가 대기 c」 | 특정 상품(또는 상품담보) 실행이 밟은 범위의 결과와 **아직 판단하지 못한 범위**를 함께. 문맥이 머리에 붙는다 |
| **문서 검토** | 「시스템 검사 통과 / 내용 검토 미실시」 | 자동 검사 결과를 사람의 내용 검토 완료로 **확대하지 않는다** |

- **실행 문맥이 없거나 평가하지 않은 것은 「문제 없음」이 아니라 「미검사」다** — 탑재된 곳이 없는 담보 · 상품을 고르지 않은 조문 · 미입력 분기 값에 막힌 분기 안쪽. 0 을 초록으로 칠하지 않는다.
- **판단하지 못한 범위가 있으면 있다고 쓴다** — 분기 판단 값이 미입력인 동안 조립 검사 칸에 「분기 미결로 미검사 범위가 있을 수 있음」.
- **warning 은 완료를 깨지 않는다**([[기능/조립산출/조립산출]]). 대신 「오류 0」은 「경고 b」와 나란히 서고 문서 검토 칸이 따로 있어 「오류 0 = 수록 · 검토 완료」로 읽히지 않는다.
- **승인 · 판본은 넣지 않는다.** 문서 검토 칸은 「미실시 / 실시(누가 · 언제)」를 넘지 않고 아무것도 잠그지 않는다. MVP 에서는 「내용 검토 미실시」 고정 문구여도 된다 — 확정 · 이력은 [[공통/기술/결정/ADR-0026-이력개정-이력일자-작업본확정]] 의 몫(MVP 이후).
- **자리** — 조립 검사 · 문서 검토는 미리보기 · 조립 화면 머리에 한 줄(문맥 표시 · 「완성본 아님」 배너와 같은 자리). 미입력 목록과 미리보기가 한 화면이면 미입력 목록은 위 섹션, 조립 검사 · 문서 검토는 미리보기 섹션 머리 — 헤더에 넣지 않는다.
- **실행 기반 조회를 꽂기 전에는 조립 검사 칸을 두지 않는다** — 담보 상세는 `CompletenessFilter`(`executionBasedFilter`, `src/domain/assembly/booklet.ts`)를 꽂아야 칸이 생긴다. 없는 것을 있는 척하지 않는다.

지금 실물 (2026-09-27 코드 확인):

| 실물 | 칸 | 상태 |
|---|---|---|
| `AssemblyCheckLine` (`src/app/_components/AssemblyCheckLine.tsx`, 상품 미리보기 · 상품담보) | 조립 검사 + 문서 검토 | 「조립 검사: 오류 a · 경고 b — 분기 미결로 미검사 범위가 있을 수 있음 · 내용 검토: 미실시」 한 줄 |
| `booklet.complete` (`src/domain/assembly/booklet.ts`) | 조립 검사의 「오류 a」 | severity `error` 가 없으면 true, warning 무시. 「완성본 아님」 배너는 `complete === false` 일 때 |
| 상품담보 「미입력」 목록 (`services.product.coverageCompleteness`) | 입력 관리 | 항목 + 「고치러 가기」. 숫자 없음 |
| 담보 상세 카드의 입력 현황 | 입력 관리 | **없음** — 2026-09-27 값 탭 노드 목록의 `n / m` 을 걷었고, 한 화면(중첩 카드)에서도 접힌 카드는 이름만 보인다 |
| 「평가 대기 c」 | 조립 검사 | **미구현** — 조립이 막힌 분기를 trace 에 남겨야 센다. 그 전까지 「분기 미결…」 문구로 대신 |

### 9.3 상호성 — 요구하기 전에 준다

받은 것이 빚을 만든다(치알디니). 무료 시식이 팔리게 하고, 부분 결과를 먼저 보여준 뒤 요구하면 응답이 는다.

**이 도구에서의 뜻** — 여기서 「요구」는 결제가 아니라 **입력**이다. 값 40개를 다 채우기 전에는
아무것도 안 보여주는 화면은 사람에게 먼저 내놓으라고 요구하는 화면이다.

- **조립 미리보기는 오류가 있어도 부분 조립을 보여준다** — ADR-0016 이 이미 그렇게 정했다.
  「완성본 아님」 배너 · 오류 패널 · 지금까지 조립된 문면이 한 화면에 있다. 오류가 문면을 가리지 않는다
- **저장 전에 결과를 보여준다** — 사전평가(조건식 참/거짓 · 채택 분기)는 저장 없이 실행되고,
  파괴적 액션의 영향 목록은 실행 전에 나온다(§9.5)
- **빈 화면을 주지 않는다** — 목록이 비면 「없음」 대신 무엇을 만들면 되는지와 만들기 경로를 같이 준다.
  검증·개발 환경은 시드를 갖고 시작한다

> **하지 않는 것** — 결과를 인질로 잡기. 결과를 흐리게 덮어 두고 입력을 마쳐야 걷어 주는 화면은 안 쓴다.
> 부분 결과는 그냥 부분 결과로 준다.

### 9.4 IKEA 효과 · 소유 효과 — 만든 것에는 이름이 붙는다

직접 조립한 것을 사람은 더 높게 친다. 내 것이 된 뒤에는 놓기 어려워진다.

**이 도구에서의 뜻** — 소유감을 **만들어낼** 일은 없다. 실무자는 이미 자기가 만든 것을 갖고 있다.
할 일은 그것이 화면에서 **자기 것으로 보이게** 하는 것이다. `PCV-0031` 만 나오는 화면에서는
자기가 어제 만든 것이 목록에서 사라진다.

- **생성 흐름의 첫 입력은 이름·표시명이다.** 코드는 자동 채번이므로
  ([[공통/기술/결정/ADR-0005-코드-표시명-이중체계]]) 사람이 채우는 첫 칸은 사람이 읽는 이름이다
- **실체는 어디서 언급되든 표시명 + 코드로 부른다** — 확인 팝업 · 오류 패널 · tooltip 전부.
  「`D0003`」 이 아니라 「보험금지급(`D0003`)」
- **버려지는 것은 사람의 말로 센다** — 「입력한 값 12개를 버린다」. 「변경사항」으로 뭉개지 않는다 (§9.5)
- 여러 단계를 거치는 생성(구분자 → 필드 추가)에서는 **생성이 끝이 아님을 화면이 말한다** —
  만들다 만 것이 목록에 남고, 이어서 할 일이 그 자리에 보인다

> **하지 않는 것** — 소유감 만들어내기. 사람이 손대지 않은 시드·프리필을 「당신이 만든 것」으로
> 세지 않는다 (§9.2 의 진짜 카운트 규칙과 같은 이유다).

### 9.5 손실 회피 · 현상 유지 편향 — 잃는 것을 이름으로 말한다

잃는 고통은 얻는 기쁨의 약 두 배다(카너먼). 그래서 사람은 기본적으로 가만히 있는 쪽을 고른다.

**이 도구에서의 뜻** — 파괴적 액션은 실제로 되돌릴 수 없다([[공통/화면/결정/ADR-0019-모드폐지-역할권한]]).
「정말 삭제하시겠습니까?」는 잃는 것을 하나도 말하지 않는다 — 사람은 상상하지 못한 채 누르거나,
무서워서 아무것도 못 한다. 둘 다 나쁘다.

- **파괴적 확인은 잃는 것을 이름과 개수로 말한다.** `Confirm` 이 이미 그 모양이다 —
  소실될 값 행 수 · 함께 삭제되는 것 · 깨질 참조를 좌표로 나열한다
  (「구분자 `보험금지급.면책여부` 를 삭제하면 참조 4건이 끊긴다: …」).
  **새 파괴적 액션은 영향 목록을 계산할 수 있을 때만 붙일 수 있다**
- **확인 버튼의 글자가 잃는 것을 가리킨다** — 「확인」이 아니라 「삭제하고 참조 4건 끊기」.
  취소 쪽은 중립어다(「취소」 · 「계속 편집」). 버튼은 텍스트다(§1.6 예외 ②)
- **잃는 것은 계산된 것만 쓴다** — 관계정보가 실제로 센 것만 적는다. 겁주려고 범위를 부풀리지 않는다
- 미저장 이탈 경고도 같은 문법이다 — 「저장하지 않은 변경 7건이 사라진다」.
  취소(§10 Q10) · 저장 시 소실 확인(§2 L2)이 같은 문법을 쓰므로 규칙이 한 벌로 통한다
- **가만히 있는 쪽에도 결과가 있으면 말한다** — `미사용` 으로 남은 담보는 탑재 조회에 안 잡힌다(§2 L1).
  「지금 안 올리면 무엇이 안 되는가」를 상태 옆에서 알려준다

> **하지 않는 것** — 만들어낸 손실 · 만들어낸 긴급성. 실제로 사라지는 것이 없으면 확인을 묻지 않는다
> (§1.5 — 마찰은 되돌릴 수 없는 곳에만).

### 9.6 숫자는 판단에 필요할 때만

- 입력 칸 개수나 비율을 화면 완성도의 대리 지표로 사용하지 않는다.
- 오류는 원인과 수정 위치를 먼저 보여준다. 개수나 분모는 문제를 이해하는 데 필요한 경우에만 붙인다.
- 조회 목록의 총 건수와 페이지 정보는 유지한다.

### 9.7 화면 리뷰 체크리스트

| 원칙 | 화면에서 확인할 것 | 위반 신호 |
|---|---|---|
| **스마트 디폴트** | 구조 선택지가 미리 골라져 있나 · 문맥에서 온 값이 들어와 있나 · 도메인 값 프리필이 「제안」 칩을 달고 손대기 전까지 미입력인가 | 전부 「— 선택 —」인 새 폼 · 아무도 안 본 기본값이 저장돼 있다 · 표식 없는 프리필 |
| **입력 화면** | 읽기 기본 · 편집/저장 전환 · 저장 하나인가 | 입력률 숫자·막대 · 항목별 저장 버튼 |
| **상호성** | 오류가 있어도 결과가 보이나 · 빈 화면에 다음 행동이 있나 | 다 채워야 열리는 미리보기 · 「없음」만 있는 화면 |
| **IKEA · 소유** | 실체가 표시명으로 불리나 · 첫 입력이 이름인가 | 코드만 나오는 확인·오류 문구 · 이름을 마지막에 묻는 폼 |
| **손실 회피** | 확인이 잃는 것을 이름·개수로 말하나 · 그 목록이 계산된 것인가 | 「정말 삭제하시겠습니까?」 · 「확인」뿐인 버튼 · 실물 없는 경고 |
| **숫자** | 사용자의 판단이나 행동에 필요한가 | 의미 없는 입력률 · 장식용 카운트 |
