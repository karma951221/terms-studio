## 원칙

1. **얇은 관통 먼저.** 모델링·에디터·조립 중 한쪽만 먼저 커지는 것을 막는다 —
   가장 단순한 사례로 입력부터 미리보기까지 뚫고, 그 다음에 넓힌다 (terms-lab 교훈 계승).
2. **관통의 종점은 화면 미리보기다.** `.docx` 는 MVP 밖 ([[00_시작/범위]]).
3. **문면을 만들려면 재료가 먼저다.** 보통약관·담보약관을 만들기 위한
   구분자 · 담보 부착 구분자(파생 축 + 작명) · 공용조항이 문면 에디터보다 앞선다.
4. 기획은 구현보다 반 발만 앞선다. 다음 단계 착수 전에 그 단계의 기획만 확정한다.

      `DiscriminatorKind` 4종 · 구조체 구분자 · 부착(노출여부) · 유형 > 폼 화면 · `StructCreateForm` 을 걷고, **코드 마스터**(레벨별 고정 필드 — 시드 상품 4벌부터) +
      **마스터 조회 페이지**(정리 트리 + 사용처 패널, [[기능/마스터/마스터]] §3.2) + **구분자(레벨 + 식, 경로 `레벨.필드키` 두 마디)** 만 남긴다. 값 저장은 노드 × 마스터 필드.
      ~~정리 트리(폴더 · 순서 · 미분류)는 데이터, 값 폼은 트리에서 파생.~~ → 2026-09-13 [[기능/마스터/마스터]] §3: 마스터 = **코드 폼 › 필드**(폼에 레벨), 코드 **`폼키.필드키`**, 트리 편집 없음, 값 폼은 **폼 카드**(관리자에게 코드 칩). 오류 메시지에 구분자 코드 · 필드 코드.
      **코드 폼 마스터([[기능/마스터/마스터]] §3) 구현 완료 (2026-09-13, `feat/마스터-코드폼`)** — 폼 › 필드 코드 마스터(`src/domain/master`, 폼 6벌) · 코드 `폼키.필드키`(식의 마스터 참조 두 토막) · 마이그레이션 `drizzle/0006_master_form_paths.sql`(값 경로 · 구분자 식 이행) ·
      `/master` 두 칸(트리 + 상세 · 사용처, `services.master`, 내비 「마스터」) · 값 폼 카드 · 관리자 코드 칩 · `?node=` · `?field=` 진입(담보 상세 · 상품).
      미구현: 깨진 참조 배지 · 특약 문면 좌표 링크 (서비스가 데이터를 아직 안 준다).
      화면은 [[기능/마스터/마스터]] (최상위 내비 「마스터」 · 읽기 전용 폼 › 필드 트리 + 사용처 패널 — 정리 트리 가지 편집 · 시드 폴더는 폐지, [[기능/마스터/마스터]] §6.2).
      문면 조건식 · 반복 · 슬롯의 참조 대상을 구분자로만 제한. 시드: 갱신여부 → 담보속성, 평균공시이율 · 감액기간 → 마스터 필드 + 투영 구분자.
      구분자 탭 개정([[기능/구분자/구분자]] — 결과 타입 명시 · 상시 넣기 패널 · 저장 전 검사 오류/경고 · 사용처 두 묶음, [[기능/구분자/구분자]] §3.3). 유저 정의 폼 · 선택 필드는 MVP 이후.
