## 1. 현재 위치와 MVP 완료 기준

**알파Plus의 고정된 구성으로 보통약관과 특약을 생성하는 기반은 있다. 2026-09-17 에 작성·수정 기반(구분자 편집·참조 영향·담보 구조·공용조항 세 검사)과 조립 결과 신뢰성(판정 근거·산출본 저장·재료 분리)이 코드에 들어왔다. 2026-09-19 에 R01 을 결정했다(동적 표 · 반복 MVP 밖 · 저장 단위 D). 남은 중심 과제는 대표 변형 확정(M01), 구성 변경에 따라 본문이 제대로 바뀌는지 입증(M06), 출처 패널(M08), 그리고 브라우저 관통 인수(M13)다.**

- 목표: `(무)알파Plus보장보험2604`의 보통약관 + 대상 특별약관을 모델링 데이터에서 조립해 **화면 미리보기**로 제공한다.
- 완료 판정: 문서별 **고정 본문 대조**와 **대표 구성 변형**을 각각 통과해야 한다. 자동 테스트 통과만으로 MVP 완료를 선언하지 않는다.
- 현재 확보한 원문: 보통약관 52조 + 특약 10벌. 특약 전체 목록에 추가 대상이 있는지는 먼저 확정해야 한다.
- 기본계약은 정확히 1개를 지원한다. 0개·복수 기본계약 지원은 MVP 이후다.
- 번호·공백·병합 등의 허용 차이는 [[QA/인수기준]] 실물 재현 인수 표를 따른다. 원본 PDF의 조판까지 재현하는 목표는 아니다.

정본: [[00_시작/범위]], [[QA/인수기준]].

### 상태를 읽는 법

| 표시 | 의미 | 일정에 잡을 일 |
|---|---|---|
| 구현됨 | 현재 코드에 기능이 있다. 도메인 로직과 화면의 수준은 아래에서 구분한다 | 필요한 인수검사·회귀검사 |
| 부분 구현 | 기반은 있지만 채택된 동작이나 화면 연결이 일부 빠졌다 | 누락 구현 + 통합 검증 |
| 검증 필요 | 기능 또는 자료가 있으나 해당 인수 조건을 통과했다는 근거가 부족하다 | 재현 시나리오·테스트·판정 |
| 범위 결정 | 문서 사이에 범위 충돌이 있거나 제안이 아직 확정되지 않았다 | 결정 후 별도 견적 |

진척률 백분율은 매기지 않는다. 화면 하나와 조립 엔진 변경의 작업량이 달라 파일 수·체크 수로 완료율을 계산하면 일정이 왜곡된다.

## 2. 도메인별 현황

### 2.1 입력 마스터 · 타입 · 값 폼 — 구현됨, 사용처 추적 보완

**만들어진 것**

- 코드로 정의하는 폼 → 필드 구조와 `폼키.필드키` 경로. 유저 정의 폼은 현재 범위가 아니다.
- 문자열·숫자·참거짓·날짜·enum·enum 목록·표(`table`) 값, 미입력 상태, 기본값 제안, 타입 검사.
- 공통 `StructForm`, 폼 카드, 감액·면책 카드 열기/닫기, 표 입력·붙여넣기·행 편집.
- `/master` 조회 화면: 폼/필드 탐색, 직접 사용하는 구분자·문서, 값이 있는 노드와 미입력 노드 조회, 입력 화면 이동.
- (2026-09-17) 다단 사용처 조회 — 필드 → 구분자 → 구분자 → 문면 → 상품 (`9ff2942`, 2.9 참고).

**MVP에서 남은 일**

- 특약·상품담보의 오류 좌표에서 실제 필드 입력칸으로 가는 경로의 브라우저 관통 확인. 좌표 정정(`cef55c6`)으로 「고치러 가기」가 제자리에 닿게 됐고, 남은 것은 화면 시나리오 확인이다.
- 새 대표 변형에 필요한 입력 필드가 현 마스터에 있는지 확인하고, 필요한 필드만 추가한다 (M06).

- 아래 대표 변형을 실제 시드 템플릿에 넣고 서비스→조립→예상 본문으로 검증한다. 순수 엔진 테스트만으로 대체하지 않는다. **2026-09-16 이후 변형 테스트는 추가되지 않았다.**
- 변환기의 표 셀·박스·호 아래 표 등 위치별 지원/검사 범위를 정리한다. 잔존 참조 보고 0건을 모든 참조의 구조화 완료로 해석하지 않는다.
- 인수표와 개발순서의 오래된 미완료 표시를 현재 증거에 맞춰 갱신한다.
- 대표 화면 흐름, 관리자/편집자 차이, 오류 복구까지 최종 관통한다.

## 5. MVP 일정에 넣지 않을 것

- `.docx`/PDF 최종 파일, 표지·목차 등 책자 앞부분, 별표 본문 출력.
- 204개 상품 배치 실행 UI·잡 러너·산출본 저장·파일 묶음. 단, M10의 구조 기반은 포함 (완료).
- 기본계약 0개/복수 조립, 다중 보통약관, 공용조항 중첩.
- 유저 정의 폼/필드 편집기, 범용 `list<T>`, 범용 산술 엔진을 자동으로 추가하는 것.
- 이력·판본·확정/해제·승인 체계, 산출물 시점 간 회귀 비교.
- 준용규정 조 자동 생성, 사내 시스템 연동/데이터 이관, 전체 상품·사업방법서 확대.
- 운영 배포·인증 고도화는 로컬 MVP와 별도 범위로 결정한다.
