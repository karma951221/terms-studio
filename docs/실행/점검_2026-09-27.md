## 2. 결정 필요

사용자가 정할 것만 모았다. 추천은 원 점검의 추천을 따랐고, 원 점검에 추천이 없으면 이 문서가 정리한 안이다(「추천(정리안)」). 영향 기능은 결정에 따라 바뀌는 기능이다.

### 2.1 데이터 · 저장 규칙 (먼저)

**D1 「저장 한 번」의 원자성과 최종 상태 검사** — 원: 공 A1 · D3 · 공조 #3 · 마 #11 · 담 #13 · 담 #5
- 무엇: 편집 화면의 저장이 서비스 호출 여러 번이고, 호출마다 트랜잭션이 따로 돈다(H1). 게다가 한 단계씩 검사해서 최종 상태가 유효해도 거부된다(H2 — 이름 맞바꾸기 등).
- 대안: (a) 액션 본문을 `services.db.transaction` 으로 감싸고, 거부면 throw 해서 롤백한다(`txContext` 세이브포인트를 쓴다). 롤백은 되지만 맞바꾸기는 여전히 거부된다. (b) 서비스마다 「편집 화면 한 벌 저장」 메서드를 둔다(한 트랜잭션에서 최종 상태로 검사). (c) **추천(정리안)** — (a) 를 여섯 곳에 공통으로 깔고, 순서에 따라 결과가 달라지는 세 곳(열거형변수 값 · 공용조항 선택지 · 담보 구조 개명)에만 도메인 「최종 한 벌」 연산을 둔다. 담보 구조의 맞바꾸기는 「거부를 유지하되 화면이 미리 표시하고 문서에 적기」로 해도 된다(원: 담 #5 (b)).
- 영향 기능: 유형 · 구분자 · 공용조항 · 담보속성 · 별표 · 담보

**D2 편집 중 저장된 값 행 삭제** — 원: 마 #10 · 공 C2 · 담 #6 (+ 유형 §5 · 담보속성 §5 미결)
- 무엇: 편집 중에 값 행 🗑 를 누르면 즉시 서버에서 지워지고 refresh 된다. 그러면 에디터가 다시 마운트되면서 다른 미저장 변경이 사라진다(H5).
- 대안: (a) **추천** — 행 삭제를 초안의 ✕ 로 바꾸고 저장할 때 반영한다. 쓰이는 값이면 저장 시점에 확인 카드를 띄운다([[공통/화면/디자인원칙]] §2 L2 표가 이미 이렇게 적었다). (b) 초안이 바뀌었으면 「버립니까?」를 물은 뒤 즉시 삭제한다. (c) 임시로 편집 모드에서 값 🗑 를 끈다. (c) 는 (a) 를 구현하기 전까지의 방어로 둘 수 있다.
- 영향 기능: 유형 · 담보속성

**D3 명시적 빈 목록 「(선택 없음)」** — 원: 마 #8 (+ 마 #9 · 담 #1 ③)
- 무엇: `list<enum>` = `[]` 가 값 폼을 한 번 거치면 미입력이 된다(H3). 화면에서는 (선택 없음)을 만들 수도 없다. [[공통/기술/결정/ADR-0004-null없음-미입력상태]] 는 이 둘을 서로 다른 상태로 본다.
- 대안: (a) 목록값(복수) 입력에 「선택 없음」을 명시하는 상태를 둔다. (b) `[]` 를 미입력과 같게 본다(시드 · 마스터 §4.3 · purge 를 같이 정리). (c) 최소 방어 — 사람이 손대지 않은 칸은 제출하지 않는다. **추천(정리안)**: (c) 를 바로 넣고(H4 ③ 의 프리필 저장도 함께 막힌다), 규칙은 ADR-0004 대로 (a) 로 간다.
- 영향 기능: 마스터(값 폼) · 상품 · 담보 · 유형(purge)

**D4 마스터가 쓰는 열거형변수의 삭제** — 원: 마 #5
- 무엇: `E0001` · `E0002` 처럼 코드 마스터가 타입으로 가리키는 열거형변수를 지우면 되살릴 길이 없다. 코드를 다시 쓰지 않으므로 같은 코드를 새로 만들 수 없다. 그 결과 선택지가 0개가 되고, 제출 스키마가 `z.never` 가 되고, 그 경로의 값 행이 스냅샷까지 모두 지워진다. 배포로만 복구된다(`domain/catalog/codes.ts:13-14` · `services/refs.ts:236-237`).
- 대안: (a) **추천** — 마스터 필드가 쓰는 열거형변수는 삭제를 거부한다(〔D-P1-17〕). (b) 지금처럼 허용하되 확인창에 「복구 불가 · 배포 필요」를 적는다. (c) 열거형변수 정의 삭제는 막고 값 삭제만 허용한다.
- 영향 기능: 유형 · 마스터

**D5 준용규정 조 자동 생성** — 원: 공조 #1
- 무엇: 조립이 특약 끝에 「준용규정」 조를 자동으로 만든다(H8). 그런데 [[기능/조립산출/조립산출]] §3.5 · §6.2 와 [[기능/조립산출/결정/ADR-0021-기본계약수-보통약관구조]] 결정 5 는 이것을 버린 안으로 적었다. 아키텍처 · 도메인모델 · 실물재현 설계는 반대로 자동 생성이 있다고 적었다.
- 대안: (a) 문서대로 조립에서 걷어낸다. (b) **추천(정리안)** — 걷어내고, 준용규정 조가 없으면 warning 「준용규정 조가 없습니다」를 낸다. (c) 자동 생성을 유지하고 조립산출 §3.5 · §6.2 · ADR-0021 을 개정한다.
- 영향 기능: 조립산출 · 문면(템플릿 작성) · 실물재현 테스트 · 스냅샷

### 2.2 화면 규칙

**D9 편집 중 이탈 가드의 범위** — 원: 공 C7 · D7 · 문 M3 · 공 C22 · D12
- 무엇: 경로 링크만 가드가 있다. 좌측 내비, 본문 이동 링크, 브라우저 뒤로 · 닫기, 로그아웃 폼, 서버 액션 redirect, 생성 화면의 경로 링크로 나가면 초안이 확인 없이 사라진다(M11).
- 대안: (a) 앱 안의 모든 이동에 가드를 둔다 — 내비 · 본문 링크 · 로그아웃 · 생성 화면을 `leave` 로 감싸고, beforeunload 와 popstate 가드를 더한다. (b) **추천(정리안)** — (a) 에서 popstate 만 뺀다. 뒤로 가기는 [[공통/화면/디자인원칙]] §1.7 에 한계로 적는다. 생성 화면은 입력이 있을 때만 묻는다. (c) 경로 링크 + beforeunload 만 두고, 편집 중에는 본문 링크를 끈다.
- 영향 기능: 전 L2 · 문면 · 생성 화면

**D10 헤더 조작군 규격 — 삭제 · 미리보기 자리와 취소 모양** — 원: 공 A17 · C14 · D1 · 담 #19
- 무엇: 디자인원칙의 검토안은 「미리보기 · 삭제는 더보기」, §2 L2 는 「삭제는 헤더 🗑」로 서로 다르다. 코드도 갈린다 — 상품 · 문면은 32px 더보기와 텍스트 「취소」, 나머지는 24px 아이콘과 ✕. `MoreMenu` 는 링크 항목만 받아 EditShell 의 삭제(액션 + 확인)를 담지 못한다.
- 대안: (a) 상품 규격(32px · 더보기)을 EditShell 전체로 넓힌다. `MoreMenu` 가 액션 항목을 받게 하고 §2 L2 를 개정한다. (b) 상품만 예외로 두고 문서 충돌만 정리한다. (c) **추천(정리안)** — 버튼 크기와 취소 모양(✕ + 변경이 있으면 「버립니까?」)은 전 화면에서 통일하고, 삭제 · 미리보기 자리는 와이어프레임 검토 뒤에 정한다(CLAUDE.md 「검토한다」).
- 영향 기능: 전 L2 · 상품 · 문면

**D11 편집자 사용자 만들기** — 원: 공 A9 · D2
- 무엇: `createUser` 를 부르는 곳이 없다(`services/auth.ts:92`). 그래서 역할권한 시나리오 4와 MVP §2.10 의 편집자 회귀를 실행할 수 없다.
- 대안: (a) 로그인 화면에 관리자 전용 「사용자 추가」를 둔다. (b) **추천(정리안)** — 시드 · E2E 픽스처에 편집자 1명을 고정한다. (c) CLI 스크립트 `db:user` 를 만든다.
- 영향 기능: 인증 · QA

**D12 새 축(형)을 추가할 때 기존 단일축 조합** — 원: 담 #4
- 무엇: 종만으로 조합을 만든 상품에 형을 추가하면, 기존 조합이 표에 보이지 않은 채 초안에 남아 저장이 거부된다(M19).
- 대안: (a) **추천(정리안)** — 무효가 된 조합을 초안에서 자동으로 빼고, 저장할 때 삭제 확인 카드(세목 부착 영향)를 띄운다. (b) 「무효」 행으로 보여 주고 해제하게 한다. (c) 거부를 유지하고 배너로 절차를 안내한다.
- 영향 기능: 상품

**D13 문면 — 적용하지 않은 폼 입력** — 원: 문 M5 · 문면 §5
- 무엇: 적용을 한 번 하면 패널 전체가 다시 마운트되어 다른 폼의 미적용 입력까지 지워진다(M13).
- 대안: ① **추천(정리안)** — 「적용 / 버리기」를 묻는다(디자인원칙 §2 L3). 패널 key 에서 `revision` 을 빼는 것은 결정과 무관하게 바로 한다. ② 저장하거나 선택을 옮길 때 자동으로 적용한다. ③ 적용 버튼을 없애고 입력을 즉시 편집본에 반영한다.
- 영향 기능: 문면

**D14 문면 — 저장 실패 때 편집본을 어디까지 보존하나** — 원: 문 H2
- 무엇: 저장 요청이 예외나 redirect 로 끝나면 편집본이 사라진다(M9).
- 대안: ① **추천** — 예외만 잡아 배너로 돌리고 편집본은 유지한다. 세션 만료는 `{ok:false}` 로 돌려준다. ② ADR-0074 결정 5를 바꿔 세션 저장소에 백업한다.
- 영향 기능: 문면

**D15 오버라이드 깨짐을 공용조항 재검사에 넣나** — 원: 공조 #8
- 무엇: 공용조항 재검사는 문서 마스터의 옵션 선택만 본다. 상품 보통약관 탭의 오버라이드가 깨진 경우는 조립 ③ 과 관계정보에서만 보인다(M8).
- 대안: (a) **추천(정리안)** — 문서대로 override 간선을 Usage 로 더해 상품별 줄로 보인다. (b) 넣지 않고, 공용조항 §3.2 · 시나리오 7 을 「관계정보 깨진 참조 · 조립 ③」으로 낮춘다.
- 영향 기능: 공용조항 · 관계정보 · 상품

**D16 공용조항 옵션 자리 빼기 · 위치** — 원: 공조 #7
- 무엇: 「문구」(inline) 본문에 한 번 넣은 옵션 자리는 뺄 수 없다. 그래서 그 옵션도 삭제할 수 없다. 옵션 자리는 늘 줄 끝에만 붙는다(M7).
- 대안: (a) **추천(정리안)** — 〔옵션〕 칩에 ✕ 를 둔다(삭제 불가를 먼저 푼다). (b) 우클릭 메뉴에 「옵션 자리 빼기」를 둔다. (c) (a)(b) 둘 다 두고, 커서 자리 삽입(문장 중간)도 된다.
- 영향 기능: 공용조항

**D17 인수기준 S2 · S4** — 원: 공 E3 · D13
- 무엇: S4 의 방어선 「별칭형 파생 → 거부」가 현행(별칭 허용 + 경고)과 맞지 않는다. S2 「중복 채번이 채번 시점에 막힌다」도 실제로는 같은 레벨 표시명 완전 중복만 막는다. S4 는 자동 검증이 0건이다.
- 대안: (a) **추천(정리안)** — 「같은 레벨 표시명 중복 거부 + 별칭 경고 + 직접 참조로 바꾸기」로 다시 쓰고 서비스 인수 테스트를 더한다. (b) 시나리오 #2 · #4 만 개정하고 S4 는 눈 검증으로 명시한다. (c) 별칭 금지를 되살린다.
- 영향 기능: 구분자 · QA · 상품(체증체감납 인수시나리오)

**D18 미사용 서버 액션 · 서비스 메서드를 얼마나 남기나** — 원: 담 #8 · #23 (+ 마 #16 · #17 · 문 M7 · 공조 #28)
- 대안: (a) **추천(정리안)** — 미구현 화면이 쓸 둘(`setAttributes` · `reorderGroups`)만 남기고 나머지 액션은 지운다. 테스트만 쓰는 서비스 메서드는 테스트 헬퍼로 옮긴다. (b) 모두 지우고 필요할 때 다시 쓴다. (c) 서비스 메서드는 「테스트 · 시드용」 주석을 달아 남긴다.
- 영향 기능: 상품 · 담보 · 문면 · 공용조항 · 유형 · 구분자

**D19 여는 폼(감액 · 면책) 필드 상세의 값 노드** — 원: 마 #6
- 대안: (a) **추천(정리안)** — 폼을 연 노드만 나열한다(마스터 §3.4 「열지 않으면 자리 자체가 없다」와 맞는다). (b) 모두 나열하되 「없음(열지 않음)」으로 미입력과 구분한다. 어느 쪽이든 §4.3 에 한 줄 적는다.
- 영향 기능: 마스터

**D20 필드 상세 「└ 조문」의 범위** — 원: 마 #7
- 대안: (a) **추천(정리안)** — 다른 구분자를 거쳐 닿는 조문까지 「… 을 거쳐」로 보인다(구분자 상세 사용처가 전이적이라 같게 맞춘다 — ADR-0049 §2). (b) 「직접 읽는 것만 — 거친 것은 구분자 링크로」를 문서에 적는다.
- 영향 기능: 마스터 · 구분자

**D21 관리자 코드 칩의 범위** — 원: 마 #3 · E2E smoke 마스터 판정(문)
- 무엇: 마스터 §3.5 는 값 폼 전체에 칩이 있다고 적었다. 실제로 칩이 있는 곳은 담보 상세뿐이다. 상품 기본정보 · 세목 표 · 상품담보 값 폼에는 없다.
- 대안: ① 상품 쪽(세목 표 셀 포함)에도 칩을 붙인다. 그러면 E2E 의 「강조 행 칩 → 마스터」 왕복이 살아난다. ② **추천(정리안)** — §3.5 를 「담보 상세 값 폼만」으로 좁히고, E2E 에서 칩 왕복 단계를 뺀다(최소 변경).
- 영향 기능: 마스터 · 상품 · E2E

**D22 담보 · 상품 L1 에 최종수정 · 수정자를 넣나** — 원: 담 #10
- 대안: (a) **추천(정리안)** — 넣는다. 스키마에 감사 컬럼이 이미 있고, 담보속성 L1 과 맞춰진다. (b) 넣지 않고 디자인원칙에 적는다. 어느 쪽이든 디자인원칙 L1 의 「담보 조회 컬럼」 · 「1열 = 코드」 예외를 현행으로 고친다(G10).
- 영향 기능: 담보 · 상품

**D23 담보를 지울 때 담보약관 템플릿** — 원: 담 #21
- 무엇: 삭제 영향 목록에는 「담보약관 템플릿」이 나오지만, 실제로는 템플릿이 지워지지 않고 소유자 없는 문서로 남는다. 탑재 상품담보도 `coverage_id` 가 고아로 남는다(`db/repo/coverage.ts:208`).
- 대안: (a) **추천(정리안)** — 템플릿도 함께 지운다(영향 목록이 이미 그렇게 예고한다. D7 과 같이 정한다). (b) 남기고 깨진 참조로 두고, 담보 §3 에 「템플릿 · 탑재 상품담보는 남는다」를 적는다.
- 영향 기능: 담보 · 문면 · 관계정보

**D24 상품담보명 규칙 화면의 자리** — 원: 공 C10 · D8 · 담 #9 (b)
- 무엇: 이 화면은 L1 하위 탭인데, 동시에 경로 「담보속성 › 상품담보명 규칙」도 가진다.
- 대안: (a) **추천(정리안)** — 탭을 유지하고, 경로 없는 EditShell 모드로 둔다. (b) 탭을 없애고 담보속성 제목 줄에서 들어가는 상세로 만든다(경로 유지). (c) 담보속성 상세의 한 섹션으로 흡수한다.
- 영향 기능: 담보속성

**D25 상품담보명 수정의 저장 단위** — 원: 공 C16 · D11
- 무엇: 특약 탑재 표가 행마다 「이름 저장 ✓」 를 두어 필드 하나씩 저장한다. 상품 저장 단위 D 안의 즉시 명령 목록에는 이름 변경이 없다.
- 대안: (a) **추천(정리안)** — 이름 변경을 D 안의 즉시 명령에 더한다(현행 동작을 문서로 인정). (b) 상품담보 상세(pcId) 편집 화면으로 옮긴다. (c) 보통약관 · 특별약관 탭 표에 편집 모드를 들인다.
- 영향 기능: 상품

**D26 상세 화면의 카운트** — 원: 공 C15 · D10
- 대안: (a) L1 의 「제목 옆 개수 없음」을 상세 · 섹션 제목에도 넓혀 모두 지운다(오류 수만 남긴다). (b) **추천(정리안)** — 판단과 무관한 분모 「전체 참조 M」과 중복 카운트만 지운다. (c) 그대로 두고 §9.6 에 허용 목록을 적는다.
- 영향 기능: 전 L2

**D27 마스터 필드 이름 라벨** — 원: 공 C12 · D9
- 무엇: 화면단어는 「표시명」을 화면에 쓰지 않는다고 정했는데, 마스터 표 · placeholder 에는 「표시명」이 나온다.
- 대안: (a) **추천(정리안)** 「필드명」 (b) 「필드 이름」 (c) 「항목명」
- 영향 기능: 마스터 · 화면단어

**D28 보통약관 안 공용조항의 조 참조 표기** — 원: 공조 #12
- 무엇: 보통약관 안에 넣은 공용조항의 조 참조가 「보통약관 제1조(…)」로 찍힌다. 보통약관이 자기 조를 이렇게 부르는 것이 실물 어투와 맞는지는 확인 필요다.
- 대안: (a) **추천(정리안)** — 보통약관 문서 안에서는 「보통약관 」 접두를 뺀다. (b) 지금처럼 늘 붙인다.
- 영향 기능: 조립산출 · 공용조항

**D29 공용조항 주석** — 원: 공조 #14
- 무엇: 생성 화면에서 받은 주석이 상세 어디에도 보이지 않고 고칠 수도 없다.
- 대안: (a) **추천(정리안)** — 상세 기본 정보에 주석 줄을 두고 편집 가능하게 한다(별표와 같게). (b) 생성 화면에서 주석 칸을 뺀다.
- 영향 기능: 공용조항

**D30 원천 좌표 「n번째 항」의 기준** — 원: 공조 #15
- 무엇: 원천 좌표의 서수가 조립 결과 기준이다. 그래서 템플릿의 순번과 다를 수 있다(`render.ts:153-177` · `coordinate.ts:48-50`).
- 대안: (a) 템플릿 순번으로 다시 계산한다. (b) **추천(정리안)** — 원천에서는 서수를 빼고 조 이름 + 노드로만 가리킨다.
- 영향 기능: 조립산출

**D31 조 · 관 제목 필수 여부** — 원: 문 L1
- 대안: ① **추천(정리안)** 필수로 한다(빈 값 거부). ② 허용한다(「제N조」만 찍힌다). 문서(템플릿) 이름은 어느 안이든 필수로 본다.
- 영향 기능: 문면

**D32 산출본 예약 절** — 원: 공 B6 · D5
- 무엇: 데이터모델은 「산출본 테이블은 아직 만들지 않는다」고 적었다. 실제로는 `product_previews` 가 Booklet jsonb 를 저장한다.
- 대안: (a) **추천(정리안)** — `product_previews` 를 `booklet_outputs` 의 실현으로 보고 예약 표에서 뺀다. (b) 미리보기용과 다중 산출용을 나누고 관계를 적는다.
